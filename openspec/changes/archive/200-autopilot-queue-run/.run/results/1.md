## Changed

- New `src/core/foundation/config-autopilot.ts`: exports the `AutopilotConfig` type (`enabled: boolean`) and `validateAutopilotConfig(raw)`, which returns `undefined` for an absent block, rejects a non-object with `autopilot must be an object`, rejects any key other than `enabled` with `autopilot.<key> is not supported`, and rejects a non-boolean `enabled` with `autopilot.enabled must be a boolean`. Tagged `@scenario cli-foundation: Autopilot values` and `@adr 021`.
- `src/core/foundation/config.ts`: `OsqConfig` gains `autopilot?: AutopilotConfig`; imports the new module; `defineConfig` takes `autopilot` out of the user config with `const { autopilot, ...user } = config;` (so its `Partial` type never enters the `OsqConfig` return), destructures the rest from `user`, collapses the four `validatedPlanner` lines into one conditional `const`, drops the blank line before `return`, and adds the resolved `autopilot` only when the user gave a block, so a config without it has no `autopilot` key. `DEFAULT_CONFIG` gains none.
- `src/core/foundation/config-user.ts`: `autopilot` added to the `Omit` list and `readonly autopilot?: Partial<AutopilotConfig>` added.
- New `tests/autopilot-config.test.ts`: proves every row of the "Autopilot values" table through `defineConfig`.

## Deviated

The task's Details predicted `config.ts` fits with the two destructures, the `validatedPlanner` collapse and removing the blank line. Measured on today's tree that lands at 250 `wc -l` lines, which `tests/line-budget.test.ts` counts as 251 and rejects (it uses `split('\n').length`, i.e. `wc -l` + 1, against a 250 cap). To clear the one extra line I inlined the resolver into its spread — `...(autopilot === undefined ? {} : { autopilot: validateAutopilotConfig(autopilot) })` — instead of keeping a `resolvedAutopilot` const symmetric with `resolvedAutoSteer`. The file now sits at 249 `wc -l` / 250 counted lines and `biome check` passes.
