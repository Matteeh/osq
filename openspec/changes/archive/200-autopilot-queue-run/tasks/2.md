## Acceptance

- [ ] New `src/core/status/queue-approval.ts` exports `writeQueueApproval`, `readQueueApproval` and `itemApproval`: they write and read `<openspecRoot>/.run/queue-approval.md` as "Queue approval record" says, the read approval carries its hash computed from the file's text, and `itemApproval` gives one item's approval as `approved`, `changed` or `unapproved`.
- [ ] New `src/core/status/autopilot-stop.ts` exports `writeAutopilotStop`, `readAutopilotStop` and `clearAutopilotStop`, which write, read and remove `<openspecRoot>/.run/autopilot-stop.md` as "Autopilot stop record" says. It also exports the stop's type with the reasons `queue_unreadable`, `not_approved`, `changed_since_approval`, `rejected`, `plan_refused`, `planner_not_ready`, `approve_refused`, `halted` and `land_stopped`, for tasks 3 to 5 to import.
- [ ] `osq queue approve` behaves as "Queue approve command" says. It reads the approver with `selectVcs` and `configValue('user.name')` and `configValue('user.email')`, as `writeApprover` in `src/core/spec/stack-dependencies.ts` does, and writes an empty approver when the project has no git.
- [ ] `src/cli/queue.ts` registers `osq queue` and its `approve` subcommand in one function that `createProgram` calls in place of its `queue` block. `osq queue` keeps its description and output; with a record it adds the approval line and words of "Queue view shows the approval" without changing `formatQueue`.
- [ ] `forwardProgram` in `src/cli/remote-client.ts` gives the `queue` command's `approve` subcommand an action that refuses with `localOnly('queue approve')`. Plain `osq queue` stays forwarded.
- [ ] New `tests/queue-approval.test.ts` proves every scenario below. It runs the commands through `queueCommand`'s module and `createProgram` against a temporary project, never this repository's queue.
- [ ] Every existing test passes unchanged, `tests/queue.test.ts`, `tests/help-groups.test.ts`, the `tests/remote-*.test.ts` files and `tests/line-budget.test.ts` included.

## Details

Write the records with the `yaml` package and read them with `parseFrontmatter`, as `src/core/run/plan-run-record.ts` does for `.run/plan-run.md`; keep `items` in queue order. The hash is over the exact text written, so read it back from the file rather than re-serializing.

The approval words go at the end of each item line `formatQueue` prints, after ` changed since planned` when that is there; the rows and the queue items are in the same order.
