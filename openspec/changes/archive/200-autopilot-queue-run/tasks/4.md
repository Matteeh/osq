## Port

```ts
/** The command functions autopilot calls; each throws what its command throws. */
export interface AutopilotCommands {
  /** `osq plan --next`: create the next queue item's change folder. */
  planNext(): Promise<void>;
  /** `osq plan <id> --run`: start the planner; its outcome lands in `.run/plan-run.md`. */
  plan(id: string): Promise<void>;
  /** `osq approve <id>`, with no override flag. */
  approve(id: string): Promise<void>;
  /** `osq land <id>`. */
  land(id: string): Promise<void>;
}
```

## Details

`src/watcher/` may not import `src/cli/` (`tests/import-graph.test.ts`), so the port type lives in `src/watcher/autopilot.ts` and the CLI hands its implementation in, as `watch-service.ts` hands in `buildSteeringPrompt`.

After `planNext`, find the item's new change through the queue state and write its marker with the queue approval's hash; a pass that cannot find it writes a `plan_refused` stop. A `CommandError` from `landCommand` with an empty message carries the exit code in `exitCode`.

"Edited item stops the queue" edits the second item's body after the approval but before the watcher runs. "A human's step clears the stop" may write the `halted` stop record by hand and then have a task running, rather than drive a real halt.
