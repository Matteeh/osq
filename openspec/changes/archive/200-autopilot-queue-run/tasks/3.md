## Acceptance

- [ ] New `src/core/status/autopilot-marker.ts` writes, updates and reads a change folder's `.run/autopilot.md` as "Autopilot change marker" says. A missing or unparsable marker reads as none.
- [ ] New `src/core/status/autopilot-view.ts` reads, from files only, everything the step needs: whether the queue file exists and parses (with the parse error), whether any active change has a pause `readActivePause` reports, the ids of active approved changes, and for the first queue row whose state is not `landed`: its item, row, approval from task 2's `queue-approval.ts`, and, when the row has an active or archived change, that change's id, folder, whether it is approved, its marker, its `currentPlanRun` view and its `readNextStep`.
- [ ] New `src/core/status/autopilot-step.ts` exports a pure function from that view to one step of "Autopilot next step": `done`, `wait`, `plan-next`, `plan`, `approve` and `land` carry the item's slug and, except `plan-next`, the change id; `stop` carries a stop task 2's `autopilot-stop.ts` can write, with reason, item, change and command. Its detail is the parse error for `queue_unreadable`, the planner's outcome for `planner_not_ready`, the next step's detail for `halted` when it has one, and empty otherwise.
- [ ] New `tests/autopilot-step.test.ts` proves "Autopilot steps" with one case per table row against hand-built views, so every row is checked in order. It proves "Marker round trip" on a temporary folder, and reads views from a temporary project without git for the rows about the queue file, the approval and an unapproved change with a `ready` `.run/plan-run.md` whose `hash` matches `hashChangeFolder`.
- [ ] Nothing outside `src/core/` is imported. No file outside the scope changes, and every existing test passes unchanged.

## Details

`readActivePause` lives in `src/core/run/usage-pause.ts`; `findActivePause` is in `src/watcher/` and core may not import it. A planner that is `failed`, `timed_out`, `unchanged` or interrupted reads like `lint_red` in the table: `stop`, `planner_not_ready`, `osq plan <id>`. `currentPlanRun` already reports an interrupted planner as `failed`, and returns null once the plan was edited after the run.
