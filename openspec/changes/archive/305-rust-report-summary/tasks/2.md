## Details

Port the `Specs Summary:` and `Now:` parts of `buildMetricsReport` and
`formatMetricsReport` in `src/core/report/report.ts`, and the `--json`
path of `reportCommand` in `src/cli/report.ts`, for the three members
`completionRate`, `now` and `specs` only. Never read anything under `src/`
from Rust; those files are in `entry` only so you can port them. Read each
counted change with storage's `read_now_facts` from task 1.

Copy the config, git-on and tree listing steps from the show crate's
`facts.rs`: `load_config`, `GitVcs::new(root).with_timeouts(..)`, the
root check, `worktree_list`, `change_trees`, `list_tree_changes` and the
stacked folders under `stacked_root`. Do not depend on `osq-feature-show`;
a feature never calls another (ADR 022). `show_land.rs` shows how a test
builds a scratch repository and a worktree with git; give each git call a
fixed author and committer through `-c user.name=.. -c user.email=..`.

Write the JSON by hand, keys in sorted order, so the rate prints as
JavaScript prints it; Rust's `{}` on an `f64` already prints `100` and
`31.25`. Compare goldens byte for byte, with no newline added or trimmed.
Copy fixtures with their dot folders, since the markers live under
`.run/`, and write the lock files into the copy, since git ignores them.

`osq-cli` already registers `ReportFeature`, and its help and dispatch read
the feature's commands, so `osq-rs report` needs no change there.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches; take its expected value
from the TypeScript source. Run the proposal's verify as the watcher does,
with `OSQ_CHANGE=openspec/changes/305-rust-report-summary`, so the link
gates see this change's new requirements.
