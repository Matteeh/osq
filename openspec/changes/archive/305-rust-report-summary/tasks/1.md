## Details

Model the reader on `change_files.rs`: it already splits a done marker's
frontmatter with `parse_frontmatter` and reads a boolean field through
`yaml_rust2`, never with a YAML loader of its own. Read the `manual` field
the same way. Test whether a marker exists with
`std::fs::symlink_metadata(..).is_ok()`, so a folder or a broken symlink
counts as TypeScript's `readdir` counts it; test `proposal.md` and
`spec.md` with `Path::exists`, which follows symlinks as `fs.stat` does.

`readChangeFolder` and `deriveTaskStateFromSnapshot` in
`src/core/status/state.ts`, and `doneMarkerIsManual` in
`src/core/report/report.ts`, are the TypeScript to port. Never read anything
under `src/` from Rust; they are in `entry` only so you can port them. The
status rule itself belongs to the report feature, in task 2; this reader
only gives the facts.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/305-rust-report-summary`, so the link gates see
this change's new requirements.
