## Changed

`src/core/status/next-step.ts`: `readActiveNextStep` now returns
`osq retry <id> change` for a change-level regression instead of
`osq reject <id> --reason <text>`. A dead or regressed task still returns
`osq retry <id> <n>`.

`src/core/status/inbox.ts`: the `change-regressed` item's command is now
`osq retry <id> change`, and the now-unused `CHANGE_REG_RETRY` constant is
removed. Every other inbox command is unchanged; `blocked` and stuck rows are
still annotated by `applyBlockedItems`/`inbox-text.ts`.

`tests/next-step.test.ts`: renamed "points a change regression at the reject
command" to say retry, and changed its expectation to `osq retry 007 change`.

`tests/inbox.test.ts`: the three change-regressed expectations now read
`osq retry <id> change` (needs-you command list, the text row, and the bare
CLI stdout assertion). The JSON kind/ordering checks and all other commands
are untouched.

Added `tests/change-halt-hint.test.ts`, covering the status-inspection delta's
"Change-level halt command" and "Change regression next step" scenarios through
`readNextStep`, `projectNeedsYou`, `formatNextStep`, and `formatInboxText`.

Verification: `node --import tsx --test tests/change-halt-hint.test.ts` (2
pass), `tests/next-step.test.ts` (30 pass), `tests/inbox.test.ts` (15 pass),
and the proposal's `pnpm verify` (2766 CLI pass, 94 UI pass, typechecks, build,
and lint clean).
