## Changed

Added `src/core/spec/approve-branch.ts` with `claimBranch(vcs, projectRoot,
folderPath, folderName)`. It returns null when `osq/<folder>` is absent,
renames a branch whose tip holds
`<dirname folderPath>/rejected/<folder>/.run/rejected.md` (POSIX, relative to
`projectRoot`) to the lowest free `osq/<folder>-rejected-<n>` when
`vcs.worktreeList()` does not list it, and otherwise throws
`branch osq/<folder> already exists`.

`src/core/spec/approve-worktree.ts`: removed `refuseExistingBranch` and now
calls `claimBranch` in its place, before the digest. The kept name flows into
both the stacked and the new-worktree results through a new `keptBranch` field
on `WorktreeApprovalResolved`.

`src/core/spec/approve.ts`: `ApproveResult` gained an optional `keptBranch`
with a doc comment. `src/cli/approve.ts` prints
`  Kept rejected branch: <branch>` immediately after the `Hash:` line when it
is set.

Added `tests/approve-rejected-branch.test.ts`, covering the delta's rejected
branch renamed, checked out, and next-free-name scenarios through
`approveSpec`, plus the CLI's kept-branch line. It builds the rejection
record on the branch with `git`, never `osq reject`.

## Deviated

For the checked-out scenario I add the branch-backed worktree with
`git worktree add --no-checkout`. A normal checked-out worktree holds
`openspec/changes/rejected/<folder>` on disk, and `changeTrees` then treats
that worktree as the tree that names the folder, so `findChange` no longer
finds the checkout's active draft and `approveSpec` fails with
`Spec "<id>" not found` before it reaches `claimBranch`. The no-checkout
worktree keeps the branch listed by `vcs.worktreeList()` — the spec's own
definition of checked out — while avoiding that unrelated filtering.

## Outside scope

A kept rejected worktree (one with `openspec/changes/rejected/<folder>` on
disk) makes `findChange`/`listChanges` drop the same change's active folder in
the checkout, so `osq approve` reports `Spec "<id>" not found` instead of the
required `branch osq/<folder> already exists`. The filtering is in
`src/core/status/change-locations.ts`, outside this task's scope; `claimBranch`
itself already behaves per the spec.
