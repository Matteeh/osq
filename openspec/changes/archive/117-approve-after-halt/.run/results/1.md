## Changed

Added `renameBranch(from, to)` to the `Vcs` port after `createBranch`, with a
one-line doc comment. `GitVcs.renameBranch` delegates to a new
`renameBranch(ctx, from, to)` in `git-vcs-merge.ts` that runs
`git branch -m from to` and throws `combined(result)` on a non-zero exit.
`NoVcs.renameBranch` calls `this.reject()`.

Moved `nonEmpty`, `parseStashBranch`, `parseStashes`, and `parseStatus`
unchanged out of `git-vcs.ts` into a new `git-vcs-parse.ts`, which exports the
three `git-vcs.ts` uses.

Updated `PORT_MEMBERS` in `tests/vcs-write.test.ts` to list `renameBranch`.
Added `tests/vcs-rename-branch.test.ts` covering the rename-keeps-commits and
rename-onto-a-taken-name scenarios in a temporary repository, plus
`NoVcs.renameBranch` failing with the reason git is off.

## Deviated

The "Rename a branch" scenario checks
`!(await listBranches('osq/001-a')).includes('osq/001-a')` rather than a deep
equality against `[]`. `listBranches` matches by `prefix*`, so after the
rename it also returns `osq/001-a-rejected-1`; the dense delta only requires
that `osq/001-a` itself no longer appears.
