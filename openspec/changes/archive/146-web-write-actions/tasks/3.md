## Acceptance

- [ ] `packages/ui/src/contracts.ts` re-exports, as types only, `WebActionsDocument`, `WebAction`, `WebActionRequest` and `WebActionResult` from `src/core/web/web-actions.ts`.
- [ ] New `packages/ui/src/change/actions-client.ts` exports `createActionClient(fetch)` as "Change actions" says: `load(selector)` gets `/api/actions/<encoded selector>` and gives null on 404, and `run(selector, token, request)` posts the request without `change` and gives the `WebActionResult`, or a result that says another action is running on 409. - [ ] New `ChangeActions` renders the buttons, the reject reason field, the manual commands, the pending state and the last result from props only, and new `ChangeActionsPanel` holds the state: it loads the actions on mount and whenever the change's `asOf` changes, runs a tap through the client, and loads again after the answer.
- [ ] `ChangeView` and `App` take an optional action client; `ChangeView` renders `ChangeActionsPanel` only when one is given. `main.tsx` passes a client over `window.fetch` only when `data.inline` is false, so a static export makes no actions request.
- [ ] New `tests/ui-actions.test.tsx` covers the scenarios of "Change actions" with `renderToStaticMarkup`, the reject button disabled while the reason is empty, retry labelled `Retry task 2` and `Retry change`, and the client's method, URL, headers and body against a recording fetch.
- [ ] The same test taps through a real server: `startWebServer` on port 0 over a ready change from `createProject` and `createChange`, with `createWebActionRunner` from `src/cli/serve-actions.ts`, and a client whose fetch adds the `Origin` header a browser would send. `load` then `run` with `approve` gives exit code 0, and a second `load` has no `approve` action.
- [ ] Every existing test passes unchanged, and every new source file under `packages/ui` stays at or under 250 lines.

fails a runtime import. Style the buttons and result with classes in
`styles.css` that follow the existing change view's tokens, readable at
narrow widths and in dark mode. Show stdout and stderr in `<pre>` blocks.

nonexistent paths as `tests/command-inputs-approve.test.ts` does, so the
