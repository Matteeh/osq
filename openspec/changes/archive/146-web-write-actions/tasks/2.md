## Ports

```ts
/** A command function for one verb, given the request and this request's inputs. */
export type WebCommand = (request: WebActionRequest, inputs: ActionInputs) => Promise<void>;

/** Build the runner `osq serve` passes to `startWebServer`. */
export function createWebActionRunner(
  inputs: { readonly cwd: string; readonly config: OsqConfig },
  commands?: Readonly<Record<WebActionVerb, WebCommand>>,
): WebActionRunner;
```

`ActionInputs` is the type `src/cli/inbox-actions.ts` already exports;
`WebActionRequest`, `WebActionVerb` and `WebActionRunner` come from
`src/core/web/web-actions.ts`.

## Details

Turn a thrown value into a result the way `createActionLauncher` in
`src/cli/inbox-actions.ts` sorts `CommandError` from any other error, but
return the message and `next` as fields instead of printing them. `land`
can throw a `CommandError` with an empty message and a non-zero exit code;
keep the empty message.

`serveCommand` waits on its signal, so the end-to-end test aborts the
signal and awaits the command's promise in a `finally`, or the run hangs.
