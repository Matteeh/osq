## Changed

- Added `src/core/web/web-actions.ts`: the `WebActionVerb`, `WebAction`, `WebActions`, `WebActionsDocument`, `WebActionRequest`, `WebActionResult`, and `WebActionRunner` ports, plus `getWebActions`, which resolves the change with `resolveChangeFolder` and builds the document from `readDispatchItems` (falling back to `readNextStep`'s `osq plan <id>` when the change has no dispatch item). Repeated commands appear once; `osq show` is skipped.
- Added `src/core/web/web-http.ts` with `sortKeysDeep`, `serializeWebJson`, `send`, `sendJson`, `sendFailure`, and `decodeChangeSelector`, moved out of `web-server.ts`. `web-server.ts` re-exports `serializeWebJson`, so `web-export.ts` and existing tests import it unchanged.
- Added `src/core/web/web-write.ts` with the token (`randomBytes`/`timingSafeEqual`), the Host/Origin/content-type/constant-time-token guard, the body reader and validator, the one-at-a-time `WriteGate`, and `createActionRoutes`, which owns the GET/POST handling for the actions path. `startWebServer` only routes to it.
- Extended `src/core/web/web-server.ts` with optional `runAction` and `getActions` (default `getWebActions`). With `runAction`, GET/HEAD on `/api/actions/<id>` returns the document plus the per-server token, POST runs one action, PUT/PATCH/DELETE on that path get 405 `Allow: GET, HEAD, POST`, and every other non-GET/HEAD method keeps 405 `Allow: GET, HEAD`. Allowed hosts use the port the server actually bound. Without `runAction` everything behaves as before and `/api/actions/<id>` is a 404.
- Added `tests/web-actions.test.ts`: raw `node:http` requests over `startWebServer` with a recording `runAction`, covering the approval document, retry/reject targets, the unplanned `osq plan` fallback, foreign Host/Origin, every unproven write with a before/after tree snapshot, a valid write's 200 result, one-at-a-time 409 then 200, bad bodies and selectors, runner rejection 500 then 200, PUT on the actions path, POST `/api/report` and PUT `/api/actions`, and POST on the actions path with no `runAction`.
- Added accepted `decisions/009-loopback-write-actions.md` (`applies_to: [web-inspection]`, the ADR rule, `checks: [tests/web-actions.test.ts]`, sections Status/Context/Decision/Consequences/Rejected) and its index line in `decisions/README.md`.

## Deviated

- `decodeChangeSelector` moved from `web-server.ts` into `web-http.ts` (and is exported) rather than staying in `web-server.ts`. The write path needs the same decode and `web-server.ts` had to shed lines to stay within the 250-line budget; putting it beside `sendJson` keeps both callers importing one HTTP helper module. The acceptance only names the five response helpers, so this is an extra export.
- The acceptance names `web-server.ts` as the place `startWebServer` adds the routes, but the guard/body/gate work lives in `web-write.ts` per the same acceptance. `web-server.ts` keeps only routing and passes the bound port through a `getPort` callback, which keeps the whole file at 218 lines.

## Outside scope

- `src/cli/serve.ts` is not touched and still calls `startWebServer` without `runAction`/`getActions`, so `osq serve` has no write endpoints yet. Task 2 adds `createWebActionRunner` and passes it; until then the server stays read-only and every existing serve test passes.
