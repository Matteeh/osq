## Changed

- Added `src/cli/serve-actions.ts`: `createWebActionRunner({ cwd, config }, commands?)`
  returns a `WebActionRunner` whose default table maps `approve`, `land`,
  `reject` and `retry` to `approveCommand`, `landCommand`, `rejectCommand` and
  `retryCommand`. Every request gets its own collecting `stdout`/`stderr`
  writers; a `CommandError` becomes its exit code, message and `next` or null,
  any other throw becomes exit code 1 with `Error: <message>` and next null,
  and the runner never rejects, touches `process.exitCode`, or writes to a
  process stream.
- `src/cli/serve.ts` now passes `runAction: createWebActionRunner({ cwd, config })`
  to `startWebServer`; the `--export` branch is unchanged.
- `src/cli/index.ts` `serve` description and the README `## Commands` line no
  longer call the dashboard read-only and now say it can approve, land, reject
  and retry. The README Delivery Dashboard prose was updated to match.
- Added `tests/serve-actions.test.ts`: a recording table proves each verb
  reaches its command with the request, cwd and config and that each result
  carries only its own writers' text while nothing reaches `process.stdout` or
  `process.stderr`; a failure case proves the `CommandError` and generic-error
  mapping; the default table proves `reject`/`retry` of change `999` fail with
  the expected messages; and an end-to-end case starts `serveCommand` on port 0,
  approves change `001` through `POST /api/actions/001` with the token, Origin
  and JSON content type, and shows the same `.run/approved` and event-type
  sequence as a twin approved directly with `approveCommand`.

Task verify (`node --import tsx --import ./tests/git-test-env.ts --test tests/serve-actions.test.ts`)
and the proposal verify (`pnpm verify`) both pass.

Touched: src/cli/serve-actions.ts, src/cli/serve.ts, src/cli/index.ts, README.md, tests/serve-actions.test.ts
