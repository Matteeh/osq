# Task 7 result

## Changed

- `src/core/report.ts`:
  - `SpecMetrics`, `TaskMetrics`, and `DurationMetrics` fields are now `readonly`.
  - `MetricsReport` now opens with the verbatim stable fields in signature order (`completionRate`, `cost?`, `durations`, `failureBreakdown`, `fileChanges`, `specs`, `tasks`, `tokens`), all `readonly`, followed by the existing backward-compatibility aliases (`totalSpecs`, `activeSpecs`, `archivedSpecs`, `totalTasks`, `doneTasks`, `deadTasks`, `runningTasks`, `pendingTasks`, `completionPercentage`, `completionRatio`, `deadBreakdown`) under a comment.
  - `formatMetricsReport` was already a pure renderer over the object; left unchanged and now covered by a dedicated test.
- `src/cli/report.ts`:
  - Added `serializeSortedJson(data: unknown): string` plus a private recursive `sortKeysDeep` that sorts every object level (preserving array order) before `JSON.stringify(..., null, 2)`.
  - Added private `toStableMetrics(report)` that projects the report down to the stable `MetricsReport` shape: top-level stable keys only, and nested `tokens` (6 neutral fields), `fileChanges` (`totalChanges`/`uniqueCount`/`uniqueFiles`), `durations`, `specs`, `tasks`, `cost`, and a copied `failureBreakdown`. `cost` is included only when present.
  - JSON mode now emits `serializeSortedJson(toStableMetrics(report))`; text mode still emits `formatMetricsReport(report)`. No other stdout is written.
- `tests/report-json.test.ts` (new, 9 tests): recursive/stable `serializeSortedJson` behavior; fixture JSON parses as a single document; exact alphabetical top-level key set `['completionRate','cost','durations','failureBreakdown','fileChanges','specs','tasks','tokens']`; raw-text alphabetical ordering; nested key shapes with no legacy aliases; non-JSON path still formats; `formatMetricsReport` renders solely from supplied object values; commander `--json` parsing (`reportCmd.parseOptions(['--json'])` → `opts().json === true`).

## Deviated

- Task notes said task 7 "will remove" the backward-compatibility aliases from `TokenMetrics`/`MetricsReport`, and the signature shows only the stable fields. I could not remove them: `tests/report.test.ts`, `tests/report-tokens.test.ts`, `tests/report-file-changes.test.ts`, `tests/report-task-states.test.ts`, and `tests/report-failure-breakdown.test.ts` are outside this task's scope but read `totalSpecs`, `completionPercentage`, `deadBreakdown`, `tokens.promptTokens`, `fileChanges.totalEvents`, etc. Removing the fields would break `pnpm tsc --noEmit`. Instead the exported `MetricsReport` keeps the stable fields first (readonly, signature order) and the JSON output is projected to exactly the stable shape, so the machine-readable contract matches the signature while existing consumers keep compiling.
- Also projected nested `tokens`/`fileChanges` in JSON to drop aliases (`promptTokens`, `totalEvents`, ...), which goes beyond the top-level key list in the Details but is required by "exact key structure matching type".
