## Acceptance
- [ ] MetricsReport type is exported with stable keys representing all report metrics
- [ ] formatMetricsReport renders exclusively from the structured MetricsReport object
- [ ] reportCommand with json true outputs valid JSON with sorted keys and no other text
- [ ] CLI flag osq report --json parses correctly via commander
- [ ] tests/report-json.test.ts asserts valid JSON parsing and exact key structure matching type

export interface SpecMetrics {

## Details

1. In `src/core/report.ts`:
   - Export the verbatim `MetricsReport` interface shown in signatures.
   - Construct the report object with consistent properties.
   - Ensure `formatMetricsReport(report)` derives all rendered text lines directly from this data structure without computing any separate side metrics.
2. In `src/cli/report.ts`:
   - Implement `serializeSortedJson(data)` which recursively sorts object keys before running `JSON.stringify(..., null, 2)` to guarantee deterministic, stable output ordering across platforms and runs.
   - When `options.json` is true, output only the serialized JSON string via `options.stdout` (or `console.log`). No logging prefixes or extra messages may be emitted.
3. In `tests/report-json.test.ts`:
   - Invoke `reportCommand({ cwd: fixtureReportDir, json: true, stdout })`.
   - Validate that the output parses cleanly with `JSON.parse`.
   - Assert all expected keys are present and in alphabetical order: `['completionRate', 'cost', 'durations', 'failureBreakdown', 'fileChanges', 'specs', 'tasks', 'tokens']`.
   - Assert `osq report --json` commander flag configuration by verifying command line flag parsing.
