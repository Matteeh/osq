## Acceptance
- [ ] HarnessEventType union in src/harness/types.ts includes done and dead
- [ ] DoneEventData interface defines task: string and DeadEventData defines task: string; reason: string
- [ ] Runner appends { type: 'done', data: { task } } to events.jsonl alongside every done marker write
- [ ] Runner appends { type: 'dead', data: { task, reason } } to events.jsonl alongside every dead marker write
- [ ] tests/runner-done-dead-events.test.ts verifies done and dead events are appended matching markers

## Signatures

In `src/harness/types.ts`:

```ts
export type HarnessEventType =
  | 'started'
  | 'tokens'
  | 'tool'
  | 'file_changed'
  | 'verify_ran'
  | 'result_written'
  | 'exited'
  | 'done'
  | 'dead';

export interface DoneEventData {
  readonly task: string;
}

export interface DeadEventData {
  readonly task: string;
  readonly reason: string;
}
```

In `src/watcher/runner.ts`:
Event emission shapes appended to `.run/events/<taskNumber>.jsonl` via `appendHarnessEvent`:
- Done event: `{ type: 'done', timestamp: string, data: { task: string } }`
- Dead event: `{ type: 'dead', timestamp: string, data: { task: string, reason: string } }`

## Details

1. In `src/harness/types.ts`, add `'done'` and `'dead'` to the `HarnessEventType` union, and export `DoneEventData` and `DeadEventData`.
2. In `src/watcher/runner.ts`, audit every location where `.run/dead/<taskNumber>.md` is written:
   - Missing `.run/approved` (`reason: 'spec_conflict'`)
   - Approval hash mismatch (`reason: 'spec_conflict'`)
   - Lock acquisition failure (`reason: 'already_running'`)
   - Agent non-zero exit code or timeout (`reason: spawnResult.timedOut ? 'timeout' : 'crashed'`)
   - Agent exited without result file and produced no final stream text (`reason: 'no_result'`)
   - Watcher independent verify failed or timed out (`reason: 'verify_red'`)
   Immediately before or after writing the dead file marker, call `appendHarnessEvent(specFolderPath, taskNumber, { type: 'dead', timestamp: new Date().toISOString(), data: { task: taskNumber, reason: failureReason } })`.
3. In `src/watcher/runner.ts`, where `.run/done/<taskNumber>` is written upon successful verify:
   Call `appendHarnessEvent(specFolderPath, taskNumber, { type: 'done', timestamp: new Date().toISOString(), data: { task: taskNumber } })`.
4. In `tests/runner-done-dead-events.test.ts`, write unit tests asserting that running tasks that succeed or fail appends the respective `done` or `dead` event with matching payload to the task's `.run/events/<n>.jsonl`.
