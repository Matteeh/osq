## Changed

- `src/core/status/next-step.ts`: added `archived` to `NextStepState`. `readArchivedNextStep` now takes `projectRoot` and `config`; after steering it calls `selectVcs` when `config.vcs.enabled` is true and, for the git port, `readDependencyState` for the located folder. Any dependency state but `landed` returns `{ state: 'archived', command: 'osq land <id>', detail: 'not landed' }`. Flag off (or no git) keeps returning `landed` without reading git. Added `@scenario status-inspection:` tags to `readNextStep` and `formatNextStep`.
- `src/core/status/status.ts`: added exported `NotLandedChange` and optional `StatusOverview.notLanded`. Added private `readNotLanded`, which with `vcs.enabled` reads `findLandCandidates` and keeps each candidate whose `readNextStep` state is `archived`, in numeric order, with the proposal title or folder name; without the flag it returns `[]` and reads nothing. `formatStatusOverview` prints `Not landed:` and `  <id>: <title> — osq land <id>` lines directly after `Archived specs: <n>`. Tagged `getStatusOverview` and `formatStatusOverview`.
- `tests/landed-next-step.test.ts`: new tests for every scenario of "Landed next step reads the default branch", "Changes waiting to land in status", and "Not landed format". They build temp git repos with `vcs.enabled`, changes archived and committed on `osq/<folder>` worktrees, merge branches into `main` for the landed cases, and write the `sync_conflict` `regressed/change.md` marker plus event for the steering case. They assert through `readNextStep`, `getSpecDetails`/`formatShowText`, `getStatusOverview`, and `formatStatusOverview`.

## Deviated

For the "Archived change without version control" case the archived folder is written into the checkout's archive directory and left untracked. With `vcs.enabled` off, `changeTrees` does not follow worktrees, so an archived folder on an `osq/` branch is not located as archived and `readNextStep` would fall through to the active path. The checkout copy is the only way to reach the archived branch of `readNextStep` with the flag off, and main still does not hold it.
