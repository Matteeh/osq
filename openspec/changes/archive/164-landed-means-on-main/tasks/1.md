## Acceptance

- [ ] `NextStepState` gains `archived`. `readArchivedNextStep` keeps returning `dead` for a change that needs steering. Otherwise, when `config.vcs?.enabled === true` and `selectVcs` returns the git port, it calls the existing `readDependencyState` for the change's folder name and returns `{ state: 'archived', command: 'osq land <id>', detail: 'not landed' }` for any state but `landed`. Without the flag or without git it returns `landed` as today and calls neither `selectVcs` nor `readDependencyState`. So status-inspection "Change next step", "Landed next step reads the default branch", "Next step commands" and "Next step detail and format" hold, and `formatNextStep` renders `archived (not landed) — osq land 007`.
- [ ] `StatusOverview` gains optional `notLanded: { id, folderName, title }[]`. With `config.vcs?.enabled === true`, `getStatusOverview` reads the existing `findLandCandidates`, keeps each candidate whose `readNextStep` state is `archived`, in numeric order, with `title` from `parseSpecMdFromFolder` or else the folder name. It sets `notLanded` only when the list is non-empty, and without the flag calls neither function.
- [ ] `formatStatusOverview` prints, directly after `Archived specs: <n>`, a `Not landed:` line and one `  <id>: <title> — osq land <id>` line per `notLanded` entry, and nothing when `notLanded` is absent, so "Explicit status with next steps" and "Changes waiting to land in status" hold.
- [ ] New `tests/landed-next-step.test.ts` builds temporary git repositories the way `setupWorktreeProject` in `tests/land-view.test.ts` does: `vcs.enabled`, a change archived and committed on `osq/<folder>` in a worktree. It checks every scenario of "Landed next step reads the default branch" and "Changes waiting to land in status", and "Not landed format", through `readNextStep`, `formatShowText(await getSpecDetails(...))` for the `Next:` line, `getStatusOverview` and `formatStatusOverview`. For the landed cases it merges `osq/<folder>` into `main` with `git merge`. For the steering case it writes the `sync_conflict` stop event on the archived change's stream the way `tests/steering-archived.test.ts` does.
- [ ] Each exported function you change carries `@scenario status-inspection: <scenario name>` lines for the scenarios it serves.
- [ ] Every existing test passes unchanged.
