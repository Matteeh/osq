## Changed

- `src/core/status/inbox.ts`: `NeedsYouKind` gains `planning`,
  `verification-pending`, and `verification-failed`; `NeedsYouItem` gains the
  optional literal `beforeApproval?: true`. `projectNeedsYou` now reads
  `overview.nextSteps[folderName]`: an unapproved change whose next state is
  `unplanned` becomes a `planning` item carrying that command instead of an
  approval item, an approval item whose change is `ready-for-approval` with a
  detail carries `beforeApproval: true`, and a change missing from `nextSteps`
  keeps today's `osq approve <id>` item. The new field is appended after
  `command`, so existing key order is untouched.
- `src/core/status/inbox-text.ts`: `needsYouLine` renders the new kinds as
  `— unplanned — <command>`, `— verification pending — <command>`,
  `— verification failed — <command>`, and prefixes an approval row with
  `— do the steps before approval first ` when `beforeApproval` is set.
- `src/core/status/inbox-projection.ts`: added `projectPendingVerifications`,
  which turns every `overview.pendingVerifications` entry into a needs-you item
  (`verification-failed` when its next-step detail is `failed`, else
  `verification-pending`, `task: null`, next-step command). `readInbox`
  appends those items after `projectInbox`'s active items.
- `packages/ui/src/home/labels.ts`: the needs-you label map now covers the new
  kinds (`needs planning`, `verification pending`, `verification failed`).
- `tests/inbox.test.ts`: the inline unapproved fixture keeps a missing verify,
  so its expected kind is now `planning` with `osq lint 001`.
- Added `tests/inbox-next-step.test.ts`: 8 tests covering "Planning inbox
  items", "Steps before approval", "Verification inbox items", and "Planning
  label" through `readInbox`/`formatInboxText` on temporary projects, including
  the missing-`nextSteps` fallback and the exact JSON key order
  `kind, change, task, command` (plus trailing `beforeApproval`) of each new
  item. It imports `needsYouKindLabel` from `packages/ui/src/home/labels.ts`.

Task verify and `pnpm verify` (CLI and UI typechecks, build, full suite, lint)
both pass.

## Deviated

- `projectInbox` itself was left unchanged; only `readInbox` appends the
  pending-verification items, exactly as acceptance line 3 words it. Direct
  callers of `projectInbox` therefore do not see pending items, but every real
  inbox consumer (`readInbox`, the bare CLI, `serve`, static export) does.
- `beforeApproval` is derived from the next-step `detail` returned by task 1
  (`ready-for-approval` with a non-null detail) rather than re-parsing the
  proposal, so the one source of truth for that flag is `readNextStep`.
