## Changed

- Added `src/core/status/dependency-readiness.ts`, holding `isDependencyDone`
  and the helpers only it needed (`findFolder`, plus the directory `listDir`
  now shared with `state.ts`). An archived dependency is met only when
  `readVerification` says its requirement is absent or its latest outcome is
  `passed`; a rejected or unfinished active dependency is never met. The new
  module also exports `isVerificationPending(folderPath)`, the shared
  "required and not passed" test used by both dependency readiness and queue
  association.
- Changed `src/core/status/state.ts` to import `isDependencyDone` and `listDir`
  from the new module, removing its local copies. `resolveUnmetDependencies`
  stays and `readChangeFolder`/`deriveSpecState` behavior is unchanged; every
  existing export is kept.
- Changed `src/core/status/queue-state.ts`: `QueueItemState` gains
  `verification-pending`, and `selectAssociation` derives a single archived
  association as `verification-pending` while `isVerificationPending` is true,
  else `landed`. `readQueueState` already builds its landed set from the
  `landed` state, so a pending association stays out of it and its dependents
  keep unmet dependencies.
- Changed `src/core/status/queue-report-detail.ts`: a `verification-pending`
  row is treated like `landed` when deriving the archived association's
  planned-to-landed seconds.
- Added `tests/verification-dependents.test.ts`: four tests. Three cover
  "Pending dependency" (blocked derivation and `readNextStep`, freed on a
  `passed` event, a `failed` outcome keeping it blocked, and an archived
  dependency without `verification` staying met). One covers
  "Verification pending queue dependency" with `projectQueue`,
  `prepareQueuePlan`, and `formatQueue` printing `[verification-pending]`, then
  shows `beta` becoming eligible after the `passed` event.

## Deviated

- The new helper `isVerificationPending` lives in `dependency-readiness.ts`
  rather than being inlined in `queue-state.ts`. `queue-state.ts` started this
  task at 246 lines against a budget the line-budget test measures as
  `split('\n').length` (so 249 real lines for a trailing newline); the added
  union member, import, and archived branch pushed it over. Sharing the helper
  removed two lines and kept the pending rule in one place.
- To stay inside that budget I also folded `mapActiveState`'s last two returns
  into one ternary and dropped one blank line between declarations in
  `queue-state.ts`. Both are formatting-only.
- In `queue-report-detail.ts` the widened condition is stored in the local
  `archivedRow` boolean so biome keeps it inside the 100-column width.
