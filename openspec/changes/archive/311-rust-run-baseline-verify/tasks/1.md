## Details

Read the attempt with the `read_retry_context` call `after_lock` already
makes, and run the pre-spawn step only when it is 1. Reuse the verdict's
`verify` helper for the run, log and event, giving it the pre-spawn
fields (`phase`, `expected`, `mismatch`, `missing_paths` on core's
`VerifyRanData`) so the task verify's event stays as it is; kill through
`dead::kill` with `DeadReason::VerifyPrecondition`, and build the excerpt
with the verdict's `excerpt`.

Copy the lint feature's `named.rs` tokenizer, `list` and `missing` into
its own file in the run crate, since a feature never calls another; add
`osq-kernel-loop` to the run crate's dependencies for `scope_files`, and
leave the root `Cargo.lock` to follow it. The mismatch rule is
TypeScript's `isPreSpawnMismatch`.

The tests rewrite `tasks/1.md` as `verify_timeout_keeps_the_output_tail`
does, then call `support::write_seal`; quote verify commands for the YAML
frontmatter. The later-attempt test writes the retry line and marker as
`tests/run_attempts.rs` does. When the mutation check reports a missed
mutant, add a test row for that line rather than keeping a branch no
test reaches. Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/311-rust-run-baseline-verify`, so the link
gates see this change's scenarios.
