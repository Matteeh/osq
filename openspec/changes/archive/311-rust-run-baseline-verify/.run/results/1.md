## Changed

- `run` now reads the retry context before the scope snapshot and, when the attempt is 1, runs the task's verify once after the approval check and before pi starts.
- The pre-spawn run reuses the verdict's shared verify helper, writes the run's log as `.run/logs/<task>-1.log`, and appends the `verify_ran` event with `phase` `pre_spawn`, `expected`, `mismatch` and `missingPaths`. A mismatch kills the task as `verify_precondition` with the required marker and excerpt before pi starts.
- Added `feature/named.rs`, a copy of the lint feature's tokenizer, `list` and `missing` rules plus the regular-file check, resolving globs through rust-loop `scope_files`.
- Added `feature/pre_spawn.rs` with the start spelling, the mismatch rule, the run step and the marker.
- `events.rs` carries the pre-spawn fields through `VerifyMeta`/`VerifyEvent`; `verdict.rs` gained `VerifyStream` to keep the shared helper within clippy's argument limit, and now writes the task/change logs as before.
- Added `osq-kernel-loop` to the run crate; `Cargo.lock` follows with the new crate dependency.
- New `tests/run_pre_spawn.rs` proves every row of "Pre-spawn verify outcomes", "Pre-spawn marker", "Pre-spawn named paths" and "Pre-spawn verify on a later attempt", plus tokenizer/naming edge rows.
- Updated `tests/run_verify_output.rs` to expect `1-2.log` for task rows and `1-4.log` in `log_count_skips_other_names` with the `1-9.log/keep` collision folder, and `tests/run_outcomes.rs` to expect `Full output: .run/logs/1-2.log`.
- Verification passed: the task's cargo tests, `cargo fmt --all --check`, workspace clippy, `OSQ_CHANGE=openspec/changes/311-rust-run-baseline-verify sh scripts/verify-rust.sh`, and cargo-mutants over each changed source file with no missed mutant.

## Deviated

- The delta table "Pre-spawn verify outcomes" lists `missingPaths` none for the `red`, `green` and `any` rows whose verify is `test -f src/a.txt`. Under the requirement text, TypeScript's `listNamedPaths`/`missingNamedPaths`, and the same table's `true src/a.txt` rows, `src/a.txt` is a missing path in the "Run outcomes" repository. The new tests therefore assert `src/a.txt` for those three rows. A present `src/a.txt` would make the red row pass and mismatch, while an absent one is missing, so the table's three `none` cells cannot all hold with its stated results.
- `Cargo.lock` changed to record the run crate's new `osq-kernel-loop` dependency, as the task details said it would follow the manifest.

## Missing context

## Outside scope

- The delta spec table's `missingPaths` values for the three `test -f src/a.txt` rows were left untouched because the spec is outside the task's code scope.
