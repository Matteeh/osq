## Acceptance

- [ ] `Event` gains the variant `Approved(ApprovedData)` for the type `approved`, and `EventKind` gains `Approved` named `approved`, as the modified rust-core "Event types" says. `ApprovedData` holds `hash: String` and `targets: Vec<String>`, both required, with no other field.
- [ ] New `crates/core/tests/approved_event.rs` proves "Approved event lines", every row, and its doc names `Covers: rust-core/approved-event-lines`.
- [ ] Every existing core test passes unchanged, and so does every other crate: a new variant needs no edit outside core, because their matches already have a catch-all arm.
- [ ] Every new public item has full docs ending with `Implements: rust-core/event-types`, or `rust-core/event-kinds` for the kind. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Follow `RejectedData` and the `Rejected` arms in `event.rs` and `kind.rs`
for every place a variant is listed: the enum, `kind`, the payload value,
the parse match and `EventKind::name`. Put `ApprovedData` in `payload.rs`
with `rename_all = "camelCase"` and `deny_unknown_fields`, as the other
payloads have, and add it to the `pub use` list.

Only Rust writes this event; TypeScript never does. Put no TypeScript name
in its docs.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/325-rust-approve-steered`, so the link gates
see this change's new scenario.
