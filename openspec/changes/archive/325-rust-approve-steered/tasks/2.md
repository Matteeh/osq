## Details

`steering.rs` returns trigger strings today. Make each trigger a small value
with its target, kind and reason, shown as the requirement says, so approve
can name targets in the event, find default-branch triggers and print the
refusals. Add the `dead` fallback for a worktree change there.

`stack/changes.rs` already builds `change_trees` from `worktree_list` for
the stacking refusal. Build the lookup's trees the same way, with no stacked
folders, and carry the matching tree along, so approve knows whether the
change is in an osq worktree and where that worktree's root is.

For the steered path, reuse `change_folder_seal`, `write_marker`, `validate`,
and the commit and tree record code in `worktree.rs`. Build the `approved`
line with core's `Envelope` and `event_line`, as retry's `record.rs` builds
its `retry` line, and take the time from `reject/time.rs`. Read HEAD's marker
with rust-vcs `show` before you restore anything after a failed commit.

To build the repositories, reuse `worktree_support`'s public helpers as they
are, from the new test file. Port the rest of the case setup from the golden
script: the worktree on `osq/001-alpha-twice`, the folder moved out of the
checkout, the old seal and markers, the commit as `Osq Tester`, then the
uncommitted edit to `tasks/1.md`. Make the commit fail as the script does,
with an empty `index.lock` in the worktree's git folder. The test calls the
feature's `run`, so no event is delivered and no marker is cleared; the
goldens' trees show the state after retry, which only the CLI test in task 3
compares.

Never read anything under `src/` from Rust; it is in `entry` only so you
can port it. Never depend on the retry crate. When the mutation check
reports a missed mutant, add a test case for that line. Run the proposal's
verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/325-rust-approve-steered`, so the link gates
see this change's new requirement.
