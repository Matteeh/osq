## Details

`retry.rs`'s `finish` already runs the refusals, the record and the scope
recertification for one target. The reaction calls it for each target, with
the reaction's root, the tree root three folders above the change folder,
and the folder's name. It does not run `plan_edits::check`. Compare
timestamps as strings: both TypeScript and Rust write
`YYYY-MM-DDTHH:MM:SS.mmmZ` in UTC. Parse the target's stream with core's
`parse_event_line`, line by line, and treat a missing file as holding no
line.

The CLI test builds each repository as the golden script does: a copy of
`steered-repo` on `main` without `openspec/changes/001-alpha-twice`, a
worktree on `osq/001-alpha-twice` holding that folder with the old seal and
the case's markers, committed as `Osq Tester`, then the edit to
`tasks/1.md`. Give `git` a fixed identity through its config in the
repository, as `worktree_support` in the approve crate does; port what you
need into the new test file rather than importing it. The CLI crate has no
`serde_json` and its `Cargo.toml` is outside scope, so compare event lines
through core: parse each golden line and each written line with
`parse_event_line`, set every timestamp to `<timestamp>`, and compare the
envelopes. Compare every other line as text.

Never read anything under `src/` from Rust; it is in `entry` only so you
can port it. When the mutation check reports a missed mutant, add a test
case for that line. Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/325-rust-approve-steered`, so the link gates
see this change's new requirements.
