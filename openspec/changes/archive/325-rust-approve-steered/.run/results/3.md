## Changed

- `RetryFeature` now reacts to `EventKind::Approved` alone. Its `react` retries each of the event's targets that still has an active regressed or dead marker and no matching `retry` line at or after the event, through the same `finish` path the `retry` command uses, skipping the plan-edits check.
- Added `crates/features/retry/src/retry/reaction.rs` for the skip checks and event-stream parsing through core's `parse_event_line`.
- Added `crates/features/retry/tests/retry_reaction.rs` proving all rows of the five rust-retry scenarios, plus two extra cases for equality and older/other retry lines.
- Added `crates/apps/cli/tests/approve_steered.rs`, which builds each golden case's scratch repository, runs `approve 1` through `run_cli` with `features()`, compares stdout, commit, tree record and the `.run/` tree with the golden, then removes `.run/delivered/` and proves a second `status` delivery changes nothing.
- Copied `steered-repo` and `steered-golden` into the CLI crate's fixtures unchanged.
- `cargo fmt --all`, the task's verify, and `OSQ_CHANGE=openspec/changes/325-rust-approve-steered sh scripts/verify-rust.sh` pass. cargo-mutants by hand on the changed retry source files caught every mutant.

## Deviated

- The CLI scenario's second run names `status`, which no registered Rust feature lists. The test runs it anyway because `run_command` still delivers events after an unknown command; it does not assert the second run's output, only that the change's `.run/` files are unchanged.
- Added two mutation-focused reaction tests beyond the scenario tables: a retry at the event's exact timestamp is kept, and an older retry, a non-retry event, a malformed line and a retry for another target do not retire a target. Both are tagged `Covers: rust-retry/later-failures-are-kept`.
