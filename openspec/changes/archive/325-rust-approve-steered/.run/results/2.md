## Changed

- Copied the seven TypeScript goldens unchanged into `crates/features/approve/tests/fixtures/steered-golden/`.
- Replaced string triggers with typed `Trigger` values carrying target, kind and reason; added the worktree `dead` fallback, default-branch and running checks, and the default-branch/checkout refusal texts.
- Added `approve/lookup.rs`: git-off lookup still uses `list_changes`, while git-on lookup uses `list_tree_changes` over worktrees and carries the matching tree with each change. Worktree candidates are limited to osq branches with an active approved folder.
- Added `approve/steered.rs`: seals the revised plan, appends the typed `approved` event with the trigger targets, commits and records the worktree commit, rolls back the seal and event on a failed commit that did not land, and prints the worktree/branch/continues lines.
- Exposed the worktree commit-and-record helper in `worktree.rs`, and added a landed-commit check through `Vcs` `show`.
- Updated `approve_steering.rs` to the full modified table, and added `approve_steered.rs` for every worktree approval and refusal row. Added a done-plus-dead fallback case and a landed-commit case for mutation coverage.
- `cargo test` for the task's six targets, `cargo fmt --all`, `OSQ_CHANGE=openspec/changes/325-rust-approve-steered sh scripts/verify-rust.sh`, and cargo-mutants over the changed approve files all pass with no missed mutant, including a final rerun after the lookup adjustment.

## Deviated

- Git-on lookup filters worktree candidates to osq branches whose active change folder is already approved before calling `change_trees`. This keeps the existing "checked out rejected branch" refusal, which expects the checkout's active change to still be found, while still finding changes approved into their worktrees.
- Added a test where a failed commit's seal is already at HEAD, so the landed branch is exercised and the success path is not rolled back.
