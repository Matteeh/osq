## Changed

- Added `src/core/report/query-recertifications.ts`: `RECERTIFICATION_TABLES`
  holding `recertifications(change, task, recertified_at, outcome, automatic,
  path, credited_to, source)` and `insertRecertifications`, modeled on
  `PAUSE_TABLES`/`insertPauses`. It reads each archived subject's digit-named
  task streams in numeric order with `readEventStream`, takes `data` with
  `asData`, and emits one row per attribution entry of each `recertification`
  event. `source` is `measures` on `source: "measures"`, else `file_changed`
  when the entry's `attribution` is a task number, else null. A non-object
  `data`, or a non-array `data.attribution`, adds no row; a non-object entry
  adds no row; a wrong-typed field reads as null; `automatic` is 1 only when
  `data.automatic === true`. The insert function carries the three
  `@scenario metrics-and-reporting:` lines and `@adr 008`.
- `src/core/report/query-tables.ts`: import and spread `...RECERTIFICATION_TABLES`
  right after `...PAUSE_TABLES` in `HISTORY_TABLES`, and call
  `insertRecertifications(db, subjects)` right after `insertPauses`.
- `tests/query-command.test.ts`, `tests/query-trial-tables.test.ts`: added the
  `recertifications(...)` line after `pauses(...)` in their table lists.
- `tests/query-tables.test.ts`: added the `recertifications` table entry with
  its columns after `pauses`.
- `tests/query-pauses.test.ts`: the "Pauses listed" case now asserts the new
  wording — `pauses(...)` directly after `task_outcomes` and no longer last.
- Added `tests/query-recertifications.test.ts`, running the real `osq query`
  command as `tests/query-pauses.test.ts` does, proving "Recertifications of
  one archived change", "No recertifications", "Recertifications listed" and
  "Pauses listed" in its new wording.

## Missing context

The task asked for a `@scenario` line "per scenario it serves"; the table-list
scenario ("Recertifications listed") is really served by `RECERTIFICATION_TABLES`
and `query-tables.ts`, not by the insert function. I tagged the insert function
with all three recertification scenarios since it is the module's only exported
function and `RECERTIFICATION_TABLES` is a const that existing siblings leave
untagged.
