# Task 5 — Spawn module and runner orchestration

Status: complete. All acceptance lines satisfied; verify command passes.

## Changed

- `src/watcher/spawn.ts` (new, 194 lines)
  - Moved `formatTaskStartedLine` (plus the private `ELLIPSIS` /
    `truncateToWidth` helpers) out of `runner.ts`.
  - Added `spawnTaskAgent`: coordinates `adapter.spawn`, hooks `onSpawn` to emit
    exactly one `started` event carrying build identity from `resolveBuildInfo`,
    records the `exited` event, and on a non-zero exit or timeout writes the
    `dead` marker/event and returns a failure `RunTaskResult`. Marker text and
    event payloads are byte-for-byte the same as the previous inline block.
  - Added `ensureTaskResult`: checks for `.run/results/<n>.md`, synthesizes it
    from the agent's final stream message when missing, or reports `no_result`.
    It derives `runDir` from `specFolderPath` and imports the verify helpers.
  - `spawnTaskAgent` derives `runDir`, `timeoutSeconds`, and `useSymbols` from
    its inputs so the runner call site stays small.
- `src/watcher/runner.ts` (rewritten, 193 lines, was 410)
  - Now imports from `./lock.js`, `./heartbeat.js`, `./spawn.js`, `./verify.js`,
    and `./outcome.js` and reads as the sequential pipeline: approval/hash and
    task-file validation, `acquireTaskLock`, heartbeat timer, test snapshot,
    `spawnTaskAgent`, test-modification gating, `ensureTaskResult`,
    `runVerificationGate`, completion recording, and the `finally` cleanup
    (stop heartbeat, clear stats, release lock).
  - Added a small local `fail(reason, marker, error, extra?)` helper that
    centralises `writeDeadMarker` + `recordDeadEvent` + `logOutcome` +
    `{ success: false, reason, error }`. Dead-marker contents and event order
    are unchanged.
- `tests/import-graph.test.ts`
  - Added `runner lifecycle module line budget` suite asserting `lock.ts`,
    `spawn.ts`, `heartbeat.ts`, `verify.ts`, `outcome.ts`, and `runner.ts` are
    each strictly under 200 lines (same counting method as the existing
    per-module budget tests).

## Deviated

- The task detail lists `startTaskHeartbeat` (heartbeat.ts), `ensureTaskResult`
  (verify.ts), and `recordTaskCompletion` (outcome.ts) as runner imports.
  Those orchestrators did not exist after tasks 2–4, and this task's scope only
  permits `spawn.ts`, `runner.ts`, and `tests/import-graph.test.ts`. To stay
  inside scope I placed `ensureTaskResult` in `spawn.ts` (it is the agent-result
  phase and depends on `verify.ts`) and kept the heartbeat timer inline in
  `runner.ts` (it consumes `heartbeat.ts` helpers). No `recordTaskCompletion`
  wrapper was added; the done-marker/event/checkbox sequence stays inline in
  `runner.ts`, which is still under budget.
- `formatTaskStartedLine` was removed from `runner.ts` rather than re-exported;
  no source or test imports it from `runner.js`.
- Blank/comment-heavy blocks were tightened to meet the hard 200-line budget;
  this is the only reason runner is not near the ~120 target.
