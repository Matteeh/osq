## Acceptance

- [ ] `ManifestData` declares optional `createdAtSource: 'created'` and makes `approvedAt` optional. `buildManifest` sets `approvedAt` to the current time only when it receives approval flags, so `writeBriefAndManifest` in `src/cli/plan-queue.ts` writes no `approvedAt`.
- [ ] `buildManifest` keeps an existing `.run/manifest.json` `createdAt` that parses as a date, together with its `createdAtSource` when that is `created`, and never adds the marker to an unmarked one.
- [ ] Without a usable existing `createdAt`, `buildManifest` uses the change folder's birth time with `createdAtSource: 'created'` when the birth time is valid and later than the epoch, and otherwise the current time, marked `created` only when no approval flags were passed.
- [ ] New `tests/manifest-creation.test.ts` calls `writeBriefAndManifest` on a new change and asserts a valid `createdAt`, `createdAtSource: 'created'`, and no `approvedAt` key.
- [ ] The same file approves that change with `approveSpec`, edits its proposal, and approves again. Both manifests keep the plan-time `createdAt` and marker, and each carries an `approvedAt` no earlier than the previous one.
- [ ] The same file asserts that approving a change whose manifest holds an unmarked `createdAt` keeps that value without a marker, and that approving a change with no manifest records the folder's birth time marked `created`; skip only that last assertion when `fs.stat` reports a zero birth time.
