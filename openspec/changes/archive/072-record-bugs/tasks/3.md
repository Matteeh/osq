## Acceptance

- [ ] New `src/core/report/brief-to-approval.ts` exports `readBriefToApprovalSeconds(folderPath: string): Promise<number | null>`: seconds from a manifest `createdAt` marked `createdAtSource: "created"` to `readManifestApprovedAt`, null when either is missing or invalid or approval precedes creation. `readApprovedAtMs` in `report.ts` also reads `readManifestApprovedAt`, and the unused brief date readers go away.
- [ ] New `src/core/report/scope-size.ts` exports `taskScopeSize(events, startScopeFiles: number): number`: the key count of `scopeHashes` on the last `measures` end event that carries an object there, else `startScopeFiles`. `deriveMeasuredTask` uses it for `scopeFiles`.
- [ ] `RepositoryRecord` replaces `firstAttemptPassRate` with `firstAttemptPasses`, and `formatRepositoryRecordBody` prints `First-attempt passes: <firstAttemptPasses>/<measuredTasks>`. The too-small sentence is unchanged.
- [ ] A cycle phase with no covered archived change prints `not reported (0 of <m> archived changes)` in `formatMetricsReport` text.
- [ ] New `tests/report-record-accuracy.test.ts` covers, through `getMetricsReport` and `getRepositoryRecord` on temp projects: brief to approval with a marked manifest, null without the marker, null approval without `.run/approved`; a task whose start event has `scopeFiles: 0` and end event lists five created files sized 5 in buckets, largest pass, and record; a task without an end event sized by `scopeFiles`; and eight first-attempt passes printing `First-attempt passes: 8/8`.
- [ ] `fixture/report/` archived changes with a manifest gain `.run/approved`, and `fixture/report/expected.json` is regenerated from `reportCommand` with `json: true`; its diff touches only cycle and scope-size values.
- [ ] `tests/report-cycle.test.ts`, `tests/report-sizes.test.ts`, and `tests/plan.test.ts` change only their manifest setup and their assertions on brief to approval, scope sizes, `firstAttemptPassRate`, and the rate line.
