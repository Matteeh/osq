## Acceptance

- [ ] New `src/core/run/manifest-approval.ts` exports `readManifestApprovedAt(changeFolder: string): Promise<string | null>`, which returns the manifest's `approvedAt` when it parses as a date and `getApprovedMarkerPath(changeFolder)` exists, and null for a missing marker, a missing or malformed manifest, or an invalid value.
- [ ] `readApprovedAt` in `src/watcher/auto-retry.ts` is replaced by `readManifestApprovedAt`, `readManifestMetadata` in `src/core/web/web-data-lifecycle.ts` fills `approvedAt` from it, and `manifestApproval` in `src/core/report/planning-slice-lookup.ts` returns it.
- [ ] New `tests/manifest-approval-gate.test.ts` covers `readManifestApprovedAt` with and without `.run/approved`, and for a malformed manifest.
- [ ] The same file builds a project with one active change whose manifest has `approvedAt` and no `.run/approved`, and asserts that its node from `getWebGraph` has `approved: null`, then that it is the manifest's value once `.run/approved` exists.
- [ ] The same file asserts that `resolveChangeApprovalTime` returns null for a change whose manifest has `approvedAt` and no `.run/approved`, returns that time once the marker exists, and still returns the `.run/rejected.md` timestamp for a rejected change with no recorded slice.
- [ ] `tests/planning-slice.test.ts` and `tests/planning-slice-archive.test.ts` change only by writing `.run/approved` wherever they write a manifest `approvedAt` for a change they treat as approved.

## Details

`src/core/run/manifest-approval.ts` imports only `node:` modules and
`src/core/status/layout.ts`. `auto-retry.ts` only runs for approved changes, so
its existing tests in `tests/auto-retry.test.ts` must stay green unchanged.
`tests/planning-slice-archive.test.ts` shows how to set up a rejected change.
