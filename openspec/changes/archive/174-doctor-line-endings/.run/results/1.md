## Changed

- `src/core/vcs/vcs.ts`: added the exported `VcsLineEnding` interface (`path`, `index`) and `lineEndings(): Promise<VcsLineEnding[]>` on the `Vcs` port.
- `src/core/vcs/git-vcs-read.ts`: added `lineEndings(ctx)`, which runs `ls-files --eol -z` through `ctx.run` (so `timeouts.gitSeconds` bounds it), returns `[]` on a non-zero exit, and parses each NUL-separated record's path from after its tab and its index from the first field's text after `i/`.
- `src/core/vcs/git-vcs.ts`: delegates `lineEndings()` to the read beside the other reads; still 247 lines, under the 250-line budget.
- `src/core/vcs/no-vcs.ts`: `lineEndings()` returns `[]`.
- `tests/vcs-write.test.ts`: added `'lineEndings'` to `PORT_MEMBERS`; nothing else changed.
- `tests/vcs-line-endings.test.ts`: new scenario tests for `version-control` "Index line endings of a temporary repository" (all four table rows on a temp repo with `core.autocrlf` false, only the four files staged) and "Line endings without git", using the `scenario` helper and the same git-call environment as `tests/vcs-path-exists.test.ts`.
