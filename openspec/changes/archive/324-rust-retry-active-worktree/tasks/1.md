## Details

`find.rs` already lists trees for archived changes. With git on, build the
tree listing once, take the first active match from it, and keep the
archived lookup for when none matches. Carry the matching `ChangeTree`
along, so the plan-edit check and the recertification know the tree root.
The tree whose `folder` is `None` is the root's own tree, and it is never
checked for plan edits.

`recertify::run` takes one `root` today and uses it for config, the verify
folder and the scope hash. Split it: config from the project root, and the
verify folder and scope hash from the tree root. For a checkout change the
two are the same folder, so the recertification goldens stay as they are.

`archive_commit.rs` already reads rust-vcs `status` entries, `path` and
`from`, relative to a tree root. Read them the same way for the plan-edit
check.

`tests/support/mod.rs` is outside scope. Use its public helpers as they are,
and put any new helper in `retry_active.rs` itself.

Port the test repository from `retry_archived.rs` and the golden script: a
repository on `main`, one worktree per fixture folder on `osq/<folder>`,
and the case's edits. Run git with a fixed author through
`-c user.name=osq -c user.email=osq@example.com` and `commit.gpgsign=false`,
since the test machine may have no git identity. Set no HOME and no stacked
folders; Rust lists none.

Never read anything under `src/` from Rust; it is in `entry` only so you
can port it. When the mutation check reports a missed mutant, add a test
case for that line. Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/324-rust-retry-active-worktree`, so the link
gates see this change's new requirements.
