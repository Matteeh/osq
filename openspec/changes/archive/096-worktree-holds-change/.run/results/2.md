## Changed

- `src/core/spec/stack-cut.ts`: dropped `removeFailedWorktree` and the
  `try`/`catch` in `cutStackedChange`. A failed cut now rethrows and leaves
  the branch, the worktree it added, and the stacked approval in place, so a
  later cut reuses them. The branch and worktree are created only when
  missing, so the retry reuses what exists.
- `tests/stack-cut-kept.test.ts`: new test with its own copied
  `makeProject`/`ActingAdapter`/prepare-script helpers. It runs the "Cut
  fails and resumes" scenario through `runWatcherOnce` and `retrySpec`:
  after the failed cycle it asserts the `stack_cut_failed` marker, the kept
  stacked approval, the existing worktree directory, `git worktree list`
  naming that path on `osq/002-b`, and no `osq: 002 approved` commit yet.
  After the retry it asserts the same path still exists and is listed, that
  the branch has exactly one `osq: 002 approved` commit, that the stacked
  approval is gone, and that the spawned task wrote its scoped file inside
  the reused worktree.
