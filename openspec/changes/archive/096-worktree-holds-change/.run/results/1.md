## Changed

- `src/core/status/change-locations.ts`: added `holdsChange`, which checks
  `<changes>/<folder>/.run/approved`, `<archive>/<folder>`, then
  `<rejected>/<folder>` with one `fs.stat` each and stops at the first that
  exists. `changeTrees` now adds a worktree tree, and records its folder in
  `namedByWorktree`, only when the worktree holds its change; a worktree that
  does not hold it therefore hides neither the checkout's copy nor a stacked
  tree of the same folder. Exported the existing `matchesFolder`.
- `src/core/spec/stack-dependencies.ts`: imported `matchesFolder` from
  `change-locations.js` and removed the local duplicate.
- `tests/change-locations-stacked.test.ts`: the "prefers a worktree over a
  stacked directory for the same folder" test now writes `.run/approved` into
  the worktree's copy of `002-b`.
- `tests/serve-sse-worktrees.test.ts`: the "passes the resolved worktree trees
  to the invalidation hub" test now writes `.run/approved` into the worktree's
  copy of `001-a`.
- `tests/change-locations-holds.test.ts`: new, covering the delta's
  "Worktree without its change", "Worktree with an unapproved copy", and
  "Archived or rejected in its worktree" scenarios through `changeTrees`,
  `listChanges`, and `findChange`, on temporary repositories with real
  `git worktree add` on `osq/` branches and stacked directories written the
  same way `tests/change-locations-stacked.test.ts` does.

## Deviated

- In the "worktree without its change" test I cut `osq/002-b` from a baseline
  commit made before `002-b` existed, then committed `002-b` to the checkout.
  The branch-from-the-same-commit setup of the pinned stacked test would have
  left the folder present in the worktree (the "unapproved copy" case instead).
