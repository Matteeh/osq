## Changed

- Added `src/cli/inbox-actions.ts` with `ActionInputs`, `CardAction`, and
  `createActionLauncher(inputs, actions?)`. The launcher runs a card verb's
  command function in-process, maps `approve`, `plan`, `retry`, `reject`, and
  `show` to `approveCommand`, `planCommand`, `retryCommand`, `rejectCommand`,
  and `showCommand`, prints a `CommandError` as `runCli` does (message then
  `Next:`), prints `Error: <message>` for any other throw, prints
  `osq inbox: no action for <arguments>` when no entry fits, and never touches
  `process.exitCode` or rejects.
- `src/cli/inbox-dispatch.ts` now defaults `launch` to
  `createActionLauncher({ cwd, config, stdout, stderr })`.
- `src/cli/inbox-terminal.ts` dropped `createChildLauncher`, its `bin`
  lookup, and the `node:child_process` / `node:url` imports. `createTerminalInput`
  now resumes the stream when each key or line read starts and removes its
  listeners and pauses the stream when the read ends.
- `tests/inbox-cards.test.ts` dropped the `createChildLauncher` import and its
  describe block; nothing else changed.
- Added `tests/inbox-in-process.test.ts` covering show in the same process,
  failed approve carrying on, terminal state between reads, each verb reaching
  its command, non-`CommandError` failures, a null-returning unmatched verb, and
  that the three call-path files do not import `node:child_process`.
- `README.md`'s Human Attention Inbox card paragraph now lists `a` approve,
  `p` plan, `r` retry, `x` reject, `s` show, `n` skip, `q` quit, says a key
  runs its command inside the same `osq inbox` process on the same terminal and
  prints its error and next step on failure, keeps the land-copy note, and
  drops the child process wording and the `c` / `p` verified / `f` keys.

## Outside scope

- The living `openspec/specs/cli-foundation/spec.md` still carries "Inbox cards
  on a terminal"; the watcher applies the change's delta at archive, so I left
  it alone.
