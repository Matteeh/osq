## Acceptance

- [ ] New `src/cli/inbox-actions.ts` exports `createActionLauncher(inputs, actions?)` and the types below, and maps `approve`, `plan`, `retry`, `reject` and `show` to `approveCommand`, `planCommand`, `retryCommand`, `rejectCommand` and `showCommand` as "Inbox card actions run in-process" says, writing a `CommandError`'s message and `Next:` line the way `runCli` in `src/cli/run.ts` does, `Error: <message>` for any other thrown value, and `osq inbox: no action for <arguments>` for arguments no entry fits. ## Ports

```ts
export interface ActionInputs {
  cwd: string;
  config: OsqConfig;
  stdout: Writer;
  stderr: Writer;
}

/** Runs one card verb with the arguments after it, or returns null when they do not fit. */
export type CardAction = (args: readonly string[], inputs: ActionInputs) => Promise<void> | null;

export function createActionLauncher(
  inputs: ActionInputs,
  actions?: Readonly<Record<string, CardAction>>,
): Launcher;
```

`Launcher` is the existing type in `src/core/status/dispatch-session.ts`, and
`Writer` the one in `src/cli/command-inputs.ts`. Look up the verb with
`Object.hasOwn` so a verb such as `constructor` matches no entry.

## Details

Read the requirement "Inbox card actions run in-process" in this change's
`specs/cli-foundation/spec.md`; it is the contract.

For the session tests, build the project the way `tests/inbox-cards.test.ts`
does (a change folder `001-...` with `proposal.md` and `tasks/1.md`, no
validator), pass `isTerminal: () => true`, a scripted `input`, `home` set to a
temporary folder, a silent `sound`, collecting `stdout` and `stderr` writers,
and no `launch`. Approving that change fails, which is the failed approve.
Point `CODEX_HOME`, `OSQ_CLAUDE_PROJECTS_DIR`, `CLAUDE_CONFIG_DIR` and
`OPENCODE_PATH` at missing folders under the temporary root, as
`tests/command-error-approve.test.ts` does, and restore them after. Save
`process.exitCode` before the failed approve and restore it after the test.

For `plan 001`, set the project up with `scaffoldProject` and `createNewSpec`
and write a `brief.md` in the change folder. The prompt handoff line contains
`ask your planning tool to plan change 001-`. Never run `plan` for an id
without a folder: it creates a change.

For terminal between reads, use a `PassThrough` with a recording `setRawMode`,
like `recordingStream` in `tests/inbox-cards.test.ts`, write `sq` to it before
the session starts, and have the injected `launch` record `isPaused()`,
`listenerCount('data')`, and the last raw mode when it is called.

The card session, `cardKeys`, and the `── <label> ──` and `── exit <code> ──`
lines in `src/core/status/dispatch-session.ts` stay as they are.
