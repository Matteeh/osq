## Acceptance

- [ ] New `src/core/vcs/snapshot.ts` captures the git state and the hashed status entries through the `Vcs` port, and compares two captures into `moved` and the files changed during the task. It never runs git itself.
- [ ] New `src/watcher/git-guard.ts` selects through `selectVcs`, captures before spawn, and after the agent exits appends the events and logs the warnings of the watcher-and-harness delta's "Git state recording" and "Scope violation recording".
- [ ] `runTask` starts the guard right before `spawnTaskAgent` and checks it right after, before its `ok` test. Each is one statement.
- [ ] `src/harness/types.ts` gains the `vcs_violation` and `scope_violation` event types with `VcsViolationEventData` and `ScopeViolationEventData` in `OsqEventData`.
- [ ] New `tests/vcs-guard.test.ts` runs real tasks through `runWatcherOnce` in temporary git repositories, with a fake adapter whose spawn runs git or edits files. It covers every scenario of both requirements and the proposal's "Agent commits and verify passes".

## Details

Resolve scope with `resolveScope`, as `captureTestGate` does, but after the
agent exits so files a glob matches that the agent created count as in scope.
Exclude every path inside the change folder, which also covers
`.run/results/<n>.md` and the watcher's own writes. Hash with the existing
content hasher `verify.ts` uses. The hints in the `vcs_violation` warning are
text for the human, and osq runs none of them. For example: HEAD moved, so
`git reset --soft <before>`; branch changed, so `git switch <before>`; stash
added, so `git stash pop`; index changed, so `git restore --staged <paths>`.

`runTask` is grandfathered in `tests/function-budget.test.ts`, and `runner.ts`
has room for the import and two statements. `tests/focused-verify.test.ts`
shows a watcher run with a custom adapter. Initialise each temporary
repository with a committed `.gitignore` for `.run/running/`. Approve its change
after the initial commit, so the fake agent's edits are the only differences.
New files stay within 250 lines and new functions within 80.
