## Changed

- Added `src/core/vcs/snapshot.ts`: `captureSnapshot(vcs, projectRoot)` reads
  HEAD commit/branch, the index digest, the stash list, and status through the
  `Vcs` port, and hashes every status-listed file (null for a deleted file). It
  never runs git. `compareSnapshots(before, after)` returns `moved` (any of
  `head`, `branch`, `index`, `stash` whose value differs) and `changedFiles`
  (paths listed before or after whose code or hash differs, sorted).
- Added `src/watcher/git-guard.ts`: `beginGitGuard` selects through `selectVcs`,
  returns null under `NoVcs`, and captures before spawn; its `check` captures
  after exit, then appends one `vcs_violation` event with `moved`/`before`/`after`
  and one `scope_violation` event whose `files` are the changed files outside the
  post-exit resolved scope and outside the change folder, logging a warning for
  each. A failed read logs `git state not recorded` and records nothing.
- `src/watcher/runner.ts`: import plus `const gitGuard = await beginGitGuard({ ...verifyCtx, scope: taskData.scope })`
  right before `spawnTaskAgent` and `await gitGuard?.check()` right after, before
  the `ok` test.
- `src/harness/types.ts`: added `vcs_violation` and `scope_violation` to
  `HarnessEventType` and `OsqEventData`, with `VcsViolationEventData` and
  `ScopeViolationEventData`.
- Added `tests/vcs-guard.test.ts` (8 tests) running real tasks through
  `runWatcherOnce` in temporary repositories with a `ActingAdapter` whose spawn
  runs git or edits files: commit, stash, branch checkout, stage, outside git,
  edit outside scope, dirty file left alone, dirty file edited again. It reads
  the archived task event stream and asserts the events, values, warnings, and
  that every task still lands.
- Verifies: `node --import tsx --test tests/vcs-guard.test.ts` → 8/8 pass;
  `pnpm verify` → exit 0.

## Deviated

- The task states `runner.ts` has room for the import and two statements, but
  `tests/import-graph.test.ts` enforces `src/watcher/runner.ts` strictly under
  200 lines and the baseline was 199. A multi-line `beginGitGuard` call would
  have pushed it to 209, so I compressed the adjacent `spawnTaskAgent` call to
  `{ ...verifyCtx, adapter, logOutcome }` and the guard call to
  `{ ...verifyCtx, scope: taskData.scope }`. Both are behavior-preserving; the
  file is now 193 lines and both statements the acceptance asks for remain one
  statement each.
- `src/core/vcs/snapshot.ts` uses the same SHA-256 content hash as `verify.ts`'s
  `hashFileContent`, implemented locally rather than imported because `verify.ts`
  lives under `src/watcher` and core cannot import watcher modules.
