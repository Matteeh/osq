## Changed

- `src/core/run/verification.ts`: `runVerificationCommand` imports
  `relativizeToolSummary` and returns `output: relativizeToolSummary(output, projectRoot)`,
  so every gate, `verify_ran` event, dead/regressed marker, and prior-failure
  context reads project-relative paths. The doc comment says so.
- `src/watcher/archiver.ts`: `archiveSpecFolder` computes
  `path.relative(projectRoot, targetPath)` (POSIX separators) and records it as
  the `archived` event's `archivePath`; `ArchivedEventData`'s comment says the
  path is relative to the project root. The function still returns the absolute
  `targetPath`.
- `tests/relative-paths.test.ts` (new): two tests through `runWatcherOnce`
  against temporary projects. A failing task verify that prints
  `<root>/src/a.ts` records `src/a.ts` (and not the root) in its `verify_ran`
  event and in `.run/dead/1.md`. An archived change records
  `archivePath: openspec/changes/archive/001-relative-archive`.
- `tests/archiver.test.ts`, `tests/verification-record.test.ts`: the two
  `archivePath` expectations are now `path.relative(root, archived)`.
- `tests/focused-tests.test.ts`, `tests/osq-change-env.test.ts`: the
  `OSQ_CHANGE` output expectations are now the change folder relative to the
  project root (the environment variable itself stays absolute).
