## Changed

- Added `src/core/vcs/doctor-git.ts`: `checkGit(projectRoot, config, options?)`
  returns the `git` check plus the `git-env` check when `GIT_DIR`,
  `GIT_INDEX_FILE` or `GIT_WORK_TREE` is set. It selects through `selectVcs`
  and reads the version through `probeVersion`, bounded by
  `timeouts.gitSeconds`. A selected `GitVcs` gives `[ok] git: <version>`; a
  `NoVcs` gives a passing warning `<reason>; git checks off`. `git-env` names
  each variable set and says osq's own git reads ignore them while verify
  commands and hooks do not. An optional `gitBinary` parameter lets tests
  simulate an absent git.
- `src/core/foundation/doctor.ts`: added the `../vcs/doctor-git.js` import and
  one spread `...(await checkGit(projectRoot, config))` right after the
  `validator` check. The file stays at its 250-line budget.
- Added `tests/vcs-doctor.test.ts` (5 tests): repository root reports git's
  version, an absent binary warns `git not found; git checks off`, a plain
  folder warns `not a git repository; git checks off`, `GIT_DIR` set adds a
  `git-env` warning naming it, and `doctorCommand` keeps exit code 0 with only
  those warnings. `GIT_DIR`/`GIT_INDEX_FILE`/`GIT_WORK_TREE` are saved and
  restored around every test that sets them.
- Pinned lists updated: `tests/doctor.test.ts` gained `git` after `validator`
  and its `doctorCommand` test now expects 8 checks/lines and allows the
  `[warn] git:` prefix; `tests/pi/doctor.test.ts` gained `git` in both lists;
  `tests/codex/adapter.test.ts` expects 8 output lines.
- Verifies run: `node --import tsx --test tests/vcs-doctor.test.ts` → 5/5 pass;
  `pnpm verify` → exit 0 (typechecks, build, full suite, lint).

## Deviated

- Passed the absent-git seam as the new check's optional `gitBinary`
  parameter instead of a `DoctorDependencies` field. The task allowed either;
  the parameter keeps `doctor.ts` within its two-line budget.
