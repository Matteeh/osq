## Acceptance

- [ ] `GatesConfig` and `DEFAULT_GATES_CONFIG` gain `providerStallSeconds` (300), `providerRetries` (3) and `providerRetryDelaySeconds` (300). `validateGatesConfig` keeps each missing key's default and rejects any value that is not a non-negative integer with `gates.<key> must be a non-negative integer`.
- [ ] `RunTaskFailureReason` gains `provider_unavailable`.
- [ ] New `src/watcher/provider-outage.ts` finds an attempt's open provider retry by the rule in the delta "Provider outage deaths": events after the last `started`, a `harness_retry` start with no later end carrying `success: true`, keeping the start time of the first open start and the error of the latest.
- [ ] When the agent crashes or times out and the attempt has an open provider retry, `spawnTaskAgent` writes the dead marker `reason: provider_unavailable`, `exit_code`, and the body `The model provider did not answer: <error>` (or `no error reported`), and records a `dead` event with that reason. Without one, the `crashed` and `timeout` markers, events and log lines stay byte-identical.
- [ ] While the agent runs, `spawnOrCrash` checks the task's event stream on a `setTimeout` chain, every `log.heartbeatSeconds` or `gates.providerStallSeconds`, whichever is smaller and positive, and sends SIGTERM to the agent's pid once an open provider retry is at least `gates.providerStallSeconds` old. The timer stops when the agent exits, and `gates.providerStallSeconds: 0` starts no timer.
- [ ] `src/watcher/spawn.ts` stays under 200 lines; move the dead-marker text for `crashed`, `timeout` and `provider_unavailable` into `provider-outage.ts`.
- [ ] `tests/provider-outage.test.ts` covers each line above through `spawnTaskAgent` with a mock adapter that appends `harness_retry` events, including a stream shaped like 135's (a zero-token `tokens` event, an open start with DeepSeek's error, then a timeout) and one where the retry ended with `success: true` before the timeout.

## Details

Reuse `appendHarnessEvent` and the `HarnessRetryEventData` type from
`src/harness/types.ts`, and `writeDeadMarker` and `recordDeadEvent` from
`outcome.ts`. `spawnOrCrash` is the only caller of `adapter.spawn` for tasks,
and it already receives `specFolderPath`, `taskNumber`, `config` and `onSpawn`;
wrap `onSpawn` to learn the pid and keep calling the original.

Use a `setTimeout` chain, not `setInterval`: `tests/watcher-heartbeat.test.ts`
expects exactly one interval while a task runs. Call `unref()` on each timer.

Don't change `auto-retry.ts`; task 2 makes the new reason retryable. Until
then a `provider_unavailable` death waits for `osq retry` like any ineligible
reason.

`src/core/foundation/config.ts` is at 249 lines; leave it alone. The keys live
in the gates block.
