## Acceptance

- [ ] New `src/core/status/pre-spawn-words.ts` exports a pure `formatPreSpawnStart(expected: string, exitCode: number, missingPaths: readonly string[]): string`. The start is red when `exitCode` is not 0 or `missingPaths` is non-empty: `started red: <paths joined by ", "> missing` with paths, else `started red: verify fails`. A green start reads `started green, as declared`.
- [ ] A red start declared `green`, or a green start declared `red`, drops `, as declared` and appends `, but it declared <expected>`, giving `started green, but it declared red` and `started red: verify fails, but it declared green`. `any` never gets that suffix.
- [ ] `runPreSpawnVerify` in `src/watcher/task-verify.ts` logs `task <n> <formatPreSpawnStart(...)>` once per pre-spawn run under `warn` and `fail`: at info level when `isPreSpawnMismatch` is false and at warn level when it is true. `formatPreSpawnWarning` is removed. The event data, the dead marker, and the returned outcome are unchanged.
- [ ] `formatPreSpawnVerify` in `src/core/status/show.ts` prints `      Pre-spawn verify: <formatPreSpawnStart(...)>` from the latest pre-spawn event's `expected`, `exitCode`, and valid `missingPaths`, and `      Pre-spawn verify: unavailable` when `exitCode` is not finite or `expected` is empty. `formatMissingPaths` goes if unused.
- [ ] New `tests/pre-spawn-words.test.ts` covers every wording above for `formatPreSpawnStart`, then runs a watcher cycle on a temp project with `MockAdapter` and asserts the logged line for a task whose verify names a missing test file, one whose verify fails, one declared green that passes, and one declared red that passes.
- [ ] `tests/pre-spawn-verify.test.ts`, `tests/show-pre-spawn.test.ts`, and `tests/show-pre-spawn-missing.test.ts` change only their expected log and show text.

## Details

`src/core/status/pre-spawn-words.ts` imports nothing from `src/watcher/`. The
existing watcher tests in `tests/pre-spawn-verify.test.ts` show how to set up
temp projects with each `verify_starts` value and capture the logger.
