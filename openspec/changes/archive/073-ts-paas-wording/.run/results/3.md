## Changed

- Added `src/core/status/pre-spawn-words.ts` exporting the pure
  `formatPreSpawnStart(expected, exitCode, missingPaths)`, which words a
  pre-spawn start as `started red: <paths> missing`, `started red: verify
  fails`, or `started green, as declared`, appending `, but it declared
  <expected>` on a mismatch (never for `any`).
- `src/watcher/task-verify.ts`: removed `formatPreSpawnWarning`; `runPreSpawnVerify`
  now logs exactly one `task <n> <start words>` line per pre-spawn run under
  `warn` and `fail`, at info level for a match and warn level for a mismatch.
  Event data, dead marker, and outcomes are unchanged.
- `src/core/status/show.ts`: `formatPreSpawnVerify` now prints
  `      Pre-spawn verify: <formatPreSpawnStart(...)>` from the latest pre-spawn
  event's `expected`, finite `exitCode`, and valid `missingPaths`, or
  `      Pre-spawn verify: unavailable` for a missing exit code/declared state.
  Removed `formatMissingPaths` and added `validMissingPaths`.
- New `tests/pre-spawn-words.test.ts` covers every wording for
  `formatPreSpawnStart` and runs four watcher cycles over `MockAdapter` for the
  missing-test-file, verify-fails, declared-green-passes, and
  declared-red-passes cases.
- `tests/pre-spawn-verify.test.ts`, `tests/show-pre-spawn.test.ts`, and
  `tests/show-pre-spawn-missing.test.ts`: expected log and show text updated to
  the new wording only.

Task `verify` (`node --import tsx --test tests/pre-spawn-words.test.ts`) and the
proposal `verify` (`pnpm verify`) both pass.

Touched: src/core/status/pre-spawn-words.ts, src/watcher/task-verify.ts, src/core/status/show.ts, tests/pre-spawn-words.test.ts, tests/pre-spawn-verify.test.ts, tests/show-pre-spawn.test.ts, tests/show-pre-spawn-missing.test.ts
