## Changed

- `src/core/foundation/init.ts`: `InitResult` gains `refreshedFiles` and
  `currentFiles`. Added `writeOrRefreshFile`, which creates a missing file,
  classifies an existing unchanged file, or overwrites a differing one, and
  keeps `scaffoldProject` under the function budget. `scaffoldProject` now takes
  `{ refreshSchema?: boolean }`; only the six `bundledTemplates` honor the flag.
  Byte comparison is `Buffer.equals` against the UTF-8 template bytes.
- `src/cli/init.ts`: `initCommand` accepts `refreshSchema` and prints
  `  refreshed <file>` and `  current   <file>` lines after the `created` and
  `exists` lines, leaving existing output and order unchanged.
- `src/cli/index.ts`: `osq init` declares `.option('--refresh-schema', ...)` and
  passes it through.
- `README.md`: documents `osq init --refresh-schema` next to `osq init` in the
  command list and warns that it overwrites local edits to the six files.
- `tests/init-refresh-schema.test.ts`: new test file covering the stale refresh,
  the fully current mtime-preserving run, the deleted-file create, the plain
  rerun under `existingFiles`, and captured `initCommand` output for refresh and
  non-refresh runs.

## Deviated

- Byte comparison is done with `Buffer.equals(Buffer.from(content, 'utf8'))`
  rather than reading the template as a raw buffer, since the template content
  is already loaded as UTF-8 for writing. For these text templates this is
  byte-equivalent.
- Added a sixth test asserting the no-flag output has no `refreshed`/`current`
  lines, beyond the four required cases.
