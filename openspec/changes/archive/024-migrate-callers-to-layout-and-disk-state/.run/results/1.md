# Task 1 — layout resolvers and dual-signature deriveSpecState

## Changed

- `src/core/state.ts`
  - Fixed the pure snapshot branch: it destructured `folderPath: fPath` and originally
    returned the outer (undefined) `folderPath` parameter, which both failed `tsc`
    (`Type 'string | undefined' is not assignable to type 'string'`) and produced a
    snapshot state with a `undefined` folder path. It now returns `folderPath: fPath`.
  - Removed the now-unused `const snapshot = snapshotOrRoot` binding (5 `snapshot.`
    references rewritten to `snapshotOrRoot.`).
  - Replaced the biome-forbidden non-null assertion `folderPath!` with `folderPath as string`.
  - Condensed two verbose doc comments so the file sits at **249 line-budget lines**
    (was 257; budget is 250 and `state.ts` is not allow-listed).
- `src/core/status.ts`, `src/core/show.ts`, `src/core/report.ts`
  - Sorted the `./layout.js` imports (`getArchiveDir, getChangesDir`) to satisfy
    `biome check` (`assist/source/organizeImports`). No behavior change; these modules
    already resolved `changes`/`archive` through `getChangesDir`/`getArchiveDir`.
- `tests/state.test.ts`
  - Added a regression test asserting `deriveSpecState(snapshot)` is synchronous
    (returns a `SpecState`, not a `Promise`) and preserves `folderPath`. This guards
    the bug fixed above.
