## Changed

- `crates/kernel/specs/Cargo.toml`: added the second `[[test]]` entry,
  `name = "openspec_archive_parity_corpus"` with
  `required-features = ["parity"]`. Task 2's `[features]` table and
  `openspec_validate_parity_corpus` entry are unchanged.
- `crates/kernel/specs/tests/openspec_archive_parity_corpus.rs` (new, 248
  lines): proves rust-specs "Archive cases match OpenSpec" over
  `tests/fixtures/openspec-diff/`.
  - One `#[test]` per case, declared through a macro, plus
    `cases_are_exactly_the_fixture_folders`, which reads the fixture folders and
    compares them with the declared list. Every test carries
    `#[ignore = "corpus test: runs the OpenSpec CLI on the differential cases"]`
    and a doc naming `Covers: rust-specs/archive-cases-match-openspec`.
  - Each case builds two temporary projects under `CARGO_TARGET_TMPDIR`, one per
    side, from `templates/openspec` plus the case's `specs/` and `changes/`.
  - `identical`: runs `validate <change> --type change --strict --json
    --no-interactive` and `archive <change> --yes --json` on the CLI project, and
    each change in byte order through `merge_change` on the Rust project,
    writing each text and removing an emptied capability's folder before the
    next. Both must exit 0 and the two `openspec/specs/` trees must be equal,
    path for path and byte for byte.
  - `both-refuse`: the first CLI archive exits non-zero with a `status` entry
    whose `code` is `archive_spec_update_failed`, the Rust merge gives
    `MergeChangeError::Merge`, and both trees still equal the case's `specs/`.
  - `osq-refuses`: the Rust merge gives `MergeChangeError::Merge` whose
    `MergeError` message holds `### Requirement:`, the CLI archive exits 0, and
    no living spec it leaves holds `### Requirement: <name>` for a `TO:` name of
    the case's delta specs.
  - `case.json`'s `expect` and the CLI's `--json` output are read with
    `serde_json`. CLI lookup, project, and tree helpers come from task 2's
    `tests/openspec_parity_support/` through `mod`; that folder is unchanged.

## Deviated

- "One test per case read from the folder" is implemented as a macro that
  declares a test per case from a static list, guarded by
  `cases_are_exactly_the_fixture_folders`, which reads the folder and asserts the
  set equals that list. Rust cannot generate test functions at run time, so a
  static list plus the exact-folder check is the closest the target allows;
  adding or removing a case fails the check until the list is updated.
- `#[rustfmt::skip]` is placed on several small helpers so their bodies stay
  compact and the file fits the task's 250-line limit (248). No workspace lint
  is loosened and `cargo fmt --all --check` still passes; the pattern is already
  used in `crates/kernel/storage/tests/reading_history.rs`.
