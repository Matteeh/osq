## Changed

- `crates/kernel/specs/Cargo.toml`: added a `[features]` table with
  `parity = []` and a `[[test]]` entry for `openspec_validate_parity_corpus`
  with `required-features = ["parity"]`. Nothing else changed, so
  `sh scripts/verify-rust.sh` (default features) does not build the target; I
  confirmed the target is absent from `cargo test -p osq-kernel-specs --no-run`
  and present with `--features parity`.
- `crates/kernel/specs/tests/openspec_validate_parity_corpus.rs`: two ignored
  corpus tests. `cli_reports_a_version` locates the CLI and asserts `--version`
  is `<n>.<n>.<n>`. `validate_matches_openspec` compares every "OpenSpec
  validate parity" item and asserts the five listed differences, with the
  `KNOWN_DIFFERENCES` table naming each label, both pass flags and its `why`.
- `crates/kernel/specs/tests/openspec_parity_support/`: shared helpers, all
  under the folder the task allows, so task 3 can `mod` the CLI and project
  helpers:
  - `cli.rs`: `OpenSpecCli::locate` (`OSQ_OPENSPEC_BIN` or
    `node_modules/.bin/openspec`), `run` with `OPENSPEC_TELEMETRY=0` in the
    project folder, `version` naming the path when the CLI is missing, and
    `is_version`.
  - `project.rs`: `Project` builds each temporary project under
    `CARGO_TARGET_TMPDIR`, scaffolds `templates/openspec`, and sets the specs
    and a change (writing `# Parity fixture\n` when a change has no
    `proposal.md`).
  - `trees.rs`, `replay.rs`, `report.rs`: folder/name helpers, the archive
    landing order of rust-specs "Archive replay", and the comparison types
    (`Outcome`, `Comparison`, `KnownDifference`) with `assert_parity`, which
    collects every failure before it panics.
  - `items/`: the validate parity item collection. Living specs are validated
    with `--specs` (one item per capability), archived changes in landing order
    against the replay before they merge, living fixtures with
    `<stem> --type spec`, delta fixtures as `specs/alpha/spec.md` of change
    `parity`, and targets changes against `targets/specs/`. The Rust side runs
    `validate_living_spec`, `validate_delta`, and
    `validate_change` + `validate_merged_change`.

## Deviated

- The item collection (living, delta, targets, archive) lives in
  `openspec_parity_support/items/` rather than in the single test file. The
  task's scope allowed only `openspec_parity_support/**` as a new path, and the
  250-line file budget made one file awkward. The folder is documented as
  shared, and task 3 can declare it as `pub mod openspec_parity_support;`
  without dead-code warnings.
- I added guards to the main test that at least one living-spec item and one
  archived-change item were compared, so a broken enumeration fails instead of
  passing vacuously.
- `is_version` and `text_of` are extra CLI helpers used by the version test and
  the no-JSON failure path.

## Missing context

- The scope listed only the test file and `tests/openspec_parity_support/**`,
  so a test-local module folder such as `tests/openspec_validate_parity/` was
  not available, which is why the item collection sits under the support
  folder.
