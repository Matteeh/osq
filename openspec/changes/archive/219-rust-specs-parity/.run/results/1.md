## Changed

- Added the `osq-kernel-linter` no-runtime-Node gate. `node_spawns` parses one
  source with `syn`, visits call expressions, and reports every
  `Command::new` whose first argument is a string literal naming `node`, `npx`
  or `openspec` after path separators and one trailing `.exe`/`.cmd` are
  removed. `workspace_node_spawns` reads the root manifest's `[workspace]`
  `members` array line by line, scans each member's `src/` recursively in
  path byte order, and returns workspace-relative `/` paths.
- Added `NodeSpawn` and `ScanError` (`Read`, `Parse`, `Manifest`) with the
  required derives, public fields, `Display`, and `std::error::Error`; all
  four are re-exported from `lib.rs`.
- Copied `openspec/changes/219-rust-specs-parity/fixture/node-spawn/` to
  `crates/kernel/linter/tests/fixtures/node-spawn/` byte for byte and added
  `tests/node_spawns.rs`, its `node_spawns_workspace.rs` module, and the
  ignored corpus test `tests/node_spawn_corpus.rs` over the repository root.
- Added `syn` (`full`, `visit`) and `proc-macro2` (`span-locations`) to
  `[workspace.dependencies]`, named them in the linter manifest, and updated
  `Cargo.lock`'s linter package entry using the already-locked versions
  `syn 2.0.119` and `proc-macro2 1.0.107`.

## Deviated

- The fast tests live in `node_spawns.rs` plus the `node_spawns_workspace.rs`
  module it declares, so each file stays under the 250-line source budget
  while the task's verify command still runs them under `--test node_spawns`.
- `strip_comment` cuts at the first `#` and `bracket_delta` counts brackets
  without a string-state machine, which the spec does not require. The simpler
  code keeps the mutation surface small; both source files reported no missed
  mutants under `cargo mutants -p osq-kernel-linter -f <file>`.

## Missing context

- The acceptance names every test at `tests/node_spawns.rs`; it did not say
  whether helper modules under the same integration target are allowed. I used
  one to respect the 250-line file budget.
