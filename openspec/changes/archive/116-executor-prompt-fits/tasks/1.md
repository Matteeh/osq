## Acceptance

- [ ] `extractCapabilityRules` takes an optional living specs directory. Given one, it leaves out each delta requirement whose statement, as `parseRequirementRules` builds it, equals the statement of the requirement with the same title in `<dir>/<capability>/spec.md`. When that living file doesn't exist, every requirement keeps its rule. Without the directory, it behaves as today.
- [ ] `resolveCapabilityRules` passes `options.projectRoot` joined with `options.config?.paths?.features`, or `openspec/specs` when that is unset, the way `livingSpecPaths` in `src/harness/prompt.ts` does. An explicit `capabilityRules` option still wins.
- [ ] New `tests/capability-rules-living.test.ts` covers the watcher-and-harness delta's "Unchanged requirement left out" through `buildExecutorPrompt`, with a temporary project root holding the living spec and a change folder holding the delta. It also checks that a capability with no living spec keeps all its rules.
- [ ] Every function stays within 80 lines, and `tests/harness-prompt-injection.test.ts` and every other test pass unchanged.
