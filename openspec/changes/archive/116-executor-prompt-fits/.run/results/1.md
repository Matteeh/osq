## Changed

- `src/harness/types.ts`: `extractCapabilityRules` now takes an optional
  `livingSpecsDir`. When given, a delta requirement whose statement (as
  `parseRequirementRules` builds it) equals the same-titled living requirement's
  statement is left out; a capability with no living spec keeps every rule, and
  omitting the directory behaves as before. Added a private
  `livingRequirementStatements` helper that reads `<dir>/<capability>/spec.md`.
- `src/harness/types.ts`: `resolveCapabilityRules` resolves the living specs
  directory as `projectRoot` + (`config.paths.features` or `openspec/specs`),
  matching `livingSpecPaths` in `src/harness/prompt.ts`. An explicit
  `capabilityRules` option, including an empty array, still wins.
- `tests/capability-rules-living.test.ts`: new test file covering the
  watcher-and-harness "Unchanged requirement left out" scenario through
  `buildExecutorPrompt`, plus direct coverage of `extractCapabilityRules` and
  `resolveCapabilityRules`, including the no-living-spec case and the
  backward-compatible no-directory call.
