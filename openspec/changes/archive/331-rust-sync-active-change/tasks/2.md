## Acceptance

- [ ] `sync` finds, refuses and runs as rust-land "Sync command" says. It finds an approved active worktree change, refuses while a watcher or a task runs for both kinds of change, and no longer gives `<folder> has not archived; Rust sync does not sync an active change yet`.
- [ ] An active change syncs as rust-land "Active sync", "Active sync verify" and "Active sync recertification" say, using storage's `task_scope_hash`, `read_done_scope`, `differing_scope_paths` and `refresh_done_marker`. Every stop of an active sync appends its uncommitted `sync_stopped` event.
- [ ] `tests/fixtures/sync-message-golden/sync.json` and `print-sync-message-goldens.mjs.txt` are the change folder's `golden/` copies, byte for byte. `message.json` is unchanged.
- [ ] `tests/sync_command.rs` proves "Sync equals TypeScript's" and "Sync refusals Rust adds" with their new rows. New `tests/active_sync.rs` proves "Active sync equals TypeScript's", "Active sync verifies done tasks" and "Sync recertifies a done task". Each test's doc names `Covers: rust-land/<scenario>`, and every land test passes.

## Details

TypeScript runs one sync for both kinds of change: `syncWithDefaultBranch`
in `sync-main.ts`. Its `archived` flag picks the verify step and whether
deltas are applied. Rust's `sync.rs` and `sync/` work on an archived path
today. Generalize them to the change folder, with a kind that picks
"Land sync verify" or the active verify and recertification. Do not copy
the steps. `land` keeps calling the archived kind, and every land test must
still pass.

The verify runs reuse `sync/verify.rs`'s run-twice, log and `verify_ran`
code, adding `task` to the data. For each recertified file, keep its bytes
before the first write, as the events bytes are kept, so a stop can put it
back. Read the watcher record with storage's `read_watch_state` and task
states with `read_now_facts`; both already exist.

The active rows' done marker for task 1 records the branch's tree before
the merge. Write it in the test with storage's `task_scope_hash` of the
worktree with `src/**`, as the script writes it with
`computeTaskScopeHash`. The two `watcher` rows need their own `HOME`. Run
them in a child test process as `spawn_home_child` in
`crates/features/show/tests/status_command.rs` does, since tests share
one process environment. Every other row runs with the test's own `HOME`.

The goldens came from TypeScript's `dist` with the script in `golden/`.
Take every expected value from them and the scenarios, never from running
the Rust code. Never read anything under `src/` from Rust; those files are
in `entry` only so you can port them.

cargo-mutants runs on every line you touch, so give each branch a row
that fails when it flips. Add a fast test when a mutant survives. Run the
proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/331-rust-sync-active-change`, so the link
gates see this change's new requirements.
