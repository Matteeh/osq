## Details

This is a move, not a rewrite. Retry's `scope::resolve` and
`scope::compute_hash`, `yaml::write`, and `recertify/done.rs`'s `rewrite`
already behave as the new storage requirements say, and the retry
scenarios already pin them. Move them into the storage crate and make
`task_scope_hash` and `refresh_done_marker` public. `refresh_done_marker`
returns `DoneMarkerError` where `rewrite` returned a retry `FeatureError`,
with the same message text. Retry wraps that display with its
`text::failed`, so its error messages stay the same.

`read_done_scope` and `differing_scope_paths` are new. They port
TypeScript's `readDoneMarker`, with `readRecordedFiles`, and
`findDifferingPaths` from `src/core/run/scope-hash.ts`. Read the
frontmatter with rust-specs `parse_frontmatter`, as the moved code does.
Every row of the storage scenario tables was checked against those
TypeScript functions in `dist`. Never read anything under `src/` from
Rust; those files are in `entry` only so you can port them.

Storage already depends on `sha2`, `yaml-rust2` and `osq-kernel-specs`.
Drop `sha2` from retry's `Cargo.toml` once retry no longer uses it; the
root `Cargo.lock` follows by itself.

cargo-mutants tests only the package that holds a mutated line. So the
moved code needs the storage tests to kill its mutants; retry's tests do
not count. The storage tables port the retry rows that killed them in
297. Add a fast test when a mutant survives. Run the proposal's verify as
the watcher does, with
`OSQ_CHANGE=openspec/changes/331-rust-sync-active-change`, so the link
gates see this change's new requirements.
