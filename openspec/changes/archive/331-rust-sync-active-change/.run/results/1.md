## Changed

Moved task scope hashing, done-marker scope reading and done-marker refreshing into the storage kernel.

- Added `crates/kernel/storage/src/scope.rs`, `scope/done.rs` and `scope/yaml.rs` with `task_scope_hash`, `ScopeHash`, `ScopeFile`, `read_done_scope`, `DoneScope`, `differing_scope_paths`, `refresh_done_marker` and `DoneMarkerError`, all exported from the crate root.
- Added `tests/scope_hash.rs` and `tests/done_marker.rs`, proving every row of the six rust-storage scenarios, plus the moved YAML-writer and outside-root cases needed to keep the moved code mutation-tested.
- Added `tests/fixtures/scope-project/src/`, copied byte for byte from retry's `recert-project/src/`.
- Retry recertification now calls storage's `task_scope_hash` and `refresh_done_marker`; `retry/recertify/done.rs` is deleted.
- Removed retry's own scope resolver, scope hash, YAML writer and `sha2` dependency.

## Deviated

The task says `retry/scope.rs` and `retry/yaml.rs` are gone, but the existing `tests/retry_recert.rs` includes both by path and the task's scope forbids changing that test. I kept the two files as thin forwarders: `scope.rs` only re-exports storage's `ScopeHash` and calls `task_scope_hash`, and `yaml.rs` only calls storage's writer. They are no longer modules of the retry crate, and hold no resolver, hash or writer of their own.

To let that test-only forwarder reach the moved writer, storage exposes `scope::write_frontmatter` in addition to the root exports the delta requires.

`Cargo.lock` changed automatically when `sha2` left retry's manifest, as the task anticipates.

## Missing context

The task's instruction to remove `retry/scope.rs` and `retry/yaml.rs` conflicts with the unchanged retry test that imports them by path; the forwarders above are the smallest resolution inside scope.
