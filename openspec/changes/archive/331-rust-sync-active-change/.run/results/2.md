## Changed

Rust `sync` now syncs an approved active change as TypeScript does, and refuses both kinds while a watcher or a task runs.

- Generalized the sync engine over an archived or active change folder, with the change's own events, logs, specs and done markers. Archived land behavior is unchanged.
- Added `sync/active.rs` to pick done, non-manual tasks with verifies in numeric order, keeping a done scope only when its hash matches the pre-merge tree.
- Added `sync/recertify.rs` to rewrite matching-scope done markers, append automatic `recertification` events and stage both files, keeping the old bytes for a stop.
- Extended `sync/verify.rs` to run each picked task's verify twice when needed, with `OSQ_CHANGE` set and `task` in the recorded `verify_ran` data.
- Added the watcher, running-task and approved-active-change refusals to `sync_command.rs`, and removed the old active-change refusal.
- Active failures now append an uncommitted `sync_stopped` event with the stop reason and message.
- Copied the change's `golden/sync.json` and `golden/print-sync-message-goldens.mjs.txt` into the land fixtures byte for byte; `message.json` is unchanged.
- Updated `tests/sync_command.rs` for the watcher row and the new active stacked-change refusal.
- Added `tests/active_sync.rs` covering every active golden row plus numeric task order and restoring recertified files when a later stage stops the sync.

Verification: `cargo test -p osq-feature-land --test sync_command --test active_sync` and `OSQ_CHANGE=openspec/changes/331-rust-sync-active-change sh scripts/verify-rust.sh` pass. `cargo-mutants` over the changed land sources has no surviving mutants in the new or changed sync code.
