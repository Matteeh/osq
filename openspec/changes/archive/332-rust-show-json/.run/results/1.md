## Changed

- Ported TypeScript's `formatShowJson` into new modules under `crates/features/show/src/json/`: a JavaScript-ordered JSON value/parser/renderer, the document head, tasks, events, planning sessions, recertifications and approval digest.
- Added `--json` argument handling and the `[--json] <id>` command usage in `feature.rs`; every other argument is now the change id, and the text path is unchanged.
- Extended the existing model so JSON reads the same values the text derives: proposal non-goals and delta, task entry and skills, planning session id and numeric exit code, recertification differing paths, digest flag ids, next-step accessors, and each event's raw line for JavaScript key order.
- Copied all 16 goldens and `print-json-goldens.mjs.txt` unchanged into `crates/features/show/tests/fixtures/json-golden/`.
- Updated `tests/feature.rs` for the new usage and added `tests/show_json.rs`, which proves the JSON arguments, all eight not-archived golden rows, both archived head arguments, and extra event-data key ordering and duplicate-key handling.

## Deviated

- Added one extra test, `show_json_event_data_key_order`, beyond the acceptance rows. It proves the requirement's JavaScript own-property order for event data, including duplicate keys and canonical array indexes, and it makes the ordering code mutation-complete.
- Archived `validation`, `land` and `verification` members are intentionally omitted, leaving them to task 2 as the task directs.
