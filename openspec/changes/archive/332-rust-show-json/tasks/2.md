## Acceptance

- [ ] With `--json`, an archived change prints `validation`, `land` and `verification` as rust-show "Show JSON" says, in the function task 1 wrote for the members after `timeline`; the text view prints exactly as before.
- [ ] New `tests/show_json_git.rs` proves every row of "Show JSON of an archived change" and "Show JSON of a worktree change", each test's doc naming `Covers: rust-show/<scenario>`, each base folder a new folder under `CARGO_TARGET_TMPDIR` named after its test and row.
- [ ] Every public item and every function that implements a requirement ends its doc with `Implements: rust-show/<requirement>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Port `withNextStep` in `src/core/status/show-model.ts`, `buildValidation`
in `src/core/status/show-model-validation.ts`, `readLandView` in
`src/core/status/show-land-model.ts` and the `LastSync` reading in
`src/core/status/last-sync.ts`. Take each value from what the land lines
already derive: `LandFacts` from `facts.rs` for the git fields, the gates,
capabilities, disclosures, halt and sync stop under
`src/archived/section/land/`, the latest `validator_ran` event in
`src/archived/section/validation.rs`, and the check and outcome rows in
`src/archived/section/verification.rs`. Where those readers keep only
counts or flags, such as capability counts or whether a task deviated, make
them keep the names and text, and have the land lines count from them.
`lastSync` is new: the last `synced` event with a string `defaultBranch` and
a number `commits`, the one the sync stop is already compared against.

Build each row's git state as `print-json-goldens.mjs.txt` does and as
`tests/show_land.rs` builds its rows, with commits by
`osq <osq@example.com>` and `osq.toml` holding `[vcs]` `enabled = true` and
`author = "osq <osq@example.com>"` where the script writes
`osq.config.ts`. Give each row an empty HOME by running the test binary
again as a child process with `HOME` set and one test selected, as
`show_land.rs` does with `OSQ_SHOW_LAND_HOME`; never set `HOME` in the test
process itself, since tests run in parallel.

Never read anything under `src/` of the repository from Rust; the
TypeScript files are in `entry` only so you can port them.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/332-rust-show-json`, so the link gates see this
change's new requirement.

## Scenarios

- rust-show: Show JSON of an archived change
- rust-show: Show JSON of a worktree change
