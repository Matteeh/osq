## Details

Port `formatShowJson` in `src/core/status/show-output.ts` and the
`SpecDetails` shape in `src/core/status/show-types.ts`. Build the document
from what `show` already derives: `model::read` for the change, its tasks,
status and next step; the event reading under `src/events/` for the
timeline and each task's events; the planning session correlation in
`src/planning.rs`; the recertification rows in
`src/archived/section/recertifications.rs`; and the digest model with its
flags under `src/digest/section/`, where each flag gains its TypeScript id.
Change those modules only so the JSON can read the same values the text
prints, never to change the text.

Write the JSON by hand in new modules under `src/`, as no other crate may be
shared (ADR 022): the workspace builds `serde_json` without
`preserve_order`, and event data must keep its keys in JavaScript's order,
which `Entries` in `src/events/model.rs` already reads in file order. Use
`serde_json` only to escape strings. Print every number through one helper
that writes a 64-bit float as JavaScript does.

Put the members after `timeline` (`next`, `afterLanding`, and later the
archived members) in one function of their own, so task 2 adds the archived
members there.

Never read anything under `src/` of the repository from Rust; the
TypeScript files are in `entry` only so you can port them. Build each test's
base folder as `print-json-goldens.mjs.txt` does, with the fixture copied
from `tests/fixtures/show-project`.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/332-rust-show-json`, so the link gates see this
change's new requirement.
