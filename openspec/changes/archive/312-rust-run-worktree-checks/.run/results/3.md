## Changed

Added `crates/features/run/src/feature/catch_up.rs`, which implements rust-run
"Commit catch-up": it refuses another halt or a spent `gates.commitRetries`
budget, commits pending dead markers (keeping an existing `.patch`) through the
new `commit::dead_with`, records another `commit_failed` halt on a failed dead
commit, then renames the active halt marker to `change.<n>.md` and appends an
automatic `retry` event. Budget counting reads `change.jsonl` with
`parse_event_line` and resets on a human retry.

`refusals::check` now runs the catch-up before the worktree checks, and
`feature.rs` declares the new module. `commit.rs` gained `dead_with`, which
takes whether to keep an existing patch; the existing `dead` entry point keeps
its signature for its current caller.

Added `crates/features/run/tests/run_commit_catch_up.rs`, proving every row of
"Commit catch-up", "Catch-up runs out" and "Other halts refuse", plus coverage
for manual retry resets, non-`commit_failed` events, untracked dead markers,
missing and existing patches, and retained ordinals.

## Deviated

The task asked `commit::dead` to take whether to keep a patch, but its existing
caller in `dead.rs` is outside this task's scope. I left `dead` unchanged and
added `dead_with` with the flag; `dead` delegates with `false`.

The worktree test helper is also outside scope, so the new test removes the
`pre-commit` hook with `support::remove` between runs instead of changing
`worktree_support`.
