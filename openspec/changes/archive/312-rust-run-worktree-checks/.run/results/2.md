## Changed

- Added `feature/halt.rs`: writes `.run/regressed/change.md` and appends the
  `change` stream's `regressed` event with core's `RegressedData`, both holding
  `output::tail_verify_output` of the detail at the config's marker limits. It
  also builds the `spec <id> halted (<reason>)` ending.
- Added `feature/checks.rs`: commits pending done tasks (`??` or `A*`, numeric
  order, `manual: true` skipped) through `commit::verified`, then halts on the
  wrong branch or on status paths outside the change's `tasks.md` and `.run/`.
- `refusals::check` runs the worktree checks after its git-root check and
  before the marker refusals, so a halt precedes the lock, approval and start.
- `commit::verified` records a `commit_failed` halt on a refused commit before
  returning its existing failure text. `dead::kill` records the same halt when
  `commit::dead` fails at any step.
- `text::halted` builds the halt ending from the folder's leading digits, and
  `events::append` carries the new requirement tag.
- `worktree::is_worktree` now also sees a linked worktree when `run` is invoked
  from inside it, so the checks apply to a change in an osq worktree.
- `tests/worktree_support/mod.rs`: `build` writes `fake-pi-mode` to the
  checkout's `.git/info/exclude` after `git init`, and gained `run_in_worktree`.
- New `tests/run_worktree_halts.rs` proves every row of "Worktree halts before
  the start", "Worktree check allows the change's records", "Pending verified
  commit" and "Failed commits halt the change", plus staged and non-numeric
  done markers and numeric pending order.
- `tests/run_worktree.rs`'s `an_untracked_test_file_is_committed` now narrows
  the scope to `src/a.txt` and `src/tests/new.rs`, writes nothing before the
  run, and uses the fake pi's `added-test` mode.

## Deviated

- The off-branch and dirty rows of "Worktree halts before the start" run from
  the worktree root, because `change_trees` (living rust-run "Worktree run")
  only names worktrees on an `osq/` branch and would otherwise refuse the id
  before a check could see the wrong branch. `is_worktree` therefore treats a
  linked `.git` file as a worktree when the tree root is the invocation root.
- Added three extra tests beyond the scenario tables (staged done marker,
  non-numeric done file, numeric pending order) to cover branches that the
  mutation check would otherwise miss.
