## Acceptance

- [ ] For a change in an osq worktree with `.run/regressed/change.md`, `run` acts as rust-run "Commit catch-up" says before "Worktree checks": it refuses any other halt or a spent budget, commits the pending dead tasks keeping an existing patch, and clears a `commit_failed` halt with an automatic `retry` event.
- [ ] New `tests/run_commit_catch_up.rs` proves every row of "Commit catch-up", "Catch-up runs out" and "Other halts refuse".
- [ ] Every run test passes unchanged.
- [ ] Every public item ends its doc with `Implements: rust-run/<requirement>`, and each new test's doc names `Covers: rust-run/<scenario>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Put the catch-up in `catch_up.rs`. Copy the ordinal and the marker rename
of rust-retry's `record.rs` rather than calling it, since a feature never
calls another; the `retry` event uses core's `RetryData` with `automatic:
Some(true)`. Count the budget from `change.jsonl` with core's
`parse_event_line`, skipping lines that do not parse. Let `commit::dead`
take whether to keep an existing patch, and record a pending dead task
through it and the halt writer task 2 added. Read the budget from
`config.gates.commit_retries`.

Build test repositories with `tests/worktree_support/mod.rs`, removing the
hook its `refuse_commits` writes between runs. Run the proposal's verify
with `OSQ_CHANGE=openspec/changes/312-rust-run-worktree-checks`.

## Scenarios

- rust-run: Commit catch-up
- rust-run: Catch-up runs out
- rust-run: Other halts refuse
