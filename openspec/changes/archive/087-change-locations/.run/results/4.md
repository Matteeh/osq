## Changed

- `src/core/report/report.ts`: `getMetricsReport` now takes its canonical
  changes, archive, and rejected directories from `changeTrees`, and lists the
  active, archived, and rejected changes with one `listChanges` call when the
  canonical layout is present. The legacy `specs/` fallback is preserved
  verbatim: when neither canonical directory exists and a legacy `specs/` tree
  does, the existing readdir logic still feeds `activeFolders`/`archivedFolders`
  and `listRejectedFolders` still feeds rejection history. Rejection history now
  iterates the `rejected` folders returned by `listChanges` in the canonical
  case. `getRepositoryRecord` lists its archived changes with
  `listChanges(..., ['archived'])`. The file-local `listRecentArchiveFolders`
  lost its directory read and now sorts the folders it is given by numeric
  prefix, newest first, capped at the limit. All `layout` imports are gone.
- `src/core/report/recent-disclosures.ts`: `formatRecentDisclosures` lists
  archived changes with `listChanges`, and its file-local
  `listRecentArchiveFolders` now sorts and caps the given folder paths with the
  same recency rule. The `fs` and `layout` imports are gone.
- `src/core/foundation/doctor.ts`: `checkLocks` and `checkDoneMarkers` iterate
  `listChanges(projectRoot, config, ['active'])`, and `checkArchives` iterates
  `listChanges(..., ['archived'])`. The per-location skip (`archive`, `_`, `.`)
  is unnecessary because the resolver already applies it. `listDirs` and the
  `Dirent` import are removed; 249 -> 231 lines.
- `src/core/foundation/doctor-prices.ts`: `changeFolders` lists
  `listChanges(projectRoot, config, ['active', 'archived'])` and maps each to
  its `folderPath`; the local `subdirectories` helper and the `fs`, `path`, and
  `layout` imports are gone; 47 -> 30 lines.
- `src/core/web/web-events.ts`: `InvalidationHubOptions` gains an optional
  `trees: readonly ChangeTree[]`. `createInvalidationHub` resolves its changes,
  archive, and rejected directories from `options.trees[0]` when the caller can
  await `changeTrees`, and otherwise from a synchronous single-tree fallback,
  `singleChangeTree`, that mirrors today's one-tree layout. The watch path and
  every classification result are unchanged with one tree. All `layout` imports
  are gone.
- `tests/web-events-locations.test.ts` (new): exercises the `trees` option with
  a fake watcher and manual debounce, including the global empty-id batch for a
  shared path.

## Deviated

- `createInvalidationHub` is synchronous and cannot await `changeTrees`, and
  the file where its options are built, `src/core/web/web-server.ts`, is outside
  this task's `scope`, so the hub cannot receive resolved trees in production
  yet. It accepts `trees` (the mechanism the task suggests) and falls back to
  `singleChangeTree`, a synchronous mirror of `changeTrees`' single tree, which
  keeps the direct synchronous `serve-sse` callers working unchanged. The
  fallback duplicates the three canonical segment names rather than calling
  `getChangesDir`/`getArchiveDir`, which this file must no longer call.
- The delta's reader list includes `web-data-folders.ts` and web events; only
  web events is in scope here.

## Missing context

- `src/core/web/web-server.ts` is the place the hub's options are built, but it
  belongs to no task's `scope` in this change. Passing
  `trees: await changeTrees(projectRoot, config)` there would let the hub take
  its directories from `changeTrees` in production instead of the synchronous
  fallback. A later task or the planner should add it to a scope.
