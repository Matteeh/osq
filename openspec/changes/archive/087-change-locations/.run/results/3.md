## Changed

- `src/core/status/status.ts`: `getStatusOverview` now lists active changes
  with `listChanges(projectRoot, config, ['active'])`, keeping the
  `resolveChangeDoc` proposal check, the resolver's numeric-prefix order, and
  the same `StatusOverview` output. `readRejectedSummaries` reads
  `listChanges(['rejected'])`, and the archived count is
  `listChanges(['archived']).length`. The archive directory for
  `listPendingVerifications` comes from `changeTrees()[0].archiveDir`. Removed
  the `path` import, `getChangesDir`/`getArchiveDir`/`getRejectedDir`,
  `compareNumericPrefix`, and the archive/rejected folder-name computation
  (247 -> 171 lines); `getStatusOverview` is 38 lines.
- `src/core/status/next-step.ts`: `readNextStep` classifies a folder as
  archived with `locateFolder(...).location === 'archived'` instead of
  comparing the parent directory to `getArchiveDir`. Dropped the `layout`
  import.
- `src/core/status/inbox-projection.ts`: the archive directory passed to
  `collectLandedItems` now comes from `changeTrees` instead of `getArchiveDir`.
- `src/core/status/queue-state.ts`: `scanQueueAssociations` iterates
  `listChanges(projectRoot, config)` and groups each change by its
  `location`, keeping the `brief.md`/`queue_item`/`queue_hash` filter and the
  active/archived/rejected grouping. Removed the three layout imports, the
  `RESERVED_DIRS` set, and the per-location readdir scan (249 -> 235 lines).
- `src/core/status/queue-report-detail.ts`: `readQueueReportFailure` resolves
  the failure's folder with `findChange(projectRoot, config,
  failure.folderName)` instead of `getChangesDir`; removed that layout import.
- `tests/function-budget.test.ts`: removed the
  `core/status/status.ts#getStatusOverview` key from `GRANDFATHERED`; the file
  changed in no other way.

## Deviated

- The task allows `inbox-projection.ts` to hand `collectLandedItems` either the
  archived folders or the archive directory from the change's tree.
  `collectLandedItems` still takes a directory and `inbox.ts` is outside this
  task's scope, so `inbox-projection.ts` uses `changeTrees` and passes
  `tree.archiveDir`.
