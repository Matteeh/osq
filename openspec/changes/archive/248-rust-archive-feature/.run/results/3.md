## Changed

- `src/record.rs`: ports `archiveSpecsRecordPath`, the recording half of `applyArchiveSpecs`, `restoreArchiveSpecs` and `removeEmptyDir`. It records `spec.md` and `osq.yml` for every capability folder under the change's `specs/` as a `serde_json` object of text or `null`, puts recorded text back, removes paths recorded as `null` and then their folder when empty, and removes the record.
- `src/archive.rs`: refuses a change whose `.run/archive-specs.json` is already a file before the merge with `<folder> holds .run/archive-specs.json from a stopped archive`; writes the record after the merge and before `apply.rs`; on a record or living-file failure restores from the record and fails with `cannot write <path>: <error>`, naming the record's path when the record could not be written; removes the record after a successful write and before the move.
- `tests/archive_record.rs`: proves the stopped-record refusal, both living-file failure rows (`gamma` as a file and `epsilon/osq.yml` as an empty folder) including the put-back of `alpha`, `beta`, no left `gamma/spec.md`, the removed record and the unchanged replacement, and the record that cannot be written.
- `src/lib.rs`, `src/feature.rs`, `src/apply.rs`, `Cargo.toml` and `Cargo.lock` are unchanged.

Verification: `cargo test -p osq-feature-archive --test archive_record` passes, as do every existing archive test. `cargo fmt --all`, `cargo clippy -p osq-feature-archive --all-targets -- -D warnings`, `cargo mutants` on both changed source files (12/12 caught in `record.rs`, 14/20 caught and 6 unviable in `archive.rs`) and `OSQ_CHANGE=openspec/changes/248-rust-archive-feature sh scripts/verify-rust.sh` all pass.

## Deviated

- `record::write` does not create the change's `.run` folder, though TypeScript's `applyArchiveSpecs` calls `mkdir`. The archive gates already require `.run/approved` and `.run/done/<n>`, so the folder always exists by the time the record is written; adding an unreachable `create_dir_all` would add a line no test can make observable for cargo-mutants.
- The record map is a `BTreeMap`, so its JSON keys are sorted rather than in TypeScript's insertion order. `applyArchiveSpecs` sorts capabilities and then records `spec.md` before `osq.yml`; key order has no observable effect because a record is removed on every path that returns and a leftover record is refused. Keeping capability iteration unsorted likewise avoids a line whose mutation no row could catch.
