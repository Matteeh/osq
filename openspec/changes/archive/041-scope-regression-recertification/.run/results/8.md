### `tests/golden-events.test.ts` special handling

The golden event fixtures pin the `verify_ran.command` byte-for-byte to the
sentinel, which acceptance line 3 requires preserving as inert serialization
coverage. `approveSpec`/`hashChangeFolder`-based approval would force that
command to change, and adding a `verify.cjs` file would also change the pinned
`repoFiles`/`repoLines`. The suite therefore seals `.run/approved` directly with
`hashChangeFolder` (no lint, no extra file), so the existing runner zero-trust
gate and both golden streams stay byte-identical while the sentinel is never
submitted as an authored change.
