## Changed

- `src/core/linter.ts` (allow-listed module, no line budget):
  - Added one read-only `analyzeVerifyCommand(projectRoot, command, packageScripts)`
    plus its narrow helpers. It tokenizes whitespace/quote operands without any
    shell execution or expansion, then classifies the command as sentinel,
    recognized package script, or unresolved.
  - Sentinel recognition is deliberately narrow: exactly `node -e|--eval` with a
    `process.exit(0)` expression, ignoring surrounding/repeated ASCII whitespace,
    single or double quotes, and an optional trailing JavaScript semicolon.
  - `readRootPackageScripts` reads the root `package.json` once and returns its
    `scripts` keys; a missing or malformed manifest deterministically yields an
    empty set without throwing.
  - Package-script recognition covers `pnpm`/`npm`/`yarn`/`bun` direct and
    `run`/`run-script` forms and ignores known non-script subcommands (`exec`,
    `install`, `publish`, …) so they fall through to the generic path check.
  - Path resolution considers quoted and unquoted repository-relative operands
    beneath `projectRoot`, skips options, inline `KEY=value` tokens, absolute
    paths, and URLs, and treats a path-shaped first token (e.g. `bin/verify.sh`)
    as local behavior while a bare command binary (`node`) is ignored.
  - `lintChangeFolder` now reads the manifest once and analyzes the change-level
    `spec.verify` plus every task verify. Diagnostics:
    - placeholder → error naming the artifact and requiring final-tree verification
    - recognized invocation with absent script → error naming the script
    - otherwise unresolved → warning naming the artifact and command
    Empty-command and chaining diagnostics are retained. Placeholder detection
    runs before the chaining check so the allowed sentinel semicolon is not
    misreported as a shell chain; genuine chains still produce the chaining error
    and are not reinterpreted as scripts.
- `tests/linter.test.ts` (declared `tests.modify: true`):
  - Replaced the placeholder passing constant with a local `node verify.cjs`
    command, created that verifier in each temp root, and seeded both the
    proposal and the scaffolded task with the valid command.
  - Added focused proposal/task cases for: proposal placeholder, task
    placeholder (one message), all normalized variants, each package-manager
    form with an absent script, a present script with no warning, task and
    proposal unresolved warnings, an existing file path and a path-shaped
    binary with no warning, missing/malformed manifest determinism, retained
    chaining without reinterpretation, and a repo-wide fixture scan proving no
    checked-in fixture uses the sentinel and every fixture root has `verify.cjs`.
- Fixtures: replaced every `verify:` line in `fixture/**/*.md` and
  `tests/fixtures/**/*.md` (52 files) with `node verify.cjs`, and added local
  deterministic verifiers `fixture/inbox/verify.cjs`, `fixture/report/verify.cjs`,
  and `tests/fixtures/report-sizes/verify.cjs` that assert the fixture's own
  paths exist and exit 0/1. The placeholder is retained only in the generated
  templates (`templates/proposal.md`, `src/core/new.ts` fallbacks), which are
  entry references outside this task.
- `AGENTS.md`: updated the fixture layout line and documented that the generated
  `verify: node -e "process.exit(0)"` sentinel is planning-only, is rejected by

- `README.md`: added lint-table rows for the placeholder and absent package
