## Changed

- `src/core/show.ts`
  - Added `RecertificationAttribution { path, attribution }` and
    `RecertificationDetail { taskNumber, timestamp, outcome, differingPaths,
    attribution, verify, exitCode, timedOut }`, and exposed
    `recertifications: RecertificationDetail[]` on `SpecDetails`.
  - The existing numbered event-stream parse loop now also collects typed
    `recertification` events from numeric-named streams (never `change.jsonl`)
    with their original stream position. No marker files are read for this
    history: it is a projection of the events already parsed for the timeline.
  - `buildRecertification` reads only explicit, well-formed fields: the task
    target comes from a numeric `data.task` or the stream name; timestamp must
    parse; `outcome` must be exactly `passed`/`requeued`; command, exit code,
    and timeout otherwise render as unavailable. Differing paths and attribution
    are normalized to sorted, de-duplicated path keys, with any path lacking a
    structured attribution recorded as `unknown`, so no raw object coercion can
    leak into output.
  - Rows sort by valid timestamp, then numeric task number, then original
    stream/event order.
  - `formatSpecDetails` renders a `Recertifications` section only when rows
    exist, placed after `Planning Sessions` and before the raw
    `Event Timeline`. `passed` is labeled `recertified`, `requeued` is labeled
    `requeued for agent work`; each row shows timestamp, verify, exit code,
    timeout state, and one indented line per sorted differing path with
    `attributed to task <n>`, `ambiguous`, or `unknown`.
  - No `src/cli/show.ts` change; both public entrypoints are used as-is.
- `tests/show.test.ts`

    `node verify.cjs` command and wrote that verifier into each temp root in

  - Added six tests: active ordered rows with all attribution states plus

## Deviated

- Rendering attribute output for a numeric attribution uses the phrase
  `attributed to task <n>` rather than a bare number, so the later task number
  is unambiguous in text. The acceptance only requires the later task number,
  `ambiguous`, or `unknown` to be rendered.
- The row's `attribution` list is the sorted union of the event's
  `differingPaths` and structured attribution paths; this keeps a path visible
  when one of the two arrays is malformed while still reporting a per-differing-
  path view.
