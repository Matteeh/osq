## Acceptance

- [ ] `getSpecDetails` derives an ordered recertification row for every valid typed `recertification` event in numbered task streams for both active and archived changes.
- [ ] Each row exposes task number, timestamp, outcome, differing paths, per-path attribution, verify command, exit code, and timeout state without reading active or retained marker files as history.
- [ ] `formatSpecDetails` adds a `Recertifications` section only when rows exist and labels passed tasks as recertified and failed decisions as requeued for agent work.
- [ ] Attribution renders the later task number, `ambiguous`, or `unknown` per differing path in stable path order rather than JavaScript object coercions.
- [ ] Multiple events sort by valid timestamp and then numeric task/event order; malformed optional fields render as unavailable without preventing proposal, task, planning, result, or timeline output.
- [ ] Existing show status, metadata, task table, diagnostics, planning sessions, results, and complete raw event timeline remain unchanged.

## Details

Add a typed display projection to `SpecDetails` from the already parsed
numbered event streams. Use only events whose type is `recertification` and
whose data has a numeric task target or whose stream name supplies one. Keep
the raw timeline intact; the new section is a concise derived view before the
timeline, not a replacement or a second filesystem scan.

Render one row per recertification decision so repeated human recertifications
remain visible. Format differing paths and their attribution on indented lines
using the structured event values established by task 3. Missing arrays,
objects, commands, exit codes, or timestamps must not throw. Do not infer
recertification from done-marker metadata because `osq show` must retain
append-only history after later requeue or archival.

Extend `tests/show.test.ts` with active and archived passed/requeued histories,
all attribution states, repeated events, malformed data, and no-event output.
Use `getSpecDetails` and `formatSpecDetails` through their existing public
entrypoints; do not change `src/cli/show.ts`.
