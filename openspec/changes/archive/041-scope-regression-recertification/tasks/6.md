## Acceptance

- [ ] `MetricsReport.history.scopeRegressions` and stable JSON always contain integer `detected`, `verificationPassedAtDetection`, `verificationFailedAtDetection`, `recertifiedByHuman`, and `requeuedForAgent` counters, including zeros.
- [ ] Every typed scope-regression `regressed` event increments detected; exit code zero increments passed-at-detection, a finite non-zero exit increments failed-at-detection, and a missing or malformed exit increments neither outcome subset.
- [ ] Every typed `recertification` event increments exactly the matching passed-human or requeued-agent counter while malformed outcomes increment neither.
- [ ] Counts derive only from numbered task event streams across the report's active and archived changes; active markers, retained marker history, results, and rejected folders do not invent history.
- [ ] Detection verification and passing recertification do not add execution attempts, multiple-attempt tasks, unexplained reruns, dead reasons, or cost coverage; an eventual agent `started` event after requeue retains the established attempt accounting.
- [ ] Text output adds one concise `Scope regressions` history block with all five labels, and deterministic JSON plus `fixture/report/expected.json` preserve every post-040 history field and ordering.
- [ ] Focused fixtures cover mixed valid, legacy, and malformed detection and recertification events across active and archived changes without changing current-state regression counts.

## Details

Extend the post-040 `HistoryMetrics` shape and its stable projection; do not
add a new top-level report section. Use `reason: scope_regression` to distinguish
scope detections from existing archive verification `regressed` events. Count
each event line once. Treat only finite numeric exit codes as detection
outcomes, so legacy scope events remain visible in `detected` without guessed
pass/fail classification.

Recognize only exact `passed` and `requeued` recertification outcomes. The
human counter is the number of passed recertification events, not unique tasks;
the agent counter is the number of requeue decisions, not subsequent starts.
Leave the existing `regressed` gap handling for unexplained-rerun detection
intact, and do not treat `recertification` itself as an execution terminal.

Add a disposable focused report fixture in
`tests/report-scope-regressions.test.ts`. Update the existing JSON shape
assertions and checked-in report expected file only for the new zero-valued
block; other report fixtures and tests are frozen. Reuse `parseEventLines`,
`asData`, `getMetricsReport`, `formatMetricsReport`, and `toStableMetrics`.
