## Acceptance

- [ ] Before any upcoming-task lock is acquired, the watcher compares every earlier automated done marker's recorded literal `scope_hash` and `scope_files` with the current tree; manual and malformed done markers remain outside this audit.
- [ ] One audit collects every stale earlier task rather than returning on the first mismatch, runs each task's verify through the configured timeout, and records its command, exit code, output, timeout state, recorded/current aggregate hashes, and sorted differing paths whether verification passes or fails.
- [ ] Each newly stale task receives one active `regressed/<n>.md` and one typed `regressed` event in its own stream; an already-active regression is neither verified nor written again on later cycles.
- [ ] A differing path is attributed to the sole later done task whose `file_changed` events name it when the current per-file hash agrees with that task's completion hash if present; multiple candidates are `ambiguous`, while no trustworthy candidate is `unknown`.
- [ ] Any stale result returns the distinct `blocked_by_regression` watcher-cycle outcome, leaves the upcoming task unlocked and without running/dead/regressed artifacts, and does not increment `tasksRun`.
- [ ] Permanent output contains one line for each stale task using that task number and attribution, followed by exactly one summary in the form `spec <id> halted: tasks <numbers> require recertification` with numeric task ordering.
- [ ] Every temporary change created by the three behavioral suites named by this task's verify command uses a real deterministic local verifier rather than the rejected template sentinel, while direct `runTask` protection, scope-hash exports, `verify_ran` emission, import direction, and source-line budgets remain green.

## Details

Extract the literal per-file hashing currently implemented by
`computeTaskScopeHash` into `src/core/scope-hash.ts` and keep the established
export available from `src/watcher/regression.ts` for frozen callers. This
change deliberately does not expand globs: resolve every declared scope entry
exactly as today's implementation does. Move only process execution and result
capture into `src/core/verification.ts`; keep event emission in the watcher so
core retains its import boundary. `runVerificationGate` remains the watcher
entrypoint and delegates to the shared executor before appending exactly one
`verify_ran` event.

Replace `checkDoneTasksScopeHashes`' first-match behavior with a reusable audit
projection that can accept the set of eligible done task numbers. Keep its
legacy export behavior compatible for `tests/runner-scope-hashes.test.ts`, but
make the cycle use the all-results audit. Read later task attribution only from
typed `file_changed` events in numbered streams and active canonical done
markers. Compare normalized project-relative POSIX paths. A sole event
candidate with no recorded completion hash for that path may be attributed;
an available mismatching hash makes it `unknown` rather than an accusation.

Use the verification result returned directly by the shared executor; do not
reread the event stream to recover exit code, duration, output, or timeout.
Extend `RegressedEventData` with the structured detection fields needed here.
The marker body may render those values for humans, but the event data remains
the reportable record. Before verifying a mismatch, check for the canonical
active regression marker so restart idempotency does not depend on memory.

Call the audit in `runWatcherCycle` after state is read and before `runTask`.
Keep the same audit as direct `runTask` protection before lock acquisition, so
callers outside the cycle cannot bypass it. Preserve processing of other change
folders in the same global cycle while exposing `blocked_by_regression` for the
affected change. Build the focused test through `runWatcherCycle` with the mock
adapter and an adapter spawn counter. Cover two stale tasks, passing and failing
verification, timeout, all attribution states, log ownership, zero task count,
absence of task-3 artifacts, and a second cycle.

The source implementation described above is already complete; this retry is
limited to repairing its final-tree verification after the verify-command
trust lint landed. In `tests/scope-recertification.test.ts`,
`tests/runner-scope-hashes.test.ts`, and
`tests/watcher-loop-logging.test.ts`, replace only dynamically authored
`node -e "process.exit(0)"` fixture commands with a deterministic local verifier
such as `node verify.cjs`, and create that verifier in each temporary project
root. Follow the established `PASSING_VERIFY` and `LOCAL_VERIFIER` pattern in
`tests/linter.test.ts`. Do not weaken the sentinel lint or change the behavioral
assertions these suites make.
