- [ ] `checkAndArchiveSpec` invokes task 1's shared scope audit over every automated canonical done task before any existing archive-time task or change verification.
- [ ] When the final task changed an earlier task's recorded file, the earlier task's detection verify runs and receives the same structured marker, event, and attribution contract as the pre-dispatch path.

- [ ] A repeated archival check with active regression markers adds no verification, marker, or event duplicates.

## Details

Reuse the task-1 audit and its result types directly. Do not add a second hash
comparison, marker formatter, attribution reader, timeout runner, or event
writer to `archiver.ts`. Supply every numeric canonical done task as eligible;
manual done markers continue to be ignored by the scope audit and retain the
existing archive behavior.

Place this gate after the existing done-state eligibility check and before the
first call that executes archive verification. A blocked audit returns `false`
through `checkAndArchiveSpec`; the watcher already uses that value to retain
the active folder. Detection verification still emits its own `verify_ran`,
but none of the ordinary archive-preflight commands may run afterward.

Extend `tests/archive-verification.test.ts` with a three-task fixture whose
final task records and changes a task-1 path, plus a two-stale-task case and a
second-call idempotency assertion. Keep `tests/archiver.test.ts` and task 1's
new audit suite frozen. Preserve the existing archive-time verifier semantics,
including its first failing command behavior, task/change regression reasons,
and successful archive order.
