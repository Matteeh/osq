## Acceptance

- [ ] `osq retry <id> <n>` distinguishes a scope-regression marker from dead and other regression targets, runs that task's verify under `verifyTimeoutSeconds` through task 1's shared executor, and spawns no adapter itself.
- [ ] On exit zero, retry attempt-suffixes only the active regression marker, keeps canonical `done/<n>`, preserves its completion body, build stamp, exit code, and prior `original_scope_hash`, refreshes `scope_hash`/`scope_files`, and writes `recertified_at` plus an incremented `recertification_count`.
- [ ] The first passing recertification copies the prior `scope_hash` to `original_scope_hash`; later passing recertifications never replace it, append one typed `recertification` event with `outcome: passed`, and do not append `retry`/`started` or increment execution attempts.
- [ ] On non-zero exit or timeout, retry attempt-suffixes both active regression and canonical done markers, appends `recertification` with `outcome: requeued`, leaves the task pending, and preserves existing target-wide ordinal and next-execution attempt semantics.
- [ ] Every recertification event carries task, differing paths and attribution from the marker, verify command, exit code, output, timeout state, recorded/original and current scope hashes, and the `passed` or `requeued` outcome.
- [ ] After a requeue and watcher restart, every textual harness prompt contains the failed recertification output in the shared prior-context section alongside the next attempt, failure reason, and prior result path.
- [ ] Dead-task retry, non-scope task regression retry, change-level retry, approval/running refusals, retained history, CLI errors, and existing retry event behavior remain unchanged.

## Details

Branch only when the numeric target has an active regression marker whose
frontmatter reason is `scope_regression` and an active automated done marker.
All validation, including approval integrity and running-state checks, happens
before verification or mutation. Continue routing dead tasks, archive verify
regressions, and the literal `change` target through the established preserving
retry transition.

Call the task-1 verification executor from core without importing watcher or
harness. Parse the task verify command and recompute the current literal scope
with `src/core/scope-hash.ts`. Preserve the done marker's body bytes as the
authoritative completion timestamp. Rebuild its YAML frontmatter without
dropping unknown metadata; retain `build_stamp` and `exit_code`, and treat an
absent or invalid recertification count as zero. Use the same target-wide
ordinal calculation as ordinary retry when renaming markers.

Extend the event union with `recertification`. A passed event is the only
transition record and does not advance attempt context. A requeued event must
carry enough append-only context for `readRetryContext` to reconstruct the next
execution attempt, reason, and failed output after restart; do not depend on a
process-local return value. Extend `SpawnTaskOptions` and `priorContextLines`
so AGY, OpenCode, and Codex all render the same bounded failed-output block.
Preserve raw output in the event, but keep prompt formatting deterministic and
avoid duplicating it in the prior result file.

Add `tests/retry-recertification.test.ts` for first and repeated pass, failure,
timeout, malformed marker refusal, preserved metadata, ordinal history,
events, and no-attempt accounting. Extend only the prior-context cases in
`tests/harness-prompt-injection.test.ts`; every other existing retry and prompt
test is frozen.
