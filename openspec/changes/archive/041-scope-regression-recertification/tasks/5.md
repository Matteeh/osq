## Acceptance

- [ ] The managed planner block states that every task verify must be re-runnable against the final tree of the completed change because watcher and archive recertification will run it there.
- [ ] The block states that a file belongs to one task unless a later task must extend it, in which case the later task is ordered after the owner and the proposal explicitly notes the shared file.
- [ ] The two rules appear in the relevant task-planning guidance rather than as detached prose and retain all existing planner instructions.
- [ ] Repository `PLANNER.md`, `templates/PLANNER.md`, and `MANAGED_PLANNER_BLOCK` remain byte-identical between the managed markers.
- [ ] `osq init` adds the new rules to a fresh project and updates only the osq-managed block in an existing planner file.
- [ ] Foreign text and managed blocks survive initialization unchanged.

## Details

Extend the existing `### Tasks` guidance in the managed block. Keep the wording
direct and normative. The final-tree rule supplements, rather than replaces,
the requirement that a task verify exercise its slice through the real entry
point. The ownership rule governs authored task scopes and requires the
proposal note only for an intentional later extension; it does not introduce
automatic overlap lint in this change.

Update all three managed-block sources together and strengthen the existing
byte-equality and initialization assertions. Reuse `MANAGED_PLANNER_BLOCK` and
the current managed-block replacement path. Do not alter AGENTS instructions,
task templates, configuration limits, or OpenSpec schema behavior.
