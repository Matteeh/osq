## Acceptance

- [ ] Lint applies the same verify-command trust checks to the proposal and every task while retaining the existing empty-command and chaining-command diagnostics.
- [ ] The template placeholder `node -e "process.exit(0)"` and equivalents normalized for surrounding/repeated whitespace, quote style, `-e` versus `--eval`, and an optional JavaScript semicolon hard-fail with one actionable message requiring real final-tree verification.
- [ ] `pnpm <script>`, `pnpm run <script>`, `npm run <script>`, and equivalent supported package-script forms hard-fail when the root `package.json` has no matching script and accept a present script without a path warning.
- [ ] A non-placeholder command that names neither an existing repository-relative path nor a recognized package script emits a warning identifying the proposal or task file, while commands naming at least one existing file or directory emit no such warning.
- [ ] Command analysis is deterministic and read-only, does not execute or resolve through the shell, tolerates a missing or malformed root `package.json`, and does not reinterpret shell chaining already rejected by lint.
- [ ] Every checked-in markdown fixture under `fixture/` and `tests/fixtures/` replaces the placeholder with a deterministic local verification command backed by files in that fixture's execution root.
- [ ] `AGENTS.md` and `README.md` explain that generated placeholders must be replaced, fixtures use real local verification, and the lint table includes the new errors and warning without presenting the placeholder as valid coverage.

## Details

Create one verify-command analyzer inside `src/core/linter.ts` and call it for
the parsed proposal verify plus each parsed task verify. Normalize only enough
to recognize the sentinel safely: trim, collapse ASCII whitespace, treat
single and double quotes around `process.exit(0)` equally, accept an optional
semicolon inside that expression, and recognize Node's `-e` and `--eval`
spellings. Do not execute, shell-expand, or broadly canonicalize arbitrary
commands.

Read the project-root `package.json` once. Recognize direct package-script
invocations for pnpm, npm, yarn, and bun, including their ordinary `run`
forms, and compare the referenced name with the manifest's `scripts` keys. A
recognized invocation with a missing script is an error, not the generic path
warning. For other commands, tokenize conservatively and consider unquoted or
quoted repository-relative operands that exist beneath `projectRoot`; command
binaries and option values do not count as behavioral paths. When certainty is
not possible, warn rather than reject.

Replace only fixture artifact commands, not archived change history. Give each
fixture root the smallest deterministic local verifier needed by its tests;
do not point at this repository's full `pnpm verify`, the network, a TTY, or a
file outside the copied fixture. Keep the placeholder in generated templates
as an explicit sentinel that planning must replace before approval. Update
existing linter setup constants that currently use the placeholder as a
passing command, and add focused proposal/task cases for every diagnostic.
Other named tests are frozen regression coverage for migrated fixtures and
scaffolding.
