## Deviated

- `outline::RequirementOutline` carries `section: Option<usize>`, the index of the `##` heading the block sits under. Living validation uses it to split inside from outside the first Requirements section instead of comparing the requirement line with the heading line. Such a comparison has no input that tells `>` from `>=` (or `<` from `<=`) because no requirement header shares a heading's line, so cargo-mutants reported those two as missed; the section index removes the equivalent mutants. It is still about headings and blocks, so task 2 can reuse it.
- `tests/validating_living.rs` would exceed the 250-line cap with every case, so the Whole-word keywords, ordering and folder cases are in `tests/validating_living_rules.rs`, which matches the scope glob `tests/validating_living*.rs`. `validating_living.rs` still proves Finding codes, one case per row.
- Messages are free-form per the spec, so the tests pin only code, line, requirement, fix and a non-empty message.
