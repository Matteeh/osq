## Details

Put the code in a new module `src/validate/`: the finding types in
`finding.rs`, the line scan in `outline.rs`, the requirement rules in
`requirement.rs`, and the living spec rules and folder reader in
`living.rs`. More files are allowed when they match `living*.rs` or
`requirement*.rs`.

The parse carries no line numbers, so `outline.rs` scans the normalized
lines itself: each `##` heading outside fences with its line and title,
and each requirement header outside fences with its line and the
requirement block it starts, plus the line of each `####` scenario line
inside a block. Task 2 reuses it for delta specs, so keep it about
headings and blocks, not about living specs. Reuse `normalize_document`,
`fence_mask`, `is_top_level_heading` and `is_named_heading` from
`src/markdown/text.rs`, `requirement_header_name` and `blocks_in` from
`src/markdown/requirement.rs`, `starts_scenario` from
`src/markdown/scenario.rs`, and `parse_requirement`; don't write a second
parser of requirement or scenario blocks. All of these are `pub(crate)`
already. Take a living spec's purpose and requirements from
`parse_living_spec`.

The requirement rules take a `Requirement` and its header line and return
findings, so task 2 can run them on ADDED and MODIFIED requirements. For
the fence rule on a body, `fence_mask` over the body's own lines gives
the lines to leave out; a mask that marks the fence lines too is what the
rule needs.

The fixtures are the source of truth. Copy them, and never edit them.
Tests find them from `env!("CARGO_MANIFEST_DIR")`. Build the "Whole-word
keywords" cases as a living spec around each body, with a scenario, so
only the keyword rule can fire. For the read error case, write the file
under `env!("CARGO_TARGET_TMPDIR")`. More test files are allowed when
they match `tests/validating_living*.rs`.

Keep every `.rs` file under 250 lines and every function under 80.
Workspace lints include `clippy::pedantic` and `-D warnings`; meet them
rather than allowing them. Keep tests in `tests/`. When the mutation step
reports a missed mutant, add a case for it. Run `cargo fmt --all` before
exiting.
