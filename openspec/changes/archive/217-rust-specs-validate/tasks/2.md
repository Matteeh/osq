## Details

Put the delta rules in `src/validate/delta.rs`, the target check in
another `delta*.rs` file, and `validate_change` in `change.rs`. Reuse
task 1's `outline.rs` scan for headings, requirement headers and their
lines, and its requirement rules for ADDED and MODIFIED requirements.
Extend `outline.rs` when the delta rules need more from the scan, and keep
task 1's tests passing.

The delta reading rules belong to `parse_delta` in
`src/markdown/delta.rs`: section titles, REMOVED names, and FROM, TO and
invalid rename lines. The rules need each entry's line, which the parse
drops, so reuse its private line helpers, such as `rename_side`,
`is_invalid_rename`, `removed_bullet_name` and `split_sections`, by making
them `pub(crate)`. Change nothing else in that file, and write no second
reading of those lines.

The fixtures under `tests/fixtures/validate/delta/` and
`tests/fixtures/validate/targets/` were copied by task 1; never edit them.
Tests find them from `env!("CARGO_MANIFEST_DIR")` and compare each
finding's `file` with the fixture path joined the same way. For the
unreadable delta, write the change under `env!("CARGO_TARGET_TMPDIR")`.
More test files are allowed when they match `tests/validating_deltas*.rs`.

Keep every `.rs` file under 250 lines and every function under 80.
Workspace lints include `clippy::pedantic` and `-D warnings`; meet them
rather than allowing them. Keep tests in `tests/`. When the mutation step
reports a missed mutant, add a case for it. Run `cargo fmt --all` before
exiting.
