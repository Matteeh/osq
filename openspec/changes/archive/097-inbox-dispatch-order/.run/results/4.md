# Task 4 — `osq inbox` ordered list and first card

## Changed

- Added `src/core/status/dispatch.ts`. It composes `readDispatchItems`,
  `orderDispatchItems`, and `readDispatchCard` into one read and exports:
  - `readDispatch(projectRoot, config)`: the ordered queue plus only the first
    item's card (`DispatchPreview`), for text output.
  - `readDispatchQueue(projectRoot, config)`: the ordered queue with every
    item's card (`DispatchQueue`), for JSON output.
  - `DispatchQueueItem`, `DispatchQueue`, and `DispatchPreview` types.
- Added `src/core/status/dispatch-text.ts`. `formatDispatchText(preview)`
  prints `Nothing needs you.` for an empty queue; otherwise
  `Needs you (<n>):`, one
  `  <position>. <kind> <id> <title>[ task <n>: <task title>] (<reason>)` line
  per item, a blank line, and the first card as `<kind>: <folder>`,
  `  why: <reason>`, the body for its kind, then `Actions:` with one
  `  <command>` line per command. The approval body is exactly
  `formatApprovalDigest`'s output; halt, land, and verify bodies print their
  card fields.
- Added `src/cli/inbox-dispatch.ts`. `inboxDispatchCommand` reads `osq inbox`
  through the real entry points, prints through the injected `stdout` when
  given (else `console.log`), and writes nothing. `registerInboxDispatchCommand`
  registers `osq inbox [--json]`.
- `src/cli/index.ts` imports and calls `registerInboxDispatchCommand(program)`
  beside `registerMessageCommand`; it is 246 lines, under the 250 cap.
- README.md's Commands list gains `osq inbox` and `osq inbox --json`, and the
  Human Attention Inbox section explains what `osq inbox` lists and how it
  orders the queue.
- Added `tests/inbox-dispatch.test.ts` covering every "Inbox dispatch command"
  scenario: the ordered list with the first card, JSON with a card per item,
  the empty message, and program registration. It also checks the halt card's
  attempts and the idle/weight reason strings.

## Deviated

- The acceptance says dispatch.ts "composes ... into one read" that reads the
  first card for text and every card for JSON. I exposed two entry functions
  (`readDispatch` for the first card, `readDispatchQueue` for every card) over
  one shared ordering helper, so each caller reads only the cards it needs.
- The delta fixes the card header, reason line, and `Actions:` block but not
  the halt/land/verify body layout; I chose a compact `label: value` form and
  verified it through the text tests.
