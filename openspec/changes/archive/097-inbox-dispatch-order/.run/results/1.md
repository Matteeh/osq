# Task 1 — Dispatch items

## Changed

- Added `src/core/status/dispatch-items.ts`. `readDispatchItems(projectRoot, config)`
  reads `getStatusOverview` and derives `{ watcherIdle, items }` with nothing
  written. Each item carries `kind` (`approval` | `halt` | `land` | `verify`),
  a `change` ref (`id`, `folder`, `title`, `folderPath`), a `task` ref
  (`number`, `title`) or null, and the exact `commands` osq already has.
  - `approval` for a change whose next step is `ready-for-approval`.
  - `halt` for each dead/regressed task and one change-level halt for
    `changeRegressed` (before its task items).
  - `verify` for each pending verification, from the overview plus the first
    change tree's archive path.
  - `land` from `findLandCandidates`.
  - Items are sorted by numeric change id, then task number, change-level
    before tasks.
  - `watcherIdle` is true when no active change's next step is `running`.
- Added `src/core/status/dispatch-land.ts`. `findLandCandidates` selects `Vcs`
  once and returns nothing under `NoVcs`. With `vcs.enabled`, it lists archived
  changes in worktree trees and keeps those `readDependencyState` reads as
  `archived`. With the flag off, it lists the first change tree's archive
  directory and keeps folders `Vcs.status` lists as untracked or modified,
  itself or under it (trailing-slash untracked entries included).
- Added `tests/dispatch-items.test.ts` covering every "Dispatch items"
  scenario: each kind with commands, unplanned draft, state follow-through,
  change regression, untracked archive with the flag off, no-git, watcher
  idle, and the worktree archive until a squash merge lands it (built with
  `makeProject`/`ActingAdapter` copied from `tests/stack-run.test.ts`).

## Deviated

- The delta does not name the item types. I exported `DispatchKind`,
  `DispatchChangeRef`, `DispatchTaskRef`, `DispatchItem`, and the
  `readDispatchItems` return type `Dispatch` from `dispatch-items.ts`.
- Items that share a change id and task number (possible for an archived
  change that is both a land and a verify item) need a deterministic tiebreak;
  I fixed the rank `approval`, `halt`, `land`, `verify`. Ordering tests in
  task 2 can still re-sort by weight.

## Missing context

- `StatusOverview.pendingVerifications` drops each pending folder's
  `folderPath`. The item needs it, so `verifyItems` derives it from the first
  `changeTrees` tree's archive directory — the same directory
  `getStatusOverview` lists pending verifications from.
