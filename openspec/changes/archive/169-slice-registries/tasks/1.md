- [ ] New `src/cli/slice-types.ts` holds `HelpGroupTitle`, `SliceCommand` and `Slice` exactly as cli-foundation "Slice registry" writes them, importing `Command` from commander and `McpTool` and `McpTarget` as types only. New `src/core/foundation/config-slices.ts` holds `SliceConfigBlock`, `composeDefaultConfig` and `resolveSliceConfig`; it imports nothing from `src/cli/`, so it types its slices structurally (`name` and optional `config`) and `SLICES` is assignable to that type.
- [ ] New `src/cli/slices.ts` exports `SLICES: readonly Slice[]` as an empty array, with a doc comment saying each `src/<capability>/slice.ts` or `src/kernel/<capability>/slice.ts` adds one `import { slice as <name> }` line and one entry, sorted by name.
- [ ] `src/core/foundation/config.ts` keeps today's default object as its base and exports `DEFAULT_CONFIG = composeDefaultConfig(base, SLICES)`; `defineConfig` ends its result with `...resolveSliceConfig(config, SLICES)`. Its exports and public types do not change. It stays at or under 250 lines; if it would not, move the base object into new `src/core/foundation/config-base.ts`.
- [ ] `tests/import-graph.test.ts` allows exactly one import from core to outside core: `src/core/foundation/config.ts` importing `src/cli/slices.ts`. Every other rule and test in it stays as it is.
- [ ] New `tests/cli-slice-registry.test.ts` holds the registry check and the import check as functions over plain inputs (folder and slice-name pairs plus registered names; a map from repository path to source text), and proves both table scenarios of "Slice registry" with those exact rows and messages. Classify import lines the way `tests/import-graph.test.ts` does (`import type`, `export type` and all-`type` brace lists do not count; `import()` does not count).
- [ ] The same test proves "osq's registry passes its own check": it finds every `src/*/slice.ts` and `src/kernel/*/slice.ts` on disk, imports each, runs both checks against `SLICES`, and expects no problem.
- [ ] New `tests/config-slice-blocks.test.ts` proves every scenario of "Slice configuration blocks" with the exact rows, comparing `JSON.stringify` output where the table gives JSON. It also checks that `JSON.stringify(DEFAULT_CONFIG)` equals `JSON.stringify(composeDefaultConfig(DEFAULT_CONFIG, []))`.
