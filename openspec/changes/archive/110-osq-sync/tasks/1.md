## Acceptance

- [ ] `syncWithDefaultBranch` follows the version-control delta's modified "Default branch sync". Its signature is unchanged. It treats the change as active when `change.location` is `active` and as archived otherwise.
- [ ] New `src/core/vcs/sync-stop.ts` exports `SyncStop`, an `Error` subclass with a readonly `reason` of `sync_conflict` or `sync_failed`. Every stop of the sync throws one, the requirement check's stop from `assertRequirementsUnchanged` included. A failure after the merge started is caught, the merge is aborted, and the failure is rethrown as a `sync_failed` `SyncStop` with the same message.
- [ ] Step 5 lives in new `src/core/vcs/sync-verify.ts`. It reads the done tasks and their `verify` through `deriveSpecState` and `readChangeFolder`. It reads a done marker's `manual` flag with `parseFrontmatter`, as `readTaskMeta` in `src/watcher/worktree-commit.ts` does, and imports nothing from `src/watcher`. It appends events with `fs` directly, as `appendSyncEvent` does today.
- [ ] `rebuildLivingSpecs` writes every capability folder under the living specs directory from the default branch and applies deltas only when given an archived folder. `listDeltaCapabilities`, `livingSpecPath`, and `changedRequirements` keep their behaviour.
- [ ] Every abort writes back `.run/events/change.jsonl` as it was before the sync, as the modified requirement's opening paragraph says. The abort for a code conflict does this too, and so do the stops in `sync-verify.ts`.
- [ ] New `tests/vcs-sync-active.test.ts` covers the scenarios "Active change before its first task", "Active change re-runs done tasks", "Red task verify after the merge", "Code conflict in an active change", "Failed commit keeps uncommitted events", and "Stacked dependent after its dependency landed" on real temporary repositories.
- [ ] `tests/vcs-sync.test.ts`, `tests/vcs-land.test.ts`, `tests/vcs-land-commit.test.ts`, and `tests/vcs-land-refusals.test.ts` pass unchanged. Every function stays within 80 lines and every file within 250.

## Details

Build repositories the way `tests/vcs-sync.test.ts` does, with git run
directly. An active change is a worktree on `osq/<folder>` whose changes
directory holds the folder with `.run/approved`, `.run/base`, and `tasks/<n>.md`
files whose `verify` is `node verify.cjs`. A task is done when
`.run/done/<n>` exists. `manual: true` goes in that marker's frontmatter.

For "Stacked dependent after its dependency landed", do with git what `osq
land` does. Commit `001`'s archive on `osq/001-<words>` with a
`.run/events/change.jsonl`. Cut `osq/002-<words>` from that commit and give it
an active `002` with one commit of its own. Commit an unrelated file on
`main`. On `001`'s branch, merge `main`, append a line to `001`'s archived
`change.jsonl`, and commit. Then land it with `git commit-tree <tip>^{tree}
-p main` and `git merge --ff-only` on `main`. Merging `main` into `002` now
conflicts only in that `change.jsonl`, as the proposal's Background says.

Conflicts under the archive directory are found by path prefix. Use
`change.tree.archiveDir` relative to `change.tree.root`. A structural test
forbids calling `getArchiveDir` outside its allowed files.
