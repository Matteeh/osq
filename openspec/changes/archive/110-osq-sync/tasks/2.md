## Details

Build projects the way `tests/vcs-land.test.ts` does: `approveSpec` into
worktrees, a local `node verify.cjs` verifier, and an adapter that edits files
in scope. Build stacked changes the way `tests/stack-run.test.ts` does.

To move the default branch at a set moment, commit on `main` in the checkout
from inside the adapter's spawn, keyed on the change and task it was handed.
An agent's commit in its own worktree is a `vcs_violation`. A commit on
`main` in the checkout is not, because the git guard's snapshot covers only
the task's own tree.

For "Dependency lands during the dependent's run", the adapter spawning
`002`'s task commits an unrelated file on `main` in the checkout. It then
calls `landChange` for `001` with the checkout as its project root, before
it writes `002`'s task edits. Assert the land's result code is zero inside
the test.

For "Conflict halts the change", give the change one task that changes a
line of a tracked file. Commit a different change to that line on `main` from
the adapter, after the task's edit. `runWatcherOnce` then verifies the task
and syncs before archive in the same cycle.
