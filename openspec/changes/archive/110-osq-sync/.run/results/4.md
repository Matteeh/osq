## Changed

- `src/core/status/last-sync.ts`: new module. `readLastSync(folderPath)` reads the
  change folder's `.run/events/change.jsonl` once, keeps the last `synced` event
  as `{ timestamp, defaultBranch, commits }`, and keeps the last `sync_stopped`
  event as `lastSyncStop` only when it follows that sync or no sync exists.
  Malformed lines and events with missing fields are ignored. `formatLastSyncLines`
  renders the `last sync:` line with `commit` for one commit, then the
  `sync stopped:` line with the change's numeric id and the stop message's first
  line indented four spaces.
- `src/core/status/status.ts`: `ChangeWorktree` gains optional `lastSync` and
  `lastSyncStop`. `getStatusOverview` reads `readLastSync` once for each change in
  a worktree and spreads it into the entry. `formatStatusOverview` prints the sync
  lines below the worktree line and its warnings and above the `next:` line.
- `tests/status-sync.test.ts`: new tests covering every "Last sync in status"
  scenario: last of several syncs directly above `next:`, lines below the worktree
  line and warnings, never synced, a broken line before a `synced`, a stop after
  the last sync with its message line, a stop cleared by a later sync, a stop with
  no sync, and the stop line through `statusCommand`.
