## Acceptance

- [ ] New `src/cli/plan-steer.ts` exports `readSteeringPlan(projectRoot, config, name)`. It finds the change with `findChange` and derives its state in the change's own tree. It returns null when no change matches, or when a change in the checkout has no `steering`. It throws the cli-foundation delta's message for an approved change in a worktree or stacked approval without `steering`. Otherwise it returns the located change, its id, and the `## Steering` section.
- [ ] The section is exactly what "Planning a change that needs steering" lists. It reads each marker with `steeringMarkerPath` and strips the frontmatter with `parseFrontmatter`, and it names the done tasks from the derived state.
- [ ] `planCommand` calls `readSteeringPlan` for a named change before `findSpecFolder`. With a result it resumes that folder, appends the section after the prompt `buildOpeningPrompt` returns, and writes the handoff's `plan-prompt.md` there. It passes the change's tree root as `cwd` to `spawnInteractive` and `readPlanningUsage`. `planCommand` is in the function-budget grandfather list, so the new lines go in place and nothing moves out; `plan.ts` stays at or under 250 lines.
- [ ] `lintCommand` resolves each explicit id with `findChange` first and falls back to `findSpecFolder`. It still lints every folder with `cwd` as project root and one import graph built from `cwd`, as "Lint finds a change in any tree" says.
- [ ] New `tests/steering-plan.test.ts` covers the three scenarios of "Planning a change that needs steering" and "Lint a change in its worktree". It runs `planCommand` and `lintCommand` against a temporary git repository with a change approved into a worktree, with `vcs.enabled` and a fake interactive adapter for the session.

## Details

`deriveSteering`, `describeTrigger`, and `steeringMarkerPath` come from task 1
in `src/core/status/steering.ts`; read them, do not change them. A test that
lints needs the fake OpenSpec validator that `installFakeValidator` in
`tests/helpers.ts` installs in the checkout. Linting with the worktree as
project root fails, because the worktree has no `node_modules`.
