## Changed

- Added `src/core/status/steering.ts`. It exports `SteeringTriggerName`
  (`stuck`, `blocked`, `regression`), `SteeringTrigger` (`target`, `trigger`,
  `reason`), `deriveSteering(snapshot)`, `describeTrigger(trigger)`, and
  `steeringMarkerPath(folderPath, trigger)`. `deriveSteering` reads only the
  `ChangeFolderSnapshot` it is given: it returns nothing for an unapproved
  change, the change-level `verify_red`/`verify_path_missing` regression first,
  then task triggers in numeric order (task regression wins; a done marker
  suppresses a dead marker; `reason: blocked` is blocked, then `stuck: true`).
  It imports types only from `state.ts`, so the two modules have no runtime
  import cycle.
- `src/core/status/state.ts`: `SpecState` gains optional
  `steering: SteeringTrigger[]`, and `deriveSpecState` sets it only when
  `deriveSteering` returns a non-empty list. The file stays at 231 lines.
- `src/watcher/loop.ts`: after the automatic-retry step the cycle re-derives
  `specState` and, when `specState.steering` is set, skips the change before
  the worktree pending-commit, archive-spec restore, and clean-tree block. No
  marker, event, commit, spawn, halt, archive, or approved-waiting count
  happens for such a change. `runWatcherCycle` stays in the grandfather list.
- Added `tests/steering-triggers.test.ts`: snapshot tests for every scenario of
  "Steering triggers" (stuck, blocked, archive regression order, task
  regression, non-trigger, done-suppressed dead task, unapproved) plus
  `describeTrigger`/`steeringMarkerPath`, and the three
  "Watcher leaves a change that needs steering" scenarios in a temporary git
  repository (edited plan left alone, second identical death marked stuck then
  left alone, retried stuck task spawns again).

## Deviated

- The automatic-retry block now re-derives `specState` on every approved change
  instead of only when a retry was made. Without this, the cycle that marks a
  second identical death stuck would not see the fresh `steering` list and could
  fall into the worktree clean-tree/commit block. The acceptance places the skip
  "right after the automatic-retry block", which this keeps.
