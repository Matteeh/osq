## Changed

- Added `src/core/spec/approve-steer.ts`. `approveSteeredChange(projectRoot,
  change, config, options)` derives the worktree change's state, refuses while a
  task status is `running` with `<folder> has a task running; approve it after
  the task ends`, then lints in the checkout, confirms the digest, appends
  observed sessions, hashes the worktree folder, writes `.run/approved` and the
  manifest there with `writeApprovalSeal`, commits the folder with
  `osq: <id> approved` through the worktree's `selectVcs`, and retires the
  triggers. It returns `worktreePath`, `branch`, and `continuesFrom`. The same
  module exports `retireSteering(projectRoot, config, change, triggers)`, which
  calls `retrySpec` for each trigger target in `deriveSteering` order and then
  returns the first task of the change that is not done, or null.
- `src/core/spec/approve.ts`: `ApproveResult` gained optional `continuesFrom`.
  `approveSpec` derives the located change's state right after `findChange`; a
  worktree change whose state has `steering` goes to `approveSteeredChange`
  instead of the existing worktree path. The in-place path is unchanged except
  that, after `approveInPlace`, a state with `steering` has its triggers retired
  through `retireSteering`.
- `src/cli/approve.ts`: prints `  Continues from task <n>` after the worktree
  lines when `continuesFrom` is set. An approval that needs no steering prints
  exactly what it printed before.
- `tests/dead-marker-retention.test.ts`: the re-seal case now writes the
  change-level `.run/regressed/change.md` with `reason: worktree_dirty` instead
  of a task-level `verify_red` regression, so it still covers "Reapproval
  retains active failure" without a steering trigger. Every other case is
  unchanged.
- Added `tests/steering-approve.test.ts`: covers each scenario of "Approval
  after steering" (blocked task approved in its worktree with `Continues from
  task 2`, the run continuing through `runWatcherCycle` to the archive, change
  regression retired with `Continues from task 3`, running task refusal writing
  nothing, and version control off retiring a stuck task in place) plus "Running
  change that needs no steering" (branch message, unchanged HEAD). The temporary
  repository setup is copied from `tests/worktree-run.test.ts`.
