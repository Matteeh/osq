## Changed

- `src/core/status/next-step.ts`: `readActiveNextStep` now returns
  `dead (needs steering) — osq plan <id>` when the derived state has
  `steering`, checked before the existing dead/regressed branch.
- `src/core/status/inbox.ts`: `NeedsYouItem` gains optional
  `steering: { trigger, reason }` (trigger is `SteeringTriggerName`). The file
  stays at 245 lines, inside the 250-line budget.
- `src/core/status/blocked-item.ts`: `applyBlockedItems` became
  `applySteeringItems(overview, items)`. For each change with `steering` it
  keeps only its first trigger's halt item, sets command `osq plan <id>` and
  `steering`, adds `blocked: { need }` for a blocked trigger read through
  `parseResultSections`, and drops the change's other halt items. Every other
  item is returned unchanged in order.
- `src/core/status/inbox-projection.ts`: `readInbox` calls `applySteeringItems`.
- `src/core/status/inbox-text.ts`: `needsYouLine` renders
  `<row> — needs steering: <trigger> (<reason>)[: <collapsed need>] — osq plan <id>`.
  The old stuck row and the old `osq plan --next --replan` blocked row are
  gone; a non-steering change regression keeps `change regressed`.
- `src/core/status/dispatch-items.ts`: `DispatchItem` gains optional
  `steering`. `haltItems` returns exactly one halt for a steered change, on its
  first trigger, with commands `osq plan <id>` and `osq show <id>`.
- `src/core/status/dispatch-text.ts`: `formatDispatchCardBody` adds
  `  needs steering: <describeTrigger>` right after the `why:` line.
- `src/core/status/dispatch-keys.ts`: `cardKeys` maps `osq plan <id>` to `p`.
- Tests updated: `tests/dispatch-items.test.ts`, `tests/dispatch-keys.test.ts`,
  `tests/dispatch-session.test.ts`, and `tests/next-step.test.ts` now stand in
  for an ordinary halt with `worktree_dirty` instead of the `verify_red`
  trigger, keeping the `osq retry` and reject-key coverage.
  `tests/inbox-blocked.test.ts`, `tests/inbox-stuck.test.ts`, and
  `tests/inbox.test.ts` expect the one steering item, `osq plan <id>`, the
  `steering` field, and (for `fixture/inbox`) `osq plan 003` / `osq plan 004`.
- Added `tests/steering-inbox.test.ts`: covers every "Steering inbox items"
  scenario plus "Steering field", "Steering halt", "Steering keys",
  "Steering next step", and "Steering format".
