## Changed

- Added `src/cli/plan-steer.ts`: `readSteeringPlan(projectRoot, config, name)`
  resolves the change through `findChange`, derives its state from the change's
  own tree (`change.tree.root`), and returns the located change, its id, and
  the `## Steering` section. It returns `null` when no change matches or a
  checkout change has no `steering`, and throws the cli-foundation message for
  an approved worktree or stacked change with none. The section lists each
  `deriveSteering` trigger with `describeTrigger`, the absolute marker path
  from `steeringMarkerPath`, the marker body from `parseFrontmatter` in a
  fenced block, then the tree root, folder, done task numbers, and id lines.
- `src/cli/plan.ts`: `planCommand` calls `readSteeringPlan` for a named change
  before `findSpecFolder`; a result resumes that folder, appends the section to
  the prompt `buildOpeningPrompt` returns, and writes it as the handoff's
  `plan-prompt.md`. `spawnInteractive` and `readPlanningUsage` receive the
  change's tree root as `cwd`. The file is 230 lines, inside the 250-line
  budget; `planCommand` stays in the function grandfather list.
- `src/cli/lint.ts`: added `resolveLintFolder`, which resolves each explicit id
  through `findChange` first and falls back to `findSpecFolder` when no tree
  matches. Linting still uses `cwd` as project root and one import graph built
  from `cwd`.
- Added `tests/steering-plan.test.ts`: covers the three "Planning a change that
  needs steering" scenarios (worktree handoff content and location, session cwd
  and prompt, refusal with no steering) and "Lint a change in its worktree". It
  builds a temporary git repository whose change is approved into a worktree,
  and uses a fake interactive adapter that records the spawn and usage-read
  `cwd`.
