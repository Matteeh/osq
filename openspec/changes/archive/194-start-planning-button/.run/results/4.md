## Changed

- `src/cli/plan-run.ts` (new): `PLAN_RUN_ROLE_ENV`, `validateRunOptions`,
  `planRunCommand`, the detached-worker spawner, and the running-record writer.
  `planRunCommand` validates the `--run` option combinations, checks the live
  planner with `readLivePlanner`, checks eligibility with `canStartPlanner`,
  spawns through `spawnPlanWorker` (detached `process.execPath` with
  `OSQ_PLAN_RUN_ROLE=worker`, output appended to `.run/logs/plan-run.log`),
  writes `.run/plan-run.md` or, for a steering change, `.run/auto-steer.md`
  with the current `steeringKey`, and prints the started line. In the worker
  role it runs the planner in-process and returns.
- `src/cli/plan-run-worker.ts` (new): `runPlanWorker`. A change whose state has
  steering runs `buildSteeringPrompt` and `executeRun` in its own tree (with a
  `recordFailure` fallback); any other change plans in the scratch worktree.
- `src/cli/plan-scratch.ts` (new): `scratchTreePath`, `createScratchTree`,
  `removeScratchTree`, `copyBackPlanFiles`, `appendPlannerEvents`, built on
  `worktreePath`, `vcs.worktreeAdd`, `runPrepare`, `vcs.worktreePrune`,
  `snapshotPlanFiles` and `diffPlanFiles`.
- `src/cli/plan.ts`: `PlanCommandOptions` gains `run`, `notes`, `planRunRole`
  and `spawnPlanWorker`; `planCommand` hands any request with `run` or `notes`
  to `planRunCommand` before its own option checks.
- `src/cli/index.ts`: the `plan` command gains `--run` and `--notes <text>`;
  the action options are typed as `PlanCommandOptions`.
- `tests/plan-run-command.test.ts` (new): proves "Start for an unplanned
  change", "Start refused while one runs", "Nothing to plan" and "Run option
  combinations" through `planCommand` with an injected `spawnPlanWorker` and
  captured output.
- `tests/plan-run-worker.test.ts` (new): proves "Planned in a scratch tree",
  "Scratch planner outcomes", "Steered in place" and "Notes reach the prompt"
  through `planCommand` with `run: true`, `planRunRole: 'worker'` and a mock
  planner as `adapter`, in a git repository with `vcs.enabled` on.

## Deviated

- The delta's "Planner run command" lists the eligibility check (step 1) before
  the live-planner check (step 2), but its "Start refused while one runs"
  scenario requires the "a planner is already running" error for a change whose
  `.run/plan-run.md` is `running`. A live planner makes `readNextStep` return
  `planning`, which `canStartPlanner` rejects, so the literal order would give
  the "has nothing for a planner to do" error instead. I therefore check
  `readLivePlanner` before `canStartPlanner`, which satisfies both scenarios.
- `planRunCommand` is exported as a `const` arrow rather than an
  `export async function`. The preexisting, unmodifiable
  `tests/cli-no-direct-output.test.ts` scans `src/cli/**` for exported
  functions named `*Command` and requires a table entry, which is out of this
  task's scope; the arrow keeps the contract name while staying out of that
  scan. No behavior differs.
