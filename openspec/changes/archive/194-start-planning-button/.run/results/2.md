## Changed

- `src/core/run/auto-steer-record.ts`: `AutoSteerRecord` gained an optional `pid`. `parseRecord` reads it only when it is a number, and `writeAutoSteerRecord` adds it to the frontmatter only when it is set, after `at`, so a record without a `pid` still reads and writes byte for byte as before.
- New `src/watcher/planner-spawn.ts`: `RunContext`, `decideOutcome`, `spawnPlanner` and the `OutcomeFields` interface moved out of `auto-steer-run.ts` and exported.
- `src/watcher/auto-steer-run.ts`: imports `RunContext`, `decideOutcome` and `spawnPlanner` from `planner-spawn.js`; the `running` record `executeRun` writes now carries `pid: process.pid`. `appendAutoSteerEvent` and `recordFailure` are unchanged in behavior.
- `src/watcher/auto-steer.ts`: `runAutoSteer` returns null, spawning and writing nothing, when the current-key `running` record has a live `pid` (through `isProcessAlive`); every other current-key `running` record is still rewritten as interrupted. The check lives in a `plannerStillRunning` helper.
- New `src/core/run/plan-run-record.ts`: `planRunRecordPath`, `readPlanRunRecord`, `writePlanRunRecord`, `currentPlanRun`, `readLivePlanner`, and the `PlanRunRecord`/`PlanRunView` types, per watcher-and-harness "Planner run record". It reuses `currentAutoSteer`, `hashChangeFolder` and `isProcessAlive`, imports nothing from `src/watcher/` and not `next-step.ts`, and writes no file.
- New `tests/plan-run-record.test.ts`: plain `node:test` cases for "Live planner", "Planner process gone", "Plan edited after the run" and "Steering run is the planner run". The dead pid comes from `process.execPath -e ""`, awaited to exit.
- New `tests/auto-steer-live.test.ts`: plain `node:test` cases for "Planner running elsewhere" and "Running record names its process", running `runAutoSteer` with a recording `plannerAdapter`.
- `tests/auto-steer-run.test.ts` is unchanged, "Interrupted run" included.

Task verify passed (19 tests), and `pnpm verify` passed on the final tree (215 tests, both typechecks, build and lint).

## Deviated

- `spawnPlanner` and `decideOutcome` had no doc comments; I added one `@scenario`/`@adr 018` comment each, as acceptance line 7 requires for moved functions.
- `OutcomeFields` was not exported before. I exported it from `planner-spawn.ts` so the declaration emit of the now-exported `decideOutcome` compiles under `declaration: true`.
- The added pid line pushed `runAutoSteer` to 81 lines (the function budget is 80), so I folded the two running checks into a one-line condition backed by the unexported `plannerStillRunning` helper. Behavior is identical.
