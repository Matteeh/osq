## Changed

- `src/core/web/web-actions.ts`: `WebActionVerb` gains `plan`; `WebActionRequest` gains
  `{ verb: 'plan'; change; notes? }`. `getWebActions` now always reads the change's
  `readNextStep`, keeps the unplanned-change `manual` command, and appends one `plan`
  action (`osq plan <id> --run`, target null) when `canStartPlanner(next, location, config)`
  is true. The four existing verb prefixes are unchanged, so a dispatch `osq plan <id>`
  stays a manual command.
- `src/core/web/web-action-body.ts` (new): owns `ActionRequestBody` and `parseActionRequest`,
  moved out of `web-write.ts`. It accepts a `plan` body with an optional non-empty string
  `notes`, and its unknown-verb error is now
  `verb must be approve, land, reject, retry, or plan`.
- `src/core/web/web-write.ts`: imports `parseActionRequest` from `web-action-body.ts`; the
  moved code is gone and the file is 207 lines.
- `src/cli/serve-actions.ts`: the default table is now the injectable
  `defaultWebCommands(plan = planCommand)`, whose `plan` entry calls
  `planCommand(request.change, { ...inputs, run: true, ...(notes) })`;
  `createWebActionRunner` defaults to `defaultWebCommands()`.
- `src/cli/server-worker.ts`: `createServerCommands(land = landCommand, plan = planCommand)`
  gains the same `plan` entry.
- `packages/ui/src/change/actions-client.ts`: `WebActionInput` gains `{ verb: 'plan'; notes? }`.
- `packages/ui/src/change/useChangeActions.ts`: `requestFor` returns `{ verb: 'plan' }` for a
  `plan` action.
- `tests/serve-actions.test.ts`: a `plan` entry added to both command tables so the file
  typechecks; no assertion changes.
- `tests/serve-plan-action.test.ts` (new): proves "Plan action offered", "Plan action bodies"
  and "Server runs the plan command" over a started server and through both command tables
  with a recording `planCommand` stand-in.

Each added or changed exported function carries its `@scenario web-inspection:` lines plus
`@adr 013` and `@adr 019`.

## Deviated

- Named the injectable default table `defaultWebCommands(plan)` rather than keeping a
  module-level const, because the task's Details asks for the default table to take an
  injectable plan command the way `createServerCommands` takes `land`. `createWebActionRunner`
  still defaults to it, so no caller changes.
- Added a third assertion case ("omits notes when the request carries none") in the new test
  file to cover "adding `notes` only when the request carries them".
