## Changed

Added the verify runner to `osq-kernel-harnesses`:

- `verify.rs` defines `VerifyRequest`, `VerifyOutcome` and `run_verify`, exported from `lib.rs`.
- `verify/env.rs` builds the verify role's environment with `role_env(EnvRole::Verify, ...)`, then sets or removes `OSQ_CHANGE` and `OSQ_DIFF`, then applies `extra_env` last.
- `verify/output.rs` holds the pure exit mapping (timeout or signal to 1) and the path rewrite that removes `<cwd>/` and turns a lone `<cwd>` followed by end, whitespace or punctuation into `.`.
- `verify/runner.rs` starts `/bin/sh -c` in the request's folder, in its own process group, with stdin closed and only the built environment; it reads stdout and stderr in arrival order, sends SIGTERM to the group at the timeout, SIGKILL after `kill_grace`, and waits at most `kill_grace` for the pipes after the shell exits.
- `tests/verify_command.rs` proves the five new scenarios, including extra assertions for the TERM grace, the KILL fallback, one-pipe-open grace handling, late output and non-boundary path prefixes.

## Deviated

The signal helper passes `--` before the negative process id (`kill -TERM -- -<pid>`) so the system `kill` never parses the group id as another option; it still sends the signal to the negative process id as required.
