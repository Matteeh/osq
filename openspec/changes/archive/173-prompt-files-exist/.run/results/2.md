## Changed

- `src/core/status/blocked-item.ts`: `applySteeringItems` now gives a `blocked`
  trigger whose reason is `entry_missing` the need status-inspection "Blocked
  inbox items" defines, through a new `readMissingEntryNeed` helper: the
  task's active dead marker body (`getDeadMarkerPath`) is parsed with
  `parseFrontmatter`, its `- <path>` lines are joined as
  `missing entry files <paths>`, and `(not stated)` when the marker is
  unreadable or lists none. A trigger with reason `blocked` still reads the
  result file's `## Blocked` section exactly as before.
- Added `@scenario status-inspection: Missing entry file in the inbox` to
  `applySteeringItems`.
- Added `tests/entry-missing-inbox.test.ts`, proving "Missing entry file in
  the inbox": it builds an approved change with task 1's dead marker
  (`reason: entry_missing`, `- src/gone.ts` and `- src/old.ts` lines) the way
  `tests/inbox-blocked.test.ts` builds its project, and checks the
  `osq --json` item's `blocked: { need: "missing entry files src/gone.ts,
  src/old.ts" }`, `steering: { trigger: "blocked", reason: "entry_missing" }`,
  command `osq plan 001`, and the text row ending
  `needs steering: blocked (entry_missing): missing entry files src/gone.ts,
  src/old.ts — osq plan 001`.
- `tests/steering-inbox.test.ts` and `tests/inbox-blocked.test.ts` pass
  unchanged.
