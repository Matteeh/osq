## Changed

- Added `src/core/run/entry-paths.ts`: `entryExists(root, entry)` and
  `missingEntryPaths(root, task)`, which returns each entry of `{ scope, entry }`
  that the tree cannot provide, in entry order. Present means the task's own
  `scope` covers it, it exists under `root` as a file or directory, or it is a
  `*`/`?`/trailing-slash pattern `resolveScope` matches to at least one file.
- Added `src/watcher/task-file.ts`: `readApprovedTaskFile` reads and parses
  `tasks/<n>.md` (a missing file still fails `crashed` with today's marker),
  then checks the entry paths with `missingEntryPaths`. A miss fails the task
  with reason `entry_missing`, the requirement's marker body, and the error
  `Missing entry files: <paths joined with ", ">`.
- `src/watcher/runner.ts`: replaced the inline task read with
  `readApprovedTaskFile`, called before `guardScopeRegression`, so no lock,
  measure, `started` event, baseline or verify runs for a missing entry. File
  is 193 lines, under the 200-line budget.
- `src/watcher/failure-reason.ts`: added `entry_missing` to
  `RunTaskFailureReason`. The automatic-retry list in
  `src/watcher/auto-retry.ts` is unchanged, so `entry_missing` is never retried
  automatically.
- `src/core/status/steering.ts`: `taskTrigger` now yields a `blocked` trigger
  with reason `entry_missing` as it does for `blocked`.
- Added `tests/entry-missing-run.test.ts`, proving "Entry names a removed
  file", "Steered task runs", every row of "Entries that count as present",
  and "Missing entry file" (through `deriveSteering`/`describeTrigger` on a
  snapshot read from disk).

## Deviated

- The acceptance says the end-to-end test rewrites `tasks/1.md` in the checkout
  "with an `entry` line before `approve()`". The test writes the whole task file
  (same title/scope/verify, with the wanted `entry`) through a small helper,
  which is the same change to the file.
- In the "Entry names a removed file" test I assert the executor never spawns
  and the artifacts are written, but not `summary.tasksRun`, because a watcher
  cycle counts the failed attempt as a run though it spawns nothing; the
  requirement's THEN lines do not constrain that counter.
