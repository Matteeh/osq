## Acceptance

- [ ] New `src/core/run/entry-paths.ts` exports `missingEntryPaths(root, task)`, taking `{ scope, entry }`, which returns, in entry order, each entry that is missing as watcher-and-harness "Entry path check before spawn" defines it: present when `scopeCoversPath(task.scope, entry)` is true, when it exists under `root` as a file or directory, or when it is a pattern (holding `*` or `?`, or ending in `/`) that `resolveScope(root, [entry])` matches to at least one file. Export the existence check as `entryExists(root, entry)` too; task 3's lint reuses it.
- [ ] New `src/watcher/task-file.ts` takes the task-file read out of `runTask`: it reads and parses `tasks/<n>.md` (a missing file still dies `crashed` with today's marker and error), then calls `missingEntryPaths` with the project root `runTask` receives, and on a miss calls `fail('entry_missing', ...)` with the marker the requirement gives and the error `Missing entry files: <paths joined with ", ">`. `runTask` calls it where it read the task file, before `guardScopeRegression`, so no lock, measure, `started` event, baseline or verify runs. `src/watcher/runner.ts` must stay under 200 lines (`tests/import-graph.test.ts`).
- [ ] Add `entry_missing` to `RunTaskFailureReason` in `src/watcher/failure-reason.ts`. Leave the automatic-retry list in `src/watcher/auto-retry.ts` as it is, so `entry_missing` is never retried automatically.
- [ ] In `taskTrigger` in `src/core/status/steering.ts`, a dead marker with `reason: entry_missing` yields a `blocked` trigger with reason `entry_missing`, as status-inspection "Steering triggers" says.
- [ ] New `tests/entry-missing-run.test.ts` proves "Entry names a removed file" and "Steered task runs" end to end with `createRecoveryProject` from `tests/recovery-support.ts` (rewrite `tasks/1.md` in the checkout with an `entry` line before `approve()`), every row of "Entries that count as present" through `runWatcherCycle` or `runWatcherOnce` with a fake adapter, and "Missing entry file" through `deriveSteering` and `describeTrigger` on a snapshot read from a folder the test writes.
- [ ] Exported functions you add or change carry `@scenario` lines for the scenarios they serve and `@adr 006`.
