# Task 1 result

## Changed

- `src/watcher/build.ts` (new): `resolveBuildInfo(projectRoot?)` + `BuildInfo` type. Reads the
  package version from `<root>/package.json` (falling back to the osq package's own
  `package.json`), tries `git rev-parse --short HEAD` with `cwd = root`, and on failure computes a
  sorted, path-folding SHA-256 over `dist/` truncated to 8 hex chars; `unknown` when `dist/` is
  absent. Results are cached per resolved root.
- `src/watcher/runner.ts`: `recordStarted` now awaits `resolveBuildInfo(projectRoot)` and includes
  `version` and `commit` alongside `pid`/`timeoutSeconds` in the `started` event data.
- `src/watcher/loop.ts`: `formatIdleStatus` takes an optional `buildInfo` (5th param) and prefixes
  the idle row with `osq v<version> (<commit>) · `; `runWatcherCycle` resolves build info once and
  passes it to both idle branches.
- `tests/watcher-build-identity.test.ts` (new): version+commit resolution, dist-hash fallback, and
  runner `started` event fields.
- `tests/watcher-loop-logging.test.ts`: idle-status assertions updated for the build prefix.

## Deviated

- Cache is a `Map` keyed by resolved project root, not a single global slot as the detail loosely
  suggested. This keeps the "resolve once" behavior for the watcher while allowing tests to resolve
  distinct temp roots.
- `resolveBuildInfo` scopes git and `dist/` to the passed `projectRoot`, defaulting to the osq
  package root when omitted (per the task detail). In the real watcher `projectRoot` is the consumer
  project, so an installed consumer with its own `package.json`/`dist/` would report that project's
  identity rather than osq's. Task 2/3 may want to pass the osq package root explicitly if that
  matters for stale-build detection.

## Missing context

None. `--dev`, stale-build preflight, and CLI flags belong to tasks 2 and 3 and were not touched.
