## Acceptance
- [ ] resolveBuildInfo in src/watcher/build.ts returns the package version and git commit or SHA-256 hash of dist/
- [ ] resolveBuildInfo falls back to dist/ hash when git command is unavailable or outside a git repository
- [ ] recordStarted in src/watcher/runner.ts records version and commit in the started lifecycle event data
- [ ] formatIdleStatus in src/watcher/loop.ts formats the idle line prefixed with osq v<version> (<commit>)
- [ ] tests/watcher-build-identity.test.ts tests build info resolution and started lifecycle event data fields
- [ ] tests/watcher-loop-logging.test.ts reflects the build version and commit in idle status assertions

## Details

1. In `src/watcher/build.ts`:
   - Create helper `resolveBuildInfo(projectRoot?: string): Promise<{ version: string; commit: string }>`:
     - Read version from `package.json` using `new URL('../../package.json', import.meta.url)` or relative to `projectRoot`.
     - Attempt to resolve git commit via `execFileAsync('git', ['rev-parse', '--short', 'HEAD'])`.
     - When git fails, is missing, or directory is not a git repository, compute SHA-256 hash of all files under `dist/` (using `node:crypto` and `node:fs/promises`) and take the first 8 characters.
     - Fall back to `'unknown'` if `dist/` is also not present.
     - Cache resolved build info in memory for subsequent calls.
2. In `src/watcher/runner.ts`:
   - In `runTask`:
     - When `recordStarted` is invoked to append the `started` event, call `resolveBuildInfo(projectRoot)`.
     - Include `version: buildInfo.version` and `commit: buildInfo.commit` in `event.data`.
3. In `src/watcher/loop.ts`:
   - In `formatIdleStatus`:
     - Accept an optional `buildInfo?: { version: string; commit: string }`.
     - Format the idle status line as: `osq v${info.version} (${info.commit}) · watching ${specsDir} · ${approvedWaiting} approved waiting · ${last}`.
   - In `runWatcherCycle`:
     - Pass the resolved build info into `formatIdleStatus`.
4. In `tests/watcher-build-identity.test.ts`:
   - Test that `resolveBuildInfo` extracts valid version and commit strings.
   - Test fallback to `dist/` hash when git execution fails.
   - Run a task with mock adapter and assert the generated `started` event in `.run/events/<n>.jsonl` contains `data.version` and `data.commit`.
5. In `tests/watcher-loop-logging.test.ts`:
   - Update idle status string matching assertions to match the new prefix `osq v... (...) · watching ...`.
6. Verification:
   - Run `node --import tsx --test tests/watcher-build-identity.test.ts`.
   - Run `node --import tsx --test tests/watcher-loop-logging.test.ts`.
