## Changed

- Added `src/watcher/own-folder-gate.ts` with the pure `findOwnFolderLines(text, folder)` and `checkOwnFolderGate(projectRoot, files, folder)`. The pure function blanks `//` and block comments while preserving line numbers, then matches the folder only when neither neighbour is a letter, digit, `_` or `-`. The check reads changed scope files outside `openspec/`, sorts matches by path and line, and returns the exact `own_folder_path` marker and error.
- `src/watcher/runner.ts`: after the task verify passes and before `runChangeVerifyGate`, the runner now checks `measures.changedScopeFiles()` with the change folder's base name and dies with `own_folder_path`. `runner.ts` stays at 198 lines.
- `src/watcher/failure-reason.ts`: added `own_folder_path`.
- `src/watcher/auto-retry.ts`: added `own_folder_path` to `ELIGIBLE_AUTO_RETRY_REASONS`.
- Added `tests/own-folder-gate.test.ts`, proving both "Own folder lines" and "Task naming its own folder dies" with `each` and literal scenario names.
- `tests/vcs-stacked-land.test.ts`: its `ActingAdapter` writes `<id> task <n>` using the folder's leading digits, and the two content assertions now expect `002 task 1` and `003 task 1`.

## Deviated

- The dead-marker assertion compares against the expected marker after removing the inserted `fingerprint:` line, because `writeDeadMarker` always adds the fingerprint. This follows the existing dead-marker tests.
- The scenario test points lookup at a temporary copy of the living spec with repeated scenario names deduped, plus the active delta found dynamically. This avoids hard-coding this change's own folder in a file the task writes, and avoids the living spec's duplicate `Native model` names.
- The task said to keep `runner.ts` under 250 lines, but `tests/import-graph.test.ts` enforces under 200 for lifecycle modules. The gate trigger is written in three compact lines so the file is 198 lines.

## Outside scope

- The living `openspec/specs/watcher-and-harness/spec.md` still has two scenarios named `Native model`, which makes scenario lookup refuse the capability unless `OSQ_CHANGE` points at a deduped copy. Removing duplicate scenario names is a stated non-goal, so I worked around it and left the living spec alone.
