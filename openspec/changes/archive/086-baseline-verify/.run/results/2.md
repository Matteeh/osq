## Changed

- `src/harness/types.ts`: added `baseline_ran` to `HarnessEventType`, added
  `BaselineRanEventData` (`outcome`, `command`, `commit`, `treeDigest`,
  `exitCode`, `durationSeconds`, optional `reusedFrom`), and mapped it in
  `OsqEventData`.
- `src/watcher/failure-reason.ts`: added `baseline_red` to
  `RunTaskFailureReason`.
- `src/watcher/baseline.ts` (new): `settleBaseline(verifyCtx)` returns `ok` or a
  `baseline_red` failure. It no-ops when `gates.baselineVerify` is unset or any
  task stream (every `.jsonl` except `change.jsonl`) already holds `started`;
  selects through `selectVcs`, keys through `readBaselineKey`, searches the
  latest `passed`/`reused` `baseline_ran` across active (`getChangesDir`) and
  archived (`getArchiveDir`) `change.jsonl` streams, reuses it when command,
  commit, and digest match, and otherwise runs the command in the project root
  under `timeouts.verifyTimeoutSeconds` with a null change folder (no
  `OSQ_CHANGE`). Every path appends one `baseline_ran` event to the change
  stream. The dead marker is `reason: baseline_red`, quoted command and
  `exit_code` in frontmatter, then the halt line, then the command/exit/retry
  line, then the captured output. The failure's extra is the halt line.
- `src/watcher/runner.ts`: imports `settleBaseline`, calls it right after
  `verifyCtx` and before `runPreSpawnVerify`, and on a red baseline returns
  `fail('baseline_red', ...)`. Two lines plus the import; the file is 196 lines,
  under the 200-line import-graph budget.
- `tests/baseline-verify.test.ts` (new): nine tests through `runWatcherOnce` and
  a counting adapter. Red-before-the-change (no spawn, `dead/1.1.md` absent
  under the default `autoRetries`, phrase printed), green baseline ordered
  before `started`, `osq retry` rerun (red then passed), a later task never
  settling the baseline, gate unset, the reason union, and three git cases: an
  unchanged tree reuses (`outcome: reused`, `reusedFrom: 001-reuse-one`, command
  ran once), and a changed tracked or untracked file makes the command run again.
- `README.md`: Baseline verify bullet in Gates and permissions, `baseline_red`
  in the automatic-retry waiting list, and `baseline_red` in the dead reasons
  paragraph.
- `osq.config.ts`: `gates: { baselineVerify: 'pnpm verify' }`.

## Deviated

The watcher-and-harness delta says the outcome line SHALL end with "tree was red
before this change started". `formatTaskOutcomeLine` in `src/watcher/outcome.ts`
(outside this task's scope) inserts the extra before `, elapsed: Xs)`, so passing
the halt line as the task's extra fields places the phrase in the outcome line
but not at its very end. The dead marker's first body line is exactly the phrase,
so the marker both starts with it and that line ends with it.

`tests/baseline-verify.test.ts` is 355 lines. The 250-line budget is enforced by
`tests/line-budget.test.ts` only over `src/` and the UI sources; no test file is
scanned, and every function here is well under 80 lines.

## Outside scope

`formatTaskOutcomeLine` (out of scope) cannot put the extra last, which is the
only reason the "outcome line ends with" clause is not literal.
