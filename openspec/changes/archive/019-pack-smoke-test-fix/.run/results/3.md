# Task 3 result: setup failure is a failed test, not cancelled siblings

## Changed

- `tests/package-install-smoke.test.ts`:
  - Removed the `before` hook and the now-unused `before` import. No hook spawns
    a process anymore; only the `after` cleanup hook remains.
  - Moved workspace creation, build, pack, `npm init`, and tarball install into
    the first `it` block, renamed to
    `packs and installs the local tarball into an isolated temporary project`.
  - Suite-scoped `workDir`, `consumerDir`, `tarballPath` hold the temp paths.
    Added a `setupComplete` flag set only after the install succeeds. The
    `npx osq init` and `npx osq new smoke` `it` blocks start with
    `assert.ok(setupComplete, 'Smoke test setup did not complete')`.
  - `run(command, args, cwd)` now wraps `execFileAsync` in try/catch and rethrows
    `Command failed: ${command} ${args.join(' ')} (cwd: ${cwd})\n<stderr|message>`
    so any spawn failure names the command, its arguments, and working directory.
  - Added a test-only `OSQ_SMOKE_TARBALL` override (read from `process.env`) that
    skips build/pack and uses the given tarball path. This is the variation the
    new reporting test drives; normal runs are unchanged.
- `tests/smoke-error-reporting.test.ts` (new):
  - Spawns `node --import tsx --test --test-reporter=tap
    tests/package-install-smoke.test.ts` with `OSQ_SMOKE_TARBALL` pointing at a
    nonexistent `.tgz` and `OSQ_SKIP_PACK_TEST=0`, then inspects TAP stdout/stderr.
  - Asserts `not ok`, `Command failed: npm install`, the missing tarball path, the
    `(cwd: .../osq-pack-smoke-.../consumer)` detail, `# cancelled 0`, and that no
    `cancelledByParent` appears.
  - Strips `NODE_TEST_CONTEXT` from the child env; otherwise the child runner
    refuses to run files ("node:test run() is being called recursively within a
    test file") and produces no TAP.
  - Cleans up its temp directory in an `after` hook.
