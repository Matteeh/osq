## Changed

- Added `src/core/foundation/harness-containment.ts`: exports `HarnessContainment`
  (`{ ok, warning?, message }`), one named containment reporter per harness
  (`agyContainment`, `opencodeContainment`, `mockContainment`, `codexContainment`,
  `piContainment`, and `claudeContainment` re-exported from `config-claude.ts`),
  the `HARNESS_CONTAINMENT` record keyed by `HarnessName`, and
  `attachContainment` for the catalog.
- `HarnessCatalogEntry.containment` is now required and typed
  `(config: OsqConfig) => HarnessContainment`; `HARNESS_CATALOG` attaches each
  reporter where it is built, so `harness-catalog.ts` stays at 245 lines.
- `diagnoseClaude` now returns only its `harness-version` check;
  `claudeContainment` keeps its current text and string return.
- `runDoctorChecks` adds one `harness-containment` check from the selected
  catalog entry right after `harness` and any `diagnose` checks, whether or not
  the harness probe passed, and only when the `config` check passed. `doctor.ts`
  names no harness; it normalizes the catalog result into a doctor check and
  carries `warning: true` through.
- Added `tests/harness-containment.test.ts` (9 tests): every message in the
  delta for every harness, the agy failure making `report.ok` false, both
  warnings (agy bypass on, opencode with another agent), Claude's two sandbox
  messages, and Pi's check order (`config`, `harness`, `harness-version`,
  `harness-auth`, `harness-containment`, `managed-blocks`).
- `tests/doctor.test.ts`, `tests/codex/adapter.test.ts`, and
  `tests/pi/doctor.test.ts` now expect `harness-containment` in their name lists
  and counts.

## Deviated

Claude's catalog `containment` reuses `claudeContainment` directly, which still
returns a plain string, so `containmentCheck` in `doctor.ts` wraps a string
result as a passing check. The catalog field is declared as
`(config) => HarnessContainment` (Claude's assignment is cast) and the five
other harnesses return objects. This keeps `tests/claude/exec-config.test.ts`,
which asserts the catalog's claude containment strictly equals a string,
passing unchanged. A stricter reading of the delta would have the claude catalog
entry return `HarnessContainment` itself.

## Missing context

`tests/claude/exec-config.test.ts` directly asserts
`lookupHarness('claude').containment(config)` with `node:assert/strict` against a
string. That file is not in this task's `scope`, and `tests.modify: true` does
not authorize it, so the catalog's claude reporter could not be changed to
return an object without triggering an undeclared test change. Either the scope
needs `tests/claude/exec-config.test.ts`, or the spec should say claude returns
a string.

## Outside scope

`tests/inbox.test.ts`'s "reads the inbox through a core helper without advancing
the cursor" asserts two `elapsedSeconds` values differ by at most 2; under the
full-suite load the CLI leg can exceed that and flake. It passed on the final
`pnpm verify` and when run alone; left untouched.
