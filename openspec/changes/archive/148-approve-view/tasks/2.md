## Acceptance

- [ ] `packages/ui/src/contracts.ts` re-exports, as types only, `WebReview`, `WebDeltaCapability` and `WebDeltaRequirement` from `src/core/web/web-data.ts` and `ApprovalFlag` from `src/core/spec/digest.ts`. New `ReviewPanel` renders the sections `Goal`, `Non-goals`, `Surface`, `Decisions`, `Human steps` and `Contract` of a `WebReview`, each an `h3` over a `<pre className="review-text">`, or `None` when the text is empty; then new `DeltaReview` renders a `Deltas` section with an `h4` per capability and, per requirement, its operation and name and a `delta-pair` of a `Living` and a `Proposed` column, worded as "Approve review view" says. New `DigestPanel` renders an `Approval digest` section with `digestText` in a `<pre className="review-text">` and, when told to, the flags.
- [ ] New `ApprovalFlags` renders a list of `<label> — <excerpt>` items, each label in `<strong>`, and nothing for an empty list. `ChangeActions` and `ChangeActionsPanel` take an optional `flags` prop; `ChangeActions` renders `ApprovalFlags` inside the Approve button's `action-item`, or before the buttons when the document has no approve action.
- [ ] `ChangeView` with a `review` renders header, error, `BriefPanel`, `ReviewPanel`, `TaskTable`, `DigestPanel` (listing the flags only when there is no action client), then `ChangeActionsPanel` with the digest's flags. With a null or missing `review` it renders exactly what it renders today, in today's order.
- [ ] New `packages/ui/src/change/review.css`, imported by `main.tsx` next to `actions.css`, styles the review with the tokens `actions.css` uses: `.review-text` has `white-space: pre-wrap` and `overflow-wrap: anywhere`, and `.delta-pair` is a grid with `grid-template-columns: repeat(auto-fit, minmax(min(100%, 18rem), 1fr))` so the columns stack at phone width.
- [ ] New `tests/ui-review.test.tsx` covers every scenario of "Approve review view" with `renderToStaticMarkup`: heading order by index in the markup; `ChangeActions` with an approve action and flags; flags listed in the digest section without an action client; `New requirement`, `Removed` and `Renamed from` wording; and, for "Reviewed change unchanged", the markup of a document without `review` equals the markup of the same document with `review: null` and holds no `Non-goals` heading. For "Phone width" it reads `review.css` and checks the two rules above.
- [ ] The same test builds a document through the real core: a project from `createProject` and a change from `createChange` in `tests/planning-observed-helpers.ts`, a living `openspec/specs/alpha/spec.md`, and a delta that modifies one requirement and removes another; `getWebChange` then `ChangeView` renders the living and proposed text of the modified requirement and the `removed_requirement` flag's excerpt.
- [ ] Every existing test passes unchanged, and every new file under `packages/ui` stays at or under 250 lines.

## Details

The UI imports from `src/` only as types; `tests/import-graph.test.ts`
fails a runtime import. The test file itself may import `getWebChange` and
the helpers at runtime, as `tests/ui-actions.test.tsx` imports
`startWebServer`.

`tests/ui-change.test.tsx` reads every entry of `packages/ui/src/change/` as a
file and fails if any contains `EventSource`, `addEventListener`,
`setInterval`, `setTimeout`, `fetch(`, `dangerouslySetInnerHTML` or the
lower-case word `markdown`, including in comments and CSS. Put every new
file directly in that folder, with no subfolder, and avoid those words.

Render all text as escaped React text. The test sets the planning-reader
environment variables to nonexistent paths, as `tests/ui-actions.test.tsx`
does, and restores them after.
