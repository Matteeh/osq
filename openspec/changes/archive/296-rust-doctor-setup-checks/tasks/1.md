## Acceptance

- [ ] `Vcs` holds `version`, `hook_names` and `line_endings` with the signatures in rust-vcs "Setup reads", `GitVcs` implements them as that requirement says, and `LineEnding` is exported from the crate root.
- [ ] New `crates/kernel/vcs/tests/setup_reads.rs` proves "Setup reads of a repository", "Hooks folder from config", "Setup reads outside a repository" and "Setup reads with a program that cannot start", one test per scenario. Each test's doc names `Covers: rust-vcs/<scenario>`.
- [ ] Every existing vcs test passes unchanged.

## Details

Put the three reads and their parsing in a new `src/git/setup.rs`, declared
in `src/git.rs` beside `state`, and add the trait methods to `port.rs` and
their `GitVcs` impls to `src/git.rs`, as `root` and `config_value` are
wired. Run each read through `GitVcs`'s private `read` or `run` helper, so
the timeout and the `Spawn` error come from "Git command" unchanged. Keep
the parsing in small pure functions, as `parse_status` and
`parse_worktrees` in `state.rs` are. Read the execute bits with
`std::os::unix::fs::PermissionsExt` on `fs::metadata`, which follows
symlinks.

Build every repository with the `support` module's `Scratch`, as
`state_reads.rs` does, so no global or system git config is read. Set
`core.autocrlf` to `false` before the commit. Write the hook files after
the commit, so none of them runs during it. Take `<version>` from running
`git --version` through `Scratch`'s helper in the scratch folder.

`src/core/vcs/*.ts` is in `entry` only to show TypeScript's reads. Never
read anything under `src/` from Rust.

`crates/kernel/vcs/src/port.rs` and `src/git.rs` are also in change 292's
scope. If 292 has landed, keep its additions as they are.

## Scenarios

- rust-vcs: Setup reads of a repository
- rust-vcs: Hooks folder from config
- rust-vcs: Setup reads outside a repository
- rust-vcs: Setup reads with a program that cannot start
