## Acceptance

- [ ] `doctor` prints the `decisions` line between its `managed-blocks` line and its change lines when the project has decisions, and no `decisions` line otherwise, as rust-doctor "Doctor decisions" says.
- [ ] `crates/features/doctor/Cargo.toml` depends on `osq-kernel-specs` through `workspace = true`, as the modified "Doctor command" says, and on no feature crate.
- [ ] New `crates/features/doctor/tests/doctor_decisions.rs` proves "Doctor decisions lines", each row in its own scratch root under `CARGO_TARGET_TMPDIR`, its doc naming `Covers: rust-doctor/doctor-decisions-lines`.
- [ ] Every existing doctor test passes unchanged.

## Details

Put the check in a new `src/doctor/decisions.rs`. One reader gathers the
records with rust-specs `read_decisions`, the living capability names, the
missing check files and the `AGENTS.md` text. Pure functions build the
expected rules block, find the current one, and build the line from
`validate_decisions`' findings, which display as `<file>: <message>`. Hold
the `decisions` and `openspec` folder names and the rules markers as named
constants (ADR 029). Take `maxRuleLength` and `maxProjectRules` from
`config.limits`. In `run_doctor` in `src/doctor.rs`, which task 2 owns,
add the line right after the `managed-blocks` line and change nothing else
there.

Adding the dependency changes `Cargo.lock`. Let cargo write it; never edit
it by hand.

`src/core/foundation/*.ts` is in `entry` only to show TypeScript's check.
Never read anything under `src/` from Rust.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/296-rust-doctor-setup-checks`, so the link
gates see this change's new requirements.
