## Changed

- Added `crates/features/doctor/src/doctor/managed.rs`: the managed-block line, TypeScript's problem rules, the three canonical blocks through `include_str!`, the `osq-coder` opencode agent check, and the two failure groups.
- Added `crates/features/doctor/src/doctor/git.rs`: the `git` line, the `vcs-prepare`, `git-hooks`, `git-signing`, `gitattributes` and `git-line-endings` warnings, and the `git-env` warning.
- Wired the managed-blocks line before the change lines and the git lines after them in `crates/features/doctor/src/doctor.rs`.
- Copied the three golden blocks byte for byte into `crates/features/doctor/src/doctor/managed/` and `crates/features/doctor/tests/fixtures/managed/`.
- Updated `doctor_checks.rs` and `doctor_changes.rs` to write the managed files, run `git init`, and expect the new managed-blocks and git lines.
- Added `crates/features/doctor/tests/doctor_setup.rs` for the managed-block rows and the two child-process git scenarios.

## Deviated

- Added one managed row not in the scenario table, `opencode-planner-missing`, so a planner-only opencode selection with no agent file proves the `||` in the harness test. It also kills the surviving `||` -> `&&` mutant.
- Reworked the marker-order check into `starts.max(ends) > 1`, `starts.min(ends) == 0` and a slice from the first start marker, because the original `||` and `<` forms produced equivalent mutants that the mutation gate reports as missed.
- The git scenarios put the plain roots and the missing-git root in a `root` folder below the row's scratch folder. `GIT_CEILING_DIRECTORIES` set to the root itself does not stop discovery from walking into the enclosing osq checkout, while a ceiling one level above does.
- The child spawn removes any inherited `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE` before applying the row's variables, so the git lines rows never gain an unexpected `git-env` line.
