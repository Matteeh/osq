## Acceptance

- [ ] `OsqLimits` in `src/core/foundation/config.ts` gains `markerOutputLines` and `markerLineChars`, each with a one-line doc comment, and `DEFAULT_CONFIG.limits` sets them to 40 and 400. This covers the cli-foundation delta's "Default marker limits".
- [ ] New `src/core/run/verify-excerpt.ts` exports `VerifyExcerptLimits`, `Pick<OsqLimits, 'markerOutputLines' | 'markerLineChars'>`, and `excerptVerifyOutput(output, source, limits)`. It returns the excerpt text with no trailing newline. `source` is the text after `Full output: `, such as `the verify_ran event in .run/events/change.jsonl`. It follows the watcher-and-harness delta's "Verify output excerpt in markers": the last `✖ failing tests:` line through the end, otherwise the last `markerOutputLines` lines, `(no output)` for blank output, lines cut with `… (<n> more characters)`, and the `Full output:` line last. The CLI's TypeScript lib has no `findLastIndex`, so find the last matching line another way.
- [ ] `verifyArchiveStep` puts `excerptVerifyOutput(output, 'the verify_ran event in .run/events/<target>.jsonl', config.limits)` where the marker now has `output.trim() || '(no output)'`. The frontmatter and the heading line stay as they are, and so do the `verify_path_missing` marker and the `regressed` event.
- [ ] New `tests/verify-excerpt.test.ts` unit-tests `excerptVerifyOutput` on the delta's "Output without a failing-tests section", "Long line cut", and "Empty output", plus output with two `✖ failing tests:` lines, where only the last one starts the excerpt.
- [ ] The same test file covers "Archive failure keeps the failing tests" and the cli-foundation delta's "Configured marker lines" through `verifyArchiveStep`, with a change-level command such as a local `node` script that prints the lines and exits 1. It asserts on `.run/regressed/change.md` and on the `verify_ran` event's full `output`.

## Details

`tests/archive-verify-path-missing.test.ts` shows how to lay out a change
folder and call the archive step. A local script written into the temporary
project root keeps the verify offline. The configured-limits scenario passes
`{ ...DEFAULT_CONFIG, limits: { ...DEFAULT_CONFIG.limits, markerOutputLines: 5 } }`
to `verifyArchiveStep`. It does not need an `osq.config.ts` file.
