## Changed

- Added `src/core/run/scope-regression-marker.ts` holding `buildScopeRegressionMarker`
  and `parseActiveStaleTask`, moved out of `scope-hash.ts`. It imports
  `StaleTaskAudit` from `scope-hash.js` as a type only.
- `buildScopeRegressionMarker` now takes an optional second `VerifyExcerptLimits`
  argument (defaulting to `DEFAULT_CONFIG.limits`) and replaces
  `input.output.trim() || '(no output)'` with `excerptVerifyOutput` pointing at
  `the verify_ran event in .run/events/<task>.jsonl`. The differing-path list and
  the blank line after it are unchanged.
- `src/core/run/scope-hash.ts` re-exports both functions for existing importers.
- `ScopeAuditOptions` in `src/watcher/regression.ts` gains optional
  `limits?: OsqConfig['limits']`; `auditScopeRegressions` forwards it to
  `buildScopeRegressionMarker`, and the `regressed` event still records the full
  `output`.
- `guardScopeRegression` (regression.ts), `checkAndArchiveSpec` (archiver.ts),
  and the pre-dispatch audit (loop.ts) now pass `limits: config.limits`.
- Added `tests/scope-regression-excerpt.test.ts`, driving
  `auditScopeRegressions` over a done task whose scoped file drifted and whose
  verify prints 100 numbered lines and exits 1. It asserts the 40-line trailing
  excerpt, the absent line 1, the `Full output:` pointer, the full 100-line
  `regressed` event, and a `markerOutputLines: 5` override.

## Deviated

- `tests/line-budget.test.ts` measures `source.split('\n').length`, so
  `src/watcher/regression.ts` was already 249 by that metric (the task's 248 is
  the `wc -l` count). Two required additions (the `limits` field and the
  `guardScopeRegression` option) would have reached 251, so I removed the blank
  line between the `ScopeRegressionResult` and `ScopeAuditOptions` interfaces.
  The file now measures exactly 250 and the budget test passes.
