## Changed

- `verifyRedFailure` in `src/watcher/task-verify.ts` now takes the task number
  and `config`. A non-timeout `verify_red` marker holds
  `excerptVerifyOutput(result.error, 'the verify_ran event in
  .run/events/<n>.jsonl', config.limits)`, and the `fail` error string uses the
  same excerpt. A timed-out verify keeps its existing timeout message and adds
  no excerpt.
- `formatPreSpawnDeadMarker` in the same file takes the task number and
  `config` and holds the excerpt of `result.output` pointing at the task's
  `verify_ran` event.
- `formatChangeVerifyMarker` in `src/watcher/change-verify.ts` takes `config`
  and holds the excerpt of `result.output` pointing at
  `.run/events/change.jsonl`; `runChangeVerifyGate`'s returned `error` is
  unchanged.
- `checkFocusedTests` in `src/watcher/focused-verify.ts` computes the excerpt of
  `run.output` pointing at the task's `focused_ran` event and passes it to
  `formatFocusedDeadMarker`; the `focused_ran` event still keeps the full output.
- `BaselineRanEventData` in `src/harness/types.ts` gains optional `output`.
  `settleBaseline` in `src/watcher/baseline.ts` writes it on a failed run when
  the output is not blank, and passes `formatBaselineDeadMarker` the excerpt
  pointing at the `baseline_ran` event in `.run/events/change.jsonl`.
- `runTask` in `src/watcher/runner.ts` passes `taskNumber` and `config` to
  `verifyRedFailure` in a one-line call.
- New `tests/dead-marker-excerpt.test.ts` drives the task verify, change verify,
  focused run, red baseline, and pre-spawn `verify_precondition` paths through
  `runTask` with 100-line local failing scripts. It asserts each marker holds the
  last 40 lines (not line 1), ends with the matching `Full output:` line, and
  that the `verify_ran`, `focused_ran`, and `baseline_ran` events keep the full
  output.

Touched: src/watcher/task-verify.ts, src/watcher/change-verify.ts, src/watcher/focused-verify.ts, src/watcher/baseline.ts, src/watcher/runner.ts, src/harness/types.ts, tests/dead-marker-excerpt.test.ts
