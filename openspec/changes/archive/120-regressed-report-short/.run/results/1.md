## Changed

- Added `src/core/run/verify-excerpt.ts` exporting `VerifyExcerptLimits` and
  `excerptVerifyOutput(output, source, limits)`. It keeps the last
  `✖ failing tests:` line through the end when present, otherwise the last
  `limits.markerOutputLines` lines; cuts each kept line at
  `limits.markerLineChars`; renders blank output as `(no output)`; and ends with
  `Full output: <source>`.
- Added `markerOutputLines` (40) and `markerLineChars` (400) to `OsqLimits`
  and `DEFAULT_CONFIG.limits` in `src/core/foundation/config.ts`, each with a
  one-line doc comment. Existing merging already carries them from
  `osq.config.ts`.
- `verifyArchiveStep` in `src/watcher/archive-verify.ts` now writes
  `excerptVerifyOutput(output, 'the verify_ran event in .run/events/<target>.jsonl', config.limits)`
  in place of the trimmed whole output. Frontmatter, heading, the
  `verify_path_missing` marker, and the `regressed` event are unchanged.
- Added `tests/verify-excerpt.test.ts` with unit tests for the no-section,
  last-failing-tests, long-line, and empty-output cases, plus two integration
  tests that drive `verifyArchiveStep` and assert on
  `.run/regressed/change.md` and the `verify_ran` event's full output.

## Deviated

- To keep `src/core/foundation/config.ts` within the 250-line budget after the
  four new declaration lines, I removed the two blank lines that separated
  `OsqTimeouts`/`LogConfig`/`PlannerConfig`. The file is now exactly 250 lines.

## Outside scope

- The `Full output:` pointer names the event per the delta; the other six
  marker writers (`scope-hash.ts`, `task-verify.ts`, `focused-verify.ts`,
  `change-verify.ts`, `baseline.ts`) still hold whole output. They are tasks 2
  and 3.
