## Details

The rows in `golden/` were printed by TypeScript's `osq query --json` and
are the expected values. When a row disagrees, the Rust reading or mapping is
wrong. Fix it in `src/read/` or `src/model/` within this task's scope, keep
the tests of tasks 1 and 2 passing, add the fast case that pins the rule, and
say in `## Deviated` which rule changed and why. Never edit a golden file, an
existing fixture file or an existing test to make a row pass. A new fixture
project under `tests/fixtures/history-cases/` is fine.

The golden JSON holds numbers such as `duration` as JavaScript printed them.
If one differs from the Rust value only in the last digit, read that number
from the event line's text, as `exact_cost` in
`src/read/snapshot/events.rs` does for costs, and say so in `## Deviated`.

The test never runs `node` or `osq`. It ignores rows of changes numbered
above 209. `tests/archive_corpus.rs` and the golden files directly in `tests/golden/` belong to change
210; leave them alone. Shared helpers cannot be imported across test files,
so write the small JSON comparison again in this file.

Keep the test file under 250 lines and every function under 80. Workspace
lints include `clippy::pedantic` and `-D warnings`. Run `cargo fmt --all`
before exiting.
