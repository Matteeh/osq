## Details

`src/model/mod.rs` is at 141 lines. Put the new work in new files under
`src/model/`: the pure row mapping for the event tables, kept apart from the
inserts, and the label reading. Row mapping functions take a snapshot, or one
`TableEvent` with its change, and return row structs, as `rows.rs` does for
the first three tables. Only the insert and label functions touch SQLite.

Take the values from the typed payloads in `TableEvent::event`.
`RecertificationData::attribution`, `MutationRanData::survivors` and
`ValidatorRanData::findings` are `serde_json::Value`; read them with the
type checks "Event table columns" names. `duration` is a
`serde_json::Number`; write it as an `f64`. `exit_code` that is
`Nullable(None)` is null. `notices` covers archived and rejected snapshots,
sorted by folder name. The halt count for its outcome is the facts' `halts`,
and a change without facts counts no halt. Every other new table takes
archived snapshots only, in the given order, as the first three do.

Labels are a JSON object of booleans read with `serde_json`. A missing file
holds no labels. Fill them with one `UPDATE <table> SET label = ? WHERE id = ?`
per label after the rows are in, as TypeScript's `applyTrialLabels` does.
`write_read_model` alone writes every label as null.

The expected rows in `tests/fixtures/history-rows/` were printed by
TypeScript and are the truth. When a row disagrees, the Rust mapping is
wrong. Never edit a fixture file. When a row disagrees because of what the
snapshot holds, which task 1 owns, write it under `## Blocked`. Read the JSON
files with `serde_json`. Tests write their databases under
`env!("CARGO_TARGET_TMPDIR")`, one file name per test.

Keep every `.rs` file under 250 lines and every function under 80. Workspace
lints include `clippy::pedantic` and `-D warnings`. When the mutation step
reports a missed mutant, add a case for it in `tests/read_model_history.rs`.
Run `cargo fmt --all` before exiting.
