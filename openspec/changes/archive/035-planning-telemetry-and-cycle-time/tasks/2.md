## Acceptance

- [ ] ManifestData and every buildManifest result contain numeric planningSessions while preserving all existing hashes, identity fields, and timestamps.
- [ ] Approval counts valid plan_started records in `.run/plan.jsonl`, including new and resumed sessions, without requiring a matching exit record.
- [ ] A missing, empty, or partially malformed planning log yields the count of valid starts, or zero when none exist, without blocking approval.
- [ ] Changing only `.run/plan.jsonl` changes planningSessions on the next approval but leaves hashChangeFolder output unchanged.

## Details

Reuse `buildManifest`, `writeManifest`, `approveSpec`, and the planning-log parser
created by task 1. Count starts from parsed records rather than counting lines,
so blank, malformed, and unknown JSONL records are ignored. Do not parse usage
or infer sessions from `plan_exited`.

Keep manifest construction as the one source for both the provisional manifest
written by `osq plan` and the authoritative manifest overwritten by `osq
approve`; the latter naturally observes all sessions completed before approval.
Do not change hasher exclusions or approval marker behavior. Extend the existing
manifest test through `approveSpec`, including a before/after hash assertion;
do not add a second manifest-writing path. Run the task verify and `pnpm verify`
before exit.
