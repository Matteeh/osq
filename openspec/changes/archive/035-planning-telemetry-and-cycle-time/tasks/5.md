## Acceptance

- [ ] MetricsReport and stable JSON expose `planning: { sessions, wallSeconds, wallSecondsByChange, tokens: { input, output, cached, reasoning }, cost: { total, formattedTotal, provenance }, coverage: { reportedSessions, totalSessions } }` from correlated planning records across active and archived changes.
- [ ] Planning aggregation counts every valid start once, sums wall time only from matched finite non-negative exits, sums each finite usage field independently, treats observed zero as reported, and counts a session with any reported token or cost field once in coverage.
- [ ] Text output contains `Planning:`, total and deterministic per-change wall time, token and harness-reported cost totals, and the exact phrase `n of m sessions reported usage`; no missing usage is estimated.
- [ ] JSON exposes `cycle: { phases, byChange }`, where byChange has one sorted row per archived folder with change, briefToApprovalSeconds, approvalToFirstTaskSeconds, firstTaskToArchiveSeconds, and totalSeconds, each nullable under the proposal rules.
- [ ] Each cycle phase aggregate has totalSeconds, averageSeconds, coveredChanges, and totalChanges; text prints only aggregate phase lines with `n of m archived changes`, while per-change rows remain JSON-only.
- [ ] Cycle derivation reads brief frontmatter date, manifest approvedAt, the earliest started event from numbered task streams, and the archived event from change.jsonl; missing, invalid, reversed, active-change, and legacy data remain null or excluded without filesystem timestamp inference, and archived events do not inflate execution durations.
- [ ] A real planCommand call through the known-delay fake planner produces the two planning events and a report planning block, while the checked-in report fixture and all pre-034 report fields remain deterministic.

## Details

Extend the post-034 `MetricsReport` rather than restoring or renaming its
`now`, `history`, or `coverage` blocks. Reuse `getMetricsReport`,
`formatMetricsReport`, `formatDuration`, `formatCost`, `serializeSortedJson`,
`toStableMetrics`, `parseFrontmatter`, and the shared planning-log
parser/correlator from task 1. Keep planning cost separate from execution
history cost and label it `harness-reported`.

Use these exact cycle phase keys under `cycle.phases`:
`briefToApproval`, `approvalToFirstTask`, `firstTaskToArchive`, and `total`.
Round exposed seconds consistently with existing duration reporting. A phase's
average is over only its covered archived changes; it is zero with zero
coverage. A row total is the arithmetic sum only when all three row phases are
non-null. The total phase aggregate includes only rows with a non-null total.

Only numeric `<n>.jsonl` task streams can supply first task start. Only an
`archived` event in `change.jsonl` supplies archive time. Ensure the legacy
execution-duration scan does not treat `change.jsonl` span as task duration now
that it can contain two events.

Add focused planning and cycle tests plus an end-to-end
`planning-integration.test.ts` that invokes `planCommand` with
`tests/fixtures/planning/fake-planner.mjs`, then calls the report entry point.
Include an AGY planning record in aggregation coverage so harnesses with null
usage still contribute their exact session count and wall time. Update the
existing JSON contract test and `fixture/report/expected.json` rather than
weakening deterministic sorting. Existing report tests not named in scope are
frozen regressions. Run the task verify and `pnpm verify` before exit.
