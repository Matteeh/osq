# Task 4 result

## Changed

- `src/watcher/archiver.ts`
  - Added exported `ArchivedEventData` (`{ archivePath }`).
  - `archiveSpecFolder` now appends exactly one change-level `archived` event via
    the append-only `appendHarnessEvent` writer after `fs.rename` and the final
    `ensureArchivedTasksTicked` projection succeed. The event targets
    `<archived folder>/.run/events/change.jsonl` (never a numbered task stream)
    and uses `new Date().toISOString()` as the authoritative archive time.
  - Event emission stays inside `archiveSpecFolder`, so a rejected/failed
    relocation throws before any event, and `checkAndArchiveSpec` never reaches
    it when task or change-level verification fails.
- `tests/archiver.test.ts`
  - Added `parseJsonl`/`readEvents` helpers.
  - New test: direct `archiveSpecFolder` writes exactly one `change.jsonl` event
    (`type: "archived"`, ISO timestamp inside the relocation window,
    `data.archivePath`, only `change.jsonl` present, and no event in the
    pre-move folder).
  - New test: failed relocation rejects and leaves the archive directory empty
    with no `archived` event.
  - New test: `checkAndArchiveSpec` blocked by a failing change-level verify
    returns false, keeps the change active, retains
    `.run/regressed/change.md` (`reason: verify_red`) and the `verify_ran` +
    `regressed` events, and emits no `archived`.
  - New test: successful `checkAndArchiveSpec` archives and the archived
    `change.jsonl` is ordered `verify_ran` then `archived`, same event contract
    as the direct path.

## Verification

## Deviated

- The task detail assumed task 1 had added a typed `archived` member to
  `HarnessEventType`/`OsqEventData` in `src/harness/types.ts`. It did not (task 1
  only added the `InteractiveUsage` port). `src/harness/types.ts` is listed as
  `entry`, not `scope`, so it could not be edited here. To keep the write on the
  append-only `appendHarnessEvent` path, `archiver.ts` declares `ArchivedEventData`
  locally and passes the event through a single `as unknown as HarnessEvent`
  assertion. Runtime JSON is exactly the typed contract the report will parse.

## Drift against features/

- None. Existing delta application, collision suffixes, `.run/` history
  preservation, task-checkbox projection, and change-level `verify_ran` history
  are unchanged; only one new event is appended post-relocation.

## Missing context

  `change.jsonl` and can parse it without the union member, but type parity is
  not yet achieved.
