# Task 1 result

## Changed

- `src/core/planning.ts` (new): append-only record types (`plan_started`/`plan_exited`),
  `NULL_PLANNING_USAGE`, brief SHA-256 hashing, osq package-version resolution,
  `recordPlanStarted`/`recordPlanExited`, `readPlanningUsage` (absence/throw -> all-null),
  and defensive `parsePlanRecords`/`readPlanRecords`/`correlatePlanSessions`/`readPlanningSessions`.
  `getPlanLogPath` is `<change>/.run/plan.jsonl`.
- `src/harness/types.ts`: added `InteractiveUsage`, `NULL_INTERACTIVE_USAGE`,
  `ReadInteractiveUsageOptions`, and the optional `readInteractiveUsage` port.
- `src/harness/opencode-usage.ts` (new): reads only session metadata/usage columns through the
  resolved CLI's `db --format json`, requires exactly one row matching cwd and the observed
  interval, sums stored cache-read + cache-write, and rejects non-finite/negative counters.
- `src/harness/codex-usage.ts` (new): resolves `CODEX_HOME` or `~/.codex`, inspects only rollout
  `.jsonl` files created in the interval, requires exactly one `session_meta.payload.cwd` match,
  and maps the last `thread_token_usage` counters independently with `cost: null`.
- `src/harness/opencode.ts`, `codex.ts`, `agy.ts`: implement the port (AGY returns all-null).
- `src/cli/plan.ts`: records the correlated pair around the existing spawn, calls the optional
  reader only after the child closes, keeps inherited stdio, and preserves non-zero propagation.
- `tests/plan-telemetry.test.ts` (new) plus `tests/fixtures/planning/{fake-planner.mjs,
  opencode-session.json, codex-rollout.jsonl}`.

## Verification

- `node --import tsx --test tests/plan-telemetry.test.ts`: 15/15 pass.
- `pnpm verify`: exit 0 (tsc, tests, lint).

## Deviated

- Usage readers were placed in new `src/harness/opencode-usage.ts` / `codex-usage.ts` files to stay
  under the 250-line budget; both match the task's `opencode*.ts` / `codex*.ts` scope globs.
- `pytest`/OpenCode artifact simulation: the fake planner writes the OpenCode artifact during the
  interactive session and serves it from `db` mode, so the artifact timestamp falls inside the
  observed interval without a static-time fixture.

## Drift against features/

  verified by an unchanged hash across a resumed session.
