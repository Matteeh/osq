# Task 5 result

## Changed

- `src/core/report.ts`
  - `MetricsReport` now exposes `planning` and `cycle` alongside the post-034
    blocks. New exported types: `PlanningMetrics`, `CyclePhaseMetrics`,
    `CycleChangeMetrics`, `CycleMetrics`.
  - `planning` derives only from correlated `.run/plan.jsonl` sessions across
    active and archived changes via the task-1 `readPlanningSessions`
    correlator: every valid `plan_started` counts once (`sessions`), wall time
    is summed from matched exits (`wallSeconds`, `wallSecondsByChange`), each
    usage field is summed independently only when finite
    (`tokens.input/output/cached/reasoning`), `cost` is `formatCost`-formatted
    `harness-reported`, and coverage counts a session once when any matched
    exit field is finite, including observed zero.
  - `cycle.byChange` has one `localeCompare`-sorted row per archived folder with
    `change` plus nullable `briefToApprovalSeconds`, `approvalToFirstTaskSeconds`,
    `firstTaskToArchiveSeconds`, and `totalSeconds`. Derivation reads only
    `brief.md` frontmatter `date`, `.run/manifest.json#approvedAt`, the earliest
    `started` across numeric `<n>.jsonl` streams, and the `archived` event in
    `.run/events/change.jsonl`. Missing/invalid/reversed endpoints and
    active/non-archived folders yield null or are excluded; no filesystem
    timestamp inference. Row seconds use the existing `Math.round(ms/1000)`
    convention; a row total is the sum only when all three phases are non-null.
  - `cycle.phases` (`briefToApproval`, `approvalToFirstTask`,
    `firstTaskToArchive`, `total`) each expose `totalSeconds`,
    `averageSeconds`, `coveredChanges`, and `totalChanges`.
  - The legacy execution-duration scan now skips `change.jsonl` so the
    change-level `verify_ran`/`archived` span can no longer inflate task
    durations. Token/file-change aggregation still reads every stream.
  - Text output adds `Planning:` (session count, total and per-change wall
    time, token totals, harness-reported cost, and the exact
    `n of m sessions reported usage` phrase) and `Cycle:` (aggregate phase
    lines only, each ending in `n of m archived changes`).
- `src/cli/report.ts` — `toStableMetrics` projects deep-cloned `planning` and
  `cycle` (including the ordered `cycle.byChange` array) into the stable JSON.
- `tests/report-planning.test.ts` (new) — fixture totals, deterministic
  per-change wall time, independent field sums, zero-as-reported, skipped
  orphan exits/malformed lines, missing logs, text phrase, and JSON shape.
- `tests/report-cycle.test.ts` (new) — fixture rows/aggregates, complete
  lifecycle, missing/invalid/reversed endpoints, active-change exclusion,
  numeric-stream-only first start, and `change.jsonl` span exclusion from
  executions durations plus aggregate text-only rendering.
- `tests/planning-integration.test.ts` (new) — real `planCommand` through the
  known-delay `fake-planner.mjs` (AGY, all-null usage), then the report entry
  point exposes one session with observed wall time and `0 of 1` coverage.
- `tests/report-json.test.ts` — added `planning`/`cycle` to the stable
  top-level keys and shape assertions, fixed the top-level-key-order check to
  match two-space-indented keys (nested `planning.tokens` no longer confuses
  it), supplied `planning`/`cycle` to the `formatMetricsReport` unit
  fixtures, and added a byte-for-byte comparison of `reportCommand --json`
  stdout (`raw + "\n"`) against `fixture/report/expected.json`.
- `fixture/report/**` — added `brief.md`, `.run/manifest.json`,
  `.run/events/change.jsonl`, and `.run/plan.jsonl` to the archived changes
  (008 is deliberately legacy with no manifest/archive event; 009 and 010 have
  complete lifecycles). Planning logs include an AGY all-null session and an
  observed-zero session. Regenerated `expected.json` from the real report
  command.

## Deviated

- A `plan_exited` record without a valid `plan_started` (orphan exit) is not
  counted as a session and its wall/usage are not aggregated, matching the
  proposal's "matched `plan_exited`" and "every valid start" language.
- `wallSecondsByChange` contains a key for every change that has at least one
  valid session, contributing `0` when that session has no observed exit.

## Drift against features/

- None. Planning cost stays separate from execution-history cost and is labeled
  `harness-reported`. Pre-034 report fields (`specs`, `completionRate`,
  `durations`, `tokens`, `fileChanges`) and post-034 `now`/`history`/`coverage`
  are unchanged; the fixture `durations` total is preserved by excluding
  `change.jsonl` from the duration scan.
