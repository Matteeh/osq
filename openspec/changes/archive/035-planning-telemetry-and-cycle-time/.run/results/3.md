# Task 3 result

## Changed

- `src/core/show.ts`
  - Added exported `PlanningSessionDetail` (`sessionId`, `startTime`, `harness`,
    `model`, optional `agent`, nullable `exitCode`, nullable `wallSeconds`) and a
    required `planningSessions` field on `SpecDetails`.
  - `getSpecDetails` reads `<change>/.run/plan.jsonl` through the shared
    `readPlanningSessions` correlator, keeps start-anchored sessions in
    `plan_started` order, and maps only lifecycle identity/timing/outcome so
    `usage` token data and `briefHash` never reach the inspection surface.
  - `formatSpecDetails` renders a `Planning Sessions:` section immediately
    before `Event Timeline:` with `harness/model`, optional `agent`, exit
    result, and `formatDuration(wallSeconds * 1000)`; null exit/wall render as
    explicit `unavailable`.
- `tests/show.test.ts`
  - New test: correlated sessions in start order (later start before an
    earlier-logged pair), optional agent, unmatched start, malformed line,
    unknown record, token/artifact non-exposure, and the same behavior for an
    archived change folder.
  - New test: section ordering before `Event Timeline:`, rendered
    harness/model/agent/exit/wall, explicit `unavailable`, and no usage values
    through both `formatShowOutput` and `showCommand`.
  - New test: absent and fully malformed planning logs leave tasks and the
    event timeline intact and render `(no planning sessions)`.

## Deviated

- Sessions that have only a `plan_exited` record (orphan exit) are filtered
  out: a displayable session requires a `plan_started` for its start time,
  harness, and model. Unmatched starts are retained with null exit and wall,
  which is what acceptance line 4 exercises. The shared correlator is used
  unchanged.

## Drift against features/

- None. Planning lifecycle records stay out of the task `timeline`; existing
  active/archive resolution, task state, dead diagnostics, results, and
  task-event ordering are untouched. Planning reads are defensive and never
  throw into `getSpecDetails`.
