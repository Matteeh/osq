## Changed

- Added `src/core/lifecycle/retry-transition.ts` (71 lines) holding the retry
  transition's rename and append work: `retainFailureMarkers` renames active
  regressed, dead, and (when requested) done markers to the shared next ordinal
  and returns the retained folder-relative paths, and `appendTargetEvent`
  appends the timestamped target-scoped lifecycle event.
- `src/core/lifecycle/retry.ts` (246 lines) now imports those helpers instead of
  defining them. Approval check, running check, reason and ordinal computation,
  and recertification stay in `retrySpec`. Removed the `biome-ignore format`
  line and the single-line import workaround; the import is now normally
  formatted.
- `retrySpec` accepts an optional fifth argument `RetryOptions`
  (`{ automatic?: boolean }`). When `automatic` is true the emitted `retry`
  event's data includes `automatic: true`; otherwise the key is absent. The
  recertification branch keeps its own event and never carries `automatic`.
- Added `tests/retry-automatic.test.ts` (new file, allowed): automatic and
  manual dead-task retries assert the retained `dead/1.1.md` name and the
  `automatic` field present/true or absent, automatic calls still refuse a
  mismatched approval hash and a live running lock without mutating, and a
  requeued scope-regression recertification carries no `automatic` key.
