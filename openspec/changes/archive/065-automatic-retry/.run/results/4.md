## Changed

- `src/core/foundation/config-gates.ts`: `GatesConfig` gains optional
  `autoRetries`; `DEFAULT_GATES_CONFIG` defaults it to 1; `validateGatesConfig`
  rejects a non-number, non-integer, or negative value with a diagnostic naming
  `gates.autoRetries`, and returns the resolved count.
- `src/harness/types.ts`: `RetryEventData` gains optional `automatic?: boolean`;
  `HarnessEventType` and `OsqEventData` gain `stuck` with the new
  `StuckEventData { task, fingerprint }`.
- `src/watcher/auto-retry.ts` (new, 231 lines, every function ≤ 80):
  exports `ELIGIBLE_AUTO_RETRY_REASONS` (`verify_red`, `change_verify_red`,
  `undeclared_test_change`, `no_result`, `crashed`, `timeout`) and
  `runAutomaticRetries(projectRoot, folderPath, config, logger) -> number`.
  Per active `dead/<n>.md` it: skips ineligible reasons; compares the stored (or
  re-derived) active fingerprint with the highest-ordinal retained
  `dead/<n>.<k>.md` and marks stuck when equal; otherwise counts automatic
  `retry` events after the later of the manifest `approvedAt` and the last
  manual `retry` and calls `retrySpec(..., { automatic: true })` under the
  configured limit. Stuck writes `stuck: true` through `parseFrontmatter` +
  `YAML.stringify` (body byte-identical), appends one `stuck` event, and logs
  once. `autoRetries <= 0` returns without doing anything.
- `src/watcher/loop.ts`: imports and calls `runAutomaticRetries` for every
  approved change after reaping and before the next task, re-derives state when
  a retry happened, accumulates a `retried` progress count, `runWatcherOnce`
  keeps looping while `tasksRun` or `retried` is non-zero, and the reaper passes
  `projectRoot` to `writeDeadMarker`.
- `tests/auto-retry.test.ts` (new): drives `runWatcherOnce`/`runWatcherCycle`
  with the mock harness and local verifiers covering verify_red-then-pass,
  two identical deaths (stuck), `spec_conflict` and `verify_precondition`
  ineligibility, count 0, a manual retry resetting an exhausted budget, and a
  pre-restart death.
- `tests/auto-retry-config.test.ts` (new): defaults, partial merge, zero,
  invalid values naming the key, and `loadConfig` from `osq.config.ts`.
- `tests/retry-watch.test.ts`: only its written `osq.config.ts` gained
  `autoRetries: 0` in `gates`.

## Deviated

- The manual-retry line of the exhausted-count test calls `retrySpec` directly
  (with no options) rather than spawning the `osq retry` CLI. That is the exact
  transition the command performs and is how the other retry suites exercise a
  human retry; the observable manual `retry` event is asserted.
