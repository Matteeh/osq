## Changed

- Added `src/core/report/report-retries.ts` (141 lines, every function under 80):
  `RetryGroupHistory` and `RetryHistory` types, `emptyRetryHistory`, the pure
  `observeRetries(events)` projection, and `addRetryHistory`. `observeRetries`
  scans one numbered task stream in order: each `retry` event opens an attempt
  (automatic when `data.automatic === true`), counts it, and resets the
  per-attempt done/cost flags; the attempt runs to the next `retry` or end of
  stream. A `done` inside it increments `reachedDone` once, finite `cost` values
  inside it sum into the group, and the group's `costReportedAttempts` counts
  each attempt with at least one finite cost once. Cost before the first retry
  belongs to no retry-opened attempt and is ignored. `stuck` counts `stuck`
  events.
- `src/core/report/report.ts`: `HistoryMetrics` gains `retries: RetryHistory`
  and imports the new module. In the task loop the stream is parsed once and
  both `observeTaskStream` and `observeRetries` consume it; `addRetryHistory`
  accumulates across streams. Two helpers
  (`formatRetryGroupLine`/`formatRetryHistoryLines`) render the block and the
  returned history object carries `retries`.
- `src/cli/report.ts`: `toStableMetrics` emits `history.retries` with both
  groups and `stuck`.
- Text adds an `Automatic retries:` block immediately after the pre-spawn
  verification line: `  Automatic retries:`, one
  `  <group>: <count> retries, <reachedDone> reached done, cost <formatted> (<n> of <count> attempts reported cost)`
  line each for `automatic` and `manual` using `formatReportedCost`, then
  `  Stuck: <stuck>`.
- `tests/report-retries.test.ts` (new): one change with an automatic retry whose
  attempt reaches done at cost 0.10 (with a larger pre-retry cost proving the
  window), a manual retry whose attempt dies plus a `stuck` event, a task with
  no retries, and a second change with no retries. It asserts every count, both
  costs, `costReportedAttempts`, `stuck`, the exact text lines, the block's
  position after the verification lines, and that `osq report --json` emits the
  same `history.retries`. A second test builds an only-normal stream and asserts
  zero counts with `not reported` text.
- `tests/report-json.test.ts` and `tests/report-scope-regressions.test.ts`: only
  the history key lists gained `retries`, and the two hand-built
  `MetricsReport` literals gained a `retries` block, as the task allows.
- `fixture/report/expected.json`: regenerated through the real report command;
  the fixture has no `retry` or `stuck` events, so `history.retries` is all
  zeros.
