## Changed

- `src/watcher/attempt.ts` (111 lines): added `readRetainedMarkerBody`, which
  reads `.run/dead/<n>.<attempt - 1>.md`, parses its frontmatter, and returns
  `stripAnsi(body)`, or `undefined` when the marker is missing. On every `retry`
  event `readRetryContext` now sets `output` from that helper instead of clearing
  it, so a manual or automatic dead-task retry carries the retained marker body.
  The requeued-recertification branch is untouched, so its captured verification
  output still wins whenever it is the latest transition. Existing
  `priorContextLines` remains the only bound (2,000 characters).
- Added `tests/retry-prior-output.test.ts`: three tests exercise
  `buildExecutorPrompt`. A manual `retrySpec` and an automatic
  `retrySpec(..., { automatic: true })` each over a dead marker containing ANSI
  codes assert the stripped body reaches the prompt and the escape bytes never
  do; a 5,000-character body asserts the prompt contains exactly the first 2,000
  characters plus `…` and no byte beyond the bound.
- `tests/retry-attempts.test.ts`: the expected `readRetryContext` context now
  includes `output: 'prior failure\n'` read from the retained `dead/1.1.md`.
  Assertions otherwise unchanged.
