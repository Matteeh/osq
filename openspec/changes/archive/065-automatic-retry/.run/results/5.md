## Changed

- `src/core/status/state.ts` (247 lines): `TaskState` gains optional `stuck`
  (the fingerprint). The dead-marker branch reads `stuck: true` plus a string
  `fingerprint` from the marker frontmatter and adds `stuck` only when present,
  so every other task state keeps exactly the same own properties. To make room
  inside the budget the function's `base` literal is built from a destructured
  `parseTaskMd` result on two lines instead of seven.
- `src/core/status/inbox.ts` (213 lines): `NeedsYouItem` gains optional
  `stuck: { fingerprint }`. `projectNeedsYou` sets it only for a `task-dead`
  item whose derived task is stuck, appended after `command`, so every other
  item's JSON key order is unchanged. The row renderers and `formatInboxText`
  moved out; `inbox.ts` re-exports `formatInboxText` from the new module.
- `src/core/status/inbox-text.ts` (new, 45 lines): `needsYouLine`,
  `runningLine`, `landedLine`, and `formatInboxText`. A stuck task-dead row
  reads `<head> — task <n>: <title> — stuck: same failure twice; amend the spec
  or osq reject <id> --reason <text> — osq retry <id> <n>`; all other rows are
  byte-identical to before.
- `tests/inbox-stuck.test.ts` (new): builds one stuck and one plain dead task
  in a real change folder, then asserts the derived task state, both `osq --json`
  needs-you items (including key order and a byte-for-byte plain item), and both
  text rows through the real bare `osq` CLI in text and `--json` modes.
