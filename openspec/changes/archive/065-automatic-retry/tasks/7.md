## Acceptance

- [ ] New `src/core/report/report-retries.ts` reads each task stream and splits `retry` events into automatic (`data.automatic === true`) and manual. An attempt opened by a retry runs to the next `retry` or the end of the stream. It reached done when a `done` event falls inside it, and its cost is the sum of finite `cost` values inside it.
- [ ] `HistoryMetrics` gains `retries: { automatic, manual, stuck }`. Each group is `{ count, reachedDone, cost, costReportedAttempts }`, and `stuck` counts `stuck` events.
- [ ] Text adds an `Automatic retries:` block after the verification lines. It has one line each for automatic and manual in the form `  <group>: <count> retries, <reachedDone> reached done, cost <formatted> (<n> of <count> attempts reported cost)`, then `  Stuck: <stuck>`. Costs are formatted with `formatReportedCost`, so an unknown cost reads `not reported`.
- [ ] `osq report --json` emits `history.retries` through `toStableMetrics`. `fixture/report/expected.json` gains only what the fixture's existing `retry` events produce. In `tests/report-json.test.ts` and `tests/report-scope-regressions.test.ts`, only history key lists, hand-built reports, and the fixture comparison change.
- [ ] New `tests/report-retries.test.ts` builds streams with an automatic retry that reaches done at cost 0.10, a manual retry that dies, a `stuck` event, and a stream without retries, and asserts every count, the cost, and the text lines.
