## Acceptance

- [ ] `GatesConfig` gains optional `autoRetries`, defaulting to 1 in `DEFAULT_GATES_CONFIG`. A negative, fractional, or non-numeric value throws naming `gates.autoRetries`. New tests live in `tests/auto-retry-config.test.ts`.
- [ ] New `src/watcher/auto-retry.ts` exports `ELIGIBLE_AUTO_RETRY_REASONS` (`verify_red`, `change_verify_red`, `undeclared_test_change`, `no_result`, `crashed`, `timeout`). It decides per dead task in an approved change as "Automatic retry" and "Stuck task detection" require:
  - It counts automatic `retry` events after the later of the manifest `approvedAt` and the last manual `retry`.
  - It compares the active marker's fingerprint with the highest-ordinal retained `dead/<n>.<k>.md`.
  - It calls `retrySpec(..., { automatic: true })`.
- [ ] Stuck: `stuck: true` is added to the active marker's frontmatter and a `stuck` event with `task` and `fingerprint` is appended, both once per death. The logger prints `↻ task <n> of <id> retried automatically after <reason> (attempt <k>)` or `■ task <n> of <id> stuck: same failure twice (<first 12 hex>)`, with `[retry]` and `[stuck]` as the plain-symbol forms.
- [ ] `runWatcherCycle` calls the decision for every approved change each cycle, after reaping and before picking the next task, and re-derives state when a retry happened. A retry counts as progress, so `runWatcherOnce` runs the retried task. The reaper passes `projectRoot` to `writeDeadMarker`. At `autoRetries: 0` the decision does nothing.
- [ ] `harness/types.ts` adds optional `automatic: true` to the `retry` event data and a `stuck` event type with `{ task, fingerprint }`. `tests/retry-watch.test.ts` changes only its written `osq.config.ts`, adding `autoRetries: 0` to `gates`.
- [ ] New `tests/auto-retry.test.ts` drives `runWatcherOnce` with the mock harness and local verifiers. It covers:
  - `verify_red` then pass: done, one automatic retry, one info line
  - two identical deaths: stuck, one `stuck` event, no third `started`
  - `spec_conflict` and `verify_precondition` deaths: never retried
  - count 0: exactly as today
  - a manual `osq retry` after an exhausted count: allows one more automatic retry
  - a death recorded before a restart: a fresh `runWatcherOnce` retries exactly once
- [ ] `loop.ts` gains only the call, the progress flag, and the reaper argument. The decision logic lives in `auto-retry.ts` under 250 lines, with every function at most 80 lines.

## Details

The watcher calls `retrySpec` after `runTask` returns. `runTask` releases
`.run/running/<n>.pid` in its `finally`, so `retrySpec`'s running check passes,
and its approval check applies as for a human. A `retrySpec` error, such as a
changed approval hash, is logged through `logger.warn` and leaves the task dead.
Rewrite the active marker with `parseFrontmatter` and YAML so its body stays
byte-identical. A worktree measurement showed that an automatic retry in the
loop breaks only `tests/retry-watch.test.ts`, whose verifier fails once and
then passes. No golden event fixture changes, because neither golden run
retries. Other tests are frozen.
