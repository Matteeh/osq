## Acceptance
- [ ] ParsedSpec in src/core/parser.ts removes writes from features, preserving reads
- [ ] src/core/linter.ts rejects any proposal that contains features.writes in frontmatter
- [ ] Delta specification files in specs/<capability>/spec.md within a change folder serve as the sole declaration of writes
- [ ] src/core/manifest.ts and src/core/show.ts resolve touched/written capabilities from delta files in specs/ rather than reading features.writes
- [ ] templates/openspec/schemas/osq/schema.yaml and templates/proposal.md omit features.writes
- [ ] osq migrate openspec adds an idempotent archive normalization step stripping features.writes and removing redundant spec.md files across all post-016 archives
- [ ] Automated test tests/proposal-writes-schema.test.ts verifies rejection of features.writes by osq lint and capability derivation from delta files

## Details

1. In `src/core/parser.ts`:
   - Update `ParsedSpecFrontmatter` and `ParsedSpec`:
     ```typescript
     export interface ParsedSpecFeatures {
       readonly reads: string[];
     }
     ```
   - In `parseSpecMd`:
     - Retain `rawFeatures.writes` only if needed internally for schema validation, but remove `writes` from the returned `features` object.
     - Provide a helper `hasDeclaredWrites(data)` to detect if `writes` was present in raw frontmatter.

2. In `src/core/linter.ts`:
   - Add a lint check rejecting `features.writes`:
     - If the parsed proposal frontmatter contains `writes` under `features`, add an error:
       `features.writes is no longer supported in proposal frontmatter; write declarations are derived strictly from delta specs under specs/<capability>/spec.md`.
   - Remove legacy checks that asserted `spec.features.writes.length > config.limits.maxFeatureWrites` or `features.writes contains entries while Delta is empty`.
   - Where capability writes are inspected (such as verifying touched capability specs), scan the change folder's `specs/` directory for subdirectories containing `spec.md`.

3. In `src/core/manifest.ts` and `src/core/show.ts`:
   - Update `buildManifest` and `showCommand` to discover written capabilities by reading `specs/` entries:
     ```typescript
     const deltasDir = path.join(changeFolderPath, 'specs');
     const writtenCapabilities = (await fs.readdir(deltasDir, { withFileTypes: true }).catch(() => []))
       .filter(e => e.isDirectory())
       .map(e => e.name)
       .sort();
     ```

4. In `src/core/migrate.ts`:
   - Add an archive normalization pass:
     - For every archived change folder in `openspec/changes/archive/`:
       - If `spec.md` exists alongside `proposal.md`, remove `spec.md`.
       - If `proposal.md` exists and contains `writes:` in frontmatter, parse frontmatter, remove `writes` from `features`, and rewrite `proposal.md`.
     - Ensure this normalization is idempotent and runs during `osq migrate openspec`.
   - Normalize the repository's post-016 archives (018 through 027 strip `writes`, 017 removes `spec.md`).

5. In `tests/proposal-writes-schema.test.ts`:
   - Assert `osq lint` rejects a proposal declaring `features.writes`.
   - Assert `osq lint` passes when `features.writes` is absent and deltas exist in `specs/`.
   - Assert `osq migrate openspec` strips `features.writes` and deletes redundant `spec.md`.
