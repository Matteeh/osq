# Task 1 result: pinned validator failure gating and removal of "skipped"

## Changed

- `src/core/linter.ts`
  - Added `OPENSPEC_PIN_REMEDIATION` naming ADR 004 (`decisions/004-pinned-openspec-validator.md`) and the install command `pnpm add -D @fission-ai/openspec@1.13.1`.
  - `validateWithOpenSpec` now fails closed: a missing binary returns an error (`ran: false, bin: null, version: null`) instead of empty errors; a version differing from `OPENSPEC_EXPECTED_VERSION` (`1.13.1`) is pushed to `errors` instead of `warnings`; an unresolvable version (no `@fission-ai/openspec/package.json`) is also an error. The `openspec validate skipped` verbose log is deleted.
  - Since `lintChangeFolder` propagates these errors, `osq lint` and `osq approve` now exit non-zero when the validator is absent or drifted. No edit to `src/core/approve.ts` was required.
- `src/core/init.ts`: renamed `InitResult.skippedFiles` to `existingFiles`.
- `src/cli/init.ts`: reads `result.existingFiles`.
- `src/core/migrate.ts`: renamed `MigrateResult.skipped` to `existing` and all push sites.
- `tests/validator-missing.test.ts` (new): covers `validateWithOpenSpec` for missing/drifted/pinned validator plus `osq lint` and `osq approve` non-zero failure paths, asserting the ADR 004 and install-command text.
- `tests/no-skipped-in-src.test.ts` (new): recursively asserts zero case-insensitive `skipped` matches under `src/`.
- `tests/linter.test.ts`: updated the two tests whose expectations changed (missing binary now fails; version drift now fails) instead of logging a warning.

## Deviated

- Added an extra fail-closed error branch for a present binary with an unresolvable version. Not explicitly listed in the task but consistent with the pinned-validator requirement.
- The missing-binary outcome intentionally returns `warnings: []` and `ran: false` (unchanged shape), so callers can distinguish "did not run" from "ran and failed".

No living-spec text was changed by this task (feature docs are updated only by an approved delta at archive time).
