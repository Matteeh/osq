# Task 3 result: proposal schema drops features.writes; delta specs are the sole writes declaration

## Changed

- `src/core/parser.ts`
  - `SpecFeatures` now declares only `readonly reads: string[]`; `parseSpecMd`
    no longer reads or returns `writes`.
  - Added exported `hasDeclaredWrites(data)` detecting a `writes` key under
    `features` in raw frontmatter for the linter.
- `src/core/linter.ts`
  - Removed the `maxFeatureWrites` limit check and the "Delta is empty while
    features.writes is not" check.
  - Added rejection: any frontmatter declaring `features.writes` produces
    `features.writes is no longer supported in proposal frontmatter; write
    declarations are derived strictly from delta specs under
    specs/<capability>/spec.md`.
  - Existing `verifyDeltaTargets` already scans `specs/<capability>/spec.md`.
- `src/core/manifest.ts`
  - `buildManifest` discovers written capabilities by listing subdirectories of
    the change folder's `specs/` directory instead of `features.writes`; the set
    is unioned with `features.reads` for hashing.
- `src/core/show.ts`
  - `getSpecDetails` derives `features.writes` from `specs/` delta directories
    (sorted); `features.reads` still comes from frontmatter.
- `src/core/migrate.ts`
  - `MigrateResult` gained `normalizedArchives: string[]`.
  - New idempotent `normalizeArchivedChanges(archiveTarget, result)` pass run by
    `migrateToOpenSpec`: removes `spec.md` when `proposal.md` exists alongside it,
    and rewrites `proposal.md` dropping `features.writes` while preserving
    `features.reads` and the body.
- `src/harness/opencode.ts` (outside frontmatter scope, required to compile)
  - `buildOpencodeArgs` fallback now collects written capability names by listing
    the change folder's `specs/` subdirectories instead of `specData.features.writes`.
- Repo archive normalization (scope `openspec/changes/archive/**`):
  - Deleted `openspec/changes/archive/017-ownership-and-test-gating/spec.md`.
  - Stripped `features.writes` from `proposal.md` in archives 018 through 027 by
    running `migrateToOpenSpec({ sampleStub: false })` against the repo. YAML
    re-serialization also reflowed `depends_on`/long titles in those files.
- `tests/proposal-writes-schema.test.ts` (new): 4 tests covering lint rejection
  (`lintChangeFolder` + `lintCommand` exit 1), lint pass with delta-only writes,
  write derivation by `getSpecDetails` and `buildManifest`, and migration
  stripping writes + removing redundant `spec.md` idempotently.
- Test fixtures updated for the schema/type change: `tests/linter.test.ts`,
  `tests/migrate.test.ts`, `tests/parser.test.ts`, `tests/show.test.ts`,
  `tests/manifest.test.ts`, `tests/opencode-spawn.test.ts`.

`templates/proposal.md` and `templates/openspec/schemas/osq/schema.yaml` already
omitted `features.writes`; no template edit was necessary.

## Deviated

1. `src/harness/opencode.ts` is not in the task scope but had to be updated
   because `SpecFeatures.writes` no longer type-checks there. It now derives
   written capabilities from `specs/` directories, matching the new contract.
   `src/watcher/archiver.ts` and `src/core/state.ts` also call the parser but do
   not read `features.writes`, so they were left untouched.
2. Extra test fixtures were modified (`parser`, `show`, `manifest`,
   `opencode-spawn`) because they asserted or seeded `features.writes`. `tests/**`
   is in scope.
3. `normalizeArchivedChanges` rewrites the entire `proposal.md` frontmatter via
   `YAML.stringify` when writes are present. This reformats unrelated frontmatter
   in the normalized archives (e.g. quoting numeric `depends_on`, wrapping long
   titles) but is required to remove the field and is a one-time change; the
   pass is a no-op afterwards.
