## Deviated

- The raw `mergeDelta` of 016..027 reproduces two legacy source comments that
  literally contain `Delta from` (016 `status-inspection` and
  `watcher-and-harness` deltas, e.g.
  `<!-- source: features/status-inspection.md # Delta from Show command ... -->`).
  Acceptance requires `git grep "Delta from" openspec/specs/` to be empty while
  `mergeDelta` and the archive folders are out of this task's scope (and
  `src/core/delta.ts` is a non-goal). The re-seed therefore post-processes the
  merged output with `stripLegacyDeltaReferences` (removes the literal
  `Delta from ` phrase from the two source comments). The equivalence test
  applies the identical normalization, so on-disk specs still equal the replayed
  merge exactly. This is the only sanitization performed.
- Because the re-seed starts from a null base, `serializeCapabilitySpec` gives
  each spec the deterministic title `<capability> Specification` rather than the
  previous hand-maintained pretty titles. This is a direct consequence of the
  required null-base re-seed.
- Added the `applyDelta`-absence / `applyOpenSpecDeltas`-direct-call assertions
  to the equivalence test so acceptance lines about the deleted identifier are
  covered by this task's verify command.
