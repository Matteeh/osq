## Changed

- `src/core/foundation/config-traceability.ts`: added `MutationConfig`
  (`command: string`, `budgetSeconds: number`), an optional `mutation` on
  `TraceabilityConfig`, `DEFAULT_MUTATION_BUDGET_SECONDS = 300`, and
  `validateMutationConfig`, called from `validateTraceabilityConfig`. The
  resolved block omits `mutation` when unset; a bare mutation command gets the
  300-second default.
- `tests/mutation-config.test.ts`: new test file covering off-by-default, the
  budget default, a custom budget, both error messages
  (`traceability.mutation.command must be a non-empty command` and
  `traceability.mutation.budgetSeconds must be a positive number`), and loading
  `mutation` from a temporary `osq.config.ts` through `loadConfig` (bare command
  and explicit budget).

## Outside scope

- `src/core/foundation/config-user.ts` declares `traceability?: Partial<TraceabilityConfig>`,
  which only partials the top level. A typed
  `defineConfig({ traceability: { mutation: { command } } })` therefore cannot
  omit `budgetSeconds` even though the validator defaults it; `loadConfig` and
  `validateTraceabilityConfig` (both exercised by the new test) do accept the
  bare command. Left alone because `config-user.ts` is not in this task's scope.
- `openspec/changes/archive/082-traceability-fast-feedback/.run/events/change.jsonl`
  gained a `verification_recorded` line during the verification run, unrelated
  to this task. Left alone.
