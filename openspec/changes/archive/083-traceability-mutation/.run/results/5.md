## Changed

- New `src/core/report/report-mutation.ts` (248 lines, under budget): derives
  the "Mutation in report" requirement. `collectMutationScores(folders, config)`
  reads numbered task streams of every active and archived change, keeps the
  latest measured `mutation_ran` event per `<file>#<function>` by timestamp,
  groups each into the opted-in capabilities its `scenarios` name (`'all'`
  accepts every capability), and returns each capability's killed/survived
  sums, the `killed / (killed + survived)` score rounded to three decimals
  (null for `0 of 0`), and every survivor as
  `{ file, function, line, column, mutator, replacement }`, in capability name
  order. `formatMutation` renders the `Mutation:`/`  <capability>: ...`/
  `    survived: <file>:<line>:<column> <mutator> -> <replacement>` text.
  Nothing is opted in or no measured event names an opted-in capability returns
  `undefined`.
- `src/core/report/report.ts`: `MetricsReport` gains optional `mutation`;
  `getMetricsReport` fills it through one `collectMutationScores` call over
  `allSpecFolders`; `formatMetricsReport` prints the section only when present,
  after `Traceability:`.
- `src/cli/report.ts`: `toStableMetrics` copies `mutation` only when present,
  with the exact stable shape and per-survivor fields.
- `src/core/status/show.ts`: a formatter beside `formatFocusedRuns`
  (`formatMutationRuns` plus two small helpers) projects a task's `mutation_ran`
  events after its last `measures` start event into
  `      Mutation: <entry>; <entry>` and one
  `        Survived: <file>:<line>:<column> <mutator> -> <replacement>` line per
  survivor; `formatSpecDetails` emits it right after the `Focused runs:` line.
- `README.md`: a new `### Mutation checks` subsection under Traceability
  documenting `traceability.mutation.command`/`budgetSeconds` (default 300),
  which functions are picked, the ranges (own range plus called private
  same-file helpers) and tests each run gets, the `{mutate}`, `{tests}`,
  `{report}` placeholders and `OSQ_MUTATE`, `OSQ_MUTATION_TESTS`,
  `OSQ_MUTATION_REPORT` variables (plus inherited `OSQ_CHANGE`), the budget,
  the five not-measured reasons, the `mutation_ran` event fields, the show and
  report lines, and the reference StrykerJS setup with the exact
  `stryker.config.mjs`, the `@stryker-mutator/core` dev dependency, the
  `npx stryker run` command, the `tsc` layout assumption, leaving
  `thresholds.break` unset, and adding `.stryker-tmp` to `.gitignore`.
- New `tests/mutation-report.test.ts` (9 tests): latest measurement wins across
  two changes; grouping by each named capability in name order; opted-in list
  filtering; no measured event and a not-measured-only stream leaving text and
  JSON unchanged; no capability opted in; the show survivor scenario with the
  line after `Focused runs:`; a not-measured show entry; hiding mutation events
  before the last `measures` start; and no mutation line for a clean task. It
  exercises `getMetricsReport`, `reportCommand` text and JSON, and
  `getSpecDetailsFromFolder` with `formatSpecDetails`.

## Deviated

- The report's text percent for a capability whose score is null (only invalid
  mutants) renders `0.0%`; the spec fixes the JSON score as null but does not
  say what the text percent is then, and no scenario covers it.
- `collectMutationScores` returns `undefined` when measured events exist but
  none names an opted-in capability, so the JSON gains no empty `mutation` key.
  The spec only fixes the no-measured-event case; an absent section is
  consistent with the traceability section's behavior.
