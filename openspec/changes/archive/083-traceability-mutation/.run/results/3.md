## Changed

- `src/core/run/verification.ts`: `runVerificationCommand` takes an optional
  fifth argument `extraEnv?: Readonly<Record<string, string>>`, applied to the
  child environment after the `OSQ_CHANGE` handling. Every existing caller is
  unchanged.
- New `src/core/trace/mutation-pick.ts`: `pickMutations(options)` builds picks
  from a `ScenarioIndex`, the function ranges, a raw task `scope`, and the
  latest start/end `measures` data. It keeps only exported functions with a
  `@scenario` tag naming an opted-in capability and at least one scenario test
  file naming that tagged scenario. A pick is emitted when the scoped own-range
  hash differs from `start.functionHashes[<file>#<name>]` (missing entry counts
  as different), or when an `end.scopeHashes` test file with different before
  and after hashes covers it. Picks carry file, name, line, mutation ranges
  (null when unknown), `<capability>: <name>` scenarios, and sorted distinct
  tests, ordered by file then start line. A local `MeasuresView` interface
  carries only the two fields read, so core imports no harness type.
- New `src/core/run/mutation-report.ts`: `readMutationReport(reportPath, file,
  ranges)` parses untrusted JSON, reads only `files[<file>].mutants[]`, counts
  `Killed`/`Timeout` as killed and `Survived`/`NoCoverage` as survived, counts
  an unknown status or a missing/mistyped field invalid, skips mutants outside
  the parsed ranges, cuts survivor replacements to 200 characters, and returns
  null for a missing, non-JSON, or `files`-less report. Exports a
  structurally-compatible `MutationSurvivor` and `MutationCounts`.
- New `src/core/run/mutation-run.ts`: `runMutationPick(pick, projectRoot,
  changeFolder, command, timeoutSeconds)` substitutes `{mutate}` (comma-joined),
  `{tests}` (single-quoted, space-separated), and `{report}` (single-quoted
  absolute temp path), runs through `runVerificationCommand` with
  `OSQ_MUTATE`, `OSQ_MUTATION_TESTS`, and `OSQ_MUTATION_REPORT` (JSON arrays for
  the first two), and returns the outcome, counts, survivors, duration, exit
  code, and output. Unknown ranges return `range_unknown` without running;
  timeout is `timed_out`, nonzero/spawn error `command_failed`, unreadable
  report `report_invalid`, with the last 2,000 output characters for the two
  command outcomes. The temp folder is removed in a `finally`.
- New `tests/mutation-pick.test.ts`: all three "Mutation picks" scenarios, both
  test files of two scenarios in one pick, a newly changed covering test for an
  unchanged function, an unchanged/untested function, a non-opted-in
  capability, a tagged function no test names, and file-then-line pick order.
- New `tests/mutation-run.test.ts`: a fake `node` command that records argv and
  environment. It covers placeholder and environment values plus `OSQ_CHANGE`,
  a survivor, every status mapping, a mistyped mutant, a mutant outside the
  ranges, a 200-character replacement cut, a missing report, non-JSON, a report
  without `files`, `command_failed`, `timed_out`, `range_unknown`, and removal of
  the temp folder.

## Deviated

- `pickMutations` takes the raw task `scope` in its options and resolves it with
  `resolveScope`, rather than deriving it from `end.scopeHashes`. The measures
  data has no explicit scope field; the end event's hash keys are equivalent for
  a completed task, but an explicit scope keeps the condition an exact match for
  "its file is in the task's resolved scope" and matches how `focused-tests.ts`
  resolves scope.
- The tests of a pick are the union of `index.testsNaming` over the tagged
  opted-in scenarios, as the requirement literally says "tests ... that name any
  of those scenarios". Condition B additionally requires `index.covers(test,
  file, name)`, as its sentence says a test file "covers it".
- `runMutationPick` handles `range_unknown` itself (returns before spawning),
  even though the requirement that records it as such sits in "Mutation check
  after a pass". It keeps every pick outcome in one place for task 4.
- The result always carries `output`; the event only needs it for
  `command_failed` and `timed_out`, so task 4 chooses whether to copy it.
