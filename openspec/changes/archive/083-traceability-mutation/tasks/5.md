- [ ] New `src/core/report/report-mutation.ts` derives the metrics-and-reporting delta's "Mutation in report" from task event streams, and `MetricsReport` gains optional `mutation`. `getMetricsReport` fills it, `toStableMetrics` copies it only when present, and `formatMetricsReport` prints the section only when present.
- [ ] `formatSpecDetails` prints the status-inspection delta's "Mutation in show" lines after the `Focused runs:` line, from a small formatter beside `formatFocusedRuns`.
- [ ] `README.md` documents `traceability.mutation`, the placeholders and environment variables, which functions are picked and which ranges and tests each run gets, the budget, the not-measured reasons, the event, and the show and report lines. - [ ] New `tests/mutation-report.test.ts` covers every scenario of both requirements with hand-written `mutation_ran` events on temporary projects, through `getMetricsReport`, the report command's JSON and text output, and `getSpecDetailsFromFolder` with `formatSpecDetails`. `tests/report-json.test.ts` and `fixture/report/expected.json` pass unchanged.

## Details

`report-traceability.ts` from change 081 is the model for an optional report
section in its own module. `report.ts` and `show.ts` are on the line-budget
allow list, and `getMetricsReport`, `formatMetricsReport`, `toStableMetrics`,
and `formatSpecDetails` are grandfathered, so keep each to the call and a few
wiring lines. The opted-in capability list comes from `config.traceability`;
`'all'` accepts every capability an event names. New functions stay within 80
lines and new files within 250.
