## Acceptance

- [ ] The `Vcs` interface in `src/core/vcs/vcs.ts` gains exactly these members, as the version-control delta's "Vcs merge operations" says:

  ```ts
  export interface VcsMergeResult {
    readonly status: 'clean' | 'conflict';
    /** Unmerged paths relative to the project root, sorted; empty when clean. */
    readonly conflicts: readonly string[];
  }

  merge(ref: string, squash: boolean): Promise<VcsMergeResult>;
  mergeAbort(): Promise<void>;
  stage(paths: readonly string[]): Promise<void>;
  isAncestor(ancestor: string, descendant: string): Promise<boolean>;
  ```

- [ ] New `src/core/vcs/git-vcs-merge.ts` implements them over `GitWriteContext`, and `GitVcs` delegates to it as it delegates `commit` and `discard` to `git-vcs-write.ts`. `merge` and `mergeAbort` are bounded by `timeouts.gitCommitSeconds`, as `commit` is. `isAncestor` is bounded by `timeouts.gitSeconds`.
- [ ] `NoVcs` returns false from `isAncestor` and fails `merge`, `mergeAbort`, and `stage` naming its reason, as its other writes do.
- [ ] The only change to `tests/vcs-write.test.ts` is adding the four names to `PORT_MEMBERS`. Its forbidden-argument test still passes over the new file.
- [ ] New `tests/vcs-merge.test.ts` covers every scenario of "Vcs merge operations" on temporary repositories, plus `NoVcs`'s four results.

## Details

Tell a conflict from a refusal after a non-zero `git merge` by listing
unmerged paths with `git diff --name-only --diff-filter=U`. None means git
refused, and `merge` fails with git's output. Build repositories the way
`tests/vcs-write.test.ts` does, with the `GIT_*` variables removed from the
environment.
