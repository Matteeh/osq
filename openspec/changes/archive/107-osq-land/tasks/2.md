## Acceptance

- [ ] `applyOpenSpecDeltas`, and the `resolveOpenSpecRoot` helper only it uses, move unchanged to new `src/core/spec/apply-deltas.ts`. `archiver.ts` imports it, still calls it as `await applyOpenSpecDeltas(projectRoot, specFolderPath, config);`, and re-exports it.
- [ ] New `src/core/vcs/sync-main.ts` exports `syncWithDefaultBranch`, which takes the checkout's project root, the config, and the archived change as `listChanges` locates it in its worktree. It resolves to `{ merged: boolean }` and follows the version-control delta's "Default branch sync" step by step. A stop is an `Error` whose message the requirement gives. It selects the worktree's `Vcs` with `selectVcs` on the worktree's root, and uses task 1's `isAncestor`, `merge`, `mergeAbort`, and `stage`.
- [ ] New `src/core/vcs/sync-specs.ts` holds the requirement check of step 1 and the rebuild of step 3. The check reads both sides with `Vcs.show` and parses them with `parseCapabilitySpec` and `parseDelta`. The rebuild uses `applyOpenSpecDeltas`.
- [ ] `vcs.prepare` runs through `runPrepare`, and the proposal's `verify` through `runVerificationCommand` with `changeFolder` null.
- [ ] Every function stays within 80 lines and every file within 250.
- [ ] `tests/archiver.test.ts`, `tests/delta-merge.test.ts`, `tests/living-specs-delta-equivalence.test.ts`, `tests/openspec-differential.test.ts`, and every other test pass unchanged.
- [ ] New `tests/vcs-sync.test.ts` covers every scenario of "Default branch sync", plus a failing `vcs.prepare` and a `pre-commit` hook that rejects the sync commit. Each stop checks that the worktree's HEAD is unchanged and its `status` is empty. It also covers the watcher-and-harness delta's new "One merge for archive and sync" scenario by reading the two source files.

## Details

Build each repository by hand, as `tests/vcs-write.test.ts` does. Give it a
default branch holding `openspec/specs/orders/spec.md`, a branch
`osq/002-<words>` cut from it with a linked worktree, and a commit on the
branch that holds the archived folder: `proposal.md` whose `verify` is
`node verify.cjs`, `specs/orders/spec.md` with the delta, and `.run/base`
naming the cut commit. The same commit holds the living spec with the delta
applied. Then advance the default branch. `verify.cjs` sits in the
repository root and exits by a file the test controls, so the red case needs
no network or real suite.

The requirement check runs before the merge, so a stop at step 1 writes
nothing.
