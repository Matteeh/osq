## Changed

- `src/core/spec/apply-deltas.ts`: new home of `applyOpenSpecDeltas` and its
  private `resolveOpenSpecRoot`, moved verbatim from `src/watcher/archiver.ts`
  so core can use the same deterministic delta merge.
- `src/watcher/archiver.ts`: dropped the moved code, imports
  `applyOpenSpecDeltas` from `../core/spec/apply-deltas.js`, calls it exactly
  as before in `archiveSpecFolder`, and re-exports it for existing callers.
- `src/core/vcs/sync-specs.ts`: new module holding the "Default branch sync"
  step 1 requirement check and the step 3 rebuild. The check reads the living
  spec at `.run/base` and at the default branch tip through `Vcs.show`, parses
  both with `parseCapabilitySpec`, collects the names `parseDelta` returns as
  MODIFIED, REMOVED, and rename sources, and reports every requirement whose
  verbatim text differs or that the default branch lacks. The rebuild writes
  the default branch's copy of each delta capability's living spec (removing
  the file when the default branch has none), runs `applyOpenSpecDeltas`, and
  stages the files.
- `src/core/vcs/sync-main.ts`: new `syncWithDefaultBranch(projectRoot, config,
  change)`. It selects the worktree's `Vcs`, returns `{ merged: false }` when
  the default branch is already an ancestor of HEAD, then checks requirements,
  merges without committing (tolerating conflicts only in the living specs the
  deltas write), rebuilds the living specs, runs `runPrepare`, runs the
  proposal's `verify` through `runVerificationCommand` with `changeFolder`
  null, and commits `osq: <id> sync <default branch>` authored by
  `vcs.author`. Every stop aborts the merge and rethrows the required message.
- `tests/vcs-sync.test.ts`: new suite building real temporary repositories with
  a linked worktree and an archived change, covering every "Default branch
  sync" scenario plus a failing `vcs.prepare`, a `pre-commit` hook that rejects
  the sync commit, and the "One merge for archive and sync" source check.

## Deviated

- `syncWithDefaultBranch`'s first parameter is unused: all work happens in the
  worktree, so the function accepts the checkout root as `_projectRoot` and
  relies on `selectVcs(change.tree.root, config)`. The signature still takes it
  first, as the task requires.
- Steps 3 through 5 (`rebuildLivingSpecs`, `runPrepare`, `runSyncVerify`) share
  one `try`/`catch` that aborts the merge, because every one of their failures
  has the same abort-then-stop behaviour.

## Outside scope

- `tests/vcs-merge.test.ts` (task 1's file) still passes; nothing there needed
  to change.
- No issue found outside this task's scope.
