## Changed

- `src/core/vcs/vcs.ts`: added `VcsMergeResult` and the four new `Vcs` members
  `merge`, `mergeAbort`, `stage`, and `isAncestor`.
- `src/core/vcs/git-vcs-merge.ts`: new module implementing the four members
  over `GitWriteContext`. `merge` runs `--no-ff --no-commit` or `--squash`,
  distinguishes a conflict from a refusal with
  `git diff --name-only --diff-filter=U -z`, and fails with git's output on a
  refusal. `mergeAbort` runs `git merge --abort`. `stage` runs
  `git add -A --` over the given paths. `isAncestor` runs
  `git merge-base --is-ancestor`.
- `src/core/vcs/git-vcs.ts`: `GitVcs` delegates the four members to
  `git-vcs-merge.ts` through its `GitWriteContext`, so `merge`/`mergeAbort`
  use `runCommit` (`timeouts.gitCommitSeconds`) and `isAncestor` uses `run`
  (`timeouts.gitSeconds`).
- `src/core/vcs/no-vcs.ts`: `NoVcs` returns false from `isAncestor` and
  rejects `merge`, `mergeAbort`, and `stage` with the reason git is off.
- `tests/vcs-merge.test.ts`: new suite covering every scenario of "Vcs merge
  operations" and `NoVcs`'s four results.
- `tests/vcs-write.test.ts`: added the four new names to `PORT_MEMBERS`, the
  only change to that file.

## Deviated

- The `stage` write runs through the `run` bound (`timeouts.gitSeconds`),
  matching the other non-commit writes; the task only pinned `merge`,
  `mergeAbort` to `gitCommitSeconds` and `isAncestor` to `gitSeconds`.
- I did not add a timeout-bound test. The acceptance asks for the scenarios of
  "Vcs merge operations" plus `NoVcs`'s four results, and there is no timeout
  scenario. `merge`/`mergeAbort` go through `runCommit`, which is already
  proven bounded by the existing commit timeout test.
