# Task 4 result

## Changed

- `src/core/state.ts` (247 lines, under the 250 budget):
  - Added and exported `ChangeFolderSnapshot` (folder metadata, parsed `SpecData`, approved hash, task file map, done marker set, dead marker map, running pid map, result file set, unmet dependency set).
  - Added and exported `readChangeFolder(projectRoot, folderPath): Promise<ChangeFolderSnapshot>`. It is the single disk I/O boundary: reads the change doc, `.run/approved`, `tasks/*.md`, `.run/done/*`, `.run/dead/*.md`, `.run/running/*.pid`, and `.run/results/*.md`, and resolves dependency completion.
  - Refactored `deriveSpecState(snapshot: ChangeFolderSnapshot): SpecState` into a synchronous, pure function. It sorts task files, derives each task from snapshot maps/sets, and evaluates `unapproved`/`dead`/`running`/`done`/`blocked`/`pending` with no filesystem calls.
  - Added `deriveSpecStateFromDisk(projectRoot, folderPath)` as the async disk-backed wrapper.
  - Rewrote `deriveTaskState` to read a snapshot and reuse the pure task evaluator; `deriveTaskStatus` alias retained.
- `src/core/layout.ts` (75 lines): added `getApprovedMarkerPath`, `getRunningPidPath`, and `getResultPath` so the state read boundary derives marker locations canonically.
- `src/watcher/loop.ts`: replaced `config.paths.specs`/`config.paths.archive` with `getChangesDir`/`getArchiveDir(config.paths.openspecRoot, ...)` and now derives state via `deriveSpecState(await readChangeFolder(projectRoot, folderPath))`.
- `tests/state-snapshot.test.ts` (new, 120 lines): 9 tests driving `deriveSpecState` with synthetic in-memory snapshots against a non-existent `folderPath`, covering unapproved, ready/pending, synchronous-only, running, done, dead, two `conflicted` shapes (done+running precedence and mixed done+dead), and blocked/unmet dependencies. Zero disk access.

## Deviated

- Added `resultFiles: ReadonlySet<string>` to `ChangeFolderSnapshot` (not enumerated in the task Details) to keep `TaskState.resultFile` parity for pending tasks.
- `readChangeFolder` also resolves dependency completion into `unmetDependencies`, because `blocked` derivation needs it and the Details did not enumerate a dependency field. Dependency folders are located from `path.dirname(path.resolve(projectRoot, folderPath))` plus a sibling `archive/`, so a custom `openspecRoot` works without a config parameter.
- `deriveTaskState` no longer contains its own duplicated marker logic; it now requires a resolvable change doc (via `readChangeFolder`). This is a behavior change for direct callers, but keeps the file under budget and guarantees one task-evaluation path.
