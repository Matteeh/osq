## Acceptance
- [ ] src/core/state.ts exports ChangeFolderSnapshot interface
- [ ] src/core/state.ts exports readChangeFolder returning a ChangeFolderSnapshot
- [ ] src/core/state.ts exports deriveSpecState as a synchronous pure function accepting a snapshot
- [ ] deriveSpecState evaluates tasks, approvals, and markers without performing disk I/O
- [ ] src/watcher/loop.ts uses readChangeFolder and pure deriveSpecState
- [ ] tests/state-snapshot.test.ts verifies deriveSpecState against synthetic in-memory snapshots
- [ ] src/core/state.ts remains under 250 lines

## Details

1. In `src/core/state.ts`:
   - Define and export `ChangeFolderSnapshot`:
     Represents folder metadata, parsed proposal/spec, approved hash, task files map, done markers set, dead markers map, and running pids map.
   - Implement and export `readChangeFolder(projectRoot: string, folderPath: string): Promise<ChangeFolderSnapshot>`:
     Reads the change files, `.run/approved`, `.run/tasks/*.md`, `.run/done/*`, `.run/dead/*.md`, and `.run/running/*.pid` into the snapshot structure.
   - Refactor `deriveSpecState(snapshot: ChangeFolderSnapshot): SpecState`:
     A synchronous, pure function that evaluates the `SpecState` (status, tasks, failure reasons) purely from the `ChangeFolderSnapshot` fields without any filesystem operations.
   - Maintain a backward-compatible wrapper `deriveSpecStateFromDisk(projectRoot: string, folderPath: string): Promise<SpecState>` if callers outside the watcher need asynchronous disk derivation.
   - Ensure `src/core/state.ts` is under 250 lines.
2. In `src/watcher/loop.ts`:
   - Read the snapshot using `readChangeFolder` and pass it to `deriveSpecState`.
3. Create `tests/state-snapshot.test.ts`:
   - Verify `deriveSpecState` directly with synthetic in-memory snapshot objects for ready, running, done, dead, and conflicted task scenarios with zero disk access.
4. Verification:
   - Run `node --import tsx --test tests/state-snapshot.test.ts`.
