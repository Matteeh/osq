## Details

Build the test with `createRecoveryProject` from `tests/recovery-support.ts`,
as the first half of `tests/recovery-sync-conflict.test.ts` does: one task
on `src/one.txt`, `autoRetries: 0`, a `ScriptedAdapter` whose first spawn
moves main with `commitMain` so the sync conflicts, then `reviseTask`.
Before the approval, lock the worktree with
`git worktree lock <project.worktree>` from the repository, which makes
git refuse to remove it; read `.run/regressed/change.md` first so the test
can compare its bytes after. After the failed approval, unlock it and
approve again. Read the branches with `git branch --list` and the
approval's output from the `CommandResult` that `project.approve()` gives.

The scenario helper's `covers` is the project's `approve`; call it through
`run`, and import `scenario` from `@matteeh/osq/testing`.

A rough version of this change, measured on 2026-10-25, passed this
sequence; without the skipped commit, the second approval fails with
`nothing to commit, working tree clean`.
