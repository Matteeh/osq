## Details

The `review` callback runs inside `confirmApproval` in
`src/core/spec/approve-worktree-shared.ts`, which does not catch it. So a
`CommandError` thrown there reaches `approveCommand`'s own `catch`, which must
pass it on untouched.

`tests/approve-confirm.test.ts` shows how `createProject` and `createChange`
set up an approvable, flagged change without terminal input. Under
`node --test`, stdin is not a terminal, so `osq approve <id> --confirm`
through `runCli` takes the no-terminal path. The flagged change needs no
answer, and the test must not pass `isTerminal`.

Through `runCli`, a successful approval runs the default planning readers,
which read `CODEX_HOME`, `OSQ_CLAUDE_PROJECTS_DIR`, and `CLAUDE_CONFIG_DIR`, and
run the binary named by `OPENCODE_PATH`. Point all four at paths inside the
test's temporary folder that do not exist, so the readers find nothing and
never touch the real home directory, and call `restoreEnv` from
`tests/planning-observed-helpers.ts` before and after each test, as
`tests/approve-confirm.test.ts` does.
