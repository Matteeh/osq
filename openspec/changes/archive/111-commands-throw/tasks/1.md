## Acceptance

- [ ] New `src/cli/command-error.ts` exports exactly this class, as the cli-foundation delta's added "Command errors" says:

  ```ts
  export class CommandError extends Error {
    readonly exitCode: number;
    readonly next: string | undefined;
    constructor(message: string, options: { exitCode?: number; next?: string } = {});
  }
  ```

  `name` is `'CommandError'`, `exitCode` defaults to 1, and `next` to `undefined`.
- [ ] `runCli` in `src/cli/run.ts` follows the delta's added "Command error output". It catches a `CommandError`: it calls `console.error(error.message)` only when the message is not empty, then `console.log(`Next: ${error.next}`)` only when `next` is set, then sets `process.exitCode = error.exitCode` and returns. The `ConfigLoadError` branch keeps its `Error: <message>` line and sets `process.exitCode = 1` instead of calling `process.exit(1)`. Any other error still propagates. The doc comment says so, and `run.ts` no longer contains `process.exit(`.
- [ ] In `statusCommand`, `showCommand`, and `reportCommand`, each `console.error(<text>); process.exit(1);` pair becomes `throw new CommandError(<text>)` with `<text>` byte for byte the same, including show's empty-id check. Nothing else in those files changes.
- [ ] New `tests/cli-capture.ts`, a helper for this and later tasks, exports `runCliCaptured(cwd: string, argv: readonly string[]): Promise<CliCapture>` and `interface CliCapture { readonly exitCode: number | undefined; readonly lines: readonly CliLine[] }` with `interface CliLine { readonly stream: 'stdout' | 'stderr'; readonly text: string }`. It changes to `cwd`, sets `process.exitCode = undefined`, and runs `runCli(['node', 'osq', ...argv])`. Meanwhile, each `console.log` call appends one `stdout` line and each `console.error` or `console.warn` call one `stderr` line, its arguments joined by a space, and `process.exit` throws `Error('process.exit called')`. It returns `process.exitCode` as `runCli` left it, and always restores the working directory, the previous `process.exitCode`, the console methods, and `process.exit`, even when `runCli` rejects.
- [ ] In `tests/cli-config-errors.test.ts`, only `runInProject` changes: it no longer replaces `process.exit`. It saves `process.exitCode`, sets it to `undefined`, reads it after `runCli` as the returned exit code, and restores the saved value in its `finally`. Every test title and assertion stays the same.
- [ ] New `tests/command-error.test.ts` uses `runCliCaptured` on a project made with `scaffoldProject` from `src/core/foundation/init.ts`. It covers "Refusal on the command line", `osq show ' '` (`Error: specify a spec ID to show (e.g. osq show 001)`), `osq report --since garbage` (`Report error: --since is not a date: garbage`), and `osq status` with a change folder whose `proposal.md` is a directory (one stderr line starting `Status error: EISDIR`). Each has exactly one stderr line, no stdout line, and exit code 1. It also covers "Caller carries on" by awaiting `showCommand('999', { cwd, config: DEFAULT_CONFIG })` with `console.error` recorded.
- [ ] Every function stays within 80 lines and every file within its line budget. `tests/line-budget.test.ts`, `tests/function-budget.test.ts`, and every other test pass unchanged.

## Details

`osq status` reads each active change's `proposal.md`, so
`openspec/changes/001-broken/proposal.md` made as a directory makes it fail
with `EISDIR`. None of these failures reads or writes the home directory.

`runCli` now sets `process.exitCode`, and a test file whose process ends with
`process.exitCode` at 1 fails. So every test that runs `runCli` restores the
previous value, as `runCliCaptured` does.
