## Changed

- `src/cli/check.ts`: removed the `exitOne` helper; the `runCheck` rejection now `throw new CommandError(\`Error running check for ${specId}:\n  ${message}\`)`, and a non-zero or timed-out check after `printCheckResult` now `throw new CommandError('')`, so stdout is unchanged and stderr stays empty.
- `src/cli/verified.ts`: removed the `exitOne` helper; the flag refusal now throws `new CommandError('Error: specify exactly one of --passed or --failed.')` and a `recordVerification` rejection throws `new CommandError(\`Error recording verification for ${specId}:\n  ${message}\`)`. Messages are byte-for-byte the same as before.
- `tests/verification-record.test.ts`: `captureExitAndLogs` no longer replaces `process.exit`; it catches a `CommandError`, sets `exitCode` to the error's `exitCode`, appends the message to `lines` only when non-empty, and rethrows anything else. Added the `CommandError` import. Test titles and assertions are unchanged.
- Added `tests/command-error-verification.test.ts`: runs `runCliCaptured` and asserts the failed-check scenario (stdout has `Exit code: 3` and a `Next:` line, no stderr, exit 1) plus the three single-stderr-line refusals for `check 999`, `verified 999`, and `verified 999 --passed`.
