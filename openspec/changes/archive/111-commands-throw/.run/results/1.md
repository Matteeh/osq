## Changed

- Added `src/cli/command-error.ts` with `CommandError`, named `CommandError`, `exitCode` defaulting to 1, and optional `next`.
- `src/cli/run.ts`: catches `CommandError`, prints a non-empty message to stderr, prints `Next: <next>` to stdout when set, and sets `process.exitCode` without ending the process; the `ConfigLoadError` branch now sets `process.exitCode = 1` instead of `process.exit(1)`. Other errors still propagate. No `process.exit(` remains.
- `src/cli/status.ts`, `src/cli/show.ts`, `src/cli/report.ts`: each `console.error(...); process.exit(1);` (including show's empty-id check) is now `throw new CommandError(...)` with byte-identical text.
- Added `tests/cli-capture.ts` exporting `runCliCaptured`, `CliCapture`, and `CliLine`; it captures stdout/stderr lines, reads `process.exitCode`, makes `process.exit` throw, and always restores cwd, exit code, console methods, and `process.exit`.
- `tests/cli-config-errors.test.ts`: only `runInProject` changed; it now reads `process.exitCode` and no longer stubs `process.exit`. Test titles and assertions are unchanged.
- Added `tests/command-error.test.ts` covering the show refusal, empty show id, bad `--since`, an `EISDIR` status failure, and the caller-carries-on `CommandError` path.
