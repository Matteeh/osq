## Changed

- `src/cli/approve.ts`: the empty-ids check now throws `new CommandError('Error: specify at least one spec ID to approve (e.g. osq approve 001)')`; the no-terminal branch of the `review` callback throws `new CommandError(refusalMessage(specId, digest))`; and the per-id `catch` first rethrows a `CommandError` untouched, otherwise computes `formatNextStep(await readNextStep(...))` when `findChange` and `readNextStep` succeed and throws `new CommandError(\`Error approving ${specId}:\n  ${message}\`, { next })`. It prints nothing and no longer calls `process.exit(`. Byte-for-byte messages and order are unchanged through `runCli`.
- `tests/approve-confirm.test.ts` and `tests/plan-approve-next-step.test.ts`: only `captureExitAndLogs` changed. It no longer stubs `process.exit`; it catches the `CommandError`, sets `exitCode` from it, appends a non-empty message, then a `Next: <next>` line when `next` is set, and rethrows anything else. Imported `CommandError`. Every test title and assertion is untouched.
- Added `tests/command-error-approve.test.ts`: drives `runCliCaptured` for the template approval (exit 1, `Error approving <id>:` on stderr, last line `Next: unplanned — osq plan <id>` on stdout), the error-before-next ordering, the missing change (one stderr line, no `Next:`), the several-ids stop at the first failure, and the `--confirm` refusal staying unwrapped.
- Added `tests/cli-no-process-exit.test.ts`: recursively reads every `.ts` file under `src/cli/` and fails, naming each offender, when any contains `process.exit(`.

## Deviated

- In the several-ids test, the successful follow-up `osq approve <id>` leaves `process.exitCode` unset (`undefined`) rather than 0, since `runCli` only assigns an exit code on failure. The assertion treats `undefined` as 0, matching real process semantics; the acceptance line's "exits with code 0" is preserved.
