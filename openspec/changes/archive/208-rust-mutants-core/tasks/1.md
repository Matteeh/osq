## Acceptance

- [ ] New `scripts/mutants-rust.sh`, a POSIX `sh` script in the style of `scripts/verify-rust.sh`, runs `cargo mutants --workspace` from the repository root with `--jobs "${OSQ_MUTANTS_JOBS:-4}"` and `--output` set to a folder made with `mktemp -d`, removed by an `EXIT` trap. With one argument it adds `--in-diff <file>`, with the path resolved from the caller's directory before the script changes directory. It exits with cargo-mutants' status, so a missed mutant (2), a timeout (3) or failing unmutated tests (4) fail it.
- [ ] Given an empty diff file, or one that touches no `.rs` file, the script exits 0 without testing a mutant; cargo-mutants 27.1.0 does this itself, printing `Diff file is empty` or `Diff changes no Rust source files`.
- [ ] New `.cargo/mutants.toml` holds a comment naming ADR 024 and saying that an `exclude_re` entry is allowed only for a mutant shown to be equivalent, with a comment saying why, and the line `exclude_re = []`. Use only keys cargo-mutants 27.1.0 accepts; it rejects unknown keys, and `jobs` is not one.
- [ ] New `crates/core/tests/display.rs` proves "Read error messages", "Task id text" and "Seal and seal error text", taking every text from the scenario tables.
- [ ] New `crates/core/tests/edges.rs` proves "Task ids with one number sort by text", "Done clears an earlier reason", "Task regressions and retries leave the change record" and "A change keeps its id and tasks".
- [ ] `sh scripts/mutants-rust.sh` exits 0: no missed mutant and no timeout. The 11 mutants it missed before are `Change<S>::id` (twice) and `Change<S>::tasks` in `change.rs`, the `Display` impls of `EventError`, `Seal`, `SealError` and `TaskId`, the two match guards in `apply_change`, the `left != right` guard in `<TaskId as Ord>::cmp`, and the deleted `reason` field in the `Done` arm of `apply_task`.
- [ ] No file under `crates/core/src/` changes, no preexisting test changes, and `sh scripts/verify-rust.sh` passes.

## Details

Each test follows the crate's style in `crates/core/tests/fold.rs` and
`crates/core/tests/gates.rs`: a doc comment saying what it proves, then a
`Covers: rust-core/<scenario>` line in kebab-case, one test per scenario, and a
one-line doc on every helper. A table scenario loops over its rows and names
the row in the assertion message. The sort test sorts the ids in the order the
scenario gives them, since a sort that treats `2a` and `2b` as equal keeps
them in input order.

A full run takes a few minutes with four jobs; most of it is the test suite,
which each mutant runs once. cargo-mutants copies the tree to a temporary
folder and builds there, so `--output` keeps `mutants.out` out of the
repository. If a mutant outside the 11 is missed, it is a test gap too: add a
test for it in the same two files, and say so under `## Deviated`.
