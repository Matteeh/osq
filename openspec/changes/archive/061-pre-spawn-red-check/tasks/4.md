## Acceptance

- [ ] For a task whose `events` hold a `verify_ran` event with `data.phase` `pre_spawn`, `formatSpecDetails` prints `      Pre-spawn verify: exit <exitCode>, expected <expected>, <matched|mismatch>` directly after that task's `Verify:` line. It uses the latest such event, and `mismatch` when its `data.mismatch` is true.
- [ ] A task with no pre-spawn event prints no such line, so output for every existing show fixture is unchanged.
- [ ] A missing or non-numeric exit code prints `exit unavailable`, and a missing `expected` prints `expected unavailable`.
- [ ] A new `tests/show-pre-spawn.test.ts` drives `osq show` on a change whose task event stream holds a pre-spawn `verify_ran` with `mismatch: true`, then a later post-spawn `verify_ran`. It asserts the line reads `mismatch` and the timeline still lists both events. A second task with a matching pre-spawn event reads `matched`.

## Details

Build the line from the task's existing `TaskDetail.events` inside
`formatSpecDetails`, using a small helper. Do not add a field to `TaskDetail`,
which the web data layer also reads. `buildSpecDetails` and
`formatSpecDetails` are grandfathered in the function budget, so keep the
helper outside them. Set up the change the way `tests/show.test.ts` does,
writing the event lines directly into `.run/events/<n>.jsonl`. Every existing
test is frozen.
