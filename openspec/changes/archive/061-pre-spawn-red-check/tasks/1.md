## Acceptance

- [ ] `GatesConfig` gains an optional `preSpawnVerify` of type `PreSpawnVerifyMode` (`'warn' | 'fail' | 'off'`, exported from `config-gates.ts`). `DEFAULT_GATES_CONFIG` sets it to `'warn'`. `defineConfig({})` resolves `warn`, `defineConfig({ gates: { preSpawnVerify: 'fail' } })` keeps `fail` and `changeVerifyAfterTask: true`, and any other value throws an error naming `gates.preSpawnVerify`.
- [ ] `parseTaskMd` returns `verifyStarts`, typed `'red' | 'green' | 'any'`: `green` or `any` when the frontmatter `verify_starts` says so, `red` when the key is absent or holds any other value.
- [ ] In `tests/archive-verification.test.ts`, the `verifyRanEvents` helper also drops events whose `data.phase` is `pre_spawn`. In `tests/runner-test-gating.test.ts`, every check for a `verify_ran` event also ignores events whose `data.phase` is `pre_spawn`. In `tests/retry-watch.test.ts`, the written `osq.config.ts` adds `gates: { preSpawnVerify: 'off' }`. No other assertion in those three files changes.
- [ ] New tests for the first two lines live in `tests/pre-spawn-config.test.ts`.

## Details

This task prepares the ground; nothing reads the new values yet. Task 2 adds a
pre-spawn `verify_ran` event carrying `phase: "pre_spawn"` on every first
attempt. The three test edits keep those files about what they already test:
archive verification counts post-spawn verify runs, the test-gating file checks
that the post-spawn gate is never reached, and the retry test's verifier fails
once and then passes, so a pre-spawn run would use up its one failure. Those
edits are harmless today because no event carries a `phase` yet.

Keep `preSpawnVerify` optional in the `GatesConfig` type. Several existing
tests build `gates: { changeVerifyAfterTask: false }` objects typed as
`OsqConfig`, and a required field breaks their typecheck. Follow the style of
the existing `changeVerifyAfterTask` check in `validateGatesConfig`, and update
its "boolean gates" object error so it no longer claims every gate is boolean.
Model the parser field on `readTestsModify`. Do not add a lint rule.
