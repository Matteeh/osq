## Acceptance

- [ ] `observeTaskStream` counts `verify_ran` events whose `data.phase` is `pre_spawn` as pre-spawn runs, and those with `data.mismatch === true` as mismatches. Such events no longer enter `verifyCodes`, so `history.verifyRuns` totals, missing exit codes, and per-task codes exclude them.
- [ ] `HistoryMetrics` gains `preSpawnVerify: { runs, mismatches, mismatchedTasks }`. `mismatchedTasks` lists the change-and-task references (the same form as `verifyRuns.byTask` keys) of tasks with at least one mismatch, sorted.
- [ ] The text report prints `  Pre-spawn verify mismatches: <mismatches> of <runs> runs` right after the `Verification runs missing exit code:` line.
- [ ] `osq report --json` (`toStableMetrics`) emits `history.preSpawnVerify` with the same three keys. `fixture/report/expected.json` gains that key with zero counts and an empty list, and nothing else in it changes.
- [ ] In `tests/report-json.test.ts` and `tests/report-scope-regressions.test.ts`, only the expected history key lists and hand-built `MetricsReport` objects change, to include `preSpawnVerify`.
- [ ] A new `tests/report-pre-spawn.test.ts` builds task streams with two pre-spawn runs (one mismatch), one post-spawn `verify_ran`, and one `started`. It asserts runs 2, mismatches 1, the mismatched task reference, `verifyRuns.total` 1, and attempts 1. `observeTaskStream` stays within the 80-line function budget.

## Details

`observeTaskStream` is already near 80 lines. Count pre-spawn events in a small
helper next to it instead of growing its body. Build the new test's streams the
same way `tests/report-history.test.ts` does. The report fixture under
`fixture/report/` has no pre-spawn events, so only the new key with zero values
appears in `expected.json`. Measuring this change showed four failing tests in
`tests/report-json.test.ts` and one in `tests/report-scope-regressions.test.ts`,
all from the new history key. Change no other preexisting test.
