  `MANAGED_PLANNER_BLOCK` stating that the watcher runs each task's `verify` once
  before the first attempt and expects it to fail, and that a task that should

    (`red` default, `green`, `any`), `gates.preSpawnVerify` (`warn` default, `fail`,

  - The dead-reasons sentence now lists `verify_precondition`.
  - The files-list line for `tasks/1.md` now names `verify_starts`.
- `tests/pre-spawn-docs.test.ts` (new): asserts README mentions

  `MANAGED_PLANNER_BLOCK` contains `verify_starts: green`.

## Deviated

- The new planner bullet is three lines, and to keep `MANAGED_PLANNER_BLOCK` at
  its original 74 lines I reflowed three existing `### Tasks` bullets (scope/verify,
  real-entry-point, re-runnable) from four lines to three without changing any
  words. Reason: `tests/golden-events.test.ts` pins `repoLines` in
  `tests/fixtures/events/{verified,dead}.jsonl` to the line count of the
  scaffolded `PLANNER.md` (generated from `MANAGED_PLANNER_BLOCK`). Adding lines
  raises that count and fails the fixture, and those fixtures lie under
  `tests/**`, so with this task's `tests.modify: false` and no test path in
  `scope` the watcher's pre-spawn test gate forbids editing them. Keeping the
  block line-count neutral passes `pnpm verify` without touching any frozen
  fixture. All asserted substrings survive the rewrap.
