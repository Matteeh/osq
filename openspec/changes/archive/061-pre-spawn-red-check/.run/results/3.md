## Changed

- `observeTaskStream` now routes each `verify_ran` event through a new `recordVerifyRun` helper that counts `phase: "pre_spawn"` runs and `mismatch: true` mismatches into `preSpawnRuns`/`preSpawnMismatches`, while only non-pre-spawn events enter `verifyCodes`. The helper keeps the function within the 80-line budget.
- `HistoryMetrics` gains `preSpawnVerify: { runs, mismatches, mismatchedTasks }` (`PreSpawnVerifyHistory`); `getMetricsReport` aggregates the per-task observation and collects sorted mismatched task references in `change/task` form.
- Text report prints `  Pre-spawn verify mismatches: <mismatches> of <runs> runs` immediately after the missing-exit-code line.
- `toStableMetrics` emits `history.preSpawnVerify`; `fixture/report/expected.json` gains the key with zero counts and an empty list.
- Updated only the expected history key lists and hand-built `MetricsReport` objects in `tests/report-json.test.ts` and `tests/report-scope-regressions.test.ts`.
- Added `tests/report-pre-spawn.test.ts` covering two pre-spawn runs (one mismatch), one post-spawn `verify_ran`, and one `started`: runs 2, mismatches 1, mismatch task `001-pre-spawn/1`, `verifyRuns.total` 1, attempts 1, plus the text line.

## Deviated

- `report-events.ts` grew past the 250-line source budget after the additions, so a few existing doc comments in the same file (top-of-file, `parseTokenEvent`, `observeAttempts`) were compacted without changing behavior, and the unused `PreSpawnVerifyObservation` interface was dropped. The file now sits at 248 lines.
