## Changed

- `src/core/status/show.ts`: added a small `formatPreSpawnVerify(events)` helper
  outside the grandfathered `buildSpecDetails`/`formatSpecDetails` functions. It
  finds the latest `verify_ran` event whose `data.phase` is `pre_spawn` and
  renders `      Pre-spawn verify: exit <code>, expected <state>, <matched|mismatch>`,
  using `exit unavailable` for a missing/non-numeric exit code and
  `expected unavailable` for a missing/blank expected state. `formatSpecDetails`
  pushes that line directly after each task's `Verify:` line only when it exists,
  so tasks without a pre-spawn event keep their previous bytes.
- `tests/show-pre-spawn.test.ts` (new): drives `showCommand` on a change with
  four tasks. Task 1 has an earlier matching pre-spawn run, a later mismatching
  one, and a post-spawn `verify_ran`; it asserts the printed line reads
  `mismatch` from the latest pre-spawn event, sits directly after `Verify:`, and
  that the timeline still lists all three runs. Task 2 reads `matched`, task 3
  renders both values unavailable, and task 4 (post-spawn only) prints no line.
