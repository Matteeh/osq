## Changed

- `src/core/report/stream-index.ts` (new): the `StreamIndex` port and
  `openStreamIndex`. It loads `node:sqlite` with a dynamic `import` and resolves
  to null when that fails. It creates `<projectRoot>/.osq/`, writes
  `.osq/.gitignore` holding `*` when missing, and opens `.osq/index.sqlite`
  with `timeout: 0` in WAL mode. The `meta` table holds the schema version and
  `streams` holds path, size, mtime and events JSON; another schema version
  drops and recreates `streams`, and a non-SQLite file is deleted with its
  `-wal`/`-shm` side files and recreated once, else null. `lookup` matches path,
  size and mtime, `store` upserts a path, and `close` deletes rows for files the
  session never looked up that no longer exist, then closes. No method throws.
- `tests/report-index-store.test.ts` (new): covers every acceptance line in a
  temporary project, including the WAL/schema shape, corrupt-file replacement,
  a recreate failure, the three `close` cases, and a second `DatabaseSync`
  holding `BEGIN IMMEDIATE` while `store`/`close` give up and `lookup` reads.

## Deviated

- Followed the `close` requirement literally: it deletes a row only when the
  path was not looked up this session **and** the file is missing, so a row for
  a path `lookup` was called with is retained even if its file is gone. The
  third `close` test pins that behavior.

## Missing context

- The acceptance does not say whether a schema-version mismatch should `DELETE`
  the rows or drop and recreate the `streams` table. I dropped and recreated to
  also survive a changed column layout, and tested with a stored row.
