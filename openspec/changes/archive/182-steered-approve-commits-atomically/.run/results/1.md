## Changed

- `src/core/vcs/git-vcs.ts`: `childGitEnv` now sets `GIT_OPTIONAL_LOCKS=0` in the child environment after removing `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE`, so every git call `GitVcs` makes (all through `runGit` → `childGitEnv`) never writes the index or holds `index.lock` while another osq process commits in the same tree. No caller changed. File stays at 249 lines (`split('\n').length`), under the 250 budget.
- `tests/vcs-optional-locks.test.ts` (new): a plain `node:test` case proving version-control "Status leaves the index alone". It builds a temporary repository with its own `git init` and commit, moves `a.txt`'s modification time one minute ahead with `fs.utimes`, reads the bytes of the file `git rev-parse --git-path index` names, then calls `status()` on `selectVcs(root, config)` with `vcs.enabled` on. Status is empty and the index bytes are unchanged; a final plain `git status` in the same state is asserted to rewrite the index, so the test fails without the change. The test's own git calls strip `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE` as `cleanGitEnv` in `tests/recovery-support.ts` does.
