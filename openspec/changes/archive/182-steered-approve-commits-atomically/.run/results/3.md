## Changed

- `src/core/lifecycle/retry-plan-edits.ts` (new): `assertPlanCommitted(projectRoot, specId, config)` as watcher-and-harness "Retry refuses uncommitted plan edits" says. It finds the change with `findChange` and returns without effect when `findChange` throws, so `retrySpec` still reports a missing change with its own message. It treats the change as in a worktree when `change.tree.worktreeFolder` is set, reads status through `selectVcs(change.tree.root, config)`, and returns for `NoVcs`. The check walks both `path` and `from` of each status entry, as `worktreeDirt` in `src/watcher/worktree-run.ts` does, keeps only entries inside the change folder other than its `tasks.md` and anything under its `.run/`, and reports them relative to the change folder, sorted. It throws `Change <id> has plan edits not committed in its worktree: <paths>. Run osq approve <id> to approve them.` with the folder-derived id, and writes nothing.
- `src/cli/retry.ts`: `retryCommand` calls `assertPlanCommitted(inputs.cwd, specId, config)` inside its existing `try`, before `retrySpec`, so a refusal reads `Error retrying <id> <target>:` then the message. `retrySpec` is unchanged. Both carry `@scenario watcher-and-harness: Plan edits not committed`.
- `tests/retry-plan-edits.test.ts` (new): plain `node:test` cases proving every row of "Plan edits not committed" through `project.retry('1')` from `createRecoveryProject`, with a task that dies `verify_red` while `autoRetries` is 0, as `tests/recovery-dead-retry.test.ts` does. Each case writes the row's edits into `project.changeFolder` before the retry: changed `tasks/1.md` and `proposal.md` refuse naming both, a new untracked `tasks/2.md` refuses naming it, a ticked `tasks.md` retries 0 with `.run/dead/1.md` kept as `.run/dead/1.1.md`, and no edits retry 0 the same way.

The task verify (`node --import tsx --import ./tests/git-test-env.ts --test tests/retry-plan-edits.test.ts`) and the proposal verify (`pnpm verify`) both pass.
