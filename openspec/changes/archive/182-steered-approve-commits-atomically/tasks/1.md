## Acceptance

- [ ] `childGitEnv` in `src/core/vcs/git-vcs.ts` sets `GIT_OPTIONAL_LOCKS` to `0` after it removes `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE`. Every git call `GitVcs` makes goes through it, so no caller changes.
- [ ] `src/core/vcs/git-vcs.ts` stays at or under 250 lines (`tests/line-budget.test.ts` counts `split('\n').length`).
- [ ] New `tests/vcs-optional-locks.test.ts` proves version-control "Status leaves the index alone". It builds a temporary repository with its own `git init` and commit, moves `a.txt`'s modification time one minute ahead with `fs.utimes`, takes the bytes of the file that `git rev-parse --git-path index` names, then calls `status()` on `selectVcs(root, config)` with `vcs.enabled` on. Status is empty and the index bytes are unchanged. Plain `git status` in the same state rewrites the index, so the test fails without the change.
- [ ] The test's own git calls strip `GIT_DIR`, `GIT_INDEX_FILE` and `GIT_WORK_TREE`, as `cleanGitEnv` in `tests/recovery-support.ts` does. Use a plain `node:test` case: the `scenario()` helper cannot look up version-control scenarios.
