## Acceptance

- [ ] `approveSteeredChange` follows spec-lint-and-approve "Approval after steering". Before `appendObservedSessions`, it keeps the bytes of the worktree folder's `.run/approved`, `.run/manifest.json` and `.run/plan.jsonl`, or that each is absent. When `vcs.commit` throws, it puts each file back, deleting one that was absent, retires no trigger, and throws the error the requirement gives, with the commit error's message as `<git error>`.
- [ ] Before rolling back, it reads `vcs.show('HEAD', '<change folder>/.run/approved')`. When that holds the new hash, the commit landed: it keeps the seal files and goes on to `retireSteering`. Put this decision in an exported helper in `src/core/spec/approve-seal-restore.ts` that takes an object with only a `show` method. The same test file covers it directly with plain objects: `show` returning the new hash plus a newline means keep, while returning the old hash or null means roll back. Do not add a `Vcs` injection seam to `approveSteeredChange`.
- [ ] The keep-and-restore helpers live in new `src/core/spec/approve-seal-restore.ts`, so `approveSteeredChange` stays under the 80-line function budget (`tests/function-budget.test.ts`). The successful path is unchanged.
- [ ] New `tests/approve-steer-commit-failed.test.ts` proves "Approved commit fails" with `createRecoveryProject`, `ScriptedAdapter` and `reviseTask` from `tests/recovery-support.ts`. Reach the stuck task as `tests/recovery-stuck-steer.test.ts` does. Create the file that `git rev-parse --git-path index.lock` names in `project.worktree` (resolved against the worktree) before `project.approve()`, and check every THEN clause. Remove the lock in a `finally`.
- [ ] Use a plain `node:test` case: the `scenario()` helper cannot look up spec-lint-and-approve scenarios.
- [ ] `approveSteeredChange` carries `@scenario spec-lint-and-approve: Approved commit fails` beside its existing tags.
