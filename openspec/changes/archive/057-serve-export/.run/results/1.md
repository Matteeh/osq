- Added `src/core/web/web-export.ts`. `exportDashboard({ projectRoot, config, targetDir, uiDir?, home?, now? })` refuses a missing-entry target that is a file or a non-empty directory (naming the resolved directory) before any write, creates a missing target, copies the built UI, writes `data.js` as `window.__OSQ_DATA__ = <serialized>;`, and rewrites the copied `index.html` with `<script src="./data.js"></script>` immediately before its first `<script`. It composes `report`, `graph`, `inbox`, and every graph change (keyed by folder key and padded id prefix) through `getMetricsReport`, `getWebGraph`, `readInbox`, and `getWebChange`, reuses `serializeWebJson` for stable output, scrubs `projectRoot` to `.` then `home` to `~` in every nested string, and returns the sorted written file paths.
- `packages/ui/vite.config.ts` now sets `base: './'`, so the built `index.html` references `./assets/...`.
- `tests/package-install-smoke.test.ts` fingerprinted-asset match now accepts `src="./assets/..."` while still fetching the asset relative to the served URL and asserting a 200 JavaScript response. No other change.
- Added `tests/web-export.test.ts`: exports a fixture with an active, an archived, and a rejected change (unique id prefixes) into a temp directory with a stub `uiDir`; asserts the report, graph, and inbox documents and both keys per change, a task result scrubbed from the absolute project path and a fake home, no absolute project or home path in any written file, `data.js` inserted before the first script, refusal of a non-empty target with an unchanged directory, and that the staged `ui/dist/index.html` uses relative asset paths.
