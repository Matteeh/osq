## Acceptance

- [ ] `osq serve` accepts `--export <dir>`. `serveCommand` takes an optional `exportDir`, and when it is set, calls `exportDashboard` with the loaded config and returns without starting a server or launching a browser.
- [ ] On success it prints `exported dashboard to <dir>`, then `scrubbed: project root and home directory paths only; read the export before publishing`, and exits 0.
- [ ] A refused or failed export prints the error message and sets exit code 1.
- [ ] Without `--export`, `serveCommand` behaves and prints as before, and `--port` and `--open` are unaffected. With `--export`, `--open` and `--port` are ignored.
- [ ] `README.md` documents `osq serve --export <dir>` next to `osq serve` in the command list. It adds one sentence saying the snapshot needs a static host, cannot open from `file://`, and scrubs only the project root and home paths.
- [ ] New `tests/serve-export.test.ts` covers export success output and the absence of a server, refusal of a non-empty directory, and an unchanged serve path. It injects `stdout` and uses a stub `uiDir`.
- [ ] The task's verify command passes.

## Details

This task's `scope` is authoritative over any injected code-ownership rules.

the option in the existing `serve` command in `src/cli/index.ts` with
commander's `.option('--export <dir>', ...)`. Resolve `<dir>` against the
current directory.
