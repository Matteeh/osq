# Task 4 — Unrecognised stream events route to verbose logging

## Changed

- `src/harness/opencode.ts`
  - Removed `console.debug` from the fall-through at the end of `processOpencodeStdoutLine`.
  - Unrecognised event types now emit `logger?.verbose(`[opencode] Unknown event type: ${eventObj.type}`)`. No stdout/stderr write happens outside the leveled logger.
- `src/harness/agy.ts`
  - Malformed/non-JSON stdout lines now log `logger?.verbose(`[agy] Unrecognised stream line: ${trimmed}`)` instead of returning silently.
  - A parsed value that is not an object also logs the unrecognised-line diagnostic.
  - Events with no `result`, no tool step, and no `step_update` log `logger?.verbose(`[agy] Unknown event type: ${eventObj.event ?? eventObj.type ?? 'unknown'}`)`.
  - `step_update` events that simply carry no usage stay silent (recognised shape, no diagnostic).
- `src/watcher/runner.ts`
  - `recordLifecycleEvent` gained an explicit `level: 'info' | 'verbose' = 'info'` parameter. This keeps `started` at info (required by the curated-log contract) while allowing `exited` to demote.
  - The `exited` call passes `'verbose'`.
  - Result synthesis changed `logger?.info('task <n> result synthesized …')` to `logger?.verbose(...)`.
  - All `appendHarnessEvent` calls are untouched, so `started`/`exited`/`result_written`/`done`/`dead` persistence in `events.jsonl` is byte-for-byte unchanged.
- `tests/stream-unrecognised-events.test.ts` (new, 7 tests)
  - Captures both `process.stdout.write` and `process.stderr.write`, and asserts zero stdout for every unrecognised path.
  - opencode: unknown type at verbose (`[opencode] Unknown event type: step_start`), silent at normal, and `console.debug` never invoked.
  - agy: unknown event and malformed line route to `[agy]` verbose lines; silent at normal.
  - Unrecognised events append nothing to `.run/events/<n>.jsonl`.
- `tests/runner-lifecycle-logging.test.ts`
  - The exited-summary test and the "same code path" test now use `createLogger('verbose')`.
  - Added a test asserting the started line still appears at `normal` while `task <n> exited` does not, and that the `exited` event is still persisted.
- `tests/runner-synthesized-result.test.ts`
  - The synthesis case now uses `createLogger('verbose')` so it can assert the demoted line.

## Deviated

- **`recordLifecycleEvent` level parameter instead of an unconditional demotion.** The task detail said to change `logger?.info(summary)` to `logger?.verbose(summary)` inside `recordLifecycleEvent`, but that helper logs both `started` and `exited`. Demoting the shared helper would also demote the task-start line, contradicting the spec contract ("Task start … log at info") and the untouched `started` assertion. I added an explicit `level` argument so only the `exited` call demotes. Acceptance line 3 (exited → verbose) and the info-level `started` contract are both satisfied.
- **`agy` malformed lines are logged at verbose.** This follows acceptance line 2 and the task detail ("unrecognised stream events or malformed lines"). `opencode` malformed lines were left silent because the detail for `opencode` only names unknown event types, and no acceptance line requires logging them.

## Drift against `features/`

None for the changed sources: this implements the `watcher-and-harness.md` "Stream Event Routing" and "Runner log level demotions" delta and invariant 4.
