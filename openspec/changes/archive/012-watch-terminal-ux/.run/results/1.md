# Task 1 — Logger status row

## Changed

- `src/core/logger.ts`
  - Extended `Logger` with `status(text: string): void` and `clearStatus(): void`.
  - Added `LoggerOptions { stream?; isTTY? }` and `createLogger(level, prefix?, options?)`.
  - Default sink is still `process.stderr`; all writes now go through the injected `stream`.
  - Interactive detection: `(options?.isTTY ?? stream.isTTY) === true && level !== 'quiet' && !process.env.CI`. When false, `status()`/`clearStatus()` are pure no-ops with zero escape output.
  - Spinner: 10 unicode frames, `setInterval(..., 80)` with `timer.unref()`.
  - `status(text)` renders `\r\x1b[2K<frame> <prefixed-text>`; subsequent animation ticks redraw with the next frame.
  - Any emitted log line (`info`/`verbose`/`warn`/`error`) while a status is active writes `\r\x1b[2K` + formatted line (trailing `\n`) + redraw below. Suppressed (level-filtered) messages leave the status untouched.
  - `clearStatus()` writes `\r\x1b[2K`, clears the interval, resets frame index and status state.
- `tests/logger-status.test.ts` (new)
  - Fake `Writable` streams with `isTTY` toggled plus a hand-rolled fake `setInterval`/`clearInterval` harness that records the 80ms delay and asserts `unref()` was called and allows manual ticks.
  - Exact byte-sequence assertions for TTY clear/log/redraw, multi-line prefixing, animation ticks, clearStatus, `isTTY` override, non-TTY no-op, `CI` no-op, and quiet no-op.
