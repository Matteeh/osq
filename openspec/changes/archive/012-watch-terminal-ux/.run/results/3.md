# Task 3 — Running status row with live counters

## Changed

- `src/watcher/runner.ts`
  - `TaskHeartbeatStats` gained `toolCount`, optional `cost`, and `lastToolSummary`.
  - `computeTaskHeartbeatStats` now maintains an in-memory accumulator per event file (`heartbeatAccumulators`), advancing a byte offset and parsing only newly appended complete lines. Counts `tokens` totals/cost and `tool` counts/last summary. Partial (not-yet-newline-terminated) lines are left for the next poll, so an event is never double counted. Missing files reset the accumulator to zero.
  - Added `clearTaskHeartbeatStats(specFolderPath, taskNumber)`, called from `runTask`'s `finally`, so counters do not leak across watcher cycles.
  - Added pure formatters:
    - `formatTaskStatusRow(taskNumber, stats, terminalWidth?)` — `task <n> · <elapsed>s · <tools> tools · <tokens> tokens [· $cost] [· summary]`. Reserves 2 columns for the logger's `<frame> ` prefix and truncates the summary with `…` so the whole row fits `process.stderr.columns ?? 80`.
    - `formatTaskHeartbeatLine(taskNumber, stats)` — preserves the existing `task <n> heartbeat (elapsed: …, events: …, tokens: …)` shape.
    - `formatTaskStartedLine(taskNumber, title, pid, timeoutSeconds, symbols, terminalWidth?)` — single info line carrying the truncated title plus pid/timeout.
    - `formatTaskOutcomeLine(taskNumber, success, reason, elapsedSeconds, symbols)` — `✓ task <n> verified (elapsed: Xs)` / `✗ task <n> dead (reason: …, elapsed: Xs)` with `[ok]`/`[dead]` word fallbacks.
  - `runTask` now owns a single timer. TTY (`logger.interactive`) ticks at `min(heartbeatSeconds, 1s)` and calls `logger.status(formatTaskStatusRow(...))`, logging the heartbeat via `logger.verbose` every `heartbeatSeconds`; non-TTY ticks at `heartbeatSeconds` and logs the heartbeat at `info`. Both paths call the same `computeTaskHeartbeatStats`.
  - `logOutcome` stops the heartbeat, clears the status, and logs the curated outcome line. It is called on every exit path (spec_conflict ×2, crashed task file, already_running, timeout/crashed, no_result, verify_red, success).
- `tests/runner-terminal-status.test.ts` (new, 13 tests)
  - Pure `formatTaskStatusRow` field/truncation tests; `computeTaskHeartbeatStats` counter and incremental-accumulation tests.
  - Started-line width test; verified/dead outcome tests.
  - End-to-end fake-binary tests: a real on-disk OpenCode script parsed by the real `OpencodeAdapter` emits a `tool_use` and a `step_finish` (150 tokens, `$0.0123`). A fake TTY stream asserts the rendered status row (spinner frame, tool count, tokens, cost, summary); a non-TTY run asserts the heartbeat log; TTY normal vs verbose loggers assert the info→verbose demotion.

## Deviations

- **Task-started line keeps the lifecycle details.** The task detail pinned `▶ task <n> started: <title>`, but `tests/runner-lifecycle-logging.test.ts` (out of scope, untouched) asserts `task <n> started (pid: …, timeout: …s)` at info. To satisfy both, the title is appended: `▶ task <n> started (pid: …, timeout: …s): <truncated-title>`. Single info line, title truncated to width, lifecycle assertion intact.
- **Curated outcome line is additional.** `formatTaskOutcomeSummary` (`task <n> verified (passed)` / `task <n> dead (reason: …)`) and its exact-equality tests in `tests/runner-outcome-logging.test.ts` are out of scope, so the new elapsed-bearing line is emitted alongside the existing summary line rather than replacing it. The curated line always starts with the symbol/word tag, so the existing `outcomeLine` helper still selects the summary line.
- TTY status cadence uses `min(heartbeatSeconds, 1000)` rather than a hard 1000ms, so the 1s default holds while tests can shrink the tick via `log.heartbeatSeconds`. This is the "polling interval capped at 1s" from the acceptance line.

## Drift against `features/`

Implements the `watcher-and-harness.md` "Task Execution/status counters" and "Runner log level demotions" deltas: shared `computeTaskHeartbeatStats` feeds both the 1s TTY row and the non-TTY heartbeat, task start carries a truncated title, outcome carries reason+elapsed, and TTY heartbeats demote to verbose. `exited` and synthesized-result demotions remain for task 4 (its scope lists `runner.ts` and the lifecycle/synthesized tests), and were deliberately left at info here.
