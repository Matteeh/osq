## Details

Port `mergeDelta` from `src/core/spec/delta.ts` and its helpers as they
are: `validateDelta`, `buildSpecSkeleton`, `extractRequirementsSection`,
`parseBlocks`, `applyRenames`, `applyRemovals`, `applyModifications`,
`applyAdditions`, `missingScenarioNames`, `scenarioNames`,
`collapseBlankRunsOutsideFences` and `recompose`. Keep their order of
checks and their quirks. For example, `recompose` walks the old block
order by position, and the no-heading branch of
`extractRequirementsSection` keeps the base text as given, a BOM
included. `mergeLivingSpec` from `src/core/spec/apply-deltas.ts` is
`merge_delta` followed by a check for no requirement. Read the TypeScript
for semantics only, and never import or call it.

Take the delta as parsed by `parse_delta`, and do not parse it again.
`Requirement::raw` is already the block text with normalized line endings
and no trailing whitespace. For the base text, reuse
`normalize_document`, `fence_mask`, `is_top_level_heading`,
`is_named_heading`, `js_trim`, `js_trim_end`, `requirement_header_text`
and `normalize_requirement_name` from `src/markdown/`. For scenario names,
find the `####` lines outside fences with `starts_scenario` and
`fence_mask`, and take each name from `parse_scenario` of that line, as
`scenario_name` in `src/markdown/scenario.rs` is private. All of these
are `pub(crate)` or public already. Write no second
requirement or scenario parser. Note that TypeScript's `trim` and
`trimEnd` are `js_trim` and `js_trim_end`, not Rust's own trims. Use a
`Vec` plus a name index for the block map, so iteration keeps insertion
order as a JavaScript `Map` does.

Put `MergeError` in `src/merge/error.rs`, the base split and skeleton in
`base.rs`, the delta checks and four operations in `apply.rs`, and the
write back, `merge_delta` and `merge_living_spec` in `compose.rs`. Other
files are allowed when they match `base*.rs`, `apply*.rs` or
`compose*.rs`. `src/merge/mod.rs` declares the modules and re-exports
the public items. Task 2 adds `change.rs` to it.

The fixtures are the source of truth. Copy them, and never edit them.
Tests find them from `env!("CARGO_MANIFEST_DIR")`. Read files as bytes,
or as UTF-8 text with no newline conversion, because
`no-requirements-header` starts with a BOM. More test files are allowed
when they match `tests/merging_deltas*.rs`.

Keep every `.rs` file under 250 lines and every function under 80.
Workspace lints include `clippy::pedantic` and `-D warnings`. Meet them
rather than allowing them. Keep tests in `tests/`. When the mutation step
reports a missed mutant, add a case for it. Run `cargo fmt --all` before
exiting.
