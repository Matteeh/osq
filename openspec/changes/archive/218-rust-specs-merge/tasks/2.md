## Acceptance

- [ ] `merge_change(change_dir: &Path, specs_dir: &Path) -> Result<Vec<MergedSpec>, MergeChangeError>` behaves as rust-specs "Change merge" says. `MergedSpec { capability: String, delta: PathBuf, text: Option<String> }` has public fields, and `MergeChangeError` has the variants `Read(SpecsError)` and `Merge { path: PathBuf, error: MergeError }`. Both derive `Debug`, `Clone`, `PartialEq`, `Eq` and `serde::Serialize`. `MergeChangeError` implements `Display`, naming the path, and `std::error::Error`. `tests/merging_changes.rs` proves "Change merges" and "Change merge edges", one case per table row.
- [ ] The tests prove "Differential cases", one case per table row, over `crates/kernel/specs/tests/fixtures/merge/openspec-diff/`. Each case is copied to a folder under `env!("CARGO_TARGET_TMPDIR")`, its changes are merged in order, and each text is written, or its capability folder removed, before the next change. A case's tree is compared with `expected/` path for path and byte for byte.
- [ ] `validate_merged_change(change_dir: &Path, specs_dir: &Path) -> Result<Vec<SpecFinding>, MergeChangeError>` behaves as "Merged spec validation" says, and `tests/validating_merged.rs` proves "Merged findings", one case per table row. It checks each finding's code, line and requirement, that its file is the delta's path, that its fix equals its code's, and that its message is not empty.
- [ ] `lib.rs` re-exports `merge_change`, `MergedSpec`, `MergeChangeError` and `validate_merged_change`. Every existing specs test, task 1's included, still passes unchanged.
- [ ] `sh scripts/verify-rust.sh` passes, its mutation step included: every public function's doc ends with `Implements: rust-specs/<requirement>`, every test's doc names `Covers: rust-specs/<scenario>`, and no mutant in this task's code is missed.

## Details

Put `merge_change`, `MergedSpec` and `MergeChangeError` in
`src/merge/change.rs`, and `validate_merged_change` in
`src/validate/merged.rs`. `merge_change` follows `applyOpenSpecDeltas`
in `src/core/spec/apply-deltas.ts` but writes nothing. It walks the
folders as `validate_change` in `src/validate/change.rs` does: make that
file's private `folders` and `read_text` `pub(crate)` and reuse them.
Change nothing else in that file. Merge with task 1's
`merge_living_spec`, and parse each delta with `parse_delta`.

`validate_merged_change` runs `validate_living_spec` on each merged text
and on the living text. Find the delta's header lines with
`outline::scan` from `src/validate/outline.rs`, and sort with
`sort_findings`. Pass the delta's displayed path as the `file` argument,
so the findings carry it.

The fixtures were copied by task 1. Never edit them. Tests find them from
`env!("CARGO_MANIFEST_DIR")` and compare each `file` or `path` with the
fixture path joined the same way. Write the edge cases and the
differential copies under `env!("CARGO_TARGET_TMPDIR")`, each in its own
folder. Shared helpers cannot be imported across test files, so walk the
trees in each file that needs it. More test files are allowed when they
match `tests/merging_changes*.rs` or `tests/validating_merged*.rs`.

Keep every `.rs` file under 250 lines and every function under 80.
Workspace lints include `clippy::pedantic` and `-D warnings`. Meet them
rather than allowing them. Keep tests in `tests/`. When the mutation step
reports a missed mutant, add a case for it. Run `cargo fmt --all` before
exiting.
