# Task 2 result

## Changed

Added the change-level merge and merged validation to the specs kernel:

- `crates/kernel/specs/src/merge/change.rs` (new): `MergedSpec`
  (`capability`, `delta`, `text`), `MergeChangeError` (`Read(SpecsError)`,
  `Merge { path, error }`) and `merge_change`, which walks
  `change_dir/specs` in byte order, reads each `spec.md`, merges it with
  `merge_living_spec` against `specs_dir/<capability>/spec.md`, and writes
  nothing.
- `crates/kernel/specs/src/validate/merged.rs` (new):
  `validate_merged_change`, which runs `validate_living_spec` on each merged
  text, drops each finding the living spec already has, and points the kept
  findings at the delta's `display` path and the delta's first header for the
  requirement, or line 1.
- `crates/kernel/specs/src/validate/change.rs`: made `folders` and
  `read_text` `pub(crate)` and reused them. Nothing else changed.
- `crates/kernel/specs/src/merge/mod.rs`, `src/validate/mod.rs`,
  `src/lib.rs`: declared and re-exported `merge_change`, `MergedSpec`,
  `MergeChangeError` and `validate_merged_change`.
- `crates/kernel/specs/tests/merging_changes.rs` (new): "Change merges" and
  "Change merge edges", one case per table row.
- `crates/kernel/specs/tests/merging_changes_differential.rs` (new):
  "Differential cases", one case per table row, each copied to
  `CARGO_TARGET_TMPDIR`, its changes merged in order, written or removed
  before the next, and the tree compared with `expected/` path for path and
  byte for byte (or the refusal's `Display` with `error.txt`).
- `crates/kernel/specs/tests/validating_merged.rs` (new): "Merged findings",
  one case per table row, checking each finding's file, code, line,
  requirement, fix and message.

`cargo test -p osq-kernel-specs --test merging_changes --test validating_merged`
passes, and `sh scripts/verify-rust.sh` passes. `cargo-mutants` over the new
`change.rs` and `merged.rs` (and the touched `validate/change.rs`) reported no
missed mutant.

## Deviated

- The differential test lives in `tests/merging_changes_differential.rs`
  because `tests/merging_changes*.rs` is allowed by scope and the task verify
  names only `--test merging_changes` and `--test validating_merged`; the
  differential target runs under the proposal verify's
  `cargo test --workspace`.
- For the error cases the test compares the inner `MergeError`'s `Display`
  with `error.txt`, because `error.txt` holds the `DeltaMergeError` message
  and the task requires `MergeChangeError`'s `Display` to name the path.
