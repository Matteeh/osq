## Acceptance

- [ ] New `.github/workflows/openspec-latest.yml` is named `OpenSpec latest`, and triggers on a weekly `schedule` cron and on `workflow_dispatch`.
- [ ] Its single job repeats the checkout, pnpm, Node 24, and `pnpm install --frozen-lockfile` steps from `ci.yml`. It then runs `npm install --prefix "$RUNNER_TEMP/openspec-latest" @fission-ai/openspec@latest`, leaving the lockfile untouched.
- [ ] A later step prints the latest version with `"$RUNNER_TEMP/openspec-latest/node_modules/.bin/openspec" --version`.
- [ ] The last step runs `node --import tsx --test tests/openspec-differential.test.ts` with `OSQ_OPENSPEC_BIN` set to that binary and `OPENSPEC_TELEMETRY` set to `'0'`.
- [ ] New `tests/openspec-latest-workflow.test.ts` parses the workflow with the `yaml` package and asserts every line above. It also asserts that no step runs `pnpm add`, `pnpm update`, or anything that writes `package.json` or `pnpm-lock.yaml`.
- [ ] The task's verify command passes.

## Details

This task's `scope` is authoritative over any injected code-ownership rules.
The workflow needs the network in CI, but no test runs it. The test only parses
the file. `tests/openspec-differential.test.ts` already reads `OSQ_OPENSPEC_BIN`
and names the validator version in every failure, so a red run names the
upstream version.

Pick any fixed weekly cron, for example `0 6 * * 1`. Do not change `ci.yml` or
`release.yml`.
