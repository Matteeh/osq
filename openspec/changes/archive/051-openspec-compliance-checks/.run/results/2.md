## Changed

- Added `src/core/spec/openspec-version.ts`:
  - `OPENSPEC_EXPECTED_VERSION` now lives here.
  - `classifyOpenSpecVersion(version, range)` parses a whitespace-separated
    comparator range (`>=`, `>`, `<=`, `<`, `=`, one to three numeric
    components) and classifies `pinned`, `in-range`, or `out-of-range`. The pin
    wins; an unreadable range, an unparseable version, or a prerelease is
    `out-of-range`.
  - `readOpenSpecPeerRange()` reads `@fission-ai/openspec` from
    `peerDependencies` in osq's own `package.json` via `PACKAGE_ROOT`;
    `assessOpenSpecVersion()` combines the read range with the pure classifier.
  - `formatInRangeWarning()` is the one shared warning text naming the version,
    the range, and ADR 005.
- `src/core/spec/linter.ts` re-exports `OPENSPEC_EXPECTED_VERSION` and routes the
  version through `versionFinding()`, one helper returning the single error or
  warning. Pinned passes, in-range warns, out-of-range keeps today's byte-for-
  byte error text.
- `src/core/foundation/doctor.ts`: `DoctorCheckResult` gains an optional
  `warning`; the validator check returns `ok: true, warning: true` with the
  exact in-range message, keeps `pinned 1.13.1`, and keeps the failing message
  outside the range.
- `src/cli/doctor.ts` prints `[warn] <name>: <message>` for a warning check; a
  warning does not affect `report.ok` or the exit code.
- `decisions/005-openspec-validator-peer-range.md` records the superseding
  policy, warning texts, the scheduled `OpenSpec latest` workflow, and the
  archive-folder naming rule; `decisions/README.md` indexes it. ADR 004 is
  untouched.
- `tests/openspec-version.test.ts` covers the range grammar, every
  classification, the real package.json range, `runDoctorChecks` with an
  injected in-range probe, `doctorCommand` `[warn]` output with exit code, and
  `lintChangeFolder` with an in-range fake validator.

## Deviated

- The linter and doctor share one warning string. Acceptance gives the doctor
  message verbatim and requires the lint warning to name the version, the range,
  and ADR 005; using the same text satisfies both and lets ADR 005 quote it once
  verbatim.
- `OPENSPEC_EXPECTED_VERSION` moved to `openspec-version.ts` and is re-exported
  from `linter.ts` so existing importers and tests keep working. This avoids a
  linter to openspec-version import cycle.
