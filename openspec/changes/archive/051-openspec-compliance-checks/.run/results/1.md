## Changed

- Rewrote `src/core/spec/delta.ts` so the deterministic merge reproduces
  `openspec archive` 1.13.1 byte for byte for every accepted delta and refuses
  what OpenSpec refuses:
  - Requirement blocks are now carried verbatim (header + statement + every
    scenario line), so `**GIVEN**`/`**AND**` and any other line survive.
  - Fence-aware, OpenSpec-shaped section parsing and reconstruction
    (`before`/`###`/preamble/requirement raws/`after`), plus the single-blank
    collapse outside fences.
  - A new capability follows `## Purpose` with its body on the next line; a base
    spec keeps its purpose section and every byte the delta does not change.
  - RENAMED uses the `### Requirement:` form and rewrites the existing block's
    header in place.
  - `DeltaMergeError` for a MODIFIED block that drops an existing scenario, an
    ADDED name that already exists with different content, a RENAMED entry that
    is not in the `### Requirement:` form (message names that form), and an
    unmatched RENAMED/MODIFIED/REMOVED target.
- Added `tests/openspec-differential.test.ts` and `tests/fixtures/openspec-diff/`
  with ten cases: added, modified, removed, renamed (header form), new
  capability with `## Purpose`, a second change to a capability the first change
  created, GIVEN/AND bullets, dropped scenario (`both-refuse`), duplicate ADDED
  name (`both-refuse`), and bare RENAMED (`osq-refuses`). It scaffolds two temp
  repositories with the osq schema, merges with `openspec archive --yes --json`
  in one and `applyOpenSpecDeltas` in the other, runs `validate --strict` for
  accepted cases, and names `openspec <version>` in every assertion.
- Added `tests/fixtures/openspec-diff/verify.cjs` for the checked-in fixture
  verifier requirement.
- Updated `tests/delta-merge.test.ts`: header-form RENAMED, new golden output,
  and one refusal test per new `DeltaMergeError` case.
- Updated `tests/living-specs-delta-equivalence.test.ts` to drop the single
  blank line directly after `## Purpose` on both sides before comparing.

## Deviated

- The fixture proposals/tasks use `verify: node verify.cjs` rather than the
  task text's `node -e "process.exit(0)"`. `tests/linter.test.ts` rejects the
  sentinel inside `tests/fixtures/**`, so the required local `verify.cjs` and a
  deterministic command replace it. OpenSpec never executes the value.
- `tests/delta-merge.test.ts` needed two compatibility edits beyond the rename
  form and golden output, because the new parity rules refuse synthetic merges
  the old permissive engine allowed: `modifyAfterRename` now keeps the existing
  scenario name `Alpha runs`, and `readLivingSpec` excludes the requirement
  names each 017 delta ADDs so the replay does not trip the new
  ADDED-already-exists refusal. Every assertion is preserved.
- `mergeDelta`'s new-spec MODIFIED/RENAMED refusals keep the existing
  `Cannot apply MODIFIED: requirement "X" not found in base spec` wording so the
  preexisting linter assertion on the requirement name still holds; OpenSpec's
  wording differs but the behavior is identical.
- Kept osq's refusal for a REMOVED target missing from the base (OpenSpec warns
  and continues) so the existing unit assertion stays. No differential fixture
  exercises it.
