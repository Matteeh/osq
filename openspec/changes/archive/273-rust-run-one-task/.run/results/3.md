## Changed

- `run` now starts pi once with `run_task`, `PiHarness::from_config`, `SystemClock`, the executor role, no start retries, zero delays, an empty agent env and the executor prompt for attempt 1. It appends `started`, every harness event, `exited` and, when the result file predates the start by at most one second, `exit_continued`.
- Added the before/after git snapshots with a SHA-256 of every listed file, the added/deleted/modified classification, the nearest-`Cargo.toml` `tests`/`benches` folders and the Rust and TypeScript lock rules. Core's `audit_scope` decides: outside paths append `scope_violation` and die, frozen tests die as `undeclared_test_change`.
- Added the verdict: a missing result dies as `no_result`, a real `## Blocked` section as `blocked`, then the task and proposal verifies run through `run_verify` with their timeouts and kill grace, recording `verify_ran` in the task stream and `change.jsonl`. Red verifies die as `verify_red`/`change_verify_red` with the last 2000 output bytes and the command, timeout and exit-code frontmatter.
- Added the done record: `.run/done/<task>` with the UTC time and a newline, a `done` event, `tick_task_checkbox` on `tasks.md`, and the `Task <task> of <folder> done` ending. The lock is released on every outcome.
- Added `tests/fixtures/fake-pi/run.sh` with the nine outcome modes plus modes for a start timeout, frozen test deletion, an added test, a listed-path modification outside scope and Rust/TypeScript lock files. Added `tests/run_outcomes.rs` proving the six named scenarios and the timeout/tail paths.
- `crates/features/run/Cargo.toml` gained `osq-kernel-runners`, `osq-kernel-harnesses` and the workspace's `sha2`.

## Deviated

- A failed start still returns `task <task> of <folder> cannot start yet` instead of the `crashed` death the "Executor start" requirement gives a failed start. Task two left `run_passing_approval_takes_and_removes_the_lock` in `crates/features/run/tests/run_refusals.rs` asserting that exact line; that file is outside this task's scope and the task sets no `tests.modify`, so it cannot be updated. A pi process that spawns and exits non-zero still dies as `crashed`, and a timeout as `timeout`.
- The frozen-test dead marker adds ` (modified)` or ` (deleted)` after each path so a deleted frozen test is distinguishable from a modified one. The body still lists `- src/tests/old.rs` as the scenario says.

## Missing context

- The task says the run now replaces the `cannot start yet` ending task two wrote, but it does not put `crates/features/run/tests/run_refusals.rs` in scope and does not set `tests.modify`. Without that authorization the old assertion cannot be updated, which forces the failed-start deviation above.
- The scope does not name `Cargo.lock`, although adding the runner and harness crates necessarily rewrites `osq-feature-run`'s entry there.
