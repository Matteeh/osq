## Changed

- Added `RunFeature` in `crates/features/run/src/feature.rs`, exported from the crate root: name `run`, one `run` command with the required summary and usage, `FeatureError::usage` for a count other than two and `FeatureError::unknown_command` for another command, both before any file is read.
- Added the run crate's own change lookup (`find.rs`), refusal checks (`refusals.rs`, `text.rs`), lock (`lock.rs`), approval check and orchestration (`run.rs`), dead record (`dead.rs`) and fixed UTC formatter (`time.rs`).
- Refusals run in the requirement's order before any write: config, no matching active change, missing `tasks/<task>.md`, non-pi executor, root outside git, done/dead/regressed markers, then the lock. Only a taken lock decides `already_running`, without a marker.
- Passing root is the git top level itself: `GitVcs::root()` must return the canonical root, so a scratch folder whose `.git` was removed but which sits inside the enclosing repository still refuses.
- The lock is created with `create_new` and holds `{"pid":<pid>,"startedAt":<epoch ms>}`, and is removed after the approval check whatever the outcome. Until task three, a passing approval ends with the documented `task <n> of <folder> cannot start yet`.
- A missing or different approval compares trimmed `.run/approved` with `change_folder_seal`, writes TypeScript's exact `spec_conflict` dead marker, appends a typed `dead` event through `event_line`, and fails with `task <task> of <folder> died: spec_conflict`.
- Added fixture `crates/features/run/tests/fixtures/run-project/` with the approved change skeleton, task, `tasks.md`, Rust source tree and `.gitignore`.
- Added `tests/support/mod.rs` helpers for isolated committed scratch repositories, `osq.toml`, seals, trees, git status, event reads and an independent UTC formatter.
- Added `tests/run_refusals.rs` proving the three required scenarios, plus passing-approval lock removal, an unwritable lock path and fixed-time UTC rows so cargo-mutants has no missed mutant among the new sources.

## Deviated

- `Cargo.lock` was updated by Cargo because `crates/features/run/Cargo.toml` gained `osq-kernel-config`, `osq-kernel-storage` and `osq-kernel-vcs`; it is not named in the task scope.
- The git refusal checks that `GitVcs::root()` names the root itself rather than merely returning a repository, because the required `CARGO_TARGET_TMPDIR` scratch folders live inside this repository and would otherwise resolve to its top level when their own `.git` is removed.
- Added tests beyond the three required scenarios inside `run_refusals.rs` for the passing approval path, an unwritable lock and the UTC formatter. They cover lines the required rows do not reach; `cargo mutants` on the new sources now reports 168 caught, 8 unviable and 0 missed.

## Missing context

- The task scope did not name `Cargo.lock`, although adding dependencies to a workspace member necessarily updates it.
