## Details

The crate's `Cargo.toml` gains `osq-kernel-config`, `osq-kernel-storage`
and `osq-kernel-vcs`. Use `GitVcs::root()` for the git check.

Refusals write nothing: check them all before the lock, in the order the
requirement lists them. Only `already_running` is decided by the lock's
`create_new` failing, so it never kills the task. Times are UTC
`YYYY-MM-DDTHH:MM:SS.mmmZ`, formatted by the run crate's own code; no new
time crate.

Keep the orchestration in `src/feature/` small modules: task 3 adds the
executor start, the scope audit and the verdict between the approval check
and the lock's removal, so leave one clear place for them. Until then, a run
that passes the approval check ends by removing the lock and failing with
`task <n> of <folder> cannot start yet`; task 3 replaces that line.

Tests may not set environment variables. Never read anything under `src/`
from Rust; the TypeScript files are in `entry` only so you can port them.
Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/273-rust-run-one-task`, so the link gates see
this change's new requirements.
