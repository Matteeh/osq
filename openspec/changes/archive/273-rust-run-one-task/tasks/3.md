## Details

The crate's `Cargo.toml` gains `osq-kernel-runners` and
`osq-kernel-harnesses`. Runner settings: the executor role from the config,
no start retries, zero delays, an empty agent env; the process environment
is the source env.

Take a snapshot before and after the start: each `GitVcs::status()` entry
with a hash of the file's bytes, or none when it is missing. A path changed
when it is in either snapshot and its code or hash differs. It is `Deleted`
when the file is now missing, `Added` when it was not listed before and is
now `??` or starts with `A`, and `Modified` otherwise. Test folders are
`tests` and `benches` beside the nearest `Cargo.toml` above each changed
path; lock rules are Rust's (`Cargo.toml`, `Cargo.lock`) and TypeScript's
(`package.json`, then `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`).

The result file counts as written during the start when its modified time is
at least one second before the start. Verify runs use the task timeout for
the task's verify and the verify timeout for the proposal's, both with the
harness kill grace. A dead marker for `verify_red` carries `command:` and,
when it timed out, `timed_out: true`; `change_verify_red` carries `command:`
and `exit_code:`. Their bodies hold the verify output's last 2000 bytes.

Tests may not set environment variables. Never read anything under `src/`
from Rust; `src/watcher/runner.ts` is in `entry` only so you can port it.
Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/273-rust-run-one-task`, so the link gates see
this change's new requirements.
