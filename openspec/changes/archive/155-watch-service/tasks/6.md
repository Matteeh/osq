## Acceptance

- [ ] New `decisions/012-watch-service.md` follows ADR 011's layout (frontmatter, `# 012. Watch service`, `Date: 2026-10-07`, Status, Context, Decision, Consequences, Rejected). Its frontmatter is `status: accepted`, `applies_to: [watcher-and-harness, cli-foundation]`, `rule: The watcher runs in the background under osq's own detached supervisor, which restarts it after a crash or a new build and never while a task runs.`, and `checks: [tests/watch-supervisor.test.ts, tests/watch-service-build.test.ts]`.
- [ ] Context says, in plain prose: the foreground watcher stops on a stale build and needs a human to build and restart it, which happened after 110–112, after 112's land, after 116 and in 149; an installed package is never flagged stale, so an upgrade leaves old code running; M3 runs osq on its own server, where nobody keeps a terminal open; and `systemd --user` may be missing under WSL2.
- [ ] Decision says: one supervisor per project, started by `osq watch --background` and stopped by `osq watch --stop`; it runs the watcher as a child and restarts it after a crash with a backoff from `config.watch`, and at once when the worker exits 75 on a new build; the worker decides only between passes, at the points where the stale check runs, so a running task always finishes; on a stale build the worker waits; records and the log live under `~/.osq/watch/<hash>/` and count only while their pid is alive; one watcher per project; the service never builds osq and never runs git (ADR 003).
- [ ] Consequences say: the supervisor's own code changes only when the service is stopped and started; a multi-project supervisor and remote access build on these records; starting at login is not provided. Rejected names a generated `systemd --user` or launchd unit, and restarting on every `src/` change as `--dev` does.
- [ ] `decisions/README.md`'s index gains `- [012. Watch service](012-watch-service.md)` after ADR 011's line.

Every existing test passes unchanged.
