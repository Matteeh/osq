## Acceptance

- [ ] `osq watch` registers `--background` ("run the watcher as a background service") and `--stop` ("stop the background service"), and implements cli-foundation "Background watch commands". Start, stop, the live-record check and the role dispatch live in new `src/cli/watch-service.ts`; `watchCommand` in `watch.ts` calls them. Every message is the exact text of the requirement, printed through `CommandInputs.stdout`, and each failure is a `CommandError` with that text.
- [ ] The supervisor role calls `runServiceSupervisor` with `process.argv[1]` as `entry`, `process.execArgv`, and the forwarded `--verbose` or `--quiet`. The worker role starts the watcher with `buildCheck` from `createServiceBuildCheck` (`settleSeconds` from `config.watch.buildSettleSeconds`), and its `onWaiting` rewrites `watcher.json`'s `waiting`. Both continuous roles write `watcher.json` from `resolveBuildInfo` and remove it in a process `exit` handler with `removeWatchRecordSync`. `--once` writes no record.
- [ ] The start path opens `watch.log` for appending, spawns the supervisor with `detached: true` and that file as stdout and stderr, calls `unref()`, and writes `service.json` with the child's pid. `--stop` polls `isProcessAlive` until `config.watch.stopWaitSeconds` has passed.
- [ ] `watchCommand` takes an optional `home`, used for every record; tests pass a temporary one. `src/cli/index.ts` stays at or under 250 lines.
- [ ] README's `osq watch` option list gains `osq watch --background` and `osq watch --stop`, and a short "Running the watcher in the background" paragraph says the service restarts the watcher after a crash and on a new build between tasks, waits instead of exiting on a stale build, never builds osq, keeps its records and log under `~/.osq/watch/`, and that `osq status` prints the log path. The stale build paragraph says the service waits for a build instead of refusing.
- [ ] New `tests/watch-background.test.ts` covers every scenario of "Background watch commands". Start and Stop run as real processes, spawned as `tests/inbox.test.ts` spawns the CLI (`process.execPath`, the tsx loader, `src/cli/bin.ts`), with `HOME` set to a temporary home and a temporary project whose `osq.config.ts` sets `harness: 'mock'`. The test waits for live `service.json` and `watcher.json` records, stops the service, and always kills any process it started in an `after` hook. The refusal cases call `watchCommand` with records written by `writeServiceRecord` and `writeWatcherRecord` for `process.pid`, and check that nothing was spawned.
- [ ] Every touched source file stays at or under 250 lines and no file in `src/` holds the word "skipped". Every existing test passes unchanged.
