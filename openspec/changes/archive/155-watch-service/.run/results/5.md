## Changed

- `src/core/status/watcher-line.ts` (new): exports `formatWatcherLine(state: WatchState): string`, rendering the status-inspection "Watcher line" table — `Watcher: running in the background, osq v<version> (<commit>), pid <service pid>` with both records live, `Watcher: restarting in the background, pid <service pid>` with only the service live, `Watcher: running in a terminal, osq v<version> (<commit>), pid <watcher pid>` with only the watcher live, and `Watcher: not running — osq watch --background` with neither — and appends `, waiting: <reason>` when the live `watcher.json` carries a waiting reason.
- `src/cli/inbox.ts`: text output is now `formatInboxText(inbox)` plus a newline plus the watcher line from `readWatchState(cwd, options.home)`; `--json` output is unchanged and neither reads or writes a watch record.
- `src/cli/status.ts`: `statusCommand` takes an optional `home` in `StatusCommandOptions` and prints the overview, an empty line, the watcher line, and `Log: <log path>` when `watch.log` exists.
- `tests/watcher-line.test.ts` (new): covers every "Watcher line" scenario and each row of its table, the `, waiting:` suffix, "Concise inbox text"'s "Entirely empty inbox" on `formatInboxText`, and command cases that run `inboxCommand` and `statusCommand` with a temporary home holding records written by `writeServiceRecord`/`writeWatcherRecord` for `process.pid`, including `osq --json` keeping only `needsYou`/`running`/`landed`, the `Log:` line, its absence without a log, and that neither command writes a watch record.
- `tests/inbox.test.ts`: the two cases that pin the bare `osq` text now expect `Watcher: not running — osq watch --background` after the inbox text (the empty-project case asserts the exact two-line output), and the second-run landed-section assertion reads only the section's first line. Nothing else in the file changes.
