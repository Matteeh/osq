## Changed

- `src/cli/watch-service.ts` (new): holds the service start, stop, live-record check, and role dispatch for `osq watch`. `startBackgroundWatch` opens `watch.log` for appending, spawns the same Node executable with its `execArgv`, `process.argv[1]`, `watch`, and the forwarded `--verbose`/`--quiet` as a detached child with `OSQ_WATCH_ROLE=supervisor` and that file as stdout/stderr, calls `unref()`, writes `service.json` with the child's pid, and prints `osq watch is running in the background (pid <pid>). Log: <log path>` through the stdout writer. `stopBackgroundWatch` SIGTERMs the live supervisor and polls `isProcessAlive` until `watch.stopWaitSeconds` has passed, printing `osq watch stopped (pid <pid>)`, `osq watch is stopping after its running task (pid <pid>)`, or `osq watch is not running in the background`. `refuseLiveWatch` throws `CommandError`s with the exact table texts when `service.json` or only `watcher.json` names a live pid; `runWatchService` skips it for a supervisor and its own worker. The supervisor role calls `runServiceSupervisor` with `process.argv[1]` as `entry`, `process.execArgv`, and the forwarded flags. The worker role starts the watcher with `buildCheck` from `createServiceBuildCheck` (`settleSeconds` from `config.watch.buildSettleSeconds`) whose `onWaiting` rewrites `watcher.json`'s `waiting`; both continuous roles write `watcher.json` from `resolveBuildInfo` (mode `background` for a worker, `terminal` otherwise) and remove it in a process `exit` handler with `removeWatchRecordSync`; `--once` writes no record. Every message is the exact requirement text through `CommandInputs.stdout`, and every failure is a `CommandError`.
- `src/cli/watch.ts`: `watchCommand` now takes an optional `home`, keeps dev-mode dispatch, and hands every other form (stop, roles, background, terminal, once) to `runWatchService`; `resolveLogLevel` moved to `watch-service.ts` and is re-exported.
- `src/cli/index.ts`: `osq watch` registers `--background` ("run the watcher as a background service") and `--stop` ("stop the background service"); stays at 248 lines.
- `README.md`: the Watcher options list gains `osq watch --background` and `osq watch --stop`; a "Running the watcher in the background" paragraph says the service restarts the watcher after a crash and on a new build between tasks, waits instead of exiting on a stale build, never builds osq, keeps its records and log under `~/.osq/watch/`, and that `osq status` prints the log path; the stale build paragraph says the service waits for a build instead of refusing.
- `tests/watch-background.test.ts` (new): covers every scenario of "Background watch commands". Start and Stop run as real processes spawned like `tests/inbox.test.ts` (`process.execPath`, the tsx loader, `src/cli/bin.ts`) with `HOME` set to a temporary home and a temporary project whose `osq.config.ts` sets `harness: 'mock'`. The Start test waits for live `service.json` and `watcher.json` records (asserting mode `background`, version/commit, and the log path), the Stop test asserts the stopped line and that both files are removed, a stubborn SIGTERM-ignoring pid yields the stopping-after-the-running-task line with a 1-second `stopWaitSeconds`, and an empty project yields the not-running line. The refusal cases call `watchCommand` with records written by `writeServiceRecord`/`writeWatcherRecord` for `process.pid` (`--background`, `--once`, and plain `watch` against a live service; `--background` against a terminal record; `--background --dev`; `--stop --once`) and check no process was spawned. Additional tests cover `--once` writing no record and a real continuous terminal watcher writing a `terminal` record and removing it on SIGINT exit. Every process started is killed in an `after` hook.
