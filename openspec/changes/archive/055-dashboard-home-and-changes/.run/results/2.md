## Changed

- `packages/ui/src/router.ts`: `Route` gains `home` and `changes`. `routeToHash`
  emits `#/` and `#/changes`; `parseHash` maps the empty hash and `#/` to home,
  `#/changes` to the list, and keeps `/report`, `/graph`, and `/changes/<key>`
  unchanged; `resolveRoute` falls back to home for any unknown hash.
- `packages/ui/src/data.ts`: `loadRoute` loads the inbox for `home` and the graph
  for `changes`, still preferring the matching inline document. The changed-event
  refresh already refetches report, graph, and inbox together, so both new routes
  invalidate through it.
- `packages/ui/src/home/`: `HomeView` plus one component per group
  (`NeedsYouGroup`, `RunningGroup`, `LandedGroup`), a `labels.ts` kind map, and an
  index. Needs-you rows show the kind words, change and task, the exact command in
  `<code>`, and a `#/changes/<id>` link; running rows show the task and
  `formatSeconds` elapsed time; landed rows show the archive time under a
  `Landed since last look` heading; each empty group renders one state line.
  Every internal link uses `onNavigate` via a prevented default.
- `packages/ui/src/changes/`: `ChangesView` and `ChangesTable` with `order.ts`
  (active first, then the rest, each descending by numeric id) and `labels.ts`
  (active splits into `awaiting approval` / `in progress`; archived and rejected
  pass through). Rows link id and title to the folder-key change page, read tasks
  as `doneCount of taskCount` (`?? 0`), format both cost columns with the shared
  `formatCost`, and show the landed date or `—`.
- `packages/ui/src/app.tsx`: renders the two views, passes `onNavigate`, and the
  nav reads Home · Changes · Report · Graph.
- `tests/ui-home.test.tsx` (new): all four needs-you kinds and their commands,
  running elapsed time, landed archive time and label, the quiet-repository
  empty-state check through `App`, and the kind-label map.
- `tests/ui-changes.test.tsx` (new): mixed locations rendered once each with
  states, progress, costs, landed date, and dash; active-first descending order
  through both `orderChangeNodes` and the rendered rows; the approved active
  scenario; and zero-coverage costs reading `not reported`.
- `tests/ui-data.test.tsx`: empty and unknown hashes now expect home, the two new
  routes join the round-trip cases, the inline load test exercises home/changes,
  and the nav/render test asserts the new order and placeholders.

## Deviated

- The links carry both `href` and an `onClick` that calls `onNavigate`, matching
  the `NavLink` pattern in `app.tsx`; the task asked for `onNavigate` on internal
  links, and the href keeps the routes server-renderable and testable.
- The changes list orders null-id nodes after numeric ids, then by descending
  folder key. The delta only pins descending id per group and the fixtures always
  have numeric ids, so this is a deterministic tiebreak rather than a departure.

## Missing context

- The delta and task do not name a fallback for null change ids in the changes
  list; I display the title alone for those and sort them after numeric ids.
- The task says a dash for a missing landed date without fixing the glyph; I used
  an em dash (`—`).
