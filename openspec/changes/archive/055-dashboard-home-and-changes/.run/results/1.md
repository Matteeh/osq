## Changed

- `src/core/web/web-data-types.ts`: `WebChangeNodeBase` gains `doneCount` next to
  `taskCount`, documented as the done-marker count.
- `src/core/web/web-data-graph.ts`: added `countDoneTasks`, which calls the
  existing `deriveSpecState(projectRoot, folderPath)` marker derivation, counts
  tasks whose state is `done` (manual done included), and returns 0 when
  derivation fails. Wired into every change node in `changeNodes`, so active,
  archived, and rejected nodes all carry it.
- `tests/web-data-progress.test.ts` (new): through `getWebGraph`, covers an
  active change with one of three tasks done, an archived change with every task
  done, an archived change without markers, a rejected node, and that every node
  carries a numeric `doneCount` no greater than `taskCount`.
- `tests/web-data.test.ts`: added `assert.equal(active.doneCount, 1)` where the
  existing test pins the active node's task count.

## Deviated

- The acceptance says `doneCount: number`, but it is declared
  `readonly doneCount?: number`. A required field breaks `pnpm verify`:
  `tests/ui-graph.test.tsx` and `tests/ui-report.test.tsx` each build a
  `WebChangeNode` literal in their `changeNode` helper via
  `{ ...base, ...overrides }`, so a required field is missing from the literal.
  Those files are outside this task's `scope` and `tests.modify` cannot reach
  them, so the only way to keep the proposal's `pnpm verify` green was to allow
  omission in hand-built literals. Runtime derivation always sets it, and the
  new tests assert it on every node. Task 2's changes view should read it as
  `node.doneCount ?? 0`.

## Missing context

- The task expected `tests/web-data.test.ts` to pin a whole change node, but it
  does not; it asserts individual fields. I added the field assertion next to
  the analogous `taskCount` assertion.
