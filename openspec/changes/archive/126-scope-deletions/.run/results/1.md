## Changed

- `src/watcher/git-guard.ts`: `scopeViolations` now judges each changed path with
  `scopeCoversPath(options.scope, file)` and no longer calls `resolveScope`, so a
  file the task deleted is still covered by the scope entry that names it
  (exactly or through a glob). The new-untracked-test and change-folder
  exemptions are unchanged.
- `src/core/run/task-commit.ts`: `verifiedCommitPaths` now keeps every path
  `scopedStatusPaths` returns whether or not it exists on disk. Only the four
  change-folder records (`.run/done/<n>`, `.run/results/<n>.md`,
  `.run/events/<n>.jsonl`, `tasks.md`) still pass through `existingPaths`. The
  result stays sorted and deduped.
- `tests/scope-deletions.test.ts`: new test driving `runWatcherCycle` in an osq
  worktree. One task with `tests.modify: true` deletes a tracked `src/old.ts`
  named exactly and a tracked `tests/old.test.ts` covered by a `tests/*.test.ts`
  glob; it is done, its `osq: 001 task 1 verified` commit shows both `D` lines,
  the worktree is clean outside `.run/`, and no `scope_violation` is recorded. A
  second task deletes a tracked file outside its scope and records one
  `scope_violation` naming it.

Both `node --import tsx --test tests/scope-deletions.test.ts` and the proposal's
`pnpm verify` pass.

Touched: src/watcher/git-guard.ts, src/core/run/task-commit.ts, tests/scope-deletions.test.ts
