## Acceptance

- [ ] `scopeViolations` treats a changed file as in scope when `scopeCoversPath(options.scope, file)` is true. It no longer calls `resolveScope`. The new-test-file and change-folder exemptions stay as they are. This covers the watcher-and-harness delta's "Scoped file deleted" and "File outside scope deleted".
- [ ] `verifiedCommitPaths` keeps every path `scopedStatusPaths` returns, whether or not it exists. Only the four change-folder records, `.run/done/<n>`, `.run/results/<n>.md`, `.run/events/<n>.jsonl`, and `tasks.md`, still pass through `existingPaths`. The result stays sorted and without duplicates.
- [ ] New `tests/scope-deletions.test.ts` covers "Deleted scoped file" through `runWatcherCycle` in an osq worktree. The mock adapter deletes a tracked `src/old.ts` named exactly and a tracked `tests/old.test.ts` covered by a `tests/*.test.ts` glob, with `tests.modify: true`. The task is done, the `osq: <id> task 1 verified` commit shows both as deleted, and `git status --porcelain` is empty outside `.run/`.
- [ ] The same file covers "Scoped file deleted" and "File outside scope deleted" of "Scope violation recording": a deletion the scope covers records no `scope_violation` event, and deleting a tracked file outside the scope records one naming it.

## Details

`tests/worktree-run.test.ts` builds a repository, approves a change into its
worktree, and drives `runWatcherCycle` with a scripted adapter. Its "commits a
new test file outside the task scope" case is the closest model. Commit
deletions with `git show --name-status` to read the `D` lines.
