- [ ] `lint` loads the config and checks the proposal rules, then the banned words, then the spec validation and link gates, as rust-lint "Lint findings", "Lint proposal rules" and "Lint banned words" say; with no error, warnings print above `<folder>: valid`.
- [ ] A config error fails `lint` with its display, as "Lint errors" says.
- [ ] New `tests/lint_proposal_rules.rs` proves "Proposal rule findings", new `tests/lint_banned_words.rs` proves "Banned word warnings" and "Fenced code and scenario quotes", and new `tests/lint_config_error.rs` proves "Lint config error". Each row copies `tests/fixtures/lint-project` into a new scratch root under `CARGO_TARGET_TMPDIR` named after its row, then writes the row's files over it; the copy helper goes in a new `tests/copy/mod.rs`, since `tests/support/mod.rs` stays unchanged. No test writes into the fixture.
- [ ] Every existing lint test passes unchanged.
- [ ] Every public item ends its doc with `Implements: rust-lint/<requirement>`, and each new test's doc names `Covers: rust-lint/<scenario>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Add `osq-kernel-config` to the crate's `Cargo.toml` as the other kernel
dependencies are written; the root `Cargo.lock` follows it on its own.
Call the specs kernel's `project_rules_errors` from task 1 for the
`AGENTS.md` errors, and core's `scope_covers_path` for scope and path
overlap.

Keep each rule in its own module under `src/lint/`, such as
`proposal.rs` for the Assumptions and Decisions sections and
`banned.rs` for the banned words, each a pure function from text to
findings, so the line and function budgets hold. A finding carries its
severity, file, optional section and message; `text.rs` writes its line.

When the mutation check reports a missed mutant, add a row-shaped test
case for that line, with the expected value taken from the TypeScript
source, rather than keeping a branch no test reaches. Run the proposal's
verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/299-rust-lint-proposal-rules`, so the link
gates see this change's requirements.
