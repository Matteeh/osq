## Changed

- Added `crates/kernel/storage/src/model/replace.rs` with the public `replace_read_model`, the table schema, the rebuild-path helper and leftover cleanup. Every failed step removes the rebuild file and returns its own error, so the database at `db_path` stays whole.
- Re-exported `replace_read_model` from `model/mod.rs` and the crate root, and made `write_read_model` and `build_read_model` write only through it. `remove_existing` is gone.
- `build_read_model` now reads the trial labels, history, manual edits and capability ownership before opening the database, then fills snapshots, notices, labels, manual edits and task outcomes in one transaction.
- Changed `apply_labels` and `insert_manual_edits` to take the rebuild `Transaction`; `write_task_outcomes` keeps its public signature and shares its row insert through `insert_task_outcomes`.
- Updated the `ReadModelError::Io` doc to name every file operation that fails as it.
- Added `crates/kernel/storage/tests/read_model_atomic.rs` proving the four scenarios, plus `write_read_model_keeps_archived_rows_only`, which kills the `==` to `!=` mutant in `write_read_model` that the corpus-only coverage missed.

## Deviated

- Added one test beyond the four named scenarios: `write_read_model_keeps_archived_rows_only` checks that a rejected snapshot from `read_history` adds no `changes` row. Without it, cargo-mutants reported `crates/kernel/storage/src/model/mod.rs` `replace == with !=` as missed, because only ignored corpus tests exercised that branch.
