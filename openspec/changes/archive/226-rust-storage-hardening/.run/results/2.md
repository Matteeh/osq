## Changed

- Added `crates/kernel/storage/src/read/snapshot/manifest.rs` with a crate-private `Manifest`, `ApprovalFlags` and `Notices`, all deriving `serde::Deserialize`, using camelCase names and ignoring unknown keys. Every top-level field is optional.
- Added `StorageError::Manifest { path, source }`; its `Display` writes `<path>: <source>` and its `source()` returns the serde error.
- `read_manifest` now returns `Result<Option<Manifest>, StorageError>`: a missing file is `Ok(None)`, another read failure is `StorageError::Read`, and text serde refuses is `StorageError::Manifest`.
- `approved_at`, `read_planner` and `manifest_notices` take `Option<&Manifest>`; `read_change` propagates the manifest error with `?` and its `# Errors` doc names `StorageError::Manifest`.
- Added `serde.workspace = true` to `crates/kernel/storage/Cargo.toml`; `Cargo.lock` gained only `serde` in the storage package's dependency list.
- Added `crates/kernel/storage/tests/reading_manifest.rs`, one test per row of rust-storage "Manifest files read or refused".

## Deviated

- `Manifest` and `ApprovalFlags` carry `#[expect(dead_code, reason = ...)]` on the unused validation-only fields. The fields must exist so serde refuses a wrong-typed one, but no table reads them; without the expectation the crate fails `-D warnings` under clippy. This is a rustc lint, not a `[workspace.lints]` entry, so no workspace lint was loosened.
