## Acceptance

- [ ] `frontmatter_string` and `markdown_body` in `read/text.rs` keep their public signatures and read through `osq_kernel_specs::parse_frontmatter`. An `Err` from it means no frontmatter key and the whole text as the body. `markdown_body` still returns a `&str` borrowed from its input, which is the suffix of the text as long as the parsed body.
- [ ] `valid_frontmatter`, `match_frontmatter`, `strip_newline`, `frontmatter_yaml` and the `yaml_rust2::YamlLoader` import are gone from `read/text.rs`. `parse_record` in `read/manual.rs` reads `kept_at`, `paths` and `capabilities` from the `data` mapping `parse_frontmatter` returns, and treats an `Err` as no record.
- [ ] New `tests/reading_frontmatter.rs` proves rust-storage "Frontmatter the specs kernel refuses", one assertion per table row, through `frontmatter_string` and `markdown_body`.
- [ ] The same file proves rust-storage "Storage has no frontmatter parser of its own". It reads every `.rs` file under `crates/kernel/storage/src` with `env!("CARGO_MANIFEST_DIR")`, and finds `YamlLoader` only in `src/read/snapshot/events.rs`.
- [ ] `frontmatter_string` and `markdown_body` keep their `Implements: rust-storage/text-fields` lines. Each test has a one-line doc naming `Covers: rust-storage/<scenario>`, and has no `#[ignore]`.

## Details

Both readers split the `---` block with the same rule, so `reading_text.rs`
and `reading_files_records.rs` stay green unchanged. The look-ups keep
using `yaml_rust2::Yaml` values, because `Frontmatter.data` is a
`yaml_rust2` `Hash`. `yaml-rust2` stays a storage dependency for those and
for `exact_cost` in `read/snapshot/events.rs`. The golden-row and corpus
tests that `sh scripts/verify-rust.sh` runs prove that every archived
title, planner, Goal and manual record reads as before.
