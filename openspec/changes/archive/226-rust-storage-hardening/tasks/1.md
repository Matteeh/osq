## Acceptance

- [ ] New `model/replace.rs` holds the public `replace_read_model`, re-exported from `model/mod.rs` and `lib.rs`. It removes any leftover file at the rebuild path (`db_path` with `.rebuild` appended to its file name), opens one `Connection` there, creates the tables with `CREATE_TABLES`, runs `fill` on one transaction, commits, closes the connection and renames the rebuild file over `db_path`. On any failed step it removes the rebuild file, ignoring a failure to remove it, and returns that step's error. File operation failures are `ReadModelError::Io`, and the doc of that variant says so.
- [ ] `write_read_model` keeps its signature, writes only through `replace_read_model`, and no longer calls `remove_existing`.
- [ ] `build_read_model` reads the trial labels, `read_history`, `read_manual_edits` and `read_capability_ownership` before it touches the database. It then makes one `replace_read_model` call whose fill inserts the archived snapshots, the notices, the labels, the manual edit rows and the task outcome rows. `apply_labels` and `insert_manual_edits` take the `Transaction` instead of a path. `write_task_outcomes` keeps its public signature for the tests that call it after `write_read_model`, and shares its row insert with the fill.
- [ ] New `tests/read_model_atomic.rs` proves rust-storage "Failed rebuild keeps the previous database", "Failed first build writes no database", "Leftover rebuild file" and "Database path that cannot be replaced". It uses the fixture project at `tests/fixtures/project` and databases under `env!("CARGO_TARGET_TMPDIR")`, each test at its own path. A failing fill inserts a `changes` row and then returns `ReadModelError::Labels` with a message the test compares. Each test checks that the rebuild path does not exist afterwards.
- [ ] `replace_read_model` ends its doc with `Implements: rust-storage/read-model-rebuild`. Each test has a one-line doc naming `Covers: rust-storage/<scenario>`, and has no `#[ignore]`.

## Details

The existing `read_model.rs` tests stay green unchanged. A directory at
`db_path` makes the final rename fail as `ReadModelError::Io`, which
`unremovable_stale_path_fails` and `read_model_errors_speak` expect. The
labels are still read before anything is written, so `malformed_label_file`
still finds its `keep` file untouched. Compare a database's rows the way
`read_model.rs` does: read every row of `changes`, `tasks` and
`dead_attempts` with `rusqlite`. Keep `model/mod.rs` under 250 lines by
putting the file handling in `replace.rs`.

## Scenarios

- rust-storage: Failed rebuild keeps the previous database
- rust-storage: Failed first build writes no database
- rust-storage: Leftover rebuild file
- rust-storage: Database path that cannot be replaced
