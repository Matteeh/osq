## Details

For "Lock file that cannot be rebuilt", `cargo` cannot write a lock file
that names a crate no registry holds, so the test writes each branch's
`Cargo.lock` text by hand. It inserts each new crate's `[[package]]` block at
the same place, between the same two existing blocks, so the merge conflicts
there. For the other two scenarios, `cargo generate-lockfile --offline` and
`cargo metadata --offline --format-version 1` write the lock files, as in
this setup: a root `Cargo.toml` with `members = ["crates/*"]`, crates `a` and
`z`, then `m1` added on one side and `m2` on the other. Both new blocks sort
between `a` and `z`, so `Cargo.lock` is the only conflict.

Name the `describe` after the requirement, since the living version-control
spec holds scenario names the `scenario` helper refuses.
