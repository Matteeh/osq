## Acceptance

- [ ] `styles.css` defines the custom properties in the tables below on `:root`, and redefines them under `@media (prefers-color-scheme: dark)`. Every color in the file comes from them.
- [ ] New `packages/ui/src/status.tsx` exports `StatusBadge` for the statuses `verified`, `manual`, `dead`, `regressed`, `running`, and `pending`. It renders a dot (`aria-hidden`) in `var(--status-<status>)`, where manual uses the verified color, followed by the status word.
- [ ] `TaskTable` and the home view's needs-you and running items render their task status through `StatusBadge`. No other status markup remains in them.
- [ ] Tables are full-width within a left-aligned content column no wider than 72rem. Text cells are left-aligned, number cells right-aligned with `font-variant-numeric: tabular-nums`, and the header row carries a bottom border in `--border`, as does each body row. No cell is centered.
- [ ] Headings use the scale below, and `.graph-edge-depends` and `.graph-edge-reads` get `fill: none`, a stroke in `--accent` and `--muted` respectively, and a 1.25px width, with reads dashed.
- [ ] New `tests/ui-status.test.tsx` renders `StatusBadge` for every status and asserts the word and color variable. It also asserts that `styles.css` defines every status variable in both schemes and has no `text-align: center` on table cells. `tests/ui-change.test.tsx` and `tests/ui-home.test.tsx` change only where they pinned the old status markup.
- [ ] The task's verify command passes.

## Details

This task's `scope` is authoritative over any injected code-ownership rules.
The direction is quiet and operational: the system font stack, a neutral
background, one accent, and hierarchy from size, weight, and spacing rather
than boxes or shadows. Keep status meaning in words; the dot is decoration. The
graph edge rules live here because this task owns `styles.css`; task 3 only
renders the paths with those classes.
