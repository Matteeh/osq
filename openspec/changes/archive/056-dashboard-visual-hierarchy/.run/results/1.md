## Changed

- `packages/ui/src/status.tsx` (new): exports `Status`, `StatusBadge`, and
  `statusForTaskState`. Each badge renders an `aria-hidden` dot whose inline
  `background-color` is `var(--status-<status>)` — `manual` pointed at
  `--status-verified` — followed by the status word. `statusForTaskState` maps
  the derived `done` task state to `verified`.
- `packages/ui/src/styles.css`: replaced the `--osq-*` palette with the task's
  `--bg`, `--text`, `--muted`, `--border`, `--accent`, and five `--status-*`
  properties, each redefined under `prefers-color-scheme: dark`. Added the body,
  h1/h2/h3, and table-header type scale; full-width tables with left-aligned
  text, a `--border` bottom rule on the header and every body row, and
  right-aligned tabular numbers (`.num` plus the task and changes table number
  columns). Added `.graph-edge-depends`/`.graph-edge-reads` with `fill: none`,
  `1.25px` strokes in `--accent`/`--muted`, and a dashed reads stroke. No color
  literal survives outside the two `:root` blocks and nothing is centered.
- `packages/ui/src/change/TaskTable.tsx`: the state cell renders
  `StatusBadge` through `statusForTaskState`.
- `packages/ui/src/home/NeedsYouGroup.tsx`: task-dead and task-regressed items
  render `task <StatusBadge>`; approval and change-regressed keep their kind
  words.
- `packages/ui/src/home/RunningGroup.tsx`: running items render the `running`
  badge.
- `tests/ui-status.test.tsx` (new): renders `StatusBadge` for all six statuses
  and checks the word and color variable, checks the `done` mapping, checks the
  whole palette is defined in both schemes, and checks `styles.css` never
  centers table cells.
- `tests/ui-change.test.tsx` and `tests/ui-home.test.tsx`: updated only the
  assertions that pinned the old status/kind markup to the badge markup.

## Deviated

- The acceptance says number cells are right-aligned. I reach the TaskTable's
  attempts, duration, and cost cells through CSS `nth-child` selectors instead
  of adding a class to the `<td>` elements, because adding that class would have
  changed the unrelated `<td>2</td>...` provenance assertion that acceptance
  line 6 says to leave alone.
- The `Dashboard home` living requirement still says each needs-you item shows
  its kind in words, and this change's delta does not modify it. So a dead or
  regressed task renders the kind's lead word `task` followed by the badge,
  rather than the badge alone.

## Missing context

- `WebTask.state` only ever carries `done`, never `manual`, and the UI task
  document exposes no manual-done signal. `StatusBadge` supports `manual` with
  its own word and the verified color, but the current derivation can never
  select it.
