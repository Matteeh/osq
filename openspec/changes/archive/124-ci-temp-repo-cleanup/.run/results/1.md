## Changed

- Added `tests/git-test-env.ts`. It exports `withoutBackgroundGit(env)`, which
  appends a `maintenance.auto=false` entry through `GIT_CONFIG_COUNT`,
  `GIT_CONFIG_KEY_<n>`, and `GIT_CONFIG_VALUE_<n>` after any existing entries,
  returns the environment unchanged when a `maintenance.auto` key is already
  present, and applies itself to `process.env` on import.
- Added `tests/git-background-work.test.ts`. It covers the delta's "Existing git
  configuration in the environment" and "The preload runs twice" against plain
  objects, the traced commit under the test environment with no `maintenance`
  child, the traced control commit with `-c maintenance.auto=true` that records
  `git maintenance run --auto`, and the `test` script preload check.
- Updated the `test` script in `package.json`: both `node --test` invocations now
  run `--import ./tests/git-test-env.ts` right after `--import tsx`.

`node --import tsx --test tests/git-background-work.test.ts` passes, and
`pnpm verify` (typechecks, build, full suite, lint) passes.

## Deviated

- The test file imports the preload as `./git-test-env.js`, not
  `./git-test-env.ts`. This repo uses NodeNext resolution, and `tsc` rejects a
  literal `.ts` import specifier with TS5097 unless `allowImportingTsExtensions`
  is set (which it is not, and changing `tsconfig` is outside scope). Under tsx
  the `.js` specifier resolves to the same `tests/git-test-env.ts` module, and
  the side-effect import still runs. The `package.json` script keeps the literal
  `./tests/git-test-env.ts` path because `node --import` resolves it at runtime.
