## Acceptance

- [ ] `package-install-smoke.test.ts` no longer runs `npm run build` before `npm pack`. Before packing, it asserts that `dist/cli/bin.js` and `ui/dist/index.html` exist, with the message `<path> is missing; run pnpm build before verifying`.
- [ ] `bin-execution.test.ts` no longer runs `npm run build` in its `before` hook. It asserts `dist/cli/bin.js` exists with the same message pattern, and every other assertion stays.
- [ ] `package-hygiene.test.ts` gains a test, next to `never spawns pnpm from any test under tests/`, that scans every test source under `tests/`. It fails on any spawn or exec call whose arguments include `run` followed by `build`, or `vite` with `build`, or `stage-ui.mjs`, and names each file and line.
- [ ] The scan's own source doesn't trip it. Build the patterns so that the literal command shapes they match don't appear in `package-hygiene.test.ts`, the same way `pnpmSpawnPattern` avoids matching itself.
- [ ] The task's verify command passes.

## Details

This task's `scope` is authoritative over any injected code-ownership rules.
`pnpm verify` runs `pnpm build` before `pnpm test`, so `dist/` and `ui/dist/`
are current whenever these tests run under verification. The smoke test's
`npm pack` runs no lifecycle script that builds, because `package.json` defines
only `prepublishOnly`, so packing only reads `dist/`. Two tests reading `dist/`
in parallel is safe; a test writing it is not.

`tests/package-ui-budget.test.ts` already fails with `run pnpm build before
verifying` when `ui/dist/index.html` is missing. Follow that message.
`tests/linter.test.ts` contains the string `pnpm build` as fixture data, not as
a spawned command, so the new scan must not flag it.
