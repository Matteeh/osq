## Acceptance

- [ ] The real root command runs the inbox instead of Commander help, accepts `osq --json`, and leaves help, version, every named subcommand, and the complete `osq status` output unchanged.
- [ ] Needs-you projection includes every unapproved proposal, active dead or regressed task, and active change-level regression exactly once, in numeric change/task order, with `approval`, `task-dead`, `task-regressed`, or `change-regressed` and the contract's exact command.
- [ ] Running projection includes only derived running tasks whose parsed lock PID is live, exposes PID, ISO start time, and non-negative elapsed seconds from the lock payload, uses `osq show <id>`, and never reaps or rewrites a stale or malformed lock.
- [ ] Landed projection reads authoritative archived events, filters strictly after a valid per-project last look, returns the newest ten recorded archives when the cursor is missing or malformed, sorts newest first, and advances the SHA-256/realpath-keyed cursor for text and JSON invocations without writing in a change folder.
- [ ] JSON output has exactly the documented top-level keys and item fields, empty arrays for empty groups, deterministic ordering, no prose, and the same snapshot values used by text rendering.
- [ ] Text output renders the three named groups with one `(none)` line per empty group, collapses a completely empty inbox to exactly `Inbox empty.`, formats running elapsed time through `formatDuration`, and ends every item row with its JSON command.
- [ ] The checked-in fixture and real CLI entry point prove mixed text output, exact JSON, live-versus-stale locks, cursor advancement and deletion, ten-item fallback, all-empty output, no change-folder mutation, and unchanged explicit status output.

## Details

Add a pure inbox projection and formatter in `src/core/inbox.ts`, with the thin
printing and cursor orchestration boundary in `src/cli/inbox.ts`. Reuse
`getStatusOverview`, `deriveSpecState`, `compareNumericPrefix`,
`isPidRunning`, `formatDuration`, `getArchiveDir`, and `resolveChangeDoc`.
Extend the existing state/status snapshot only as needed to carry parsed
running-lock identity and change-level regression through derivation; do not
perform a second scan of active dead, regressed, approved, or running markers.
Keep `formatStatusOverview` and `statusCommand` behavior byte-for-byte stable.

The stable JSON model has exactly three arrays. A needs-you item has `kind`,
`change: { id, title }`, nullable `task`, and `command`; task kinds carry
`task: { number, title }`. A running item has `change`, `task`, numeric `pid`,
ISO `startedAt`, integer non-negative `elapsedSeconds`, and `command`. A landed
item has `change`, ISO `archivedAt`, and `command`. Preserve this property set
and the top-level order `needsYou`, `running`, `landed`; do not add cursor paths,
last-look timestamps, display strings, rejected changes, blocked changes, or
pending work to the API object.

Parse running lock JSON defensively and use `isPidRunning` at the inbox I/O
boundary. Compute elapsed seconds from the same injected clock used to render
the snapshot, rounded consistently with `formatDuration`; invalid start times
or PIDs do not create running items. Filtering a lock is read-only and does not
replace the watcher's stale-lock transition.

For landed changes, read only valid `archived` records from
`.run/events/change.jsonl`; do not infer archive time from directory metadata,
task completion, manifests, or numeric folder order. Resolve the project root
with `fs.realpath`, hash its UTF-8 bytes with SHA-256 lowercase hex, and store
`{"lastLook":"<ISO>"}` at
`<homedir>/.osq/last-look/<hash>.json`. Treat missing, unreadable, malformed,
or invalid-date cursor content as absent. Capture one invocation time, use it
for the snapshot and cursor, and make home/cursor roots injectable in tests so
the suite never writes the developer's real home directory.

Register `--json` on the root Commander program and give only the root command
an action. Keep the existing `report --json` option scoped to report and retain
the current `-print` normalization. The integration test must spawn
`src/cli/bin.ts` through the local tsx loader in a copied `fixture/inbox`
project so root action wiring, cwd resolution, stdout, and cursor persistence
are exercised together. Replace the fixture lock PID and start time at test
runtime with the test process values. Existing tests outside the two declared
files are frozen regressions. Run the task verify and `pnpm verify` before exit.
