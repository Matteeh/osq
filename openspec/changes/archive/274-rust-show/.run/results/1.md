## Changed

- Copied `openspec/changes/274-rust-show/fixture/show-project` and `golden/` unchanged into the crate's test fixtures.
- Added the show crate's module layout: `feature`, `lookup`, `model` with `model/**`, `header`, `tasks`, `text`, and empty first versions of `events`, `planning`, `runs`, `digest` and `archived`.
- `ShowFeature` now offers the one `show` command, validates exactly one id argument before reading files, resolves ids, prefixes and paths as TypeScript does, and prints the model with a final newline.
- The model reads proposals, task files, task order, approval, task and change markers, result disclosures, raw result and dead diagnostics, written capabilities, human steps, dependency readiness, steering triggers, status and next step.
- Header, goal, contract, task lines, status, next step, location, approval, dependencies, features, after-landing steps and disclosures now match TypeScript's text for the outline.
- Added tests for `show-feature-commands`, `show-argument-errors`, `show-lookup-forms`, `show-errors-equal-typescript-s`, `show-outline`, `status-and-next-step-from-markers` and `dependency-readiness-from-folders`, including edge cases for each lookup form, negative numeric padding, task-number ordering, placeholder spellings, disclosures and an unmet dependency after every task is done.
- `cargo fmt --all`, clippy with `-D warnings`, the task verify, the proposal verify with `OSQ_CHANGE=openspec/changes/274-rust-show`, and package-wide cargo-mutants all pass.

## Deviated

- The empty sections this task does not own are empty const slices (`VERIFICATION`, `VALIDATION`, `RECERTIFICATIONS`, `LAND`, `LINES`) instead of functions returning empty vectors. The printed text is identical, and it avoids cargo-mutants reportable equivalent mutants that replace an always-empty function body with another always-empty value.
- `model.rs` reads task files and `.run` markers through the specs kernel and storage's listing and result-section helpers instead of `osq_kernel_storage::read_change`. `read_change` parses events with core's strict typed payloads and refuses the fixture's deliberately loose TypeScript event data such as `verify_ran` tags, which this task does not need to read.

## Missing context

- The task's instruction to reuse `read_change` conflicts with the fixture: its event payloads are valid for TypeScript's show but not for core's typed event reader. The later event-timeline task will need a lenient reader of its own.
