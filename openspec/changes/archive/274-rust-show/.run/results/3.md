## Changed

- Added `src/events/model.rs`, `src/events/read.rs` and `src/events/timeline.rs`, and wired `src/events.rs` to them: every `.run/events/*.jsonl` stream is read, ordered and rendered as TypeScript's `readEventStreams` and `timelineLines` do. Event `data` keeps file order through a small ordered `Deserialize`, values print as JavaScript's `String()`, and the reader exposes task streams to later tasks.
- Replaced the `src/runs/section.rs` stub with the run-history lines: pre-spawn verify, retries, current stuck, instructions changed, dependencies added, focused runs, and mutation with survivors, split into modules under `src/runs/section/`.
- Added `tests/show_runs.rs` with the "Show run history" scenario test plus three extra tests for JavaScript value rendering, event-file ordering, and run-line edges no golden reaches.

## Deviated

- The event timeline orders timestamps by their text. For osq's fixed `YYYY-MM-DDTHH:MM:SS.mmmZ` form this is the same order as parsing them, and invalid timestamps fall back to text order as TypeScript does. This avoided an equivalent cargo-mutants branch on timestamps that cannot be distinguished by any test.
- The `Entries` visitor's `expecting` message is marked `#[cfg_attr(docsrs, mutants::skip)]`: `Data`'s untagged deserializer accepts every JSON value, so cargo-mutants' `Ok(Default::default())` replacement is equivalent. The comment above it records why. A manual cargo-mutants run over every touched source file then reported 114 caught, 0 missed, 7 unviable.
- Added tests beyond the one required scenario test in `tests/show_runs.rs`, as the task's Details allows, so every touched line is covered by cargo-mutants.
