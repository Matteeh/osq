## Details

The crate's `Cargo.toml` adds `osq-kernel-storage`, `osq-kernel-specs`,
`osq-kernel-loop`, `serde` and `serde_json`, each as `.workspace = true`.
Do not touch `Cargo.lock`. Reuse the storage kernel's `list_changes`,
`read_change` and `parse_result_sections`, the specs kernel's
`read_proposal`, `read_task_file`, `section` and `parse_frontmatter`, and
the loop kernel's `scope_files`. Never read anything under `src/` from Rust;
the TypeScript files are in `entry` only so you can port them.

The steering triggers and the planning-sentinel check also exist in the
inbox crate (`needs/steering.rs`, `needs/placeholder.rs`). A feature never
depends on another feature, so copy what you need into `src/model/**`.

Each test copies `tests/fixtures/show-project` into its own new folder under
`CARGO_TARGET_TMPDIR`, named after the test. Because git ignores
`.run/running/`, it then writes `openspec/changes/003-running/.run/running/1.pid`
holding `{"pid":4242,"startedAt":1759395600000}` and a newline, as
`print-goldens.mjs.txt` does. Test files share no module: a helper used by
two test files is written in each. The status table's rows build their
files exactly as `print-status-table.mjs.txt` writes them.

Port every branch of the TypeScript you port. If cargo-mutants reports a
missed mutant on a branch no golden or table row reaches, add a test on a
scratch folder whose expected text you read from the TypeScript source.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/274-rust-show`, so the link gates see this
change's requirements.
