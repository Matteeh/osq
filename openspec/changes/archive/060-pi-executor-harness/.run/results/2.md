## Changed

- `src/core/foundation/doctor.ts`: `checkHarness` now returns the probed version alongside its check, and `runDoctorChecks` looks the selected entry up through `findHarness` and, after a passing `harness` check, awaits its optional `diagnose` hook. Every returned diagnosis is appended as a check preserving `name`, `ok`, `warning`, and `message`. A catalog entry without the hook adds nothing, and the module names no harness. Kept the file under the 250-line budget (241 lines) by inlining the hook call instead of a separate helper.
- `README.md`: listed `pi` under available adapters, added a `### Pi` section modeled on the Codex section (config example with placeholder provider/model, `pi.bin` -> `OSQ_PI_PATH` -> `pi`, `pi.model` -> `OSQ_MODEL` for a Pi executor -> native, `pi.thinking` as effort, the install command, the tested range, `pi auth check`, no Pi files written by `osq setup` because Pi reads `AGENTS.md` and an `AGENTS.override.md` would shadow it, the exact flags osq passes with extensions/skills/prompt templates off, no sandbox/no permission prompts/open network, the protocol-not-confinement statement, and that Pi cannot plan), and added `harness-version`/`harness-auth` to the diagnostics list.
- `tests/pi/doctor.test.ts`: new tests drive `runDoctorChecks` through its injectable `loadConfig` seam with `pi.bin` on the fake executable. They cover diagnoses appended after the harness check, no extra checks without a hook, silent pass on `0.87.1`, warning (report stays ok) on `0.88.0`, `harness-auth` failure naming `deepseek` and `credentials_not_configured`, ready passing, and no auth invocation without `pi.provider`.
