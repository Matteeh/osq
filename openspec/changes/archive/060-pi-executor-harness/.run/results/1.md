## Changed

Added the Pi executor harness end to end.

- `src/core/foundation/config-pi.ts`: `PiConfig` type and `validatePiConfig` (rejects blank/non-string, naming `pi.<key>`); `PI_TESTED_RANGE` (`>=0.87.0 <0.88.0`), `assessPiVersion`, and `runPiAuthCheck` (`pi auth check --provider <name> --json`); `resolvePiBinary`, `resolvePiEffort`, and the `diagnosePi` hook plus the `HarnessDiagnoseContext`/`HarnessDiagnosis` port.
- `src/core/foundation/config-env.ts`: moved `applyHarnessModelEnv` out of `config.ts` so the `pi` field/merge stays under the 250-line budget.
- `src/core/foundation/config.ts`: accepts harness `pi` and a `pi` section, validates it, merges it, and re-exports `PiConfig`.
- `src/core/foundation/harness-catalog.ts`: registers `pi` (configKey `pi`, `envModelWhenUnselected: false`, `planner.agent` unsupported, `diagnose` hook) and adds `resolvePiModel` (the harness-name comparison lives here, not in `config*.ts`).
- `src/harness/pi/`: `pi-args.ts` (headless argv + shared executor prompt), `pi-stream.ts`/`pi-tools.ts` (LF-only translation of tools, text, tokens, file changes, retry records, and settlement; kill grace), and `pi.ts` (`PiAdapter`, `preflightPi`).
- `src/harness/types.ts`: `SpawnDetails`, `onSpawn(pid, details?)`, the `harness_retry` event, `started.harnessVersion`, and `tokens.provider`/`tokens.model`.
- `src/watcher/spawn.ts`: forwards optional spawn details into the `started` event.
- `src/harness/index.ts` and `src/index.ts`: adapter registration and public exports.
- New tests under `tests/pi/` plus the captured `tests/fixtures/pi/run.jsonl` and replay fixtures.

## Deviated

- Resolution and the `diagnose` hook do not live in `config-pi.ts` as the task details described. The harness-name comparison in `resolvePiModel` is forbidden inside `config*.ts` by the frozen `tests/harness-architecture.test.ts`, and putting the hook there would create a module cycle. Resolution and Pi metadata therefore live in `harness-catalog.ts` and `config-pi.ts` split so that no `config*.ts` file names a harness and no cycle forms. `src/index.ts` re-exports all of it.
- `src/harness/pi/pi-tools.ts` is a small extra split file so every Pi source file stays under the line budget.
