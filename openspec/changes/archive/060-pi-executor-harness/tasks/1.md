## Acceptance

- [ ] `defineConfig` and `loadConfig` accept harness `pi` and a `pi` section with optional `bin`, `provider`, `model`, and `thinking`, reject blank or non-string values with a message naming `pi.<key>`, and resolve the binary from `pi.bin`, then `OSQ_PI_PATH`, then `pi`, the model from `pi.model`, then `OSQ_MODEL` only when Pi is the executor, then `default`, and effort from `pi.thinking` or null. `PiConfig` is exported from `src/index.ts`.
- [ ] Through `getHarnessAdapter('pi')` and a fake `pi` under `tests/pi/`, a spawned task receives exactly `--mode json --no-session --no-approve --offline --no-extensions --no-skills --no-prompt-templates [--provider p] [--model m] [--thinking t] -- <prompt>`, where the prompt equals `buildExecutorPrompt` for the same options. It runs in the project root, gets `OSQ_TASK_NUMBER` and `OSQ_SPEC_FOLDER`, and sees stdin closed (the fake records reading EOF at once). Unconfigured flags are omitted.
- [ ] Stream translation writes a project-relative `tool` event per `tool_execution_start`, a `text` event per assistant `message_end` with non-empty text, one `tokens` event per assistant `message_end` (`input`, `output`, `cacheRead`, `reasoning`, `totalTokens`, `cost.total`, `provider`, `model`), and a `file_changed` event per successful `edit` or `write`. A U+2028 inside a string parses as one record, a trailing `\r` is tolerated, malformed or unknown records are skipped, and three responses produce three `tokens` events whose sums match. Replaying `tests/fixtures/pi/run.jsonl` gives one `tool` event per `tool_execution_start` and one `tokens` event per assistant `message_end` in the fixture.
- [ ] `auto_retry_start` and `auto_retry_end` each write a `harness_retry` event with `phase`, `attempt`, and whichever of `maxAttempts`, `delayMs`, `success`, and `error` Pi supplied. A retry after `agent_end` does not end the run. A fake that writes `agent_settled` and keeps running is stopped after `timeouts.harnessKillGracePeriodMs`, and `spawn` returns exit 0.
- [ ] Through the watcher on a disposable fixture copy, a non-zero exit writes a crashed dead letter with Pi's stderr. The missing-credentials replay (session header on stdout, `No API key found for the selected model.` on stderr, exit 1) writes a dead letter that names `pi auth check`. A successful run without a result file is synthesized from the last `text` event, falls to `no_result` without one, and reaches `done` only after the watcher's own verify.
- [ ] `onSpawn` accepts the details below, and a Pi task's `started` event carries `harness: "pi"`, the resolved model or `default`, and `harnessVersion` from `pi --version`. Its manifest records `pi.thinking` as effort. `tests/golden-events.test.ts` still passes unchanged, so adapters that pass only a PID are unaffected.
- [ ] The catalog registers `pi` with `planner.agent` unsupported and implements the `diagnose` hook below. `PiAdapter.preflight` probes `--version` under `timeouts.harnessPreflightSeconds`, prints a warning outside `>=0.87.0 <0.88.0`, fails before any task spawns when `pi.provider` is set and `pi auth check --provider <name> --json` does not report `ready` (naming provider and reason), and runs no auth check without a provider.

## Details

This task's `scope` wins over any injected code-ownership rule. Model the
adapter on `CodexAdapter`, not OpenCode: reuse `spawnWithTimeout`,
`EventStreamParser`, `asRecord`, `firstNonEmptyString`,
`resolveEventTimestamp`, `appendHarnessEvent`, `relativizeToolSummary`, and
`buildExecutorPrompt`. Keep `spawnWithTimeout`'s default stdin of `ignore`.
Put Pi's config type, validation, resolution, tested range constant, version
check, and auth check in `src/core/foundation/config-pi.ts`, the way
`config-codex.ts` holds Codex's. The adapter's preflight and the catalog's
`diagnose` hook both call them, so doctor never imports `src/harness`. Split
the adapter into small files under `src/harness/pi/` (for example arguments,
stream, and adapter) so every file stays under 250 lines and every function
under 80.

`src/core/foundation/config.ts` is 4 lines under its 250-line budget. If the
`pi` field and merge push it over, move `applyHarnessModelEnv` into a new
`src/core/foundation/config-env.ts`. `applyHarnessModelEnv` already handles the
`OSQ_MODEL` fallback once the catalog entry has `configKey: 'pi'` and
`envModelWhenUnselected: false`.

Tool summaries: `bash` uses `args.command`; `read`, `edit`, and `write` use
`args.path`; `grep`, `find`, and `ls` use `args.pattern` or `args.path`; any
other tool uses its JSON args. Remember each `tool_execution_start`'s
`toolName` and `args.path` by `toolCallId`, so a `tool_execution_end` with
`isError: false` can emit `file_changed`.

To end the run at `agent_settled`, the adapter keeps the PID it receives from
`spawnWithTimeout`'s `onSpawn`. If the process has not closed within the kill
grace after `agent_settled`, it sends `SIGTERM` and reports exit 0 for a run
that settled. To detect missing credentials, match `No API key found` in
stderr. Ignore `message_end` records whose `message.role` is not `assistant`.
Only the `session` header has a `timestamp`, so `resolveEventTimestamp` falls
back to the current time for the rest; that is expected.

The fake `pi` follows `tests/codex/fake-codex.mjs`: a Node script, selected
through `pi.bin` or `OSQ_PI_PATH`, that answers `--version` and `auth check`
from environment variables and replays a named JSONL fixture. Put
hand-written fixtures under `tests/pi/fixtures/`. `tests/fixtures/pi/run.jsonl`
is the human-captured run; read it and never edit it. Every existing test is
frozen, and existing adapters' behavior must not change.
