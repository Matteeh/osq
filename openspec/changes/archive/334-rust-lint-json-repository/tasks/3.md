## Acceptance

- [ ] With `--json`, `lint` returns the document rust-lint "Lint JSON" names, written by hand in the lint crate with `serde_json` used only to escape strings, as `Output::text` when every checked change is valid and as `Output::with_code` with the code 1 otherwise; `--repository` changes nothing in the document.
- [ ] A failure before the document stays the `FeatureError` the other lint requirements name.
- [ ] The seven `json-*.json` files under `openspec/changes/334-rust-lint-json-repository/golden/` are copied byte for byte to `crates/features/lint/tests/golden/`.
- [ ] New `tests/lint_json.rs` proves "Lint JSON documents" and "Lint JSON failures", every row checked, comparing the output's text with the golden's bytes and its code with the row's code, each test's doc naming `Covers: rust-lint/<scenario>`, each scratch root a new folder under `CARGO_TARGET_TMPDIR` named after the test and row.

## Details

- The workspace's `serde_json` sorts object keys, so never build the document as a `serde_json::Value`; write the keys in the order "Lint JSON" gives.
- The rules copy writes over the fixture copy the files of the last row of "Banned word warnings" in rust-lint; `tests/lint_banned_words.rs` shows how.
- `tests/support/mod.rs` removes `repository: ` lines; JSON tests call `LintFeature` directly or use `run_args`, which removes nothing.

## Scenarios

- rust-lint: Lint JSON documents
- rust-lint: Lint JSON failures
