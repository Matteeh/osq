## Acceptance

- [ ] `Output` in `crates/core/src/feature.rs` gains the public field `code: i32`; `Output::text` sets it to 0 and the new `Output::with_code(text, code)` sets the code it is given, as rust-core "Feature constructors" says. `Output` stays `#[non_exhaustive]`, and no other crate changes.
- [ ] `dispatch` in `crates/apps/cli/src/lib.rs` returns the output's `code` in place of the fixed 0, as rust-cli "Command dispatch" says; every existing core and cli test passes unchanged.
- [ ] New `crates/core/tests/feature_output_code.rs` proves "Output exit codes" and new `crates/apps/cli/tests/dispatch_output_code.rs` proves "Output code through run_cli", every row checked, each test's doc naming `Covers: <capability>/<scenario>`.

## Details

- The cli test builds its own small test feature, as `crates/apps/cli/tests/dispatch.rs` does, since another test binary's helpers cannot be imported.
- Both new public items' docs end with `Implements: rust-core/feature-constructors`; `dispatch` keeps its tags.

## Scenarios

- rust-core: Output exit codes
- rust-cli: Output code through run_cli
