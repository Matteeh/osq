## Changed

- `crates/features/lint/src/feature.rs`: reads `--json` as a third flag, in any position, and passes it with the ids and `--repository` to `run_lint`.
- `crates/features/lint/src/lint.rs`: `run_lint` now returns `Output`; with `--json` it returns the JSON document instead of the text lines, and otherwise wraps the existing text result in `Output::text`.
- `crates/features/lint/src/lint/json.rs`: writes TypeScript's `buildLintJson` shape by hand, with keys in the required order, `null` for missing requirement or section, `:<line>` on spec finding files, and `serde_json` used only to escape strings. A valid document is `Output::text`; an invalid one is `Output::with_code(..., 1)`.
- `crates/features/lint/tests/lint_json.rs`: proves all seven "Lint JSON documents" rows against the golden bytes and codes, and "Lint JSON failures" for the missing id, with each scratch root named after its test and row.
- `crates/features/lint/tests/golden/json-*.json`: the seven golden files copied byte for byte from the change's `golden/` folder.

The task verify and the proposal verify pass, as do `cargo fmt --all --check` and clippy with `-D warnings`. `cargo mutants` over `lint/json.rs` reported 21 caught and 1 unviable mutant, none missed.

## Outside scope

- `sh scripts/verify-rust.sh` still stops in `crates/kernel/linter/tests/link_gates_corpus.rs` because the living specs do not yet hold this change's new requirement and scenario names, including `rust-lint/lint-json`, `rust-lint/lint-json-documents` and `rust-lint/lint-json-failures`. Those names live in the delta specs until the watcher archives the change. The task and proposal verifies pass.
