## Changed

- `crates/core/src/feature.rs`: `Output` gains the public `code: i32` field; `Output::text` sets it to 0 and the new `Output::with_code(text, code)` sets the given code. `Output` stays `#[non_exhaustive]`, and both constructors' docs end with `Implements: rust-core/feature-constructors`.
- `crates/apps/cli/src/lib.rs`: `dispatch` returns the output's `code` instead of the fixed 0; `dispatch` keeps its existing tags.
- `crates/core/tests/feature_output_code.rs`: new test proving every row of rust-core "Output exit codes".
- `crates/apps/cli/tests/dispatch_output_code.rs`: new test with its own `check` feature proving every row of rust-cli "Output code through `run_cli`".

The task verify and the proposal verify both pass, as do the format check and clippy over the workspace.

## Outside scope

- `sh scripts/verify-rust.sh` stops in `crates/kernel/linter/tests/link_gates_corpus.rs` because the repository link gates do not yet know the new scenario names `rust-core/output-exit-codes` and `rust-cli/output-code-through-run-cli`: those scenarios live only in this change's delta specs until the watcher archives them into `openspec/specs/`. The two crates the task and proposal name pass every test, including their own link gates.
