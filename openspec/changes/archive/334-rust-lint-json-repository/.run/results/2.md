## Changed

- `crates/features/lint/src/feature.rs`: reads `--json` and `--repository` as flags in any position, every other argument as a change id, rejects unknown `--` flags before any file read, and uses the `[--json] [--repository] [ids...]` usage.
- `crates/features/lint/src/lint.rs`: `run_lint` now takes the ids and `--repository`, finds every id before checking any change, checks each change in order, gathers each active change's spec validation and the living specs once, deduplicates repository findings, and renders change blocks followed by the repository count line or header and list.
- `crates/features/lint/src/lint/finding.rs`: adds `ReportFinding` with an `Origin` holding each source's finding data, so the findings the text is rendered from stay available for the JSON task.
- `crates/features/lint/src/lint/text.rs`: renders every finding from its source, adds the count line, repository count line and repository header, and keeps spec, merge, rule and link lines shared with the repository renderer.
- `crates/features/lint/tests/support/mod.rs`: `run` removes every `repository: ` line from output text and failed messages; `run_args_without_repository` gives the same for multi-id rows.
- `crates/features/lint/tests/feature.rs`: proves the new command usage.
- `crates/features/lint/tests/lint_arguments.rs`: proves the new argument-error rows and every "Lint with no change" row.
- `crates/features/lint/tests/lint_several_changes.rs`: proves every "Lint several fixture changes" row and "Lint stops at a missing id".
- `crates/features/lint/tests/lint_repository.rs`: proves "Repository lines on the fixture", "Repository living spec findings" and "Repository check error" against the full text.

The task verify, the proposal verify, `cargo fmt --all`, clippy with `-D warnings`, and a cargo-mutants run over the four changed source files all pass; the mutation run reported 65 caught and 18 unviable mutants, none missed.

## Deviated

- Added `run_args_without_repository` to `tests/support/mod.rs`, not only the required `run` stripping, because "Lint several fixture changes" uses several arguments and still compares with repository lines removed.
- `run_lint` builds `ChangeReport` values from `ReportFinding` data and renders them at the end, rather than keeping only lines, so task 3 can write the same findings as JSON.

## Outside scope

- `sh scripts/verify-rust.sh` reaches `crates/kernel/linter/tests/link_gates_corpus.rs` and fails there because the living specs do not yet have this change's scenario names (`rust-lint/lint-with-no-change`, `rust-lint/lint-several-fixture-changes`, `rust-lint/lint-stops-at-a-missing-id`, the three repository scenarios, and the task-1 core/CLI scenarios). They live in the delta specs until the watcher archives the change. The task and proposal verifies pass.
