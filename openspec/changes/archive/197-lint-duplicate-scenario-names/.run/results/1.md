## Changed

- Added `src/core/spec/duplicate-scenario-lint.ts`, exporting
  `duplicateScenarioFindings(capability, deltaFile, livingContent, mergedContent)`.
  It parses the merged text and the living text with `parseCapabilitySpec` (the
  same merge/parse pair `lookupScenario` uses), collects each scenario heading
  once per heading in merged order, and emits one `makeFinding('error', …)` for
  each name that appears more than once in the merged spec while the living spec
  held it at most once. The finding is on the delta file and on the second
  requirement holding the name, with the exact "appears in both … give each
  scenario of a capability its own name" text. The function carries one
  `@scenario spec-lint-and-approve: …` line for each of the five scenarios of
  "Repeated scenario name refusal" and "Repeated scenario name exceptions".
- `src/core/spec/linter.ts`: `verifyDeltaTargets` now imports
  `duplicateScenarioFindings` and calls it once per capability right after
  `mergeDelta` succeeds, passing the living text it already read and the merged
  text, and pushes its findings. The function is 77 lines, inside the 80-line
  budget.
- Added `tests/duplicate-scenario-lint.test.ts`, plain `node:test` blocks named
  after the scenarios. The four lint scenarios use `lintChangeFolder` over
  temporary projects; the approval scenario uses `approveSpec` and checks no
  `.run/approved` is written. Expected messages come from the THEN lines.
- Reused living scenario names in fixture deltas were given names of their own,
  with no assertion changed:
  - `tests/impact-lint.test.ts`: `delta()`'s `Added <capability> behavior`
    scenario `Works` becomes `Added works`.
  - `tests/ungoverned-lint.test.ts`: the three inline `Added cap behavior`
    scenarios `Works` become `Added works`.
  - `tests/instructions-drift.test.ts`: `DELTA_MD`'s `Ingress routing` scenario
    `Route` becomes `Ingress route`.
  - `tests/source-comment-lint.test.ts`: `requirementBlock` names its scenario
    `${name} works`.

Task verify and `pnpm verify` both pass.
