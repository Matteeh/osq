## Details

`lookupScenario` in `src/core/trace/scenario-lookup.ts` reads one capability's
scenarios by running `mergeDelta` and then `parseCapabilitySpec`; use the same
pair so lint and the `scenario()` helper agree. Read it, don't change it.
Count a name once per scenario heading, so a name repeated inside one
requirement is reported too, naming that requirement twice. Follow
`source-comment-lint.ts` for the module's shape and
`tests/source-comment-lint.test.ts` and `tests/instruction-delta-lint.test.ts`
for the test's: `installFakeValidator`, `scaffoldProject`, a local
`verify.cjs`, and a living spec written under `openspec/specs/<capability>/`.
Take expected values from the scenario lines, not from running the code. Do
not use the `scenario()` helper: spec-lint-and-approve holds duplicate scenario
names, so its lookup throws for that capability.

The new check breaks four existing tests whose fixture deltas reuse a living
scenario name. Measured fixes: in `tests/impact-lint.test.ts` and
`tests/ungoverned-lint.test.ts` rename the `Works` scenario under each
`Added … behavior` requirement to `Added works`; in
`tests/instructions-drift.test.ts` rename the `Route` scenario in `DELTA_MD`
to `Ingress route`; in `tests/source-comment-lint.test.ts` make
`requirementBlock` name its scenario `${name} works`.
