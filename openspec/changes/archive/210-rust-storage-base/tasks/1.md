## Details

Crate layout: every reading module sits under `src/read/`, with
`src/read/mod.rs` as its root, so task 2's `src/model/` stays apart.
`error.rs` holds `StorageError`, whose variants name the path
of a file that could not be read and, for a refused event line, the file,
the 1-based line and rust-core's `EventError`. `listing.rs` holds `Location`,
`ChangeEntry` and `list_changes`. `snapshot.rs` and `snapshot/` hold
`TaskFile`, `ChangeSnapshot`, `EventFacts`, `DeadAttempt`, `read_change` and
`read_archive`, split into more files under `src/read/snapshot/` when one
grows long. `text.rs` holds the four pure text leaves. `lib.rs` declares the
`read` module and re-exports its public items. Every `.rs` file stays under
250 lines and every function under 80.

The snapshot's event facts are what task 2's tables need, gathered in one
pass while the events are folded with rust-core's `apply`: started counts per
task stream, manual retries (a `retry` whose `automatic` is not `Some(true)`)
over the task streams and `change.jsonl`, the sum of `tokens` costs as `f64`
in task order then file order, the `dead` events in that order with the
trimming rules of "Columns of the tasks and dead_attempts tables", and the
timestamp of the last `archived` event in `change.jsonl`. `EventFacts` is
`None` when `.run/events/` does not exist, so task 2 can write null. Task
streams are the files rust-core's `Stream::from_file_name` names as a task,
in `TaskId` order. Reuse `parse_event_line`, `apply`, `ChangeState::new`,
`change_status`, `Stream` and `TaskId` from `osq-core`; add nothing to core.

`approvedAt` and `planner` come from `.run/manifest.json` (read with
`serde_json`); `approvedAt` counts only when `.run/approved` exists and
`timestamp_ms` reads it. `planner` falls back to `brief.md` frontmatter.
Titles: a proposal title that is not a string or trims to empty is `None`; a
task title that is not a string is empty text. A missing `proposal.md`,
`brief.md`, manifest or `tasks/` folder is not an error; an unreadable event
file is.

`goal_section` follows TypeScript's case-insensitive pattern
`##\s+Goal\s*\n([\s\S]*?)(?=\n##\s+|$)`, where `$` is the end of the text,
`\s` is any whitespace, and the first match wins; the scenario rows show its
edges, including that an empty Goal heading takes the next heading's text.
Hand-write it; add no regex crate. `markdown_body` and `frontmatter_string`
follow the pattern `^---\r?\n([\s\S]*?)\r?\n---\r?\n?([\s\S]*)$`: when the
YAML in group 1 does not parse, or the text does not match, there is no
frontmatter and the body is the whole text. `timestamp_ms` checks the fixed
form digit by digit and computes days from the civil date; add no date crate.
