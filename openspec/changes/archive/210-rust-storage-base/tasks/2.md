## Details

The read model lives under `src/model/`, with `src/model/mod.rs` as its root;
`lib.rs` declares the `model` module and re-exports its two public functions.

Only snapshots whose location is archived get rows; `write_read_model` skips
the others, so `build_read_model` can pass every snapshot `read_archive`
returns. Rows go in the order of the given snapshots, and within one change
in `TaskId` order, as the snapshot already holds them. Write all rows in one
transaction. `write_read_model` removes any file at `db_path` before it opens
the database, so a stale database never leaks rows.

Map each column from the snapshot with pure functions: `archived_on` is the
first 10 characters of the archive timestamp; `elapsed_seconds` is
`(archive_ms - approved_ms + 500) / 1000` in integer arithmetic when both
timestamps read through `timestamp_ms` and the difference is not negative;
`attempts`, `halts` and `cost` are null when the snapshot's `EventFacts` is
`None`, and `cost` is also null when no `tokens` event reported one.

Tests write their databases under `env!("CARGO_TARGET_TMPDIR")`, one file
name per test, and never into the source tree. Do not edit the fixtures, the
reading modules or their tests; they belong to task 1. When a row disagrees
with the scenario because of the snapshot, write it under `## Blocked`.

Keep every `.rs` file under 250 lines and every function under 80. Workspace
lints include `clippy::pedantic` and `-D warnings`. When the mutation step
reports a missed mutant, add a test case for it. Run `cargo fmt --all` before
exiting.
