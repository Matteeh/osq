## Deviated

- `list_changes` returns `Vec<ChangeEntry>` and not a `Result`. "Change listing" names only the missing-folder case, which lists nothing, and mirroring TypeScript's tolerant reads keeps a missing or unreadable directory from erroring. A file that exists but cannot be read is still an error on the event path (`StorageError::Read`).
- `read_change(entry: &ChangeEntry)`: the entry carries the folder path, so the snapshot reader needs no project root.
- Added `crates/kernel/storage/tests/reading_events.rs` and extra edge cases beyond the literal table rows. The one-case-per-row scenarios are all present; the extras exist only to kill mutants (equal leading numbers in the sort, century leap years, separator bytes, per-stream fact scoping, the validator stream, an unreadable event file, `Display`/`source`).
- The task lists `.run/running` and `.run/regressed` without saying whether they are files or folders; the fixtures use files, and `read_change` never inspects them.
- A malformed `.run/manifest.json` reads as absent (as TypeScript's `readManifestObject`), while an event file that exists but cannot be read is a `StorageError`.

## Missing context

- The task left the `EventFacts` field names open; task 2 needs them. They are now `started: BTreeMap<TaskId, u64>`, `halts: u64`, `cost: Option<f64>`, `dead_attempts: Vec<DeadAttempt>`, `archived_at: Option<String>`.
- The task did not say whether `list_changes` may fail, nor whether `read_change` takes the entry by value or by reference.
