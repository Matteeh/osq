## Changed

- Copied `changes.json`, `tasks.json` and `dead_attempts.json` from
  `openspec/changes/210-rust-storage-base/golden/` into
  `crates/kernel/storage/tests/golden/`, byte for byte (`cmp` confirms).
- Added `crates/kernel/storage/tests/archive_corpus.rs` (249 lines) with the two
  corpus tests, each `#[ignore = "corpus test: reads the live archive"]`, reading
  `openspec/changes/archive/` from `env!("CARGO_MANIFEST_DIR")` up three folders
  and sharing one `read_archive` result through a `OnceLock`:
  - `archived_changes_replay` (`Covers: rust-storage/archived-changes-replay`):
    at least 200 changes read, every task folds to `Done` exactly when
    `.run/done/<n>` exists (outside the exceptions), and every change numbered 038
    or higher holds an `archived` event. Failures name the change, the task, the
    folded status and the marker.
  - `golden_rows` (`Covers: rust-storage/golden-rows`): writes the read model from
    the shared 014 to 209 snapshots under `env!("CARGO_TARGET_TMPDIR")`, reads the
    three tables in table order and compares the rows with the JSON files: text and
    null as written, numbers as `f64`. Failures name the table, the row's folder
    and task, the column and both values.
- Golden numbers are read through `yaml-rust2`, not `serde_json`: the files are
  valid YAML, and `yaml-rust2` parses a decimal with `f64::from_str`, correctly
  rounded, while `serde_json`'s default float parser is one unit in the last place
  off for some 17-digit decimals the files hold (e.g. `0.14749...`).
- Fixed `crates/kernel/storage/src/read/snapshot/events.rs`: `Facts::observe` now
  receives the raw event line, and `record_tokens` reads its cost with the new
  `exact_cost` (`yaml-rust2` + `as_f64`, filtered to finite values). This was a
  real Rust bug, not a test artifact: `osq-core` keeps `TokensData.cost` as a
  `serde_json::Number` whose float parse is one ulp off, so 14 archived changes
  summed a `changes.cost` that differed from TypeScript's. `text.rs` was left
  untouched.
- Added `crates/kernel/storage/tests/golden_cases.rs` (`Covers:
  rust-storage/golden-rows`) and the fixture
  `crates/kernel/storage/tests/fixtures/exact-cost/`, whose task stream holds a
  `0.12749423999999998` cost, so cargo-mutants kills mutants in the new lines with
  a fast case and the corpus tests stay out of its loop.

  `003-watcher-and-harness` has no `.run/events/` directory at all and done markers

## Outside scope

- `osq-core`'s `TokensData.cost` is documented "kept as written" but is a
  `serde_json::Number`, whose float parse is lossy without serde_json's
  `float_roundtrip` feature. The clean fix is to enable that feature in the
  workspace or crate `Cargo.toml`, both outside task 4's scope; task 4 instead
  re-reads the cost from the raw line in storage. Nothing else reads
  `TokensData.cost` yet, but a later feature that does will still see the lossy
  value.
