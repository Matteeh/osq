## Changed

- `crates/kernel/storage/src/model/mod.rs` (new): public `write_read_model(db_path, snapshots)` and `build_read_model(project_root, db_path)`, the three untyped `CREATE TABLE` statements exactly as TypeScript's `osq query` names them, one transaction per build, and one insert helper per table. Only snapshots whose `Location` is `Archived` get rows.
- `crates/kernel/storage/src/model/rows.rs` (new): the pure snapshot-to-row mapping. `archived_on` is the first 10 characters of the last `archived` timestamp; `elapsed_seconds` is `(archive_ms - approved_ms + 500) / 1000` with `timestamp_ms`, null when not approved, either end is missing, or the difference is negative; `attempts`/`halts`/`cost` are null when the snapshot has no `EventFacts`; `cost` is null when no `tokens` event reported one.
- `crates/kernel/storage/src/model/error.rs` (new): `ReadModelError` with `Storage`, `Sqlite` and `Io` variants.
- `crates/kernel/storage/src/lib.rs`: declares `pub mod model` and re-exports `build_read_model` and `write_read_model`.
- `crates/kernel/storage/tests/read_model.rs` (new): proves "Fixture project rows", "Delete and rebuild" and "Rebuild over a stale database" on the task 1 fixture project, reading typed rows back with `rusqlite` (`Value::Text`/`Integer`/`Real`/`Null`), plus two edge tests that kill the remaining mutants.

Task verify `cargo test -p osq-kernel-storage --test read_model` passes (5 tests). `sh scripts/verify-rust.sh` passes with `mutation check not run: OSQ_DIFF is not set`. `cargo mutants -p osq-kernel-storage -f` over the three model files reports 0 missed (34 caught, 7 unviable); `lib.rs` yields no mutants.

## Deviated

- New error type: `src/read/error.rs` is outside the task's `scope`, so I could not add a variant to `StorageError`. `write_read_model` and `build_read_model` return a new `ReadModelError` declared in `src/model/error.rs`; `build_read_model` wraps `read_archive`'s `StorageError`.
- `remove_existing` is written `if db_path.exists() { fs::remove_file(db_path)?; }` rather than matching `ErrorKind::NotFound`. Same behaviour (a stale file or directory is removed before open), and it leaves no uncovered comparison for the mutation check.
- Extra tests beyond the three scenarios reuse the closest scenario name in their `Covers:` tag, the convention task 1 used for its `reading_events.rs` edges.
- Doc order: each public function's doc ends with its `Implements:` line(s), with `# Errors` above them, per the task's acceptance wording.

## Missing context

- The task fixed the function names but not their signatures. I chose `write_read_model(db_path: &Path, snapshots: &[ChangeSnapshot]) -> Result<(), ReadModelError>` and `build_read_model(project_root: &Path, db_path: &Path) -> Result<(), ReadModelError>`; task 4's golden test will call them, and the error type is `osq_kernel_storage::model::ReadModelError`.
- Because task 1's `StorageError` is out of scope, the crate now has two error types; the planner may want one.
