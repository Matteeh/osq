## Acceptance

- [ ] New `crates/apps/cli/src/lib.rs` holds `features()`, `CliResult` and `run_cli` as rust-cli "Feature registry", "Command line result", "CLI help" and "Command dispatch" say, and `main.rs` only does what "CLI entry point" says. `Cargo.toml` keeps the `osq-rs` binary and its dependencies.
- [ ] Tests in `crates/apps/cli/tests/` prove every scenario of the rust-cli delta, each test doc naming `Covers: rust-cli/<scenario>`. "Unknown command", "Help from the features' data" and "First feature wins" call `run_cli` with small test features defined in the test. The binary scenarios run `env!("CARGO_BIN_EXE_osq-rs")`.
- [ ] A new fixture project under `crates/apps/cli/tests/fixtures/` holds the files `inbox`, `queue` and `query` read, at least one change folder and an `openspec/queue.md` with one item. Each binary run copies it into a new folder under `CARGO_TARGET_TMPDIR`.
- [ ] Every public item ends its doc with `Implements: rust-cli/<requirement>`, and `cargo fmt --all` then `sh scripts/verify-rust.sh` pass.

## Details

Write no command name, summary or usage text in `osq-cli`; take them from
each feature's `commands()`. The expected stdout of "Commands through the
binary" is what the feature's own `run` returns on a second fresh copy, so
the test pins no feature's text. The cargo-mutants gate covers `main.rs` too,
and the binary tests check its exit code and streams.

## Scenarios

- rust-cli: CLI crate ownership
- rust-cli: Registered features
- rust-cli: Commands through the binary
- rust-cli: Feature error through the binary
- rust-cli: Unknown command
- rust-cli: Help from the features' data
- rust-cli: Help lists every registered command
- rust-cli: First feature wins
- rust-cli: Binary exit code
