## Acceptance

- [ ] `merge_ownership` in `crates/kernel/linter/src/gates/change.rs` gives a capability no globs when its delta's `removed` names `Code ownership` and its `added` and `modified` hold none, as rust-linter "Change ownership" says. An ADDED or MODIFIED `Code ownership` still replaces the living globs, and `link_gates` and `build_link_graph` still read living globs only.
- [ ] Two new fixture changes under `crates/kernel/linter/tests/fixtures/link-gates-ownership/openspec/changes/`, each delta a `spec.md` whose REMOVED requirement carries `**Reason**` and `**Migration**` lines: `003-retire`, with a `keep` delta that REMOVES `Code ownership` and a `fresh` delta that ADDS `Code ownership` over `crates/fresh/**`, `crates/keep/**` and `crates/split/**`; and `004-orphan`, with only the `keep` delta.
- [ ] New `crates/kernel/linter/tests/link_gates_removed_ownership.rs` proves "A change removes a capability's ownership" and "Removed ownership with no new owner" the way `link_gates_ownership.rs` proves its scenarios, each test doc naming `Covers: rust-linter/<scenario>`.

## Details

Add no fixture file outside the two new change folders, since the other
ownership tests read the same fixture. The proposal's verify needs this fix:
its corpus link gates run with this change's deltas live, and without it every
file under `crates/apps/cli/` is owned by both rust-workspace and rust-cli.
