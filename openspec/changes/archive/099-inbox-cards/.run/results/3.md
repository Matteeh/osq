## Changed

Added `src/core/status/dispatch-session.ts`, exporting `runCardSession`,
`CardSessionOptions`, `CardInput`, and `Launcher`. It is a private
`CardSession` class whose methods keep the run loop small and under the
function budget.

- `runCardSession` derives the ordered items with `readDispatchItems` plus
  `orderDispatchItems`, moves each item the reviewer set aside behind the rest
  in set-aside order, and prints `formatCardScreen` for the first item with its
  `readDispatchCard` card.
- A key from `cardKeys` prints `── <label> ──`, awaits `launch` with its
  arguments, prints `── exit <code> ──`, and derives again. The reject key asks
  `Reason: ` through `input.line` first and passes the answer as one extra
  argument; an empty or null answer shows the same card without launching.
- Re-deriving after every key means an item that is gone gives way to the next
  card, an item still present shows its card afresh, and a new item that
  appeared while a card was open joins the order at the next key.
- `n` records the first item's identity and moves it behind the others for the
  rest of the session; a recorded item that is no longer derived drops out.
- `q`, `\u0003`, a null key, or the abort signal ends the loop; any other key is
  ignored. The pending `input.key()` promise is cached, so waiting, the first
  card after it, and every later card share at most one outstanding read.
- With no items it prints `Nothing needs you. Waiting for new items (q to
  quit).`, watches with `watchDispatch`, and on the first derivation with items
  closes the watch, calls `sound.notify(at)` once, and opens the first card.
  `sound.notify` is only ever called from that arrival path, so it never plays
  while a card is shown. The session writes no files.

Added `tests/dispatch-session.test.ts` with a scripted `CardInput` that leaves
a later key pending, a recording launcher that writes `.run/approved` the way
`osq approve` would, a recording sound, a fake watcher, an immediate debounce
scheduler, and a manual `every` timer. Tests cover approve-and-move-on, item
still present, reject with a reason, empty reason, skip cycling, a set-aside
item that goes away, empty-then-arrival (manual poll, one notify, one pending
key read), no sound while a card is open, an ignored key, quitting on a card
and while waiting, and signal abort on a card and while waiting. No test waits
on a real timer.

## Deviated

- The delta calls the skipped ordering "skipped", but `tests/no-skipped-in-src.test.ts`
  forbids that word anywhere under `src/`. The implementation and its comments
  use "set aside" instead; behaviour is unchanged.
- The scenario `Skip` is realized with an `n`-then-`n` cycle, and a separate
  test covers "a skipped item that goes away," since both are required.
