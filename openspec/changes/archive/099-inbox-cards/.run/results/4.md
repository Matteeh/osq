## Changed

Added `src/cli/inbox-terminal.ts` with the two terminal defaults:

- `createTerminalInput(stream)` returns a `CardInput`. `key()` turns raw mode
  on for exactly one read and off again in a `finally`; leftover bytes from a
  chunk stay buffered for the next call. `line(question)` writes the question
  to stdout, turns raw mode off, and reads until a newline, keeping anything
  after it buffered. `setRawMode` is optional, so a stream without it still
  works.
- `createChildLauncher(projectRoot)` spawns `process.execPath` with this
  module's sibling `bin.ts` (under tsx: `--import <import.meta.resolve('tsx')>`)
  or `bin.js` when built, plus the key's arguments, `cwd` the project root,
  `stdio: 'inherit'`, never a shell. It resolves with the exit code, or 1 when
  the child ends by a signal or fails to start. A no-op `SIGINT` listener is
  installed for the child's lifetime, so Ctrl-C reaches the command and not
  osq.

Wired the card session into `inboxDispatchCommand`. It now takes `isTerminal`,
`input`, and `launch`. `--json` and `--follow` keep their exact old paths; when
`isTerminal()` is true and neither is set it builds the session's seams in
`inbox-terminal.ts` defaults and runs `runCardSession` with the inbox sound.
The terminal check mirrors `defaultIsTerminal` in `src/cli/approve.ts`. The
session does not receive the `--follow` abort signal, so that SIGINT handler
cannot end the session; the launcher keeps osq alive while a child runs.

Updated README.md: the Commands list line for `osq inbox` says it opens cards
on a terminal, and the Human Attention Inbox section gains a paragraph that
lists the keys (`a`, `r`, `x`, `c`, `p`, `f`, `s`, `n`, `q`), says a key runs
the osq command as a child process on the same terminal, says the land command
is shown under `Run yourself:` to copy, and says a non-terminal stdout or
`--json`/`--follow` prints as before.

Added `tests/inbox-cards.test.ts`: the terminal session shows the approval
card and `Keys:` block and resolves without launching; a non-terminal prints
the old text and never touches the injected input or launcher; `--json` wins
over a terminal; `createTerminalInput` records raw on/off around a key, reads
from a stream without `setRawMode`, and reads a line with raw off; the real
`createChildLauncher` resolves `--version` with 0, and a bad command with 1.

## Deviated

- `inboxDispatchCommand` does not forward its `signal` to `runCardSession`.
  Task 3's session checks abort at its next key read, so forwarding the
  `--follow` abort would end the session right after the child exits, not just
  the child. The task's SIGINT acceptance and the proposal's "Ctrl-C stops
  only the command" are better met by the launcher's temporary ignore listener
  plus dropping the signal; `signal` still drives `--follow` unchanged.
- Added three tests beyond the four named scenarios (json precedence, the
  `line` raw-off path, and a failed child) to pin the requirement clauses that
  the scenario list folds into "Raw mode around a key" and "Real child".

## Missing context

- The delta fixes `createTerminalInput(stream)` but not where `line(question)`
  writes. It writes to `process.stdout`, which is the terminal the session
