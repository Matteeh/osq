## Changed

Added `src/core/status/dispatch-keys.ts`, exporting `CardKey`, `CardKeys`,
`cardKeys(item)`, and `formatCardScreen(total, item, card, keys)`.

- `cardKeys` walks the item's commands in order. `osq approve`, `osq retry`,
  `osq reject`, `osq check`, `osq verified`, and `osq show` map to their keys;
  `osq verified <id> --passed|--failed` becomes the `p`/`f` pair. Each key
  carries its `label`, its `args` without the leading `osq`, and `asks`
  (`'reason'` only for reject, whose args end at `--reason`). Commands that do
  not start with `osq ` or whose verb is unknown are returned unchanged in
  `manual`.
- `formatCardScreen` returns the `Needs you (<total>):` header, the card body
  from `formatDispatchCardBody`, the `Keys:` block (`  <key>  <label>`, then
  `  n  skip`, `  q  quit`), and, only when present, the `Run yourself:` block.

Exported `formatDispatchCardBody(item, card)` from
`src/core/status/dispatch-text.ts` (the header, reason, and kind body, before
`Actions:`) and rebuilt the existing `cardLines` on top of it, so
`formatDispatchText` and `osq inbox` print exactly what they did before.

Added `tests/dispatch-keys.test.ts`, which reads items with `readDispatchItems`
from temporary projects and covers every "Card keys" scenario: approval keys,
change-level halt keys (including the reject reason ask), verify keys, the
worktree land case (git pipeline manual, `s` the only key), and the screen.

## Deviated

- `cardKeys` returns `{ keys: CardKey[]; manual: string[] }` (the exported
  `CardKeys` type), and `formatCardScreen`'s fourth parameter is that whole
  result, so the screen can print the manual commands. The delta names the
  parameter `keys` but also requires manual commands to be returned, so the
  object is the only shape that carries both. Task 3 should read the typed
  signatures in `dispatch-keys.ts`.
- `formatCardScreen` returns a single `string` joined with `\n`, matching
  `formatDispatchText` and `formatInboxText`. `formatDispatchCardBody` returns
  `string[]` because the delta calls it "the card lines before `Actions:`".

## Missing context

- The delta's `formatCardScreen(total, item, card, keys)` does not fix the type
  of `keys` (key list versus the full mapping result). I chose the full result
  for the reason above.
