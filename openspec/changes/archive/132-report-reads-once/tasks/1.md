## Acceptance

- [ ] `src/core/report/stream-reads.ts` exports the port below, built on `AsyncLocalStorage` from `node:async_hooks`. A nested `withStreamReads` reuses the outer scope, and `withStreamReads` resolves to what its work resolves to.
- [ ] Inside a scope, calls to `readParsedFile` for one resolved absolute path with the same parser read the file once and resolve to the same object, including calls that start before the first read finishes. The scope keeps the parsed result, never the file text.
- [ ] Outside any scope, every call reads the file from disk. Two separate `withStreamReads` calls share nothing.
- [ ] A missing or unreadable file resolves to null, in and out of a scope. A parser that throws rejects the call.
- [ ] `readEventStream` parses with `parseEventLines` from `report-events.ts`, then removes `data.output` from every `verify_ran`, `regressed`, and `recertification` event, and leaves every other field and event as parsed.
- [ ] `readEventStream` freezes each event and its `data` object, so assigning to either throws.
- [ ] `tests/report-stream-reads.test.ts` covers each line above, counting reads with `mock.method` on the default export of `node:fs/promises`, and checks the file on disk still holds the `output` it removed.

## Port

```ts
export function withStreamReads<T>(work: () => Promise<T>): Promise<T>;
export function readParsedFile<T>(
  filePath: string,
  parse: (content: string) => T,
): Promise<T | null>;
export function readEventStream(
  filePath: string,
): Promise<readonly Readonly<Record<string, unknown>>[] | null>;
```

## Details

The module reads with `fs.readFile(path, 'utf8')` from the default import of
`node:fs/promises`, as the report readers do today, so the test can count
reads. It keeps nothing at module level except the `AsyncLocalStorage`
instance and the set of log-carrying event types, and writes no file. No other
file changes in this task; task 2 routes the report through it.
