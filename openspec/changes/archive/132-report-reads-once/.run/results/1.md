## Changed

- Added `src/core/report/stream-reads.ts`: an `AsyncLocalStorage` read scope with
  `withStreamReads`, `readParsedFile`, and `readEventStream`. Inside a scope each
  resolved absolute path plus parser identity reads and parses the file once and
  shares one promise; outside a scope every call reads from disk. `readEventStream`
  parses with `parseEventLines`, drops `data.output` from `verify_ran`, `regressed`,
  and `recertification`, and freezes each event and its data. Read failures give
  `null`; parser throws reject.
- Added `tests/report-stream-reads.test.ts` covering every acceptance line, counting
  reads through `mock.method` on the default `node:fs/promises` export and checking
  the on-disk file still holds the removed logs.

## Deviated

- The log-carrying events get a fresh `data` object built without `output` instead
  of mutating and then deleting from the parsed object, because Biome's
  `noDelete` performance rule rejects `delete` and setting the key to `undefined`
  would leave the key present. Behaviour is the same: no `output` key, everything
  else unchanged, data and event frozen.
