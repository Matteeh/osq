## Changed

- `src/core/report/report.ts`: `getMetricsReport` keeps its signature and now
  returns `withStreamReads(() => buildMetricsReport(...))`; the old body moved
  into the new unexported `buildMetricsReport`. Every event-stream read now goes
  through `readEventStream`: `projectMeasuredTasks`, `readFirstTaskStartMs`,
  `readArchivedAtMs`, `hasRejectedEvent`, `collectDeadOutcomes`, the task-event
  loop (section 5) and the events-directory scan (section 6). The now-unused
  `parseEventLines` import was removed.
- `src/core/report/report-dependencies.ts`: `streamPairs` reads through
  `readEventStream`.
- `src/core/report/approval-flags.ts`: `changeEventTrouble` reads every task and
  change stream through `readEventStream`.
- `src/core/report/planning-economics.ts`: `readMeasuresTotals` reads task
  streams through `readEventStream`.
- `src/core/report/report-mutation.ts`: `readMeasuredEvents` reads task streams
  through `readEventStream`; the import swap is line-neutral.
- `src/core/report/planning-records.ts`: `readPlanRecords` reads through
  `readParsedFile(..., parsePlanRecords)` and returns `[]` for a null (missing)
  log; the now-unused `fs` import was removed.
- `src/core/status/queue-report-detail.ts`: `archivedEventMs` reads the
  change-level stream through `readEventStream` and still returns the first
  valid `archived` timestamp.
- `tests/function-budget.test.ts`: grandfather key renamed
  `core/report/report.ts#getMetricsReport` to `.../buildMetricsReport`; nothing
  else changed.
- `tests/report-reads-once.test.ts`: new test covering no double `.jsonl` reads,
  fresh reads on a second call (with an appended `tokens` line counted), and a
  source scan that fails when a report module other than `report-events.ts`,
  `stream-reads.ts` and `archive-record-run.ts` calls `parseEventLines`.

## Deviated

- The read-count test asserts every `.jsonl` under `specs/archive` plus every
  rejected `change.jsonl` is read once, rather than every `.jsonl` in the
  fixture. `osq report` never reads a rejected change's numbered task streams or
  `plan.jsonl` (only its change-level stream, for rejection detection), so a
  blanket "every fixture `.jsonl`" assertion would fail. The assertion covers
  every stream the report actually reads, and separately asserts no `.jsonl`
  path is read twice at all.
