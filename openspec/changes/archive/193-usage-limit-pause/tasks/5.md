## Acceptance

- [ ] New `src/core/status/inbox-paused.ts` exports the `PausedItem` type (`change`, `task`, `pausedUntil`, `command`) and a reader that builds the paused items of status-inspection "Paused task in the inbox". It takes the status overview and the clock, reads each approved active change's pause with `readActivePause` from task 2's `src/core/run/usage-pause.ts`, and takes the task title the way `projectRunning` in `inbox.ts` does.
- [ ] `Inbox.running` in `inbox.ts` becomes `(RunningItem | PausedItem)[]`. `RunningItem` keeps its fields. `inbox.ts` is at 248 lines and must stay at or under 250, so change only that property and add the one import. `projectRunning` still returns live items only.
- [ ] `readInbox` in `inbox-projection.ts` merges the paused items into `running`, sorted with the live items by numeric change and task order with `compareNumericPrefix`. It skips a paused task that also has a live running item.
- [ ] `formatInboxText` in `inbox-text.ts` renders a paused item as the scenario's row, with `formatPauseUntil`. Live rows stay as they are.
- [ ] `RunningGroup.tsx` shows a paused item with `paused until <YYYY-MM-DD HH:MM> UTC` in place of the elapsed time, as web-inspection "Dashboard home" says. The UI imports only types from `src/`, so format the time inside the component, from the ISO string's date and its hours and minutes. Live items render as today.
- [ ] New `tests/usage-pause-inbox.test.ts` proves "Paused task", "No item for a passed pause" and "Paused running item keys" through `readInbox` and `formatInboxText`, and runs the real `osq --json` once, as `tests/inbox-validator-failing.test.ts` does. New `tests/ui-home-paused.test.tsx` proves "Paused task on home" by rendering `HomeView`, as `tests/ui-home.test.tsx` does. Take expected values from the scenarios.
- [ ] Each exported function and component you add or change carries one `@scenario <capability>: <name>` line per scenario it serves.
