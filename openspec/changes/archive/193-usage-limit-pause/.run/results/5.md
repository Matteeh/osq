## Deviated

`PausedItem` declares the live-only fields `pid`, `startedAt` and `elapsedSeconds` as `never`, and `projectPaused` casts its four-field literal to `PausedItem`. The runtime object still has exactly `change`, `task`, `pausedUntil` and `command`, so the JSON contract (and the "Paused running item keys" scenario) holds; the `never` members exist only so `(RunningItem | PausedItem)[]` keeps `.pid` / `.startedAt` / `.elapsedSeconds` legally accessible.

The reason is `tests/inbox.test.ts` (an entry, not in scope, no `tests.modify`): it reads `.pid`, `.startedAt` and `.elapsedSeconds` directly off `Inbox['running'][number]`, and does arithmetic with `.elapsedSeconds`. With a plain four-field `PausedItem`, that preexisting test would fail `pnpm verify`'s `typecheck:cli`, which kills this task. A narrower `PausedItem` with exactly the four members is only possible together with a `tests.modify` for `tests/inbox.test.ts` that narrows each running item before reading those fields.

## Missing context

The task should have set `tests.modify: true` and included `tests/inbox.test.ts` in `scope`, or declared how the union should stay compatible with its direct property access. I worked around it with `never` members rather than change that file.
