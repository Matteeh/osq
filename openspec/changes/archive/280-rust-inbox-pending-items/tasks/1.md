## Acceptance

- [ ] `read_usage_pause`, `read_autopilot_stop`, `watch_state_dir`, `read_after_land_failure` and `read_queue_titles`, with `PauseRecord`, `AutopilotStop`, `AfterLandFailure` and `QueueTitle`, are exported from the crate root and behave as rust-storage "Usage pause record", "Autopilot stop record", "After-land failure record" and "Queue item titles" say.
- [ ] New `crates/kernel/storage/tests/reading_pending_records.rs` proves the pause, stop and after-land scenarios, and new `crates/kernel/storage/tests/reading_queue_titles.rs` proves the queue scenarios, one test per scenario, each table row checked, each test's doc naming `Covers: rust-storage/<scenario>`.
- [ ] Every existing storage test passes unchanged, rust-storage "One frontmatter reader" included.

## Details

Put the three record readers in `src/read/pending.rs` and the queue reader
in `src/read/queue.rs`. Split frontmatter only with `parse_frontmatter`, as
`manual.rs` does, and test a timestamp with `timestamp_ms` from `text.rs`.
Parse `after-land.json` with `serde_json`, which storage already depends on.
Add `sha2.workspace = true` to the storage manifest for `watch_state_dir`;
`Cargo.lock` follows. Canonicalize with `std::fs::canonicalize`, falling back
to `std::path::absolute`.

`crates/features/plan/src/queue/parse.rs` is the plan feature's Rust port of
`parseQueue`. Copy the rules you need from it into `src/read/queue.rs`; a
kernel never depends on a feature (ADR 022), and the plan feature stays as
it is. Never read anything under `src/` from Rust; the TypeScript files are in
`entry` only so you can port them.

Every expected value is in the delta's tables; they were printed by
TypeScript's readers. Write each row's files under its own folder in
`CARGO_TARGET_TMPDIR`, as `reading_land_facts.rs` does, and pass a scratch
home folder, never the real home.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/280-rust-inbox-pending-items`, so the link gates
see this change's new requirements.
