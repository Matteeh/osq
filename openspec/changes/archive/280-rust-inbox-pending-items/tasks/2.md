- [ ] The Needs you group holds the after-land-failed and autopilot-stopped items of rust-inbox "After-land failed item" and "Autopilot stopped item", and lists every item in the order "Needs-you order" gives.

## Details

The pause reader needs each change's folder path, which `ChangeSnapshot` does
not hold, so read pauses in `read.rs` next to the snapshots, from the
`ChangeEntry` paths. The home is the `HOME` environment variable, read once
in `run` as `stacked_folders` already reads it; with no `HOME` there is no
after-land item. Keep the new lines pure functions of the snapshots and
records, with the IO in `run` and `read.rs` (ADR 023). Reuse `compare_ids`
and `change_id` from `groups/mod.rs` and the running line's head from
`groups/running.rs`.

In the test, build each row's project under its own folder in
`CARGO_TARGET_TMPDIR`, named after the test and the row. Write the
`after-land.json` rows at `watch_state_dir(<project>, $HOME)` and remove that
folder when the row ends, even when it fails, with a guard whose `Drop`
removes it. Do not set process environment variables in tests. The live
running task in "Paused tasks" uses the lock format `tests/running.rs`
writes, with `std::process::id()` as its pid. Every expected line is in the
delta's tables; TypeScript's `dist` printed them.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/280-rust-inbox-pending-items`, so the link gates
see this change's new requirements.
