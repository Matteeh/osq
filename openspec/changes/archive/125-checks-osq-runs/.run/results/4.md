## Changed

- `src/core/status/next-step.ts`: dropped `verification-pending` from
  `NextStepState`, deleted the `readVerification` import, and replaced
  `readArchivedNextStep` with an unconditional `{ state: 'landed', command:
  null, detail: null }` for every archived folder.
- `src/core/status/queue-state.ts`: dropped `verification-pending` from
  `QueueItemState`, removed the `isVerificationPending` import, and made a
  single archived association derive as `landed`.
- `src/core/status/queue-report-detail.ts`: `readQueueReportItem` treats only
  `landed` as an archived row when deriving `plannedToLandedSeconds`.
- `src/core/status/dependency-readiness.ts`: deleted `isVerificationPending`
  and the `readVerification` import; `isDependencyDone` counts every archived
  dependency as met.
- `src/core/status/status.ts`: removed the `changeTrees` and
  `listPendingVerifications` imports, the `pendingVerifications` field on
  `StatusOverview`, its projection, and the `Verification pending:` section of
  `formatStatusOverview`.
- `src/core/status/show.ts`: removed the `readVerification` import. Added
  `afterLanding?: string` to `SpecDetails` with a `readAfterLanding` helper
  built from `parseHumanSteps`; `withNextStep` attaches the notes for active
  and archived changes and builds the `Verification:` history from the
  timeline, including it only when it has at least one check or outcome row.
  `formatSpecDetails` prints `After landing:` in the verification section's
  place, each line indented two spaces.
- `tests/next-step.test.ts`: dropped the `readVerification` and
  `listPendingVerifications` cases and import, and rewrote the archived next
  step and explicit status cases for `landed` and the absent pending section.
- `tests/show-next-step.test.ts`: the failed-outcome and check cases now expect
  `landed` with no pending command while still printing the event rows.
- `tests/verification-dependents.test.ts`: archived dependencies with a
  `verification` key now count as met; the archived queue association derives
  as `landed` and frees its dependent.
- `tests/show-after-landing.test.ts` (new): covers "Plain archived change",
  "Failed verification", "Verification pending queue dependency", "Full status
  with next steps", "Archived change with an outcome", "After-landing notes",
  and "Archive without verification events", plus active after-landing notes
  and their ordering after the verification section.

`node --import tsx --test tests/show-after-landing.test.ts` passes, and so does
`pnpm verify` (typechecks, build, full suite, lint).
