## Changed

- `src/watcher/archiver.ts`: removed `readArchivedVerification` and the
  `VerificationRequirement` import. `relocateArchivedSpec` now writes an
  `archived` event whose data is exactly `{ archivePath }`.
  `checkAndArchiveSpec` reads the proposal's `check` with `readCheckCommand`
  and, after the change-level verify, runs it through `verifyArchiveStep` with
  target `change`; a false result calls `restoreArchiveSpecs` and returns
  false, exactly as a red change-level verify does.
- `src/core/vcs/sync-verify.ts`: added `readCheck`, which reads the change
  folder's proposal with `parseSpecMdFromFolder`, `parseFrontmatter`, and
  `readCheckCommand`. For an archived change `runSyncVerify` runs the check
  through `runOne` after the verify, with a null change folder and before the
  `synced` event. `runOne` takes a `kind` so a red check stops with
  `<folder>: check failed on osq/<folder> merged with <default branch>:` and
  the output tail. `src/core/vcs/sync-main.ts` is unchanged.
- `tests/change-check.test.ts` (new): archive-step coverage for "Check passes",
  "Check fails", and "After-landing steps" with a local `node check.cjs`, plus
  `syncWithDefaultBranch` coverage for "Red check after the merge", "Sync
  records its check", and "Archived check runs without it". The last sets
  `OSQ_CHANGE` in osq's own environment and asserts the archived check sees no
  value.

None.
