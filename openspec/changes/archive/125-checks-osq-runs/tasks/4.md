## Acceptance

- [ ] `readNextStep` returns `landed` with a null command and a null detail for every archived change. `NextStepState` loses `verification-pending`, and `readArchivedNextStep` goes. This covers the status-inspection delta's "Change next step", "Next step commands", and "Next step detail and format".
- [ ] An archived queue association derives as `landed`, and `QueueItemState` loses `verification-pending`. `readQueueReportItem` treats only `landed` as an archived row. `isVerificationPending` goes, and `isDependencyDone` counts every archived dependency as met. This covers "Brief queue state projection" and "Explicit status with next steps".
- [ ] `StatusOverview` loses `pendingVerifications`, and `osq status` no longer prints `Verification pending:`.
- [ ] `osq show` builds the `Verification:` history from the timeline and includes it only when there is at least one row. It no longer calls `readVerification`. It adds `afterLanding` from `parseHumanSteps` for an active or archived change whose steps are not empty, and prints `After landing:` right after the `Verification:` section's place, with each line indented by two spaces. This covers "Show next step" and "Show after-landing notes". `show.ts` is on the line-budget allow list.
- [ ] After this task nothing in the scope imports `src/core/status/verification.ts`; task 5 deletes it. That includes `tests/next-step.test.ts`, which drops its `readVerification` and `listPendingVerifications` cases.
- [ ] Each listed test that expects `verification-pending`, a pending dependency, a `Verification pending:` section, or an `osq check` or `osq verified` next step now expects what the delta says.
- [ ] New `tests/show-after-landing.test.ts` covers "Plain archived change", "Failed verification", "Verification pending queue dependency", "Full status with next steps", "Archived change with an outcome", "After-landing notes", and "Archive without verification events".

## Details

`tests/verification-dependents.test.ts` writes `archived` events with a
`verification` key directly; its cases now show that key no longer holds a
dependent back. `tests/show-next-step.test.ts` writes `check_ran` and
`verification_recorded` events the same way.
