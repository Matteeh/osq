## Acceptance

- [ ] After the change-level verify passes, the archiver reads the proposal's `check` with `readCheckCommand` and runs it through `verifyArchiveStep` with target `change`. When that returns false, it calls `restoreArchiveSpecs` and returns false, as it does for a red change-level verify. This covers the watcher-and-harness delta's "Change check at archive".
- [ ] The `archived` event's data is exactly `{ archivePath }`. `readArchivedVerification` and the `VerificationRequirement` import leave `src/watcher/archiver.ts`. `src/core/spec/human-steps.ts` does not change in this task. This covers "Archived event without a verification requirement".
- [ ] For an archived change, `runSyncVerify` reads the proposal's `check` from the change folder with `parseSpecMdFromFolder`, `parseFrontmatter`, and `readCheckCommand`. It runs the check through `runOne` after the verify and before the `synced` event, with a null change folder. A failure's message reads `<folder>: check failed on osq/<folder> merged with <default branch>:` and the output tail. `src/core/vcs/sync-main.ts` does not change; it is at 249 of 250 lines.
- [ ] New `tests/change-check.test.ts` covers the watcher-and-harness delta's "Check passes", "Check fails", and "After-landing steps" through the archive step, with a local `node check.cjs` written into the temporary project root.
- [ ] The same file covers the version-control delta's "Red check after the merge" and "Sync records its check" through `syncWithDefaultBranch` on an archived change in a worktree.
- [ ] The same file covers the watcher-and-harness delta's "Archived check runs without it": a check that prints `OSQ_CHANGE` during the sync sees none while osq's own environment sets it.

## Details

`tests/archive-verify-path-missing.test.ts` shows how to lay out a change
folder and run the archive step. `tests/vcs-sync.test.ts` builds a repository,
a worktree, and an archived change, then moves the default branch. Its
"Red verify after the merge" case is the model for the red check.
