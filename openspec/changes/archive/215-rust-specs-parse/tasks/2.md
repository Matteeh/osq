## Details

The value types, their fields in this order, and how they serialize:

- `Frontmatter { data: yaml_rust2::yaml::Hash, body: String }`, not serialized
- `SyntaxError { line: usize, message: String }`, the 1-based line in the parsed text
- `Proposal { title, depends_on: Vec<String>, fixes: Vec<String>, reads: Vec<String>, goal, contract, contract_tables: usize, non_goals, delta, verify }`
- `TaskFile { title, verify, scope: Vec<String>, entry: Vec<String>, skills: Vec<String>, tests_modify: bool, verify_starts: VerifyStarts, acceptance: Vec<String> }`
- `VerifyStarts { Red, Green, Any }`, serialized as `red`, `green` and `any`
- `ChecklistItem { number: Option<u32>, title, checked: bool, section: Option<String>, line: usize }`
- `Sidecar { group, tags: Option<Vec<String>> }`
- `SidecarError { Syntax(SyntaxError), Problems(Vec<String>) }`
- `SpecsError { Read { path: PathBuf, message: String }, Syntax { path: PathBuf, line: usize, message: String }, Sidecar { path: PathBuf, problems: Vec<String> } }`

`parse_frontmatter(text) -> Result<Frontmatter, SyntaxError>`,
`parse_proposal(text) -> Result<Proposal, SyntaxError>`,
`parse_task_file(text) -> Result<TaskFile, SyntaxError>`,
`parse_task_list(text) -> Vec<ChecklistItem>` and `parse_sidecar(text) ->
Result<Sidecar, SidecarError>` are pure. Each `read_*(path: &Path)` reads the
file to a string and calls its parser: `read_living_spec` gives task 1's
`LivingSpec`, `read_delta` its `Delta`, and the others this task's values.

Reuse task 1's `js_trim` for every trim and `section` for the proposal's
sections and the task file's Acceptance. Read YAML with `yaml-rust2`'s
`YamlLoader::load_from_str`; its `ScanError` marker's `line()` is the YAML's
1-based line, so a frontmatter error's line adds 1 for the opening `---`. A
YAML text with no document is empty YAML. A list item's text follows
"Frontmatter values"; for a YAML real, use the text `yaml-rust2` keeps.
Hand-write every pattern; add no regex crate.

Crate layout: the parsers sit under `src/document/`, with
`src/document/mod.rs` as its root and one file per document kind, and the
readers and `SpecsError` under `src/read/`, with `src/read/mod.rs` as its
root. `lib.rs` declares both modules and re-exports their public items.
Every `.rs` file stays under 250 lines and every function under 80.

The non-UTF-8 and missing-file cases write or name files under
`env!("CARGO_TARGET_TMPDIR")`; the successful reads use small fixture files
in `tests/fixtures/documents/`. Run `cargo fmt --all` before exiting.
