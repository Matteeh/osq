## Details

The goldens were printed by TypeScript and are the expected values; never
edit a golden file, a living copy, or a test or fixture from tasks 1 and 2.
Say in `## Deviated` which rule a fix changed and why.

The corpus test finds documents the way the goldens were printed: in each
archived folder, every `specs/<capability>/spec.md` as a delta spec, every
`tasks/*.md` as a task file, `proposal.md` and `tasks.md`. It compares them
with `deltas.json`, `tasks.json`, `proposals.json` and `task_lists.json` by
path, relative to the repository root with `/` separators, and checks that
the set of paths found in folders 001 to 214 equals the set in each golden.
"Living specs read" reads every `openspec/specs/<capability>/spec.md` with
`read_living_spec` and its `osq.yml` with `read_sidecar`.

The digest replaces every string inside a value that is longer than 64
UTF-16 code units, counted with `str::encode_utf16`, with `fnv1a64:` and the
16 lowercase hex digits of the 64-bit FNV-1a hash of its UTF-8 bytes: offset
basis `0xcbf29ce484222325`, prime `0x100000001b3`, each byte XORed in before
the wrapping multiply. Object keys, `path` and `capability` stay as written.
JSON numbers compare as numbers. Read every file once per test binary; a
`std::sync::OnceLock` may share the parsed goldens.

Keep every test file under 250 lines and every function under 80. Workspace
lints include `clippy::pedantic` and `-D warnings`. Run `cargo fmt --all`
before exiting.
