## Details

The value types, their fields in this order, and how they serialize:

- `Requirement { name, body, scenarios: Vec<Scenario>, raw }`
- `Scenario { name, when: Vec<String>, then: Vec<String>, outcomes: Vec<Outcome>, raw }`
- `Outcome { text, rows: Option<Vec<BTreeMap<String, String>>> }`
- `LivingSpec { title, purpose, requirements: Vec<Requirement>, code_ownership: Vec<String> }`, the purpose empty text when there is none
- `Delta { title, purpose, added: Vec<Requirement>, modified: Vec<Requirement>, removed: Vec<String>, renamed: Vec<Rename>, invalid_renames: Vec<String>, unpaired_renames: Vec<UnpairedRename> }`
- `Rename { from, to }`, `UnpairedRename { side: RenameSide, name }`, and `RenameSide { From, To }` serialized as `FROM` and `TO`

Text fields are `String`. A table row that names one column twice keeps the
last cell, as a later map insert does.

`parse_living_spec(text) -> LivingSpec`, `parse_delta(text) -> Delta`,
`parse_requirement(block) -> Requirement` and `parse_scenario(block) ->
Scenario` cannot fail: every input text reads. `section(body, heading) ->
String`, `code_ownership(text) -> Vec<String>`, `js_trim(text) -> &str` and
`normalize_requirement_name(name) -> String` are pure too. Task 2 reuses
`js_trim` and `section`.

Crate layout: everything sits under `src/markdown/`, with `src/markdown/mod.rs`
as its root and one file per concern, such as `text.rs` for the JavaScript
whitespace, trimming, line-ending and code-fence rules, `requirement.rs`,
`scenario.rs`, `table.rs`, `living.rs`, `ownership.rs`, `delta.rs` and
`section.rs`. `lib.rs` declares `pub mod markdown` and re-exports its public
items; task 2 adds its own modules to it. Hand-write every pattern; add no
regex crate. The requirement texts give each rule; where they quote a
TypeScript pattern, `\s` is JavaScript's whitespace and `$` the end of the
text. Every `.rs` file stays under 250 lines and every function under 80;
workspace lints include `clippy::pedantic` with `-D warnings`.

Put the tests in `tests/parsing_markdown.rs`, and in more
`tests/parsing_markdown_*.rs` files when one grows past 250 lines. Write each
table row's input as a Rust string literal with the escapes the table shows.
Run `cargo fmt --all` before exiting.
