## Changed

Added the Markdown half of the specs kernel under `crates/kernel/specs/src/markdown/`:

- `text.rs`: JavaScript whitespace (`char::is_whitespace` minus U+0085 plus U+FEFF), `js_trim`, `normalize_requirement_name`, line-ending/BOM normalization, and the code-fence mask.
- `types.rs`: `Requirement`, `Scenario`, `Outcome`, `LivingSpec`, `Delta`, `Rename`, `UnpairedRename` and `RenameSide`, each deriving `Debug`, `Clone`, `PartialEq`, `Eq` and `Serialize`, with `FROM`/`TO` rename sides.
- `requirement.rs`, `scenario.rs`, `table.rs`: requirement blocks, scenario bullets, outcome tables and block collection.
- `living.rs`, `ownership.rs`, `delta.rs`, `section.rs`: living specs, Code ownership sources, delta operations and Markdown sections.
- `lib.rs` declares and re-exports `markdown`; `Cargo.toml` names exactly `osq-core`, `serde`, `serde_json` and `yaml-rust2` with `.workspace = true`; `Cargo.lock` records the new crate dependencies.

Added `tests/parsing_markdown.rs` and `tests/parsing_markdown_docs.rs` with one case per table row for all sixteen acceptance scenarios. Every public function's doc ends with `Implements: rust-specs/<requirement>` and every test's doc names `Covers: rust-specs/<scenario>`.

`cargo test -p osq-kernel-specs --test parsing_markdown`, `cargo clippy`, `cargo fmt --check` and `sh scripts/verify-rust.sh` pass. A manual `cargo mutants -p osq-kernel-specs` run reported 173 caught, 20 unviable, 0 missed and 0 timeouts.

## Deviated

- Bullets under REMOVED and the valid FROM/TO headers take a requirement header case-insensitively per the delta's wording ("requirement header"), while TypeScript's REMOVED-bullet regex is case-sensitive. No archived document uses a lower-case header, so parity is unaffected.
- A line that trims to a lone `|` counts as a table row because the delta says a row starts and ends with `|`; TypeScript's `\|.*\|` pattern needs two pipes.
- Living and delta titles skip lines inside code fences, following "Lines inside a code fence never count as headings"; TypeScript's title regex does not apply the fence mask.
- A malformed first line makes `parse_requirement`/`parse_scenario` return its best-effort values (header text as the name and no scenarios where applicable) instead of failing, as the task requires those functions never to fail.
