# Task 4 result

## Changed

- Added `src/core/status/dispatch-follow.ts`. It exports `followDispatch`,
  `FollowDispatchOptions`, and `EveryFn`. `followDispatch(projectRoot, config,
  options)` prints `formatDispatchText(readDispatch(...))`, then
  `Waiting for new items (Ctrl-C to stop).`, watches the change trees through
  `createInvalidationHub` with `inbox.eventDebounceMs` and the injected
  `watch`/`schedule`, and derives every `inbox.pollSeconds` through `every`
  (default `setInterval`, handle with `cancel()`). Each derivation builds items
  from `readDispatchItems` + `orderDispatchItems` and prints
  `<HH:MM> + <summary>` per new item and `<HH:MM> - <summary>` per departed item
  (keeping the departed item's last text), then calls `sound.notify(now)` once
  when any `+` line printed. Derivations are single-flight: a batch or poll
  during one queues exactly one more. After each derivation it re-reads
  `options.trees` (default `changeTrees`) and, when `treeWatchPaths` changed,
  closes the hub, opens a new one over the new trees, and derives once more. A
  throwing derivation prints `osq inbox: <message>` to stderr and keeps
  following. An aborted `options.signal` cancels the poll, closes the hub, and
  resolves. It writes nothing to the project.
- `src/core/status/dispatch-text.ts`: added and exported
  `formatDispatchItemSummary(item)` and made `itemLine` call it, so the list
  text is unchanged and the follow lines reuse the same summary.
- `src/cli/inbox-dispatch.ts`: `inboxDispatchCommand` takes `follow`, `signal`,
  `sound`, `watch`, `schedule`, `every`, `now` (plus `stderr` and `trees`).
  With `follow`, it builds `createInboxSound(cwd, config)` only when no `sound`
  is given and runs `followDispatch`. With `follow` and `json`, it writes
  `osq inbox: --follow prints text; drop --json` to stderr and sets
  `process.exitCode = 1`. `registerInboxDispatchCommand` adds `--follow` and
  aborts the command's `AbortController` on SIGINT.
- `README.md`: the Commands list includes `osq inbox --follow`; the Human
  Attention Inbox section now describes what `--follow` prints, when it sounds,
  the players tried, the bell fallback, and all five `inbox` keys with defaults.
- Added `tests/inbox-follow.test.ts`: one summary-format test plus nine
  `followDispatch` scenarios (new halt sounds once, start silent, departure
  silent, poll finds an item at `pollSeconds * 1000`, two items in dispatch
  order sound once, item returns and sounds again, empty inbox waits until
  abort, tree change reopens the hub and derives once more) and two command
  tests (seams pass through and the loop resolves on abort; `--follow --json`
  writes stderr and exit code 1). It uses a fake watcher, a manual debounce
  scheduler, a manual poll timer the test fires, a counting `trees` seam, a
  recording sound, and fixture markers written like `tests/inbox-dispatch.test.ts`.
  No test waits on a real timer (progress is observed with `setImmediate`).

## Deviated

- `followDispatch`'s `sound` option defaults to a silent no-op; the command
  builds the real `createInboxSound` when no sound is passed, as the task
  details direct. This keeps the loop's tests soundless by default.
- The loop starts one derivation (`void runFollower`) after the initial print so
  the "read the trees after each derivation" rule also covers the first print.
  That run prints nothing when the queue is unchanged and never sounds for
  items present at start.
- Added an optional `stderr` seam and a `trees` seam to `inboxDispatchCommand`
  beyond the seven named options, to route the refusal line and the fake trees
  into the loop from tests.

## Outside scope

- After `signal` aborts, an already-in-flight derivation can still finish and,
  in a test whose temp project is removed immediately, print
  `osq inbox: Neither proposal.md nor spec.md found ...`. That is the specified
  "derivation that throws prints and keeps following" behavior; abort does not
  wait for in-flight work. Left as is.
