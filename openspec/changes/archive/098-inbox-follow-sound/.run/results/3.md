# Task 3 result

## Changed

- Added `src/core/status/inbox-sound.ts`. `createInboxSound(projectRoot,
  config, deps)` returns `{ notify(now) }` and exports `InboxSound`,
  `InboxSoundDeps`, and the `InboxSoundChild` seam type. `deps` holds
  `platform`, `path`, `spawn`, `bell`, `warn`, and `exists`, each defaulted
  (`spawn` = `node:child_process` with `stdio: 'ignore'`, `detached: true`,
  unref'd; `bell` = `\u0007` to stdout; `warn` = a line to stderr; `exists` =
  `fs.existsSync`). The sound plan and player are resolved once at build time:
  `off` does nothing, `bell` rings, `default` is `PACKAGE_ROOT/sounds/inbox.wav`,
  any other value resolves against the project root; a missing file warns once
  with `osq inbox: inbox.sound: <path> does not exist; using the bell` and
  rings. Players are `afplay` on darwin and the first of `pw-play`, `paplay`,
  `aplay` on linux, each found as a regular file with an execute bit in a
  `PATH` directory. `notify` checks local quiet hours (start inclusive, end
  exclusive, wrapping across midnight) and a `soundWindowSeconds` window, then
  either rings or spawns the player detached, ignoring output, and rings when
  the spawn emits an error or throws.
- Added `tests/inbox-sound.test.ts` with a recording harness (fake `spawn`,
  `bell`, `warn`, injected `platform` and `path`, real `exists`) and fake
  executable players in a temporary directory. It covers every "Inbox sound"
  scenario: linux order, darwin, no player, spawn error, bell/off, custom file,
  missing file (warn once), quiet hours across midnight with inclusive/exclusive
  boundaries, one sound per window, and a scan of every `.ts` file under
  `src/watcher/` and `src/harness/` for `inbox-sound` or `dispatch-follow`
  imports. No test makes a sound.
