# Task 1 result

## Changed

- Added `src/core/foundation/config-inbox.ts` with `InboxConfig`, `QuietHours`,
  `DEFAULT_INBOX_CONFIG`, `parseQuietHours`, and `validateInboxConfig`, modeled
  on `config-serve.ts`. Defaults are `sound: 'default'`, `quietHours: null`,
  `soundWindowSeconds: 5`, `eventDebounceMs: 200`, `pollSeconds: 30`; a partial
  block keeps each missing default and every invalid value throws a message
  naming its key.
- `src/core/foundation/config.ts`: imported the inbox module, added
  `OsqConfig.inbox?: InboxConfig`, put `DEFAULT_INBOX_CONFIG` on `DEFAULT_CONFIG`,
  and made `defineConfig` set `inbox` from `validateInboxConfig(config.inbox)`.
- `src/core/foundation/config-user.ts`: added `'inbox'` to the `Omit` list and
  declared `readonly inbox?: Partial<InboxConfig>`, exactly as `vcs` is declared.
- `src/index.ts`: exported the `InboxConfig` type plus `QuietHours`,
  `DEFAULT_INBOX_CONFIG`, `parseQuietHours`, and `validateInboxConfig`, matching
  how the serve block is exported.
- Added `tests/config-inbox.test.ts` covering every "Inbox configuration"
  scenario, including the config-file one through `loadConfig` on a temporary
  project, plus direct `parseQuietHours` coverage.

## Missing context

The task and delta do not pin the return shape of `parseQuietHours`. It returns
`{ start, end }` (minutes after local midnight) and the shape is exported as the
`QuietHours` type, so task 3 can import it that way.
