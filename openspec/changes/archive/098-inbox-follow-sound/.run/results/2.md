## Changed

- Added `scripts/make-inbox-sound.mjs`: a `node:`-only generator that computes
  an original two-tone chime (880 Hz then 1320 Hz, 8000 Hz mono) with a linear
  fade on each tone and `Math.round` per sample, wrapped in a minimal 16-bit
  PCM WAV. Writes to `argv[2]` when given, otherwise to `sounds/inbox.wav`
  under the repo root. Output is byte-for-byte deterministic.
- Added `sounds/inbox.wav`, the script's output (3244 bytes, under the 4096
  limit; `file` reports "WAVE audio, Microsoft PCM, 16 bit, mono 8000 Hz").
- `package.json`: added `sounds` to `files`. No other field changed.
- `tests/package-hygiene.test.ts`: added `sounds/` to `isAllowedPath` and
  asserted the packed tarball holds `sounds/inbox.wav`. All other checks are
  untouched.
- Added `tests/inbox-sound-file.test.ts`: runs the script with `node` into a
  temporary directory and covers every "Inbox sound file" scenario, plus
  determinism across two runs, non-silent samples, the default output path,
  and the `files` entry.

## Deviated

- The "writes to `sounds/inbox.wav` when no argument is given" test does not
  delete the shipped file first. `pnpm verify` runs test files in parallel, so
  a deletion window could race the `npm pack` read in `package-hygiene`. The
  test instead writes a sentinel, runs the script with no argument, compares
  the result to a fresh temporary generation, and restores the original bytes
  in a `finally`. The shipped file is never absent.
