## Changed

- `README.md`: the `**Steering.**` bullet now names all five triggers —
  `stuck`, `blocked`, `regression`, `conflict`, and `requirement_changed` —
  says a red verify or check after osq merges the default branch is a
  `regression` with reason `sync_verify_red`, says the watcher's sync and
  `osq land` both stop on these, says `osq land` records an archived change's
  stop on its branch and refuses to land it until it is steered, and adds that
  approval after a `conflict` restarts from the default branch, keeps the old
  branch as `osq/<folder>-restarted-<n>`, and runs every task again, while
  `requirement_changed` or `sync_verify_red` merges the default branch without
  running verify, keeps done tasks, and judges a revised requirement against
  the default branch's current text. The `## Version control` sync paragraph
  now names `sync_conflict`, `requirement_changed`, and `sync_verify_red`,
  drops `sync_failed`, and says each asks for steering with `osq plan <id>`.
- `CHANGELOG.md`: one new `## [Unreleased]` entry ending `(129)` saying a
  change the default branch stops, archived or not, shows once with
  `osq plan <id>`, that `osq land` records the stop, and that approval restarts
  after a conflict or merges the default branch otherwise.
- `tests/steering-default-branch-docs.test.ts` (new): covers the README
  default-branch steering bullet, the sync paragraph's three reasons, the loop
  diagram's steering step, and the CHANGELOG entry.
