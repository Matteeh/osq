## Changed

- `src/core/spec/approve.ts`: `approveSpec` now resolves the id with
  `findSteeringChange` and falls back to `findChange` (whose message it keeps)
  when that returns null. `ApproveResult` gained optional
  `restarted: { defaultBranch, keptBranch }` and `merged: { defaultBranch }`.
- `src/core/spec/approve-steer.ts`: after the existing running-task refusal,
  a change whose triggers include a default-branch trigger (via
  `isDefaultBranchTrigger`) is handed to `approveDefaultBranchSteering`. Every
  other change keeps 128's path unchanged.
- `src/core/spec/approve-default-branch.ts` (new): the shared prelude. Lints
  the folder with the checkout as project root, reviews the digest with
  `confirmApproval`, commits the revised folder as `osq: <id> replanned` with
  `vcs.author`, collects observations, and dispatches to restart on `conflict`
  or merge otherwise.
- `src/core/spec/approve-default-branch-restart.ts` (new): copies the folder
  aside, removes the worktree, renames the branch to the lowest free
  `osq/<folder>-restarted-<n>`, cuts `osq/<folder>` from the default branch's
  tip, adds the worktree, runs `vcs.prepare`, places the folder with `.run/`
  trimmed to `events/` and `plan.jsonl`, appends observations, seals with
  `writeApprovalSeal`, writes `.run/base` and `.run/approver` with
  `writeProvenance`, commits `osq: <id> approved`, and reports `Continues from
  task <n>`.
- `src/core/spec/approve-default-branch-merge.ts` (new): moves an archived
  folder to the changes directory, rebuilds the living specs from the default
  branch with `rebuildLivingSpecs(..., false, [])`, writes
  `.run/requirements-base` with the default branch's tip, appends observations,
  seals and commits `osq: <id> approved`, runs `syncWithDefaultBranch` with
  `skipVerify`, restarts on a `sync_conflict` stop, refreshes done markers
  whose scope hash differs with `refreshRecertifiedDoneMarker`, and retires
  triggers through `retireSteering`.
- `src/cli/approve.ts`: extracted the result printing into
  `printApprovalResult` (keeps `approveCommand` in the function budget) and
  added the `  Restarted ...` / `  Merged ...` line after `  Branch:`.
- `tests/steering-approve-default-branch.test.ts` (new): temporary git
  repositories with `vcs.enabled` covering every scenario of "Approval after a
  default-branch trigger": conflict restarts, restarted change runs every task
  again and lands, red verify reopens with done tasks kept, reopened change
  runs only the new task and archives, changed requirement is judged against
  the default branch, and a conflicting merge restarts.

## Deviated

- In the merge path I stage both the new changes folder and the old archive
  folder path, so the `osq: <id> approved` commit records the move and leaves
  the worktree clean. Committing only the new folder left the deleted archive
  copy dirty and the watcher halted with `worktree_dirty`.
- `defaultBranchResult` (the shared result fields) lives in
  `approve-default-branch-restart.ts` and is imported by the merge module, so
  the module split keeps every function within the 80-line budget.
