## Changed

- `src/core/status/steering.ts`: `SteeringTriggerName` gained `conflict` and
  `requirement_changed`. A change-level `regressed/change.md` now maps
  `sync_conflict` to `conflict`, `requirement_changed` to `requirement_changed`,
  and `sync_verify_red` (with `verify_red`/`verify_path_missing`) to
  `regression`. Added `isDefaultBranchTrigger(trigger)`. `steeringMarkerPath`
  now points every change-target trigger at the regressed marker.
- `src/core/vcs/sync-stop.ts`: `SyncStopReason` gained `requirement_changed`
  and `sync_verify_red`.
- `src/core/vcs/sync-files.ts` (new): `readRequirementsBase` reads
  `.run/requirements-base`, else `.run/base`, else null; plus `readEvents`,
  `restoreEvents`, and `eventsRelative` moved out of `sync-main.ts`.
- `src/core/vcs/sync-main.ts`: uses `readRequirementsBase` for the requirement
  check, takes a fifth `options: { skipVerify?: boolean } = {}`, drops the
  verify suffix and passes `skipVerify` through when set. The conflict stop now
  reads `<folder>: <paths> conflict with <branch>; run osq plan <id>, and
  approving the revised plan restarts osq/<folder> from <branch>` for active
  and archived changes alike. 243 lines.
- `src/core/vcs/sync-specs.ts`: `assertRequirementsUnchanged` throws
  `SyncStop` with reason `requirement_changed` and the new
  `run osq plan <id> to revise the plan against <branch>` message.
- `src/core/vcs/sync-verify.ts`: red verify and check stops are
  `sync_verify_red`; `skipVerify` runs no command but still appends `synced`.
- `src/watcher/worktree-run.ts`: `WorktreeHaltReason` gained
  `requirement_changed` and `sync_verify_red` so `checkSync` halts with the
  stop's own reason. `sync-run.ts` unchanged.
- Tests: updated the pinned messages/reasons in `tests/vcs-sync.test.ts`,
  `tests/vcs-sync-active.test.ts`, `tests/vcs-land.test.ts`, and
  `tests/change-check.test.ts`. Added `tests/steering-sync.test.ts` with the
  snapshot scenarios (default-branch triggers, run trigger, archived change)
  and the temporary-repository scenarios (requirement changed, requirements
  base after a revised approval, red verify, skip verify, watcher red verify
  before archive).

## Deviated

- `sync-files.ts` also took over `eventsRelative` from `sync-main.ts`; the
  three named helpers alone left `sync-main.ts` over the 250-line budget after
  the new import and `skipVerify` plumbing. The helper is about the same events
  file, so it belongs in the same module.

## Outside scope

- `tests/vcs-land.test.ts`'s "stops on a sync conflict" still only asserts that
  `osq land` records nothing and leaves the checkout alone; recording the stop
  on the branch is task 2's work and there is no `src/core/vcs/land.ts` change
  here.
