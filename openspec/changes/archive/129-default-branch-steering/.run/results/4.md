## Changed

- `src/cli/plan-steer.ts`: `readSteeringPlan` now looks the change up with
  `findSteeringChange` (task 3) instead of `findChange`, so an archived change
  in a worktree that needs steering is planned in place. The signature stays
  `(projectRoot, config, name)`; the caller in `plan.ts` needed no change,
  because the existing steering path already writes `plan-prompt.md` into
  `folderPath` and starts a session with `tree.root` as `cwd`. Added
  `defaultRequirementText` (living spec at the default branch via
  `livingSpecPath` + `parseCapabilitySpec`) and `requirementLines`, which reads
  the base with `readRequirementsBase` and asks `changedRequirements` for the
  changed requirements, then adds `#### <capability>: <requirement> on
  <default branch>` plus the requirement's full text in a fence, or `Removed on
  <default branch>.` `buildSteeringSection` now selects the change tree's `Vcs`
  when any trigger is a default-branch trigger, names the default branch, and
  after the tree line adds the restart line for `conflict` or the merge line
  otherwise. A `conflict` trigger replaces the done-tasks line with `Every task
  runs again after the restart. Revise any task the conflict shows is wrong.`
- `src/cli/lint.ts`: `resolveLintFolder` resolves an explicit id through
  `findSteeringChange` first and falls back to `findSpecFolder` when it returns
  null or throws. Linting still runs with `cwd` as project root.
- `tests/steering-plan-default-branch.test.ts` (new): a self-contained
  temporary-git-repository setup copied from `tests/steering-plan.test.ts`
  (extended with a living `orders` spec, an acting adapter, and archiving),
  covering "Plan an archived change after a land conflict", "Changed
  requirement text in the prompt", and "Lint an archived change that needs
  steering".

`pnpm verify` passes: both typechecks, the build, the full suite, and lint.

## Deviated

- The `####` requirement blocks are emitted inside each
  `requirement_changed` trigger block, directly after that trigger's marker
  body, before the three trailing lines. The delta lists them "under" the
  trigger, and this keeps the changed requirement attached to its evidence.
- The test's conflict scenario drives a real `osq land` stop
  (`sync_conflict`) rather than writing the marker by hand; only the
  `requirement_changed` scenario writes the marker by hand, as the task's
  Details direct.
