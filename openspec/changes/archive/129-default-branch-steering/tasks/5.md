## Acceptance

- [ ] `approveSpec` looks the change up with `findSteeringChange` and, when it returns null, fails with the message `findChange` gives. Every path for a change that needs no default-branch steering is unchanged. `approveSpec` stays within the function budget.
- [ ] `approveSteeredChange` keeps its running-task refusal first. A change whose triggers include a default-branch trigger then goes to `approveDefaultBranchSteering` in new `src/core/spec/approve-default-branch.ts`. Every other change keeps 128's path.
- [ ] `approveDefaultBranchSteering` lints, reviews the digest, commits `osq: <id> replanned`, and restarts after a `conflict`, exactly as the spec-lint-and-approve delta's "Approval after a default-branch trigger" says. It reuses `confirmApproval`, `writeApprovalSeal`, `readBriefHash`, and `toIso` from `approve-worktree-shared.ts`, `runPrepare`, `writeProvenance`, the planning-observation helpers `approveIntoWorktree` uses, and the `Vcs` port's `worktreeRemove`, `renameBranch`, `listBranches`, `createBranch`, and `worktreeAdd`.
- [ ] Otherwise it merges, as that requirement says. It reuses `rebuildLivingSpecs` with `archived` false to put the default branch's living specs in place, `syncWithDefaultBranch` with `skipVerify`, `computeTaskScopeHash`, `readDoneMarker`, and `refreshRecertifiedDoneMarker` for the done markers, and `retireSteering` for the triggers. A merge that stops with `sync_conflict` restarts instead. Split the module into more `approve-default-branch*.ts` files to keep each function within the budget.
- [ ] `ApproveResult` gains optional `restarted: { defaultBranch, keptBranch }` and `merged: { defaultBranch }`. `osq approve` prints the restart or merge line after `  Branch:` and before `  Continues from task <n>`, as the delta says.
- [ ] New `tests/steering-approve-default-branch.test.ts` covers every scenario of "Approval after a default-branch trigger", in temporary git repositories with `vcs.enabled`. "Restarted change lands" and "Reopened change runs and archives" drive `runWatcherCycle` with a fake adapter until the change archives, and the first also runs `landChange`.

## Details

`isDefaultBranchTrigger` and `skipVerify` come from task 1, the land's
recorded stop from task 2, and `findSteeringChange` from task 3. Read them, do
not change them. Build the stopped archived change by landing it against a
conflicting or red default branch with `landChange`. Build the
`requirement_changed` case by approving a change that modifies a requirement,
then committing a change to that requirement on the default branch, and
letting a watcher cycle halt it. Copy the temporary-repository setup from
`tests/steering-approve.test.ts` rather than importing from another test.
`retrySpec` resolves the change with `findChange(projectRoot, …)`, so pass it
the checkout root, after the folder has moved to the changes directory.
