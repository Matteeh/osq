## Acceptance

- [ ] New `src/core/status/steering-change.ts` exports `findSteeringChange(projectRoot, config, id)` and `listArchivedSteering(projectRoot, config)`, as the status-inspection delta's "Archived change that needs steering" says. They read archived changes from `listChanges(projectRoot, config, ['archived'])`, keep those whose tree has a `worktreeFolder`, and derive state with `readChangeFolder(change.tree.root, change.folderPath)`.
- [ ] `readNextStep` returns state `dead`, command `osq plan <id>`, and detail `needs steering` for an archived change whose derived state has `steering`, and `landed` for every other archived change, as "Change next step" says.
- [ ] `readInbox` adds one `change-regressed` needs-you item per change `listArchivedSteering` returns, with no task, command `osq plan <id>`, and `steering` from its first trigger, in numeric change order with the other items. `inbox.ts` and `inbox-text.ts` need no change: the steering row already renders a change target.
- [ ] `readDispatchItems` gives an archived change in an osq worktree whose derived state has `steering` one `halt` item with no task, its first trigger as `steering`, and commands `osq plan <id>` and `osq show <id>`, in place of its `land` item, as "Dispatch items" says. Every other land item is unchanged.
- [ ] New `tests/steering-archived.test.ts` covers "Archived change found for steering", "Inbox row for an archived change", the new "Change next step" scenario, and the new "Dispatch items" scenario, in temporary git repositories with `vcs.enabled`, through `readInbox`, `formatInboxText`, `readNextStep`, and `readDispatchItems`.

## Details

`deriveSteering` and the `conflict` trigger come from task 1, and `osq land`'s
recorded stop from task 2; read them, do not change them. The easiest way to
build an archived change with a recorded stop is to land it with `landChange`
against a conflicting default branch, as task 2's test does. Copy that
temporary-repository setup into the new file rather than importing from
another test.
