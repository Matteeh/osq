## Acceptance

- [ ] New `src/core/vcs/land-stop.ts` exports `recordLandStop(config, change, stop)`, which writes the marker and the `regressed` event and commits them on the change's branch, as the version-control delta's "Land records a steering stop" says. It writes the event line itself, with the shape `haltWorktreeChange` in `src/watcher/worktree-run.ts` gives it, because `src/core` does not import the watcher.
- [ ] `landChange` catches a `SyncStop` from `syncWithDefaultBranch`. For `sync_conflict`, `requirement_changed`, or `sync_verify_red` it records the stop and then throws the sync's message, or that message plus the failed-commit line when recording fails. Any other error is rethrown unchanged. `land.ts` stays at or under 250 lines.
- [ ] `land-checks.ts` exports a refusal that derives the change's state in its worktree and refuses with the delta's "Land refusals" message when it has `steering`, naming its first trigger through `describeTrigger`. `landChange` calls it after the worktree-clean check and before `assertNoEarlierChange`, only for a change that has not landed.
- [ ] `osq land` prints the same stop on stderr and exits one as before. The checkout's HEAD, index, and tree stay as they were.
- [ ] New `tests/vcs-land-steering.test.ts` covers the three scenarios of "Land records a steering stop" and "Recorded stop refuses the next land", through `landCommand` against temporary git repositories with `vcs.enabled`.

## Details

The stop reasons, `isDefaultBranchTrigger`, and the derived `steering` for an
archived folder come from task 1; read them, do not change them. Copy the
temporary-repository setup (`setupProject`, `archiveAll`, `captureLand`, and

importing from another test. "Other stops record nothing" can make
`vcs.prepare` a command that exits 1.
