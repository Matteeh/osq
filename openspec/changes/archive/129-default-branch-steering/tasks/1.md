## Acceptance

- [ ] `steering.ts` derives the `conflict` and `requirement_changed` triggers and a `regression` for `sync_verify_red` from `.run/regressed/change.md`, and exports `isDefaultBranchTrigger(trigger)`, as the status-inspection delta's "Steering triggers" says. `SteeringTriggerName` gains the two names.
- [ ] `SyncStopReason` gains `requirement_changed` and `sync_verify_red`. `assertRequirementsUnchanged` stops with `requirement_changed`, and `runSyncVerify` stops with `sync_verify_red` for a red verify or check. The changed-requirement and conflict messages are exactly what the version-control delta's "Default branch sync" says, for an active and an archived change alike.
- [ ] New `src/core/vcs/sync-files.ts` exports `readRequirementsBase(folderPath)`, which returns the commit in `.run/requirements-base`, else the one in `.run/base`, else null. It also takes over `readEvents` and `restoreEvents` from `sync-main.ts`, and the requirement check uses `readRequirementsBase`. `sync-main.ts` stays at or under 250 lines.
- [ ] `syncWithDefaultBranch` takes a fifth parameter `options: { skipVerify?: boolean } = {}`. With `skipVerify` set, the progress line has no verify suffix, and `runSyncVerify` runs no command but still appends the `synced` event. Every existing caller passes nothing and behaves as before.
- [ ] `WorktreeHalt`'s reason in `worktree-run.ts` gains `requirement_changed` and `sync_verify_red`, so `checkSync` halts with the stop's own reason as the watcher-and-harness delta's "Watcher sync" says. `src/watcher/sync-run.ts` needs no change.
- [ ] The pinned tests expect the new texts and reasons. In `tests/vcs-sync.test.ts`, the changed-requirement and conflict messages change. In `tests/vcs-sync-active.test.ts`, the red task verify reason becomes `sync_verify_red` and the conflict message ends as the delta's "Code conflict in an active change" says. In `tests/vcs-land.test.ts` the conflict message changes. In `tests/change-check.test.ts` the red check reason becomes `sync_verify_red`. Every other case is unchanged.
- [ ] New `tests/steering-sync.test.ts` covers "Default-branch triggers", "Run trigger is not a default-branch trigger", and "Archived change" with snapshots built in the test. In temporary git repositories it also covers "Requirement changed on the default branch", "Requirements base after a revised approval", "Red verify after the merge", "Verify skipped on request", and the watcher's "Red verify before archive needs steering".

## Details

For the temporary repositories, copy the setup from `tests/vcs-sync.test.ts`
and `tests/vcs-sync-active.test.ts` for the sync scenarios, and from
`tests/worktree-sync.test.ts` for the watcher scenario, into the new file
rather than importing from another test. The "Archived change" scenario only
needs a `ChangeFolderSnapshot` with an approved hash and the marker;
`deriveSteering` does not care where the folder lives.

`sync-change.ts` matches the scope glob but needs no change: `osq sync`
records whatever reason the stop carries.
