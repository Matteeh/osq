## Changed

- Refactored `src/core/report/stream-index.ts` to export `openIndexDatabase`, the
  shared opener that loads `node:sqlite`, prepares `.osq/`, opens WAL mode and
  recreates an unusable database. `openStreamIndex` now uses it with
  `initializeSchema` and keeps its existing behavior.
- Added `src/core/report/blob-line-index.ts` exporting `BlobLineEntry`,
  `BlobLineIndex` and `openBlobLineIndex`. The `blob_lines` table stores one
  nullable line count per blob hash; `store` writes in one transaction and rolls
  back on failure, while `lookup`, `store` and `close` never throw.
- Added `tests/blob-line-index.test.ts` proving the stored blob answers after a
  reopen, a blob store beside an existing `streams` row with the schema version
  unchanged, and a null result when `.osq` is a regular file.

## Deviated

- The new tests use `node:test` directly instead of the `@matteeh/osq/testing`
  scenario helper. The living metrics-and-reporting spec already holds two
  scenarios named "Two report runs", so `lookupScenario` rejects the whole
  capability before looking up any scenario.

## Outside scope

- The living `openspec/specs/metrics-and-reporting/spec.md` has duplicate
  "Two report runs" scenarios at lines 1071 and 1181, which blocks scenario-helper
  tests for that capability. Left unchanged because living specs are not editable
  here.
