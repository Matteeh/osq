## Changed

- Added `src/watcher/repo-counts.ts` with `gatherRepoCounts(projectRoot, gitSeconds)`, which reads `git ls-files -s -z` and `git ls-files -m -z` through `runGit`. It drops symlinks and submodules, reads changed or conflicted paths from disk, looks up every other path's blob in `openBlobLineIndex`, counts only text files, stores newly read blob line counts once at the end, and falls back to the existing `IGNORED_DIRS` walk when either git command fails or the folder is not a repository.
- Moved the old recursive walk out of `src/watcher/measures.ts` into `repo-counts.ts` as that fallback.
- `measures.ts` re-exports `gatherRepoCounts` and gives `gatherStartMeasures` and `createTaskMeasures` an optional trailing `gitSeconds`, passed through to the counts.
- `src/watcher/runner.ts` passes `config.timeouts.gitSeconds` into `createTaskMeasures`.
- Added `tests/repo-counts.test.ts` proving the six named scenarios in temporary git and non-git folders, counting `fs.readFile` calls by path to show ignored, untracked and warm-run files are never read.

## Deviated

- The new tests use `node:test` directly rather than the `@matteeh/osq/testing` scenario helper. The living watcher-and-harness spec has duplicate scenario names (for example "Captured run" and "Outside git"), so `lookupScenario` rejects the whole capability before looking up any scenario. The task's acceptance only names the scenarios and does not require the helper.
- Keeping the one `createTaskMeasures` call inside `runner.ts` needed a `gitSeconds` local so the call fits one formatted line; one existing blank line was removed to keep `runner.ts` under its strict 200-line budget.

## Outside scope

- The living `openspec/specs/watcher-and-harness/spec.md` has duplicate scenario names, which blocks the scenario helper for this capability. Left unchanged because living specs are not editable here.
