## Changed

- Added `src/roles/harness.rs` with `Harness` (six variants, `Agy` as
  `Default`), `as_str`, `default_model`, `supports_planner_agent`, the named
  `DEFAULT_AGY_MODEL` and `DEFAULT_OPENCODE_MODEL` constants and
  `read_harness`, which trims a name before matching and reports an unknown
  one with the delta's `must be one of: ...` reason.
- Added `src/roles/executor.rs` with `ExecutorConfig`, its `Default` (agy with
  `gemini-3.8-flash-high`) and `read_executor`, which falls back to the
  harness's default model when `model` is unset.
- Added `src/roles/planner.rs` with `PlannerConfig`, `OSQ_PLANNER_AGENT`,
  `PlannerConfig::following` for the missing-table case and `read_planner`,
  which requires `harness` and `model`, defaults `agent` to `osq-planner` for
  opencode and refuses an agent for codex, pi and claude.
- Added `src/roles/validator.rs` with `ValidatorConfig` and `read_validator`,
  which defaults `enabled` to true and `timeoutSeconds` to 900 and requires
  `harness` and `model` only while enabled.
- Added `src/roles/mod.rs`, which declares the four modules, re-exports the
  four types and holds the dotted-path helper the harness reader uses.
- `src/config.rs`: `Config` gained `executor`, `planner` and `validator`;
  `Default` builds the planner from the default executor; `parse_config` reads
  the three tables after `vcs`, one at a time, with the planner following the
  executor when its table is absent. Nothing else in the file changed.
- `src/lib.rs`: declared `mod roles;` and re-exported `Harness`,
  `ExecutorConfig`, `PlannerConfig` and `ValidatorConfig`.
- Added `tests/roles.rs` with the five scenario tables, one row per row of the
  delta's tables, plus two tests worked out from the delta's rules: the
  planner following an explicit executor model, and `mock` accepting a planner
  agent because its catalog entry has one.
- Ran `cargo fmt --all`, `cargo clippy -p osq-kernel-config --all-targets --
  -D warnings` (clean), `cargo mutants -p osq-kernel-config -f <file>` on each
  new or changed source file (every mutant caught or unviable), the task's
  `cargo test -p osq-kernel-config --test roles` and the proposal's
  `sh scripts/verify-rust.sh` (exit 0).

## Deviated

- Two mutation-coverage tests could not name a separate scenario, since only
  the five scenarios in the delta exist; they carry
  `Covers: rust-config/role-tables-with-defaults` and
  `Covers: rust-config/executor-model-by-harness`, the scenarios whose rules
  they extend. The linter kernel's link gate refuses a `Covers:` tag naming a
  requirement instead of a scenario, so the first tags I used
  (`rust-config/role-settings`) were reported and fixed.
- `Harness` has an explicit `default_model` and `supports_planner_agent` as
  `pub(crate)` methods rather than free constants, so all three readers share
  one table of known names and their defaults.

## Missing context

- The task says to run `sh scripts/verify-rust.sh` with `OSQ_CHANGE` set, but
  the script reads `OSQ_DIFF`; with only `OSQ_CHANGE` set it prints
  `mutation check not run`. I ran the required per-file `cargo mutants` calls
  by hand instead.

## Outside scope

- `cargo fmt --all` on the whole workspace changed nothing outside the files
  listed below; the verify's `cargo fmt --all --check` passes.
