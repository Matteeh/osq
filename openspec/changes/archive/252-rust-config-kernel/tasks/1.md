## Details

TypeScript's rules are `DEFAULT_CONFIG` in `src/core/foundation/config.ts`,
`validateVcsConfig` in `src/core/foundation/config-vcs.ts` and the git
defaults in `src/core/vcs/git-vcs.ts`. Read them only to check a rule; the
delta is the contract. Rust code never imports or calls anything under
`src/`.

Parse with `text.parse::<toml::Table>()` and walk the table by hand; the
config types derive no serde traits. Write the author check by hand on the
string; add no regex crate. Use temporary folders under
`env!("CARGO_TARGET_TMPDIR")` for the file tests.

Tests never build a whole `Config` literal: compare single fields, or build
the expected value with `..Config::default()`, so task 2's new fields do not
break them. The `Read` error's message comes from the operating system, so
"Unreadable osq.toml" checks only that it is not empty; "Error texts"
builds each error by hand and checks its display.

`toml` 1.1.2 and its dependencies are in the local cargo cache. Resolve
them with `cargo build --offline -p osq-kernel-config`, which adds only new
entries to `Cargo.lock`; do not run `cargo update`.

cargo-mutants runs on every line this task adds. Each default constant,
each bound of the positive integer rule and each step of the author check
must change a value a table row checks; add a row with values worked out
from the delta's rules if a mutant survives. Before exiting, run
`cargo fmt --all`, then
`cargo mutants -p osq-kernel-config -f <file> -o "$(mktemp -d)"` on each
new source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE` set to
`openspec/changes/252-rust-config-kernel`, so the link gate corpus test sees
this change's new capability and requirements.
