## Changed

- `src/core/report/change-digest.ts` (new, 249 lines): exports
  `buildChangeDigest(projectRoot, config, request)`, the `DigestRequest`,
  `ChangeDigest`, `DigestChange`, `DigestCapability`, `DigestRequirement`,
  `DigestRenamedRequirement`, `DigestAdrEntry`, `DigestTasks`, and
  `DigestSelection` types, and the `DigestSelectionError` class. It validates
  the request, matches ids with `matchesFolder`, selects a date range with both
  ends included, orders by `archivedOn` then id (undated last), and builds
  stable change, requirement (`<change>/<capability>/<kind>/<name>`), and ADR
  (`ADR-<number>`) ids. ADR rules come from `readDecisions` and
  `sameAdrNumber`, null when the folder no longer holds the ADR. With
  `cost: false` the `cost`, `executorModels`, and `planner` keys are omitted.
- `src/core/report/change-digest-period.ts` (new, 134 lines): exports
  `buildDigestPeriod` and the `DigestPeriod` shape. It counts changes,
  requirements per kind, capabilities touched (most first, then by name),
  halts, and elapsed and cost totals each with the recorded count. It lists
  every `readDecisions` ADR whose `date` falls in the range. `cost: false`
  omits the period's `cost` key.
- `tests/change-digest-select.test.ts` (new, 318 lines): writes archives and a
  `decisions/` folder under temporary roots with `DEFAULT_CONFIG` and covers
  "Range includes both ends", "Ids in date order", "Unknown id", "Empty range",
  "Period totals", every refusal message in "Change digest selection", and that
  `cost: false` leaves no `cost`, `executorModels`, or `planner` key.

Task verify `node --import tsx --test tests/change-digest-select.test.ts`
passes 12/0. Proposal verify `pnpm verify` exits 0 (2938 TS tests, 94 TSX
tests, 0 failures; both typechecks, build, and lint pass).

## Deviated

- The task does not pin the exact JSON nesting under a change. I grouped
  requirement entries under each capability as `added`, `modified`, `removed`,
  and `renamed` arrays, each entry carrying its stable `id` and `name` (a
  rename also carries `from`). The period totals read from that same shape.
- No comments are kept on the internal helpers in `change-digest.ts`: the
  250-line budget left no room, and `biome format` wrapping pushed the file
  over until they were removed.

## Missing context

- The task names the fields each change carries but not the JSON key names for
  the capability and requirement entries. Task 4's Markdown renderer will need
  to read the shape chosen here; if the planner wanted a flat
  `requirements` list instead, that is this digest's one open interface choice.
