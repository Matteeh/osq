## Acceptance

- [ ] New `src/core/report/change-digest.ts` exports `buildChangeDigest(projectRoot: string, config: OsqConfig, request: DigestRequest): Promise<ChangeDigest>`. `DigestRequest` is `{ ids: readonly string[]; since: string | null; until: string | null; cost: boolean }`. It also exports `DigestSelectionError`, an `Error` subclass.
- [ ] Selection, ordering, and every refusal follow the metrics-and-reporting delta's "Change digest selection". Each refusal throws `DigestSelectionError` with exactly the message listed there. Records come from `listArchivedChanges`, and ids match with `matchesFolder`.
- [ ] `ChangeDigest` is the JSON document of "Change digest output". It holds `schemaVersion: 1`, plus `selection`: `{ kind: 'ids', ids }` or `{ kind: 'range', since, until }`. It also holds `period`, and `changes` with the stable change, requirement, and ADR ids, each change carrying the fields of "Change digest content". Each ADR's rule comes from `readDecisions` and `sameAdrNumber`.
- [ ] New `src/core/report/change-digest-period.ts` computes the range totals of "Change digest content", including the ADRs whose `Adr.date` falls in the range. An id selection gets `period: null`.
- [ ] With `cost: false`, no change or period in the document has a `cost`, `executorModels`, or `planner` key. Nothing in the document holds a path, the current time, or anything outside the record's fields.
- [ ] New `tests/change-digest-select.test.ts` covers "Range includes both ends", "Ids in date order", "Unknown id", "Empty range" (document side), and "Period totals". It also covers every refusal message, and that `cost: false` leaves no cost or model key. It writes archives and a `decisions/` folder under a temporary project root, using `DEFAULT_CONFIG`.

## Details

The archive day is the record's `archivedOn`. Compare `YYYY-MM-DD` strings
directly: they sort like dates. Validate a date with `/^\d{4}-\d{2}-\d{2}$/`
and a successful `Date.parse`. Ordering is by `archivedOn`, with null last,
then by numeric id.

A change's elapsed time and cost stay numbers or null in the document;
formatting belongs to the Markdown renderer in task 4. Keep the period's
elapsed and cost coverage as `{ total, recorded }`, where `recorded` counts the
changes with a non-null value.

Copy the archive-writing helpers you need into the new test rather than
importing them from `tests/change-digest-archive.test.ts`.
