# Task 7 result: openspec/config.yaml + osq schema bundle scaffolded by osq init

All five acceptance lines implemented and covered by tests. Task verify
(`node --import tsx --test tests/init.test.ts`) passes: 10/10. Repo gate
(`pnpm tsc --noEmit && pnpm test && pnpm lint`) passes: 400/400, `tsc` clean,
`biome check` clean.

## Changed

- `templates/openspec/config.yaml` (new)
  - Declares `schema: osq`, a non-empty `context`, and per-artifact `rules` for
    `proposal`, `specs`, and `tasks`.
- `templates/openspec/schemas/osq/schema.yaml` (new)
  - Fork of the `spec-driven` schema with artifact order `proposal` → `specs`
    → `tasks`; the `design` artifact is removed and `tasks` depends on `specs`
    (not `design`). `apply` requires `tasks` and tracks `tasks.md`.
- `templates/openspec/schemas/osq/README.md` (new)
  - Documents the forked graph and states explicitly that `tasks/<n>.md` sits
    outside the schema graph and is an osq-specific execution unit.
- `templates/openspec/schemas/osq/templates/{proposal,spec,tasks}.md` (new)
  - The materialization templates referenced by `schema.yaml`; without them the
    schema would resolve but artifact creation would fail.
- `src/core/init.ts`
  - Added `TEMPLATES_ROOT` resolved from `import.meta.url` (source →
    repo `templates/`, compiled → package `templates/`).
  - `scaffoldProject` now creates `openspec/`, `openspec/schemas/`,
    `openspec/schemas/osq/`, `openspec/schemas/osq/templates/`,
    `openspec/specs/`, `openspec/changes/`, and `openspec/changes/archive/`.
  - Added a `bundledTemplates` read step that copies the six OpenSpec bundle
    files listed above into the target. Existing files are reported in
    `skippedFiles` and never overwritten.
  - Updated `MANAGED_AGENTS_BLOCK`: step 1 now points at `proposal.md`, and a
    new `## OpenSpec layout` section documents `openspec/specs/<capability>/`,
    `openspec/changes/<id>-<slug>/`, `proposal.md` + delta specs, the
    `openspec/schemas/osq/schema.yaml` graph, and `tasks/<n>.md` as the
    execution unit with `tasks.md` as a write-only projection.
- `tests/init.test.ts`
  - Added one test per acceptance line (schema/config parse, schema graph and
    reference validity, README wording, managed-block refresh, idempotency plus
    preservation of a user-owned `openspec/config.yaml` and `schema.yaml`).

## Acceptance mapping

- config.yaml declares `schema: osq` and artifact rules: parse test asserts the
  schema string, non-empty context, and non-empty `proposal`/`specs`/`tasks`
  rule arrays.
- schema.yaml forked from spec-driven without design: ordered artifact-id
  assertion, no `design`, `specs.requires == [proposal]`,
  `tasks.requires == [specs]`, and every `requires` target declared.
- README documents `tasks/<n>.md` as an osq-specific execution unit: string
  assertions on `tasks/<n>.md`, `osq-specific`, and `execution unit`.
- Managed AGENTS.md block refreshed with OpenSpec layout instructions: stale
  managed block replaced, markers still exactly once, OpenSpec paths present.
- Idempotent, no overwrite: second run reports empty `createdDirs` /
  `createdFiles`, lists the OpenSpec files as skipped, and preserves custom
  config/schema bytes.

## Deviations

- Bundled the three schema materialization templates (not enumerated in the
  acceptance lines) because `schema.yaml` references `template: proposal.md`,
  `spec.md`, and `tasks.md`; a schema without them is non-functional.
- Wired `scaffoldProject` to read from the package `templates/` directory (task
  2 flagged this as task 7's job) instead of inlining the YAML as string
  constants in `init.ts`. `templates/` is already in `package.json#files`.
- `MANAGED_AGENTS_BLOCK` step 1 now says the parent is `proposal.md` rather than
  `spec.md`; the existing managed-block assertions in `tests/opencode-setup.test.ts`
  and `tests/init.test.ts` are unchanged and still pass. This does not change the
  harness prompt tests, which do not assert the parent filename.
