# Task 2 result: proposal.md parsing, OpenSpec task lists, rewritten templates

## Changed

- `src/core/parser.ts`
  - Added `PROPOSAL_FILENAME` / `SPEC_FILENAME` constants and `ChangeDocKind` / `ResolvedChangeDoc` types.
  - Added `resolveChangeDoc(folderPath)`: prefers `proposal.md`, falls back to `spec.md`, else `null`.
  - Added `parseSpecMdFromFolder(folderPath)`: resolves the change document and parses it (proposal first, spec fallback).
  - Added `ChecklistItem` and `parseTaskList(content)`: parses `tasks.md` checklists, supporting flat numbered items, unnumbered bullets, `-`/`*` markers, `[ ]`/`[x]`/`[X]`, `##` section headers, and `N.`/`N)` item numbers. Each item records `number`, `title`, `checked`, `section`, and `line`.
  - `parseSpecMd` / `parseTaskMd` behavior preserved and unchanged for existing callers.
- `templates/proposal.md` (new)
  - Proposal frontmatter (`title`, `depends_on`, `features.reads`, no `features.writes`), `## Goal`, `## Contract`, `## Non-goals`, `## Delta` with a fenced OpenSpec delta spec skeleton (`## ADDED/MODIFIED/REMOVED/RENAMED Requirements`, `### Requirement:`, `#### Scenario:`).
- `templates/tasks.md` (new)
  - OpenSpec grouped checklist (`## 1. Section title` + `- [ ] 1. ...`).
- `tests/parser.test.ts`
  - Added tests for proposal frontmatter without `features.writes`, Goal/Non-goals extraction, `entry`/`skills`, `parseTaskList` grouped and flat formats, `resolveChangeDoc`/`parseSpecMdFromFolder` fallback against temp dirs, and both template files.

## Acceptance mapping

- `parseSpecMd` parses `proposal.md` with fallback to `spec.md`: `parseSpecMdFromFolder` + `resolveChangeDoc`, tested with proposal-only, spec-only, both, and missing folders.
- Frontmatter extracts `title`, `depends_on`, `features.reads` without `features.writes`: test `parseSpecMd extracts proposal frontmatter without requiring features.writes`.
- Goal and Non-goals extracted from proposal bodies: same test asserts both sections.
- `parseTaskMd` parses scope, verify, entry, skills, acceptance: existing tests plus populated `entry`/`skills` test.
- Task list parser supports OpenSpec checklist with section headers and item numbers: `parseTaskList` grouped + flat tests.
- Templates rewritten for proposal, tasks, and delta specs: `templates/proposal.md` and `templates/tasks.md` asserted by content and by the parser.

## Deviations

- Delta spec template: scope listed only `templates/proposal.md` and `templates/tasks.md`, so the delta spec skeleton is embedded as a fenced block inside `templates/proposal.md` rather than a separate file. It documents all four OpenSpec operation headings, `### Requirement:`, and `#### Scenario:`. If a standalone delta template file is wanted, that belongs to task 7's `templates/` scope.
- `parseSpecMd` itself still accepts content (unchanged); folder resolution/fallback lives in new additive helpers so existing out-of-scope callers (`linter.ts`, `state.ts`, `show.ts`, `archiver.ts`, `harness/opencode.ts`) keep compiling. Later tasks can migrate those callers to `parseSpecMdFromFolder`.
- `templates/` at repo root is currently unused by `osq init` (task 7 scope will wire scaffolding to it).

## Drift against features/

Expected: the feature doc update is applied by the approved delta at archive time, and this task's scope did not include feature docs.
