# Task 4 result: OpenSpec validator integration in lint

All six acceptance lines implemented and covered by tests. Task verify
(`node --import tsx --test tests/linter.test.ts`) passes: 19/19. Repo gate
(`pnpm verify`: `tsc --noEmit && test && lint`) passes: 378/378.

## Changed

- `src/core/linter.ts`
  - Added `OPENSPEC_EXPECTED_VERSION = '1.13.1'` and `OPENSPEC_ERROR_PREFIX = 'openspec:'`.
  - Added `LintLogger` / `LintOptions`; `lintChangeFolder` takes an optional 4th
    argument `{ logger? }` (existing 3-arg callers unchanged).
  - `resolveOpenSpecBin(projectRoot, config)`: resolves the project-local
    `node_modules/.bin/openspec` (or an explicitly configured absolute bin).
    Missing install resolves to `null`.
  - `resolveOpenSpecVersion(projectRoot)`: reads `version` from the local
    `node_modules/@fission-ai/openspec/package.json`.
  - `parseOpenSpecFindings(output)`: tolerant JSON parser for
    `openspec validate --json`, classifying findings as errors/warnings.
  - `validateWithOpenSpec(...)`: runs `validate --changes --strict --json
    --no-interactive` then `validate --specs --strict --json --no-interactive`
    with `OPENSPEC_TELEMETRY=0`, cwd = project root, timeout =
    `config.timeouts.verifyTimeoutSeconds`. Logs the resolved version and emits
    one warning when it differs from the pin. Findings are prefixed
    `openspec:`. Missing local binary is a no-op.
  - `verifyDeltaTargets(projectRoot, folderPath, config)`: reads every
    `<change>/specs/<capability>/spec.md` delta and dry-runs `mergeDelta` against
    `openspec/specs/<capability>/spec.md`; unmatched MODIFIED/REMOVED/RENAMED
    targets and missing bases become prefixed errors before approval.
  - `lintChangeFolder` now also appends delta-target errors and OpenSpec
    validation errors/warnings to its result.
- `src/cli/lint.ts` (new): `lintCommand([ids...])` resolves folders by ID
  (`findSpecFolder`) or lints every non-archive folder under `paths.specs`;
  logs per-folder findings and calls an injectable `exit(1)` on failure
  (default sets `process.exitCode`).
- `src/cli/index.ts`: registered `lint [ids...]` before `approve`.
- `tests/linter.test.ts`: kept the eight legacy tests and added eleven tests with
  a fake project-local `node_modules/.bin/openspec` that records argv, cwd, and
  `OPENSPEC_TELEMETRY`, plus a fake `@fission-ai/openspec` manifest. Covers both
  validate commands/args/env, JSON finding prefixing, version logging and
  once-only mismatch warning, delta target existence (missing/present base,
  ADDED-only), CLI registration, and non-zero/zero exit behavior.

## Deviations

- `config.paths.openspecRoot` and `config.openspec` are not present in the
  working tree (see Missing context). Accessed defensively, defaulting to
  `openspecRoot: 'openspec'` and bin `openspec`, mirroring the workaround already
  used by `src/watcher/archiver.ts` in task 3. `config.ts` is outside this task's
  scope.
- Version resolution reads the installed package manifest rather than spawning
  `openspec --version`; the real CLI's version output format is unknown and
  manifest reading is deterministic.
- "Warns once" implemented as once per `lintChangeFolder` invocation: the
  version is resolved a single time before both validate commands, so the
  mismatch warning is emitted once even though two commands run. No cross-process
  or cross-folder dedup (each `osq lint <id>` is a separate invocation).
- OpenSpec validation is a no-op (not an error) when no local binary is present,
  so projects without OpenSpec and all existing out-of-scope `approveSpec` tests
  keep working. The spec's own pin lands via task 1.
- The JSON finding parser accepts several shapes (`issues`/`errors`/`warnings`/
  `findings`/`problems`/`validations`/`results`/`items`, string or object
  findings, `severity`/`level`/`type`/`kind`) because the real output schema
  could not be inspected.
- `osq lint` accepts optional variadic IDs (contract only shows `osq lint [id]`);
  with no IDs it lints every non-archive change folder. The exit sink is
  injectable so tests do not terminate the test process.
