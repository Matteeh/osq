# Task 5 result: Write-only checkbox projection

All five acceptance lines implemented and covered by tests. Task verify
(`node --import tsx --test tests/runner-checkbox-projection.test.ts`) passes:
11/11. Repo gate (`pnpm verify`) passes: 389/389 tests, `tsc --noEmit` clean,
`biome check` clean.

## Changed

- `src/watcher/runner.ts`
  - Replaced the single-regex `tickTaskCheckbox` with an exported pure helper
    `tickTaskCheckboxContent(content, taskNumber)` plus a thin
    `tickTaskCheckbox` that only reads and rewrites `tasks.md`.
  - Ticking now supports flat numbered checklists, grouped checklists whose
    items carry their own number, and grouped checklists whose task number
    lives on the enclosing `## <n>.` section header (unnumbered items).
  - Only the target row's `[ ]` -> `[x]` is rewritten; original bullet,
    bracket spacing, and numbering punctuation (`1.` vs `1)`) are preserved.
  - Idempotent (already-`[x]`/`[X]` rows untouched) and a no-op when
    `tasks.md` is absent. No `.run/` read or write.
- `tests/runner-checkbox-projection.test.ts` (new, 11 tests)
  - Format handling: flat, grouped numbered, grouped unnumbered, idempotency,
    item-number-beats-section-number.
  - File behavior: on-disk tick, missing-file no-op.
  - Hash/state: ticking leaves `hashChangeFolder` equal to the approved hash,
    leaves `.run/approved` and every `.run/` file untouched.
  - Zero-trust state: source guard (`runner.ts` never imports `parseTaskList`
    nor references `.checked`) plus functional guard (a ticked checkbox with no
    done marker keeps `deriveSpecState` `pending`).
  - Verify-pass: `runTask` writes `.run/done/1` and ticks `- [x] 1.` after the
    independent verify exits 0.
  - Archive: every archived `tasks.md` (>= 15) parses with zero unchecked
    items.

## Deviations

- Acceptance line 5 says "all fifteen archived tasks.md files"; the test
  asserts `>= 15` and fully ticked rather than exactly 15, because the suite is
  permanent and future changes archive more specs. Today exactly 15 exist.
- The archive test resolves `openspec/changes/archive` first, falling back to
  `specs/archive`, so it keeps passing after the task-9 layout cut-over.
- Only `-`-bullet items are ticked; `*`-bullet items are intentionally left
  alone. `hasher.normalizeTasksMd` only canonicalizes `-` bullets, so ticking a
  `*` item would change the hash and violate acceptance line 3. Fixing that
  would require `src/core/hasher.ts`, which is outside this task's scope.
- Non-numeric task numbers cannot be matched (task units are `<n>.md`, so this
  is unreachable in practice).
