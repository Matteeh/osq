All five acceptance lines implemented and covered by tests. Task verify
(`node --import tsx --test tests/cut-over.test.ts`) passes: 7/7. `pnpm tsc
--noEmit` is clean and `biome check` is clean on the three touched files.

## Changed

- `src/core/config.ts`
  - `DEFAULT_CONFIG.paths` switched to the OpenSpec layout:
    `specs: 'openspec/changes'`, `archive: 'openspec/changes/archive'`,
    `features: 'openspec/specs'`.
  - Added `openspecRoot: 'openspec'` to `OsqPaths` and to the defaults. This is
    the field task 1 declared but that is absent from the working tree; other
    runtime units (`linter.ts`, `archiver.ts`, `migrate.ts`) already read it
    through a defensive cast. All existing `paths` overrides remain `Partial`,
    so user configs keep merging over these defaults.
- `src/watcher/loop.ts`
  - The watcher already derives its watched directory and archive target from
    `config.paths.specs` / `config.paths.archive`, so it now monitors
    `openspec/changes` and archives to `openspec/changes/archive` under the new
    defaults. The existing `archive` folder filter still excludes the archive
    subdirectory.
  - Added exported pure `extractHumanSteps(content)`: reads the
    `## Human steps` section from a change document.
  - Added `readHumanSteps(specFolderPath)`: prefers the OpenSpec `proposal.md`,
    falls back to legacy `spec.md` via `resolveChangeDoc`.
  - Added an in-cycle `archiveCompletedSpec` helper used by both archive call
    sites (post-task and already-done). It reads the Human steps *before* the
    archive move and, when the folder is archived, logs
    `Human steps after completion:` followed by the section. This is the only
    completion-outcome addition; the runner's single outcome line is untouched.
  - The task never moves the legacy layout: no migration call, no directory
    rename, no import of `core/migrate`.
- `tests/cut-over.test.ts` (new, 7 tests)
  - Default paths assertion; watcher processes an approved change under
    `openspec/changes` and archives under `openspec/changes/archive`; legacy
    `specs/` folders are not picked up; the Human steps section is printed in
    the completion outcome; legacy folders are not moved; source-level
    assertions that obsolete legacy path literals are gone from `config.ts`
    and that `loop.ts` does not import/invoke migration; unit coverage for
    `extractHumanSteps` (present, absent, blank).

## Acceptance mapping

- Paths switch: `switches DEFAULT_CONFIG paths to the openspec layout`.
- Watcher monitors openspec/changes: `monitors openspec/changes for approved
  change folders` (picks up + archives) and `does not pick up change folders
  left in the legacy specs/ directory`.
- Human steps outcome: `prints the Human steps outcome after the change
  completes`, seeded with the exact stop watcher / `osq migrate openspec` /
  `osq watch` steps from the parent spec.
- No directory move by the task: `never moves the legacy layout itself while
  cutting the runtime over` plus the `loop.ts` source assertion.
- Obsolete legacy identifiers absent: `removes obsolete legacy path
  identifiers from the runtime units` (source scan of `config.ts` and
  `loop.ts`) and `extracts a Human steps section from a change document`.

## Deviated

- The Human steps are read generically from the completed change's
  `## Human steps` section instead of hardcoding the cut-over instructions in
  `src/`. This keeps the runtime ignorant of any consumer project and still
  yields exactly the stop/migrate/restart steps because this change's
  `spec.md` carries them.
- Added `openspecRoot` (task 1's declared field) while in `config.ts` scope.
  Without it the cut-over defaults are incoherent with the cast-based lookups
  in `linter.ts`/`archiver.ts`. No behavior change: the fallback was already
  `'openspec'`.
- Human steps print when the change is archived (i.e. when the final task
  completes), not after every intermediate task, so mid-change manual guidance
  is never emitted prematurely.

## Missing context / repo-gate breakage

- Switching `DEFAULT_CONFIG` is a deliberately breaking cut-over. The full
  suite now reports 245/418 passing (173 failures): every out-of-scope test
  that scaffolds under `specs/`, reads `features/`, or asserts legacy
  `DEFAULT_CONFIG` paths now fails (e.g. `config.test.ts`, `watcher.test.ts`,
  `watcher-preflight.test.ts`, `archiver.test.ts`, `migrate.test.ts`,
  report/status/show suites). Those tests must be updated to create/approve
  under `openspec/changes` in a follow-up; they are outside this task's
  `scope`, and the task's own `verify` is green.
- `src/core/migrate.ts` derives its migration *sources* from `config.paths`
  (`features`, `specs`, `archive`). With the new defaults those point at the
  OpenSpec targets, so `osq migrate openspec` can no longer find the legacy
  directories. The human step printed by this task is therefore not executable
  until `migrate.ts` sources fixed legacy constants (`features`, `specs`,
  `specs/archive`). This file is out of scope here.
- `state.ts` and `linter.ts` still require a literal `spec.md` and resolve
  dependencies under a hardcoded `specs/`, so a proposal-only change cannot be
  approved or executed yet. The cut-over test writes both `spec.md` and
  `proposal.md` to stay within the current readers; migrating those readers to
  `resolveChangeDoc` is follow-up work.
- `@fission-ai/openspec` is still not installed in this checkout, so
  `openspec validate --strict` was not exercised here (it degrades to
  `ran: false`).
