# Task 3 result: deterministic OpenSpec delta requirement merging

## Changed

- `src/core/delta.ts` (new, pure engine)
  - `parseDelta`: parses `# Spec Delta: <capability>`, `## Purpose`, and the
    `## ADDED/MODIFIED/REMOVED/RENAMED Requirements` operation sections.
  - `parseRequirement` / `parseScenario`: extract requirement names, bodies, scenario
    names, and ordered `**WHEN**` / `**THEN**` bullets; canonical raw blocks are rebuilt
    in the source style for deterministic output.
  - `parseCapabilitySpec` / `serializeCapabilitySpec`: round-trip living capability specs
    (`# <capability> Specification` -> `## Purpose` -> `## Requirements`).
  - `mergeDelta(base, capability, delta)`: executes strictly
    RENAMED -> REMOVED -> MODIFIED -> ADDED; creates a new capability spec from the delta
    Purpose when no base exists; throws `DeltaMergeError` with a fixed message for a
    missing RENAMED/MODIFIED/REMOVED target.
- `src/watcher/archiver.ts`
  - New `applyOpenSpecDeltas(projectRoot, specFolderPath, config)`: reads every
    `<change>/specs/<capability>/spec.md` and deterministically merges it into
    `<projectRoot>/<openspecRoot>/specs/<capability>/spec.md`.
  - `applyDelta` now applies OpenSpec deltas first, then falls back to the legacy prose
    `## Delta` + `features.writes` behavior. Resolution now uses `parseSpecMdFromFolder`
    (proposal.md -> spec.md fallback).
- `tests/delta-merge.test.ts` (new): 11 tests covering all six acceptance lines plus
  archiver create/update and no-delta no-op behavior.

## Acceptance mapping

- Delta parser extracts ADDED/MODIFIED/REMOVED/RENAMED blocks:
  `parseDelta extracts ADDED, MODIFIED, REMOVED, and RENAMED blocks`.
- Requirement parser extracts names and WHEN/THEN bullets:
  `requirement parser extracts requirement names and scenario WHEN/THEN bullets`.
- Strict sequence RENAMED -> REMOVED -> MODIFIED -> ADDED:
  `merges operations in strict ... sequence` and `applies RENAMED before REMOVED and MODIFIED`.
- Missing MODIFIED/REMOVED targets throw deterministic error: two `assert.throws` tests
  matching the exact `DeltaMergeError` message.
- Non-existent capability creates new spec from delta Purpose:
  `creates a new capability spec from the delta Purpose when no base exists`.
- Golden-file byte-for-byte rebuild across all four operations:
  `golden-file test asserts byte-for-byte exact rebuilding across all four operations`
  (inline golden constant, plus exact round-trip on re-serialize).

## Deviations

- `applyOpenSpecDeltas` resolves the target specs root via an optional
  `paths.openspecRoot`, falling back to `'openspec'`. Reason: task 1's declared
  `openspecRoot` addition is not present in the working tree (`src/core/config.ts` still
  has no such field), and `config.ts` is outside this task's scope. The accessor keeps
  `tsc --noEmit` strict-clean now and becomes a no-op once task 1 lands the field.
- `applyDelta` now reads the change document through `parseSpecMdFromFolder` (proposal
  -> spec fallback) instead of `spec.md` only. Legacy `features.writes` behavior is
  preserved; `tests/archiver.test.ts` still passes.
- A missing RENAMED source also throws `DeltaMergeError`, beyond the two targets named
  in the acceptance line, to keep the sequence fully deterministic.

## Drift against features/

- `features/watcher-and-harness.md` still documents prose `## Delta` application into
  `features/*.md` and does not mention `openspec/specs/<capability>/spec.md` or
  requirement-level merging. Expected: the living-doc delta is applied at archive time;
  this task stayed inside its scope.
- `features/spec-lint-and-approve.md` describes only `spec.md` change documents.

## Missing context

- The canonical living spec layout was not specified beyond "merge into
  `openspec/specs/<capability>/spec.md`". Chosen format:
  `# <capability> Specification`, `## Purpose`, `## Requirements`, with requirement
  raw blocks preserved/canonicalized. No golden file existed, so the test defines it inline.
- The exact `paths.openspecRoot` value/placement depends on task 1, which is not in the tree.
