## Acceptance

- [ ] `HarnessExit` gains a public `error: Option<String>` with a one-line doc, and the `Harness` trait gains `harness_version(&self) -> Option<String>` with no default body. `run_task` returns an exited start's `HarnessExit` unchanged, as rust-runners "Harness and model per role" says, and `run/failure.rs` and every other runners file stay as they are.
- [ ] The fake harness in `tests/support/mod.rs` gains a version it returns from `harness_version()`, `None` by default, and a way for a test to set it. The `exit` helper builds an exit with no error, so the existing `run_task.rs` tests keep their assertions.
- [ ] A new test in `crates/kernel/runners/tests/run_task.rs` proves "Exit error and harness version", one assertion per row that names the row.
- [ ] `PiHarness` behaves as rust-harnesses "Pi harness" says. `last_error()` and its field are gone, `PiHarness::failure` fills the exit's `error`, and `with_preflight` and `harness_version()` are public. `PiReady` is reused from the pi preflight module and is not copied.
- [ ] `crates/kernel/harnesses/tests/pi_harness_run.rs` reads the exit's `error` wherever it read `last_error()`, and its row values do not change. `settled_start_hides_stderr` stays and checks the exit's `error`. New `crates/kernel/harnesses/tests/pi_harness_version.rs` proves "Pi harness version", one assertion per row that names the row, without starting a program.
- [ ] Each function that implements a requirement ends its doc with its `Implements:` line, such as `Implements: rust-harnesses/pi-harness`. Each new test's one-line doc names `Covers: rust-runners/exit-error-and-harness-version` or `Covers: rust-harnesses/pi-harness-version`.

## Details

Port the result fields from `PiAdapter.spawn` in `src/harness/pi/pi.ts`.
It returns `error: settled ? undefined : error`, and it gives
`harnessVersion` to `onSpawn` only when the probed version is non-empty.

Keep every condition observable for cargo-mutants. The blank-version rows
check the trim, and the settled-with-stderr test checks that a settled
start has no `error`.

Before exiting, run `cargo fmt --all`, then
`OSQ_CHANGE=openspec/changes/254-rust-harness-port-results sh scripts/verify-rust.sh`
so the link-gate corpus test sees this change's requirements.
