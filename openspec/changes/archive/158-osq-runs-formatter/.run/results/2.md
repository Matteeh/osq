## Changed

- `src/harness/types.ts`: added `format_ran` to `HarnessEventType`, exported `FormatRanEventData` (`command`, `files`, `exitCode`, `duration`, `timedOut`, optional `output`), and wired it into `OsqEventData`.
- `src/watcher/measures.ts`: `createTaskMeasures` now also returns `changedScopeFiles()`, which compares the scope now against the `before` snapshot `emitStart` took and returns the sorted paths whose current hash is non-null and differs; empty before `emitStart`.
- `src/watcher/format-files.ts` (new): the format step. Reads `config.gates?.formatCommand`, gets the changed files from the measures, replaces `{files}` the way `runFocusedTests` does, runs through `runVerificationCommand` with the change folder and `{ config }`, appends one `format_ran` event (output cut by `tailVerifyOutput`, omitted when blank), and warns once with the exit code on a failed/timed-out/thrown run. Never ends the attempt.
- `src/watcher/task-verify.ts`: added `TaskVerifyMeasures` and the optional `measures` on `TaskVerifyOptions`; `checkBlockedFirst` runs the format step after the missing-verify-path check and before `checkFocusedTests`; doc comment names the step.
- `src/watcher/runner.ts`: changed only the existing `checkBlockedFirst(verifyCtx, fail)` line to `checkBlockedFirst({ ...verifyCtx, measures }, fail)`; file stays at 199 lines.
- `tests/format-before-verify.test.ts` (new): covers every scenario of "Format before verify" through `runTask` with `approveSpec`, `scaffoldProject`, `installFakeValidator`, a result-mutating adapter, and `preSpawnVerify: 'off'`/`autoRetries: 0`; `.cjs` format and verify scripts built from line arrays; the done-marker hash checked with `hashFileForMeasures`; a warn-recording logger for the failing-format case.

## Deviated

- The test file needed biome's formatter/import sorting; I ran `biome format --write` and fixed the import order on the new test only. No preexisting test was modified.
- `format-files.ts` also logs the thrown-error message at `verbose` in addition to the single `warn`; the acceptance only requires the warn with the exit code.
