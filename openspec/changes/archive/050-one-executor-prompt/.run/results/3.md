## Changed

- `src/core/foundation/doctor-managed.ts`: `checkManagedBlocks` now takes the
  loaded `OsqConfig`. Init-owned files (`AGENTS.md`, `PLANNER.md`, the Claude
  command) still report `(run osq init)`. When `config.harness` or
  `config.planner?.harness` is `opencode`, it also reads
  `.opencode/agent/<config.opencode?.agent ?? DEFAULT_CONFIG.opencode?.agent>.md`
  and compares it with `MANAGED_AGENTS_MD_BODY` via `inspectManagedBlock`; a
  missing file or bad block reports `(run osq setup)`. Failure groups are joined
  init-first then setup with `; `. No literal `osq-coder` was written; the
  default comes from `DEFAULT_CONFIG.opencode?.agent`.
- `src/core/foundation/doctor.ts`: `checkManaged` accepts the loaded config and
  forwards it; `runDoctorChecks` passes `config`.
- `tests/doctor-agent-file.test.ts` (new): builds a healthy repo like
  `tests/doctor.test.ts` (current managed files plus
  `openspec/changes/archive/`) and exercises `runDoctorChecks` with injected
  `loadConfig`/`probeValidator`, asserting only the `managed-blocks` check.
  Covers a missing agent file, a stale block, a current block written by
  `OpencodeAdapter.setup`, a custom `opencode.agent` name, an `opencode`
  `planner.harness` with a `mock` executor, a `codex` harness with no agent file
  passing, and a stale `AGENTS.md` plus stale agent file yielding both suffixes.
