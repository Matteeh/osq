## Details

This task's `scope` is authoritative over any injected code-ownership rules.

Reuse `inspectManagedBlock` and the `PROBLEM_TEXT` map in `doctor-managed.ts`.
Take the agent name from `config.opencode?.agent`, falling back to
`DEFAULT_CONFIG.opencode.agent`; write no literal `osq-coder` in code. The path
in messages is relative to the project root, for example
`.opencode/agent/osq-coder.md`. `osq setup` writes the file for both the
execution and the planner harness, which is why either one triggers the check.

The healthy repository in `tests/doctor.test.ts` uses the `mock` harness, so
it needs no agent file. Build the new test's healthy repository the same way:
`AGENTS.md`, `PLANNER.md`, and `.claude/commands/osq-plan.md` holding the
managed constants from `src/core/foundation/init.js`, and
`openspec/changes/archive/`. Use `defineConfig` from `src/index.js` for the
injected configs, and `OPENSPEC_EXPECTED_VERSION` from
`src/core/spec/linter.js` for the validator probe. Assert on the
`managed-blocks` check only.
