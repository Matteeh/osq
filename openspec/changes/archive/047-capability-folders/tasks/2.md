### How to rewrite specifiers

Do all `git mv` calls first. The rewrite is mechanical. For each relative
specifier in a file under `src/`, `tests/`, or `packages/ui/src/`, resolve it
against the importing file's old location, map the target through the table,
and recompute the specifier from the importing file's new location, keeping
the `.js` suffix. Specifiers between two files that moved into the same folder
become `./<name>.js`; imports from `src/core/<folder>/` into `src/harness/`
become `../../harness/...`, and so on. You may run a throwaway rewrite script
from the OS temp directory, but do not add one to the repository. Then let
`pnpm typecheck:cli` (src and `tests/**/*.ts`) and `pnpm typecheck:ui`
(`packages/ui` and `tests/**/*.test.tsx`) find any specifier you missed.
Neither sees path strings, which are listed next.

### Why this is one task

Eleven of the fifteen harness files import core modules, so moving core
already edits them. A separate harness task would change files inside this
task's scope and halt the change for recertification. `tests/import-graph.test.ts`
derives tiers from the first segment under `src/` and needs no change for
subfolders. `tests/line-budget.test.ts` keys on base names and needs none
either.
