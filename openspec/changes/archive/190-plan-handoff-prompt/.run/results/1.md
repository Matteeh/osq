## Changed

- Added `src/core/foundation/plan-handoff.ts` exporting `formatPlanPasteBlock(folderPath)`
  and `formatPlanHandoff({ folderPath, nextStep, slashCommandId })`. Both are pure text
  builders that read no file, and return exactly the lines cli-foundation "Plan paste block"
  gives, each followed by a newline.
- Added `src/cli/plan-prompt-handoff.ts` with `writePromptHandoff(options)`, moved out of
  `src/cli/plan.ts`. It writes `plan-prompt.md`, resolves `slashCommandId` to the change's id
  only when `.claude/commands/osq-plan.md` exists under the working directory and the folder's
  parent is the changes directory, and prints `formatPlanHandoff`.
- `src/cli/plan.ts` now imports `writePromptHandoff` from the new module and passes
  `folderPath`, `openingPrompt`, `nextStep`, `specId`, `cwd`, `changesDir`, and `stdout`.
  `--print` and `--session` are untouched. The file dropped from 249 to 242 lines.
- Added `tests/plan-paste-block.test.ts` proving "Paste block text" directly and the four
  "Plan handoff with the paste block" scenarios through `planCommand` (including a copied
  steered-worktree setup and `.claude/commands/osq-plan.md` written into the checkout).
- Updated only the one-line handoff assertions in `tests/plan-handoff.test.ts`,
  `tests/plan-approve-next-step.test.ts`, and `tests/queue-plan.test.ts` to check the first
  line, and the expected text of "prepares the prompt for a change that has a brief" in
  `tests/mcp-tools.test.ts` to `formatPlanHandoff`.
