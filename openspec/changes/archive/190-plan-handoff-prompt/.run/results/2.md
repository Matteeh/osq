## Changed

- `src/cli/remote-plan.ts`: `emitHandoff` now finds the server's handoff line,
  prints every line before it unchanged, downloads the folder to the working
  copy, and prints `formatPlanHandoff({ folderPath, nextStep, slashCommandId: null })`
  in place of that line and everything after it. Without a handoff line the
  collected text is printed unchanged, `--print` and a failed command are
  untouched, and `planOnServer` keeps its
  `@scenario cli-foundation: Plan downloads a working copy` and `@adr 014`
  tags. Removed the now-unused `rewriteHandoff`; refreshed the `planOnServer`
  doc wording.
- Added `tests/remote-plan-handoff.test.ts`, copying `tests/remote-plan.test.ts`'s
  setup (its own `startWebServer` + `createForwardedRunner` runner and a
  `.claude/commands/osq-plan.md` in the checkout, so the server itself prints
  the Claude Code line). It proves "Plan downloads a working copy" by asserting
  stdout is exactly the scenario table's lines with the working-copy path and
  the server's next step, that the working copy holds the server folder's files
  with `.run/` left out, that no output line holds `/osq-plan`, and that a line
  the server prints before the handoff comes through unchanged.

## Deviated

  the same `readNextStep`/`formatNextStep` the server uses, then asserts
  equality against an explicitly built table-shaped string rather than against
  `formatPlanHandoff` itself.
- The real server never prints a line before the handoff, so the
  preceding-lines case uses a server whose `runCommand` emits one preamble line
  and then delegates to `createForwardedRunner`.
