## Changed

- `crates/features/plan/Cargo.toml` adds `osq-kernel-config` and `osq-kernel-vcs` as workspace dependencies.
- `crates/features/plan/src/next/number.rs` keeps the checkout's direct entry scan, then with `vcs.enabled` adds the leading numbers from `list_tree_changes(change_trees(...))`, the folders under `stacked_root`, and every `osq/` branch. Worktrees, branches and the repository root all run through one `GitVcs` built with `with_timeouts(&config.timeouts)`.
- `crates/features/plan/src/next.rs` turns a config or git error into `FeatureError::failed("plan", <display>)` before writing any change folder.
- Added `crates/features/plan/tests/next_number_trees.rs` proving both required scenarios on scratch git repositories with a real `git worktree`, a branch with no worktree, and the scratch repository's own git identity. It also counts a stacked approval folder.

## Deviated

- Added a third test, `next_change_number_counts_stacked_approvals`, beyond the two named scenarios, to exercise the stacked-folder branch of the numbering rule and keep the new lines mutation-tested.

## Missing context

- `sh scripts/verify-rust.sh` on its own fails the link-gate corpus because the in-flight delta's tags are not yet living; running it with `OSQ_CHANGE=openspec/changes/264-rust-worktree-changes`, as the watcher does, passes.
