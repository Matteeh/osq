## Acceptance

- [ ] New `crates/core/src/schedule.rs`, with files beside it under `crates/core/src/schedule/` as you see fit, holds `lock_unit`, `schedule`, `QueuedChange`, `Dependency`, `RunningChange`, `Schedule`, `ScheduledChange` and `ScheduleState`, following rust-core "Lock units", "Change scheduling" and "Schedule states".
- [ ] `QueuedChange`, `Dependency`, `RunningChange`, `Schedule` and `ScheduledChange` have public fields named as the requirement names them, with `String` ids and `Vec<String>` files. `ScheduleState` is an enum with `Ready`, `NeedsApproval`, `WaitingOn(String)` and `BlockedBy { id: String, shared: Vec<String> }`, and implements `Display` as the requirement's reasons. All types derive `Debug`, `Clone`, `PartialEq` and `Eq`.
- [ ] `lock_unit(path: &str) -> String` and `schedule(queue: &[QueuedChange], running: &[RunningChange]) -> Schedule` behave as the requirements say; `schedule` compares lock units, not files.
- [ ] `src/lib.rs` declares `pub mod schedule;` and re-exports those eight items. Nothing else in it changes.
- [ ] New `crates/core/tests/schedule.rs` proves "Lock unit of a path", "Every state and overlap rule" and "Running changes come first" with the literal values of their tables, checking each state and its `Display` text.
- [ ] New `crates/core/tests/schedule_props.rs` proves "Scheduling is deterministic", "Started and running changes never overlap" and "An unmet dependency never starts" with `proptest`, as `crates/core/tests/fold_props.rs` does, over queues of up to 8 changes and up to 3 running changes whose ids and files come from small fixed pools, so overlaps and shared crates happen often.
- [ ] Every public item's doc ends with `Implements: rust-core/lock-units`, `Implements: rust-core/change-scheduling` or `Implements: rust-core/schedule-states`, and each test's one-line doc names `Covers: rust-core/<scenario>` in kebab-case, such as `Covers: rust-core/every-state-and-overlap-rule`.

## Details

Core does no IO (rust-core "Core does no IO"): no file under
`crates/core/src/` may contain the text `std::fs`, `std::process`,
`std::env`, `std::net`, `std::thread`, `SystemTime` or `Instant`, comments
included, and core gains no dependency.

cargo-mutants runs on every line this task adds. Each step of the state
order, the crate prefixes in `lock_unit` and the byte order of `shared` must
change a value a test checks. Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-core -f <file> -o "$(mktemp -d)"` on each new source
file, then `sh scripts/verify-rust.sh`.
