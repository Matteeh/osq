## Changed

- Added `src/core/spec/requirement-lookup.ts`: `lookupRequirement(projectRoot, openspecRoot, capability?, requirement?)` lists living capability names, one capability's requirement names in `parseCapabilitySpec` order, or one requirement's verbatim `raw` block. It lists first, then checks membership before joining any path, and throws a plain `Error` with the delta's exact messages for an unknown capability or requirement.
- Added `src/cli/spec.ts`: `specCommand(capability?, requirement?, options)` with optional `cwd`, `config`, and `stdout`, printing each lookup result followed by one newline and wrapping lookup failures in a `CommandError` carrying the same message. `registerSpecCommand(program)` registers `osq spec [capability] [requirement]` with the delta's description.
- `src/cli/index.ts`: imported and registered `registerSpecCommand`, and folded each `-print` argv rewrite's `raw` local into its `map` call. The file stays at 249 lines.
- `README.md`: added an `osq spec [capability] [requirement]` line after `osq show <id>`, and changed the executor description to read the requirements a task names through `osq spec <capability> <requirement>` instead of whole capability docs.
- Added `tests/spec-command.test.ts`: covers every scenario of the spec-lint-and-approve delta's "Living requirement lookup" and "Living requirement lookup errors" and the cli-foundation delta's "Spec command" and "Spec command documentation".

## Deviated

- The lookup reuses the existing `specDirectories` helper from `src/core/spec/scenario-impact.ts` to list the directories that hold a `spec.md`, instead of open-coding the same `readdir`/`stat` logic. This keeps one definition of "living capability" and the delta only mandates `getSpecsDir`, `parseCapabilitySpec`, and `normalizeRequirementName`, which are all still used.
