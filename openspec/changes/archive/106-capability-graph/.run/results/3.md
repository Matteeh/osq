## Changed

- Added `src/core/web/system-graph-trace.ts` (`buildSystemGraphTrace`): for
  every capability `optedInCapabilities` opts in with a living spec it builds
  the `test` and `function` nodes and the `owns`, `proves`, `covers`, `serves`,
  and `follows` edges, marks the `untested` scenarios and `unclaimed`
  functions, and returns the per-capability `gaps` plus the scenario gap map.
  Owned functions come from `ownedFunctions`, unclaimed counts from the same
  list filtered by `scenarios.length === 0`, survivors from `collectMutationScores`
  flattened per `<file>#<function>` and deduped, and `follows` matches ADR
  numbers with `sameAdrNumber`.
- `src/core/web/system-graph-types.ts`: added `SystemGraphTracePart`,
  `SystemGraphTraceInput`, and `SystemGraphNodeSet<T>`.
- `src/core/web/system-graph.ts`: `getSystemGraph` now builds one import graph
  and one scenario index per call, reads the active and archived change folders
  through `listChanges`, collects the mutation scores, calls
  `buildSystemGraphTrace`, and applies its `traceability`/`gaps` to capability
  nodes and its `untested` gaps to scenario nodes before the final sort.
- Added `tests/web-system-graph-trace.test.ts`: covers the five "System graph
  traceability" scenarios (pricing sample, surviving mutant, unknown `@adr`,
  not opted in, 2,000 scenarios) and the "Untested and unclaimed" and "Same
  counts as the report" scenarios of "System graph gaps" through
  `getSystemGraph` on temporary copies of `fixture/trace/pricing`, with the
  2,000-scenario build time reported via `t.diagnostic`.

## Deviated

`getSystemGraph` builds one import graph for the scenario index and the
traceability part, but `buildSystemGraphCode` still builds its own because
`src/core/web/system-graph-code.ts` was not in this task's scope. The
acceptance line asking for a single import graph shared with the import edges
and unowned file nodes therefore holds only for the traceability side.

## Missing context

To meet that acceptance line, `src/core/web/system-graph-code.ts` needed to be
in scope (or its `buildSystemGraphCode` needed to already accept a prebuilt
import graph from task 2). As written, the executor cannot pass the shared
graph to the code part without editing a file outside `scope`.

## Next
