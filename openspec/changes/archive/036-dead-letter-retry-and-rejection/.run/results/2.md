# Task 2 result — eligible change rejection moves its complete record

## Changed

- `src/core/layout.ts`: added `getRejectedDir(openspecRoot, projectRoot)` for
  `openspec/changes/rejected`, beside the canonical changes/archive helpers.
- `src/harness/types.ts`: added `'rejected'` to `HarnessEventType`, a
  `RejectedEventData { reason }` payload, and the member in `OsqEventData`. No
  existing event type was weakened.
- `src/core/reject.ts` (new): `rejectSpec(projectRoot, specIdOrPrefix, reason,
  config)`. Trims and requires a non-empty reason, resolves only active change
  folders via `findSpecFolder`, and refuses a destination collision before any
  mutation. Reads running markers and approval directly via `readChangeFolder`;
  a live running marker is refused even when `deriveSpecState` precedence would
  report dead/regressed. An approved folder is eligible only when the derived
  status is `dead` or `regressed` (active numeric markers or
  `regressed/change.md` only); an unapproved folder is eligible. Success does
  one `fs.rename` into `rejected/<original-folder-name>/`, then writes
  `.run/rejected.md` and appends one typed `rejected` event to
  `.run/events/change.jsonl`, both sharing one generated ISO timestamp and the
  trimmed reason.
- `src/cli/reject.ts` (new): thin `rejectCommand(id, { reason })` that loads
  config, calls `rejectSpec`, prints the destination, and exits non-zero on
  refusal.
- `src/cli/index.ts`: registered `reject <id>` with required
  `--reason <text>` and an `InvalidArgumentError` parser rejecting empty or
  whitespace-only reasons at the Commander boundary.
- Tests: new `tests/reject.test.ts` (15 cases) and three new cases in
  `tests/cli.test.ts` covering wiring, reason validation, every eligibility
  class, exact destination, collision refusal, marker/event agreement, and
  byte-for-byte content retention.

## Deviated

- Reused the canonical layout and parser/state helpers, but did not call
  `appendHarnessEvent`: `src/core` may not import `src/harness`
  (`tests/import-graph.test.ts`). `src/core/reject.ts` appends the typed event
  directly, mirroring `src/core/done.ts` and `src/core/retry.ts`. The emitted
  shape matches the union exactly.
- The `rejected` payload carries `reason`; the shared ISO timestamp is the
  event's top-level `timestamp`, as the task details specify.
- Marker reason and timestamp are serialized with `JSON.stringify` (valid YAML
  double-quoted scalars) so arbitrary reasons round-trip through
  `parseFrontmatter`.
