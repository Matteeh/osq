# Task 3 result — rejected state projections in status, dependencies, lint, and reports

## Changed

- `src/core/status.ts`: added `RejectedSpecSummary` and `StatusOverview.rejected`;
  `getStatusOverview` now discovers folders under the canonical rejected
  directory (sorted with `compareNumericPrefix`), reads title from the change
  document and reason/timestamp defensively from `.run/rejected.md` via
  `parseFrontmatter`, and excludes the `rejected` directory from active
  candidates. `formatStatusOverview` renders a deterministic `Rejected specs`
  group using `unavailable` for missing/malformed metadata. Rejected folders no
  longer short-circuit discovery when the changes directory is absent.
- `src/core/state.ts`: `isDependencyDone` explicitly recognizes a folder under
  `changes/rejected/` and always returns `false`, even when its preserved folder
  contains done markers. The function was compacted so the file stays inside the
  250-line source budget.
- `src/core/linter.ts`: dependency existence now also searches
  `getRejectedDir(...)`, so a `depends_on` reference retained in rejected history
  lints as an existing (historical) change.
- `src/core/report.ts`: added `RejectionHistory` to `HistoryMetrics`
  (`history.rejections.total` / `byPlannerModel`). Rejected folders are
  discovered separately from the active/archive scans (never added to
  `allSpecFolders`), count at most once only when `.run/events/change.jsonl`
  contains a valid `rejected` event, parse malformed lines defensively, read
  planner attribution only from non-empty `brief.md` frontmatter (`unknown`
  otherwise), and sort group keys deterministically. The History text section
  renders `Rejections: <n>` and per-model counts.
- `src/cli/report.ts`: `toStableMetrics` exposes `history.rejections` while
  preserving every existing top-level and nested shape.
- `src/core/layout.ts`: added `getRejectedMarkerPath` alongside `getRejectedDir`.
- `fixture/report/`: added `specs/rejected/011-rejected-known` (planner recorded,
  duplicate rejected events, malformed lines, preserved tasks/plan/events),
  `012-rejected-unknown` (no planner), and `013-rejected-handmoved` (marker and
  preserved artifacts but no valid `rejected` event). `expected.json` gained only
  the `history.rejections` block; all other fixture bytes are unchanged and
  rejected artifacts are proven excluded from every aggregate.
- Tests: new `tests/status-rejected.test.ts`, `tests/state-rejected.test.ts`,
  `tests/report-rejected.test.ts`; added a rejected-dependency lint case to
  `tests/linter.test.ts`; updated `tests/report-json.test.ts` and
  `tests/regression-status.test.ts` for the additive shapes.

## Deviated

- `src/cli/report.ts` is edited although it is not listed in the task `scope`.
  The JSON projection (`toStableMetrics`) lives there, and the acceptance lines
  require `history.rejections` in JSON text output plus a deterministic fixture
  round-trip through the real report command. Keeping the edit is the only way
  to satisfy them; the task details' explicit reference to `serializeSortedJson`
  points at this file.
- `src/core/report.ts` keeps the legacy `specs/` fallback and therefore resolves
  rejected history from `specs/rejected` when a project uses the legacy layout;
  the checked-in report fixture is a legacy-layout fixture. Canonical projects
  use `getRejectedDir(...)`.
- The task detail suggested extending runtime dependency resolution explicitly;
  the existing resolver never scanned `rejected/`, so the added branch is
  behavior-preserving and only documents the invariant.
