## Acceptance

- [ ] The real CLI registers `reject <id>` with required `--reason <text>`, and both Commander validation and the core transition reject an empty or whitespace-only reason.
- [ ] Reject resolves only an active change and allows an unapproved change, or an approved change with an active numeric dead/regressed marker or `regressed/change.md` and no running task.
- [ ] Healthy approved, completed, running, archived, already rejected, missing, and destination-colliding changes are refused without moving or overwriting a folder.
- [ ] Success moves the original folder to `openspec/changes/rejected/<original-folder-name>/` without applying deltas, changing task checkboxes, or altering any pre-existing authored or `.run` file.
- [ ] The moved folder gains `.run/rejected.md` with YAML reason and timestamp and one typed `rejected` event in `.run/events/change.jsonl` carrying the same reason and timestamp.
- [ ] Brief, proposal, task files, delta specs, results, failure markers, `plan.jsonl`, and existing event bytes are retained across the move.
- [ ] Tests drive the command wiring and core filesystem transition for every eligibility class, exact destination, collision refusal, marker/event agreement, and retained-content invariants.

## Details

Add `getRejectedDir` beside the canonical changes and archive layout helpers.
Implement a thin `rejectCommand` and a core `rejectSpec` transition, reusing
`findSpecFolder`, `readChangeFolder`, `deriveSpecState`, `parseFrontmatter`, and
`appendHarnessEvent`. Resolve only beneath the active changes directory; do not
teach the shared active-folder resolver to find archived or rejected folders.

Check the destination and every eligibility condition before `fs.rename`.
Inspect running markers directly so a running task cannot be hidden by another
state-precedence result. For an approved folder, accept `dead`, `regressed`, or
a change-level regressed marker only; do not treat historical suffixed markers
as active failures. An unapproved folder remains eligible under the parent
contract.

Move the directory as one filesystem rename, then create the rejection marker
and append the event against the destination folder. Generate one ISO timestamp
for both artifacts. Store the reason as safely serialized YAML frontmatter;
the event timestamp is the event's top-level timestamp and its typed data carries
the reason. Add `rejected` and its payload to the existing discriminated event
union without weakening any existing event type.

Snapshot representative files before the transition and compare their bytes
afterward. Tests should include a brief and proposal, tasks and delta, planning
log, task event stream, result, and dead or regressed marker so preservation is
proved rather than inferred from directory existence. Existing files below
`.run/` may not be rewritten merely to append the change-level rejection event.
Run the task verify and `pnpm verify` before exit.
