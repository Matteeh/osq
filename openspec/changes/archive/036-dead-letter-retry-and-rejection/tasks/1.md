## Acceptance

- [ ] The real CLI registers `retry <id> <target>` and accepts only an existing numeric task with an active dead or regressed marker, or the literal `change` with an active change-level regression.
- [ ] Retry refuses a running target and refuses a missing or mismatched approval hash before mutation, preserves all files and events on refusal, and names `osq approve <id>` as the hash-remediation command.
- [ ] A successful retry renames active dead and regressed markers to the next shared failure ordinal without deletion; task regression also retains its active done marker under an inactive suffixed name so state becomes pending, while change regression becomes archiveable again.
- [ ] Approval no longer renames active dead markers, and retry appends one typed event containing target, reason, next execution attempt, and timestamp to the target event stream.
- [ ] Every new started event records attempt 1 initially or the matching next retry attempt, derived entirely from retained files and append-only events after restart.
- [ ] AGY, OpenCode, Codex, and mock execution receive the retry attempt and failure reason through shared spawn options; all three textual prompts name the prior failure and existing prior-result path without removing that result before spawn.
- [ ] A fixture using the real CLI and mock harness runs `watch --once`, dies once, runs `retry`, runs `watch --once` again, and lands while asserting the renamed marker, retry event, matching started attempt, and preserved result context.

## Details

Add a thin `retryCommand` and a core retry transition, reusing
`findSpecFolder`, `getChangesDir`, `hashChangeFolder`, the canonical layout
helpers, `parseFrontmatter`, and `appendHarnessEvent`. Resolve only active
change folders. Validate the task file or literal change target, approval hash,
active failure marker, and running marker before the first rename or event
append. Missing approval is the same remediation class as hash mismatch.

Treat attempt as a target-wide execution ordinal across both dead and regressed
history. The active failure belongs to the current attempt and is renamed with
the next ordinal after all retained `dead/<target>.<n>.md` and
`regressed/<target>.<n>.md` files. The `retry` event names the following
execution attempt. When a numeric regression has `done/<n>`, rename it to
`done/<n>.<failed-attempt>`; never unlink it. If both active failure kinds are
present for malformed legacy state, preserve both with the same current
ordinal and use the state-precedence regression reason for retry context.

Remove `retainDeadMarkers` from `approveSpec` and reverse the old retention test
expectation: approval may refresh `.run/approved` and the manifest but must not
change any dead or regressed marker. Do not move failure-transition behavior
into approval.

Extend the typed event union with `retry` and add `attempt` to newly emitted
started data without rejecting legacy started lines that lack it. Reuse
`spawnTaskAgent`, `recordLifecycleEvent`, and `appendHarnessEvent`; read the
latest applicable retry event before spawn so process restarts do not lose the
attempt or reason. Initial starts use attempt 1. A retried start must use the
attempt recorded by the immediately preceding retry transition.

Carry attempt and optional prior-failure reason on the existing shared
`SpawnTaskOptions` port. Update `buildAgyPrompt`, `buildOpencodePrompt`, and
`buildCodexPrompt` to render one consistent prior-context section containing
the failure reason and `.run/results/<n>.md` when it exists. Codex already
detects the prior result; reuse that behavior for all adapters rather than
adding harness-specific filesystem state. The mock adapter need not render a
text prompt, but must receive the same shared options for integration
assertions.

Add focused transition and prompt tests plus `tests/retry-watch.test.ts`. The
integration fixture must launch the source CLI non-interactively in a temporary
project configured with the mock harness. Use a deterministic verification
command whose first invocation fails and whose later invocations pass without
modifying the authored change folder, then inspect the archived folder after
the second watcher run. Keep unrelated harness, watcher, and test files frozen.
Run the task verify and `pnpm verify` before exit.
