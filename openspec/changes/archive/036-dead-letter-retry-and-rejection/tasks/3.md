## Acceptance

- [ ] StatusOverview discovers rejected folders separately and text output renders a deterministic `Rejected specs` group with folder, title, reason, and timestamp, without adding them to active specs or archived counts.
- [ ] Missing or malformed rejection markers remain visible with explicitly unavailable metadata and do not prevent other status groups from rendering.
- [ ] Dependency existence lint accepts an identifier found under `rejected/`, while runtime dependency resolution always leaves a dependent change blocked even if the rejected change contains done markers.
- [ ] MetricsReport exposes `history.rejections: { total, byPlannerModel }`, counts each rejected folder at most once only when it has a valid rejected event in `events/change.jsonl`, and sorts model keys deterministically.
- [ ] Rejection grouping reads only a non-empty `planner` value from `brief.md` frontmatter and uses `unknown` otherwise, with grouped counts summing to the rejection total.
- [ ] Rejected changes do not enter current task counts, completion rate, execution attempts, planning totals, or archived cycle rows merely because their preserved artifacts resemble active or archived state.
- [ ] Focused status, dependency, lint, text-report, JSON, malformed-data, and deterministic fixture tests pass without weakening existing state or report assertions.

## Details

Reuse `getRejectedDir`, `resolveChangeDoc`, `parseFrontmatter`,
`deriveSpecState`, `getStatusOverview`, `formatStatusOverview`,
`getMetricsReport`, `formatMetricsReport`, and `serializeSortedJson`. Add a
small rejected summary type to status rather than representing rejected folders
as active `SpecState`; rejection is a terminal location, not a new task state.
Read `.run/rejected.md` defensively and sort entries with
`compareNumericPrefix`.

Extend dependency existence lookup to search the rejected directory so the
authored reference remains valid. Extend completion resolution explicitly so
rejected is recognized but always false. Do not infer landing from all-done
markers, approval, or proposal contents inside a rejected folder.

Extend the post-035 report shape without renaming or restoring any existing
top-level block. Use the exact nested keys `history.rejections.total` and
`history.rejections.byPlannerModel`. Discover rejected folders separately from
active and archive scans. A folder contributes once when at least one valid
`rejected` event exists in its change-level stream; duplicate valid events do
not inflate the change count. Parse malformed event lines defensively. Read
planner attribution from `brief.md`, never from the event, manifest, planning
log, model heuristics, or folder metadata.

Render a concise rejection line in the existing History text section. Extend
the checked-in report fixture with rejected changes covering a known planner
and `unknown`, and update its complete sorted expected JSON after dependency
035 has established the planning and cycle fields. Preserve every unrelated
post-035 report shape and exclude rejected folders from all non-rejection
aggregates. Run the task verify and `pnpm verify` before exit.
