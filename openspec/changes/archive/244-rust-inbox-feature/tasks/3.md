## Details

The rules come from `projectRunning`, `collectLandedItems` and
`projectInbox` in `inbox.ts`, `readValidatorFailing` in
`validator-failing.ts`, `validatorFailingItem` and `readInbox` in
`inbox-projection.ts`, `runningLine` and `landedLine` in `inbox-text.ts`,
and `formatDuration` in `src/core/report/report.ts`. Read them only to
check a rule; the delta is the contract and its tables were printed by
TypeScript. Rust code never imports or calls anything under `src/`.

Running needs a task whose folded status is `Running`, which a `started`
event as the stream's last event gives. Round the elapsed seconds half up,
as JavaScript's `Math.round` does; `f64::round` agrees on every value at or
above 0, and anything below 0 counts as 0. A pid of 0 is never live.

Landed and validator ids and titles fall back to the folder name. The
golden text also checks every needs-you line again and where the validator
item sorts among them.

If the golden test fails, the inbox is wrong, not the golden. Say in
`## Deviated` which rule you found and how you matched it.

cargo-mutants runs on every line this task adds, so each condition must
change a value a row checks: the live-pid check and pid 0, the clamp at 0,
each duration branch, the ten-item cut, the newest-first sort and its id
tie-break, the missing archive time, each disclosure count, the `not_run`
skip, the failing outcome set, the in-a-row count and the error fallback.
Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-feature-inbox -f <file> -o "$(mktemp -d)"` on each
new or changed source file, then `sh scripts/verify-rust.sh` with
`OSQ_CHANGE` set to `openspec/changes/244-rust-inbox-feature`.
