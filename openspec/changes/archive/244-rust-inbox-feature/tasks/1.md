## Details

The rules come from TypeScript's `readChangeFolder` and
`deriveTaskStateFromSnapshot` in `state.ts`, `readMissingEntryNeed` in
`blocked-item.ts` and `parseHumanSteps` in `human-steps.ts`. Read them only
to check a rule; the delta is the contract. Rust code never imports or
calls anything under `src/`.

Write the test folders as `reading_specs_outcomes.rs` does, with a
`temp_root` that removes any leftover folder of the same name and a
`write` that creates parent folders, and give every test its own folder
name, since tests run in parallel. Each scenario's change folder is an
active change, `openspec/changes/<folder>/`, with a `proposal.md` titled
after the folder except where the row says otherwise, and task files whose
frontmatter holds only a `title`. Read it with `list_changes` and
`read_change`.

A marker is keyed by its file name without `.md` or `.pid`; only keys that
are a task id of the change count for a task, and `change` counts for
`change_regressed`. Read the result file of a task only for its `blocked`
section.

cargo-mutants runs on every line this task adds, so each condition must
change a value a row checks: the boolean `true` checks, the non-string
reason, the `- ` entry match and its empty-text skip, the whole-number
lock fields, the `None`/`None.` normalization and both `###` headings.
Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-kernel-storage -f <file> -o "$(mktemp -d)"` on each
new or changed source file, then `sh scripts/verify-rust.sh` with
`OSQ_CHANGE` set to `openspec/changes/244-rust-inbox-feature`, so the link
gate corpus test sees this change's new requirements.
