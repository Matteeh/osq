## Details

The rules come from `projectNeedsYou` in `inbox.ts`, `applySteeringItems`
and `readNeed` in `blocked-item.ts`, `deriveSteering` in `steering.ts`,
`readActiveNextStep` in `next-step.ts` and `needsYouLine` in
`inbox-text.ts`. Read them only to check a rule; the delta is the contract
and its tables were printed by TypeScript. Rust code never imports or
calls anything under `src/`.

Take each change's status from its snapshot's folded state
(`state.record().regressed` and the `state.tasks()` statuses) and the
steering facts from the snapshot fields task 1 added (`proposal`, `brief`,
`before_approval`, `change_regressed`, and each task's `done` and
`markers`). Only snapshots whose location is `Active` give needs-you items
here; task 3 uses the archived ones. A task's number in item text is its
`TaskId` as written.

Build `Command`, `Output` and `FeatureError` only through their
constructors, and match `FeatureError` with a wildcard arm, as
`crates/core/tests/feature.rs` does. `at` keeps the time in the struct for
task 3; `new` stores none.

cargo-mutants runs on every line this task adds, so each condition must
change a value a row checks: the placeholder's word count, both flags, the
`;` strip and whitespace removal, the brief choice, the before-approval
flag, the dead and regressed statuses, every trigger reason, the passing
scope regression, the done check, the first-trigger pick, both needs and
the whitespace collapse. Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-feature-inbox -f <file> -o "$(mktemp -d)"` on each
new source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE` set to
`openspec/changes/244-rust-inbox-feature`.
