## Changed

- Added private `src/groups/` with `mod.rs`, `running.rs`, `landed.rs` and `validator.rs`: pure functions from snapshots to the Running and Landed lines and the one validator-failing item, using `needs::Item`. `running.rs` holds the one `/proc/<pid>` liveness check.
- `src/lib.rs` now declares `mod groups;`, appends the validator item before sorting the needs-you items with `needs::sort`, passes the running and landed lines to `text::inbox_text`, and reads `SystemTime::now()` once per `run` for `InboxFeature::new`; `InboxFeature::at(now_ms)` still uses its fixed time. `run`'s doc names the four new requirements.
- Copied `openspec/changes/244-rust-inbox-feature/fixture/golden/` to `crates/features/inbox/tests/golden/repo/` and `golden/inbox.txt` to `crates/features/inbox/tests/golden/inbox.txt` with `cp -R`/`cp`; `diff -r` and `cmp` confirm both are byte-for-byte copies.
- Added `tests/running.rs`, `tests/landed.rs`, `tests/validator.rs` and `tests/golden.rs`, each on `CARGO_TARGET_TMPDIR` scratch roots with any leftover folder removed first, plus the validator rows one test at a time and the golden parity check.
- Added extra tests, all inside the new files, for a pid of 0, the system clock driving `new`, each disclosure count and zero omission, landed id tie-breaking by leading number, an unreadable validator timestamp counting as 0, and validator id/title fallback.
- `cargo mutants -p osq-feature-inbox -f <file>` on every new or changed source file reported every mutant caught or unviable.

## Deviated

- Elapsed seconds round half up with integer arithmetic (`millis >= 500`) rather than `f64::round`, because the workspace has no casts and clippy would warn on the conversion. It agrees with `Math.round` on every non-negative value.
- Added the extra tests listed above so cargo-mutants can observe the pid-0, clock, disclosure, id tie-break and invalid-timestamp branches.
