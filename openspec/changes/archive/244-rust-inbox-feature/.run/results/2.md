## Changed

- Added `InboxFeature` in `src/lib.rs` with `new()`, `at(now_ms)`, the name `inbox`, its one `inbox` command, and `run`: it refuses another command with `FeatureError::unknown_command`, any argument with `FeatureError::usage`, reads through storage, prints the three groups and ends with one newline.
- Added private `src/read.rs`: `list_changes` plus `read_change` over every entry, in listing order, mapping a `StorageError` to `FeatureError::failed("inbox", ...)`.
- Added private `src/text.rs`: pure rendering of the three group line lists, with `Inbox empty.` and `  (none)`.
- Added private `src/needs/`: `mod.rs` (`Item { id, line }`, a stable id sort by leading number then bytes), `entry.rs` (planning, approval, change-regressed and task items), `placeholder.rs` (quoted-word split, `node -e`/`--eval`, `process.exit(0)` normalization), `steering.rs` (trigger rules, first-trigger selection, blocked needs with whitespace collapse) and `line.rs` (the requirement's item lines).
- Added `osq-kernel-storage.workspace = true` to `crates/features/inbox/Cargo.toml`; `Cargo.lock` only gained that dependency for `osq-feature-inbox`.
- Copied `openspec/changes/244-rust-inbox-feature/fixture/golden/` to `crates/features/inbox/tests/fixtures/needs-you/` with `cp -R`, removed only `openspec/changes/archive/`, and verified the result is byte-for-byte identical with `diff -r --exclude=archive`.
- Added `tests/inbox_command.rs` proving the seven named scenarios plus three extra tests for the id order and the trigger match arms the listed fixtures do not reach.

## Deviated

- The system-clock read is left to task 3. `new()` stores `None` and `at(now_ms)` stores the fixed time, ready for task 3's Running group, but nothing task 2 prints depends on the clock, so reading it now would add lines no test can distinguish and cargo-mutants would report them as misses.
- `sort` takes and returns `Vec<Item>` instead of mutating a slice. A no-op replacement then loses items and is caught, while task 3 can still push the validator item and call `needs::sort`.
- Added three tests beyond the task's scenario list (`needs_you_items_sort_by_number`, `steering_change_triggers`, `steering_task_triggers`) because the named fixtures do not exercise `2` before `10`, `sync_conflict`, `requirement_changed`, `verify_path_missing`, `sync_verify_red`, a passing non-scope regression, a trigger on a later task, or `entry_missing` with no entries. Each one names `Covers: rust-inbox/needs-you-of-the-active-fixture`.
- `InboxFeature` also derives `Default`; clippy's `new_without_default` is denied by the workspace rules, and `new()` stays `Self::default()` as core's `ChangeRecord::new` does.

## Missing context

- The task's details say to run `sh scripts/verify-rust.sh` with `OSQ_CHANGE`, but that script's mutation step reads `OSQ_DIFF`; I ran it with `OSQ_CHANGE` set and covered the mutation step by running `cargo mutants -p osq-feature-inbox` (all 93 mutants caught or unviable).
