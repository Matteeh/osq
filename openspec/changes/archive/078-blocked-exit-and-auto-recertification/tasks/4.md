## Acceptance

- [ ] New `src/core/lifecycle/recertify.ts` exports the done-marker refresh that `retrySpec` does after a passing recertification: `original_scope_hash` kept or set, `scope_hash`, `scope_files`, `scope_resolver`, `recertified_at`, and `recertification_count` plus one. `retrySpec` calls it instead of its own copy, and `osq retry` behaves exactly as before.
- [ ] `RecertificationEventData` in `src/harness/types.ts` gains optional `automatic?: true`.
- [ ] New `src/watcher/auto-recertify.ts` decides whether a stale task qualifies, as the watcher-and-harness delta's "Automatic scope recertification" says. It reads the later tasks' `scope` with `parseTaskMd`, matches it with `scopeCoversPath`, and reads their `measures` end events' `scopeHashes`. When the task qualifies, it refreshes the done marker through `recertify.ts` and appends the `recertification` event with `automatic: true` to the task's stream.
- [ ] `auditScopeRegressions` asks `auto-recertify.ts` after a passing detection verify and before writing any marker. A task it recertifies writes no marker or `regressed` event and isn't in `stale`. The audit result gains `recertified`, the recertified task numbers.
- [ ] `runWatcherCycle` logs one line per recertified task, naming the task and its differing paths, and the change keeps running.
- [ ] New `tests/auto-recertify.test.ts` covers every scenario of "Automatic scope recertification" and "Automatic recertification event", plus a passing `osq retry` still writing no `automatic` key.

## Details

`regression.ts` is 246 lines and must stay within 250. Move `buildDoneMetadata`
into new `src/watcher/done-metadata.ts` and re-export it from `regression.ts`
with `export { buildDoneMetadata } from './done-metadata.js';`, because
`runner.ts` and `tests/scope-recertification.test.ts` import it from there.
`auditScopeRegressions` and `retrySpec` are on the function-budget grandfather
list and must stay over 80 lines; they will, since each loses or gains only a
few lines.

Build the event from the same fields the audit already holds: `differingPaths`,
`attribution`, the verify command, exit code, output, timeout state,
`recordedHash`, and `currentHash`. Condition 2 compares per-file hashes: the
done marker's `scope_files` entry, each end event's `scopeHashes[path].before`
and `.after`, and `computeTaskScopeHash`'s `fileHashes` for the current tree.

For the tests, a small adapter that extends `MockAdapter` and writes the scoped
file in `spawn` lets real runs record real `measures` events, so task 1 and
task 2 run through `runWatcherCycle`. A hand edit before task 2 starts is caught
by the audit before task 2 even runs, so for the broken-chain case write task
2's done marker and `measures` end event directly, with a `before` that differs
from task 1's recorded hash, and call `auditScopeRegressions`.
`tests/scope-recertification.test.ts` shows how to build done markers with
`buildDoneMetadata`.
