## Changed

- `src/core/report/result-sections.ts`: added `blocked: string | null` to
  `ResultSections`, mapped `blocked` in `HEADING_KEYS`, and filled it in
  `parseResultSections` under the existing matching and `None` rules.
  Disclosure reading and counting were left untouched, so `## Blocked` is not a
  disclosure.
- `src/watcher/failure-reason.ts`: added `'blocked'` to `RunTaskFailureReason`.
- New `src/watcher/blocked.ts`: `checkBlocked` reads
  `.run/results/<n>.md` through `parseResultSections` and, when `blocked` is
  present, calls `fail('blocked', ...)` with a marker of `reason: blocked`
  frontmatter followed by the stated need. Also exports
  `formatBlockedDeadMarker`.
- `src/watcher/task-verify.ts`: added `checkBlockedFirst(projectRoot,
  specFolderPath, taskNumber, taskData, fail)`, which runs the blocked check
  then `checkMissingVerifyPaths`. `checkMissingVerifyPaths` stays exported.
- `src/watcher/runner.ts`: imports and calls `checkBlockedFirst` in place of
  `checkMissingVerifyPaths` after `ensureTaskResult`, so the blocked check runs
  before the missing-path check and neither verify runs for a blocked task. The
  file stays at 199 lines.
- `tests/result-sections.test.ts`: the `parseResultSections('')` expected object
  gained `blocked: null`; nothing else changed.
- New `tests/blocked-exit.test.ts`: covers the three "Blocked exit" scenarios
  through `runWatcherCycle`/`runWatcherOnce` with a `MockAdapter` whose
  `resultContent` holds `## Blocked` (death, marker body, no `verify_ran`; no
  `retry` in a cycle with `gates.autoRetries: 1`; `None` falls through to a
  passing verify and archive), plus a `## blocked:` parse.

## Deviated

- The combined check is named `checkBlockedFirst`. A more descriptive name such
  as `checkBlockedOrMissingPaths` would push the runner's single-line call past
  biome's 100-column width, forcing a multi-line call that would grow
  `runner.ts` past its 200-line budget. The task named no function, and the
  doc comment states the order.
