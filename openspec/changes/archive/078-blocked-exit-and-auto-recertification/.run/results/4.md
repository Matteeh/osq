## Changed

- New `src/core/lifecycle/recertify.ts`: `refreshRecertifiedDoneMarker(runDir,
  taskNumber, recordedHash, current)` keeps every existing done-marker field,
  retains/sets `original_scope_hash`, refreshes `scope_hash`, `scope_files`,
  `scope_resolver: 2`, `recertified_at`, and increments
  `recertification_count`. `retrySpec` now calls it instead of its inline copy,
  so `osq retry` behavior is unchanged (existing retry/recertification suites
  still pass).
- `src/harness/types.ts`: `RecertificationEventData` gained optional
  `automatic?: true`.
- New `src/watcher/done-metadata.ts`: `buildDoneMetadata` moved out of
  `regression.ts`; `regression.ts` re-exports it with
  `export { buildDoneMetadata } from './done-metadata.js';`, so `runner.ts` and
  `tests/scope-recertification.test.ts` keep their imports.
- New `src/watcher/auto-recertify.ts`: `autoRecertify` reads later-numbered task
  files with `parseTaskMd`, checks `scopeCoversPath` for each raw differing
  path, then walks the later in-scope tasks' `measures` end `scopeHashes` for
  the path. It requires the first `before` to equal the done marker's recorded
  `scope_files` hash, every later `before` to equal the previous `after`, the
  last `after` to equal `computeTaskScopeHash`'s current per-file hash, and at
  least one differing path. On qualification it refreshes the done marker
  through `recertify.ts` and appends one `recertification` event with
  `outcome: passed` and `automatic: true`, using the audit's differing paths,
  attribution, command, exit code, output, timeout state, recorded hash, and
  current hash. It returns false without writing on any gap.
- `src/watcher/regression.ts`: `auditScopeRegressions` asks `autoRecertify`
  after a passing detection verify and before writing any marker. A recertified
  task gets no marker, no `regressed` event, and is skipped from `stale`.
  `ScopeAuditResult` gained `recertified` (task numbers) and `recertifiedPaths`
  (per-task display paths for logging). `regression.ts` is 248 lines.
- `src/watcher/loop.ts`: `runWatcherCycle` logs one
  `[recertified] task <n> recertified automatically (<paths>)` info line per
  recertified task before the stale/halt check, so the change keeps running.
- New `tests/auto-recertify.test.ts`: a `WritingAdapter` extends `MockAdapter`
  and writes the scoped file during `spawn`, so tasks 1 and 2 run through
  `runWatcherCycle` and record real `measures` events. Covers the later-task
  extension (recertification, marker refresh, event shape, no retry/attempt,
  task 3 runs, one log line), the audit result (`stale: []`, `recertified:
  ['1']`), verify-fails-at-detection, human-edit gap, file outside every later
  scope, resolver-upgrade-only regression, and a passing human `osq retry`
  writing no `automatic` key.

## Deviated

- `ScopeAuditResult.recertified` is the specified `string[]` of task numbers.
  Acceptance also requires `runWatcherCycle` to log each recertified task's
  **differing paths**, which task numbers alone cannot carry, so the audit result
  additionally has `recertifiedPaths: Record<string, string[]>`. No other field
  or the `stale` contract changed.
- The shared done-marker refresh is named `refreshRecertifiedDoneMarker` (the
  task named no symbol) and takes the recorded hash plus a `ScopeHashResult`.

## Missing context

- The task says the automatic event should carry the audit's fields, but the
  audit's `StaleTaskAudit` does not expose the raw `DifferingPath[]` (only the
  display strings) and `DifferingPath` is not exported from `scope-hash.ts`.
  `auto-recertify.ts` therefore receives the raw `differing` array structurally
  via its own `DifferingScopePath` shape rather than importing that type.
