- [ ] `lintChangeFolder` rejects a `proposal.md` whose `## Surface` section is missing, or empty once HTML comments and whitespace are removed. It pushes exactly the error below. A legacy `spec.md` change document is exempt, as it is for the `verify` check.
- [ ] Any other section text passes, including `None`, a list, or the seeded comment followed by `None`. Lint does not parse or judge the text.
- [ ] New `tests/proposal-surface-lint.test.ts` covers a missing section, an empty section, a comment-only section, `None`, a list, and a fresh `createNewSpec` proposal, through both `lintChangeFolder` and `approveSpec`.
- [ ] Every `proposal.md` written inline by the five preexisting tests in scope gains `## Surface` holding `None`, placed as in task 2. Nothing else in those files changes.
- [ ] `README.md` adds `## Surface` between `## Non-goals` and `## Contract` in the proposal example under `## Change folder`. It also adds one sentence after that example saying what the section lists and that `None` is valid.
- [ ] The task's verify command passes.

## Details

This task's `scope` is authoritative over any injected code-ownership rules.

Put the check next to the existing `proposal.md must declare a verify command in
frontmatter` check, and read the section from the proposal body. `parser.ts` is
not in scope, so match the heading `## Surface` on its own line in
`linter.ts`. `lintChangeFolder` is on the function-budget grandfather list; add
the check as a small helper function in `linter.ts` rather than inline logic.

The error text, exactly:

`proposal.md needs a ## Surface section: list the commands, flags, config keys, frontmatter fields, document sections, dead reasons, and event types this change adds, changes, or removes, or write None`

A trial run of this rule also failed tests in the five preexisting files in
scope, plus the thirteen other files that task 2 already fixed. Every other test
that approves a proposal builds it with `createNewSpec`. Task 1's seeded
`None` keeps those tests green, so don't change them.
