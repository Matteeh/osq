## Acceptance

- [ ] `pi_line_events` gives one `UsageLimit` event after a `message_end` line's `Text` and `Tokens` events exactly when rust-harnesses "Pi usage limit" says, with `error` set to `errorMessage` and no `resets_at`.
- [ ] New `crates/kernel/harnesses/tests/pi_usage_limit.rs` proves "Pi usage limits", every table row checked, its test's doc naming `Covers: rust-harnesses/pi-usage-limits`.
- [ ] Every existing harnesses test, the TypeScript goldens of "Captured pi run matches TypeScript" and "Edge lines match TypeScript" included, still passes unchanged.

## Details

Put the account-limit texts and the pure check, which lowercases both
sides with ASCII rules before the substring test, in a new private
module `src/pi/limit.rs`, declared in `src/pi.rs`. Call it from
`message_end` in `stream.rs` after the text and tokens are pushed, and
read `stopReason` and `errorMessage` with the existing `text_field`, so
an empty or non-string `errorMessage` counts as absent. The list is pi
0.87.0's `NON_RETRYABLE_PROVIDER_LIMIT_ERROR_PATTERN` plus DeepSeek's
`insufficient balance`; write each text as the delta lists it, and add no
general `usage limit` text. The `402 Insufficient Balance` row is
DeepSeek's real error and must give a `UsageLimit`.

Build each row's expected events with core's `Event::UsageLimit`,
`Event::Text` and `Event::Tokens` values and compare whole vectors, as
`pi_stream_edges.rs` does. Run the proposal's verify with
`OSQ_CHANGE=openspec/changes/293-rust-run-usage-pause`, as the watcher
does, so the link gates see this change's new requirement.
