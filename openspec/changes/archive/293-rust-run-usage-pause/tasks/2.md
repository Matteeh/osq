## Acceptance

- [ ] The run's runner settings carry a `usage_limit_wait` of 1800 seconds from a named constant, and a `Paused` outcome writes `.run/paused.md` as rust-run "Run usage pause" says before the run fails with the existing `text::usage_limit` text.
- [ ] A paused run writes no `exited` event, no dead or done marker, and releases its lock.
- [ ] New `crates/features/run/tests/run_usage_pause.rs` proves "Paused on a usage limit", its test's doc naming `Covers: rust-run/paused-on-a-usage-limit`.
- [ ] Every existing run test, `usage_limit_text`, "Executor exits" and "Prior context handed to pi" included, still passes unchanged.

## Details

Put the pause file's text in a pure function and its write in a new
`src/feature/pause.rs`, and call it from the `RunOutcome::Paused` arm of
`start::run`, which already appends the runner's `paused` event among the
gathered events. Create `.run/` when it is missing. Never read anything
under `src/` from Rust; the TypeScript files are in `entry` only so you
can port them.

Commit a new executable fake pi at `tests/fixtures/limit-pi/run.sh`
(`chmod +x`), modelled on `record-pi/run.sh`: it prints the scenario's
`message_end` line on stdout with a newline and exits 1, and writes no
file. Build the root with `support::repo`, point `pi.bin` at the fake as
`run_outcomes.rs` does, and run twice. Bound the `until` with
`osq_kernel_runners::pause_until` of a `UsageLimitData` with neither
field, the epoch milliseconds read just before and just after each run,
and `Duration::from_secs(1800)`; the fixed-form times compare as
strings. Read the file back with `osq_kernel_storage::read_usage_pause`.
Leave `fake-pi/run.sh`, `record-pi/run.sh` and `tests/support/mod.rs` as
they are.

Run the proposal's verify with
`OSQ_CHANGE=openspec/changes/293-rust-run-usage-pause`, as the watcher
does, so the link gates see this change's new requirement.
