## Ports

```ts
// src/watcher/commit-catch-up.ts
/**
 * Commit a worktree change's pending dead records and clear a `commit_failed`
 * halt when they commit, within `gates.commitRetries`. Returns false when the
 * change stays halted this cycle and the caller skips it.
 */
export async function catchUpWorktreeCommits(
  change: LocatedChange,
  specId: string,
  config: OsqConfig,
  logger?: Logger,
): Promise<boolean>;
```

## Details

It returns true without doing anything for a change outside git
(`selectVcs` kind not `git`), and when `.run/regressed/change.md` holds any
reason other than `commit_failed`, so the existing regressed path in
`runWatcherCycle` handles those as before. Read the marker's reason with
`parseFrontmatter`. Count events by parsing `.run/events/change.jsonl` line by
line; a `retry` event's data holds `target` and, for an automatic one,
`automatic: true`.

The log line uses `resolveSymbol('↻', '[retry]', logger?.symbols === true)`,
as `src/watcher/auto-retry.ts` does.
