## Changed

- `src/core/vcs/sync-verify.ts`: `syncVerifyTasks` now hashes each done task's scope with `computeTaskScopeHash` before the merge; when the hash equals the done marker's `scope_hash` it records the scope and marker on the `SyncVerifyTask` (step 1). `runSyncVerify` calls the new recertification after every step-5 verify pass and before the `synced` event, and `SyncVerifyOptions` carries the `Vcs` and the recertification backup state.
- `src/core/vcs/sync-recertify.ts` (new): `recertifySyncTasks` does steps 2 and 3 — for each kept task whose merged-tree hash differs it refreshes the done marker with `refreshRecertifiedDoneMarker`, appends the automatic `recertification` event (attribution `sync` per differing display path, `exitCode` 0, `timedOut` false, no `output`) to `.run/events/<n>.jsonl`, and stages the marker and stream. `createSyncRecertifyState`/`restoreSyncRecertified` keep each file's contents before its first write so `sync-main.ts` can write them back.
- `src/core/vcs/sync-main.ts`: `SyncContext` carries the recertification state; `prepareSync` creates it; `stopAfter` restores it beside `restoreEvents`; `finishSync` passes the `Vcs` and state to `runSyncVerify`. File stays at 243 lines.
- `tests/vcs-sync-recertify.test.ts` (new): covers every "Sync recertifies done tasks" scenario — merge-only change, task changed before the merge, merge leaves the task alone, commit failure restores both files, and the archive path through `runWatcherCycle`.

## Deviated

- In the archive scenario the task stream ends with the archiver's own `verify_ran`, not the `recertification` event, so the test asserts a `recertification` event is present rather than that it is last.
- `SyncVerifyTask` gained two optional fields instead of a separate candidate list, so the existing verify step and the recertification share one traversal.
