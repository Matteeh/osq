## Changed

- `src/core/foundation/config-gates.ts`: added the optional `commitRetries` gate,
  defaulting to 2 in `DEFAULT_GATES_CONFIG`, validated through the existing
  `nonNegativeInteger` helper so a negative, fractional, or non-numeric value
  fails with `gates.commitRetries must be a non-negative integer`.
- `src/core/run/dead-commit.ts`: `commitDeadTask` now removes an existing
  `.run/dead/<n>.patch` before it calls `patch()`, so a stale patch from an
  earlier try never grows into the new one.
- `src/watcher/commit-catch-up.ts` (new): `catchUpWorktreeCommits` returns true
  for a change outside git; leaves any non-`commit_failed` halt alone; counts
  `commit_failed` regressed events in `.run/events/change.jsonl` since the last
  human `retry` for target `change` and leaves the change halted when that
  exceeds `gates.commitRetries` (a gates object without the key counts as 2);
  commits pending untracked/added `.run/dead/<n>.md` records in task order
  through `commitWorktreeDeadTask`, halting again on a failed commit; and after
  a `commit_failed` halt clears it through `retrySpec(..., { automatic: true })`
  and logs `↻ change of <id> caught up after commit_failed`.
- `src/watcher/loop.ts`: `runWatcherCycle` calls `catchUpWorktreeCommits` for a
  worktree change right after the reaper and before `runAutomaticRetries`, and
  skips the change for the cycle when it returns false.
- `tests/commit-catch-up.test.ts` (new): drives `runWatcherCycle` with a real
  worktree and a rejecting `pre-commit` hook to cover dead and verified
  catch-up, a record left undone, budget spend, retry after a human retry, and
  other halts; covers "Patch from an earlier try" through `commitDeadTask`; and
  covers the gate key's default and invalid value through `loadConfig` and
  `defineConfig`.

`pnpm verify` passes: 3341 CLI tests, 114 UI tests, both typechecks, build, and
lint.

## Deviated

- `commit-catch-up.ts` keeps a local `DEFAULT_COMMIT_RETRIES = 2` for the
  `config.gates?.commitRetries ?? 2` fallback, rather than importing the value
  from `config-gates.ts`. A `GatesConfig` built by hand can lack the key, and
  the task fixes that fallback at 2; `DEFAULT_GATES_CONFIG.commitRetries` is
  itself optional, so it cannot replace the fallback without the same literal.
- Added one extra gate-key test beyond the two named scenarios: a `gates` object
  built in a test without `commitRetries` runs with the two-catch-up budget.
