## Changed

- `src/core/vcs/checkout-root.ts` (new): `resolveCheckoutRoot(cwd, config)`
  returns `cwd` unchanged unless `vcs.enabled` is on, `selectVcs` picks git,
  `root()` is a linked worktree whose `head().branch` starts with `osq/`, and
  the first `worktreeList()` entry is another path after `fs.realpath`. It
  falls back to `cwd` on any git error and never throws.
- `src/cli/approve.ts`: `approveCommand` now resolves the checkout before the
  spec-ID check, reloads the checkout's config with `loadConfig` when it moved
  and `options.config` was not passed, prints `Approving from the checkout
  <path>` to `inputs.stderr` when it moved, and passes the resolved path to
  `approveSpec`, `findChange`, and `readNextStep` in place of `inputs.cwd`.
- `tests/approve-from-worktree.test.ts` (new): covers approving another
  checkout change from inside `001`'s worktree (stderr names the checkout and
  `001`'s worktree is untouched), approving in place from the checkout with no
  stderr, approving a steered change from its own worktree with a test file
  that exists only in that worktree, `resolveCheckoutRoot` returning `cwd` for
  the checkout and a non-`osq/` worktree with no stderr, a symlinked worktree
  path, and the vcs-off / not-a-repository fallbacks.

`pnpm verify` passes: CLI typecheck, UI typecheck, build, every test, and lint.
The task's own verify command passes with 21 tests.

## Deviated

- "Checkout or other worktree" is covered through `approveCommand` for the
  checkout and through a direct `resolveCheckoutRoot` assertion for the
  non-`osq/` worktree; the same test also runs `approveCommand` from that
  worktree and checks stderr is empty. Approving a change there would have
  needed a full in-worktree draft, which adds no coverage of the branch check.
