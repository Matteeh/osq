## Details

Port `createSchemaDatabase`, `denialCause`, `allowlistAuthorizer`,
`withoutTrailingSemicolon` and `authorizeAndPrepare` from
`src/core/report/query-run.ts`. Set the authorizer with
`Connection::authorizer`, which rusqlite's `hooks` feature from task 1
enables, and match `rusqlite::hooks::AuthAction`: `Select`, `Function` and
`Recursive` are allowed, and so is `Read` when its `table_name` is one of the
sixteen tables. The closure must be `Send` and `'static`, so keep the first
denial in an `Arc<Mutex<Option<...>>>` it shares with the caller, holding the
action's kind and its table name as owned text. The prepared statement's SQL
text is `Statement::expanded_sql()`, which is the statement's own text since
`query` binds no parameters.

A prepare that fails with no denial, and a select with no statement, keep
task 1's messages, so the `sqlite-error-*` cases of `tests/query_run.rs`
still pass. The planner
checked with rusqlite 0.40.2 that `CREATE TABLE` is first denied as an insert
and `DROP TABLE` as a delete, both on `sqlite_master`.

cargo-mutants runs on every line this task adds, so each branch must change
a value a case checks: each allowed action, the table-name test, each cause,
keeping the first denial rather than the last, the trailing-whitespace and
single-semicolon trim, and the length comparison. Before exiting, run
`cargo fmt --all`, then `cargo mutants -p osq-feature-report -f <file> -o "$(mktemp -d)"`
on `src/query/authorize.rs` and `src/query.rs`, then `sh scripts/verify-rust.sh`
with `OSQ_CHANGE` set to `openspec/changes/243-rust-query-feature`.
