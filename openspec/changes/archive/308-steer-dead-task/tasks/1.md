## Details

`humanSteering` takes the derived `SpecState` and reads each dead task's
`deadReason`; it reads no file. Only a change whose `tree.worktreeFolder` is
set uses it in `readSteeringPlan`; a checkout or stacked change keeps
`state.steering`. Pass the chosen triggers into `buildSteeringSection`
instead of reading `state.steering` there.

Build the worktree test repositories as `setupWorktree` in
`tests/steering-plan.test.ts` does, copying the helpers you need into the
new file. Write the dead marker as `---\nreason: timeout\n---\nAgent timed out\n`
with no `stuck` key. Call `humanSteering` on `deriveSpecState` of a
`readChangeFolder` snapshot for the three status-inspection scenarios.

## Scenarios

- status-inspection: Dead task without a trigger
- status-inspection: Run triggers win
- status-inspection: Nothing died
- cli-foundation: Plan a dead task in its worktree
- cli-foundation: Approved change needs no steering
