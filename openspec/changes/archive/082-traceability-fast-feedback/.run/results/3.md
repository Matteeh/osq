## Changed

- `src/harness/types.ts`: `HarnessEventType` gains `focused_ran`; added
  `FocusedRanOutcome` and `FocusedRanEventData` (`command`, `files`,
  `scenarios`, `outcome`, `exitCode`, `duration`, `timedOut`, `output`) and wired
  the payload into `OsqEventData`.
- `src/watcher/focused-verify.ts` (new): `checkFocusedTests` collects through
  `collectFocusedTests`, runs through `runFocusedTests`, appends one
  `focused_ran` event with `appendHarnessEvent`, and on `failed` returns the
  `verify_red` death through the injected `fail`. The dead marker carries
  `reason: verify_red`, `focused: true`, and the quoted command, with body
  `Watcher focused scenario tests failed:` followed by the output. `problem`
  and `passed` return null.
- `src/watcher/task-verify.ts`: `checkBlockedFirst` now runs
  `checkMissingVerifyPaths`, returns if it stops, and otherwise calls
  `checkFocusedTests` last. `runner.ts` is unchanged.
- `tests/focused-verify.test.ts` (new): covers the requirement's scenarios and
  the proposal's "Boundary broken" through `runTask` with a fake adapter: pass
  then verify with event order, `failed` ending the attempt with the marker
  frontmatter and no following `verify_ran`, a broken command recorded as
  `problem` with the verify still deciding, an unset command appending no event,
  and the automatic retry carrying the focused output. Two real
  `node --import <tsx> --test --test-reporter=tap` runs of the copied pricing
  fixture, with tsx from `import.meta.resolve('tsx')`, show the intact copy
  passing and the `>= 100` -> `> 100` copy ending on its focused run.

Task verify (`node --import tsx --test tests/focused-verify.test.ts`, 7/7) and
the proposal verify (`pnpm verify`, exit 0: 2071 CLI tests, 88 UI tests, lint)
both pass.

## Deviated

- The copied pricing fixture rewrites the helper import to the absolute URL of
  `src/testing/index.ts` as the task says, but it keeps a comment line holding
  the literal `from '@matteeh/osq/testing'`. The scenario index scanner keys on
  that literal import specifier in `src/core/trace/tag-scan.ts`, so a file whose
  import is only the URL is not a scenario test file and collection would be
  empty, producing no focused run. The comment keeps the rewrite and lets the
  index see the file. Runtime ignores the comment.
- The "Broken focused command" scenario uses the spec's own example
  `node missing-runner.js {files}` rather than inventing another command.
