It never scans test files itself.

## Details

The focused command in these tests can be a small `node` script in the
temporary project that prints the TAP lines each case needs, so no test
depends on a real test runner. A file counts as a scenario test file when it
imports `@matteeh/osq/testing`, and the index needs only the file text, so the
fixtures never have to run. `tests/trace-scan.test.ts` shows how to build the
index. With `traceability.capabilities` set to `'all'`, every scenario counts
as opted in, so nothing needs to list the living specs. The watcher sets `OSQ_CHANGE` for osq's own verify runs, so pass the
change folder explicitly and assert on the value you passed. New functions stay
within 80 lines and new files within 250.
