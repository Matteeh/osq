## Details

`checkDependencies` in `src/watcher/dependencies.ts` is the model for a
post-exit check that appends an event and kills through `fail`.
`tests/denied-dependency.test.ts` and `tests/verify-path-missing.test.ts` show a
fake adapter, a run through the watcher cycle, and an automatic retry. The dead
marker body is what the retry's prompt carries. The runner is 199 lines and
must stay under 200, which is why the call goes in `checkBlockedFirst`.
`task-verify.ts` is 184 lines. The golden event scenario sets no
`focusedTests`, so its fixtures don't change. Every child process that runs
the helper must delete or set `OSQ_CHANGE` explicitly. The real TAP run also
needs `NODE_TEST_CONTEXT` removed. The focused command inherits the test
process's environment through `runVerificationCommand`, and a child
`node --test` that inherits it runs no file and exits 0. Change 081's
`tests/trace-pricing.test.ts` hit this. Remove it from `process.env` for that
case and restore it afterwards, and assert that the broken copy's output holds
`not ok`, so a silent pass can't hide the problem. New functions stay
within 80 lines and new files within 250.
