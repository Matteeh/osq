## Changed

- `src/watcher/dependencies.ts`
  - Added a private `manifestReader(fileName)` that returns osq's own
    `package.json` reader for `package.json`, and for any other file name a
    reader that delegates to the language adapter's `manifestDependencies`,
    found through `LANGUAGE_PRESETS` (no manifest name is hard-coded but
    `package.json`).
  - `readScopedDependencies` now maps every scoped manifest that has a reader
    to its names, mapping a missing or unreadable file to an empty list.
  - `checkDependencies` now reads each baseline file through the same reader,
    collects manifests the adapter cannot read, appends the
    `dependencies_added` event, fails on denied added names first, and only
    then, while some accepted ADR denies at least one name, fails the task with
    the unreadable manifests and error
    `Cannot read dependency tables: <file>, <file>`.
  - Added `formatUnreadableDependencyMarker` beside
    `formatDeniedDependencyMarker`; both now share a private
    `dependencyMarker(heading, lines)`.
  - Added `@scenario watcher-and-harness: ...` and `@adr 017` doc tags to the
    changed/added exported functions.
- New `tests/denied-dependency-cargo.test.ts` proves the six scenarios through
  `runTask`, copying the project-building helpers from
  `tests/denied-dependency.test.ts` (not importing from or changing it), with a
  scoped `crates/core/Cargo.toml` (serde + insta) and an accepted ADR 007 that
  denies `openssl`.

## Deviated

- A baseline manifest that is **missing** at comparison time maps to no names
  and no unreadable failure; only an existing file whose adapter returns
  `{ ok: false }` counts as "cannot be read". The spec's "missing or unreadable
  file SHALL map to an empty list" plus the requirement's "some current
  manifest ... cannot be read by its language adapter" are ambiguous for a
  deleted file, and the scenarios only cover an existing unreadable file, so I
  did not invent an error string for a missing one.
- To stay inside the 250-line source budget after the added reader and marker,
  the two dead-marker formatters now share a private `dependencyMarker` helper.
  The rendered bytes of `formatDeniedDependencyMarker` are unchanged.

## Missing context

- The spec does not say what error text an unreadable *missing* baseline
  manifest should report (see `## Deviated`). If a deleted scoped `Cargo.toml`
  must also fail the task while some accepted ADR denies a name, the planner
  should state the per-file error string.
