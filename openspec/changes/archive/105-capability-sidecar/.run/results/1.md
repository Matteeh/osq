## Changed

- Added `src/core/foundation/config-capability-groups.ts` exporting
  `CapabilitiesConfig`, `DEFAULT_CAPABILITIES_CONFIG` (`{ requireGroups: false }`),
  and `validateCapabilitiesConfig`, which returns the default for an absent
  block and throws `capabilities.requireGroups must be a boolean` otherwise,
  modelled on `config-traceability.ts`.
- `src/core/foundation/config.ts` gains `capabilities?: CapabilitiesConfig` on
  `OsqConfig`, the default in `DEFAULT_CONFIG`, the validated value in
  `defineConfig`, and re-exports the `CapabilitiesConfig` type. File is 245
  lines, under the 250-line budget.
- `src/core/foundation/config-user.ts` accepts a partial `capabilities` block.
- Added `tests/config-capability-groups.test.ts` covering the default (module,
  `DEFAULT_CONFIG`, `defineConfig`, `validateCapabilitiesConfig`), the opt-in
  scenario through `loadConfig` on a temporary project, a non-object block, and
  the invalid non-boolean value.

`node --import tsx --test tests/config-capability-groups.test.ts` passes (4/4),
and the proposal's `pnpm verify` passes end to end.
