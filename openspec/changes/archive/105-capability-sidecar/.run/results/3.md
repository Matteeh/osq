## Changed

- Added `src/watcher/archive-sidecars.ts` exporting `applyArchiveSidecars`.
  It reads `creates` via `readCreates` from the proposal frontmatter and, for
  each entry with a group whose capability now has a living `spec.md` and no
  sidecar, writes `formatSidecar({ group })`; it then copies every
  `specs/<capability>/osq.yml` the change carries over the living sidecar as
  raw bytes, so a replacement always wins. It is the sole sidecar writer
  besides `osq migrate sidecars`.
- `src/watcher/archiver.ts`: `archiveSpecFolder` calls `applyArchiveSidecars`
  immediately after `applyOpenSpecDeltas`.
- `src/core/run/manifest.ts`: `buildManifest` now records
  `hashes["<capability>/osq.yml"]` with `hashFileContent` for every capability
  it records a spec hash for (null when the sidecar is absent), matching the
  existing spec-hash key.
- Added `tests/archive-sidecars.test.ts` covering all four scenarios of
  "Sidecars at archive": created with a group, bare creation, byte-for-byte
  replacement, and manifest hashes (present hash and null), through
  `archiveSpecFolder` and `buildManifest` on temporary projects.

`node --import tsx --test tests/archive-sidecars.test.ts` passes (5/5), the
existing archive and manifest suites pass unchanged, and the proposal's
`pnpm verify` exits 0.
