## Changed

- `WebCapabilityNode` now carries `group?: string | null`; the graph builder
  fills it from `readLivingSidecar(projectRoot, config.paths.openspecRoot, id)`,
  so a missing or malformed sidecar yields `null`.
- `graphLayout` groups lanes when at least one capability has a group: real
  groups sorted by name, capabilities without a group last under `ungrouped`,
  original capability order kept within a group. It adds the vertical room of a
  `GRAPH_GEOMETRY.groupHeaderHeight` header row above each group's lanes and
  returns `groups: GraphGroupHeader[]` with each header's y and lane ids. With
  no group, lanes and geometry are the previous formula and `groups` is empty.
- `GraphCanvas` draws one `graph-group-header` row per group, labelled with the
  group name, and draws none when `layout.groups` is empty.
- New `tests/ui-graph-groups.test.tsx` covers grouped lane order and headers,
  order within a group, the unchanged ungrouped layout, one canvas render with
  headers (and one without), and the web data group/null/`broken`-sidecar cases
  on a temporary project.

## Deviated

- The acceptance line says `group: string | null`, but I declared it optional
  (`group?: string | null`). A required field makes the existing capability
  literals in `tests/ui-graph.test.tsx` and `tests/ui-report.test.tsx` fail the
  UI typecheck, and those files are outside this task's scope and must pass
  unchanged. Every derived `WebCapabilityNode` still always sets `group`, and
  the layout treats `undefined` as no group, matching the existing `doneCount?`
  pattern.
