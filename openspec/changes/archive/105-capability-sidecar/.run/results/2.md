## Changed

- Added `src/core/spec/capability-sidecar.ts`: `UNGROUPED`, the
  `CapabilitySidecar` and `SidecarParseResult` types, `livingSidecarPath`,
  `parseSidecar` (problems `not a YAML mapping`, `group must be a non-empty
  string`, `tags must be a list of non-empty strings`, `unknown key <key>`),
  `formatSidecar`, and `readLivingSidecar` (null for missing or broken).
- `src/core/spec/capability-relations.ts`: `readCreates` now accepts bare
  names and `{ name, group }` mappings, adds `entries` (`{ name, group }`,
  `group` null for a bare name), marks a mapping missing a string `name` or
  `group` malformed, and keeps `names`/`malformed` exactly as before.
- Added `src/core/spec/sidecar-lint.ts`: `collectSidecarFindings` reads the
  change's replacement sidecars (`specs/<capability>/osq.yml`, including dirs
  with no `spec.md`), the living sidecars, and `creates`/written capabilities.
  Replacement problems and replacements for no known capability are change
  findings; broken living sidecars are repository findings; with
  `requireGroups` a bare/`ungrouped` `creates` entry or a written living
  capability with no real group is a change finding.
- `src/core/spec/linter.ts`: `lintChangeFolder` runs the sidecar lint for a
  `proposal.md` change and adds its own findings and repository findings.
- Added `tests/capability-sidecar.test.ts` covering every scenario of
  "Capability sidecar", "Grouped creation", and "Grouped entry" through
  `parseSidecar`, `formatSidecar`, `readLivingSidecar`, `readCreates`, and
  `lintChangeFolder` on temporary projects.

`node --import tsx --test tests/capability-sidecar.test.ts` passes (24/24)
and the proposal's `pnpm verify` passes end to end.

## Deviated

- `CreatesDeclaration.entries` is a non-enumerable own property. The task
  requires both adding `entries` and leaving `tests/capability-relations.test.ts`
  unchanged, and that file asserts `readCreates(...)` with
  `assert.deepEqual` against `{ names, malformed }`. A non-enumerable property
  is readable as `creates.entries` while `deepEqual` ignores it, satisfying
  both. No preexisting test was touched.
- The "Capability sidecar" repository finding is produced for every living
  sidecar with a problem, not only capabilities the change touches. The
  requirement says a broken living sidecar is a repository finding generally;
  the "Broken living sidecar" scenario's reading change still sees it.
