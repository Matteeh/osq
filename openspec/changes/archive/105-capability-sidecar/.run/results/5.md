## Changed

- `src/core/report/report.ts`: added `CapabilityCoverage` and an optional
  `CoverageMetrics.capabilities`. New `collectCapabilityCoverage` lists living
  capabilities via `readLivingCapabilityNames` and splits them by whether
  `livingSidecarPath` exists, each in the name order the reader already
  returns. `getMetricsReport` calls it and spreads
  `{ capabilities }` into `coverage` only when at least one living spec
  exists, so a project with none keeps the old shape.
- `src/cli/report.ts`: `toStableMetrics` copies `coverage.capabilities`
  (`withSidecar` / `withoutSidecar`, arrays cloned) only when present.
- `tests/report-sidecars.test.ts`: new test with a small temporary-project
  helper. Both scenarios run through `reportCommand({ cwd, config, json: true })`:
  living `orders` and `pricing` with only `pricing` sidecarred yields
  `withSidecar: ["pricing"]` / `withoutSidecar: ["orders"]`, and a project
  with no living spec omits the key from `coverage` and from the raw JSON.
