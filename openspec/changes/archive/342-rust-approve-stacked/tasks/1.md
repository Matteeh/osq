## Details

The refusal's code in `stack.rs` and `stack/` already lists the changes,
resolves `depends_on`, reads delta capabilities and reads each folder's
state. Extend it rather than starting over:

- `stack/state.rs`'s `read` must also give the hash.
- One reader gives the awaited entries of any change folder path. Use it for
  the checkout's folder and for each step of a closure.
- `stack/text.rs`'s refusal goes.

`refuse::check` today runs the stacking refusal before the rejected branch
claim, and `worktree::approve` does the rename. Rename the kept branch once,
before either the stacked approval or the worktree approval writes. Write
`.run/approver` with the same code `worktree/markers.rs` uses, but write no
`.run/base`. Remove folders with `worktree/copy.rs`'s `remove`.

`approve_stacked.rs` builds each repository with `worktree_support`'s
`build_with` and runs `approve` once per step. It renders the last run as the
golden script does: keep only the approval lines it keeps, list every file
under the stacked folder, sorted, with `manifest.json` and `plan.jsonl` left
out, and write a `.run/` file that ends without a newline as its text
followed by a line `(no newline)`. Then put `<root>` back. Port the helpers
you need into the new file; `worktree_support` is outside scope.

Never read anything under `src/` from Rust; it is in `entry` only so you
can port it. When the mutation check reports a missed mutant, add a test
case for that line. Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/342-rust-approve-stacked`, so the link gates
see this change's requirements.
