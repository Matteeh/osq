# Task 4 result — transient plan-prompt in lint, hashing, and archival

Status: complete. Task verify and `pnpm verify` both pass.

## Changed

- `src/core/hasher.ts`: added one exported root-relative exclusion predicate,
  `isExcludedChangePath(relPath)`. It excludes `.run`, `.git`, `.DS_Store` at any
  depth and root-only `plan-prompt.md`. `collectFiles` now computes each entry's
  relative path and consults the predicate instead of comparing basenames, so
  hashing and linting share one contract and a nested `plan-prompt.md` stays
  authored content. Path ordering, NUL framing, line-ending normalization, task
  checkbox normalization, and hash format are unchanged.
- `src/core/linter.ts`: imported the shared predicate, deleted the duplicate
  `CHANGE_FOLDER_IGNORES` set, and made `collectArtifactFiles` apply the same
  root-relative rule. Control-character scanning now excludes only the root
  transient prompt and still scans a nested same-named file. No proposal, delta,
  task, verify, scope, or acceptance diagnostic was weakened.
- `src/watcher/archiver.ts`: `archiveSpecFolder` removes root `plan-prompt.md`
  idempotently (`fs.rm(..., { force: true })`) after `applyOpenSpecDeltas`
  succeeds and before the destination is created or the folder is relocated.
  Because verification gates and the scope audit run earlier in
  `checkAndArchiveSpec`, a failed gate leaves the active prompt untouched.
- `tests/hasher.test.ts`: root prompt add/edit/remove leaves the hash identical;
  a nested `plan-prompt.md` changes it.
- `tests/linter.test.ts`: a root prompt carrying prohibited control characters
  produces byte-identical findings to the prompt-free baseline; a nested
  `plan-prompt.md` is still scanned and rejected.
- `tests/archive-verification.test.ts`: successful archive drops the prompt while
  keeping proposal/tasks/`.run`; a failed change-level verify leaves the prompt
  in place with no archive.
- `tests/plan-prompt-lifecycle.test.ts` (new): real-entrypoint lifecycle coverage
  for lint exclusion with live diagnostics, approval/re-approval sealing,
  runner conflict checking, retry integrity, failing archive verification,
  successful archive retention + delta application + checkbox projection +
  archived event, idempotent absence, and a delta failure that leaves folder and
  prompt recoverable.

## Deviated

- Archive deletion runs after `applyOpenSpecDeltas` rather than before it. The
  acceptance lines require removal "after every final verification passes" and
  "before relocation", and explicitly require that a delta failure not follow a
  "premature destructive step". Deleting after a successful merge keeps the
  prompt available for diagnosis if the merge throws. All authored artifacts,
  delta application, relocation, checkbox projection, and the `archived` event
  are unchanged.
- No OpenSpec projection shim was added. The pinned validator's change scope only
  reads `proposal.md` and `specs/<capability>/spec.md`; it never reads an
  arbitrary root file, so the root prompt already never enters its input. The
  shared predicate is applied at the only place the linter itself reads folder
  bytes (`collectArtifactFiles`).
