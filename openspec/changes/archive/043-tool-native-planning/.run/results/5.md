# Task 5 result — unified planning inspection and reporting

Status: complete. Task verify and `pnpm verify` both pass.

## Changed

- `src/core/report.ts`: added `changesWithPlanningRecords` to `PlanningMetrics`
  and counted it while walking the canonical active/archived folders already
  used for planning aggregation. The flag is set on the first valid
  `plan_started` seen in a folder, so a change with several sessions counts
  once, an incomplete start still covers the change, and exit-only or malformed
  lines never do. The value is returned in the `planning` block and rendered as
  the exact line `<n> changes have a planning record` immediately after the
  `n of m sessions reported usage` line. Existing session, wall-time, token,
  cost, coverage, cycle, queue, history, and size shapes are untouched. The
  aggregation already consumed task 3's source-aware `readPlanningSessions`, so
  observed, explicit `source: owned`, and source-less legacy starts were already
  treated identically with no second projection.
- `src/cli/report.ts`: added `changesWithPlanningRecords` to the stable JSON
  planning projection (serialized keys stay alphabetically deterministic).
- `src/core/show.ts`: `PlanningSessionDetail.model` is now `string | null` and
  the detail carries the record's model verbatim instead of pre-substituting a
  string; text rendering uses `model ?? 'unavailable'`. This is the full
  nullable-model projection task 3 left as a one-line compatibility shim. No
  usage, transcript, token, cost, or artifact-hash field is exposed, and the
  `Planning Sessions` section keeps its position before the event timeline with
  no source badge.
- `tests/report-planning.test.ts`: helpers gained optional `source`/nullable
  `model`; added mixed-source aggregation coverage (legacy + owned + observed
  with null model) and a distinct-change/coverage test (several records on one
  change, an incomplete owned start, exit-only and malformed lines elsewhere).
  Fixture assertions now pin the integer and the exact text sentence.
- `tests/report-json.test.ts`: added the new planning key to the stable-shape
  assertions and the text phrase to both synthetic formatting cases.
- `tests/show.test.ts`: added mixed legacy/owned/observed projection coverage
  (start order, identical fields, null model rendering, no usage/hash leakage),
  and extended the missing/malformed-log test to prove task details, results,
  recertification history, and the event timeline still render.
- `fixture/report/expected.json`: added only `changesWithPlanningRecords: 3` to
  the planning block (008, 009, 010 each carry a valid start; rejected folders
  stay excluded).

## Deviated

  value (`null` and a present model both render the same as before), and the
