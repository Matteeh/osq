## Acceptance

- [ ] `hashChangeFolder` excludes only root `plan-prompt.md` in addition to established runtime/metadata exclusions, so adding, changing, or deleting that file leaves approval, runner conflict, and retry integrity hashes identical while a covered authored-file change still changes the hash.
- [ ] Change lint excludes root `plan-prompt.md` from control-character, schema, artifact, and tree validation inputs without hiding a same-named nested authored file or weakening any proposal, delta, task, verify, scope, or acceptance diagnostic.
- [ ] A real approval followed by prompt creation or refresh remains runnable because every approval-hash consumer shares `hashChangeFolder`; no caller implements a second prompt exclusion or special-case comparison.
- [ ] Archive-time scope, task, and change verification run while the prompt still exists, and any failed verification leaves the active prompt untouched for diagnosis with the established regression marker and event behavior.
- [ ] After every final verification passes, archiving removes `plan-prompt.md` before relocation while retaining proposal, brief, tasks, deltas, `.run` history, checkbox projection, delta application, and the authoritative archived event.
- [ ] Prompt removal is idempotent when the file is already absent, and archive relocation or delta failure does not produce a partially archived folder through a premature destructive step.
- [ ] Focused lifecycle tests exercise lint, approval hashing, runner conflict checking, retry integrity, failing archive verification, and successful archive output through real entrypoints while established hash and watcher suites remain green.

## Details

Introduce one shared root-relative exclusion predicate in `src/core/hasher.ts`
or an existing neutral helper and use it from file collection. Do not add
`plan-prompt.md` to a basename-only recursive ignore set: a nested file with the
same name is authored content. Keep `.run`, `.git`, `.DS_Store`, tasks checkbox
normalization, path ordering, NUL framing, line-ending normalization, and hash
format unchanged.

Apply the same root-relative rule in `collectArtifactFiles` before linter file
content scanning and OpenSpec validation staging. If OpenSpec validates the
live tree directly, provide it a deterministic authored projection rather than
temporarily renaming or deleting the prompt. The original prompt bytes must
remain untouched after lint success or failure.

Delete the prompt only inside the successful archive transition after every
scope recertification and verification gate has passed. Perform deletion before
the final archived folder is exposed, tolerate absence, and keep failure paths
recoverable. Do not remove any `.run` record or planning telemetry.

Build `tests/plan-prompt-lifecycle.test.ts` around temporary valid changes and
the real `lintChangeFolder`, `approveSpec`, runner integrity path, retry path,
and `checkAndArchiveSpec` where practical. Extend established hasher, linter,
and archive suites only for their direct unit contracts; other named suites are
frozen final-tree checks. Run the task verify and `pnpm verify` before exit.
