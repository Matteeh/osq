## Acceptance

- [ ] `PlanRecord` gives every new lifecycle record `source: owned | observed`, reads a missing legacy source as owned, permits observed model and exit code to be null, and preserves all established owned `--session` recording, correlation, incomplete-session, and usage behavior.
- [ ] After lint succeeds and before the seal and manifest are written, approval calls `findPlanningSessions` with the change folder, its persisted creation time, one captured observation end, and independent Codex, OpenCode, and Claude readers; failures, missing stores, malformed records, and unavailable OpenCode binaries degrade to no matches without failing approval.
- [ ] A session matches only when a successful native file-edit call has an observed timestamp in the inclusive creation-to-approval window and its normalized target is segment-contained by the change folder; relative paths resolve from the recorded session directory, sibling prefixes and `..` escapes fail, and reader results are deterministically ordered and deduplicated by harness plus native session id.
- [ ] The Codex reader retains its owned-session usage contract and observes rollout JSONL through `session_meta`, `turn_context`, successful `response_item` `apply_patch` custom calls and only their `Add File`, `Update File`, `Delete File`, or `Move to` headers, final cumulative token counters, and first/last valid record timestamps; arbitrary shell command text is not interpreted as an edit and unavailable fields remain null.
- [ ] The OpenCode reader retains its owned-session usage contract and uses the configured executable's read-only `db --format json` interface to select only needed `session` columns plus completed `part` rows whose `data` has tool `write` or `edit` and `state.input.filePath`; `time_created`/`time_updated`, stored model, token columns, and cost are used verbatim with cache read plus cache write, never transcript or file content.
- [ ] The Claude reader recursively considers `~/.claude/projects/**/*.jsonl`, groups by native `sessionId`, and recognizes successful assistant `tool_use` blocks named `Write` or `Edit` at `input.file_path` and `NotebookEdit` at `input.notebook_path`; model comes from the qualifying assistant message, start/end and cumulative token/cost fields come from the final `cost-state` when present with timestamp bounds as fallback, and missing values stay null rather than being estimated.
- [ ] Each new match appends exactly one deterministic observed start/exit pair carrying exact timestamps, nullable usage/cost, null exit code, current brief hash, and osq version; reapproval never duplicates a native session, manifest `planningSessions` counts valid starts and chooses the newest reported observed model before any newest reported owned model, config alone yields null, and the CLI emits exactly one `No planning record found for <id>.` notice per approved change with no match.

## Details

Keep the filesystem log as the only durable planning state. Extend the existing
records rather than adding a second observed-session file: write `source` on
both lifecycle records and use a stable session id derived from the reader name
and native id. Parse legacy records without `source` as owned. An observed exit
has no process exit status, so store `exitCode: null`; calculate `wallSeconds`
only from the two observed timestamps. Before appending, compare stable ids with
all readable existing starts so a repeated approval is idempotent. Sort readers
by the fixed harness order and matches by start then native id before appending.

Put the reader-neutral session shape, containment/window helpers,
`findPlanningSessions`, and append orchestration in `planning*.ts` modules so
`src/core` never imports `src/harness`. Pass structural reader functions into
`approveSpec`; `approveCommand` supplies the three local readers and resolves
the OpenCode executable with the existing harness catalog without constructing
an adapter or requiring planner configuration. Capture `now` once. Use the
initial `.run/manifest.json` `createdAt` written with the change as the lower
bound, with the folder's valid filesystem birth time as fallback; if neither is
valid, safely produce no observed matches. Run observation only after lint so a
failed change is not recorded, then append before building the final manifest.
Reader failure isolation belongs in `findPlanningSessions`, not in each CLI
call site.

For Codex, recurse below `resolveCodexDataHome()/sessions`, stream/parse JSONL
defensively, use `session_meta.payload.id` or `session_id` as identity and cwd,
and resolve patch-header paths from that cwd. Accept only successful
`response_item.payload` custom calls named `apply_patch`; do not infer writes
from `exec_command` or free-form command strings. Preserve the existing last
cumulative `thread_token_usage` mapping and accept the locally observed
`event_msg` `token_count.info.total_token_usage` equivalent without summing
cumulative snapshots. Cost stays null when the rollout does not report it.

For OpenCode, extend the existing safely quoted SQL builder with a join from
`session` to `part`; project JSON values with SQLite `json_extract` so raw
`part.data`, prompts, output, old/new strings, and write content never enter
osq. Require completed edit/write parts and use the part's `time_created` as the
edit time. Treat `session.model` as nullable text, session creation/update as
bounds, and the existing stored usage/cost columns as cumulative values. Keep
the all-null interactive usage path and its one-session uniqueness behavior
unchanged.

For Claude Code, expose a parser that tests can feed JSONL without a real home
directory. The locally confirmed store is `~/.claude/projects/`, with top-level
`sessionId`, `cwd`, and ISO `timestamp`; assistant `message.model`,
`message.usage`, and `message.content` tool blocks; and a final `cost-state`
carrying millisecond `startTime`, `totalDuration`, `totalCostUSD`, and
`modelUsage`. Sum the final per-model input/output/thinking counters and cache
read plus cache creation exactly once. Prefer those exact cost-state bounds;
otherwise use the earliest/latest valid record timestamps. Never serialize or
return prompt text, response text, edit contents, or tool results.

Build `tests/fixtures/planning-observed/claude-projects` with two synthetic,
content-free sessions in the confirmed shapes: exactly one completed edit is
inside the change and one is outside. The real approval path must append one
observed pair, preserve its model/tokens/cost, set manifest planner, and avoid a
duplicate on reapproval. Add focused Codex patch-path, OpenCode query/row,
window-boundary, path-escape, reader-failure, legacy-source, owned-fallback,
and no-log cases. The no-log CLI case must still approve and print the exact
one-line notice in addition to the established approval output. Keep existing
approve, manifest, and telemetry tests frozen as compatibility checks. Run the
task verify and `pnpm verify` before exit.

This task also owns `tests/config-planner.test.ts` expectations required by the
new manifest attribution contract. It may make the minimal nullable-model
compatibility change in `src/core/show.ts`; task 5 owns the complete show/report
projection. Task 6 owns the cross-workflow expectation and golden event-fixture
