## Acceptance

- [ ] Default `plan <name> --brief <file>` creates one change, writes `brief.md` with YAML null `planner` and the current date, writes the exact five-section opening prompt to root `plan-prompt.md`, constructs no adapter, appends no planning log, and prints exactly one line containing the folder path and `ask your planning tool to plan change <slug>`.
- [ ] Default `plan --next` preserves first-eligible selection, dependency identifiers, queue item/hash metadata, rejection and failure gates, and planning-budget behavior while marking exactly one item planned through the same null-attributed prompt-file handoff.
- [ ] The prompt file is the exact `buildOpeningPrompt` result: complete PLANNER.md, change identity and landed dependency paths, sorted capability paths, complete brief, and the unchanged bounded repository-record fifth section.
- [ ] `--session` is mutually exclusive with `--print`, works for ordinary, resumed, and queue planning, resolves the planner only on that branch, writes the selected model to the brief, launches the existing interactive adapter arguments, and preserves lifecycle, usage, exit, and failure propagation.
- [ ] `--print` works for ordinary, resumed, and queue planning, creates the change and brief as before, emits only the exact five-section prompt to stdout, and creates no `plan-prompt.md`, adapter process, or planning record.
- [ ] Reopening an existing change in default mode reuses its folder and unchanged brief, refreshes its prompt file from current repository context, and prints the same one-line handoff without creating another folder.
- [ ] Commander registers `--session` and the established planning options, rejects incompatible modes before mutation, and focused tests convert every previously implicit interactive invocation to explicit session intent while retaining repository-record and queue regressions.

## Details

Keep `planCommand` as the orchestration point but do not call
`resolvePlannerSelection`, `getHarnessAdapter`, `recordPlanStarted`, or any usage
reader until the explicit session branch. Build the prompt once after ordinary,
resumed, or queue resolution, then dispatch it to exactly one of prompt-file,
stdout, or interactive-session behavior. Use `fs.writeFile` for
`plan-prompt.md`; the later lifecycle task owns its hash and archive treatment.

Extend `PlanCommandOptions`, `validatePlanModeOptions`, and `createProgram` with
the session flag. Preserve `-p`/`--print` and the command's currently accepted
`-print` form. Reject session plus print before queue inspection, brief reads,
or folder creation. The default and print branches must not fail merely because
the configured planner binary, model, or adapter is unavailable.

Let `formatBriefContent` accept a nullable planner attribution and render YAML
`null` without string quotes. Pass the selected brief model only for session;
ordinary and queue handoff pass null. Do not change queue parsing, selection,
spend calculation, item hashing, dependency context, or the repository-record
derivation. Queue budget enforcement retains its current non-print behavior;
this change only removes the implicit launch.

Update existing planning tests rather than layering contradictory defaults on
them. Every case that proves today's interactive launch or telemetry must add
`session: true` or `--session`; default-path cases must use an adapter that
would make accidental construction or launch observable. Assert prompt bytes
by reading the file, not by reconstructing its sections in the test. Keep
Codex process behavior covered only through explicit session mode. Run the task
verify and `pnpm verify` before exit.
