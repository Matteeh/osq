## Acceptance

- [ ] The managed AGENTS block contains a `Planning a change` section telling Codex to read and follow the selected change's `plan-prompt.md`, write only inside that folder, run and fix `osq lint <slug>`, and never run `osq approve`, without weakening the existing executor protocol.
- [ ] Init creates `.claude/commands/osq-plan.md` with the slug argument and the same four rules inside one osq start/end block; repeated init replaces stale managed bytes while preserving preamble, epilogue, foreign blocks, and all unrelated repository files byte-for-byte.
- [ ] Clean and already-initialized repositories receive required parent directories and current command content, and `InitResult` plus CLI output classify the new file consistently without rewriting existing config, environment, schema, or consumer-owned template files.
- [ ] `MANAGED_PLANNER_BLOCK`, root `PLANNER.md`, and `templates/PLANNER.md` remain byte-equal and state the prompt read, change-folder-only writes, lint-and-fix, and no-approval rules in planner-appropriate wording alongside every existing planning discipline rule.
- [ ] Doctor's managed-instructions check compares current managed content rather than marker presence alone, fails actionably for missing, partial, duplicated, reversed, or stale Claude/AGENTS/PLANNER blocks, and passes after `scaffoldProject` repairs each case without disturbing foreign content.
- [ ] README planning examples describe default prompt handoff, explicit `--session`, print mode, installed Claude/Codex entry points, approval observation, and that model choice belongs to the author's planning tool; generated config contains no required planner model.
- [ ] Repository copies of AGENTS.md, PLANNER.md, and the Claude command match the installed constants, focused preservation tests pass, import boundaries stay valid, and any new init or doctor helper remains within the source-line budget without an allow-list addition.

## Details

Keep `OSQ_START_MARKER`, `OSQ_END_MARKER`, `MANAGED_AGENTS_MD_BODY`, and
`MANAGED_PLANNER_BLOCK` as the canonical public managed-block values. Add one
canonical Claude command body and reuse the existing block replacement logic;
do not create a second marker parser. The command must use Claude's documented
`$ARGUMENTS` substitution and resolve the folder by that supplied slug rather
than embedding a repository-specific path.

Refactor init/doctor responsibilities into cohesive `init*.ts` and
`doctor*.ts` helpers if either existing module would cross 250 lines. Doctor
must compare the extracted block bytes with the installed canonical values and
diagnose each file by name. An unmanaged AGENTS.md is no longer healthy because
the Codex planning entry point is now required; preserve foreign managed blocks
and content outside osq's own marker pair.

Add the repository `.claude/commands/osq-plan.md` as the consumer example that
the current checkout itself would receive from init. Keep `templates/PLANNER.md`
packaged and byte-equal to the root block; the Claude command may be a source
constant or bundled template as long as installed and repository bytes have one
authority and packaging includes it. Do not add an AGY-specific file or claim a
contract that was not confirmed.

Extend init, managed-block, and doctor suites with temporary existing
repositories containing hand-authored preambles, foreign blocks, stale osq
blocks, and sentinel files whose bytes are snapshotted before init. Keep
`tests/codex-guidance.test.ts`, line-budget, and import-graph suites frozen as
final-tree checks. Run the task verify and `pnpm verify` before exit.
