## Changed
- Added `src/cli/remote-commands.ts`: `createForwardedCommands(land = landCommand)` plus `createForwardedRunner(cwd, options?)`. The command table calls the same command functions the CLI actions call, with `cwd`, emitting `stdout`/`stderr` writers, and `home` for `osq`, `status` and `report`; `approve` runs non-interactively, `land` publishes, and `plan` checks `findChange`/`changeTrees` for an unapproved briefed change in the project's own tree before `planCommand`, wrapping other errors as `Error: <message>`. The runner serializes `approve`, `land`, `reject`, `retry`, `sync`, `new`, `plan` and `lint` through a promise chain and resolves the last NDJSON line without rejecting or writing to a process stream.
- Added `src/cli/remote-transport.ts`: `readServerSetting`, the `RemoteServer` type, `runOnServer`, `readFromServer` and `writeToServer` over the global `fetch`, with the token read from `GET api/commands` and the three `CommandError` failure forms.
- Changed `src/cli/server-worker.ts`: `runServerWorker` passes `startWebServer` a `runCommand` from `createForwardedRunner(cwd, { home: options.home })`.
- Added `tests/remote-forward.test.ts`: every "Same output as local" row against a real `startWebServer` on port 0 with a site and the forwarded runner versus the in-process call (comparing streams and, for the throwing row, the `CommandError` message/next/exit); the failure exit code and next step; the publishing land; the read-at-once/write-one-at-a-time order with deferred handlers; and the plan-without-a-brief refusal.
- Added `tests/remote-setting.test.ts`: every "Server values" row and each transport failure row (closed loopback port, 403 answer, stream ending without its last line).

## Deviated
- `server-worker.ts` now destructures `resolveInputs(options)` as `const { cwd, config: readConfig } = resolveInputs(options); const config = await readConfig();` instead of three separate lines. The added `runCommand` line pushed `runServerWorker` to 81 lines, one over the function budget, and this is the only behavior-preserving way to drop a line without changing what the function does.
- The command table is built through a small generic `table()` adapter per group (`readCommands`, `writeCommands`) rather than 18 explicit handler bodies, to keep the new file inside the 250-line budget. Each adapter still calls the exact command function, arguments and options the CLI action uses.

Touched: src/cli/remote-commands.ts, src/cli/remote-transport.ts, src/cli/server-worker.ts, tests/remote-forward.test.ts, tests/remote-setting.test.ts
