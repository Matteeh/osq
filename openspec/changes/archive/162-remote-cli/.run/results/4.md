## Changed
- Added `src/cli/remote-client.ts`: `forwardProgram(program, server)`. It returns a command's forwarded request from the Commander action values (positional args, variadic args flattened, a missing one as null, and the parsed options), replaces the root action and each forwarded command's action with a send through `runOnServer` (via `processStdout`/`processStderr`), hands `plan` and `lint` to `planOnServer`/`lintOnServer`, and replaces the actions of `init`, `setup`, `migrate`, `watch`, `serve`, `doctor`, `inbox` and each `server` subcommand with the one-line local-only `CommandError`. `plan --session`, `plan --brief` and `digest --out` refuse the same way; a nonzero forwarded end is rethrown as a `CommandError` with its exit code and next step.
- Changed `src/cli/run.ts`: `runCli` reads `readServerSetting(process.env)` inside its `try` and calls `forwardProgram` only for a non-null server, so an invalid `OSQ_SERVER` prints as a `CommandError` and unset leaves parsing unchanged.
- Changed `README.md`: the "Running osq on a server" section now explains exporting `OSQ_SERVER`, which commands stay local, that `osq plan <id>` downloads a working copy under `~/.osq/remote/` and `osq lint <id>` uploads it, that a planner's shell or editor must be started with it set, and that unsetting it returns to local use.
- Added `tests/remote-cli.test.ts`: the real CLI spawned as `tests/server-command.test.ts` spawns it, with a temporary `HOME`. It starts a server with `osq server start` on a free port over a `harness: 'mock'` project with change `001-demo`, polls `<url>api/server`, compares `osq show 001` and `osq spec` with and without `OSQ_SERVER`, and stops the server in an `after` hook that also kills every recorded pid. It refuses every local-only command against a raw HTTP server that must count zero requests, checks the invalid `OSQ_SERVER` line and exit 1, and checks the out-of-reach line against a free-but-closed loopback port.
