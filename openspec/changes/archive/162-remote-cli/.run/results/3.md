## Changed
- Added `src/cli/remote-plan.ts`: the client side of cli-foundation "Planning against a server". `remoteWorkRoot(server, home = os.homedir())` builds `<home>/.osq/remote/<host>/<project>` with every `:` in the host replaced by `-`; `planOnServer(server, request, outputs)` runs the forwarded plan through `runOnServer`, passes `--print` output through unchanged, and otherwise collects the stdout, matches the handoff line `<path>: ask your planning tool to plan change <folder> — next: <next>`, downloads the folder with `readFromServer('api/files/<folder>')`, replaces the working copy with exactly the downloaded files, and reprints the line with the working-copy path; `lintOnServer(server, request, outputs)` resolves each named id with `matchesFolder`, reads the working copy's files except those under `.run/` as `/`-separated paths, uploads them with `writeToServer(..., 'PUT', 'api/files/<folder>')`, then forwards `lint`. Both throw the last line's failure as a `CommandError` with its message, exit code and next step.
- Added `tests/remote-plan.test.ts`: the four "Planning against a server" scenarios against a real `startWebServer` on port 0 with a site and `createForwardedRunner(root, { home })` over a temporary project with the default config, plus `--print` pass-through and `lint` with no ids. "Lint uploads the working copy" compares the forwarded output with `lintCommand(['001'], { cwd: root, stdout, stderr })` run in-process after the upload and checks the server folder holds the working copy's files plus its own `.run/`.

## Deviated
- The test fixture seeds the change with `proposal.md`, `tasks/1.md`, a passing root `verify.cjs`, and a fake `node_modules/.bin/openspec` from `tests/helpers.ts` in addition to the `brief.md` and `.run/manifest.json` the task named. The "Lint uploads the working copy" scenario needs a change that lints successfully and a real verifier; with only the named files the lint pass fails on the template placeholder and the missing OpenSpec binary, and the output comparison would exercise the failure path rather than a successful lint.
- Added two cases beyond the four named scenarios (`--print` downloads nothing, `lint` with no ids uploads nothing) to cover the acceptance lines the scenarios do not name.
