## Changed

- Added `src/core/status/queue-pick.ts` with `pickQueueRow`: it chooses the first eligible row without a slug, or the named row with one, and owns the not-in-queue, already-has-change, waiting, and no-eligible refusals.
- `prepareQueuePlan` now takes an optional `slug`, keeps the active-failure check first, delegates the row choice to `pickQueueRow`, and then runs the unchanged rejected-item and spend gates.
- `osq plan --next [slug]` parses an optional queue slug; `PlanCommandOptions.next` is `boolean | string` and passes through `prepareQueueSelection`, which forwards the slug to `prepareQueuePlan` without adding lines to `plan.ts`.
- `--run` refuses a bare `--next` and one carrying a slug, and the remote plan check treats a string slug as next mode.
- Added `tests/queue-plan-slug.test.ts` covering the named-item plan, the slugless first pick, every refusal row, the `--run` guard, and a forwarded slug.

## Deviated

- `prepareQueueSelection` accepts the whole `next` option (`boolean | string`) and derives the slug itself, rather than taking a separate `slug`. This keeps `plan.ts` at its 249-line size while still passing next mode through the selection helper; `prepareQueuePlan` still takes the optional `slug` the task requires.

## Outside scope

- `tests/vcs.test.ts` and `tests/vcs-doctor.test.ts` intermittently fail with `Error: spawn EIO` when asserting a missing git binary. The failing tests pass in isolation and on a rerun of `pnpm verify`, so this is a pre-existing environment flake, not a queue-planning regression. The final full `pnpm verify` run passed.
