## Details

Put the command in its own module, such as `src/spec.rs`, and keep
`feature.rs` a dispatcher on `invocation.command`. List the capability
folders as plan's `capabilities` in `next.rs` does, but keep only those
where `<folder>/spec.md` exists, and sort the names. Check the capability
against that list before building any path from it. Read the spec with
`osq_kernel_specs::read_living_spec` and compare `Requirement::name` with
`osq_kernel_specs::normalize_requirement_name` of the argument; print
`Requirement::raw` and a newline. No new dependency is needed, so
`Cargo.lock` does not change.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from `requirement-lookup.ts` or a golden. Run the proposal's verify as the
watcher does, with `OSQ_CHANGE=openspec/changes/298-rust-spec-command`, so
the link gates see this change's requirements.
