## Details

Never read anything under `src/` from Rust; the TypeScript files are in
`entry` only so you can port them. Build the trees as
`crates/features/plan/src/next/number.rs` does, but in the inbox crate: a
feature never calls another feature (ADR 022). Use `GitVcs::new(root)` with
`with_timeouts(&config.timeouts)`; the default branch is
`default_branch(<vcs.defaultBranch, else main>)`, and `osq/<folder>` exists
when `list_branches("osq/<folder>")` names it exactly.

The test builds each scratch repository under its own folder in
`CARGO_TARGET_TMPDIR`, named after the test, with real `git` (`init -b
main`, a local `user.name` and `user.email`, `git worktree add` per row). The
archived worktree changes, `.run` included, are committed on their branch;
`008-active` is left uncommitted. `007-merged` is merged into `main` with
`git merge` after its commit. The `archived` event in `002-wait` is one line
of `.run/events/change.jsonl`:
`{"type":"archived","timestamp":"2026-10-21T20:19:27.083Z","data":{"archivePath":"openspec/changes/archive/002-wait"}}`.
Point `worktreeRoot` at an empty folder beside the repository, so no
stacked folder under the real home is found. Do not set process
environment variables in tests.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/270-rust-inbox-archived`, so the link gates see
this change's new requirements.

## Scenarios

- rust-inbox: Config that does not load
- rust-inbox: Worktree changes with vcs on and off
- rust-inbox: Archived worktree changes
