## Changed

- Added `osq-kernel-config` and `osq-kernel-vcs` dependencies to the inbox crate.
- `InboxFeature::run` now loads `osq.toml`, and the read layer:
  - reads the root alone with `list_changes` when vcs is off, or when vcs is on but the root is not a git repository;
  - with vcs on and git at the root, builds trees with `change_trees` over `GitVcs::worktree_list` and the stacked folders, then reads them with `list_tree_changes`.
- The Landed group now uses only the root tree's snapshots; needs-you, running and validator use every listed tree.
- Added archived-worktree needs-you items: steering first with the existing steering triggers and `osq plan`, otherwise `archived, not landed — osq land` when the default branch lacks the archive folder and `osq/<folder>` holds its archived `.run/approved`.
- Exposed the first steering trigger from `needs/steering.rs` and added archived-item rendering in `needs/mod.rs`.
- Added `crates/features/inbox/tests/inbox_trees.rs` with the three required scenarios: config that does not load, worktree changes with vcs on and off, and archived worktree changes.
- Ran `cargo fmt --all`, `cargo test -p osq-feature-inbox --test inbox_trees`, targeted cargo-mutants over each changed source file, and the proposal verify (`sh scripts/verify-rust.sh` with `OSQ_CHANGE`).

## Deviated

- Added a fourth test, `stacked_changes_are_read`, beyond the three scenarios. It exercises the stacked-folder tree and proves a root archive is not treated as a worktree archive. It keeps the existing worktree scenario's `Covers` tag; it also removes cargo-mutants misses in `read.rs`.

Touched: crates/features/inbox/Cargo.toml, crates/features/inbox/src/lib.rs, crates/features/inbox/src/needs/mod.rs, crates/features/inbox/src/needs/steering.rs, crates/features/inbox/src/read.rs, crates/features/inbox/tests/inbox_trees.rs
