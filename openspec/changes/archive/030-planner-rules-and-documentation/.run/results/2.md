# Task 2 result

## Changed

- `src/core/linter.ts`:
  - Added `INSTRUCTION_SHAPED_REQUIREMENT_REGEX = /^(?:update|document)/i` and
    `instructionVerbOf`, which returns the leading imperative verb of a delta
    requirement name.
  - Added `scanInstructionShapedRequirements`, which iterates parsed
    `DeltaRequirement`s and pushes an `OPENSPEC_ERROR_PREFIX`-prefixed error naming
    the capability, the requirement title, and the offending verb and stating that
    delta specs must define living capability requirements, not instructions.
  - `verifyDeltaTargets` now parses each capability delta once and scans
    `added`, `modified`, and `removed` requirements before applying the merge. It
    continues to report unresolvable delta targets; the instruction check is
    additive and appears even when a merge target also fails.
  - `approveSpec` (unchanged) calls `lintChangeFolder`, so instruction-shaped
    deltas now block approval and no `.run/approved` marker is written.
- `tests/instruction-delta-lint.test.ts` (new): builds a change folder with a
  hand-written proposal/task plus fake validators, then asserts `Update` and
  `Document` requirement names are rejected (case-insensitively), MODIFIED and
  REMOVED sections are inspected, the error names capability + title, declarative
  requirements pass with zero errors, and `approveSpec` rejects and does not seal.
- `tests/linter.test.ts`: added `Update`/`Document` rejection tests and a
  declarative acceptance test using the existing `writeDelta` helper.
