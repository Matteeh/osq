## Details

In `src/core/linter.ts`, reuse `verifyDeltaTargets`, `parseDelta`, `DeltaRequirement`, `OPENSPEC_ERROR_PREFIX`, and `resolveOpenSpecRoot`.
Add validation to delta inspection that examines parsed requirements across `added`, `modified`, and `removed` sections of every capability delta spec under `specs/<capability>/spec.md` in the change folder.
Check each requirement name against an instruction verb pattern matching leading "update" or "document" (case-insensitive).
When matched, add an error formatted with `OPENSPEC_ERROR_PREFIX` identifying the capability, the requirement title, and explaining that deltas must define living state requirements rather than instructions ("update", "document").
In `tests/instruction-delta-lint.test.ts` and `tests/linter.test.ts`, reuse `writeDelta`, `lintChangeFolder`, and `DEFAULT_CONFIG` from test helpers to assert that delta requirements starting with "Update" or "Document" fail linting and approval with clear diagnostics, while declarative requirements pass.
