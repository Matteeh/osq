## Changed

- Added `land/sync/verify.rs`, which runs the archived proposal's `verify` from rust-specs `parse_proposal` and its trimmed frontmatter `check`, stops the sync with `sync_verify_red` on a red command, and on a pass writes the next `.run/logs/change-<k>.log`, its `.gitignore`, and a `verify_ran` event with the output tail.
- Called that step from `sync.rs` between `vcs.prepare` and the `synced` event.
- Extended `sync/command.rs` with `run_timed`, keeping `run` as its exit-code-and-output wrapper, so the `verify_ran` duration comes from `run_verify`.
- Added `tests/land_sync_verify.rs` with one test per "Sync verify outcomes" row plus a supplemental next-free-log-number test.

## Deviated

- The `verify: true` row uses `verify: "true"`: a bare `true` is a YAML boolean, and `parse_proposal` treats a non-string value as no verify, as TypeScript's parser does. Quoting keeps the row's intended `true` command and its expected events.
- Added one supplemental test for the next free log number to cover `count_logs` and `is_log_name`; it closed four mutants that the scenario rows did not reach.

## Missing context

- The delta row writes `verify: true` unquoted, which conflicts with the requirement to read `verify` through `parse_proposal`; the row needed a quoted value to run the command it names.

## Outside scope

- `rust-core`'s `event_line` sorts JSON object keys alphabetically because `serde_json` has no `preserve_order`, so the `verify_ran` data keys serialize as `command`, `duration`, `exitCode`, `log`, `output` rather than TypeScript's insertion order. The event sets only the five required fields.
