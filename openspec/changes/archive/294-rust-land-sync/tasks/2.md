## Acceptance

- [ ] In step 5 of "Land sync", before the `synced` event, `land` runs the archived proposal's verify and check as rust-land "Land sync verify" says: it writes each passing command's log and `verify_ran` event, and a red one stops the sync with the reason `sync_verify_red`, recorded as "Land stop record" says. A proposal with neither leaves the sync as task 1 built it, and every `land_sync.rs` test passes unchanged.
- [ ] A new `tests/land_sync_verify.rs` proves "Sync verify outcomes", one test per row. Each test's doc names `Covers: rust-land/sync-verify-outcomes` and each test uses its own land repository.
- [ ] Every public item ends its doc with `Implements: rust-land/<requirement>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Port the archived branch of `runSyncVerify` and `runOne` from TypeScript's
`sync-verify.ts`, `writeVerifyLog` from `verify-log.ts`, and
`tailVerifyOutput` with `cutLine` from `verify-excerpt.ts`. Put the step
in a new `land/sync/verify.rs` and call it from `sync.rs` where the
`synced` event is written. Read `verify` with rust-specs `parse_proposal`
and `check` from `parse_frontmatter`. Build each `VerifyRequest` as task 1
builds the sync's commands, with the worktree as `cwd` and no change. A
red verify or check goes through task 1's stop path, so the merge is
aborted, the events file is put back, and the stop is recorded.

Write the `verify_ran` event with rust-core's `VerifyRanData`, setting
only `command`, `exit_code`, `duration`, `log` and `output`, so its keys
come out in TypeScript's order. Count a line's characters as `char`s.

In the tests, build each repository with the helpers in
`tests/support/mod.rs`, a frozen test file: `add_change_with` with the
fixture change's files and the row's `proposal.md`, then commit `other.txt`
on `main` in the checkout. Read the events and files on the branch's tip
with the support's `git` helper and `git show`.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take expected values
from the delta's THEN lines and the TypeScript source. Run the proposal's
verify with `OSQ_CHANGE=openspec/changes/294-rust-land-sync`, so the link
gates see this change's new requirements.
