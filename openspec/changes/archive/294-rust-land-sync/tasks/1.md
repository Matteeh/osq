## Details

Port `syncWithDefaultBranch` from TypeScript's `sync-main.ts` for an
archived change only, with `changedRequirements` and `rebuildLivingSpecs`
from `sync-specs.ts`, `blockedConflicts` and `rebuildLockfiles` from
`sync-lockfiles.ts`, `runPrepare` from `approve-worktree.ts`, and
`recordLandStop` from `land-stop.ts`. Leave out the bridge, the progress
line, the active-change branches and the verify step; task 2 adds the
verify step just before the `synced` event, so call the event writer from
one place it can insert before.

Put the sync in a new `land/sync.rs` with submodules under `land/sync/`,
and call it from `run_land` with one line, so `run_land` stays under
clippy's `too_many_lines`. After a sync commit, read the change's
`worktree_list` entry again, so the tip and the message's `Osq-Head` are
the sync commit. Keep the moved check of "Land commit" as it is.

Write events with rust-core's `Envelope`, `Event::Synced` and
`Event::Regressed` and `event_line`, as the run crate's `events.rs`
appends them, and take the time from the land crate's own `time.rs`. Build
each command's `VerifyRequest` as `after.rs` builds the after-land
command's, with the worktree, or the lock file's folder, as `cwd`. Write
the merged specs as the archive crate writes `merge_change`'s results.
Do not depend on another feature crate.

In the tests, build every repository with the helpers in
`tests/support/mod.rs`; it is a frozen test file, so leave it unchanged.
Use `add_fixture_change` or `add_change_with`, then commit `main`'s row
commit in the checkout with `write` and `commit`. For the lock file
scenario, create each crate with a `Cargo.toml` and an empty `src/lib.rs`
and write each `Cargo.lock` with `cargo generate-lockfile --offline`, run
by the test in that tree before its commit. For the hook rows, write an
executable `pre-commit` that exits 1 into a scratch folder and set the
checkout's local `core.hooksPath` to it after the setup commits. Read the
branch's tip with the support's `branch_head`, `message` and `tree`.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take expected values
from the delta's THEN lines and the TypeScript source. Run the proposal's
verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/294-rust-land-sync`, so the link gates see
this change's new requirements.
