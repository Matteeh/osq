## Changed

- Copied the change's `fixture/reject-worktree` fixture and its seven goldens
  into `crates/features/approve/tests/fixtures/` unchanged.
- `reject` now reads `osq.toml` after its arguments, before any change lookup,
  and fails with the `ConfigError` display when it cannot load.
- With git on, `reject` finds the change across the root's osq worktrees with
  `worktree_list`, `change_trees` and `list_tree_changes`, using approve's
  git-on check and lookup matching. With git off, or for a change in the root,
  it keeps the existing checkout behavior and makes no git call after lookup.
- Added `src/reject/worktree.rs`: it selects the status paths under the old and
  rejected folders, builds the commit message, commits the move with
  `vcs.author`, checks for other changes, and removes the worktree or keeps it
  with the `VcsError` display. The branch is never deleted.
- Added the worktree output lines to `src/reject/text.rs` and exposed approve's
  git-on check to the reject module.
- Added `tests/reject_worktree.rs`, which builds every golden case's scratch
  git repository, compares the rendered output, branches, worktrees, tip,
  commit and status against the goldens, and proves the config-load refusal.
  It also proves a rejected folder never matches a git-on lookup.

## Deviated

- Added the rejected-folder lookup test to `tests/reject_worktree.rs` after
  cargo-mutants found a missed `&&` mutant in `locate_trees`; it distinguishes
  active from rejected entries.
