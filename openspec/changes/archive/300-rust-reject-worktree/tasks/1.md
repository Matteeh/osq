## Details

Reuse approve's own "git is on" check from `approve.rs` and its
`find.rs` matching. Build the trees as archive's lookup does in
`crates/features/archive/src/archive.rs`: `GitVcs::new`, `with_timeouts`,
`worktree_list` turned into `TreeCandidate`s, and `change_trees` with no
stacked folders. A feature never calls another, so write that code in this
crate. Keep the git-off path on `list_changes`, so the existing reject
tests, which have no `osq.toml`, never run git. Put the worktree steps in
their own module under `src/reject/`, and keep the path choice, the message
and the output lines pure.

In the test, build each repository with `git` through
`std::process::Command`, exactly as the golden script's header says, under
a new folder of `CARGO_TARGET_TMPDIR` named after its row, and canonicalize
it before use. The script's TypeScript calls stand in for the Rust `reject`
run; leave them out. Write the hook with mode `0o755` through
`std::os::unix::fs::PermissionsExt`. Build the text the golden holds before
comparing, replacing the scratch folder with `<scratch>`. A test cannot set
environment variables.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source or a golden. Run the proposal's verify as the
watcher does, with `OSQ_CHANGE=openspec/changes/300-rust-reject-worktree`,
so the link gates see this change's requirements.
