## Details

Put the excerpt and tail functions in their own file in the run crate,
ported from TypeScript's `excerptVerifyOutput` and `tailVerifyOutput`; the
retry feature's `excerpt.rs` already ports the tail and may be copied, since
a feature never calls another. Write the log as land's `write_log` does, but
counting `<target>-<digits>.log` files for the task's target or `change`.
Convert the `u64` limits with `usize::try_from(..).unwrap_or(usize::MAX)`.
No new dependency is needed.

The tests rewrite `tasks/1.md`, `proposal.md` and `osq.toml` as
`verify_timeout_keeps_the_output_tail` does, then call `support::write_seal`.
The table's commands are the shell text `run_verify` runs; quote them for
the YAML frontmatter.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Run the proposal's verify
as the watcher does, with `OSQ_CHANGE=openspec/changes/309-rust-run-verify-tail`,
so the link gates see this change's scenario.
