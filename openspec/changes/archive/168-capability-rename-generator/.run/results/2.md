## Changed

- Added `src/core/spec/generated-move-lint.ts` exporting
  `collectGeneratedMoveFindings({ projectRoot, openspecRoot, folderPath, proposalPath, data })`,
  shaped like `collectCapabilityRelationFindings`. It reads `data.generated`,
  returns `[]` when absent, and:
  - fails a non-mapping/mis-typed `generated` with
    `generated must name kind rename or split, from, and a list to` on the proposal;
  - fails a `from` with no living spec with
    `generated names <from>, which has no living spec` on the proposal;
  - otherwise, leaving out every `Code ownership` requirement, reads the living
    `<from>` blocks with `parseCapabilitySpec` and the deltas with `parseDelta`,
    and reports the three moved-requirement findings, attributing the two
    ADDED ones to the target delta and the REMOVED one to the `from` delta.
    Blocks are compared after line-ending normalization and trimming, matching
    `normalizeBlockRaw` in `delta.ts` (private, so reproduced locally).
- Added the call in `lintChangeFolder` in `src/core/spec/linter.ts`, next to the
  capability relation check, for every proposal; each finding is added with
  `findings.addOwn`. No other check changed.
- Added `tests/generated-move-lint.test.ts`, which builds temporary projects
  with a living `gadgets` spec (`Count`, `Price`, `Code ownership`) and a change
  whose proposal carries a generated rename with hand-written generator-format
  deltas. It exercises every scenario of "Generated move lint" through
  `lintChangeFolder` and filters to only this check's messages. It also covers
  the `from` has no living spec message and the no-`generated` case.

## Missing context

The acceptance says the test uses "hand-written deltas in the generator's
format", but the generator itself is task 3 and did not exist in this tree. I
reproduced the format from the "Generated capability move" requirement
(`# Spec Delta: <old>` plus `## REMOVED Requirements` with `**Reason**`/
`**Migration**`, and `# Spec Delta: <target>` plus `## ADDED Requirements`). If
the generator's exact bytes differ, these tests should still hold because the
check compares requirement blocks, not the reason/migration lines.
