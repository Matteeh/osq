## Changed

- `src/core/spec/apply-deltas.ts`: added `mergeLivingSpec(baseContent, capability, delta)`, which returns `mergeDelta`'s text or null when `parseCapabilitySpec` finds no requirement. `applyOpenSpecDeltas` now merges through it; on null it removes the capability's `spec.md` and `osq.yml`, then the folder when empty, and writes nothing for it. Exported with `@scenario`/`@adr 002` tags.
- `src/core/spec/merged-spec-check.ts`: `validateMergedSpecs` filters out every input whose merged content has no requirement, and returns `[]` without running the validator when none is left. Exported with `@scenario` tags.
- `tests/living-specs-delta-equivalence.test.ts`: dropped the fixed `CAPABILITIES` list and its `mergeDelta` import; added `livingCapabilities`/`replayCapabilities` discovery from `openspec/specs/` and every replayed change folder's deltas. `replayLivingSpec` now returns `string | null` and merges with `mergeLivingSpec`; the main test checks a null replay has no living folder and every other one matches its living spec. The legacy-reference and byte-stability checks were kept.
- `tests/capability-emptied.test.ts` (new): temporary scaffolded projects that exercise the three "Emptied capability removed" scenarios through `applyArchiveSpecs`/`restoreArchiveSpecs`, and the "Emptied capability not validated" scenario through `lintChangeFolder` with the repository's OpenSpec binary.

## Deviated

- In the lint scenario I gave the new `widgets` capability a briefly-short `## Purpose`, so the real merged-spec validation reports a `widgets after archive` finding. That finding proves the merged `widgets` spec was validated while asserting no `gadgets after archive` finding, matching the scenario's THEN line "validates the merged `widgets`".
