## Changed

- `src/cli/capability.ts` (new): `capabilityRenameCommand(old, new, options)`,
  `capabilitySplitCommand(old, mapFile, options)`, and
  `registerCapabilityCommand(program)`. Options are the command inputs plus a
  required `change`. Each loads config and (for split) reads the map inside its
  error handling, runs `generateCapabilityMove`, and prints `wrote <path>` per
  written file then `<n> file(s) outside the specs name <old>; proposal.md
  lists them` to stdout. Every failure becomes a `CommandError` whose message
  is `Error: <message>`, which `runCli` prints to stderr with exit 1.
  `registerCapabilityCommand` adds `capability` with the required description
  and the `rename`/`split` subcommands, each with a required `--change`, and
  `split` with a required `--map`.
- `src/cli/index.ts`: imports and calls `registerCapabilityCommand`. Still 240
  lines.
- `src/cli/help-groups.ts`: `capability` last in the Plumbing group.
- `src/cli/remote-client.ts`: `capability` joins `LOCAL_ONLY`, so with
  `OSQ_SERVER` set it refuses as a local-only command.
- `README.md`: the Plumbing block gains `osq capability rename <old> <new>
  --change <id>` and `osq capability split <old> --map <file> --change <id>`.
- `tests/help-groups.test.ts`: `capability` added last to the expected Plumbing
  group.
- `tests/cli-no-direct-output.test.ts`: typed entries for both command
  functions; no other change.
- `tests/capability-command.test.ts` (new): builds a temp project with living
  `gadgets` (`spec.md` + `osq.yml`) and `pricing`, and unapproved change `002`.
  Checks every scenario of cli-foundation "Capability command": the rename
  stdout and files, the split deltas and sidecar, the missing-map refusal with
  nothing written, and the Plumbing help order. It also checks
  spec-lint-and-approve "Generated rename replays": after the CLI rename,
  `lintChangeFolder` reports no generated-move finding; `applyArchiveSpecs`
  archives the change, after which `openspec/specs/gadgets/` is gone; replaying
  from no base the delta that created `gadgets` then the change's `gadgets`
  delta with `mergeLivingSpec` gives null, and replaying the `widgets` delta
  from no base equals the living `widgets` spec bytes.
