## Changed

Added the capability move generator and its tests, all under the task scope.

- `src/core/spec/capability-move.ts` — `generateCapabilityMove(projectRoot, config, changeId, move)`. Resolves the change with `findChange` and refuses an approved folder, no living `<old>`, a rename onto a living target, and bad capability names, all before writing. Reads blocks with `parseCapabilitySpec`, the purpose with `extractPurposeSection`, sidecars with `parseSidecar`/`formatSidecar`. Removes the earlier `generated` field's folders, writes `specs/<old>/spec.md`, then each new target's `osq.yml` and `spec.md`, then edits `proposal.md`. Returns `{ folderPath, written, naming }`.
- `src/core/spec/capability-move-map.ts` — `readMoveMap(text)` parses the YAML map and returns split targets in map order, throwing the refusals the text alone decides.
- `src/core/spec/capability-move-proposal.ts` — `editGeneratedProposal` edits frontmatter with `YAML.parseDocument` (keeping other keys' flow form), sets `generated`, merges `creates`, and replaces/appends the `## Generated` section. `readGeneratedNames` feeds the removal step.
- `src/core/spec/capability-naming.ts` — `findNamingFiles` scans the project read-only for whole-word mentions.
- `tests/capability-move.test.ts` — temp projects with a living `gadgets` (`spec.md` + `osq.yml`) and `pricing`, an unapproved change 002. Covers every scenario of "Generated capability move", "Generated move map" (all eight table rows) and "Generated move proposal", including the byte-for-byte check through `mergeDelta`.
