- [ ] `src/core/spec/apply-deltas.ts` exports `mergeLivingSpec(baseContent, capability, delta)`, which returns what `mergeDelta` returns, or null when `parseCapabilitySpec` finds no requirement in it. `applyOpenSpecDeltas` merges through it, and on null removes the capability's `spec.md` and `osq.yml` and then the folder when it is empty, so watcher-and-harness "Emptied capability removed" holds. `rebuildLivingSpecs` and `applyArchiveSpecs` stay unchanged and get this through `applyOpenSpecDeltas`.
- [ ] `validateMergedSpecs` in `src/core/spec/merged-spec-check.ts` leaves out every input whose merged content has no requirement, and returns `[]` without running the validator when none is left, so spec-lint-and-approve "Merged living spec validation" holds, its new scenario included.
- [ ] `tests/living-specs-delta-equivalence.test.ts` drops its fixed `CAPABILITIES` list. It replays every capability that has a folder under `openspec/specs/` or a delta in a replayed change folder, merging with `mergeLivingSpec`. A capability whose replay ends null must have no living folder, and every other one must match its living spec as today. Every other test in the file is kept, and the file passes against the current archive, which already replays all 8 capabilities to their living specs.

Expected values come from the scenarios' THEN lines.
