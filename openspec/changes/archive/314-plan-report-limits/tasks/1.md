## Acceptance

- [ ] `PlanningConfig` gains `record?: PlanningRecordConfig` with `minimumTasks`, `recentChanges` and `deadOutcomes`, defaulting to the exported `DEFAULT_PLANNING_RECORD` (5, 20, 10) in `DEFAULT_PLANNING_CONFIG`; `validatePlanningConfig` reads it as `validatePlanningHistory` reads `history`, failing with `planning.record.<key> must be a positive integer`.
- [ ] `report.ts` drops the three `REPOSITORY_RECORD_*` constants: `getRepositoryRecord` takes its window and dead rows from `config.planning.record`, and `formatRepositoryRecordBody(record, config = DEFAULT_CONFIG)` prints the too-small sentence with the configured `minimumTasks`. `src/cli/plan.ts` passes its config as the second argument and stays within 250 lines.
- [ ] New `tests/plan-record-config.test.ts` proves "Default record sizes", every row of "Configured record sizes" through `buildOpeningPrompt` on temporary archives, and "Invalid record configuration" for each key with 0, -1 and 1.5.
- [ ] `tests/config-planning.test.ts` expects the `record` defaults in its whole-block comparisons and is otherwise unchanged; `pnpm verify` passes.

## Details

Build the temporary archives the way `tests/report-sizes.test.ts` does. Use
`node:test`, not `scenario()`: metrics-and-reporting holds a duplicate
scenario name, so `lookupScenario` refuses it. Tag the changed exported
functions with `@scenario metrics-and-reporting: <name>` lines.

## Scenarios

- metrics-and-reporting: Default record sizes
- metrics-and-reporting: Configured record sizes
- metrics-and-reporting: Invalid record configuration
