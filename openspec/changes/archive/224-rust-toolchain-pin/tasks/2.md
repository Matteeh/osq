## Acceptance

- [ ] `scripts/verify-rust.sh`, right after its `cd`, reads the pinned version from the `channel` line of `rust-toolchain.toml` and the found version as the second word of `cargo --version`. When they differ, it prints rust-core "Verify script toolchain check"'s message to standard error and exits 1 before `cargo fmt`. Its header comment says so in one sentence. The rest of the script does not change.
- [ ] The test's `CARGO_STUB` answers `--version` by printing `$CARGO_VERSION_TEXT` without recording it, and records every other call as today. `withStub` sets `CARGO_VERSION_TEXT` to `cargo 1.99.1 (stub)` unless a case sets another. The existing "Verify script steps" and "Verify script names the missing diff" cases otherwise stay as they are and pass.
- [ ] `tests/rust-verify-script.test.ts` gains a `describe('rust-core: Verify script refuses another toolchain', ...)` with one case per table row of that scenario, checking the exit code, that stdout or stderr holds the row's text, and the recorded commands.
- [ ] `pnpm lint` reports nothing in `tests/rust-verify-script.test.ts`.

## Details

The script runs under `set -eu` with plain `sh`, so use only POSIX
`sed` and shell parameter expansion to read both versions. The test runs
the script from the repository root, so it reads the real
`rust-toolchain.toml` that task 1 wrote.
