## Changed

- `src/cli/plan-queue.ts`: `prepareQueueSelection` now throws
  `new CommandError(preparation.message)` on a refusal instead of printing the
  refusal and setting `process.exitCode = 1`. The incomplete-coverage notice
  still goes to `console.error` and a ready selection is still returned.
- `src/cli/plan.ts`: a non-zero planner exit code now throws
  `new CommandError('', { exitCode })` after `recordPlanExited`, instead of
  assigning `process.exitCode`.
- `src/cli/index.ts`: the `plan` and `serve` actions rethrow a `CommandError`
  unchanged and turn any other error into `CommandError('Error: <message>')`.
  Neither action touches `process.exitCode`; `runCli` reports both.
- `tests/plan-command-error.test.ts` (new): direct `prepareQueueSelection`
  refusal and notice, direct `planCommand` planner exit code with the recorded
  `plan_exited`, and the `plan`/`serve` CLI paths through `runCliCaptured` for
  queue refusal, planner exit code, another plan error, and a failing serve.
- `tests/plan-telemetry.test.ts`: the non-zero exit and spawn-failure tests
  assert the thrown `CommandError` (`exitCode` 3 and 1, empty message) and that
  `process.exitCode` stays `undefined`.
- `tests/queue-budget.test.ts`: the four budget refusals capture the thrown
  `CommandError` instead of the old stderr line and `process.exitCode`.
- `tests/queue-plan.test.ts`: the rejected-without-replan refusal asserts the
  thrown `CommandError` (`/--replan/`, exit code 1).
- `tests/codex/plan.test.ts`: the generated subprocess runner imports
  `CommandError` and maps it onto the child's `process.exitCode`, so the
  existing nonzero/signal propagation assertions still measure the command's
  exit code now that `planCommand` throws it.

## Deviated

- `tests/codex/plan.test.ts` runs `planCommand` in a child process, so it
  cannot assert a rejection in-process. Its runner now catches the thrown
  `CommandError` and sets `process.exitCode` from it, which keeps the child's
  observed status and the existing assertions unchanged.
