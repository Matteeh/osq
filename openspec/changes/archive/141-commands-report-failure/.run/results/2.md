## Changed

- `src/cli/doctor.ts`: removed the injectable `exit` option from
  `DoctorCommandOptions`; when the report is not ok, `doctorCommand` now
  throws `new CommandError('', { exitCode: 1 })` after printing the same one
  line per check. A passing run still returns the report, and nothing writes
  `process.exitCode`.
- `tests/doctor-command-error.test.ts` (new): proves `DoctorCommandOptions`
  no longer accepts `exit` (compile-time `@ts-expect-error`), a passing
  injected report returns and prints one line per check, a failing injected
  report prints the same lines then rejects with an empty `CommandError` of
  exit code 1 while leaving `process.exitCode` unchanged, and through
  `runCliCaptured` `osq doctor` exits 0 on a healthy repo and 1 with the
  failing check line after `PLANNER.md` drifts.
- Converted every test that passed `exit` to `doctorCommand` or read the code
  it pushed: `tests/doctor.test.ts`, `tests/adr-checks-denies.test.ts`,
  `tests/harness-generic-workflows.test.ts`, `tests/codex/adapter.test.ts`,
  `tests/openspec-version.test.ts`, `tests/vcs-doctor.test.ts`,
  `tests/vcs-doctor-warnings.test.ts`. Success-path calls drop the option;
  the two failing-report calls (`doctor.test.ts`,
  `adr-checks-denies.test.ts`) and the failing harness workflow call now
  `assert.rejects` a `CommandError` with exit code 1.
