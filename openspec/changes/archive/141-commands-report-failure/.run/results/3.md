# Task 3 result

## Changed

- `src/cli/land.ts`: removed the `exit` option and `process.exitCode`
  assignment; the stale-build refusal and any thrown error now throw
  `CommandError(<line>)` with no stderr line of its own, and a non-zero
  `landChange` code throws `CommandError('', { exitCode: code })` after its
  lines print. A `CommandError` inside the `try` is rethrown unchanged.
- `src/cli/message.ts`: removed the `exit` option and `process.exitCode`
  assignment; a refusal now throws `CommandError(<message>)` and the command
  prints no error line of its own. The squash message on stdout and the
  `Branch:` line on stderr are unchanged.
- `tests/vcs-land-command-error.test.ts` (new): the two option types have no
  `exit`; direct `landCommand` calls reject with the refusal and stale-build
  `CommandError`s while printing nothing and leaving `process.exitCode` alone;
  direct `messageCommand` rejects with the refusal `CommandError` printing
  nothing; `osq land` and `osq message` print the same single stderr line and
  exit 1 through `runCli`.
- Converted every test that passed `exit` to `landCommand` or `messageCommand`
  (`vcs-land*`, `checkout-copy-ignored`, `steering-archived`, `squash-message`,
  `change-locations-landed`, and the `landCommand` call in
  `steering-plan-default-branch`): each capture helper now calls the command
  with no `exit`, catches the thrown `CommandError`, takes its `exitCode`, and
  renders its message to the captured stderr exactly as `runCli` would, so the
  existing byte-equality assertions stay meaningful. Land success records exit
  code 0; message success records `null`, as before.

## Deviated

- The non-zero-`landChange` branch is implemented but not exercised by the new
  test. `landChange` (`src/core/vcs/land.ts`) currently only ever returns
  `code: 0`; every refusal throws. There is no injectable seam for it, and
  adding one is the separate `command-inputs` change, so the new test covers
  the reachable land failures (stale-build and thrown error) and both runCli
  paths instead.

## Missing context

- Nothing blocking. The unreachable non-zero `landChange` return means the
  acceptance line about it can only be verified by inspection until the land
  core gains a non-zero return or a seam.
