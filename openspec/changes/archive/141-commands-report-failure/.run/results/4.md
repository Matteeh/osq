# Task 4 result

## Changed

- `src/cli/sync.ts`: removed the `exit` option from `SyncCommandOptions` and
  the `process.exitCode` assignment. A failure now throws
  `CommandError(<the line it would have printed to stderr>)` and prints
  nothing itself; the success path just returns and still prints the result
  line to stdout and the progress to stderr.
- `src/cli/graph.ts`: removed the `exit` option and the `process.exitCode`
  assignment. A failure now throws `CommandError(<the line it would have
  printed to stderr>)` and prints nothing itself; summary and `--json` output
  are unchanged.
- `src/cli/migrate.ts`: removed the `exit` option and the `process.exitCode`
  assignment. An unsupported target and a failed migration log exactly their
  old lines, then throw `new CommandError('', { exitCode: 1 })`; the success
  path still returns the migration result. Dropped `| null` from the return
  type since the two `null` returns are now throws.
- `tests/sync-graph-migrate-command-error.test.ts` (new): proves the three
  option types have no `exit`; `syncCommand` and `graphCommand` reject with the
  exact line while printing nothing and leaving `process.exitCode` alone;
  `migrateCommand` logs the unsupported target and the failed migration then
  rejects with an empty `CommandError` of exit code 1; and `osq sync`, `osq
  graph`, and `osq migrate` print the same stdout/stderr and exit 1 through
  `runCliCaptured`.
- Converted the scoped preexisting tests to the thrown `CommandError` and no
  `exit`: `tests/vcs-sync-command.test.ts`, `tests/web-graph-command.test.ts`,
  `tests/migrate.test.ts`, `tests/migrate-sidecars.test.ts`.

## Deviated

- `migrateCommand`'s declared return type lost `| null` in addition to the
  `exit` option. The two paths that returned `null` now throw, so keeping
  `null` in the type would be a lie; the proposal's non-goals already say a
  failing command throws instead of returning a result.
- `GraphCommandOptions` keeps its `stderr` property even though `graphCommand`
  no longer writes to it. The task only asked to remove `exit`, and the
  property is still accepted (tests pass it), so the programmatic surface
  changed by exactly the one option named in the task.
- The `osq migrate` runcli case in the new test captures `process.stderr.write`
  around `runCliCaptured` because the default logger writes directly to
  `process.stderr`, which `cli-capture.ts` does not intercept. The
  `runCliCaptured` call still supplies the exit-code and console assertions.
