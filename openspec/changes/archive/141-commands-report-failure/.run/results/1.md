## Changed

- `src/cli/lint.ts`: removed the injectable `exit` option from
  `LintCommandOptions`; when any linted change is invalid, `lintCommand` now
  throws `new CommandError('', { exitCode: 1 })` after printing the same
  findings, repository count, or JSON document as before. Updated the function
  doc comment. A valid run still returns `{ valid, entries }`.
- `tests/lint-command-error.test.ts` (new): direct invalid call rejects with an
  empty `CommandError` of exit code 1 and leaves `process.exitCode` unchanged;
  direct valid call returns the result; through `runCliCaptured`, an invalid
  change exits 1 with the same stderr finding and no stdout, and a valid change
  exits 0.
- Converted every test that passed `exit` to `lintCommand` or read the exit
  code it set, so each now expects the thrown `CommandError`:
  `tests/impact-lint.test.ts`, `tests/lint-findings.test.ts`,
  `tests/lint-output.test.ts`, `tests/lint-repository-count.test.ts`,
  `tests/lint-skip-rejected.test.ts`, `tests/linter.test.ts`,
  `tests/proposal-writes-schema.test.ts`, `tests/validator-missing.test.ts`,
  `tests/scope-lint.test.ts`, `tests/steering-plan.test.ts`,
  `tests/steering-plan-default-branch.test.ts`.

## Deviated

- `lintCommand` no longer returns the failed result, so two worktree-resolution
  tests (`tests/steering-plan.test.ts` and
  `tests/steering-plan-default-branch.test.ts`) now parse the JSON document
  that `lintCommand` writes to `stdout` before throwing, instead of reading
  `result.entries`. That keeps the worktree path and finding assertions. The
  invalid-folder check is now asserted on the finding message in the document
  plus the empty `CommandError`, which still proves resolution found the
  change rather than failing with a not-found error.
- `tests/validator-missing.test.ts` gathered validator error text from
  `result.entries`; it now captures `logger.error` lines and asserts the same
  ADR 004 and install-command fragments there, since the result is no longer
  returned on failure.
