## Acceptance

- [ ] `SyncCommandOptions`, `GraphCommandOptions` and `MigrateCommandOptions` have no `exit` option, and none of the three commands sets `process.exitCode`.
- [ ] `syncCommand` and `graphCommand` throw `CommandError(<message>)` where they printed `<message>\n` to stderr and exited 1. Their stdout and progress output are unchanged.
- [ ] `migrateCommand` logs its error exactly as today, then throws `new CommandError('', { exitCode: 1 })`, for an unsupported target and for a failed migration. Its success path returns its result as today.
- [ ] Through `runCli`, `osq sync`, `osq graph` and `osq migrate` print the same stdout and stderr as before this task and exit with the same code.
- [ ] New `tests/sync-graph-migrate-command-error.test.ts` covers the lines above, each failure called directly with `assert.rejects` and once through `runCli` with `tests/cli-capture.ts`.
- [ ] `vcs-sync-command`, `web-graph-command`, `migrate` and `migrate-sidecars` expect the thrown `CommandError` and pass no `exit`.
