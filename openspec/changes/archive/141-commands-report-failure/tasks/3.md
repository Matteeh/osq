## Acceptance

- [ ] `LandCommandOptions` and `MessageCommandOptions` have no `exit` option, and neither command sets `process.exitCode`.
- [ ] `landCommand` throws `CommandError(<line>)` where it printed `<line>\n` to stderr and exited 1: the stale-build refusal and any thrown error. A non-zero code from `landChange` throws `new CommandError('', { exitCode: code })` after its lines print. Progress lines and the success output are unchanged.
- [ ] `messageCommand` throws `CommandError(<message>)` where it printed the message to stderr and exited 1. The squash message on stdout and the `Branch:` line on stderr are unchanged.
- [ ] Through `runCli`, `osq land` and `osq message` print the same stdout and stderr as before this task and exit with the same code.
- [ ] New `tests/vcs-land-command-error.test.ts` covers the lines above for both commands, each failure called directly with `assert.rejects` and once through `runCli` with `tests/cli-capture.ts`.
- [ ] Every test that passed `exit` to `landCommand` or `messageCommand` now expects the thrown `CommandError`: the `vcs-land*` tests, `checkout-copy-ignored`, `steering-archived`, `squash-message`, `change-locations-landed`, and the `landCommand` calls in `steering-plan-default-branch`.

## Details

A thrown `CommandError` inside the `try` must not reach the `catch` that turns
errors into messages; rethrow it there. Task 1 already changed the
`lintCommand` calls in `steering-plan-default-branch`.
