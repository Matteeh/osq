## Changed

- Added `src/cli/plan-steer-prompt.ts`: `buildSteeringPrompt(projectRoot, config, id)`, which calls `readSteeringPlan`, returns null when it finds no change needing steering, and otherwise reads the change's `brief.md` and proposal title, builds the opening prompt through `buildOpeningPrompt` from `src/cli/plan.ts`, and appends the steering section after a blank line, returning the prompt `osq plan <id> --print` prints without its final newline. - `src/cli/watch-service.ts`: `runWatcher` now passes `steeringPrompt: buildSteeringPrompt` in the `startWatcher` options, so the terminal watcher, the background service worker and `--once` all hand the builder to the watcher. Nothing else in the file changed.
- Added `tests/steering-prompt.test.ts`: three plain `node:test` cases over a committed temp repository whose change (with `brief.md`) is approved into a linked worktree. "Nothing to steer" asserts id `042` returns null. "osq watch starts the planner" runs `watchCommand({ once: true, allowStale: true, cwd, stdout, stderr })` twice with the `vcs-worktree-recreate` `osq.config.ts` shape plus `autoSteer: { enabled: true }`, and asserts `.run/auto-steer.md` records `unchanged` and `change.jsonl` holds exactly one `auto_steer_ran` event.
