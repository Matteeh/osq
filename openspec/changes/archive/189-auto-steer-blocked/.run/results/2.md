## Changed

- Added `src/core/foundation/config-auto-steer.ts`: `DEFAULT_AUTO_STEER_TIMEOUT_SECONDS` (1800), the `AutoSteerConfig` type (`enabled: boolean`, optional `timeoutSeconds`), `validateAutoSteerConfig(raw)` (keys first, then `enabled`, then `timeoutSeconds`), and `plannerRunConfig(config)` (harness from `resolvePlannerSelection`, section `model`/`agent` from the selection where present). Both exported functions carry `@scenario cli-foundation:` lines and `@adr 018`.
- `src/core/foundation/config-limits.ts`: now owns the `LogConfig` interface.
- `src/core/foundation/config.ts`: imports and re-exports `LogConfig` through the existing `config-limits.js` import and `export type` lines, so importers of `config.js` keep working; `OsqConfig` gains `autoSteer?: AutoSteerConfig`; `defineConfig` destructures the raw `autoSteer` out of `restConfig` and adds the resolved block only when `validateAutoSteerConfig` returns one. `config.ts` is 249 lines.
- `src/core/foundation/config-user.ts`: `OsqUserConfig` takes `autoSteer?: Partial<AutoSteerConfig>`.
- Added `tests/auto-steer-config.test.ts`: plain `node:test` cases covering the "Auto steer values" table through `defineConfig` plus "Planner run config from the planner block" and "Planner run config without a planner block" through `plannerRunConfig`.

`DEFAULT_CONFIG` has no `autoSteer` key, and nothing reads `autoSteer` yet.

## Deviated

- The task suggested validating the raw block; to keep `defineConfig`'s destructuring line under the 100-column formatter width without adding a line, the raw value is destructured as `autoSteer` and the resolved value is assigned to `resolvedAutoSteer`, then spread as `{ autoSteer: resolvedAutoSteer }`. This still removes the raw key from `restConfig`, so `defineConfig({})` and an explicit `autoSteer: undefined` both leave the key absent.
