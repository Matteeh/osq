## Changed

- Added `src/core/run/auto-steer-record.ts`: `AutoSteerOutcome`, `AutoSteerRecord` (`key`, `outcome`, `changed`, `at`, optional `detail`), `autoSteerRecordPath` (`.run/auto-steer.md`), async `steeringKey` (`sha256:` over the approved hash, each `describeTrigger` text and each marker's bytes), `readAutoSteerRecord` (null for missing or malformed), `writeAutoSteerRecord` (YAML frontmatter plus body), and async `currentAutoSteer(state)` for any `{ folderPath, approvedHash, steering? }`. The outcome type lives here so `src/harness/types.ts` imports it without a core→harness edge.
- Added `src/harness/types.ts`: the `auto_steer_ran` event type and `AutoSteerRanEventData` (`outcome`, `harness`, `model`, `duration`, `exitCode`, `triggers`, `changed`, `restored`, optional `output`), wired into `HarnessEventType` and `OsqEventData`.
- Added `src/watcher/auto-steer-plan.ts`: `snapshotPlanFiles` and `diffPlanFiles`, the change-folder files outside `.run/` and their added/changed/removed diff.
- Added `src/watcher/auto-steer.ts`: `SteeringPromptBuilder`, `AutoSteerOptions` (`steeringPrompt?`, `plannerAdapter?`, `logger?`) and `runAutoSteer`, with the early guards (autoSteer off, no prompt builder, unapproved, default-branch trigger, current-key record), the `running`-record interruption rewrite, the prompt build with its thrown-error `failed` record, and the call into the execution half.
- Added `src/watcher/auto-steer-run.ts`: the seven steps — snapshot the tree and plan files, write the `running` record, spawn `planner` once with the built prompt and `plannerRunConfig`, put back everything outside the plan through `restoreTreeExcept`, diff the plan files, decide the outcome (`failed`/`timed_out`/`unchanged`/`ready`/`lint_red`), then write the record and the change-level `auto_steer_ran` event and log `spec <id> automatic planner <outcome>`.
- `src/watcher/validator-guard.ts`: added `restoreTreeExcept(projectRoot, vcs, snapshot, keep)` and made `restoreValidatorTree` call it with its own skips, so the validator's behavior is unchanged.
- `src/watcher/loop.ts`: `runWatcherCycle` and `runWatcherOnce` take an optional last `steer: AutoSteerOptions = {}`; `StartWatcherOptions` gains `steeringPrompt`; `startWatcher` passes it through; the steering branch awaits `runAutoSteer(projectRoot, change, specState, config, { ...steer, logger })` before `continue`.
- Added `tests/auto-steer-run.test.ts`: 13 `node:test` cases over a temporary git repo with one change approved into a worktree, proving every scenario of "Automatic steering run" and "Automatic steering record". "Key follows the trigger" and "Stale record" call `steeringKey`/`currentAutoSteer` directly; "Approval after a revised plan" uses `approveCommand`.

## Deviated

- The interrupted-run path in "Automatic steering record" says only to rewrite the record, spawn nothing and return `failed`. I also append one `auto_steer_ran` event for it, because step 7 records every outcome and the event is what makes the interruption visible. Nothing in the scenarios or later tasks asserts the absence of that event.
- `runAutoSteer` was split across `auto-steer.ts` (guards, key, interruption, prompt) and `auto-steer-run.ts` (steps 2–7) to stay inside the 250-line file budget; both match the task's `src/watcher/auto-steer*.ts` scope.
