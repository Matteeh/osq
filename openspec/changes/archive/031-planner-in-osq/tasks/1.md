## Acceptance
- [ ] OsqConfig and OsqUserConfig define optional planner configuration block with harness, model, and optional agent
- [ ] defineConfig validates planner.harness and planner.model as non-empty strings and planner.harness as a supported harness name
- [ ] loadConfig propagates user-configured planner block from osq.config.ts
- [ ] ManifestData interface declares planner field recording the planner model or null
- [ ] buildManifest populates manifest.planner from config.planner.model or null when omitted
- [ ] tests/config-planner.test.ts verifies valid and invalid planner configurations and manifest planner attribution

## Details

Extend `src/core/config.ts` with `PlannerConfig` declaring `harness: string`, `model: string`, and optional `agent?: string`.
Add `planner?: PlannerConfig` to `OsqConfig` and `OsqUserConfig`.
In `defineConfig`, when `planner` is provided, validate that `harness` and `model` are non-empty trimmed strings, and that `harness` is one of the supported harnesses (`agy`, `opencode`, or `mock`). If invalid, throw an error describing the failure.
In `loadConfig`, propagate `userConfig.planner` into the resolved configuration.
In `src/core/manifest.ts`, update `ManifestData` to include `planner: string | null`.
In `buildManifest`, set `planner: config.planner?.model ?? null`.
Update `tests/manifest.test.ts` to assert that `manifest.planner` is present.
Create `tests/config-planner.test.ts` asserting that `defineConfig` accepts valid planner configs, rejects missing or empty harness or model strings, rejects unknown harness names, and verifies that `buildManifest` correctly captures the planner model in `manifest.json`.
