## Changed

- Copied the TypeScript goldens, their script and the `json-records` fixture into the crate unchanged.
- Added `src/cursor.rs`: the cursor path from `watch_state_dir`'s hash, the `lastLook` read, the cursor write, and a small UTC formatter that writes `toISOString()`'s fixed form.
- `InboxFeature` now holds an optional home, gains `with_home`, reads the cursor before the groups and writes it after them; a missing home reads and writes no cursor. `run` uses the feature home for the after-land record too.
- `groups::landed::lines` filters archived changes strictly after the cursor and drops the ten-item fallback while a cursor exists.
- Updated every existing inbox test helper to run with `with_home` on a fresh empty scratch home under `CARGO_TARGET_TMPDIR`; the after-land tests write their records under that same home.
- Added `tests/inbox_cursor.rs` for "Landed after the cursor", "Cursor file after a run" and "Inbox cursor equals TypeScript's", plus a date-edge check of the cursor's ISO form.

## Deviated

- The "Landed after the cursor" future-cursor row expects `Inbox empty.` rather than a rendered `  (none)` Landed group: with no needs-you or running items either, "Inbox command" requires the whole inbox to read `Inbox empty.`. The Landed group itself holds no items, as the row says.

## Outside scope

- The proposal verify's repository link-gate corpus test fails without `OSQ_CHANGE` because the new requirement and scenario names live only in the in-flight delta. With `OSQ_CHANGE=openspec/changes/333-rust-inbox-json` the full proposal verify passes.
