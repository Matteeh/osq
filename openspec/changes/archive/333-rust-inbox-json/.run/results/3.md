## Changed

- Each inbox item is now plain data first: needs-you items carry their kind,
  change and task references, command, steering, raw blocked need, stuck
  fingerprint, validator facts and autopilot-stop facts; running items carry
  their live-lock or pause facts; landed items carry their archive time and
  optional disclosure counts. Both text lines and JSON objects render from
  that data.
- Added `src/json.rs` and `src/json/inbox.rs`: an ordered JSON tree rendered as
  `JSON.stringify(value, null, 2)` writes it, with `serde_json` used only to
  escape strings, and the `needsYou`, `running`, `landed` members in TypeScript
  order.
- `inbox` accepts `--json` in any position and any number of times, refuses
  every other argument, and lists the usage `[--json]`.
- Landed items now pass one-category disclosure cases through the same check
  as mixed cases without an untested boolean chain.
- Added `tests/inbox_json.rs` proving the four golden rows: `repo`,
  `repo-cursor`, `records --json` and `records` text, each in its own fresh
  base folder with its own empty home and cursor assertion.
- Updated `tests/inbox_command.rs` for the `[--json]` usage and the refused
  `--yaml` and `--json extra` rows.

## Deviated

None.

## Outside scope

As task 1 and 2 already noted, `sh scripts/verify-rust.sh` run without
`OSQ_CHANGE` fails the linter's link-gate corpus test because the new scenario
names live only in the in-flight delta. With
`OSQ_CHANGE=openspec/changes/333-rust-inbox-json` the full proposal verify
passes.

mutants: 299 caught, 31 unviable, 0 missed), since `OSQ_DIFF` is not set locally.
