## Details

Today each group builds its lines straight from the snapshots. Make each
item plain data first, the facts "Inbox JSON" lists, and render both the
text line and the JSON object from that data, so the two never derive a
value twice. `needs::Entry` already holds most of a needs-you item. The
stuck fingerprint is the dead marker's `fingerprint`, which task 1 added to
rust-storage `HaltMarker`; a blocked need keeps
its whitespace in JSON and collapses it only in the text line.

Write the JSON by hand: the workspace's `serde_json` sorts object keys, and
the members must come in the order "Inbox JSON" gives. Add the workspace's
`serde_json` to the crate's manifest and use it only to escape strings.

Build the `records` case as the golden script's header says and as
`tests/inbox_trees.rs` builds its worktrees, with commits by
`osq <osq@example.com>` and `osq.toml` written before the first commit. Write
the running lock with `std::process::id()` and the `after-land.json` under
the case's scratch home with rust-storage `watch_state_dir`.

Never read anything under `src/` of the repository from Rust; the
TypeScript files are in `entry` only so you can port them.
