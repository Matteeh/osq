## Acceptance

- [ ] `src/core/report/stream-reads.ts` exports the three functions in the port below, beside its current exports. `readParsedFile`, `readEventStream` and `withStreamReads` behave as today, and `tests/report-stream-reads.test.ts` passes unchanged.
- [ ] Inside a `withStreamReads` scope, calls to `readSharedFile` for one resolved absolute path with the same parser read the file once and resolve to the same value, including calls that start before the first read finishes. `readTextFile` shares one read per path among all its callers.
- [ ] `readSharedFile` rejects with the file-system error a direct `fs.readFile` would give, such as `ENOENT` or `EISDIR`, inside a scope and outside one. Inside a scope a failed read is not retried and raises no unhandled rejection. A parser that throws rejects the call. Outside a scope, every call reads from disk, and two separate scopes share nothing.
- [ ] `freezeDeep` freezes the value and every object and array inside it, and returns the same value; a primitive comes back unchanged.
- [ ] New `src/core/report/change-reads.ts` exports `readBriefData` and `readManifestObject` from the port. `readBriefData` gives the `brief.md` frontmatter data from `parseFrontmatter`, deep-frozen, or null when the brief is missing or unreadable. `readManifestObject` gives `.run/manifest.json` parsed as a JSON object, deep-frozen, or null when it is missing, unreadable, malformed, or not a plain object.
- [ ] Both read through `readSharedFile` with one module-level parser each, so inside one scope each brief and each manifest is read and parsed once for every caller.
- [ ] `tests/report-shared-reads.test.ts` covers each line above, counting reads with `mock.method` on the default export of `node:fs/promises`.

## Details

`readSharedFile` keeps its results in the same `withStreamReads` scope as
`readParsedFile`, in its own map, because `readParsedFile` caches results that
are null on failure. Read with `fs.readFile(path, 'utf8')` from the default
import of `node:fs/promises`, as the module does today, so tests can count
reads. `readTextFile` is `readSharedFile` with a module-level parser that
returns the text unchanged.

`freezeDeep` skips values that are already frozen, so shared values are not
walked twice.

No other file changes in this task; task 2 routes the readers through these
functions.
