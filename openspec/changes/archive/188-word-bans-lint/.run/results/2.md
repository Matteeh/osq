## Changed

- Added `src/core/spec/banned-word-lint.ts`: exports
  `collectBannedWordFindings({ projectRoot, folderPath, bannedWords })`. It
  reads the change's `tasks/*.md` in task order with `parseTaskMd`, checks a
  task against each ban whose paths and scope entries cover each other by
  `scopeCoversPath`, then checks every delta spec (by capability name) once any
  task file was checked. It extracts inline code spans, fenced code lines, and
  double-quoted text under a `#### Scenario:` heading in file order, dedupes
  text, flags a text when a whitespace token contains the word ignoring case
  unless the token holds `/` the ban's paths do not cover, and builds each
  warning with `makeFinding`. Carries one `@scenario spec-lint-and-approve:`
  doc line per scenario of "Banned word warning" and "Banned word warning
  text" (five total).
- `src/core/spec/impact-lint.ts`: `collectImpactFindings` appends
  `collectBannedWordFindings` with `input.config.bannedWords ?? []`. All are
  warnings, so `valid` and the exit code are unchanged.
- Added `tests/banned-word-lint.test.ts`: plain `node:test` blocks named after
  the scenarios, each table row on its own, run over temporary scaffolded
  projects through `lintChangeFolder` and (for the never-block scenario)
  `lintCommand`.
