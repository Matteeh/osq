## Changed

- Added `src/core/foundation/config-banned-words.ts`: exports the `BannedWord`
  interface (`readonly word: string; readonly paths: readonly string[]`) and
  `validateBannedWordsConfig(raw)`, which returns `[]` for `undefined`, keeps a
  valid list with `word` and every glob trimmed, and throws
  `bannedWords must be a list of { word, paths } entries` otherwise. Carries one
  `@scenario cli-foundation:` line per scenario of "Banned words configuration".
- `src/core/foundation/config.ts`: `OsqConfig` gains
  `readonly bannedWords?: readonly BannedWord[];`, `base` holds `bannedWords: []`,
  and `defineConfig` sets `bannedWords: validateBannedWordsConfig(config.bannedWords)`.
  `OsqUserConfig` was left unchanged. The `opencode` default in `base` is
  collapsed onto one line to stay under the line budget (248 newlines, within the
  250-line metric).
- Added `tests/banned-words-config.test.ts`: one `node:test` block per scenario
  of "Banned words configuration", each table row in its own block, all through
  `defineConfig`, with `DEFAULT_CONFIG` checked once.

## Outside scope

- `src/cli/lint.ts` and the lint pipeline still do not read `bannedWords`; that
  warning is task 2's, per the proposal's task split.
