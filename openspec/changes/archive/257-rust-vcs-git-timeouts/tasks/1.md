## Details

The limits are TypeScript's `run` and `runCommit` in
`src/core/vcs/git-vcs.ts`; `runCommit` serves `commitMessage` in
`git-vcs-write.ts`, `commitTree` and `fastForward` in `git-vcs-land.ts`,
and `merge` and `mergeAbort` in `git-vcs-merge.ts`.

Wait without a polling interval or a sleep in the runner, since no number
lives in code. For example, read each stream on its own thread and wait on
a channel with `recv_timeout(limit)`, then reap the process after its
streams close, or kill it and reap it when the limit passes. Do not join
the stream threads after a kill: a grandchild can keep a pipe open. The
fake git `exec`s its `sleep`, so the kill ends the process that holds the
pipes.

Write the fake git script once per test into its own folder under
`env!("CARGO_TARGET_TMPDIR")`, named after the test and row and removed
first if it is left over, since tests run in parallel; make it executable
with `std::os::unix::fs::PermissionsExt`. Measure each timed-out call with
`std::time::Instant` and assert it ends within 10 seconds, well under the
fake's 30-second sleep.

cargo-mutants runs on every line this task changes, so each branch must
change a value a row checks: each command name the limit choice tests,
the kill, the timed-out error's fields and display, and `with_timeouts`.
Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-kernel-vcs -f <file> -o "$(mktemp -d)"` on
`src/git.rs`, `src/git/run.rs` and `src/error.rs`, then
`sh scripts/verify-rust.sh` with `OSQ_CHANGE` set to
`openspec/changes/257-rust-vcs-git-timeouts`, so the link gate corpus test
sees this change's requirement.
