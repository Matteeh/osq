## Changed

- Added `osq-kernel-config.workspace = true` to `crates/kernel/vcs/Cargo.toml`; `Cargo.lock` now lists `osq-kernel-config` under `osq-kernel-vcs`.
- `GitVcs` holds a `Timeouts`, set by `Timeouts::default()` in `new` and replaced by the new public `with_timeouts(&Timeouts)`. Existing signatures are unchanged.
- `VcsError` gained `TimedOut { command, limit }`, displaying `<command> timed out after <limit>` with `Duration`'s `Debug` form and returning `None` from `source`.
- Moved the runner to new `crates/kernel/vcs/src/git/run.rs`. It spawns, writes standard input, reads both streams on their own threads, waits on a channel until the command's limit, and kills and waits for the process when the limit passes. A pure private `limit` function chooses `git_commit` for `commit`, `commit-tree` and `merge`, and `git` for every other command.
- Added `crates/kernel/vcs/tests/git_timeouts.rs`, proving `rust-vcs/default-timeouts`, `rust-vcs/commands-that-run-out-of-time` (all 13 rows) and `rust-vcs/commands-that-finish-in-time` with the specified fake git script and limits.
- Existing vcs tests, including `git_command.rs`, are unchanged and pass.
- `cargo mutants` on `src/git.rs` (45 caught, 12 unviable), `src/git/run.rs` (27 caught, 2 unviable) and `src/error.rs` (2 caught, 1 unviable) had no missed mutants.
- `OSQ_CHANGE=openspec/changes/257-rust-vcs-git-timeouts sh scripts/verify-rust.sh` passed.

## Deviated

- The two tests that write and start fake git scripts hold a static `Mutex` for their whole body. Without it, a concurrent `Command::spawn` fork could inherit another test thread's still-open write descriptor to its script, making the script's `exec` fail intermittently with `Text file busy`. Each test still writes its script in its own folder, named after the test and row, after removing a leftover folder; only the concurrent spawning is serialized.
- The `Implements: rust-vcs/git-command` tag sits on the `VcsError` enum rather than on the new variant. The linter's tag collector does not read tags on enum variants, so a variant tag would make the `live_tags_become_edges` corpus test compare two plain-text tags with one graph edge. The variant itself keeps its one-line doc.

## Outside scope

- The link-graph tag collector in `crates/kernel/linter/src/tags/collect.rs` ignores doc tags on enum variants, which is why the enum-level `Implements` tag was used. Left unchanged.
