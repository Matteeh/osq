## Details

Port `findChange` and `matchesFolder` from
`src/core/status/change-locations.ts`, `deriveSteering` and
`describeTrigger` from `src/core/status/steering.ts`, and the in-place
seal of `approveInPlace` from `src/core/spec/approve.ts` without the
digest, notices, planning observation and manifest. Storage's
`ChangeSnapshot` gives `approved`, `change_regressed` and each `TaskFile`'s
`id`, `done` and `markers` (`HaltMarker` has `reason`, `stuck` and
`verification_passed`); `change_folder_seal` gives the seal, whose
`as_str` is the marker text. Model the feature on `PlanFeature` in
`crates/features/plan/src/feature.rs`, and build errors only through
core's constructors.

A "valid change folder" in the scenarios is one task 2's validation
accepts, so these tests keep passing after task 2: the root holds
`openspec/specs/alpha/spec.md` copied from
`tests/fixtures/approve-repo/openspec/specs/alpha/spec.md`, and the change
folder holds a `proposal.md` whose frontmatter is `title: A`,
`tasks/1.md` and `specs/alpha/spec.md` holding
`## ADDED Requirements\n\n### Requirement: Alpha rests\nThe system SHALL rest alpha.\n\n#### Scenario: Alpha rests\n- **WHEN** alpha stops\n- **THEN** alpha rests\n`.
Write that helper once in `tests/support/mod.rs` and use it from every
test file with `mod support;`. Marker frontmatter is written as
`---\n<lines>\n---\n`. Each test writes its repository into its own folder
under `env!("CARGO_TARGET_TMPDIR")`, named after the test and row and
removed first if it is left over, since tests run in parallel.

Copy the fixture and the golden markers with `cp -r` and `cp`, renaming
only the two `tasks-md.txt` files; never edit them and never regenerate
them. In "Approval markers", the expected seal is
`osq_kernel_storage::change_folder_seal` of the folder read after the run.

cargo-mutants runs on every line this task adds, so each branch must
change a value a row checks: each match form of the lookup and the
listing order, the archived exclusion, each change reason, the scope
regression exception, the done suppression, each dead reason and the
stuck flag, the unapproved case, the `.run/` creation, and the id
fallback. Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-feature-approve -f <file> -o "$(mktemp -d)"` on each
new source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE` set to
`openspec/changes/250-rust-approve-feature`, so the link gate corpus test
sees this change's requirements.
