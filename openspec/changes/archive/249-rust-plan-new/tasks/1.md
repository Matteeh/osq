## Acceptance

- [ ] `crates/features/plan/Cargo.toml`, the root `Cargo.toml` and `Cargo.lock` do not change; the task uses only the crate's current dependencies and the standard library.
- [ ] `src/feature.rs`'s `PlanFeature` becomes a struct with one private field, an optional fixed time in epoch milliseconds, with `new()` and `at(now_ms)` as rust-plan "Plan feature" says, modelled on `InboxFeature` in `crates/features/inbox/src/lib.rs`; `commands` gives `queue` and `plan`, and `run` sends `plan` to `next::run_next` with the arguments checked as "Plan arguments" says, before any file is read.
- [ ] New `src/next.rs` declares the `next` submodules and holds `run_next`, the one orchestrator that reads the folders, refuses, numbers, writes `proposal.md`, `tasks.md`, `tasks/1.md` and `brief.md`, and returns the handoff; the choice and failure order (`next/select.rs`), the number (`next/number.rs`), the file texts (`next/files.rs`), the UTC date (`next/date.rs`) and the handoff (`next/handoff.rs`) are pure functions over plain values.
- [ ] `src/queue.rs` and `src/queue/*.rs` change only to let `run_next` reuse the queue's parse, associations, states and unmet slugs, including the folders whose brief names an item no longer queued, which the failure check reads; `queue`'s output and errors do not change.
- [ ] `tests/plan_feature.rs`, `tests/queue_items.rs`, `tests/queue_states.rs`, `tests/queue_golden.rs` and `tests/queue_corpus.rs` change only `PlanFeature` to `PlanFeature::new()`, plus, in `tests/plan_feature.rs`, the commands assertion and the unknown-command row, as the modified "Plan feature commands" and "Queue argument errors" say.
- [ ] New `tests/plan_next.rs` proves "Plan argument errors", "Refused next items" and "Chosen next items"; new `tests/plan_folder.rs` proves "Next change numbers", "Seeded proposal lines", "Brief dates", "Brief date from the system clock" and "Handoff text", each on repositories it writes under `CARGO_TARGET_TMPDIR`, one assertion per row that names the row.
- [ ] Each function that implements a requirement of this task, public or not, ends its doc with one `Implements: rust-plan/<requirement>` line per requirement it serves, such as `Implements: rust-plan/next-queue-item`; private items get a one-line doc, and each test's one-line doc names `Covers: rust-plan/<scenario>` in kebab-case, such as `Covers: rust-plan/refused-next-items`.

## Details

Port `prepareQueuePlan` and `findActiveQueueFailures` from
`src/core/status/queue-planning.ts` and `queue-state.ts` without the budget,
`nextChangeNumber`'s checkout scan from `change-number.ts`,
`createNewSpec`'s seeding from `new.ts`, `formatBriefContent` and
`createQueueChange` from `src/cli/plan-queue.ts`, and `formatPlanHandoff`
from `plan-handoff.ts`. Copy the texts of `FALLBACK_PROPOSAL_MD`,
`FALLBACK_TASK_1_MD` and the tasks template into Rust constants; Rust never
reads `src/` or `templates/`. Task 2's golden test checks them byte for
byte, so keep `` \` `` in the proposal as a plain backtick.

The failure check runs before the queue file is read: a repository with
no `openspec/queue.md` and an active failure gives the failure message.
Read failures from `ChangeSnapshot::change_regressed` and each `TaskFile`'s
`markers.regressed`, `done` and `markers.dead`, in that precedence, as the
requirement says. A change id is the folder's leading digits, or its whole
name, as `links.rs`'s `change_id` gives it.

The brief's date comes from the fixed time, or else from the system clock
read in `run`, never inside a pure function; convert epoch milliseconds to
a civil UTC date by hand, since the crate has no date dependency. Leave the
`.run/` folder unwritten, and write no `plan-prompt.md`: task 2 adds it, so
no test of this task may check that it is absent or that the folder holds
exactly four files.

Each test writes its repository into its own folder under
`env!("CARGO_TARGET_TMPDIR")`, named after the test and row and removed
first if it is left over, since tests run in parallel. Build errors only
through core's constructors and match `FeatureError` with a wildcard arm,
as `tests/plan_feature.rs` does. "Brief date from the system clock" reads
`SystemTime` in the test before and after the run, as
`crates/features/inbox/tests/running.rs` does.

cargo-mutants runs on every line this task adds, so each branch must change
a value a row checks: each argument check, each refusal and its order, the
`(waiting on …)` suffix, the replan check, each failure precedence and the
empty-reason fallback, the id and target order, each folder the number
scans and the padding, the `fixes:` line's presence, every date boundary,
and the `.claude/commands/osq-plan.md` file check. Before exiting, run
`cargo fmt --all`, then `cargo mutants -p osq-feature-plan -f <file> -o "$(mktemp -d)"`
on each source file this task changes, then `sh scripts/verify-rust.sh`
with `OSQ_CHANGE` set to `openspec/changes/249-rust-plan-new`, so the link
gate corpus test sees this change's requirements.
