## Changed
- `crates/features/run/Cargo.toml` now depends on `osq-kernel-specs.workspace = true`.
- `crates/features/run/src/lib.rs` exports `PriorAttempt` and `executor_prompt`.
- `crates/features/run/src/prompt.rs` orchestrates the prompt: task and proposal reads through the specs kernel, delta and living spec lists, capability rules, prior context and the fixed prompt lines.
- `crates/features/run/src/prompt/lines.rs` holds the fixed opening line, seven executor steps and exit lines copied from TypeScript.
- `crates/features/run/src/prompt/statements.rs` holds the pure requirement parser and the prior output bound, including JavaScript `\s` handling.
- `crates/features/run/tests/executor_prompt.rs` proves all seven `rust-run` scenarios: the five golden prompts, missing task file, spec lists, capability rules, requirement statements, prior context and output bounds.
- `crates/features/run/tests/fixtures/prompt-project/` and `prompt-golden/` are byte-for-byte copies of the change fixture and the five golden files.
- `Cargo.lock` gained `osq-kernel-specs` in `osq-feature-run`'s dependency list, as cargo rewrites it for the manifest.

## Deviated
- `Cargo.lock` is outside the task's `scope`, but the acceptance says the lock file follows the manifest and cargo rewrites it on every verify; the watcher's lock-follows-manifest rule covers it. The change is only the one `osq-kernel-specs` entry.
- The test file adds a `requirement_blocks` test beside the table rows so a parser that skips a requirement directly followed by another is caught; it covers the same `rust-run/requirement-statements` scenario.
