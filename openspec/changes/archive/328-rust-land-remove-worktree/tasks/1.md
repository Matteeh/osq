## Details

Compute the worktree path as the approve crate's `worktree` in
`worktree/path.rs` does, from `stacked_root`'s parent, with the checkout's
repository root from `project_git_root`. Copy that small function into the
land crate; do not depend on the approve crate (ADR 022).

Fold the cleanup's failure into the output the way `after::finish` and
`after::retry` already fold an after-land failure: the message is every
line, joined by newlines, without the last newline.

The tests build their own repositories with the support module's public
helpers, with no change to `tests/support/mod.rs`:
- Write `osq.toml` with `worktreeRoot = "<scratch>/wt"` under `[vcs]`.
- Commit the ignore rules on `main`.
- Add the worktree with `git worktree add -q -b osq/001-alpha-orders <path> main` through `LandRepo::git`.
- Copy the fixture change into its archive as `add_fixture_change` does, then `commit_all`.

Name each row's scratch after the test and the row.

The failing-removal row removes the write permission of
`node_modules/locked` with `std::os::unix::fs::PermissionsExt`, and must put
it back before the test ends, so the next run can delete its scratch.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/328-rust-land-remove-worktree`, so the link
gates see this change's new requirement.
