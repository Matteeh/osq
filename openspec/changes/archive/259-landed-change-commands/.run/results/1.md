## Changed

Added `src/core/lifecycle/retry-archived.ts` with the archived-aware lookup and the land-retry commit. The lookup keeps `findChange`'s active match and error, falls back to the first archived change in an osq worktree, and refuses a numeric target with `<folder> has archived; osq retry clears only its land stop: osq retry <id> change`. The commit runs through the worktree's `selectVcs`, commits the retained marker, the removed `change.md` and `change.jsonl` as `osq: <id> land retry`, and restores the files from `HEAD` after a failed commit.

`src/core/lifecycle/retry.ts` now calls that lookup in place of `findChange` and stays inside the 250-line source budget. `src/cli/retry.ts` runs the archived commit after `retrySpec` and before printing.

Added `tests/retry-archived.test.ts`, which builds the `sync_verify_red` stop through `createRecoveryProject`, `commitMain` and the project's `land` and `retry`, then proves both new scenarios.

## Deviated

The commit's failure put-back reads each path's earlier bytes at `HEAD` because the retry transition has already moved `change.md` and appended the retry event before the commit runs. A land stop is committed on the branch, so `HEAD` is the state the put-back restores.

Touched: src/core/lifecycle/retry.ts, src/core/lifecycle/retry-archived.ts, src/cli/retry.ts, tests/retry-archived.test.ts
