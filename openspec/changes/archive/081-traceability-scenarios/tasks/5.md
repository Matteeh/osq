## Details

The seven test-caught breaks, from the vision's "What catches what" table:

| Break | Message |
|---|---|
| delete the `then` for "the total is 1620.00" | `No assertion for: the total is 1620.00` |
| add the table row `\| 1000 \| 7.00 \|` | `THEN the unit price follows this table: failed at quantity 1000, unit price 7.00` |
| change "the total is 1620.00" to "the total is 1600.00" in the spec | `"the total is 1620.00" is not a THEN of this scenario` |
| call `quote(200, 'SAVE10')` directly instead of `run(200, 'SAVE10')` | `THEN the subtotal is 1800.00: checked before quote ran` |
| change `>= 100` to `> 100` in `quote` | `THEN the unit price follows this table: failed at quantity 100, unit price 9.00` |
| check the table with `then` and a single row | `THEN the unit price follows this table: has a table, so check it with each` |
| rename the second scenario "Volume discount tiers" | `The pricing spec has two scenarios named "Volume discount tiers"` |

The eighth break belongs to lint in task 7, which copies this fixture.

The fixture's `quote.ts` doc comment carries
`@scenario pricing: Volume discount tiers`,
`@scenario pricing: A percentage code comes off the tiered subtotal`, and
`@adr 001`. The ADR has `status: accepted`, `applies_to: [pricing]`, and the
rule `Every amount is an integer number of cents, and a quote rounds once, half up.`
Write the test with `cents` as in the vision. `fixture/` is outside typecheck
and biome, so its imports stay as a consumer writes them. Resolve tsx for the
child with `import.meta.resolve('tsx')`, because the temporary folder has no
`node_modules`. Write the property check with a seeded loop, since fast-check
isn't a dependency.

The watcher sets `OSQ_CHANGE` for osq's own verify runs, so every child process
these tests start must delete or set it explicitly. `src/testing/` may import
only `node:` built-ins and osq's own relative modules. New functions stay
within 80 lines and new files within 250.
