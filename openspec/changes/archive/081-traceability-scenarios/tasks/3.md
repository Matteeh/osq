## Acceptance

- [ ] `runVerificationCommand` takes a required fourth argument `changeFolder: string | null` and sets or removes `OSQ_CHANGE` in the spawned environment, as the watcher-and-harness delta's "Change folder in verify environment" says.
- [ ] `runVerificationGateResult` passes `context.specFolderPath`, or null without a context. `retrySpec` passes the change folder it recertifies, and `runCheck` passes null.
- [ ] New `tests/osq-change-env.test.ts` covers both scenarios of the requirement. It runs a real task through `runTask` with a fake adapter whose verify prints `OSQ_CHANGE`, and reads the `verify_ran` event.
- [ ] The same test shows the change-level verify through the watcher cycle printing the change folder, and `runCheck` printing nothing for `OSQ_CHANGE` while the test process has it set.

## Details

Every watcher gate already hands `runVerificationGateResult` a context holding
`specFolderPath`, so `runner.ts`, `task-verify.ts`, `change-verify.ts`,
`archive-verify.ts`, and `regression.ts` need no change. The runner is 199
lines and `tests/import-graph.test.ts` keeps it under 200. Pass the absolute
folder path. `tests/verify-path-missing.test.ts` shows a fake adapter and a run
through the watcher cycle, and `tests/verification-record.test.ts` shows
`runCheck`. Restore `process.env.OSQ_CHANGE` after the test. A trial of the
required argument broke no test and no typecheck. `retrySpec` is grandfathered
in the function budget, so add only the argument.
