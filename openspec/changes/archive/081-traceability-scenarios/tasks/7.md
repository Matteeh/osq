## Acceptance

- [ ] New `src/core/spec/traceability-lint.ts` exports one entry that returns the findings of the spec-lint-and-approve delta's "Planned scenarios", "Traceability links", "Unreadable traceability forms", and "Scenario blast radius". It builds the scenario index once from the import graph it is given.
- [ ] `lintChangeFolder` calls it once, right after the impact findings, passing the task projections it already builds, each task's file path and resolved scope entries, the proposal path, and the import graph. It adds each finding with `addOwn`.
- [ ] The link rules live in new `traceability-links.ts` and the blast radius in new `scenario-impact.ts`. Severity comes from `config.traceability.mode`, the ADR reads from `readDecisions` and `sameAdrNumber`, and ownership from `readCapabilityOwnership` and `ownerCapabilities`.
- [ ] New `tests/trace-lint.test.ts` covers every scenario of "Planned scenarios", "Traceability links", and "Unreadable traceability forms" on temporary projects through `lintChangeFolder`. Each link message is asserted once, for a missing scenario, a missing and an out-of-scope ADR, an `@adr`-only function checked against its Code ownership, duplicate names, and an unreadable tag.
- [ ] The same test copies `fixture/trace/pricing/` and adds a change whose task scopes `src/pricing/quote.ts` and the test. It opts pricing in and asserts no traceability finding. Then it makes the table test cover a new exported `tierPrice` and asserts `quote: no test for "Volume discount tiers" covers it`.
- [ ] New `tests/trace-impact-lint.test.ts` covers both scenarios of "Scenario blast radius", a REMOVED requirement, the listing for a capability that isn't opted in, the `require` error for an opted-in one, and a repository with no scenario test file producing no finding.
- [ ] Both tests assert that the traceability entry returns no finding for a project with nothing opted in and no scenario test file, and that such a project's `lintChangeFolder` findings equal those it gets with `traceability` left out of the config.

## Details

`linter.ts` is on the line-budget allow list and `lintChangeFolder` is
grandfathered, so add only the call. `resolvedTaskScopes` already holds each
task's number, path, existing paths, and parsed task. Resolve each task's scope
with `resolveScope` to include paths that don't exist yet. The CLI builds the
import graph once per lint run and passes it through `LintOptions`, so the
index reuses that graph. Read `## Scenarios` from the task file text in the new
module. Leave `parser.ts` alone.

Build projects as `tests/impact-lint.test.ts` does, with `installFakeValidator`
and `scaffoldProject`, and pass a config with `traceability` set. The pricing
fixture belongs to task 5, so copy it and never edit it. Its test file imports
`@matteeh/osq/testing`, which is exactly what marks it as a scenario test file.
Lint never runs it. New functions stay within 80 lines and new files within 250.
