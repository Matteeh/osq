## Acceptance

- [ ] New `src/core/trace/scenario-lookup.ts` implements the traceability delta's "Effective scenario lookup". It takes the capability, the name, the working directory, and an environment record, and returns the scenario's `outcomes` or throws an `Error` with the exact message.
- [ ] It also exports a function that returns every scenario of one capability's effective spec for an explicit openspec root and change folder, for lint.
- [ ] It reads specs synchronously with `node:fs` and parses them only with `parseDelta`, `mergeDelta`, and `parseCapabilitySpec` from `delta.ts`. It lists active changes with `isActiveChangeFolderName`.
- [ ] Parsed specs are cached per process, keyed by openspec root, `OSQ_CHANGE`, and capability.
- [ ] New `tests/trace-scenario-lookup.test.ts` covers all five scenarios on temporary projects. It also covers duplicate names in the living spec, a duplicate that only the change's delta introduces, a missing capability, a working directory nested below the project root, and two lookups that read the spec file once.

## Details

`src/testing/` imports this module in task 5, and it runs in a consumer's
test process, so it may import only `node:` built-ins and osq's own relative
modules. `delta.ts` imports nothing, and `layout.ts` imports only `node:path`.
Pass the environment in explicitly and never read `process.env` here, because
the watcher sets `OSQ_CHANGE` for osq's own verify runs. Expose a way for the
test to clear or count cache reads. A spy on a function the module exports is
enough. New functions stay within 80 lines and new files within 250.
