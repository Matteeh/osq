## Acceptance

- [ ] New `src/core/trace/tag-scan.ts` scans one file's text as the traceability delta's "Traceability tags" and "Scenario calls" say. It returns exported functions with their tags, scenario calls, and unreadable forms, each with a 1-based line.
- [ ] New `src/core/trace/scenario-index.ts` builds the "Scenario index" from a project root and an `ImportGraph`, reading each of `graph.files` once. It exports a lookup of the tests naming a scenario, and a `covers` check that uses `graph.importsOf`.
- [ ] New `tests/trace-scan.test.ts` covers every scenario of the three requirements. It also covers each documented declaration form, several tags on one function, a tag in a `//` comment, a blank line between the comment and the declaration, `@adr` without digits, a call spanning three lines, double quotes, a template literal name, `covers` bound to a member expression, and an aliased `scenario` import.
- [ ] The same test builds an index over a temporary copy of the pricing sample files it writes itself, and asserts that the test covers `quote` and that no unreadable form is recorded.

## Details

Read with regular expressions over lines. No TypeScript parser, which would
be a fifth runtime dependency. The vision's regex checker read 56,000 lines in
67 ms. Build the graph in the test with `buildImportGraph`. The index persists
nothing. A tag-like line is any comment line (trimmed, starting with `*`, `//`,
or `/*`) that holds `@scenario` or `@adr`. New functions stay within 80 lines
and new files within 250.
