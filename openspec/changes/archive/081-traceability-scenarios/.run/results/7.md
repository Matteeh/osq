## Changed

- Added `src/core/spec/traceability-lint.ts` (238 lines). `collectTraceabilityFindings`
  builds the scenario index once from the passed import graph, reads the opted-in
  set, the change's delta scenarios, the effective spec, each task's planned
  scenarios, the ADRs, and the capability ownerships, then returns the link,
  unreadable, and blast-radius findings in one call. When no capability is opted
  in it skips every link and unreadable finding; the blast radius still runs for
  every delta capability. Exports `TraceabilityTask`/`TraceabilityInput`.
- Added `src/core/spec/traceability-links.ts` (227 lines). Holds the link rules:
  duplicate effective scenario names, added or differing MODIFIED scenarios no
  scoped test names, `@scenario` tags naming missing scenarios, tagged functions
  no covering test reaches, and `@adr` tags that are missing, unaccepted, or out
  of scope by the capabilities the function serves (tag capabilities, else Code
  ownership). Planned scenarios count as tested and as covering the functions
  tagged with them in the planning task's scope until a scoped test names them.
  Also exports `scenarioKey`, `traceabilitySeverity`, and
  `plannedCoversFunction`.
- Added `src/core/spec/scenario-impact.ts` (197 lines). Reads each delta
  capability's added, differing modified, and removed scenarios (plus the living
  spec's scenarios for REMOVED requirements) and produces the blast radius:
  the listing warning/error and the `tests.modify` warning for each test naming
  an altered scenario that no task scopes for modification.
- `src/core/spec/linter.ts`: added `resolvedPaths` to `ResolvedTaskScope`
  (populated from the `resolveScope` projection already computed, so it includes
  paths that don't exist yet), imported `collectTraceabilityFindings`, and called
  it once right after `collectImpactFindings`, passing the task projections, the
  proposal path, and the shared import graph, adding each finding with `addOwn`.
- Added `tests/trace-lint.test.ts` and `tests/trace-impact-lint.test.ts` (20
  tests together) covering every scenario of "Planned scenarios", "Traceability
  links", "Unreadable traceability forms", and "Scenario blast radius", plus the
  pricing fixture copy, the not-opted-in and nothing-opted-in comparisons, and
  the direct entry assertions.

## Deviated

- The acceptance says the link rules live in `traceability-links.ts` and the
  blast radius in `scenario-impact.ts`. The 250-line file budget left no room for
  all of the delta/living reading in the entry, so `scenario-impact.ts` also
  hosts the change reading (`readDeltaCapabilities`, `readCapabilityChanges`,
  `blastScenarios`, `specDirectories`) and the entry hosts the `## Scenarios`
  reading. Behavior matches the acceptance; only helper placement moved.
- "A scenario test covering the function names" is implemented as the
  intersection of `index.coveringTests(fn.file, fn.name)` and
  `index.testsNaming(tag.capability, tag.name)`, because the index exposes
  function coverage and scenario naming separately and the tag needs both.
- `resolvedTaskScopes` did not already hold each task's full resolved scope, only
  its existing files. I added `resolvedPaths` from the same `resolveScope` result
  rather than resolving twice, which also gives the planned-scenario rule the
  not-yet-written test paths it needs.
