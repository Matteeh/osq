## Changed

- `src/core/run/verification.ts`: `runVerificationCommand` now takes a required
  fourth argument `changeFolder: string | null`. It builds a child environment
  from `process.env` and sets `OSQ_CHANGE` to the folder, or removes the key
  when null, then passes it to `spawn`.
- `src/watcher/verify.ts`: `runVerificationGateResult` forwards
  `context?.specFolderPath ?? null` to `runVerificationCommand`, so every
  watcher gate (task pre-spawn and post-exit, change-level, archive-time, and
  scope-regression audit) now hands its change folder through the context it
  already received.
- `src/core/lifecycle/verification-record.ts`: `runCheck` passes `null`, so an
  archived change's `check` command runs with `OSQ_CHANGE` removed.
- `src/core/lifecycle/retry.ts`: `retrySpec` passes `folderPath`, the change
  folder it recertifies.
- `tests/osq-change-env.test.ts` (new): three tests. One runs a real task
  through `runTask` with a file-writing adapter whose task verify prints
  `OSQ_CHANGE` and asserts the post-spawn `verify_ran` output is the absolute
  change folder. One runs the proposal verify through `runWatcherOnce` and
  asserts every change-level `verify_ran` output is the change folder. One sets
  `process.env.OSQ_CHANGE`, runs `runCheck` on an archived change, and asserts
  the recorded output is empty, restoring the variable afterwards.

## Deviated

- `tests/runner-synthesized-result.test.ts` enforces `src/watcher/verify.ts`
  under 200 split-lines; the new call took it to 204. I collapsed the
  `runVerificationGateResult` doc comment from five lines to one (its intent is
  unchanged and the file's only budget concern is line count). No test changed.
- Biome's `noDelete` rule rejects the `delete` operator, so both removals of
  `OSQ_CHANGE` use `Reflect.deleteProperty` on the child-environment copy.
