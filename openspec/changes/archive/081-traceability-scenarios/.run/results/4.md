## Changed

- Added `src/core/trace/scenario-lookup.ts` (247 lines). `lookupScenario(capability, name, cwd, env)` returns the scenario's `outcomes` or throws one exact message: a merge refusal, `The <capability> spec has two scenarios named "<name>"` (first repeat in document order), `The <capability> spec has no scenario "<name>"`, or `The <capability> scenario "<name>" differs between <place> and <place>; set OSQ_CHANGE to the change folder the test should prove`. With `OSQ_CHANGE` it derives the openspec root from `<root>/changes/<id>` and merges the living spec with that change's delta via `mergeDelta`; without it, it walks up from the working directory to the nearest ancestor holding `openspec/specs` and treats the living spec plus each active change's ADDED/MODIFIED requirements as places in folder order. `effectiveScenarios(openspecRoot, changeFolder, capability)` returns every scenario of one capability's effective spec for lint. Reads use `node:fs` synchronously, parsing uses only `parseDelta`, `mergeDelta`, and `parseCapabilitySpec`, and active changes are listed with `isActiveChangeFolderName`. Parsed places are cached per process by openspec root, change folder, and capability; `clearScenarioLookupCache` and `scenarioSpecReadCount` expose the cache and read counter. The module imports only `node:` built-ins and osq relative modules.
- Added `tests/trace-scenario-lookup.test.ts` (296 lines) on temporary projects: all five "Effective scenario lookup" scenarios (delta-only add, modified outcome, removed, disagreeing places, active-change add), the `effectiveScenarios` export, a refused delta merge, duplicate names in the living spec, a duplicate only the delta introduces, a missing capability, a working directory nested below the project root, and two lookups reading the spec file once.

## Deviated

- The task hinted a spy on an exported function would let the test count cache reads. Because the module is ESM and its imports are immutable, I exposed `clearScenarioLookupCache()` and `scenarioSpecReadCount()` instead; the caching test clears the cache, runs two lookups, and asserts one read. Same coverage, explicit API.

## Missing context

- "The places that define a scenario" was ambiguous between a delta file and each ADDED/MODIFIED requirement. I made each requirement a place, so a duplicate inside one delta requirement still fails as a duplicate, while two requirements that disagree fail as places differing.
