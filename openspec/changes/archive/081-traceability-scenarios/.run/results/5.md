## Changed

- Added `src/testing/scenario.ts` (213 lines). `scenario(capability, name, { covers }, body)` registers one `node:test` test titled `Scenario: <name>`, looks the scenario up with `lookupScenario(capability, name, process.cwd(), process.env)`, and calls `body` with `run`, `then`, and `each`. `run` counts each call as started and as settled when it returns a non-promise or its promise settles. `then` and `each` validate the outcome by exact text, run the check, and only assert the outcome when a call has settled; `each` walks the table rows in header order and awaits each row's check before the next. Final checks run `never ran` first, then `No assertion for:` in spec order. Every failure message matches "Scenario helper failures": lookup errors unchanged, `"<text>" is not a THEN of this scenario`, `THEN <text>: has a table, so check it with each`, `THEN <text>: has no table`, `THEN <text>: failed` (with cause), `THEN <text>: failed at <column> <value>, ...` (with cause), `THEN <text>: checked before <fn> ran`, `THEN <text>: checked before <fn> settled`. `scenario` is generic over the covered function, so `run` takes its parameters and returns its return type, and `each` rows are `Record<string, string>`.

## Deviated

- The child processes these tests spawn must drop `NODE_TEST_CONTEXT` as well as `OSQ_CHANGE`. When the outer `node --test` run starts a child with `node --test`, the inherited `NODE_TEST_CONTEXT` makes the child refuse to run any file and exit 0, so the break tests silently passed; deleting it is required for the child to actually execute. `OSQ_CHANGE` is still deleted or set exactly as the acceptance says.
- The `@ts-expect-error` probe uses a locally declared numeric `quote` rather than the fixture's, because importing the fixture's scenario test would pull `@matteeh/osq/testing` into `typecheck:cli`, which runs before `dist/` exists. The probe still proves the exported generic parameterizes `run` by the covered function.
