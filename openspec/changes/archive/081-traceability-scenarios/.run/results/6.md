## Changed

- Added `src/core/trace/tag-scan.ts` (250 lines). `scanSource(file, text)` returns `{ scenarioTestFile, functions, calls, unreadable }`, every entry with its 1-based line. It reads tags only from a `/** ... */` doc comment whose closing line is directly above `export function`, `export async function`, or one of the `export const` arrow/function-expression forms (with an optional annotation). A tag-like comment line holding `@scenario` or `@adr` that cannot attach, a malformed `@scenario`, and an `@adr` without digits become unreadable. Untagged exported functions are recorded too. A file whose import names `@matteeh/osq/testing` is a scenario test file; its `scenario(` calls are read when capability and name are unescaped quoted literals and the third argument is `{ covers: <identifier> }`, across lines, with double quotes. Other calls and an aliased `scenario` import become unreadable.
- Added `src/core/trace/scenario-index.ts` (121 lines). `buildScenarioIndex(projectRoot, graph)` reads each of `graph.files` once, aggregates the scans, and exposes `files`, `scenarioTestFiles`, `functions`, `calls`, `unreadable`, `testsNaming(capability, name)`, `scenariosInFile(file)`, `coveringTests(functionFile, name)`, and `covers(testFile, functionFile, name)`, which checks `graph.importsOf`. Nothing persists.
- Added `tests/trace-scan.test.ts` (471 lines, 22 tests). Covers every documented declaration form, several tags on one function, an untagged function, a `//` comment tag, a blank line before the declaration, `@adr` without digits, a nameless `@scenario`, the three named scenarios ("Tagged arrow const", "Tag above an unread form", "Non-literal name", "Test covers the tagged function"), a three-line call, double quotes, a template literal name, a member-expression `covers`, a non-literal capability, an aliased import, a file without the helper, a non-direct import, and a differently named function. It writes its own pricing sample and asserts the test covers `quote` with no unreadable form.

## Deviated

- To stay under the 250-line file budget I read `scenario(` with one regex per call shape plus a reason helper, rather than the per-argument scanner the first draft used. Behavior is the same and the tests pin every listed case.
- `UnreadableForm` carries an optional `capability` for an unreadable call whose first argument was a literal, so task 7 can skip a call naming a capability that isn't opted in. Not required by this task's acceptance lines but the "Unreadable traceability forms" requirement needs it.
