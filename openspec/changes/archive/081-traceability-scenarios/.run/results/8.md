## Changed

- Added `src/core/report/report-traceability.ts` (147 lines). `collectTraceabilityGaps(projectRoot, config)` returns, in capability name order, one `{ capability, untestedScenarios, unclaimedFunctions }` per opted-in capability that has a living spec. Untested scenarios are the living spec's scenario names, in spec order, that no scenario test file in the repository names. Unclaimed functions are the scenario index's exported functions in files outside scenario test files and test paths that the capability's Code ownership covers and that carry no `@scenario` tag, sorted by file then line. It builds the import graph once with `buildImportGraph`, skipping `config.paths.openspecRoot`, and persists nothing. It returns `undefined` when no capability is opted in. `formatTraceability` renders the `Traceability:` section body.
- `src/core/report/report.ts`: added optional `traceability` to `MetricsReport`, collected it in `getMetricsReport`, spread it into the report only when present, and printed the section from `formatMetricsReport` only when present (after History, before Coverage).
- `src/cli/report.ts`: `toStableMetrics` copies `traceability` only when present, projecting `{ capability, untestedScenarios, unclaimedFunctions: [{ file, name }] }`.
- `src/core/status/show.ts`: added optional `scenarios` to `TaskDetail`, `attachTaskScenarios` (resolves each task's scope, builds the import graph only when some scope holds a test path, then attaches distinct pairs sorted by capability and name), the small `formatTaskScenarios` beside `formatDependenciesAdded`, and the `Scenarios:` line printed right after `Dependencies added:`.
- Added `tests/trace-report.test.ts` (4 tests) covering both scenarios of "Traceability gaps in report" and "Scenarios in show" through `getMetricsReport`, the report command's JSON and text output, and `getSpecDetailsFromFolder` with `formatSpecDetails`, plus the nothing-opted-in absence of the JSON key and text section.
