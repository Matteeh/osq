## Changed

- Added `src/core/foundation/config-traceability.ts` exporting
  `TraceabilityMode`, `TraceabilityConfig`, `DEFAULT_TRACEABILITY_CONFIG`
  (`{ capabilities: [], mode: 'warn' }`), and `validateTraceabilityConfig`,
  modeled on `validateGatesConfig`. A missing block returns the default, a
  partial block keeps each missing default, a non-object is rejected, and a bad
  `capabilities` or `mode` throws the two exact messages.
- `src/core/foundation/config.ts`: imported the module, re-exported
  `TraceabilityConfig`, added `traceability?: TraceabilityConfig` to `OsqConfig`,
  added `traceability: DEFAULT_TRACEABILITY_CONFIG` to `DEFAULT_CONFIG`, and set
  `traceability: validateTraceabilityConfig(config.traceability)` in
  `defineConfig` so the resolved config always holds it. File is 248 lines.
- `src/core/foundation/config-user.ts`: re-declared `traceability` as
  `Partial<TraceabilityConfig>` and excluded it from the `Partial<Omit<...>>`
  mapping so callers only spell the fields they set.
- Added `tests/traceability-config.test.ts` covering both delta scenarios, the
  default, `'all'`, a list, a partial block, invalid `capabilities`, invalid
  `mode`, and loading `traceability` from a temporary `osq.config.ts` through
  `loadConfig`.
