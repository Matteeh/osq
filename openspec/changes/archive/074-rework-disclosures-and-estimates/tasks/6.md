## Acceptance

- [ ] New `src/core/report/record-rework.ts` maps each change id to the sorted ids of active and archived changes, never rejected ones, whose `SpecData.fixes` name it. `history.rework` lists `{ change, fixedBy }` by change id, and text prints a `Rework:` section with `  <id>: fixed by <ids>` lines or `  (none)`.
- [ ] `collectApprovalFlagOutcomes` takes that map; a change also counts as troubled when the map lists it. `approvalFlags.troubledChanges` lists `{ change, flags, kinds }` for each troubled change with at least one flag, kinds ordered `dead`, `regressed`, `rework`, and text prints `  <id> (<flags>): <kinds>` lines after the per-flag lines, naming the fixing ids for rework.
- [ ] New `src/core/report/record-disclosures.ts` builds `history.disclosures` from `countChangeDisclosures` for active and archived changes with a non-zero count, by change id, and text prints an `Executor disclosures:` section with `  <id>: deviated <n>, missing context <n>, outside scope <n>` lines or `  (none)`.
- [ ] New `src/core/report/record-estimates.ts` sorts each valid session's recorded cost into `harness` or `approvalPrice` by its slice `costSource`, and estimates a session with slice input and output tokens and no cost by calling `resolveSliceCost` with one turn carrying the slice tokens and the `plan_started` model when `config.planning.prices` has that model. `planning.cost.bySource` holds `{ total, sessions }` for `harness`, `approvalPrice`, and `reportEstimate`, plus `totalWithEstimates`; the existing `planning.cost` fields keep their values.
- [ ] Text prints each source on a labelled line, `Estimated from planning.prices` for report estimates, and a `Planning cost with estimates: <total> (<estimated> estimated)` line. `toStableMetrics` emits every new field.
- [ ] New `tests/report-record-extras.test.ts` covers rework and a rejected fixer, rework as flag trouble, disclosure counts, an estimate equal to `resolveSliceCost` over the same single turn, an unpriced model left unestimated, and the text lines, through `getMetricsReport`, `formatMetricsReport`, and `reportCommand` with `json: true`.
- [ ] `fixture/report/expected.json` is regenerated from `reportCommand` with `json: true` and differs only by the new fields; `tests/report-json.test.ts` changes only its expected key lists.
