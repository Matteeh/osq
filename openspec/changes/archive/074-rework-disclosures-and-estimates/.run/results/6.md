## Changed

- Added `src/core/report/record-rework.ts`: `changeIdOfFolder`, `collectRework(folders)` reads each active/archived change's `fixes` through `parseSpecMdFromFolder` (rejected folders are never read) and returns `{ change, fixedBy }` ordered by change id with sorted fixer ids; `formatRework` emits the `Rework:` section with `  <id>: fixed by <ids>` lines or `  (none)`.
- Added `src/core/report/record-disclosures.ts`: `collectDisclosures(folders)` maps `countChangeDisclosures` to changes with a non-zero count, by change id; `formatDisclosures` emits `Executor disclosures:` with `  <id>: deviated <n>, missing context <n>, outside scope <n>` lines or `  (none)`.
- Added `src/core/report/record-estimates.ts`: `collectCostBySource(folders, prices)` splits every valid session's recorded `usage.cost` into `harness` or `approvalPrice` (slice `costSource: "price_table"`) and estimates a no-cost session whose slice holds input and output tokens by calling `resolveSliceCost` with one turn built from the slice tokens and the `plan_started` model; `formatPlanningCostBySource` prints a labelled line per source, `Estimated from planning.prices` for report estimates, and `Planning cost with estimates: <total> (<estimated> estimated)`.
- `src/core/report/approval-flags.ts`: `collectApprovalFlagOutcomes(folders, rework)` now derives trouble kinds in the fixed `dead`, `regressed`, `rework` order, counts rework as later trouble, and lists `troubledChanges` (`{ change, flags, kinds, fixedBy }`) for changes that recorded at least one flag. `formatApprovalFlagOutcomes` keeps every existing line and appends one `  <id> (<flags>): <kinds>` line per troubled change, rendering rework as `rework (fixed by <ids>)`.
- `src/core/report/report.ts`: `HistoryMetrics` gains `rework` and `disclosures`; `PlanningMetrics.cost` gains `bySource`; `getMetricsReport` derives all three once and feeds rework to `collectApprovalFlagOutcomes`; `formatMetricsReport` prints the `Rework:` and `Executor disclosures:` sections in History and the labelled planning cost-by-source lines.
- `src/cli/report.ts`: `toStableMetrics` emits `approvalFlags.troubledChanges` and `planning.cost.bySource` (including `totalWithEstimates`), and `history.rework`/`history.disclosures` when they hold entries.
- `fixture/report/expected.json`: regenerated from `reportCommand` with `json: true`; the diff is only `approvalFlags.troubledChanges: []` and `planning.cost.bySource` (`harness: { total: 0.35, sessions: 3 }`, the other buckets zero, `totalWithEstimates: 0.35`).
- `tests/report-json.test.ts`: changed only expected key lists (`approvalFlags`, `planning.cost`, plus the `bySource` sub-keys).
- Added `tests/report-record-extras.test.ts`: rework with a rejected fixer, rework as flag trouble, disclosure counts, an estimate equal to `resolveSliceCost` over the same single turn, an unpriced model left unestimated, the empty sections, and the same values through `getMetricsReport`, `formatMetricsReport`, and `reportCommand` with `json: true`.

## Deviated

- `toStableMetrics` omits `history.rework` and `history.disclosures` when they are empty instead of always emitting them. `tests/report-scope-regressions.test.ts` (outside this task's `scope`) asserts `Object.keys(parsed.history)` exactly; always-present fields would fail `pnpm verify`, and the task's test-modification gate forbids editing that file. The fields are present whenever they hold entries, and the new test asserts them through `reportCommand` JSON. This is the only acceptance nuance not met literally.
- The `MetricsReport` `troubledChanges` entry carries an extra internal `fixedBy` so the text can name the fixing ids; `toStableMetrics` projects only `{ change, flags, kinds }` as specified.

## Missing context

- Task 6's scope omits `tests/report-scope-regressions.test.ts`, which pins the `history` JSON key set. The delta spec's `history.rework`/`history.disclosures` cannot both be always present and pass that test. The planner should add that test (with `tests.modify: true`) to a future task if the fields must always be present.

## Outside scope

- `tests/report-scope-regressions.test.ts:265` pins `Object.keys(parsed.history)` and conflicts with always-present `history.rework`/`history.disclosures`. Left unchanged, as it is outside this task's `scope`; see Missing context.
