## Changed

- `src/core/foundation/config-planning.ts`: added `PlanningDisclosuresConfig` (`recentChanges`, `maxCharacters`) and made `PlanningConfig.disclosures` required, defaulting to `{ recentChanges: 3, maxCharacters: 4000 }` via `DEFAULT_PLANNING_DISCLOSURES`. `validatePlanningConfig` now merges a partial `disclosures` block over those defaults and rejects any value that is not a positive integer with `planning.disclosures.<key> must be a positive integer`.
- `src/core/report/recent-disclosures.ts` (new): exports `RECENT_DISCLOSURES_HEADING`, `DISCLOSURES_CLAIM`, `TRUNCATION_MARKER`, `quoteDisclosureText`, `truncateDisclosureEntry`, and `formatRecentDisclosures(projectRoot, config)`. It lists the configured number of newest archived folders the way `report.ts` does (local copy, no import), reads each through `readChangeDisclosures`, quotes newest change first and in task order as `<folder> task <n>, <deviated|missing context|outside scope>:` plus `> `-prefixed text, drops nothing but the opening claim when no disclosure exists, and cuts the first entry over `maxCharacters` to end with `[truncated]`.
- `src/cli/plan.ts`: `buildOpeningPrompt` loads config once, then appends `## Recent executor disclosures` and the body only when `formatRecentDisclosures` returns non-null, after the repository record. All planning modes go through this function.
- `tests/plan-disclosures.test.ts` (new): window size, newest-first order, task/section order, the budget cut with nothing after it, exclusions, the `> ` prefix on a `#`-starting line, disclosure config defaults/rejections, section absence without disclosures, and `osq plan <name> --print` output ending with the section.
- `tests/config-planning.test.ts`: only its expected default, price, idle-gap, loaded-config, and public-surface planning objects now carry the default `disclosures` block.

## Deviated

- Acceptance line 6 asks for a test of "the `> ` prefix on a disclosure line that starts with `#`". Task 2's `parseResultSections` treats any line starting with `#` as a heading boundary, so a `#`-starting line can never survive inside a real result section. I tested `quoteDisclosureText` directly for that guarantee (with a comment explaining why) instead of through `formatRecentDisclosures`.
- Acceptance line 7 restricts `tests/config-planning.test.ts` to expected-object updates, so the new `validatePlanningConfig` acceptance/rejection tests for `disclosures` live in `tests/plan-disclosures.test.ts`, which the task verify runs.

## Missing context

The `#`-prefix acceptance line conflicts with the already-landed `parseResultSections` boundary rule; only a helper-level test can cover it without changing task 2's file.
