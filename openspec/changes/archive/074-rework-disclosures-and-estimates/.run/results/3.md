## Changed

- `src/core/status/inbox.ts`: `LandedItem` gains optional `disclosures?: DisclosureCounts` (`{ deviated, missingContext, outsideScope }`). `collectLandedItems` calls `countChangeDisclosures(folderPath)` for each eligible archive and spreads the field in only when at least one count is above zero, so a landed change without disclosures keeps exactly its previous keys.
- `src/core/status/inbox-text.ts`: added a small `disclosedSuffix` helper and `landedLine` now appends `— disclosed: deviated <n>, missing context <n>, outside scope <n>` (only the non-zero counts, in that order) only when the item carries `disclosures`.
- `src/core/status/show.ts`: added a `formatDisclosures` helper beside `formatStuck`, emitting `      Disclosures: <names>` from `parseResultSections(task.resultContent)` with names in the order deviated, missing context, outside scope; `formatSpecDetails` pushes it after the task's pre-spawn, retry, and stuck lines, and prints nothing for a task without a real section. `show.ts` still prints the whole result file as before.
- Added `tests/disclosures-inbox-show.test.ts`: archives `001-disclosed` (task 1 result with a real `## Outside scope` and a `## Missing context` of `None`) and `002-plain` (no result), then asserts the bin's `--json` landed item key set and `{ deviated: 0, missingContext: 0, outsideScope: 1 }`, the plain item having no `disclosures` key, the text row suffix, the `osq show 001` `Disclosures:` line, and that `osq show 002` prints no such line.

## Deviated

- The task lists `src/core/report/result-sections.ts` under `entry` but not `scope`, so I imported `countChangeDisclosures`/`parseResultSections` without editing it.
- I placed the disclosed suffix **before** the trailing landed command (`001: … — archived <iso> — disclosed: outside scope 1 — osq show 001`). The status-inspection delta scenario says the text line "ends with `— disclosed: outside scope 1`", but the living `Concise inbox text` requirement, which this change does not modify, says every non-empty inbox row SHALL end with its exact action command, and the task's Details points at the `stuck` row (hint before the `osq retry` command) as the pattern. Putting the suffix before the command keeps both landed rows command-terminated and mirrors `stuck`. Flagging for the planner/reviewer because the delta wording reads as absolute-end.

## Missing context

- The task and delta disagree on suffix placement (above). Also `LandedItem`'s disclosure shape is named only as `{ deviated, missingContext, outsideScope }`; I reused the existing `DisclosureCounts` type from `result-sections.ts` since it is exactly that shape.
