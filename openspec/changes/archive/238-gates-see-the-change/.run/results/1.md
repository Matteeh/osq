## Changed

- `change_link_gates` now reads each delta once, derives the change's `Code ownership` globs with `code_ownership` from the requirement's `raw` text, and merges them over the living globs. A capability with an ADDED or MODIFIED `Code ownership` replaces its living globs whether or not it has a living spec; every other capability keeps `read_capability_ownership`'s globs. The merged list is sorted by capability name and passed into the graph before the `owns` edges are added.
- Moved the change-specific code into `src/gates/change.rs` and kept only `link_gates`, `run_link_rules` and scoping in `gates.rs`. The public `change_link_gates` path is unchanged.
- `graph/build.rs` gained a crate-private `build_link_graph_with` that takes the ownership list; `build_link_graph` computes the living list and calls it. `graph/files.rs::add_ownership` now takes the ownership list instead of reading living specs itself. No public item was added and `link_gates`/`build_link_graph` keep their signatures and behaviour.
- Copied `openspec/changes/238-gates-see-the-change/fixtures/link-gates-ownership/` byte for byte with `cp -R` to `crates/kernel/linter/tests/fixtures/link-gates-ownership/`.
- Added `tests/link_gates_ownership.rs` proving the three scenarios: the base fixture finding, ownership moving to a new capability through `001-split`, and a new capability overlapping a living one through `002-fresh`.
