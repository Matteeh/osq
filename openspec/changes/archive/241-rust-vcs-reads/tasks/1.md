## Acceptance

- [ ] New `src/error.rs` holds `VcsError`, an enum deriving `Debug` with the variant `Spawn { command: String, source: std::io::Error }`, implementing `Display` and `std::error::Error` as rust-vcs "Git command" says.
- [ ] New `src/port.rs` holds `pub trait Vcs` with the nine reads of rust-vcs "Repository state reads", each `&self` and returning `Result<_, VcsError>`, with `&str` parameters (`rev`, not `ref`), and `Head`, `StatusEntry` and `Worktree` with the public fields it names, deriving `Debug`, `Clone`, `PartialEq` and `Eq`.
- [ ] New `src/git.rs` holds `GitVcs` with `new`, `with_program`, `with_env` and `command` as "Git command" says, one private runner every read goes through, and `impl Vcs for GitVcs` calling free functions in new `src/git/state.rs`, which holds each read's git arguments and its pure parser.
- [ ] `src/lib.rs` keeps its crate doc, declares `mod error; mod git; mod port;` and re-exports `VcsError`, `Vcs`, `Head`, `StatusEntry`, `Worktree` and `GitVcs`. `Cargo.toml` and `Cargo.lock` do not change.
- [ ] New `tests/support/mod.rs` holds the scratch helpers both read test files use: a scratch folder per test under `CARGO_TARGET_TMPDIR`, running `git` with the isolated settings of "Repository state reads", writing a file, and a `GitVcs` with those settings. Every helper it holds is used by `tests/state_reads.rs`.
- [ ] New `tests/git_command.rs` proves "Command for a read" and "State reads with a program that cannot start"; new `tests/state_reads.rs` proves "State of the read repository", "Unborn repository" and "Directory outside any repository", with the literal values of their tables, one assertion per row.
- [ ] Every public function's doc, the trait's methods included, ends with `Implements: rust-vcs/git-command` or `Implements: rust-vcs/repository-state-reads`, and each test's one-line doc names `Covers: rust-vcs/<scenario>` in kebab-case, such as `Covers: rust-vcs/unborn-repository`.

## Details

Port the TypeScript functions named in each bullet of "Repository state
reads": `root`, `head`, `status`, `show` and `pathExists` from
`git-vcs-read.ts`, `parseStatus` and `nonEmpty` from `git-vcs-parse.ts`,
and `configValue`, `listBranches`, `defaultBranch` and `parseWorktrees`
from `git-vcs-write.ts`. Use `std::process::Command::output`; a spawn
error becomes `VcsError::Spawn`, and any exit status but success is the
read's empty answer. `head` runs its `rev-parse` before its
`symbolic-ref`, so the missing-program row names `rev-parse`.

The isolated settings are `GIT_CONFIG_GLOBAL=/dev/null`,
`GIT_CONFIG_NOSYSTEM=1`, `GIT_CEILING_DIRECTORIES=<scratch folder>` and
`maintenance.auto` off through `GIT_CONFIG_COUNT=1`,
`GIT_CONFIG_KEY_0=maintenance.auto`, `GIT_CONFIG_VALUE_0=false`. Commits
also get fixed `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_AUTHOR_DATE` and
the matching `GIT_COMMITTER_*` values. Make the scratch folder canonical
before building in it, and remove a leftover folder of the same name first,
so a rerun starts clean. Give every test its own folder name, since tests
run in parallel. Build the worktrees beside the repository inside the
scratch folder. `git-test` and `/repo` in "Command for a read" are never
run; compare `get_program`, `get_args`, `get_current_dir` and `get_envs`.

cargo-mutants runs on every line this task adds, so each condition must
change a value a table row checks: the four-character field check (the
untracked `z` row), the `R` or `C` test and the empty `from`, the
`origin/` strip (prefer `strip_prefix` with a non-empty check over length
comparisons), the `refs/heads/` strip, the detached and blank-line
endings, and every environment change in `command`. Before exiting, run
`cargo fmt --all`, then `cargo mutants -p osq-kernel-vcs -f <file> -o "$(mktemp -d)"`
on each new source file, then `sh scripts/verify-rust.sh` with
`OSQ_CHANGE` set to `openspec/changes/241-rust-vcs-reads`, so the link gate
corpus test sees this change's new requirements.
