## Details

`stream.rs` already parses a task stream loosely for `read_task_history`.
Reuse it for both new stream readers. Give its `Event` what they need,
such as the line's `timestamp` string and a data member's raw
`serde_json::Value`, so `scopeHashes`, `scopeResolver` and `added` can be
read. `read_task_history`'s results must not change.

Read timestamps with `timestamp_ms` from `text.rs`. Read a task file with
`osq_kernel_specs::parse_task_file`: its `title` and the length of its
`acceptance`. Read `fixes` with `osq_kernel_specs::parse_proposal`. Trim
dependency names and files with `osq_kernel_specs::js_trim`, since
JavaScript's `trim` also strips U+FEFF and `str::trim` does not.

`read_result_disclosures` gives what the existing private
`read_disclosures` gives. Make one call the other, or rename it and keep
`snapshot.rs` reading the same entries; `snapshot.rs` is outside scope, so
keep its call working unchanged.

The TypeScript files in `entry` are what you port: `deriveMeasuredTask`,
`projectMeasuredTasks` and `readTaskMetadata` in `report.ts`,
`observeAttempts` in `report-events.ts`, `taskScopeSize` in
`scope-size.ts`, and `addedPairs`, `distinctPairs` and
`collectDependencies` in `report-dependencies.ts`. Never read anything
under `src/` from Rust; those files are in `entry` only so you can port
them. Every row of the scenario tables was checked against TypeScript's
`dist` on 2026-10-24.

In "Task sizes of task streams", each row writes `tasks/1.md` with the
title `When one runs, it passes` and three `- [ ]` acceptance items, and
each event line is a JSON object with `type`, `timestamp` and `data`. A
`started`, `done`, `dead` or `regressed` line's data is `{}`.

cargo-mutants runs on every line you touch, so give each branch a row that
fails when it flips. The scenario tables cover each branch; add a fast test
when a mutant survives. Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/330-rust-report-history-sizes`, so the link
gates see this change's new requirements.
