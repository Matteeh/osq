## Changed

- Added exported `syncBeforeSpawn(change, specState)` to `src/watcher/sync-run.ts`: true when no task of the change is done, otherwise true only when `readRetryContext` gives the next task an `attempt` above 1. Its doc carries an `@scenario` line for each of the two scenarios.
- `startNextTask` in `src/watcher/loop.ts` now runs `checkSync` for a worktree change when `syncBeforeSpawn` says so, replacing the done-marker test; the halt and the second state read are unchanged.
- Added `tests/retry-sync.test.ts`, proving "Sync before a retried attempt" with `each` over both retry rows and "Sync stop before a retried attempt".

## Deviated

- The retried-attempt assertion filters branch subjects to those starting with `osq: `. A sync merge also pulls the default branch's own `main moves` commit into the worktree's history, so the raw subject list after task 1 verified includes it between task 1 and the dead commit. The scenario's expected values are osq's transition subjects, which now match exactly in order.
