## Details

Build the project with `createRecoveryProject` from
`tests/recovery-support.ts`, with tasks `src/one.txt` and `src/two.txt`,
`files: { 'src/tool.txt': 'broken\n' }` and the row's `autoRetries`.
Approve it with its `approve`, and drive it with a `ScriptedAdapter`
whose task 1 writes `one\n`, and whose task 2 reads `src/tool.txt` under
`options.projectRoot` and writes `good\n` when it reads `fixed\n`, else
`bad\n`, so the default `verify.cjs` kills the first attempt. Move main
with `commitMain` inside task 2's first spawn: an automatic retry runs
in the same `watchOnce`, so a commit made after it would come too late.
For the human row, call the project's `retry('2')` after the first
`watchOnce`. Read the subjects with `subjects(project.worktree)`. For
the stop scenario, `commitMain` writes `src/one.txt` as `main\n` inside
task 2's first spawn.

The scenario helper's `covers` is `runWatcherOnce`; call it through
`run` with the project's `repo` and `config` and the adapter, rather
than through `watchOnce`. `tests/recovery-sync-conflict.test.ts` shows
the halt assertions.

`src/watcher/loop.ts` is on the line budget's allow list; keep it no
longer than it is. A rough version of this change, measured on
2026-10-23, passed both scenarios and broke no existing test.
