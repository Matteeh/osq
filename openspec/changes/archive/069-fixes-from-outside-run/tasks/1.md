## Acceptance

- [ ] `resolveBuildInfo` in `src/watcher/build.ts` takes an optional osq package root, defaulting to `PACKAGE_ROOT`, and never reads the project's `package.json`. `version` comes from that root's `package.json`. `commit` is the short HEAD commit only when `git rev-parse --show-toplevel` run in that root resolves to the same real path as the root; otherwise it is the existing `dist/` hash of that root, otherwise `unknown`. The per-root cache stays.
- [ ] New `src/watcher/build-project.ts` exports `resolveProjectCommit(projectRoot)`, which returns the project root's short HEAD commit or null when it is not in a git repository.
- [ ] `spawnTaskAgent` in `spawn.ts` records osq's identity from `resolveBuildInfo()` as `osqVersion`, `version`, and `commit`, and `projectCommit` from `resolveProjectCommit(projectRoot)`. `StartedEventData` in `src/harness/types.ts` gains `projectCommit?: string | null`. `runWatcherCycle` in `loop.ts` prints osq's identity from `resolveBuildInfo()` in the idle status line.
- [ ] `buildDoneMetadata` in `regression.ts` writes osq's commit as `build_stamp` and the project commit as `project_commit`. `DoneMarkerMetadata` in `outcome.ts` gains optional `projectCommit`, and `writeDoneMarker` writes `project_commit: "<sha>"` or `project_commit: null` after `build_stamp`.
- [ ] The two golden streams under `tests/fixtures/events/` gain `"projectCommit":null` on their `started` event, and nothing else in them changes.
- [ ] New `tests/watcher-build-identity-project.test.ts` covers, each in its own case:
  - `resolveBuildInfo(<root>)` for a fake osq package root whose `package.json` says `9.9.9`, placed at the top of its own git repository, returns `9.9.9` and that repository's HEAD.
  - The same fake root placed below the top of a git repository, as `node_modules/@matteeh/osq` is, with a `dist/` file, returns the `dist/` hash and never the repository's HEAD; without `dist/` it returns `unknown`.
  - `resolveBuildInfo()` in this checkout returns the checkout's `git rev-parse --short HEAD`.
  - `runTask` on a temp project whose `package.json` says `1.0.0`, in its own git repository with one commit, records a `started` event whose `osqVersion` and `version` equal osq's own `package.json` version and whose `projectCommit` is the project's HEAD. Its done marker has `build_stamp` equal to `resolveBuildInfo().commit` and `project_commit` equal to the project's HEAD.
  - The same run on a temp project without git records `projectCommit: null` and `project_commit: null`.
  - `runWatcherCycle` on a temp project whose `package.json` says `1.0.0` prints an idle status line beginning `osq v<osq's version> (<resolveBuildInfo().commit>)`.
- [ ] `spawn.ts` and `outcome.ts` stay under 200 lines; `build.ts`, `build-project.ts`, and `regression.ts` stay under 250.

## Details

Run git in tests with `-c user.name=osq -c user.email=osq@example.invalid` and
create every temp repository under `os.tmpdir()`. Build the `runTask` fixtures
the way `tests/watcher-build-identity.test.ts` does, with `installFakeValidator`,
`scaffoldProject`, `createNewSpec`, a local `node verify.cjs`, and
`approveSpec`, and commit the scaffolded project before running when the case
needs git. Capture the idle line with a logger the way
`tests/watcher-loop-logging.test.ts` does.

`tests/golden-events.test.ts` already masks `version`, `commit`, and
`osqVersion` and does not change; its temp project has no git, so
`projectCommit` is null there. The existing cases in
`tests/watcher-build-identity.test.ts` pass a fake package root to
`resolveBuildInfo` and may keep doing so; change them only where the new
semantics require. Human recertification in `src/core/lifecycle/retry.ts`
merges the existing done frontmatter, so `project_commit` survives it without
changes there.
