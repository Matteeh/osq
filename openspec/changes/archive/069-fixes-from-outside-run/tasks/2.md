## Acceptance

- [ ] New `src/core/spec/digest-capability.ts` exports a pure `resemblingCapability(name, living)` that returns the first name in `living`, in name order, that the new name resembles, or null. Two names resemble each other when they are equal once hyphens and underscores are removed, when the words of one, split on hyphens and underscores, all appear among the words of the other, or when both are at least five characters long and their edit distance is at most two.
- [ ] Each capability in the digest carries whether the change creates it: it has no living spec, its delta's `purpose` from `parseDelta` is non-empty, and `resemblingCapability` returns null. `formatApprovalDigest` prints that capability's heading as `  <name> (new capability):`; every other heading is unchanged.
- [ ] `unknown_capability` fires once for a capability with no living spec when a resemblance exists, labelled `unknown capability <name> resembles <living>`, or, failing that, when its delta has no `## Purpose`, labelled `unknown capability <name> without a Purpose`. The excerpt still names the missing living spec path. A deliberately created capability raises no flag. Flag order is unchanged.
- [ ] New `tests/approval-digest-capability.test.ts` drives `buildApprovalDigest` and `formatApprovalDigest` on fixture changes and covers: a delta with `## Purpose` for a new dissimilar name raises no flag and prints `(new capability)`; a delta without `## Purpose` for a missing capability raises the flag labelled `without a Purpose`; a delta with `## Purpose` for `watcher-harness` next to a living `watcher-and-harness` raises the flag labelled `resembles watcher-and-harness`; `cli` next to a living `api` raises no flag. It also unit-tests `resemblingCapability` for each of the three conditions.
- [ ] `tests/approval-digest.test.ts` changes only where the new labels or the digest capability shape require it.
- [ ] The `unknown_capability` sentence in `README.md` describes the new conditions.
- [ ] `digest.ts`, `digest-flags.ts`, and `digest-capability.ts` each stay under 250 lines.

## Details

The living capability names are the directories under
`<openspecRoot>/specs/` that hold a `spec.md`; read them once per digest.
Reuse `parseDelta`'s `purpose`; add no new parsing. Build fixture changes the
way `tests/approval-digest.test.ts` does. Its existing `brand-new-capability`
deltas carry no `## Purpose`, so they keep flagging, now with the
`without a Purpose` label.
