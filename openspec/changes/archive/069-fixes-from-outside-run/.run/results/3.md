## Changed

Both acceptance lines pass and both verify commands are green.

- `src/watcher/fingerprint.ts`: added a `DURATION_KEY` rule that replaces only the number after a duration key (keeping the key and separator), so `duration_ms: 3.803686` and `# duration_ms 92.962079` normalize to `<duration>`. Added a temp-path rule built from `os.tmpdir()` and its `fs.realpathSync` result (regex-escaped, alternated), applied after the project-root replacement, that rewrites `(tempdir)/<first-segment>` to `<tmp>` while keeping the remainder, so `/tmp/paas-Hfp38F/state.db` becomes `<tmp>/state.db`, `/tmp/paas-Hfp38F` becomes `<tmp>`, and `file:///tmp/paas-Hfp38F/a.mjs` becomes `file://<tmp>/a.mjs`.
- `tests/dead-fingerprint.test.ts`: updated the no-project-root assertion for `/tmp/proj/src/a.ts` to expect `<tmp>/src/a.ts`, and added cases for the duration-key rule and the temp-path boundaries (slash, end of string, whitespace, quote).
- `tests/dead-fingerprint-node-test.test.ts`: new test that writes a failing `node:test` file which creates and prints a `mkdtemp` directory and fails an assertion naming the path, runs it twice with `node --test`, writes each combined output as a `verify_red` dead marker through `writeDeadMarker`, and asserts equal fingerprints; a second run with a different assertion message gives a different fingerprint.

## Deviated

- The new test spawns `node --test` with `NODE_TEST_CONTEXT` removed from the child environment. The outer node test runner sets `NODE_TEST_CONTEXT=child-v8`, and inheriting it made the child treat itself as a nested run and skip the file, printing a PID-carrying warning that broke normalization. Stripping it is test-harness plumbing, not a behavior change.
