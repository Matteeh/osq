## Changed

- Removed `ChangeActions.tsx` and `ChangeActionsPanel.tsx`.
- Added `useChangeActions.ts`: the loading, reload-on-fresh-document, single-tap
  and result logic moved unchanged into `useChangeActions(selector, asOf,
  client, opened)`. It loads nothing when the client is `undefined`, and it
  derives the `TaskRetry` list (`targets`, `pending`, `onRetry`) from the same
  loaded document so a task-target `retry` runs through the one hook.
- Added `ActionRetry.ts`: a `TaskRetryContext` and `useTaskRetry`, the seam
  that carries the hook's retry controls from `ChangeView` to `TaskTable`
  without `PageFolds`. `TaskRetryContext` is not in the task's scope, but
  `PageFolds.tsx` is not either (it is an `entry` file), so the retry travels
  through context instead of a second prop on `PageFolds`.
- Added `ActionResult.tsx`: the exit code, captured stdout/stderr, and the
  failure message with its `Next:` step.
- Added `ActionButtons.tsx`: the button bar's main item. Approve (with the red
  notice note and the review flags) when `page.main` is `approve` and the
  actions hold `approve`; Land when the main is `land` and the actions hold
  `land`; otherwise the review flags, which appear at the start of the bar.
- Added `ActionMenu.tsx`: the `<details class="page-menu">` `More actions`
  menu with Reject and its reason field (disabled until non-empty),
  `Retry change`, and each manual command as `<code>`.
- `TaskTable` takes an optional `retry` prop and shows `Retry task <n>` in the
  matching row's state cell; without the prop and outside the change view it
  is byte-identical to before.
- `ChangeView` mounts `ActionMenu` in the head (after the summary),
  `ActionButtons` as the first child of `.page-buttons` before the plan
  buttons, and `ActionResult` below the bar, all from the one
  `useChangeActions` hook, in place of `ChangeActionsPanel`. It provides the
  hook's retry controls around the top block and folds.
- `index.ts` drops the two removed exports and exports `ActionButtons`,
  `ActionMenu`, `ActionResult`, `useChangeActions`, `TaskRetryContext`,
  `useTaskRetry` and the `TaskRetry` / `ChangeActionsState` types.
- `actions.css` gains `.page-menu`, `.menu-row`, `.menu-button` (44px
  minimum), `.action-retry` (44px minimum) and `.action-blocked` styling.
- Added `tests/ui-actions-page.test.tsx`, proving "Approval buttons", "Result
  after a tap", "Static export has no buttons" and "Reject in the menu" from
  explicit props through `renderToStaticMarkup`.
- Updated only the tests in `tests/ui-actions.test.tsx`,
  `tests/ui-review.test.tsx` and `tests/ui-notices.test.tsx` that rendered
  `ChangeActions`, so they render the new components and keep the expectations
  the modified requirement still holds.

`pnpm verify` exits 0 (both typechecks, the build, every test and lint). The
task verify passes with 4 tests.

## Deviated

- Task 4 owns `TaskTable.tsx` and `ChangeView.tsx`, but `ChangeView` renders
  the task table through `PageFolds.tsx`, which is only in this task's `entry`,
  not its `scope`. The acceptance line "`ChangeView` mounts ... the retry prop"
  would normally thread a prop through `PageFolds`; the prior attempt did that
  and was killed for a scope violation. Instead `ChangeView` provides
  `TaskRetryContext` (new `ActionRetry.ts`) around the folds and `TaskTable`
  reads it as the fallback when its optional `retry` prop is absent. The prop
  still exists and is what the new test drives.
- The modified requirement says the flags show "above the button bar" when the
  actions hold no approve. `ActionButtons` renders them as the first child of
  `.page-buttons`, i.e. before the plan buttons, because the same component
  also has to render the Approve item inside the bar. The visible order is the
  flags first; nothing renders them as a sibling outside the bar.
- `ActionMenu`'s Reject/Retry-change controls use a `menu-button` class rather
  than `action-button`, so "the button bar holds only Approve" reads exactly on
  the bar's own `.action-button` count. The requirement pins no class for the
  menu controls.
