It reads and writes frontmatter with the `yaml` package and reads the folder from `config.paths.openspecRoot`.
- [ ] New `src/core/vcs/manual-edits.ts` exports `keepManualEdits(projectRoot, config, { comment, paths, now })`, which returns the output lines or throws an `Error` with the refusal message, exactly as version-control "Manual edit keeping" and "Manual edit commit" say. `now` defaults to the current time and sets the record's `kept_at`. It also exports `MANUAL_KEEP_ADVICE`, the text `keep them with osq manual "<why>"`, for the approve and land refusals.

## Details

`tests/vcs-land-commit.test.ts` shows how a test builds a temporary git project
with `scaffoldProject`, `vcs.enabled` and a clean git environment. A record
scenario needs a living `cli-foundation` spec whose Code ownership source
comment covers `osq.config.ts`. Take expected values from the scenario lines
and tables, not from running the code; the short commit in the output is the
new HEAD's abbreviated hash, so read it with git in the test. `vcs.status`
reports an untracked folder as one entry ending in `/`; treat a named path
as naming it when the entry starts with the path. Keep each new file under the
250-line budget and each function under 80 lines.
