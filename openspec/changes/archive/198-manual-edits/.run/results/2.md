## Changed

- `src/core/vcs/manual-records.ts` (new): `ManualEditRecord` (`file`, `keptAt`,
  `paths`, `capabilities`, `comment`), `ManualRecordFields`,
  `manualRecordsDir`, `manualRecordFileName`, `renderManualEditRecord`, and
  `readManualEditRecords`. Frontmatter is written and read with `yaml` via
  `parseFrontmatter`; the folder is `<openspecRoot>/manual`, read from
  `config.paths.openspecRoot`. Records come back in `kept_at` order, leaving
  out a file without a string `kept_at` or a `paths` list.
- `src/core/vcs/manual-edits.ts` (new): `keepManualEdits` and
  `MANUAL_KEEP_ADVICE` (`keep them with osq manual "<why>"`). It uses
  `selectVcs`, `vcs.status`, `vcs.configValue` and `vcs.commit`; finds
  capabilities with `readCapabilityOwnership` and `ownerCapabilities`; removes
  the record when the commit throws. Refusals follow the requirement's table
  order.
- `src/cli/manual.ts` (new): `manualCommand(comment, paths, options)` and
  `registerManualCommand`, following `src/cli/sync.ts`. Lines go to stdout; a
  refusal throws a `CommandError`.
- `src/cli/index.ts`: imports and registers `osq manual <comment> [paths...]`
  with the description `keep uncommitted edits as a manual change with a comment`.
- `src/cli/help-groups.ts`: `manual` added last in the Everyday group.
- `tests/vcs-manual-edits.test.ts` (new): every scenario of the four
  requirements over temporary git projects, one `node:test` block per scenario
  and per refusal-table row, plus a `MANUAL_KEEP_ADVICE` check.
- `tests/help-groups.test.ts` and `tests/cli-no-direct-output.test.ts`:
  updated for `manual` (`tests.modify: true`).

## Deviated

- The acceptance line asks for "a function that renders one record file's text
  and its file name"; I exported two small functions,
  `renderManualEditRecord(fields)` and `manualRecordFileName(keptAt)`, instead
  of one combined return, because the writer and the readers each need one.
- `KeepManualEditsOptions.now` accepts `Date | number | string` so the test can
  pass an ISO string; it is normalized with `new Date(...).toISOString()`.
- The short commit is `commit.slice(0, 7)` of the full SHA `vcs.commit`
  returns; the task fixes that the output holds the new HEAD's abbreviated
  hash and the test reads it with `git rev-parse --short HEAD`.
