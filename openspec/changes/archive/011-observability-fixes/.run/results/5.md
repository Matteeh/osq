# Task 5 result: shared harness stream helpers and legacy metric alias removal

## Changed

- **`src/harness/stream.ts` (new)**: exports `asRecord`, `firstNonEmptyString`,
  `resolveEventTimestamp`, and `EventStreamParser`. The timestamp helper resolves a top-level
  `timestamp` or a nested `step_update.timestamp` (superset of the old agy helper). The parser
  buffers chunked stdout, delivers only non-blank complete lines serially, swallows per-line
  handler rejections, and drains the trailing partial line on `flush()`.
- **`tests/harness-shared.test.ts` (new)**: 13 unit tests covering `asRecord` (objects vs
  arrays/null/primitives), `firstNonEmptyString` (skips empty/non-string), `resolveEventTimestamp`
  (ISO string, epoch number, nested `step_update`, invalid/missing fallback), and
  `EventStreamParser` (split chunks, trailing partial line, empty lines, serial `await` order,
  handler rejection resilience, flush idempotence).
- **`src/harness/agy.ts`**: deleted local `asRecord`, `firstNonEmptyString`, and
  `resolveAgyTimestamp`; imports the shared helpers. All three call sites now use
  `resolveEventTimestamp`. `AgyAdapter.spawn` constructs the shared `EventStreamParser` directly.
- **`src/harness/opencode.ts`**: deleted local `asRecord`, `firstNonEmptyString`, and
  `resolveEventTimestamp`; imports the shared helpers. `OpencodeAdapter.spawn` constructs the
  shared `EventStreamParser` directly.
- **`src/watcher/runner.ts`**: imports `asRecord` from `../harness/stream.js`;
  `computeTaskHeartbeatStats` and `extractFinalTextFromStream` now use it instead of unchecked
  `as HarnessEvent` casts. The prior local `asRecord` had already been removed by tasks 1-4.
- **`src/core/report.ts`**: removed all legacy aliases from `MetricsReport`
  (`totalSpecs`, `activeSpecs`, `archivedSpecs`, `totalTasks`, `doneTasks`, `deadTasks`,
  `runningTasks`, `pendingTasks`, `completionPercentage`, `completionRatio`, `deadBreakdown`),
  from `TokenMetrics` (`promptTokens`, `candidateTokens`, `totalTokens`, `prompt`, `candidate`),
  and from `FileChangeMetrics` (`totalEvents`). Removed the corresponding return-object fields
  and the alias locals; canonical `specs`/`tasks`/`tokens`/`failureBreakdown` are unchanged.
- **Tests updated to canonical properties** (acceptance line 5): `tests/report.test.ts`,
  `tests/report-tokens.test.ts`, `tests/report-json.test.ts`,
  `tests/report-task-states.test.ts`, `tests/report-failure-breakdown.test.ts`,
  `tests/report-file-changes.test.ts`.

## Deviated

- `AgyEventStreamParser` and `OpencodeEventStreamParser` were kept as thin `extends
  EventStreamParser` compatibility subclasses instead of being deleted. The duplicated buffering
  implementation is gone and both adapters instantiate the shared `EventStreamParser` directly;
  the subclasses exist only because `tests/agy-stream-events.test.ts`,
  `tests/opencode-events.test.ts`, and `tests/opencode-tool-events.test.ts` import the old names
  and are outside this task's `scope`. Removing them would require out-of-scope test edits and a
  `tsc` failure. A follow-up can migrate those call sites and delete the shims.
- Test files outside the frontmatter `scope` were edited (`tests/report*.test.ts`) because
  acceptance line 5 explicitly requires existing tests to use canonical properties; leaving them
  would have broken `pnpm tsc --noEmit` and the report tests.
- Acceptance line 3 says runner had a local `asRecord` duplicate. At the start of this task the
  working tree no longer contained it (tasks 1-4 had already removed it alongside
  `extractTextFromStreamEvent`). The shared import is now present and used to harden the two
  remaining event-parsing loops.

## Drift against `features/`

`features/watcher-and-harness.md` still lists only the older event set and does not mention the
shared `EventStreamParser`/helpers; `features/metrics-and-reporting.md` does not state that the
deprecated `MetricsReport` aliases are removed. The spec's `## Delta` assigns these documentation
updates to follow-up 012, so neither feature doc was edited here.
