# Task 4 result: reasoning tokens emitted by adapters; report prefers reported cache

## Changed

- `src/harness/opencode.ts`: added `reasoningTokens: number` to `OpencodeTokensData`; `extractOpencodeTokens` now reads
  `Number(tokensObj.reasoning ?? tokensObj.reasoningTokens ?? tokensObj.thinking ?? 0) || 0` and returns it; the `tokens`
  event emitted by `processOpencodeStdoutLine` now includes `reasoningTokens`.
- `src/harness/agy.ts`: added `reasoningTokens: number` to `AgyStreamTokensData`; `extractAgyTokens` now reads
  `Number(usage.thinking_tokens ?? usage.reasoning_tokens ?? 0) || 0` and returns it; the `tokens` event emitted by
  `processAgyStdoutLine` now includes `reasoningTokens`.
- `src/core/report.ts`: reasoning is read as `data.reasoningTokens ?? data.reasoning ?? data.thinking_tokens ?? 0`.
  Added `hasReportedCache` (`data.cachedTokens`, `data.cached_input`, `data.cache_read_tokens`, or a numeric
  `data.cache`/`data.cache.read`). When a cache field is present the adapter-reported cache counter is used directly;
  the remainder formula (`reportedTotal - input - output - reasoning`) is used strictly when no cache field exists.
  `total` still prefers the harness-reported total.
- `tests/report-tokens.test.ts`: updated fixture expectations to the reported-cache behavior (`cached_input`
  9036195 -> 8958336; formatted label likewise), renamed the remainder test to make the "only when no cache field"
  condition explicit, and added: preference test where remainder (25) differs from reported cache (30), real-world
  opencode counts `{3625,154,9964,6144,41}` asserting `cached_input === 6144` and `reasoning === 41` (and that
  reasoning is not folded into cache), plus four adapter tests covering `extractOpencodeTokens` /
  `extractAgyTokens` reasoning extraction and emission of `reasoningTokens` on the `tokens` events.

## Verify

## Deviated

- The fixture test's old assertion "the neutral breakdown always adds back up to the reported total" was removed.
  With cache preferred over the remainder, the fixture's reported cache counters sum to a value that differs from
  `total - input - output` (by 77859 across the fixtures), so the invariant no longer holds by design. Individual
  category and total assertions (including `total === 9386624`) remain. The invariant is still asserted in the
  no-cache-field remainder test where it is valid.
- The fixture expectation change (9036195 -> 8958336) is a direct consequence of acceptance line 5. No fixture data
  was modified.
