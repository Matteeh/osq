# Task 1 result: onSpawn records started with pid; runner owns lifecycle events

## Changed

- `src/harness/process.ts`: added `onSpawn?: (pid: number) => void` to `SpawnWithTimeoutOptions`; `spawnWithTimeout` now invokes `onSpawn(child.pid)` synchronously right after `spawn(...)` when a pid exists.
- `src/harness/types.ts`: added `onSpawn?: (pid: number) => Promise<void> | void` to `SpawnTaskOptions`.
- `src/harness/agy.ts` / `src/harness/opencode.ts`: forward `onSpawn` to `spawnWithTimeout`; removed the `started` and `exited` `appendHarnessEvent` calls from `spawn()`; `SpawnResult` now returns `pid` and `elapsedMs` copied from the process result. Unused destructured fields dropped (`noUnusedLocals`).
- `src/watcher/runner.ts`: runner passes `onSpawn: (pid) => recordStarted(pid)` to `adapter.spawn`. `recordStarted` appends the single `started` event (`{ pid, timeoutSeconds }`) and logs `task <n> started (pid: <pid>, timeout: <timeout>s)`. A fallback `await recordStarted(spawnResult.pid)` guarantees a `started` event even for adapters that never call `onSpawn`. The `exited` event now carries `{ exitCode, pid, elapsedSeconds, timedOut, signal }`, logged as before.
- `tests/runner-lifecycle-pid.test.ts` (new): runs the real `AgyAdapter` and `OpencodeAdapter` against on-disk `fake-agy.mjs` / `fake-opencode.mjs` binaries (no mock adapter). Asserts `onSpawn` fires once with the real pid, `SpawnResult.pid`/`elapsedMs` are returned, adapters append no `started`/`exited` events, and `runTask` produces exactly one `started` and one `exited` event with matching pid, exitCode `0`, `timedOut: false`, and a numeric `elapsedSeconds`; also asserts the pid is logged to stderr.

## Missing context / known breakage

Four pre-existing tests outside this task's `scope` assert the *old* adapter-owned lifecycle contract and now fail under the new invariant (adapters must never emit lifecycle events). They were intentionally not modified because they are outside scope:

- `tests/agy-stream-events.test.ts` > `translates stream events through the adapter spawn path with the shared logger` (expects `events[0] === 'started'`).
- `tests/opencode-events.test.ts` > `tokens event is appended ...` (expects 3 events: started, tokens, exited).
- `tests/opencode-spawn.test.ts` > `Fake opencode binary ...` (expects `started`/`exited` from `adapter.spawn`).
- `tests/harness-process.test.ts` > `AgyAdapter uses spawnWithTimeout helper preserving existing timeout behavior` (expects `.run/events/1.jsonl` to exist after a bare adapter spawn).

These tests contradict the spec invariant "Adapters translate stream events (`tokens`, `tool`, `text`) and must never emit lifecycle or marker events", so they need updating to the runner-owned contract. They should be added to a follow-up task's scope (or this task's scope expanded) before the full `pnpm test` suite is green again.
