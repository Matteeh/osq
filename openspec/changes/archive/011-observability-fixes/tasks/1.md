## Acceptance
- [ ] spawnWithTimeout and SpawnTaskOptions accept an onSpawn(pid) callback invoked immediately on child process creation
- [ ] AgyAdapter and OpencodeAdapter forward onSpawn, return pid and elapsedMs on SpawnResult, and stop appending started and exited
- [ ] Runner defines onSpawn to append started with pid and timeout, logging pid to stderr at start time
- [ ] Runner appends exited event with pid, exitCode, elapsedSeconds, and timedOut upon adapter completion
- [ ] events.jsonl contains exactly one started event and one exited event per task execution
- [ ] Test runs real AgyAdapter and OpencodeAdapter against a fake harness binary asserting on events.jsonl without mock adapters

## Details

1. In `src/harness/process.ts`, add `onSpawn?: (pid: number) => void` to `SpawnWithTimeoutOptions`. In `spawnWithTimeout`, immediately after calling `spawn(command, args, { cwd, env, stdio })`, if `child.pid !== undefined`, invoke `options.onSpawn?.(child.pid)`.
2. In `src/harness/types.ts`, add `onSpawn?: (pid: number) => Promise<void> | void` to `SpawnTaskOptions`.
3. In `src/harness/agy.ts` and `src/harness/opencode.ts`:
   - Pass `onSpawn: options.onSpawn` through to `spawnWithTimeout`.
   - Remove `appendHarnessEvent` calls for `started` and `exited` from `spawn()`. The runner alone owns lifecycle events.
   - Return `{ exitCode: result.exitCode, timedOut: result.timedOut, signal: result.signal, error: result.error, pid: result.pid, elapsedMs: result.elapsedMs }` on `SpawnResult`.
4. In `src/watcher/runner.ts`:
   - Pass an `onSpawn` callback to `adapter.spawn`. In `onSpawn(pid)`, append the `started` event with `{ pid, timeoutSeconds }` and log `task <n> started (pid: <pid>, timeout: <timeout>s)` to stderr.
   - When `adapter.spawn` resolves, append the `exited` event with `{ exitCode, pid: spawnResult.pid, elapsedSeconds, timedOut, signal }` and log `task <n> exited (code: <exitCode>, elapsed: <elapsedSeconds>s)`.
   - If `onSpawn` was not triggered before completion, record `started` before exit as a fallback so every run has a started event.
5. In `tests/runner-lifecycle-pid.test.ts`:
   - Create a test using fake harness binaries (`fake-agy.mjs` and `fake-opencode.mjs`).
   - Run tasks through the real adapters and assert that `.run/events/<n>.jsonl` contains exactly one `started` event with a valid PID and one `exited` event with matching PID.
   - Invariant: Do not satisfy acceptance using a mock adapter.
