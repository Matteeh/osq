- [ ] New `crates/kernel/harnesses/src/process.rs`, with files beside it under `src/process/` as you see fit, holds `ProcessSpec`, `ProcessOutcome`, `ProcessError` and `run_process(spec: &ProcessSpec, on_line: &mut dyn FnMut(&str)) -> Result<ProcessOutcome, ProcessError>` with the fields and behaviour rust-harnesses "Process runner" names. `ProcessSpec`, `ProcessOutcome` and `ProcessError` derive `Debug`, `Clone`, `PartialEq` and `Eq`; `ProcessError` also implements `Display` and `std::error::Error`.
- [ ] Only the standard library is used; `crates/kernel/harnesses/Cargo.toml` is unchanged. The program gets its environment through `Command::env_clear` followed by `spec.env`, and the stop and kill go through the system `kill` utility, `kill -TERM <pid>` then `kill -KILL <pid>`.
- [ ] No loop polls with a fixed sleep: threads read stdout and stderr and one waits for the exit, and the calling thread receives lines and the exit on one channel with deadlines from `spec.timeout` and `spec.kill_grace`. No duration is written in the source.
- [ ] `src/lib.rs` keeps its crate doc, declares `mod process;` and re-exports the four items.

## Details

TypeScript's runner is `spawnWithTimeout` in `src/harness/process.ts`, and
its line handling is `EventStreamParser` in `src/harness/stream.ts`. Read
them only to check a rule; the delta is the contract. Rust code never
imports or calls anything under `src/`.

Run each script as the program `/bin/sh` with the arguments `-c` and the
script, since the child has no `PATH` unless the row gives one. Make each
temporary folder under `env!("CARGO_TARGET_TMPDIR")`. Every script in the
table ends on its own within about 10 seconds, so a mutant that drops a
stop or a kill fails the row's under-5-seconds assertion instead of
hanging the test run. Keep those scripts exactly as the table writes them.

Signal the program only while its exit has not been received, so a
reaped pid is never signalled.

cargo-mutants runs on every line this task adds. The exit code mapping,
the blank-line rule, the trailing partial line, the stop, the kill and
the bounded wait for stdout after exit must each change a value a row
checks. Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-kernel-harnesses -f <file> -o "$(mktemp -d)"` on
each new source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE`
set to `openspec/changes/242-rust-harness-process`, so the link gate
corpus test sees this change's new requirements.
