## Details

TypeScript's adapter is `buildPiArgs` in `src/harness/pi/pi-args.ts`,
`processPiStdoutLine` in `pi-stream.ts`, `piToolSummary` and
`toProjectRelative` in `pi-tools.ts`, and `relativizeToolSummary` in
`src/core/run/summary.ts`. Read them only to check a rule; the delta and
the goldens are the contract. Rust code never imports or calls anything
under `src/`.

Rules that are easy to miss, each visible in `golden/pi-edges-events.json`:

- The summary is cut to 60 characters before the root is stripped, so
  line 15 ends `echo /work/proje`.
- `/work/project2/x` is not stripped; `"/work/project"` becomes `"."`.
- A `tool_execution_end` with no `toolName` still counts through the
  tool remembered for its `toolCallId` (line 7).
- `isError` missing is not `false`, so line 10 gives nothing.
- `/work/other/notes.md` becomes `../other/notes.md`.

If a golden test fails, the translation is wrong. Say in `## Deviated`
which rule you found and how you matched it.

cargo-mutants runs on every line this task adds. If the goldens leave a
branch unchecked, such as the root being `/` or empty, a path equal to
the root, or a negative `attempt`, add the case to
`tests/pi_stream_edges.rs` with values taken from the delta's rules. Before
exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-kernel-harnesses -f <file> -o "$(mktemp -d)"` on
each new source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE`
set to `openspec/changes/242-rust-harness-process`.
