# Task 5 — queue delivery report

Status: complete. Re-run of prior attempt 2 after the amended task declared
`tests: modify: true` and added `tests/report-json.test.ts` to `scope`; the
prior `undeclared_test_change` is therefore resolved.

## Changed

- `src/core/queue-report-detail.ts` (new, 209 lines): report-only projection with
  `QueueReportPlanning`/`Item`/`Failure`/`Rejection` types, `emptyQueueReport`,
  per-item projection, active-failure reason enrichment, and retained-rejection
  rows. Elapsed time derives from the earliest valid `plan_started` across all
  associated active/archived/rejected attempts and the landed association's valid
  typed `archived` event; missing/invalid/reversed endpoints yield `null` with no
  filesystem-time inference. Failure reasons read defensively with
  `parseFrontmatter` from the canonical regressed/dead marker (change target
  `change`), defaulting to `unavailable`. Rejection rows read each retained
  rejected folder's `.run/rejected.md`, keep one row per attempt, and sort by
  numeric change.
- `src/core/queue-report.ts` (new, 74 lines): stable `QueueReport` view and
  `readQueueReport`. Returns the deterministic unconfigured empty view when
  `openspec/queue.md` is absent; otherwise reuses the `src/core/queue.ts` facade
  (`projectQueue`, `readQueuePlanningUsage`, `findActiveQueueFailures`,
  `getQueuePath`) and composes the derivation module.
- `src/core/report.ts`: `MetricsReport` gains `readonly queue: QueueReport`;
  `getMetricsReport` reads it once; `formatMetricsReport` adds a concise `Queue`
  section (landed progress, planning sessions/cost/coverage, covered item wall
  times, active failures, retained rejections) and an explicit
  `(not configured)` line when no queue exists. Numeric cost stays in the object;
  text uses the existing `formatCost`.
- `src/cli/report.ts`: stable `toStableMetrics` projection adds the top-level
  `queue` key with numeric cost and no formatted string.
- `fixture/report/expected.json`: explicit unconfigured `queue` block added
  between `planning` and `specs`; no queue data retrofitted into fixtures.
- `tests/report-json.test.ts`: expected top-level key list plus `queue` and
  `queue.planning` key-shape assertions updated.
- `tests/report-queue.test.ts` (new): focused coverage for the unconfigured view,
  malformed configured queue, item order/state/drift, full and partial cost
  coverage across active/archived/rejected attempts, earliest-plan-start elapsed
  time, missing/reversed endpoints, active task and change failure reasons with
  unavailable fallback, retained rejection rows with malformed metadata, text
  output, and stable JSON determinism.
