Verified implementation already in the tree:

- `src/core/config-queue.ts` (`QueueConfig`, `validateQueueConfig`): a present
  `queue` block is atomic; both ceilings must be finite non-negative numbers;
  absent, partial, string, negative, NaN, Infinity, array, and non-object
  blocks are rejected clearly. `src/core/config.ts` re-exports the type and
  merges the validated block; `src/index.ts` re-exports `QueueConfig`.
- `src/core/queue-planning.ts`: `readQueuePlanningUsage` uses
  `scanQueueAssociations(..., null)`, so valid non-empty `queue_item` briefs
  across active, archived, and rejected locations count even when the slug is
  no longer in `openspec/queue.md`; malformed lines are dropped by
  `readPlanRecords` and non-queue changes are never scanned.
  `aggregatePlanUsage` counts each valid `plan_started` once, sums cost only
  from a single start with a single correlated exit whose cost is finite
  (recorded zero included; non-finite cost is normalized to null at parse
  time), and marks coverage incomplete for duplicate/missing/null-cost exits.
  `evaluateQueueBudget` refuses when both ceilings are absent, always enforces
  `sessions + 1 > maxPlanningSessions`, enforces `cost >= maxPlanningCost` only
  with complete coverage, and otherwise returns one factual incompleteness
  notice.
- `src/core/queue.ts` is the stable facade that re-exports the above for
  `src/cli/plan.ts` and the tests.
- `src/cli/plan-queue.ts` `prepareQueueSelection` calls `prepareQueuePlan` with
  `enforceBudget: !print`, prints refusals to stderr with exit code 1 and the
  incomplete-coverage notice before `createNewSpec` runs. `src/cli/plan.ts`
  feeds the selection into the unchanged create/resume, print, adapter,
  manifest, and telemetry sequence. Print mode bypasses only the two spend
  gates.
