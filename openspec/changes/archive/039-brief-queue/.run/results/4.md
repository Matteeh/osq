# Task 4 — queue/config/plan source decomposition

## Changed

- `src/core/queue.ts`: replaced the 526-line implementation with a small
  re-export facade. Every previously exported queue type and function still
  resolves through this path, and no extracted module imports it.
- `src/core/queue-parser.ts` (new, 93 lines): `QueueItem`, `getQueuePath`,
  `parseQueue`, `readQueue`, section hashing, and all heading/slug/dependency
  validation moved verbatim.
- `src/core/queue-state.ts` (new, 246 lines): association scanning,
  `selectAssociation`, projection (`projectQueue`), active-failure derivation
  (`findActiveQueueFailures`), and `formatQueue`. Exports the internal
  `readQueueState` snapshot, `scanQueueAssociations`, and `QueueAssociation` /
  `QueueAssociationGroups` / `QueueStateSnapshot` types for planning (and task 5).
- `src/core/queue-planning.ts` (new, 221 lines): planning usage aggregation,
  budget evaluation, next-item selection and `prepareQueuePlan`. Dependency
  direction is parser → state → planning.
- `src/core/config-queue.ts` (new, 32 lines): `QueueConfig` and
  `validateQueueConfig` moved out of `config.ts`.
- `src/core/config.ts` (242 lines): imports and re-exports `QueueConfig` from
  `config-queue.ts`; `OsqConfig`, `OsqUserConfig`, `DEFAULT_CONFIG`,
  `defineConfig`, and `loadConfig` behavior, defaults, environment handling, and
  error text are byte-compatible.
- `src/cli/plan-queue.ts` (new, 176 lines): option-mode validation
  (`validatePlanModeOptions`), read-only queue preparation plus refusal/notice
  reporting (`prepareQueueSelection`), landed-dependency prompt context
  (`buildOpeningPrompt`), and queue change seeding (`createQueueChange`).
- `src/cli/plan.ts` (207 lines): keeps `readBriefInput`, `planCommand`, and
  re-exports `formatBriefContent`/`buildOpeningPrompt`, preserving the exact
  create/resume, print, adapter, manifest, and planning-telemetry sequence.

## Deviated

- The queue-specific orchestration alone could not remove the 74 lines needed to
  bring `plan.ts` under budget, so `plan-queue.ts` also hosts the shared plan
  command seeding helpers (`createChange`, `writeBriefAndManifest`) and
  `formatBriefContent`. `formatBriefContent` is re-exported from `plan.ts`, so
  `tests/plan*.test.ts` keeps its established import path and byte behavior; no
  helper changed. This is a budget-forced expansion of the extraction surface.
- `queue-state.ts` exposes `readQueueState`, `scanQueueAssociations`, and their
  association types through the facade. This is beyond planning's immediate
  needs, but task 5 requires archive/rejection association detail and the task
  details ask that report derivation not reimplement scanning/state rules.
- Doc comments in the extracted modules were shortened (not code) to keep
  `queue-state.ts` at 246 lines.

## Drift against features/

- None. Behavior is unchanged: the read-only queue parser, filesystem-derived
  state projection, failure gate, rejection/replan gate, and spend gates match
  the `cli-foundation`, `status-inspection`, and `metrics-and-reporting` deltas.
  The module-boundary requirement is met without touching the line-budget allow
  list, adding a dependency, changing a config field, output, event shape, or
  introducing a cache/alternate path.
