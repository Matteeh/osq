## Acceptance

- [ ] Public configuration exports `QueueConfig` and accepts an optional `queue` block only when both `maxPlanningSessions` and `maxPlanningCost` are finite non-negative numbers; invalid, partial, string, negative, NaN, and infinite values are rejected clearly.
- [ ] A non-print `plan --next` requires both queue ceilings, while `osq queue`, ordinary `plan <name>`, and `plan --next --print` retain their behavior when the queue config block is absent.
- [ ] Planning-session usage counts valid `plan_started` records across queue-associated active, archived, and rejected folders, including retained attempts for slugs no longer present in the current queue, without counting malformed records or non-queue changes.
- [ ] The session gate refuses before folder creation when one more launch would exceed `maxPlanningSessions`, and exact-boundary and zero-limit cases are covered.
- [ ] Cost is summed only from finite recorded cost on correlated exits, and coverage is complete only when every counted start has a correlated exit with finite cost, including observed zero.
- [ ] Complete coverage refuses before mutation when recorded cost has reached `maxPlanningCost`; incomplete coverage ignores only the cost gate, prints one explicit note, and continues to enforce the session gate.
- [ ] All budget refusals and notices leave queue, change folders, planning logs, and harness spawn records unchanged, while ordinary planning telemetry tests remain green.

## Details

Add `QueueConfig` beside the existing public config types and validate it in
`defineConfig`; do not invent default monetary or session limits. Absence is
valid for repositories that do not use non-print next-item planning, but a
present block is atomic and must contain both values. Export the type from
`src/index.ts`. Do not add a path setting for the queue.

Build the queue planning aggregate from the existing `readPlanRecords` or
`readPlanningSessions` functions. Discover queue changes by valid non-empty
`queue_item` brief metadata across all three canonical locations, rather than
only associations to current parsed items; deleting or renaming a queue
section must not erase already incurred planning spend. Count each valid start
once. A duplicate or missing exit leaves cost coverage incomplete. A finite
zero cost is covered, while token coverage does not imply cost coverage.

Run the gates after all read-only queue failure and eligibility checks but
before `createNewSpec`, manifest writes, plan records, or adapter spawning.
The session condition is `current sessions + 1` exceeding the maximum. With
complete cost coverage, a total equal to or above the cost ceiling refuses
because another session would begin beyond the recorded ceiling; when there
are no prior sessions, coverage is complete. Print mode neither spends nor
records a session and bypasses only the two spend gates, not syntax, queue,
failure, dependency, or rejection checks.

Use injected adapters and captured console output in focused tests. Snapshot
directory entries and every existing `plan.jsonl` before refused calls. Keep
the note factual: recorded cost coverage is incomplete, so the cost ceiling is
not enforced. Do not estimate cost, use token presence as a proxy, or change
the existing planning record schema.
