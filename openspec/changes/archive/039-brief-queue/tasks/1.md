## Acceptance

- [ ] The real CLI registers `queue`, reads only `openspec/queue.md`, and renders every valid item in source order without changing the queue file's bytes or metadata.
- [ ] The parser accepts exact `## [slug] Title` headings, one `Depends on:` line with `nothing` or comma-separated earlier slugs, and a verbatim non-empty brief body; it returns a `sha256:` digest of each complete raw section.
- [ ] Missing files, malformed headings or dependency lines, invalid or duplicate slugs, empty titles or bodies, duplicate dependencies, and unknown, self, or forward dependencies fail with the queue path and item context.
- [ ] Associations come only from `queue_item` in `brief.md` beneath canonical active, archive, and rejected directories, and malformed unrelated folders cannot hide otherwise valid queue items.
- [ ] State precedence is landed, active dead/regressed as dead, running, approved, planned, rejected, then unplanned; associated rows carry the selected change id and retain a deterministic rejected-attempt count.
- [ ] Each row derives unmet queue dependencies and `changed since planned` from current landed associations and the selected change's `queue_hash`, with no state cached between calls.
- [ ] Text output is deterministic, includes change ids, rejection counts, unmet dependencies, and drift where applicable, and tests exercise parsing and formatting through `createProgram` rather than only private helpers.

## Details

Add a pure queue parser and a filesystem projection in `src/core/queue.ts`.
Reuse `parseFrontmatter`, `deriveSpecState`, `compareNumericPrefix`, and the
canonical `getChangesDir`, `getArchiveDir`, and `getRejectedDir` helpers. Hash
the UTF-8 bytes beginning at an item heading and ending immediately before the
next matching item heading or EOF; do not reconstruct markdown before hashing.
Permit ordinary `###` and deeper headings inside a brief. Treat only headings
matching the queue item form as item boundaries.

Use the slug grammar already produced by `slugify`: lowercase ASCII letters
and digits separated by single hyphens. The dependency line is the first
non-blank line after the heading. Trim dependency tokens for lookup while
keeping the brief body text available for later writing. A dependency must
already have appeared in file order, which makes self, forward, and cyclic
references invalid without a separate graph algorithm.

Scan active directory entries without treating `archive` or `rejected` as
active changes. `queue_item` establishes association even when `queue_hash` is
missing; a missing or non-string hash is drifted because equality cannot be
established. Prefer an archived association, then one active association, then
the most recent rejected folder by numeric order. Preserve the total rejected
folder count even when an active replan exists. If more than one active or
archived association exists for one slug, report an actionable ambiguous-state
error instead of choosing silently.

Map `deriveSpecState` values deliberately: `unapproved` becomes planned;
`regressed` and `dead` become dead; `running` remains running; and approved
`blocked`, `pending`, or `done` becomes approved until archival. Queue
dependency readiness is stricter than task dependency state: only an archived
queue association is landed.

Keep `src/cli/queue.ts` thin: load configuration, obtain and format the queue
projection, and print it. Register the command in `createProgram`. All tests
create disposable repositories, cover active/archive/rejected marker
combinations, and compare queue file bytes and stat values before and after the
command. Do not introduce JSON output, watcher behavior, report behavior, or
planning mutation in this task.
