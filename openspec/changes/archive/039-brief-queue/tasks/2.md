## Acceptance

- [ ] The real CLI accepts either `plan <name>` with its existing options or `plan --next [--replan] [--print]`, rejects missing or conflicting modes, and keeps ordinary new and resumed planning byte-compatible where queue behavior is not selected.
- [ ] Next-item selection halts first on every active queue-associated dead or regressed task or change target, naming each deterministic target and exact `osq retry <id> <task|change>` remediation before any file is written.
- [ ] Selection otherwise chooses exactly the first unplanned item in file order whose queue dependencies are landed, skips active and landed items, and exits without mutation with an actionable summary when no item is eligible.
- [ ] A rejected first eligible item refuses without `--replan`; with `--replan` it creates one new active attempt while preserving every rejected folder, marker, event, reason, and rejection count.
- [ ] The created folder is `<next-id>-<queue-slug>` with numbering across active, archived, and rejected folders, its proposal uses the queue title and landed dependency change ids, and unrelated template content remains intact.
- [ ] `brief.md` contains only the item body plus existing planner/date metadata and exact `queue_item`/`queue_hash` metadata; the opening prompt uses the existing launch path and identifies landed dependency archive paths without exposing later queue items or the complete queue file.
- [ ] A three-item disposable fixture drives the real source CLI with the mock harness through `plan --next --print`, authored mock plan output, `approve`, and `watch --once`; it asserts every derived transition, a dead-task halt, retry preservation, eventual landing, and one newly planned item per invocation.

## Details

Make the Commander argument for `plan` optional and add `--next` and
`--replan`. Validate the mode before loading brief input or creating a folder:
ordinary planning still requires a name, next mode forbids a name and
`--brief`, and `--replan` is valid only with `--next`. Preserve the `-print`
normalization and all existing direct `planCommand` callers.

Keep queue selection and preflight reads in `src/core/queue.ts`, then have the
thin CLI pass the selected body and metadata into the existing plan path.
Perform queue validation, association projection, global active-failure checks,
eligibility selection, and rejection permission checks before `createNewSpec`.
For multiple active failures, sort by numeric change and target and include all
retry commands in one refusal. Historical attempt-suffixed markers are not
active failures.

Extend `createNewSpec` just enough to accept an explicit folder slug, display
title, and initial dependency ids while retaining existing calls. Update
`getNextSpecNumber` to scan the canonical rejected directory as well as active
and archive entries so rejection followed by replan cannot reuse an id. Write
the proposal frontmatter through safe YAML handling or the existing parser
conventions; do not replace the proposal template body.

Extend `formatBriefContent` through optional metadata rather than creating a
second formatter. The queue body must not contain its heading or dependency
line. Add landed archive paths to the change context in `buildOpeningPrompt`
without reading their full contents and without reading or embedding
`openspec/queue.md`. After preparation, print and interactive modes follow the
same prompt construction, adapter selection, lifecycle recording, usage read,
and exit propagation as ordinary planning. Print mode creates the change but
does not spawn or append `plan.jsonl`.

Build `tests/queue-watch.test.ts` in temporary directories with
`installFakeValidator`, scaffolded templates, the source CLI, and the mock
harness. After each printed prompt, materialize the minimal valid planner
output in the generated proposal, task list, task, and delta files before
approval. Make the middle item's verify fail once through fixture state outside
the authored change folder, assert that the third item cannot plan, then use
the real approval/retry/watch path to land it. Do not approve this repository's
039 change or write any marker in it.
