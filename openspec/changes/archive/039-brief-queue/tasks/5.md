## Acceptance

- [ ] `MetricsReport` and stable JSON expose a top-level queue view with `configured`, landed and total item counts, planning sessions, recorded cost, cost coverage, ordered item rows, active failures, and retained rejections.
- [ ] A missing `openspec/queue.md` yields a deterministic unconfigured empty queue view and leaves every existing report aggregate unchanged; a malformed configured queue fails with its actionable queue parse error.
- [ ] Queue planning totals include valid sessions and finite costs from associated active, archived, and rejected attempts, with cost coverage based on finite recorded cost rather than general usage coverage.
- [ ] Every item row carries slug, title, state, selected change id or null, rejection count, drift, and nullable planned-to-landed seconds derived only from its earliest valid plan start and valid archived event in chronological order.
- [ ] Active dead and regressed task or change targets include their marker reason when valid and an unavailable value otherwise; retained rejection rows include queue slug, change, reason, and timestamp without collapsing multiple attempts.
- [ ] Text output adds a concise `Queue` section with landed progress, planning sessions and cost coverage, covered item wall times, dead targets, and rejected attempts; JSON ordering and queue item order are deterministic.
- [ ] Focused malformed-data tests, the checked-in report fixture, and the source-line budget pass while existing current-state, history, planning, cycle, coverage, token, cost, and rejection metrics retain their established values.

## Details

Reuse `projectQueue`, `findActiveQueueFailures`, and
`readQueuePlanningUsage` through the stable `src/core/queue.ts` facade instead
of independently reimplementing established queue parsing, state, failure, or
spend rules. Keep every task-4 queue, configuration, and planning module frozen.
Place report-only archive association, rejection-detail, and elapsed-time
derivation in one or more `src/core/queue-report*.ts` modules, each within the
source-line budget, and consume that projection from `src/core/report.ts`.

Keep the existing global planning block unchanged: its deliberate exclusion of
rejected folders is separate from the queue view, which includes rejected queue
attempts for queue spend. Add the queue block to `MetricsReport`, the stable
projection in `src/cli/report.ts`, and `formatMetricsReport`.

For an unconfigured repository, return zero counts, zero cost, zero coverage,
and empty arrays with `configured: false`; do not make ordinary reports depend
on a queue file. Once the file exists, parsing errors remain errors rather than
silently presenting an empty queue. Keep numeric cost unformatted in JSON and
include the existing `formatCost` rendering for text.

Derive planned-to-landed wall seconds from the earliest valid `plan_started`
timestamp among all attempts for the item and the archived association's valid
typed `archived` event. Return null when either endpoint is missing, invalid, or
reversed. Do not use brief dates, manifest timestamps, mtimes, ctimes, or folder
numbering as time substitutes.

Read active dead and regressed markers defensively using `parseFrontmatter`.
Represent a change-level regression target as `change`; sort active failures by
numeric change and target. Read each retained rejected folder's canonical
marker for reason and timestamp, preserve one row per attempt, and sort by
numeric change. Location alone is enough to retain the queue rejection row,
while malformed metadata is displayed as unavailable rather than dropping the
attempt; this does not alter the existing rejection-history rule that requires
a valid event.

Add an explicit queue block to `fixture/report/expected.json` for its current
no-queue state. Focused temporary fixtures cover complete and partial cost,
multiple rejections, active task and change failures, drift, missing endpoints,
and a fully timed landing. Update the established top-level and queue-shape
assertions in `tests/report-json.test.ts`; other existing report tests remain
frozen. Do not retrofit queue data into unrelated fixture changes merely to
make the new block non-empty. Do not modify `tests/line-budget.test.ts` or its
allow list. Run the task verify and `pnpm verify` before exit.
