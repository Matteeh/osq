## Details

Port `merge`, `mergeAbort` and `unmergedPaths` from `git-vcs-merge.ts`,
and `fastForward`, `changedPaths` and `blockedPaths` from
`git-vcs-land.ts`. The writes of task 1 and the reads stay as they are.

The fast-forward repository's uncommitted state is chosen so the blocked
paths come out of order before sorting: `status()` lists `m.txt` before
`z.txt`, whose `from` is `c.txt`. Check "a merge in progress" by whether
the file `.git/MERGE_HEAD` exists under the repository.
Give every test its own scratch folder name, and keep each test function
under clippy's 80-line limit with named setup and check helpers.

cargo-mutants runs on every line this task adds, so each condition must
change a value a row checks: the `squash` choice, the empty conflict list
that falls back to `VcsError::Failed`, the `path` and `from` tests of the
blocked rule, the sort, and the fall-back to no changed paths when the diff
fails (the `nope` row). Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-kernel-vcs -f <file> -o "$(mktemp -d)"` on each new
or changed source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE`
set to `openspec/changes/245-rust-vcs-writes`.

## Scenarios

- rust-vcs: Merges on a repository
- rust-vcs: Fast-forwards on a repository
- rust-vcs: Merge writes with a program that cannot start
