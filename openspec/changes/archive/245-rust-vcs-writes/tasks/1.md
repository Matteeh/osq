## Acceptance

- [ ] `src/error.rs` gains `VcsError::Failed { command: String, output: String }`, displaying as `<command> failed: <output>` with `source()` giving `None`, as rust-vcs "Git command" says; `Spawn` and its display stay as they are.
- [ ] `src/git.rs` gains one private runner that every read and write goes through: it builds the command with `command`, sets a write's own variables after it, gives an optional text as standard input, and returns the exit's success with the decoded standard output and standard error. The existing private `read` keeps its answers by calling it, and a private write helper turns a failed exit into `VcsError::Failed` with the joined command and stdout followed by stderr.
- [ ] `src/port.rs` says the trait is osq's version-control port, and the `Vcs` trait gains the five writes of "Branch and worktree writes" and the three of "Commit writes", each `&self`, returning `Result<_, VcsError>`, with `&str` parameters and `&[&str]` for `paths` and `extra_parents`. New `src/git/write.rs` holds each write's git arguments and the pure author split; `src/git.rs` declares `mod write;` and its `impl Vcs for GitVcs` calls them.
- [ ] `src/lib.rs` keeps its re-exports, and `Cargo.toml` and `Cargo.lock` do not change.
- [ ] In `tests/git_command.rs` and `tests/history_reads.rs` only the `let VcsError::Spawn { command, source } = &error;` line of `assert_spawn` changes, to a `let ... else` that panics on any other variant.
- [ ] New `tests/branch_and_commit_writes.rs` proves "Branch and worktree writes on a repository", "Branch and worktree writes with a program that cannot start", "Stage and commit on a repository", "Commit from a tree", "Commit from a tree that git is set to sign" and "Commit writes with a program that cannot start", with the literal values of their tables, one assertion per row and per "Then" fact.
- [ ] Every new trait method's doc ends with `Implements: rust-vcs/branch-and-worktree-writes` or `Implements: rust-vcs/commit-writes`, and each test's one-line doc names `Covers: rust-vcs/<scenario>` in kebab-case, such as `Covers: rust-vcs/commit-from-a-tree`.

## Details

Port `createBranch`, `worktreeAdd`, `worktreeRemove`, `worktreePrune` and
`commit` from `git-vcs-write.ts`, `stage` and `renameBranch` from
`git-vcs-merge.ts`, and `commitTree`, `parseAuthor` and `signCommits` from
`git-vcs-land.ts`. Where TypeScript writes the message to a temporary file
and passes `-F <file>`, pass `-F -` and write the message to the child's
standard input, as the delta says; spawn with piped standard input, write
the text, drop the pipe, then wait for the output. Implement the author
split with `str` methods, not a regex crate. The reads of change 241 keep
their answers and their tests pass unchanged apart from the one line above.

The new test file declares `mod support;` and uses `tests/support/mod.rs`
unchanged, calling every helper it holds (`Scratch::new`, `path`, `git`,
`write` and `vcs`), since an unused helper is a dead-code warning and
clippy denies warnings. Add the committer and date variables to the
`GitVcs` with `with_env`, as "Commit writes" says. Give every test its own
scratch folder name, since tests run in parallel. Build each scenario's
repository in its own test, and keep each test function under clippy's
80-line limit by moving repository setup and repeated checks into named
helpers in the test file. Check a refused row with `matches!` or a
`let ... else` on `VcsError::Failed` and `output.contains(...)`.

cargo-mutants runs on every line this task adds, so each condition must
change a value a row checks: the empty `paths` checks of `stage` and
`commit` (the `stage(&[])` and `commit(&[], ...)` missing-program rows),
the `--only` arguments, each `-p` and the `-S` test against `true`, the
author split's `>` and `<` checks, and the success test in the write
helper. Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-kernel-vcs -f <file> -o "$(mktemp -d)"` on each new
or changed source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE`
set to `openspec/changes/245-rust-vcs-writes`, so the link gate corpus test
sees this change's requirements.
