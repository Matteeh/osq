## Changed

- `crates/kernel/vcs/src/port.rs`: added `MergeOutcome` (`Clean`, `Conflict { paths }`) and `FastForward` (`Done { changed }`, `Blocked { paths }`), each deriving `Debug`, `Clone`, `PartialEq` and `Eq`, and the `Vcs` trait's `merge`, `merge_abort` and `fast_forward`, documented with `Implements: rust-vcs/merge-writes`.
- `crates/kernel/vcs/src/lib.rs`: also re-exports `MergeOutcome` and `FastForward`; nothing else changed.
- `crates/kernel/vcs/src/git/merge.rs`: new module holding the merge arguments, the NUL path split, the shared sort-and-dedupe of paths, and the blocked-path rule; `merge`, `merge_abort` and `fast_forward` run through the task 1 runner and write helper, with `fast_forward` reading `status()` first.
- `crates/kernel/vcs/src/git.rs`: declares `mod merge;` and delegates the three new trait methods to it.
- `crates/kernel/vcs/tests/merge_writes.rs`: new scenario tests for "Merges on a repository", "Fast-forwards on a repository" and "Merge writes with a program that cannot start", using `tests/support/mod.rs` unchanged and a committer environment for git's merge identity.

## Deviated

- `merge` propagates `VcsError::Spawn` from its own command before reading the conflicted paths, so a missing program reports the merge's command as the missing-program table names; only a `VcsError::Failed` merge falls through to the `diff --diff-filter=U` read.
- The refused `merge_abort` row also asserts the command, though the scenario only names the phrase.
