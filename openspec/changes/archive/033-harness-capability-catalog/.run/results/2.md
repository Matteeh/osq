# Task 2 result — Generic diagnostics, preflight, planning, and attribution

## Changed

- `src/core/manifest.ts`: deleted the private `resolveModel` harness-name switch
  and the per-harness effort call. `buildManifest` now derives `harness`, `model`
  (or `default`) and `effort` (or null) from `resolveExecutorIdentity(config)`.
  `planner` remains `config.planner?.model ?? null`, preserving the 032 schema and
  planner semantics.
- `src/watcher/loop.ts`: removed the `preflightOpencode` import and the
  `adapter.name === 'opencode' || config.harness === 'opencode' || ... codex` gate
  with its adapter-specific fallback. Startup now invokes the supplied adapter's
  optional `preflight` port directly, with no harness-name comparison and no
  legacy fallback.
- `src/watcher/spawn.ts`: the task `started` event model now comes from
  `resolveExecutorIdentity(config).model` (shared resolver) instead of the
  `resolveAdapterModel` indirection. Event shape unchanged.
- `src/core/doctor.ts`: no-binary harness message generalized to
  `no external executable required`; binary resolution still flows through the
  catalog-backed `harnessBinary`, the probe seam and configured timeout are
  unchanged.
- Added `tests/harness-architecture.test.ts`: reads registered names and config
  sections from `HARNESS_CATALOG`, strips comments, and rejects harness-name
  comparisons and cross-harness config fallbacks in the generic consumers
  (`src/core/config*.ts`, `doctor.ts`, `manifest.ts`, `src/cli/plan.ts`,
  `src/watcher/loop.ts`, `src/watcher/spawn.ts`). Includes a self-check that the
  detector fires on synthetic branches and ignores prose/comments.
- Added `tests/harness-generic-workflows.test.ts`: real entry-point coverage with
  disposable fixture copies and fake executables (no network/auth/TTY) for
  `runDoctorChecks`/`doctorCommand` (agy, opencode, codex probes; mock no-binary;
  missing/nonzero/timeout), `buildManifest`/`approveSpec` attribution,
  `startWatcher` preflight (generic port, absent port, real opencode/codex
  executables), task `started` events for agy/opencode/mock/codex, and
  `planCommand` brief metadata plus interactive model/agent for implicit,
  explicit, and mixed planner selections.

## Deviated

- Watcher preflight is invoked only when the selected catalog entry declares an
  external executable (`entry.executable(config) !== null`). A pure
  "call whenever present" implementation would invoke the preflight that the
  frozen `tests/watcher-preflight.test.ts` attaches to a `MockAdapter` with
  `harness: 'mock'`; that test asserts the port is not called. That test is in
  this task's verify, is not in scope, and the task forbids test edits
  (`tests.modify: false`), so the catalog-executable capability gate is the only
  design that keeps it green. There is no harness-name comparison or
  adapter-specific fallback; the gate reuses the catalog's no-binary capability.
- The `started` event keeps `harness: adapter.name` rather than
  `identity.harness`. The frozen `tests/runner-lifecycle-logging.test.ts` asserts
  a stub adapter's own name while expecting the executor-identity model, so the
  model is shared-resolved while the harness field stays the executing adapter.
  The `planCommand` decision points already consumed `resolvePlannerSelection`
  from task 1, so `src/cli/plan.ts` needed no further edit.
