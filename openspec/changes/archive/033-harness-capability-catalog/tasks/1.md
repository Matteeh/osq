## Acceptance

- [ ] An immutable catalog contains every supported harness exactly once and exposes normalized lookup, ordered available names, executable resolution, executor identity, planner selection, and planner-agent capability.
- [ ] validatePlannerConfig accepts only catalogued harnesses, retains the required non-empty model, and rejects unsupported optional settings with the selected harness and setting in the error.
- [ ] getHarnessAdapter resolves through a factory map typed exhaustively by the catalog-derived HarnessName and reports catalog names for unknown adapters.
- [ ] Executor identity returns only the selected harness's effective model or default and applicable effort or null, with no fallback to another harness configuration.
- [ ] Planner selection uses explicit planner values when configured and otherwise the selected executor's catalog entry, including its supported default agent, without model or effort leakage.
- [ ] Public configuration exports and existing agy, OpenCode, mock, and Codex behavior and precedence remain compatible, and catalog contract tests cover lookup, factory parity, planner capabilities, native defaults, and mixed selections.

## Details

Create a configuration-safe catalog in `src/core/harness-catalog.ts`; core must not import `src/harness/**`. Keep adapter construction in `src/harness/index.ts`, with its factory object checked exhaustively against the catalog-derived `HarnessName`. The catalog is static application metadata, not mutable runtime state or dynamic plugin discovery.

Reuse `OsqConfig`, `PlannerConfig`, `validatePlannerConfig`, `getHarnessAdapter`, and the binary/model/config resolution helpers delivered by 032. Consolidate the supported planner harness set and the agy/OpenCode/Codex selection branches into catalog entries. Preserve case-insensitive lookup and deterministic error ordering. A catalog entry may declare no external executable for mock, whether planner.agent is supported, an optional planner-agent default, and how its already-loaded configuration resolves binary, model, and effort.

Expose named helpers for catalog lookup, available names, executor identity, and planner selection; do not add methods to `HarnessAdapter`. Executor identity uses the literal `default` sentinel when native selection leaves the model unspecified. Planner selection must distinguish the model value used in brief attribution from an absent model override passed to a native CLI. Explicit planner configuration never inherits executor effort or agent defaults from a different harness.

New tests use public configuration and adapter lookup entry points. Assert catalog and runtime factory key parity in addition to the compile-time exhaustive mapping. Existing tests named by verify are read-only regressions. Run the task verify and the change-level verify before exit, and record any pre-existing 032 failures without editing frozen tests.
