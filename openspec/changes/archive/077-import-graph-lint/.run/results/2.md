## Changed

- `src/core/foundation/config.ts`: `OsqLimits` and `DEFAULT_CONFIG.limits` gain
  `importGraphDepth: 2` and `maxListedImporters: 8`; the existing limits merge in
  `defineConfig` already carries them.
- New `src/core/spec/test-impact.ts` (181 lines): `frozenTestFindings` warns once
  per task whose existing scope a preexisting, unmodifiable `tests/` file
  reaches within `limits.importGraphDepth`, listing up to `maxListedImporters`
  importers nearest first as `<test> (<scoped file>)`, with the count, the direct
  count, and an `and <rest> more` tail. `verifyWithoutScopeFindings` warns when a
  task verify names only existing tests and none reaches the scope at any depth.
  Both read `reachImporters`/`reachImports`.
- New `src/core/spec/capability-impact.ts` (141 lines): `readCapabilityOwnership`
  reads every living `spec.md` with `parseCodeOwnership`; `ownerCapabilities`
  matches with `scopeCoversPath`; `undeclaredReadFindings` warns per capability
  that owns a directly imported, out-of-scope file when no owner is read or has a
  delta; `writeWithoutDeltaFindings` warns per resolved scope path owned only by
  capabilities with no delta. No graph needed for the write warning.
- New `src/core/spec/impact-lint.ts` (76 lines): `collectImpactFindings` runs
  both modules for a change, reading delta capability names from
  `<folder>/specs/*` and the living specs, and returns warnings only.
- `src/core/spec/linter.ts`: `LintOptions` gains optional `importGraph`;
  `lintChangeFolder` builds one (skipping the OpenSpec root) when none is passed
  and adds each `collectImpactFindings` finding as the change's own.
- `src/cli/lint.ts`: `lintCommand` builds the graph once with `buildImportGraph`,
  skipping `config.paths.openspecRoot`, and passes it to every change.
- `README.md`: the lint table lists the four import-graph warnings.
- New `tests/impact-lint.test.ts` (11 tests) lints temporary repositories built
  with `installFakeValidator`/`scaffoldProject` and living specs with Code
  ownership, asserting severity, file, requirement, and section as well as
  message: both frozen-reach scenarios, the short-list warning text, the
  `maxListedImporters` cap, the `importGraphDepth` 3 deeper reach, the
  undeclared read and its clearing via `features.reads`, the write-without-delta
  warning, the verify warning and its non-firing, the Python-only repository
  through `lintCommand`, and two changes linted by one run.

## Deviated

- The read warning skips a file entirely when any of its owners is declared; the
  spec says the file warns "when no owner ... is in features.reads or has a
  delta", so a file co-owned by a declared and an undeclared capability emits
  nothing.
- `verifiedTestPaths` only counts test operands present in the import graph, so a
  `.py` test named in a verify does not warn and the Python-only repository can
  emit only the write warning. Glob operands expand through `resolveScope`, and a
  missing exact test or unmatched glob suppresses the warning.
- `frozenTestFindings` pairs a reached test with the first sorted scoped file in
  its transitive imports, as task 1's result anticipated for its chosen return
  shapes.
- The spec fixes the frozen-test and write warning text but not the read text; I
  chose `Scoped files import code owned by the <cap> capability: <files>. Add
  <cap> to features.reads`, and the test asserts fragments rather than exact
  bytes.

## Missing context
