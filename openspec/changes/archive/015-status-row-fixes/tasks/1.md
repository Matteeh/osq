## Acceptance
- [ ] Status line truncation moves into the logger's redraw() method
- [ ] redraw() constrains output to stream.columns (default 80) minus spinner frame and space, appending an ellipsis
- [ ] Logger never applies prefix formatting (such as [osq]) to status text
- [ ] formatTaskStatusRow and formatIdleStatus stop truncating and stop taking a terminalWidth parameter
- [ ] Test with columns 40 and 100-char status asserts written bytes are \r\x1b[2K + frame + space + 37 chars + ellipsis, with no [osq] prefix
- [ ] Tests verify status rows do not wrap across terminal boundaries or leave ghost characters on redraw

## Details

1. In `src/core/logger.ts`:
   - In `createLogger`:
     - Update `status(text: string)`: store `statusText = text` directly without running it through `render(text)`.
     - In `redraw()`: compute available columns as `(stream.columns ?? 80) - 2` (accounting for the 2-column `<frame> ` prefix).
     - If `statusText.length > availableColumns`, truncate to `availableColumns - 1` and append the ellipsis (`…`).
     - Write `${CLEAR_LINE}${SPINNER_FRAMES[frameIndex]} ${truncatedStatusText}`.
2. In `src/watcher/runner.ts`:
   - Remove `terminalWidth` parameter from `formatTaskStatusRow(taskNumber, stats)`.
   - Remove truncation logic from `formatTaskStatusRow`, assembling the full row string.
3. In `tests/logger-status.test.ts`:
   - Add test with fake stream having `columns: 40`, set 100-char status, and assert output is exactly `\r\x1b[2K` + frame + ` ` + 37 chars + `…` and does not contain `[osq]`.
   - Update existing tests that asserted `[osq]` on the status row to assert the raw un-prefixed status text.
