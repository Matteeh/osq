## Changed

- `src/watcher/runner.ts`
  - Added exported `relativizeToolSummary(summary: string, root: string = process.cwd()): string`:
    - Returns the summary unchanged when empty or when `root` is missing.
    - Normalizes `root` by stripping trailing `\`/`/` separators (keeps a bare
      filesystem root `/` or `\` intact, and bails out if it collapses to empty
      so it cannot become a regex that matches every separator).
    - Globally strips `${normalizedRoot}/` and `${normalizedRoot}\` from the summary.
    - Collapses an exact root match to `.` via a boundary lookahead
      (`$`, whitespace, or punctuation) so `/rootfoo` is not mangled.
  - `computeTaskHeartbeatStats` gained an optional `projectRoot?: string` parameter.
    The `tool` branch now stores
    `accumulator.lastToolSummary = relativizeToolSummary(summary, projectRoot)`;
    omitting `projectRoot` therefore falls back to `process.cwd()`.
  - The heartbeat timer in `runTask` passes `projectRoot` into
    `computeTaskHeartbeatStats(specFolderPath, taskNumber, startTime, projectRoot)`,
    so the live status row gets relativized summaries.
- `tests/runner-terminal-status.test.ts`
  - Imports `relativizeToolSummary`.
  - New `relativizeToolSummary` block: strips root + trailing separator (asserts no
    leading `/<path.sep>specs`), normalizes a trailing separator on the root, falls
    back to `process.cwd()`, leaves paths outside the root untouched, and maps an
    exact root match to `.`.
  - New `computeTaskHeartbeatStats` tests: relativizes an absolute summary against
    the supplied `projectRoot` while asserting `.run/events/1.jsonl` still contains
    the raw absolute summary; falls back to `process.cwd()` when `projectRoot` is
    omitted; renders the relativized path in `formatTaskStatusRow` with no leading
    slash before `specs`.
  - New end-to-end TTY test using a second fake OpenCode binary that emits an
    absolute `src/watcher/runner.ts` path: the live status row contains the relative
    path and no `/<path.sep>src/<path.sep>watcher`. This exercises the `runTask` →
    `computeTaskHeartbeatStats` plumbing that the unit tests cannot.
