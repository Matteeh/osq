# Task 1 result — status row fits the terminal

Verify: `node --import tsx --test tests/logger-status.test.ts` → 12 pass / 0 fail.

## Changed

- `src/core/logger.ts`
  - `LoggerOptions.stream` type now includes `columns?: number`.
  - Added `ELLIPSIS`, `SPINNER_PREFIX_WIDTH` (2), `DEFAULT_COLUMNS` (80) constants.
  - Added `fitStatusText(text)`: available = `(stream.columns ?? 80) - 2`; when the text
    overflows it keeps `available - 1` chars and appends `…` (empty when `available <= 0`).
  - `redraw()` now writes `CLEAR_LINE + frame + ' ' + fitStatusText(statusText)`.
  - `status(text)` stores the raw text (no `render()`), so `[prefix]` is never applied to
    the status row.
- `src/watcher/runner.ts`
  - `formatTaskStatusRow(taskNumber, stats)` dropped its `terminalWidth` parameter and all
    truncation logic; it now always assembles the full row, appending ` · <summary>` only
    when a tool summary exists.
  - Removed the now-unused `STATUS_SPINNER_PREFIX_WIDTH` constant. `truncateToWidth` /
    `ELLIPSIS` remain for `formatTaskStartedLine`.
- `tests/logger-status.test.ts`
  - `FakeStream` accepts an optional `columns`.
  - Status-row assertions no longer expect the `[osq]` prefix (prefix still asserted on
    log lines).
  - New test: `columns: 40`, 100-char status → exactly
    `\r\x1b[2K⠋ ` + 37 chars + `…`, and no `[osq]`.
  - New test: overflowing row's visible width stays `<= 40`; a shorter redraw starts from
    `\r\x1b[2K` and leaves no trailing/ghost characters.
