## Changed

- `src/watcher/runner.ts`
  - Added exported `formatTokens(tokens: number): string`:
    - `<1000` → `tokens.toString()`
    - `<1_000_000` → `(tokens / 1000).toFixed(1)`, rolling `'1000.0'` over to `'1.0M'`,
      otherwise `${k}k`
    - `>=1_000_000` → `${(tokens / 1_000_000).toFixed(1)}M`
  - `formatTaskStatusRow` now renders `${formatTokens(stats.totalTokens)} tokens`
    (cost still `${stats.cost.toFixed(4)}`).
  - `formatTaskHeartbeatLine` now renders `tokens: ${formatTokens(stats.totalTokens)}`.
- `tests/runner-terminal-status.test.ts`
  - Imports `formatTokens` and `formatTaskHeartbeatLine`.
  - `formatTaskStatusRow` primary assertion updated from `1500 tokens` to `1.5k tokens`.
  - New status-row test: `1_500_000` → `1.5M tokens` (and no `1500000 tokens`); `1500` → `1.5k tokens`.
  - New `formatTokens` table-driven test over `999`/`1000`/`999_949`/`999_950`/`1_000_000`
    (`999`, `1.0k`, `999.9k`, `1.0M`, `1.0M`).
  - New heartbeat test asserting the same abbreviation (`tokens: 1.5k`, not `tokens: 1500`).
  - Replaced the stale `truncates the tool summary ...` test (left over from task 1, it still
    passed a third width argument and asserted formatter truncation) with a test asserting the
    formatter assembles the full row untruncated — this was the only pre-existing red in the
    task's verify.
