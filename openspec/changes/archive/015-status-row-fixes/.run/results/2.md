# Task 2 result — exactly one outcome line per task

Verify: `node --import tsx --test tests/runner-outcome-logging.test.ts` → 15 pass / 0 fail.

## Changed

- `src/watcher/runner.ts`
  - Deleted `formatTaskOutcomeSummary` entirely (definition and export). No reference
    remains under `src/`.
  - `formatTaskOutcomeLine` now takes an optional `extra?: string`; dead lines render
    `${symbol} task ${n} dead (reason: ${reason}${extra ? `, ${extra}` : ''}, elapsed: ${s}s)`.
    The legacy `(passed)` suffix is gone: verified lines are `... verified (elapsed: ${s}s)`.
  - `logOutcome` in `runTask` now accepts `(success, reason?, extra?)` and forwards `extra`.
  - Removed the duplicate `logger?.info(formatTaskOutcomeSummary(...))` call at every
    completion/failure path (`spec_conflict` missing approval, `spec_conflict` hash mismatch,
    task-file-not-found `crashed`, `already_running`, spawn `crashed`/`timeout`, `no_result`,
    `verify_red`, success). All outcomes now route exclusively through `logOutcome`; the two
    detail strings still flow through as `extra` (`code: <exitCode>`, `timed_out: true`).
  - Control-flow comments in the `already_running` branch were preserved.
- `tests/runner-outcome-logging.test.ts`
  - Imports the runner namespace and asserts `'formatTaskOutcomeSummary' in runner === false`.
  - New pure-formatter block covers verified line (no `(passed)`), unicode symbols, all six
    failure reasons, and detail placement (`code: 7`, `timed_out: true`) before `elapsed`.
  - Replaced the summary-based `outcomeLine` helper with `outcomeLines`, which counts every
    line containing `task <n> verified` or `task <n> dead (reason:`.
  - End-to-end MockAdapter execution for the verified task and each dead path now asserts
    `outcomeLines(...).length === 1`, the new elapsed-bearing shape, and (for verified/dead)
    that stderr contains no `(passed)`.
