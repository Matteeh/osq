# Task 8 result — single-line task outcome logging

## Changed

- `src/watcher/runner.ts`
  - Added exported `formatTaskOutcomeSummary(taskNumber, success, reason?, extra?): string`. Pure formatter:
    - `success === true` -> `task <n> verified (passed)`
    - otherwise -> `task <n> dead (reason: <reason>)`, appending `, <extra>` when `extra` is provided.
  - Wired `logger?.info(formatTaskOutcomeSummary(...))` directly beside every marker write in `runTask`:
    - missing `.run/approved` -> dead `spec_conflict`
    - folder hash mismatch -> dead `spec_conflict`
    - task file not found -> dead `crashed`
    - lock not acquired -> `already_running` (log only; no marker, see Deviated)
    - agent non-zero exit -> dead `crashed, code: <exitCode>`
    - agent timed out -> dead `timeout`
    - no result file and no final text -> dead `no_result`
    - verify failed/timed out -> dead `verify_red` / `verify_red, timed_out: true`
    - done marker written -> `task <n> verified (passed)`
- `tests/runner-outcome-logging.test.ts` (new, the task's verify command) — 13 tests:
  - Unit coverage of `formatTaskOutcomeSummary`: pass line, dead line, extra detail (`timed_out: true`, `code: 7`), and single-line output for all seven expected lines.
  - Integration coverage with stderr capture + `createLogger('normal')` for the pass path and every dead path (spec_conflict, already_running, crashed with code, timeout, no_result, verify_red, verify_red+timed_out). Each dead test also asserts the matching `.run/dead/<n>.md` marker exists, so log and marker are exercised together.
  - A no-logger test asserts no outcome line is emitted when `runTask` is called without a logger.

## Deviated

- `already_running` is logged but no dead marker is written, preserving existing behavior. Task Details list `already_running` among dead-marker reasons and the spec's failure-reason table includes it, but `deriveTaskState` checks `dead/<n>.md` before `running/<n>.pid`; writing a dead marker for a task that is genuinely still running under another process would flip the spec to `dead` and stop retries. Logging alone satisfies the acceptance line ("logs whenever a dead marker is written") since no marker is written on this path.
- The `crashed` extra is only emitted when an exit code is known (agent non-zero exit). The task-file-not-found path logs `task <n> dead (reason: crashed)` with no `code:` token rather than the placeholder-empty `code: ` shown in the task example.
- `formatTaskOutcomeSummary` renders `reason: undefined` if called with `success === false` and no reason. The runner always passes a reason; the optional parameter is retained to match the task signature.

Real `osq watch` runs therefore pass no logger and emit no outcome lines; the outcome logging is only observable when a logger is supplied, as the tests do. `loop.ts` is outside this task's `scope`.
