# Task 6 result — agy stream-json event translation

## Changed

- `src/harness/agy.ts`
  - Imported `Logger` (type-only) from `../core/logger.js` and `ToolEventData` from `./types.js`.
  - `buildAgyArgs` now appends `--output-format stream-json` to the returned CLI argument array.
  - Added exported `AgyStreamTokensData` interface and `extractAgyTokens(event)`:
    - Reads `step_update.usage` (also accepts `result.usage`/`event.usage` for the exported helper).
    - `promptTokens = input_tokens || 0`, `candidateTokens = output_tokens || 0`, `cachedTokens = cache_read_tokens || 0`, `totalTokens = total_tokens || input + output`, `cost: 0`.
    - Returns `null` when no usage object exists.
  - Added exported `extractAgyToolEvent(event)`:
    - Requires `step_update.step_type === 'tool'`.
    - Tool name from `step_update.tool_name || tool_info.name` (also `step_update.name`).
    - Parameters resolved from `tool_info.parameters`, `step_update.parameters`, `tool_info.input`, `step_update.input`, `event.parameters`.
    - Command tools (`run_command`, `command_status`, `send_command_input`) summarize `CommandLine`/`command`/`cmd` truncated to 60 chars; file tools resolve path fields (`AbsolutePath`, `path`, `file_path`, `filePath`, `file`, `DirectoryPath`, `pattern`, ...); other tools fall back to 60 chars of param JSON.
  - Added `recordAgyToolEvent(...)`: single shared handler that appends `{ type: 'tool', timestamp, data: { tool, summary } }` and calls `logger?.verbose('[tool] <tool>: <summary>')` (satisfies the spec invariant).
  - Added `processAgyStdoutLine(line, specFolderPath, taskNumber, logger?)`:
    - JSON parse failures / non-object payloads are discarded silently (plain-text fallback).
    - Tool steps are recorded first; otherwise `step_update` lines with usage append `{ type: 'tokens', ... }`.
    - The trailing `result` event is intentionally not counted to avoid double-counting duplicate usage totals.
    - Timestamp resolves from `event.timestamp`/`step_update.timestamp`, else `new Date().toISOString()`.
  - Added `AgyEventStreamParser` (buffered line splitting, serialized `pending` chain, `flush()`), mirroring the OpenCode parser.
  - `AgyAdapter.spawn` now constructs `AgyEventStreamParser(specFolderPath, taskNumber, options.logger)`, feeds stdout chunks via `onStdout`, and awaits `flush()` after the process exits.
- `tests/agy-stream-events.test.ts` (new, the task verify command): 10 tests covering:
  - `--output-format stream-json` in `buildAgyArgs`.
  - Token extraction (all fields, cache, derived total, missing-field defaults, null cases).
  - Tokens event persistence from `processAgyStdoutLine`.
  - Tool extraction for command (truncated) and file tools with `tool_info.name` fallback.
  - Tool event persistence plus verbose stderr log, and normal-level suppression.
  - Fixture parsing (`fixture/agy-events.jsonl`) both line-by-line and via chunked `AgyEventStreamParser`, asserting exactly one tokens event (no result double count).
  - Plain-text / malformed stdout fallback for direct calls and the parser.
  - End-to-end `AgyAdapter.spawn` with a fake `AGY_PATH` binary emitting the fixture.

## Deviated

- `extractAgyToolEvent` return type uses the shared `ToolEventData` (`{ tool: string; summary: string }`) instead of the inline object literal in the task signature; the types are structurally identical.
- `extractAgyTokens` supports `result.usage` as well as `step_update.usage`, but `processAgyStdoutLine` only emits tokens for the `step_update` line. Emitting for `result` too would double-count the identical usage payload present in `fixture/agy-events.jsonl` and corrupt heartbeat token totals.
- Parameter/tool-name lookups accept a few extra locations and camelCase path keys (`filePath`, `AbsolutePath`, `DirectoryPath`) for robustness; the task text only named `parameters.CommandLine` and "path parameters".
- `AGY_COMMAND_TOOLS` includes `command_status`/`send_command_input` alongside `run_command`; these carry the same command-oriented parameters.

## Drift against features/

- `features/watcher-and-harness.md` is intentionally untouched; feature docs only change when the watcher applies the approved spec `## Delta`. Agy stream-json translation is additive and undocumented until then.

## Missing context

- `fixture/agy-events.jsonl` contains no tool step, so the synthetic tool shape used in tests follows the task Details (`step_update.step_type === 'tool'`, `tool_name`/`tool_info.name`, `tool_info.parameters.CommandLine`). If real `agy` emits parameters at a different nesting, the resolver already checks several locations, but no real capture confirms it.
- Out-of-scope integration gap carried from tasks 3–5: `src/watcher/runner.ts` still does not pass its `Logger` into `adapter.spawn`, so verbose `[tool]` lines do not appear in real `osq watch` runs even though events are persisted. `runner.ts` is outside this task's scope.
- Also out-of-scope: `AgyAdapter.spawn` does not propagate `pid`/`elapsedMs` from `spawnWithTimeout` into its `SpawnResult`, so runner lifecycle lines show `pid: unknown` for agy.
