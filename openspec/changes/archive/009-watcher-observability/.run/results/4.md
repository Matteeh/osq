# Task 4 result — periodic execution heartbeats

## Changed

- `src/watcher/runner.ts`
  - Added `TaskHeartbeatStats` interface (`elapsedSeconds`, `eventCount`, `totalTokens`).
  - Added exported `computeTaskHeartbeatStats(specFolderPath, taskNumber, startTime)`:
    - `elapsedSeconds = Number(((Date.now() - startTime) / 1000).toFixed(1))`.
    - Reads `.run/events/<n>.jsonl`; returns zeroed counters when the file is absent.
    - Counts non-empty lines for `eventCount`.
    - Sums `event.data.totalTokens` for lines where `type === 'tokens'`; malformed lines are skipped rather than failing the whole heartbeat.
  - In `runTask`, after the lock is acquired and before spawning, creates the heartbeat interval from `config.log?.heartbeatSeconds ?? 60` (× 1000 ms), guarded by `heartbeatIntervalMs > 0`, and calls `timer.unref()`.
  - Heartbeat callback logs `task <n> heartbeat (elapsed: <s>s, events: <n>, tokens: <n>)` through the injected `Logger` at info level.
  - The `finally` block now sets `heartbeatActive = false` and `clearInterval(heartbeatTimer)` before releasing the lock, so the timer stops even on early failure returns/throws.
  - `spawnStartMs` now reuses the shared `startTime`, so lifecycle elapsed and heartbeat elapsed share one origin.
- `src/core/config.ts`: no change needed — `DEFAULT_CONFIG.log.heartbeatSeconds = 60` and the `log` merge already landed in task 1. Covered by a test rather than edited.
- `tests/watcher-heartbeat.test.ts` (new, the task's verify command):
  - Defaults: `DEFAULT_CONFIG.log.heartbeatSeconds === 60`, `defineConfig({})` default, and override to `0.05`.
  - Unit: `computeTaskHeartbeatStats` returns elapsed/eventCount/totalTokens from a mixed event stream, and tolerates a missing file.
  - Integration: stub adapter writes four `tokens` events while sleeping; asserts multiple heartbeat lines, the field pattern, and accumulated `tokens: 1000`.
  - `unref()`: wraps `globalThis.setInterval` and asserts exactly one interval is created and that it is unref'd.
  - Cleanup: after `runTask` resolves, waits 250 ms and asserts the heartbeat line count is frozen.

## Deviated

- Added a `heartbeatActive` guard in addition to `clearInterval`. An in-flight async heartbeat could otherwise log once after `runTask` resolved; the guard makes the "stops on completion" acceptance line deterministic. Not in the task detail text, but required to satisfy acceptance line 4 reliably.
- Timer is created after the approved-hash/task-file/lock gates (immediately before the `try`) rather than at the very top of `runTask`. This satisfies "before spawning the task adapter" and avoids starting a timer on the early `spec_conflict`/`already_running` returns.
- `heartbeatIntervalMs > 0` guard added so an explicit `heartbeatSeconds: 0` cannot spin a ~1 ms timer.

## Drift against features/

- `features/watcher-and-harness.md` is intentionally untouched; feature docs only change when the watcher applies the approved spec `## Delta`. The heartbeat is additive and undocumented in the feature doc until then.
