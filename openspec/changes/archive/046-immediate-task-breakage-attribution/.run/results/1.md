# Task 1 — When task verification passes, change verification gates completion

## Changed

- `src/core/config-gates.ts` (new): `GatesConfig`, `DEFAULT_GATES_CONFIG`
  (`changeVerifyAfterTask: true`), and `validateGatesConfig` (partial merge over
  the default, rejects a non-object block and a non-boolean toggle).
- `src/core/config.ts`: wires `gates` into `OsqConfig`, `OsqUserConfig`,
  `DEFAULT_CONFIG`, and `defineConfig`; trimmed an unrelated doc comment to stay
  inside the 250-line budget (now 245).
- `src/core/doctor.ts`: `validConfig` now requires a resolved boolean
  `gates.changeVerifyAfterTask`.
- `src/watcher/change-verify.ts` (new): parses the proposal verify with
  `parseSpecMdFromFolder`, runs it through `runVerificationGateResult` with
  `{ specFolderPath, taskNumber: 'change' }`, and formats the
  `change_verify_red` dead marker (command, numeric `exit_code`, `timed_out`
  when applicable, captured output with a deterministic `(no output)` fallback).
  A missing proposal verify is a failed gate, not silent completion.
- `src/watcher/outcome.ts`: added `'change_verify_red'` to
  `RunTaskFailureReason` (196 lines).
- `src/watcher/runner.ts`: after the task gate passes and before
  `measures.emitEnd`/done marker/event/checkbox, calls `runChangeVerifyGate` and
  routes a failure through the existing `fail` path (199 lines).
- `tests/runner-test-gating.test.ts`: 4 new cases (enabled green run + change
  target event, failing change verify evidence/no done, disabled opt-out,
  failing task verify never runs the proposal command).
- `tests/config.test.ts`: default true, opt-out preservation, non-boolean and
  non-object rejection, `loadConfig` reads the block.
- `tests/doctor.test.ts`: config check rejects a missing or non-boolean
  resolved gate.

## Verification

Task verify command passes: 69 tests, 0 failures across runner-test-gating,
config, doctor, golden-events, import-graph, and line-budget. `pnpm lint` and
`pnpm typecheck:cli` also pass.

## Deviated

- `OsqConfig.gates` is declared optional (`gates?: GatesConfig`) rather than
  required. Making it required breaks `tests/opencode-config.test.ts:27`, which
  builds an `OsqConfig` literal without `gates` and is outside this task's
  scope (it is included by `typecheck:cli`). Resolved configuration from
  `defineConfig`/`loadConfig` always contains the validated boolean, doctor
  rejects a missing/non-boolean value, and the runner treats only an explicit
  `false` as disabled, so observable behavior matches the delta.

## Drift against features/

The behavior is a superset of the delta, but five pre-existing out-of-scope
archive tests encode the old "change verify only runs at archive time" contract
and now fail under the default-on gate. Full `pnpm test`: 1231/1236 pass, 5 fail:

- `tests/archive-verification.test.ts`
  - "archives a clean change after re-running every task and change verify"
    (now observes the task-boundary `change` `verify_ran` events in addition to
    the archive-time one).
  - "blocks archiving when the change-level verify fails" (the task now dies
    with `change_verify_red` before completion).
  - "halts archival and records final-task drift before the archive verifier
    runs" (asserts zero change-target verify events after tasks).
  - "leaves the transient plan-prompt.md in place when archive verification
    fails" (task dies before archive).
- `tests/plan-prompt-lifecycle.test.ts`
  - "failing archive verification leaves the active prompt untouched" (task
    dies before archive).

These files are not in any task's `scope` (proposal says "No other production or
test file is intentionally shared"), so they were intentionally not edited.
Remediation: in each failing case pass a config with
`gates: { changeVerifyAfterTask: false }` to `runTask` (the gate-disable path is
implemented and tested), and update the change-target `verify_ran` count
assertions for the cases whose proposal verify is green. This work must be
added to a task's scope or a follow-up change; otherwise the proposal
`verify: pnpm verify` gate cannot go green and the change will regress at
archive time.
