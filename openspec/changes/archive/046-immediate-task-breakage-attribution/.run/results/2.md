# Task 2 — scope and tests.modify jointly authorize each preexisting test edit

## Changed

- `src/watcher/verify.ts` (196 split-lines, under 200):
  - New exported `captureTestGate(projectRoot, scope, testsModify)` runs the
    existing `snapshotTestFiles` and calls the shared `resolveScope` before
    spawn, projecting the resolved existing paths into an authorization set. It
    returns `{ snapshot, testsModify, authorized }`, so `runTask` never resolves
    or snapshots after the adapter can mutate the tree.
  - `findUndeclaredTestChanges` now takes an optional
    `{ testsModify, authorized }` argument. A changed/deleted preexisting test is
    skipped only when `testsModify === true` and its project-relative path is in
    the pre-spawn authorization set. Diagnostics append
    `; authorizing scope: <path>` and remain sorted by project-relative path.
    The 2-argument form keeps its exact legacy output for the existing direct
    helper test.
- `src/watcher/runner.ts` (198 split-lines, under 200): captures the gate before
  `spawnTaskAgent`, passes it to the post-spawn comparison, and dies with
  `undeclared_test_change` before `ensureTaskResult` or either verifier. Task 1's
  change-verify gate is untouched.
- `src/core/linter.ts`: new `collectHarnessFixtureWarnings` reuses each task's
  already-computed `resolveScope` projection (`ResolvedTaskScope.existingPaths`)
  and emits one non-failing warning per task, in `compareNumericPrefix` order,
  when a `src/harness/` file resolves but no file under `tests/fixtures/events/`
  does. No second matcher or tree walk.
- `tests/runner-test-gating.test.ts`: `writeTask` accepts a scope; existing
  cases assert the new scope remediation; added in-scope edit, in-scope
  deletion, out-of-scope edit with `tests.modify: true`, and sorted-diagnostics
  cases.
- `tests/linter.test.ts`: five new cases (missing coverage warns; exact file,
  directory, and glob coverage stay silent; one warning per affected task in
  task order).
