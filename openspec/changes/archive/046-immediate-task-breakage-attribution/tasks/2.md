## Acceptance

- [ ] `runTask` always snapshots preexisting files under `tests/**` and resolves the task scope against the same pre-spawn tree before the adapter can modify or delete files.
- [ ] With `tests.modify: true`, a changed or deleted preexisting test proceeds only when its project-relative path was present in that pre-spawn resolved scope; an in-scope deletion remains authorized.
- [ ] With `tests.modify` false or absent, every changed or deleted preexisting test remains forbidden, while a file absent from the snapshot remains governed by the existing new-test behavior.
- [ ] Every unauthorized test change fails before result synthesis or verification with `undeclared_test_change`; sorted marker diagnostics name its modified/deleted state and the literal `scope: <project-relative-test-path>` entry that would authorize it.
- [ ] Lint emits a deterministic non-failing warning naming `tests/fixtures/events/` when resolved scope includes any `src/harness/` file but no declared scope resolves content under that fixture folder.
- [ ] The fixture warning is absent when an exact directory, exact fixture file, or supported glob scope covers `tests/fixtures/events/`, and it does not duplicate the shared scope resolver.
- [ ] `verify.ts` and `runner.ts` remain strictly under 200 lines, task 1's change gate remains intact, and all frozen golden/import/budget tests pass without event fixture edits.

## Details

Extend `snapshotTestFiles` and `findUndeclaredTestChanges` in `verify.ts`
without introducing another test-tree walker. Add a small exported helper there
that calls the existing `resolveScope` before spawn and projects the resolved
preexisting test paths into an authorization set. Keep compatibility for the
existing direct helper tests while allowing `runner.ts` to pass
`taskData.testsModify` and the authorized set into the post-spawn comparison.
New files are absent from the snapshot and therefore remain permitted.

Diagnostics must be stable by project-relative POSIX path. Retain the existing
`(modified)` and `(deleted)` facts and add the exact literal remediation
`scope: tests/...` for each unauthorized file. Perform the gate before
`ensureTaskResult` and either verification command, as today. Task 2 extends
the runner branch and focused runner test owned first by task 1; preserve its
incremental change verification cases.

In `linter.ts`, reuse each task's already-computed `resolveScope` result. A
resolved `src/harness/` path triggers the warning only when the same resolution
contains no path below `tests/fixtures/events/`. The warning names the folder,
remains non-failing, and is emitted once per affected task in deterministic
task order. Build temporary harness and fixture files in `linter.test.ts` to
cover missing, exact-file, directory, and glob declarations. Do not edit golden
fixtures: neither gate changes an event payload shape.
