## Acceptance

- [ ] In `web-data-observations.ts`, each execution cost (per task stream and per change) and each planning cost is `null` when its reported count is 0, even when attempts or sessions exist. Coverage stays `{ reported: 0, total: N }`.
- [ ] A cost with at least one reported value is unchanged: the sum of reported values.
- [ ] New `tests/web-data-unreported.test.ts` builds a project with a change whose attempts and planning session report no cost, and one whose attempts partly report cost. It asserts both through `getWebGraph` and `getWebChange`.
- [ ] `tests/web-data.test.ts` and `tests/planning-observed.test.ts` pass unchanged.
- [ ] The task's verify command passes.

## Details

This task's `scope` is authoritative over any injected code-ownership rules.

Today `cost` is `null` only when there are no attempts or sessions, and
otherwise it is `sum(costValues)`, which is `0` when nothing was reported. The
living spec already says a missing planning start gives a null planning cost,
never zero. This task applies the same rule to "recorded but not reported".
Reuse the existing reported counters; no new field is needed. The `web-data.test.ts`
and `planning-observed.test.ts` helpers show how to write task event streams
and `plan.jsonl` records.
