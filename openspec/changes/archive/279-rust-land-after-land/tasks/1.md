## Acceptance

- [ ] After a land whose fast-forward is `Done`, `land` runs `vcs.afterLand` as rust-land "Land after-land command" says, writes or removes the record, and returns or fails with the lines it names. With the key unset, every existing land test passes unchanged.
- [ ] `Cargo.toml` adds `osq-kernel-harnesses`, `sha2` and `serde_json` with `workspace = true`, and `Cargo.lock` follows.
- [ ] A new `tests/land_after.rs` proves "After-land outcomes" and "A passing command clears the record". Each test's doc names `Covers: rust-land/<scenario>`, uses its own land repository, and removes its record before it ends.
- [ ] Every public item ends its doc with `Implements: rust-land/<requirement>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Port `executeAfterLand` and `outputTail` from TypeScript's
`land-after.ts`, and `watchStateDir` from `watch-state.ts`. Build the
`VerifyRequest` as the run crate's `verdict.rs` does, with
`std::env::vars()` as the source. Read `HOME` inline with
`std::env::var("HOME").unwrap_or_default()`, as the report crate does.
Copy the millisecond UTC formatter from the run crate's `time.rs`; do not
depend on another feature crate.

Write the record with `serde_json::json!`. Its keys then come out sorted,
which gives TypeScript's order `change`, `command`, `exitCode`,
`failedAt`.

In the test, build the record path from `HOME` and the canonical
checkout path, and write each row's settings into the checkout's untracked
`osq.toml` with the support module's `write`. The support module is a
frozen test file, so leave it unchanged.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source. Run the proposal's verify as the watcher does,
with `OSQ_CHANGE=openspec/changes/279-rust-land-after-land`, so the link
gates see this change's new requirements.
