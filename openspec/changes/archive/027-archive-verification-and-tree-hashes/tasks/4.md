## Acceptance
- [ ] src/core/parser.ts parses verify from proposal frontmatter into SpecData
- [ ] src/core/linter.ts requires a non-empty verify command on proposals and fails without one
- [ ] src/watcher/archiver.ts re-runs every task verify command against the final tree prior to archiving
- [ ] src/watcher/archiver.ts runs change-level verify command against the final tree prior to archiving
- [ ] Verification failure blocks archive, writes regressed marker and event, and halts change
- [ ] tests/linter.test.ts validates that proposals lacking verify are rejected
- [ ] tests/archive-verification.test.ts verifies all three end-to-end scenarios without mock adapter

## Details

1. In `src/core/parser.ts`:
   - Add `readonly verify: string;` to `SpecData`.
   - In `parseSpecMd`, extract `verify`:
     ```typescript
     const verify = typeof data.verify === 'string' ? data.verify.trim() : '';
     ```
   - Retain backward compatibility across existing parser consumers.

2. In `src/core/linter.ts`:
   - In `lintChangeFolder`, check:
     ```typescript
     if (!spec.verify) {
       errors.push('proposal.md must declare a verify command in frontmatter');
     }
     ```
   - Update `tests/linter.test.ts` to assert that proposals without a `verify` command produce a lint error.

3. In `src/watcher/archiver.ts`:
   - In `checkAndArchiveSpec(projectRoot, specFolderPath, config)`:
     - If `specState.status !== 'done'`, return `false`.
     - Read all tasks from `specFolderPath/tasks`.
     - For each task in order:
       - Re-run its `taskData.verify` command against `projectRoot` using the same timeout (`config.timeouts.verifyTimeoutSeconds ?? 600`) and detached TTY-free environment (`stdio: ['ignore', 'pipe', 'pipe']`).
       - If verification fails:
         - Write `.run/regressed/<taskNumber>.md` containing command, exit code, and captured output.
         - Append `regressed` event to `.run/events/<taskNumber>.jsonl` with `exitCode` and `duration`.
         - Return `false` to block archiving and halt the change.
     - Parse `specData` from proposal.
     - Re-run proposal's `verify` command against `projectRoot`.
     - If change-level verification fails:
       - Write `.run/regressed/change.md` containing command, exit code, and captured output.
       - Append `regressed` event to `.run/events/change.jsonl` with `exitCode` and `duration`.
       - Return `false` to block archiving and halt the change.
     - If all verifications pass, call `archiveSpecFolder`.
   - Keep `src/watcher/archiver.ts` strictly under 250 lines.

4. Create `tests/archive-verification.test.ts`:
   - Implement end-to-end tests for three scenarios:
     1. Clean archive: tasks pass, change-level verify passes, folder archives to `openspec/changes/archive/`, event logs and done markers verified.
     2. Refusal on modified scope: task 1 files are modified after task 1 is done; runner refuses task 2 before spawning, writes `.run/regressed/1.md`, appends `regressed` event, halts change.
     3. Change-level verify failure at archive: all tasks complete, but change-level verify exits with code 1; archiver writes `.run/regressed/change.md`, appends `regressed` event, and blocks archiving.
   - Assert on `events.jsonl` and marker files.
   - Do NOT use `MockAdapter`. Use a real harness adapter (`AgyAdapter` or `OpencodeAdapter`) with an executable fake harness script.

5. Verify:
   `node --import tsx --test tests/archive-verification.test.ts`
