## Acceptance

- [ ] `parseClaudeSession` returns `turns`: one `PlanningTurn` per distinct `message.id` among assistant records, timestamped at that id's earliest record, with the id's model and the edits from successful `Write`, `Edit`, or `NotebookEdit` tool uses in any of its records. An assistant record without a `message.id` is its own turn.
- [ ] Turn usage comes from `message.usage` once per id: `input_tokens` as input, `output_tokens` as output, `cache_read_input_tokens` as cache read, `cache_creation_input_tokens` as cache write, `output_tokens_details.thinking_tokens` as reasoning, and cost null. A missing or non-numeric field is null.
- [ ] The session carries `harnessVersion` from the first record's `version` and `sessionCost` from a `cost-state` record's `totalCostUSD`, else null. `cost-state` counters no longer supply token usage. The session no longer sets `usage`, `startedAt`, or `endedAt`, and still returns null when it has no edit.
- [ ] `readClaudePlanningSessions` merges files that share a session id (a transcript and its subagent files), keeping each message id once.
- [ ] A new content-free fixture under `tests/fixtures/planning-claude/` holds one session with a message split across three records, a message spanning two records with an edit into the change folder, a message without usage, and no `cost-state`. Next to it, `source.json` records `{"harness":"claude","version":"2.1.280"}`. New tests in `tests/planning-claude-turns.test.ts` assert the turn count, per-turn tokens counted once, null session cost, the harness version, and that a transcript with malformed usage yields null usage while `approveSpec` with that reader still succeeds.
- [ ] Only the assertions about session-level usage change in `tests/planning-observed-claude.test.ts`. `claude-usage.ts` stays under 250 lines, so the turn parsing lives in new `claude-turns.ts`.

## Details

Build the fixture from this record shape, which matches Claude Code 2.1.280
with every message body removed. Keep only these keys, and never put real
prompt, response, or file content in a fixture:

```json
{"type":"assistant","sessionId":"s-1","cwd":"__CWD__","version":"2.1.280","timestamp":"2026-09-22T21:31:13.179Z","message":{"id":"msg_1","role":"assistant","model":"claude-opus-5-5","content":[{"type":"text"}],"usage":{"input_tokens":2,"output_tokens":537,"cache_read_input_tokens":51596,"cache_creation_input_tokens":3876,"output_tokens_details":{"thinking_tokens":17}}}}
```

A tool-use block keeps only `type`, `id`, `name`, and `input.file_path`.
Errored tool uses are still recognized by a later user record's `tool_result`
with `is_error: true`, as today. Use the placeholder rendering the existing
fixture tests already use (`renderTree` in `tests/planning-observed-helpers.ts`)
so edit paths land inside a temporary change folder. The approval test that
reads the old `claude-projects` fixture was already loosened by task 3 to
assert only cost, model, and identity. Every other preexisting test is frozen.
