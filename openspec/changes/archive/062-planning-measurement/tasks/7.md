## Acceptance

- [ ] `PlanningMetrics` gains `byChange`, keyed by change folder name for every change with a valid planning start. Each entry holds `sessions`; `tokens` with `input`, `output`, `cacheRead`, `cacheWrite`, `reasoning`; `activeMinutes`; `cost`; `specWords`; `changedLines`; `specWordsPerChangedLine`; and `minutesLastEditToApproval`. Every value except `sessions` is nullable, and null means no session or event reported it.
- [ ] Tokens and active minutes sum each session's `plan_exited.data.slice`. A session without a slice contributes its `usage` input, output, and reasoning, and nulls for the cache split and active minutes. Cost sums sessions' non-null `usage.cost`. `minutesLastEditToApproval` is the latest slice `approvedAt` minus the latest slice `lastEditAt`, rounded to two decimals.
- [ ] Spec words are the first task `measures` start event's `proposalWords` plus each task's first start `taskWords`. Changed lines sum each task's last `measures` end `changedLines`. `specWordsPerChangedLine` is their ratio rounded to two decimals, null when changed lines are 0 or unknown.
- [ ] `PlanningMetrics` gains `comparison: { planning, execution }`, each with `input`, `output`, `cached`, `reasoning`, and nullable `cost`. Planning takes the block's totals; execution takes `tokens.input`, `tokens.output`, `tokens.cached_input`, `tokens.reasoning`, and the history cost total, or null when no attempt reported one. The planning `cost.formattedTotal` reads `not reported` unless at least one session reported a cost, even when sessions reported tokens.
- [ ] Text adds `Planning by change:` with one line per change, then `Planning vs execution:` with one line each for input, output, cached, and reasoning tokens and cost. A null value prints `unavailable`, and a null cost prints `not reported`. The exact line formats are under Details.
- [ ] `osq report --json` emits both fields through `toStableMetrics`. `fixture/report/expected.json` gains them for the fixture's three planned changes and changes nowhere else. In `tests/report-json.test.ts` and `tests/report-planning.test.ts`, only key lists, hand-built reports, and the fixture comparison change.
- [ ] New `tests/report-planning-economics.test.ts` builds changes with sliced and legacy records and `measures` events, and asserts each field, the ratio, the legacy nulls, and the `not reported` cost when sessions report tokens without cost.

## Details

Compute both fields in new `src/core/report/planning-economics.ts` from the
change folders `getMetricsReport` already walks, and keep `report.ts` changes to
wiring. Both `getMetricsReport` and `formatMetricsReport` are grandfathered in
the function budget, so add helpers rather than growing them.

Text formats:

```
Planning by change:
  <change>: sessions <n>, active <m> min, tokens in <i> out <o> cache-read <r> cache-write <w> reasoning <x>, cost <cost>, spec words <s>, changed lines <l> (<ratio> words/line), last edit to approval <a> min
Planning vs execution:
  Input tokens: planning <p>, execution <e>
  Output tokens: planning <p>, execution <e>
  Cached tokens: planning <p>, execution <e>
  Reasoning tokens: planning <p>, execution <e>
  Cost: planning <cost>, execution <cost>
```

Print costs through `formatReportedCost`. Measured against the full suite,
adding a planning key breaks only `tests/report-json.test.ts`,
`tests/report-planning.test.ts`, and `fixture/report/expected.json`. The
cost-label fix alone breaks nothing. Other preexisting tests are frozen.
