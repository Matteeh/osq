## Acceptance

- [ ] `parseCodexObservation` returns `turns`: each `event_msg` payload of type `token_count` with an `info.last_token_usage` becomes one `PlanningTurn` at its timestamp. A `token_count` whose `info.total_token_usage` equals the previous one's adds no turn, and `token_usage_record` lines add none.
- [ ] Turn usage: input is `input_tokens` minus `cached_input_tokens` (never below 0), cache read is `cached_input_tokens`, cache write is `cache_write_input_tokens`, output is `output_tokens`, reasoning is `reasoning_output_tokens`, and cost is null. A missing or non-numeric field is null. The model is the latest `turn_context` or `session_meta` model.
- [ ] Edits come from successful `apply_patch` calls, as today, and from `event_msg` payloads of type `patch_apply_end` with `success: true`, whose edited paths are the keys of `changes`; the change bodies are never read or kept. Edits attach to the next turn. Edits after the last `token_count` form one final turn with null usage at the last edit's timestamp.
- [ ] The session carries `harnessVersion` from `session_meta.cli_version` and a null `sessionCost`, and no longer sets `usage`, `startedAt`, `endedAt`, or `edits`.
- [ ] A new content-free fixture `tests/fixtures/planning-codex/rollout.jsonl`, with `source.json` recording `{"harness":"codex","version":"0.154.0-alpha.6.2"}`, holds two responses (the second duplicated as a `token_usage_record` and a repeated `token_count`), one `patch_apply_end` edit, and one `exec` custom tool call. Tests in `tests/planning-codex-turns.test.ts` assert two turns, the cache-adjusted input, the edit on the second turn, and that the `exec` call adds no edit.
- [ ] Only the assertions about session-level cumulative usage, start and end, and session-level `edits` (now read from `turns`) change in `tests/planning-observed-codex.test.ts`.
