## Acceptance

- [ ] `buildOpencodeObservationQuery` selects one row per assistant message and completed `write` or `edit` part. It reads `message` joined to `session` on `message.session_id`, left-joins `part` on `part.message_id` with the existing tool, type, and status filters, and keeps only sessions that have at least one such part. It never names `part.sessionID`.
- [ ] Each row carries `session_id`, `directory`, `version` (session), `message_id`, `message_time`, `model` (`$.modelID`), the token fields `$.tokens.input`, `$.tokens.output`, `$.tokens.reasoning`, `$.tokens.cache.read`, `$.tokens.cache.write`, `cost` (`$.cost`), `edit_path`, and `edit_time`, all projected through `json_extract` so no message or part body leaves the database.
- [ ] `readOpencodePlanningSessions` groups rows by session and message into `turns`: one per assistant message at `message_time`, with those tokens (OpenCode's `input` already excludes cache), the message's cost, its model, and its edit paths. The session carries `harnessVersion` from `version` and a null `sessionCost`, and no longer sets `usage`, `startedAt`, `endedAt`, or `edits`.
- [ ] A spawn failure, non-zero exit, or unparseable output still yields no sessions, and a row with malformed token fields yields null usage for that turn.
- [ ] New tests in `tests/planning-opencode-turns.test.ts` use the existing fake `opencode` pattern (a script printing `OSQ_OPENCODE_DB_ROWS_FILE`) with rows for two messages in one session, one with an edit. They assert two turns with per-message tokens and cost, and the harness version. A second test asserts the query text joins on `message.session_id` and `part.message_id`.
- [ ] Only the query-shape and session-level usage or edit assertions change in `tests/planning-observed-opencode.test.ts`. `mapUsage` and the owned-session usage reader are unchanged.

## Details

Checked against OpenCode 1.18.31 on this machine. The tables are
`session(id, directory, version, model, ...)`,
`message(id, session_id, time_created, data)`, and
`part(id, message_id, session_id, time_created, data)`. An assistant message's
`data` holds `role`, `modelID`, `providerID`, `cost`, and
`tokens: {input, output, reasoning, cache: {read, write}}`. Times are epoch
milliseconds; reuse `parseTimeMs`. Today's query joins on `part.sessionID` and
fails on this version with "no such column", which is why OpenCode planning is
never observed. Put `source.json` recording `{"harness":"opencode","version":"1.18.31"}`
next to any rows fixture you add under `tests/fixtures/planning-opencode/`.
Other preexisting tests are frozen.
