## Acceptance

- [ ] The reader port gains per-turn records. `ObservedPlanningSession` adds optional `harnessVersion: string | null`, `sessionCost: number | null`, and `turns: readonly PlanningTurn[]`, and makes `usage`, `edits`, `startedAt`, and `endedAt` optional. A session without `turns` becomes one turn per edit with null usage, keeping the session's `usage` only when its slice holds every such turn. The `PlanningTurn` shape is under Details.
- [ ] Turns are attributed as in "Planning turn attribution": a turn that edited change folders belongs to the first one; the approvals of changes the session edited split it into segments; any other turn belongs to the next change edited in its segment, or else to the change whose approval closes it. A change folder is recognized by name under the changes directory or its `archive/`. Another change's approval time is `plan_exited.data.slice.approvedAt` from its `.run/plan.jsonl` for the same session, else its `.run/manifest.json` `approvedAt`, else it sets no boundary. This change's approval time is the observation time.
- [ ] Each appended pair uses the first and last owned turn as `plan_started` and `plan_exited` timestamps, their span as `wallSeconds`, and the owned turns' sums as `usage` (`cachedTokens` = cache read + cache write; a kind is null when no owned turn reported it). `plan_exited.data.slice` holds `start`, `end`, `approvedAt`, `lastEditAt` (latest owned turn with an edit), `turns`, `activeMinutes` (gaps at most `planning.idleGapMinutes`, rounded to two decimals), `tokens` (`input`, `output`, `cacheRead`, `cacheWrite`, `reasoning`), and `costSource`. The model is the last owned turn's model, else the session's.
- [ ] Cost follows "Planning slice measures": sum of per-turn costs when every owned turn has one (`harness`); else `sessionCost` when the slice holds all of the session's turns (`harness`); else a `planning.prices` estimate when every owned turn's model is priced and has non-null input and output (`price_table`); else null.
- [ ] `parsePlanRecords` reads a valid `slice` into `PlanExitedRecord.data.slice`. A missing or malformed slice is left absent, and existing records parse exactly as before.
- [ ] New `tests/planning-slice.test.ts` covers the slicing scenarios in the delta: three sequential changes, parallel changes (the union of both slices equals every turn up to the second approval, with no turn twice), discussion before the first edit, a re-approval that does not move a boundary, the 2/3/25-minute idle gap, and each cost rule. New `tests/planning-observed-slices.test.ts` drives `approveSpec` with injected turn readers across three changes in one project.
- [ ] Only assertions about observed timestamps, `wallSeconds`, `usage`, or the returned observation shape change in the two scoped test files. The approval test that reads the `claude-projects` fixture through the real `readClaudePlanningSessions` asserts cost `0.42`, model, and session identity, but no token counts, because task 4 stops reading tokens from `cost-state`. Every source file stays under 250 lines and every new function under 80.

## Details

`PlanningTurn` is the port every reader will return. Define and export it from
the slicing module, and re-export it from `planning-observed.ts`:

```ts
export interface PlanningTurn {
  readonly timestamp: string;
  readonly model: string | null;
  readonly inputTokens: number | null;       // excludes cached input
  readonly outputTokens: number | null;
  readonly cacheReadTokens: number | null;
  readonly cacheWriteTokens: number | null;
  readonly reasoningTokens: number | null;
  readonly cost: number | null;
  readonly edits: readonly string[];          // raw paths, resolved like today's edits
}
```

Keep matching as it is: a session matches when one of its edits lands inside
the change folder between creation and observation time, using
`normalizeObservedTarget` against `sessionDir`. When a session has `turns`, its
edits are the turns' edits at each turn's timestamp; otherwise they are the
legacy `edits`. Slicing then uses every turn of
the session, including turns before the change folder existed. Keep the
existing once-per-change idempotency by session id. `approveSpec` passes the
changes directory it already resolves and `config.planning` (falling back to
`DEFAULT_CONFIG.planning`). `planning-observed.ts` is at 244 lines, so put the
slicing, boundary lookup, and cost rules in new `planning-slice*.ts` modules.
The readers are not touched in this task; they still return sessions without
turns until tasks 4 to 6. Other preexisting tests are frozen.
