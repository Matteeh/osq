## Acceptance

- [ ] New `src/core/foundation/config-planning.ts` exports `PlanningConfig` (`idleGapMinutes: number`, optional `prices`), `PlanningPrice` (`input`, `output`, `cacheRead`, `cacheWrite`: USD per million tokens), `DEFAULT_PLANNING_CONFIG` with `idleGapMinutes: 10`, and `validatePlanningConfig`.
- [ ] `OsqConfig` gains optional `planning: PlanningConfig`; `DEFAULT_CONFIG.planning` is the default, and `defineConfig` resolves a partial user block over it. `OsqUserConfig` accepts `planning` as a partial block.
- [ ] `defineConfig({ planning: { prices: { 'claude-opus-5-5': { input: 5, output: 25, cacheRead: 0.5, cacheWrite: 6.25 } } } })` keeps that entry and `idleGapMinutes: 10`.
- [ ] A non-object block, an `idleGapMinutes` that is not a positive finite number, a `prices` that is not an object, or a price entry missing a kind or holding a negative or non-numeric value throws an error naming the key, for example `planning.prices.claude-opus-5-5.output`.
- [ ] `PlanningConfig` and `PlanningPrice` are exported from `src/index.ts`. New tests live in `tests/config-planning.test.ts`.

## Details

Follow `config-serve.ts` and `validateServeConfig` for the file shape and how
`defineConfig` calls the validator. The prices in the example are only test
values; osq ships no price table. Adding the block to `DEFAULT_CONFIG` was
measured against the full suite and changes no existing test. Every existing
test is frozen.
