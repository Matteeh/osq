## Changed

- Added the slicing modules owned by this task:
  - `src/core/report/planning-slice.ts`: `PlanningTurn`, `PlanningTokens`,
    `PlanningSlice`, `PlanningCostSource`, path helpers (`isSegmentContained`,
    `resolveEditPath`, `normalizeObservedTarget`, `changeFolderForPath`), turn
    sorting, per-turn owner resolution, segment boundaries, attribution, and
    `sliceChangeOwnership`.
  - `src/core/report/planning-slice-measures.ts`: per-kind token sums, cache
    combination, idle-gap active minutes, last-edit lookup, and the ordered
    per-turn / whole-session / price-table cost rules.
  - `src/core/report/planning-slice-record.ts`: `parsePlanningSlice`, leaving a
    missing or malformed slice absent.
  - `src/core/report/planning-slice-lookup.ts`: `resolveChangeApprovalTime`
    (recorded slice `approvedAt`, else manifest `approvedAt`, else null) and
    `resolveChangeCreationTime`.
  - `src/core/report/planning-slice-turns.ts`: session-to-turn normalization
    (one turn per edit with null usage when no turns), session edits, matching,
    and the last owned turn's model.
- `src/core/report/planning-observed.ts` (214 lines): `ObservedPlanningSession`
  gains `harnessVersion`, `sessionCost`, and `turns` and its `startedAt`/
  `endedAt` are now optional. `findPlanningSessions` accepts `changesDir` and
  `planning`, matches exactly as before, and reduces each match with
  `sliceChangeOwnership`; `appendObservedSessions` writes `usage` and the
  `slice` into the observed exit record. Re-exports `PlanningTurn`, the path
  helpers, and the two lookup functions.
- `src/core/report/planning-records.ts`: `PlanExitedRecord.data.slice` typed and
  parsed; legacy records parse exactly as before.
- `src/core/spec/approve.ts`: passes the resolved changes directory and
  `config.planning` (falling back to `DEFAULT_CONFIG.planning`).
- New `tests/planning-slice.test.ts`: three sequential changes, parallel
  changes (union equals every turn, no turn twice), discussion before the first
  edit, archive recognition, a re-approval boundary that prefers the recorded
  slice, the 2/3/25-minute idle gap, every cost rule plus the null rule, token
  sums, legacy usage retention, and valid/malformed slice parsing.
- New `tests/planning-observed-slices.test.ts`: drives `approveSpec` with
  injected turn readers across three changes in one project and asserts the
  three non-overlapping slices, their bounds, tokens, cost source, and identity.
- `tests/planning-observed-approve.test.ts`: observation literals now carry a
  `slice` (returned shape), and the claude fixture assertion checks cost `0.42`
  plus model and session identity but no token counts.

## Deviated

- Acceptance line 1 asks to make `usage`, `edits`, `startedAt`, and `endedAt`
  optional. I made `startedAt`/`endedAt` optional but kept `usage` and `edits`
  required. The frozen reader tests (`tests/planning-observed-claude.test.ts`,
  `codex`, `opencode`) read `.edits`/`.usage` directly and the frozen
  `claude-usage.ts` reads `a.edits`/`hasUsage(a.usage)`; those files are outside
  this task's scope and cannot be changed, so optional properties make
  `pnpm typecheck:cli` fail, which the watcher's `pnpm verify` runs. Tasks 4 to 6
  can still return `turns` and set the two legacy fields to null usage and an
  empty edit list; nothing in the slicing path reads them once `turns` exists.
- `PlanningObservation.slice` is required, so the in-scope approve test's
  observation literals had to gain a `slice` field (the returned observation
  shape acceptance line 6 allows).

## Missing context

- The task assumed the optional port change is compatible with the frozen
  reader tests and readers, but with the current scope it is not; that conflict
  is the source of the deviation above.
