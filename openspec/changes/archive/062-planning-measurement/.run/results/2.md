## Changed

- Added `src/core/foundation/config-planning.ts`: `PlanningPrice`, `PlanningConfig`,
  `DEFAULT_PLANNING_CONFIG` (`idleGapMinutes: 10`), and `validatePlanningConfig`.
  A partial block keeps the default idle gap; `prices` is validated per model id
  with all four kinds required as finite non-negative numbers, and every rejection
  names the offending key, e.g. `planning.prices.<model>.output`.
- `src/core/foundation/config.ts`: added optional `planning?: PlanningConfig` to
  `OsqConfig`, `planning?: Partial<PlanningConfig>` to `OsqUserConfig` (with
  `planning` added to the omitted keys), `planning: DEFAULT_PLANNING_CONFIG` to
  `DEFAULT_CONFIG`, and `planning: validatePlanningConfig(config.planning)` in
  `defineConfig`. Removed the now-redundant `PlanningConfig`/`PlanningPrice`
  re-export and inlined the one validation call to keep the file at the 250-line
  budget.
- `src/index.ts`: exported `PlanningConfig` and `PlanningPrice` types plus
  `DEFAULT_PLANNING_CONFIG` and `validatePlanningConfig`.
- Added `tests/config-planning.test.ts` covering the default, partial merge, the
  acceptance example, the non-object/idle-gap/prices/price-entry rejections with
  their key names, `loadConfig` from `osq.config.ts`, and the public type surface.

## Deviated

- Dropped the `export type { PlanningConfig, PlanningPrice }` line from
  `config.ts` (index imports the types directly from `config-planning.ts`), and
  inlined the planning validation call in `defineConfig`, because the additions
  otherwise pushed `config.ts` to 252 lines and failed `tests/line-budget.test.ts`.
  The task requires only that `src/index.ts` exports the two types.
- The task named `src/core/foundation/config-gates.ts` as an entry file but it
  needed no change; it was read only for the partial-block validation pattern.
