## Changed

- `src/harness/opencode/opencode-usage.ts`: rewrote
  `buildOpencodeObservationQuery` to select one row per assistant `message`
  joined to `session` on `message.session_id`, left-joining `part` on
  `part.message_id` with the existing tool/type/status filters and requiring
  `part.message_id IS NOT NULL`. The projection reads `session.version`,
  `message.id`, `message.time_created`, and, through `json_extract`,
  `$.modelID`, `$.tokens.input/output/reasoning/cache.read/cache.write`,
  `$.cost`, and `$.state.input.filePath` plus `part.time_created`. It no longer
  names `part.sessionID`. Exported `finiteNonNegative` for the observe reader;
  `mapUsage`, `buildOpencodeSessionQuery`, and the owned-session reader are
  unchanged.
- `src/harness/opencode/opencode-observe-usage.ts`: rewrote
  `readOpencodePlanningSessions` to group rows by session and assistant
  message. Each message becomes one `PlanningTurn` at `message_time` with its
  model, independently nullable token kinds, cost, and the union of its part
  edit paths. A session carries `harnessVersion` from `version`,
  `sessionCost: null`, and the turns; `startedAt`/`endedAt` are omitted.
- `tests/planning-observed-opencode.test.ts`: updated only the query-shape
  assertions and the session-level usage/edit assertions. Session rows now
  carry the new message-shaped projection; the session assertions check null
  legacy usage, `harnessVersion`, `sessionCost`, and the derived edit list.
  `mapUsage` and the owned-session reader tests are untouched.
- Added `tests/planning-opencode-turns.test.ts` and the content-free fixture
  `tests/fixtures/planning-opencode/` (`source.json` with
  `{"harness":"opencode","version":"1.18.31"}` and `rows.json` with `__CWD__`/
  `__INSIDE_PATH__` placeholders). It drives the existing fake `opencode` script
  reading `OSQ_OPENCODE_DB_ROWS_FILE`: two messages in one session, one with an
  edit, yield two turns with per-message tokens, cost, and the edit; a second
  test asserts the query joins `message.session_id` and `part.message_id` and
  never names `part.sessionID`; a third asserts a malformed token row yields
  null turn usage.

## Deviated

- Acceptance line 3 says the session "no longer sets `usage` ... or `edits`".
  `ObservedPlanningSession.usage` and `.edits` are still required fields and
  `src/core/report/planning-observed.ts` is outside this task's scope, so the
  reader keeps `usage: NULL_INTERACTIVE_USAGE` and derives `edits` from the
  turns. This is the same cross-task conflict recorded by tasks 3, 4, and 5;
  nothing in the slicing path reads either once `turns` exists.
- The new fixture files and `tests/planning-opencode-turns.test.ts` are not in
  the three-path `scope` list, but acceptance line 5 names the new test file and
  the `tests/fixtures/planning-opencode/` fixture, and new test files are always
  allowed.
- The existing fixture's second message deliberately carries a row without an
  edit path so the reader is shown to keep one turn per assistant message, as
  acceptance line 5 requires two turns with "one with an edit".
