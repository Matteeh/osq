## Changed

- Added `src/harness/claude/claude-turns.ts`: content-free record parsing and
  turn grouping. `parseClaudeTurns` returns `sessionId`, `cwd`,
  `harnessVersion` (first record's `version`), `sessionCost` (last `cost-state`
  `totalCostUSD`, else null), and one `ClaudeTurn` per distinct assistant
  `message.id`. A record without an id becomes its own anonymous turn. Each
  turn is timestamped at its id's earliest record, carries that id's first
  non-null model and the successful `Write`/`Edit`/`NotebookEdit` paths of any
  of its records (errored tool results excluded), and reads
  `input_tokens`, `output_tokens`, `cache_read_input_tokens`,
  `cache_creation_input_tokens`, and
  `output_tokens_details.thinking_tokens` once from `message.usage` with cost
  null. Every field is independently null when missing or non-numeric.
- Rewrote `src/harness/claude/claude-usage.ts` on top of `parseClaudeTurns`:
  `parseClaudeSession` now returns `turns` plus `harnessVersion` and
  `sessionCost`, stops deriving usage from `cost-state` counters, stops setting
  `startedAt`/`endedAt`, and still returns null when no edit exists.
  `readClaudePlanningSessions` merges files that share a session id through
  `mergeTurns`, which keeps each message id once (choosing the earliest
  timestamp and unioning edits) and rebuilds merged turns. `edits` is derived
  from the turns for the legacy field. Turn identity is carried in a
  non-enumerable `messageId`, so the serialized `PlanningTurn` shape is
  unchanged.
- `tests/planning-observed-claude.test.ts`: the session-level usage assertions
  now expect all-null usage, `sessionCost` 0.5, `harnessVersion` null, and
  `startedAt`/`endedAt` undefined. The edit, model, identity, and no-content
  assertions are unchanged.
- Added `tests/planning-claude-turns.test.ts`: asserts the fixture session has
  three turns with a three-record message counted once, the edited message's
  edit, a no-usage message with null tokens, the merged subagent duplicate not
  adding turns, null session cost, and the harness version from
  `source.json`; a second anonymous-record test; and a malformed-usage test that
  yields null turn tokens and still approves through `approveSpec`.
- Added `tests/fixtures/planning-claude/`: `source.json`
  (`{"harness":"claude","version":"2.1.280"}`) and
  `project-alpha/session-turns.jsonl` plus `session-subagent.jsonl`, one
  content-free session split across two files (a three-record message, a
  two-record message with a `__INSIDE_PATH__` edit, a message without usage, no
  `cost-state`, and duplicated ids in the subagent file).

## Deviated

- Acceptance requires the session to "no longer set `usage`". However,
  `ObservedPlanningSession.usage` is still a required field and
  `src/core/report/planning-observed.ts` is not in this task's scope, so the
  reader sets `usage: NULL_INTERACTIVE_USAGE` (and derives `edits` from the
  turns). This follows task 3's recorded cross-task note that tasks 4 to 6 keep
  the two legacy fields populated until a task owning `planning-observed.ts`
  makes them optional. `startedAt`/`endedAt` are omitted because that file was
  already changed to make them optional.
- `tests/planning-observed-claude.test.ts` also updates its `startedAt`/
  `endedAt` assertions; those are unavoidable because the session no longer
  sets them, even though the frozen assertion rule names only session-level
  usage.
- Merge identity uses a non-enumerable `messageId` rather than adding an
  enumerable field: `PlanningTurn` (owned by `planning-slice.ts`, out of scope)
  has no id, and an enumerable field would change the turn's serialization and
  deep equality.

## Missing context
