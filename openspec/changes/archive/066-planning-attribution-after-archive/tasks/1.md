## Acceptance

- [ ] When `resolveChangeApprovalTime` is given a change folder that does not exist, it looks up the same folder name under `archive/` beside it: `archive/<name>` and every `archive/<name>-<n>`. Among those, a folder with a recorded slice for the session wins; otherwise it takes the manifest `approvedAt` of the highest-suffix folder, with unsuffixed lowest.
- [ ] When no archived folder matches, it looks up `rejected/<name>`. A recorded slice for the session wins; otherwise the `timestamp` in `.run/rejected.md` is the boundary.
- [ ] An existing folder resolves exactly as today, and the result stays cached per folder and session.
- [ ] New `tests/planning-slice-archive.test.ts` builds real folders in a temporary changes directory and calls `sliceChangeOwnership` with `resolveApproval` wired to the real `resolveChangeApprovalTime`. The session edits 063 at 10:00, has turns without edits at 10:05, 10:10 and 10:20, and edits 064 at 10:30. 063 is approved at 10:11, recorded as a `plan_exited` slice for the session, and 064 at 10:40. It asserts that 064 owns exactly 10:20 and 10:30 with 063 active, moved to `archive/063-…`, and moved to `archive/063-…-1` beside an unrelated `archive/063-…`.
- [ ] The same file asserts that no turn lands in both changes: slicing 063 at its own approval, with 063 active, gives 10:00, 10:05 and 10:10, which is disjoint from 064's slice.
- [ ] The same file covers 063 rejected at 10:11 with no recorded slice: it is moved to `rejected/063-…` with `.run/rejected.md` frontmatter `timestamp` at 10:11, and 064 owns only 10:20 and 10:30.
- [ ] `planning-slice-lookup.ts` stays under 250 lines, and no new function exceeds 80 lines.

## Details

The turn owner stays the folder path the edit was recorded under
(`changeFolderForPath` in `planning-slice.ts`), so `planning-slice.ts` does not
change. Only the time lookup for that path falls back. The archive and rejected
folders are `archive` and `rejected` directly under the changes directory,
matching `changeFolderForPath` and `src/watcher/archiver.ts`, which suffixes
collisions `-1`, `-2`, and so on.

Reuse `readPlanRecords` and `validIso` as the existing lookup does. Read
`.run/rejected.md` with `getRejectedMarkerPath` from `src/core/status/layout.ts`
and `parseFrontmatter` from `src/core/spec/parser.ts`, as `src/core/status/status.ts`
does in `readRejectedSummary`. Use the `sliceRecord`, `turn`, and `edit` helper
shapes from `tests/planning-slice.test.ts` as a model. That file stays frozen
and green.
