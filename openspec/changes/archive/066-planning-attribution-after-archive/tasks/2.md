## Acceptance

- [ ] `PlanningComparisonSide` types `input`, `output`, `cached`, and `reasoning` as `number | null`, like `cost`.
- [ ] In `getMetricsReport`, each planning comparison token total is null until a planning session's usage reports that kind, then sums as today. The execution side keeps its current values. `planning.tokens` stays numeric, with 0 where nothing was reported, as today.
- [ ] The `Planning vs execution` text lines print `not reported` for a null planning token total and the number otherwise. Per-change rows keep `unavailable`.
- [ ] `osq report --json`, through `toStableMetrics` in `src/cli/report.ts`, carries null for those fields.
- [ ] New `tests/report-planning-unreported.test.ts` builds a project with one planning session whose usage reports no tokens and asserts null for all four planning comparison token fields in the report and in the stable JSON, and `planning not reported` on each of the four token lines of `formatMetricsReport`. A second case with only `inputTokens` reported asserts input is a number while the other three are null.
