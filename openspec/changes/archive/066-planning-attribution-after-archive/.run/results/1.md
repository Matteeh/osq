## Changed

- `src/core/report/planning-slice-lookup.ts`: `resolveChangeApprovalTime` now
  keeps its existing direct lookup for a folder that still exists, and when the
  folder is gone falls back to `archive/<name>` / `archive/<name>-<n>` beside the
  changes directory, then `rejected/<name>`. A recorded `plan_exited` slice for
  the session wins; otherwise the archived lookup takes the manifest `approvedAt`
  from the highest suffix (unsuffixed lowest) and the rejected lookup takes the
  `.run/rejected.md` frontmatter `timestamp`. The per folder and session cache is
  unchanged.
- `tests/planning-slice-archive.test.ts`: real change folders in a temp changes
  directory driven through `sliceChangeOwnership` with `resolveApproval` wired to
  the real `resolveChangeApprovalTime`. Covers 063 active (064 owns 10:20 and
  10:30, 063 owns 10:00/10:05/10:10, no overlap), 063 moved to `archive/<name>`,
  063 moved to `archive/<name>-1` beside an unrelated `archive/<name>` with a
  later manifest, and 063 moved to `rejected/<name>` with a 10:11 marker and no
  recorded slice.

## Deviated

- The archived manifest fallback scans from the highest suffix down and returns
  the first valid `approvedAt`, rather than reading only the single highest
  suffix folder's manifest. The spec's "highest-suffix folder" ordering is kept;
  the scan just tolerates a highest-suffix folder with no usable manifest. No
  acceptance line distinguishes the two.
