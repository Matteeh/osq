## Changed

- `src/core/report/planning-economics.ts`: `PlanningComparisonSide` now types
  `input`, `output`, `cached`, and `reasoning` as `number | null`, matching
  `cost`.
- `src/core/report/report.ts`: the four planning comparison token accumulators
  start at `null` and become a number on the first session that reports that
  kind (`(current ?? 0) + value`). `planning.tokens` stays numeric with `?? 0`.
  Added `formatComparisonToken` next to `formatComparisonCost`; the four
  `Planning vs execution` token lines use it so a null planning total prints
  `not reported`. Per-change rows still use `formatOptionalValue` and print
  `unavailable`.
- `src/cli/report.ts`: unchanged. `toStableMetrics` spreads the comparison
  sides, so the now-nullable fields serialize as JSON `null`.
- `tests/report-planning-economics.test.ts`: the `report --json` round trip now
  expects null for `output`, `cached`, and `reasoning` for the session that
  reported only `inputTokens`.
- `tests/report-planning-unreported.test.ts`: new. One session reporting no
  tokens asserts all four comparison planning fields are null in the report and
  in the stable JSON, with `planning not reported` on each of the four text
  token lines. A second case with only `inputTokens` asserts `input` is `7`
  while the other three are null.
