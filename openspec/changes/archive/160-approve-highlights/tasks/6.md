## Acceptance

- [ ] `WebReview` gains `readonly notices?: ApprovalNotices`, imported as a type from `src/core/spec/notices.ts`. `readWebReview` sets it from `buildApprovalNotices(projectRoot, details.folderPath, config, details.digest)` whenever it returns a review, as "Approve notices document" in the web-inspection delta says.
- [ ] The `approve` member of `WebActionRequest` gains `readonly opened?: readonly string[]`. `parseActionRequest` accepts an `approve` body with `opened` as a list of strings, keeps the field off the request when the body has none, and answers any other `opened` with 400, as the modified "Loopback write actions" says.
- [ ] `osq serve`'s approve command in `serve-actions.ts` passes a request's `opened` to `approveCommand` as `openedNotices`, and passes nothing when the request has none.
- [ ] New `tests/web-notices.test.ts` covers "Review with notices" through `getWebChange`, "Approve with opened notices" through `startWebServer` with a recording `runAction` as `tests/web-actions.test.ts` posts, and the serve wiring through `createWebActionRunner` with its default commands on a temporary project whose change removes a requirement: `{ verb: 'approve', change, opened: [] }` gives exit code 1 with the refusal and no `.run/approved`, and `opened: ['removed_requirement']` approves.
- [ ] Every existing test passes unchanged; `tests/web-actions.test.ts` still sees `{ verb: 'approve', change: '001' }` for a body without `opened`.

## Details

The default runner's `approveCommand` reads local planning stores. Set the
planning-reader environment variables to nonexistent paths around that case
and restore them after, as `tests/ui-actions.test.tsx` does.

`getWebChange` already passes `readWebReview` the details whose `digest`
`getSpecDetailsFromFolder` built; do not build the digest again.
`src/core/web/` must not import from `src/cli/`.
