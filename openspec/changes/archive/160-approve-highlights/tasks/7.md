## Acceptance

- [ ] `contracts.ts` re-exports, as types only, `ApprovalNotices`, `ApprovalNotice` and `NoticeSeverity` from `src/core/spec/notices.ts`. New `NoticePanel` renders "Notice block view" in the web-inspection delta: a `Notices` `h3`, `Nothing unusual` when `unusual` is false, one `<details>` per shown notice with a `<summary>` holding the severity word and the label and the detail below it, and one `<details>` summarised `<k> more` holding the rest. Opening any notice calls an `onOpen(id)` prop.
- [ ] New `notice-state.ts` exports `unopenedRedLabels(notices, opened)`, the labels of red notices whose ids are not in `opened`, in notice order, and `approveInput(opened)`, which gives `{ verb: 'approve', opened }` with the ids sorted, or `{ verb: 'approve' }` when `opened` is undefined. `WebActionInput`'s approve member gains `readonly opened?: readonly string[]`.
- [ ] `ChangeView` keeps the opened ids in state and, for a review with `notices`, renders `NoticePanel` after the header and error and before `BriefPanel`, and passes `ChangeActionsPanel` the opened ids and `unopenedRedLabels`. `ChangeActionsPanel` posts `approveInput(opened)` for an approve tap, `opened` undefined when the review has no notices. `ChangeActions` takes optional `approveBlockedBy` labels: while it is non-empty the Approve button is disabled and its item shows `Open each red notice to approve: <label>, <label>`.
- [ ] New `packages/ui/src/change/notices.css`, imported by `main.tsx` next to `review.css`, gives each notice a `notice-red`, `notice-amber` or `notice-grey` class with a `border-inline-start` stripe in `var(--status-dead)`, `var(--status-regressed)` or `var(--status-pending)`, and the notice text `overflow-wrap: anywhere`.
- [ ] New `tests/ui-notices.test.tsx` covers every scenario of "Notice block view" with `renderToStaticMarkup`: the section before the brief, `Nothing unusual` with a grey notice, five shown and `2 more`, `ChangeActions` disabled with `approveBlockedBy` and enabled without it, `unopenedRedLabels` and `approveInput` for the opened case, and, for phone width, reads `notices.css` and checks the stripe tokens and `overflow-wrap`. It also renders a document built by `getWebChange` for a change that removes a requirement and finds the `removes requirements` notice.
- [ ] Every existing test passes unchanged; a review without `notices` renders the same markup as before, and every new file stays at or under 250 lines.

## Details

The UI imports from `src/` only as types; `tests/import-graph.test.ts`
fails a runtime import. The test file itself may import `getWebChange` and
the helpers in `tests/planning-observed-helpers.ts` at runtime, as
`tests/ui-review.test.tsx` does, setting the planning-reader environment
variables to nonexistent paths and restoring them after.

`tests/ui-change.test.tsx` reads every entry of `packages/ui/src/change/` and
fails if one contains `EventSource`, `addEventListener`, `setInterval`,
`setTimeout`, `fetch(`, `dangerouslySetInnerHTML` or the lower-case word
`markdown`, in comments and CSS too. Put every new file directly in that
folder and avoid those words; use React's `onToggle` on `<details>` to see an
opening.

A static render cannot open a notice, so test the gate through
`ChangeActions` props and the two pure helpers.
