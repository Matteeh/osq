## Acceptance

- [ ] New `src/core/spec/plan-ready-record.ts` exports `recordPlanReady(projectRoot, folderPath, config)`, resolving to true when it appended a record. It appends nothing when the folder has `.run/approved` or `.run/rejected.md`, or when `hashChangeFolder` equals the last `readPlanReady` record's hash; otherwise it builds the digest with `buildApprovalDigest`, the notices with `buildApprovalNotices`, and calls `appendPlanReady` with `recordNotices` of them.
- [ ] `lintCommand` calls `recordPlanReady` for each folder whose lint result is valid, only when it was given explicit ids, in JSON mode too, before it throws for an invalid folder.
- [ ] New `tests/plan-ready-lint.test.ts` covers every scenario of "Plan ready records" in the spec-lint-and-approve delta through `lintCommand` on temporary projects built as `tests/lint-command-error.test.ts` builds them, and checks that `readPlanRecords` still returns only the planning-session records of a log holding `plan_ready` lines.
- [ ] Every existing test passes unchanged, and no test writes into `fixture/`.

## Details

Lint runs in the planner's checkout, so the record lands in the draft's
`.run/plan.jsonl`, which approval already carries into the worktree. The
change-folder hash excludes `.run/`, so the record never changes the hash
approval seals.
