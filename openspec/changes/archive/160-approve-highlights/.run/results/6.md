## Changed

- `src/core/web/web-data-types.ts`: imported `ApprovalNotices` as a type and
  added `readonly notices?: ApprovalNotices` to `WebReview`, per "Approve
  notices document".
- `src/core/web/web-data-review.ts`: `readWebReview` now sets `notices` from
  `buildApprovalNotices(projectRoot, details.folderPath, config, details.digest)`
  whenever it returns a review, so `getWebChange` always carries them without
  rebuilding the digest.
- `src/core/web/web-actions.ts`: the `approve` member of `WebActionRequest`
  gained `readonly opened?: readonly string[]`.
- `src/core/web/web-write.ts`: `parseActionRequest` accepts an `approve` body
  whose `opened` is a list of strings, keeps `opened` off the request when the
  body has none, and returns 400 (`approve opened must be a list of strings`)
  for any other `opened`.
- `src/cli/serve-actions.ts`: the default `approve` command passes the
  request's `opened` to `approveCommand` as `openedNotices` only when the body
  carried it; without it the command receives plain inputs as before.
- Added `tests/web-notices.test.ts`, covering "Review with notices" through
  `getWebChange` (equality with `buildApprovalNotices` for the folder and the
  red `removed_requirement` notice), "Approve with opened notices" through
  `startWebServer` with a recording `runAction` (opened carried; a non-list
  `opened` returns 400 without calling it; a body without `opened` leaves the
  field off), and the serve wiring through `createWebActionRunner` with its
  default commands on a temporary project whose change removes a requirement
  (`opened: []` refuses with the red-notice message and writes no
  `.run/approved`; `opened: ['removed_requirement']` approves).

`node --import tsx --import ./tests/git-test-env.ts --test
tests/web-notices.test.ts` passes (4 tests). The proposal verify `pnpm verify`
passes: both typechecks, the build, every CLI and UI test, and lint.
