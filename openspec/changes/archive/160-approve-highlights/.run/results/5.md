## Changed

- `src/core/spec/digest.ts`: `ApprovalDigest` gains `readonly notices?: ApprovalNoticeRecord`, where `ApprovalNoticeRecord` is `{ readonly items: readonly RecordedNotice[]; readonly opened: readonly string[] | null }`, declared here with `RecordedNotice` imported as a type. `buildApprovalDigest` never sets it; `digest.ts` stays at 250 lines.
- `src/core/spec/approve-worktree-shared.ts`: `ApprovalReviewOptions` gains `openedNotices?: readonly string[]`, and its `review` port becomes `(digest, notices: ApprovalNotices) => Promise<ApprovalReview>`. `confirmApproval` builds the notices with `buildApprovalNotices`, refuses an unopened red notice before calling `review` with `open each red notice before approving: <label>, <label>`, and returns the digest with `notices` set from `recordNotices` plus `opened` holding the given ids that name a notice, distinct and sorted, or null when `openedNotices` was not given. `writeApprovalSeal` passes `digest.notices` to `buildManifest`.
- `src/core/run/manifest.ts`: `ManifestData` gains `notices?: ApprovalNoticeRecord`; `buildManifest` records the approval digest's notices next to `approvalFlags`, and a planning-only manifest (no approval flags) omits it. `manifest.ts` stays under 250 lines.
