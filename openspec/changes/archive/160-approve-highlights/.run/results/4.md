## Changed

- Added `src/core/spec/plan-ready-record.ts`: `recordPlanReady(projectRoot, folderPath, config)` returns false when the folder has `.run/approved` or `.run/rejected.md`, or when `hashChangeFolder` equals the last `readPlanReady` record's hash; otherwise it builds the digest with `buildApprovalDigest`, the notices with `buildApprovalNotices`, appends one `plan_ready` line through `appendPlanReady` with `recordNotices` of them, and returns true.
- `src/cli/lint.ts`: after linting each folder, when the folder's result is valid and the command was given explicit ids, it calls `recordPlanReady`. Recording happens before the command throws for an invalid folder, and in JSON mode too.
- Added `tests/plan-ready-lint.test.ts`, built on temporary scaffolded projects as `tests/lint-command-error.test.ts` does. It covers the "Plan ready records" scenarios: first clean lint records one line with the folder hash and the change's notices; a second unchanged lint appends nothing; a revised plan appends a second record and counts one revision; a failing lint, an approved folder, a rejected folder, and `osq lint` without ids append nothing; JSON mode records; and `readPlanRecords` still returns only the planning-session records from a log holding `plan_ready` lines.
