## Details

Port `landChange` in `src/core/vcs/land.ts` without the sync, the
after-land command, the cleanup and the recorded stops. Port
`buildSquashMessage` and `formatSquashMessage` in
`src/core/run/squash-message.ts` over `osq_kernel_storage::read_land_facts`,
and `changeTrees` and `matchesFolder` in
`src/core/status/change-locations.ts`. The match is the one
`crates/features/approve/src/approve/find.rs` holds. Features never share
code, so write it again here. Model `LandFeature` on `ApproveFeature`, and
build errors only through core's constructors. Read settings with
`osq_kernel_config::load_config` and git with `osq_kernel_vcs::GitVcs`
through the `Vcs` trait: a `GitVcs` at the root for the checkout, and one
at the change's worktree path for its `head` and `status`.

Task 3 adds refusals to `run_land` between the lookup and the landed
report, and between the landed report and the tip check. Keep those two
points easy to find in `run_land`. The test helpers must let task 3 build
everything its rows need without changing `tests/support/mod.rs`:

- a land repository in a fresh folder named after the test and row under
  `env!("CARGO_TARGET_TMPDIR")`, removed first if it is left over, since
  tests run in parallel;
- a worktree change with any archived folder files, including the fixture
  change from `tests/fixtures/land-change/001-alpha-orders`;
- commits on `main` or on a change's branch that write given files;
- a git runner for the checkout or a worktree.

Run every helper git command with the isolated settings of
`crates/kernel/vcs/tests/support/mod.rs`, the fixed author and committer,
and `GIT_CONFIG_GLOBAL=/dev/null`. The feature's own `GitVcs` still reads
the user's global config, so the repository's local `commit.gpgSign
false`, `user.name` and `user.email` are what keep its commits
deterministic and unsigned.

The expected message comes from `tests/fixtures/land-message.txt`, with
`<head>` replaced by `git rev-parse osq/001-alpha-orders` taken before
`land` runs. Never edit or regenerate the fixtures; copy them with `cp -r`
and `cp`. In "Git refuses the fast-forward", create the lock file at the
path `git rev-parse --git-path index.lock` prints in the checkout, and
remove it afterwards.

cargo-mutants runs on every line this task adds, so each branch must
change a value a row checks. That means each match form, the worktree
filters (branch prefix, the root itself, the held folder), the archived
choice and the checkout fallback, the landed check and its two texts, and
the two lookup failures. It also means each message part and trailer,
the distinct-value order, the moved checks, both blocked texts, the
fast-forward failure and its head comparison, and the changed-path lines.
Before exiting, run
`cargo fmt --all`, then
`cargo mutants -p osq-feature-land -f <file> -o "$(mktemp -d)"` on each
new source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE` set to
`openspec/changes/256-rust-land-feature`.
