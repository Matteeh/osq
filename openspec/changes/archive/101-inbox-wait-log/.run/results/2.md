## Changed

- `src/core/status/dispatch-order.ts`: `orderDispatchItems` takes an optional fourth `firstSeen` map (`FirstSeenTimes`, `ReadonlyMap<string, Date>`), defaulting to empty. `compareOrdered` now breaks weight ties by first-seen time: logged items before unlogged ones, then earlier first-seen first, before change id and task number. `reasonFor` returns `waiting since <YYYY-MM-DD HH:MM>` (local time) when neither the idle nor the holds-up reason applies and the item has a first-seen time; every existing reason is unchanged. Added `formatSeen`/`two`, `compareFirstSeen`, and the exported `FirstSeenTimes` type.
- `src/core/status/dispatch.ts`: `readDispatch` and `readDispatchQueue` take an optional `home` defaulting to `os.homedir()`. A new `firstSeenFor` reads `readWaitLog` and folds it with `firstSeenTimes`, or returns an empty map when there is no log; `orderedQueue` passes it to `orderDispatchItems`.
- `src/core/status/dispatch-watch.ts`: `WatchDispatchOptions` gains optional `home`, and `WatchContext` carries the resolved home. `OnItems` gains a third `idle` argument; `deriveOnce` reads the wait log under `ctx.home`, folds it, orders with those first-seen times, and calls `onItems(items, at, dispatch.watcherIdle)`.
- `tests/dispatch-age.test.ts`: new tests for the delta's "First seen breaks ties", "Logged before unlogged", and "Idle and first seen" scenarios. They build temporary projects as `tests/dispatch-order.test.ts` does, write the wait log under a temporary home as JSON lines, and drive the watch with local fakes modelled on `tests/dispatch-watch.test.ts`.

## Deviated

- The new tests write the wait log as JSON lines through `resolveWaitLogPath` rather than through `createWaitRecorder`; the task allowed either. This keeps the ordering assertions independent of the recorder's session bookkeeping.
- I did not touch `src/core/status/dispatch-follow.ts` or `dispatch-session.ts`. Their initial `readDispatch` previews still default to `os.homedir()`; passing `home` through the command and session belongs to tasks 3 and 4. Existing follow tests pass unchanged.
