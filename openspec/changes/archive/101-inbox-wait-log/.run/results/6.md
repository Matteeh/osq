## Changed

- `src/core/report/report.ts`: `MetricsReport` gains an optional `inboxWait`
  (`InboxWaitReport`). `getMetricsReport` takes a third `options` argument
  (`InboxWaitOptions`: `home`, `since`, `until`), calls `collectInboxWait`, and
  adds `inboxWait` to the returned report only when it is not null.
  `formatMetricsReport` prints `formatInboxWait`'s lines as their own section
  directly after the `Mutation:` section, before `Coverage:`.
- `src/cli/report.ts`: `ReportCommandOptions` gains `home`, `since`, and
  `until`. Added and exported `parseReportPeriod(since, until)`, which reads
  each given value with `Date.parse` and throws
  `--since is not a date: <value>` / `--until is not a date: <value>` /
  `--since must be before --until`. `reportCommand` calls it inside its existing
  `try` and passes `home`/`since`/`until` to `getMetricsReport`.
  `toStableMetrics` copies `inboxWait` only when present.
- `src/cli/index.ts`: `report` registers `--since <date>` and `--until <date>`
  and forwards them; the file stays within the 250-line budget at 248.
- `README.md`: the Human Attention Inbox section documents the per-project wait
  log under `~/.osq/inbox/` (first seen, card opened, gone, watcher idle at each
  moment), the unobserved marks, that the one-shot and `--json` output write
  nothing, and the first-seen tiebreak. Metrics & Reporting documents what the
  `Inbox waiting` section shows, the `--since`/`--until` flags, and the flag
  example.
- `tests/report-inbox-wait-cli.test.ts`: new test covering the delta's five
  scenarios (section printed from the fixture log under a temporary home, period
  passed through, no log unchanged, bad date through `parseReportPeriod`, and
  the registered `--json`/`--since`/`--until` options).

## Deviated

- `getMetricsReport`'s `options` is typed as the existing `InboxWaitOptions` and
  passed straight through to `collectInboxWait`. The spec's "defaulting to
  `os.homedir()`" therefore happens in `readWaitLog`/`resolveWaitLogPath` rather
  than a second default in `getMetricsReport`; behaviour is the same.
- The CLI test uses the existing `fixture/report` tree as the project root and
  copies `fixture/report/inbox-wait.jsonl` under a fresh temporary home, rather
  than building a new minimal tree. The task only required the fixture log be
  placed under a temporary home.
