## Acceptance

- [ ] A verified task of a change in an osq worktree is committed as rust-run "Verified task commit" says, with the message "Task commit message" gives; a failed commit fails the run and keeps every file.
- [ ] The paths come from the in-scope and test-folder rules `scope.rs` already holds, so the audit and the commit share one source.
- [ ] The message is a pure function in its own module under `src/feature/`, so task 4 reuses it for the dead commit.
- [ ] New `tests/run_worktree.rs` proves "Verified task commit", "Verified task commit fails" and "Trailers from the last started event", building its repositories with task 2's `tests/worktree_support/mod.rs`, which it may extend.
- [ ] Every existing run test passes unchanged, `tests/run_worktree_tree.rs` included.
- [ ] Every public item ends its doc with `Implements: rust-run/<requirement>`, and each new test's doc names `Covers: rust-run/<scenario>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Commit with a `GitVcs` at the tree's root that task 2 finds. Write the
hook in the failing-commit test with mode `0o755` through
`std::os::unix::fs::PermissionsExt`. A test cannot set environment
variables.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source. Run the proposal's verify as the watcher does,
with `OSQ_CHANGE=openspec/changes/301-rust-run-worktree`, so the link
gates see this change's requirements.

## Scenarios

- rust-run: Verified task commit
- rust-run: Verified task commit fails
- rust-run: Trailers from the last started event
