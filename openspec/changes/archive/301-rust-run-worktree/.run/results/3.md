## Changed

- Added `crates/features/run/src/feature/commit.rs`: a verified task in an
  osq worktree commits its scoped status paths, its untracked test files and
  whichever of `.run/done/<task>`, `.run/results/<task>.md`,
  `.run/events/<task>.jsonl` and `tasks.md` exist. A refused commit leaves
  every file as it was and fails with
  `task <task> of <folder> is done, but osq could not commit it: <error>`.
- Added `crates/features/run/src/feature/message.rs`: TypeScript's pure
  `formatCommitMessage`, the `Osq-Change`, `Osq-Task`, `Osq-Model` and
  `Osq-Version` trailers from the last complete `started` event, the folder's
  leading-digit id, and whole elapsed seconds from the last `started` event,
  clamped at zero.
- Extended `scope.rs` with `commit_paths`, sharing `audit_input` with the
  scope audit so scope coverage, lock rules and test folders have one source.
  Change-folder files other than the four records stay out, as TypeScript's
  verified commit does.
- `run.rs` commits after the done record only when the change's tree differs
  from the checkout; `worktree.rs` gained `is_worktree` for that check.
- `start.rs` records the crate version as `osqVersion` so the run's own
  `started` event carries the two extra trailers.
- `text.rs` gained the failed-commit message.
- Added `tests/run_worktree.rs`, proving "Verified task commit", "Verified
  task commit fails" and "Trailers from the last started event", plus the
  untracked test-file rule, pre-existing out-of-scope files, elapsed seconds
  and complete-event trailer selection.
- Extended `tests/worktree_support/mod.rs` with an executable refusing hook,
  exact stored-message reads, the last started event, and a repository whose
  seal is committed.

## Deviated

- The worktree test repository drops the fixture's `.gitignore`, whose
  `.run/` rule made git refuse the done, result and event records, and its
  approval commit now commits the seal instead of using `--allow-empty`.
- `start.rs` now sets `osqVersion` where task 2 left it absent, because the
  required `Osq-Version` trailer must come from the run's own `started` event.
- Extra tests import `message.rs` with a fixed test clock, so elapsed seconds
  and trailer selection are proven without waiting on the clock.

## Missing context

- The task did not say where `osqVersion` comes from. I used the run crate's
  workspace version, which the test reads back from the started event.
