## Changed

- `src/core/vcs/sync-verify.ts`: `runOne` now writes each passing run's whole
  output with `writeVerifyLog(options.change.folderPath, 'change', output)`,
  records the `.run/logs/change-<n>.log` path as the `verify_ran` event's `log`,
  and sets `output` to `tailVerifyOutput(output, config.limits)` only when that
  tail is not blank. The sync still stages only `change.jsonl`, so the commit
  holds no log file.
- `src/watcher/worktree-run.ts`: `haltWorktreeChange` takes a fifth
  `limits: VerifyExcerptLimits = DEFAULT_CONFIG.limits` parameter and writes
  `tailVerifyOutput(halt.detail, limits)` as both the `.run/regressed/change.md`
  body and the `regressed` event's `output`.
- `src/watcher/loop.ts`: all eight `haltWorktreeChange` calls pass
  `config.limits`; nothing else in the file changed.
- `src/watcher/stack-run.ts`: the `halt` helper takes its `limits` from its
  caller and both call sites pass `config.limits`.
- `src/core/lifecycle/retry.ts`: the `recertification` event's `output` is
  `tailVerifyOutput(gate.output, config.limits)` for both outcomes.
- `tests/verify-log-sync.test.ts` (new): drives an active change through
  `syncWithDefaultBranch` with a done task whose verify prints 100 lines and
  asserts the log holds all 100 lines, the event holds lines 61-100 with the
  `change-1.log` path, and the sync commit holds no file under `.run/logs/`.
- `tests/event-output-tail.test.ts` (new): covers "Halt detail cut",
  "Configured tail length", "Human recertification tail", and that a one-line
  halt detail and a short passing recertification output are kept exactly.
