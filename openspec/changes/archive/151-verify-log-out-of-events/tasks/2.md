## Acceptance

- [ ] For each passing command, `runSyncVerify` writes the log with `writeVerifyLog(change folder, 'change', output)` and appends its `verify_ran` event with `log` and with `output` set to `tailVerifyOutput(output, config.limits)` only when that tail is not blank. It stages nothing new: the sync commit holds no file under `.run/logs/`.
- [ ] `haltWorktreeChange` takes a fifth parameter `limits: VerifyExcerptLimits = DEFAULT_CONFIG.limits` and writes `tailVerifyOutput(halt.detail, limits)` as both the body of `.run/regressed/change.md` and the `regressed` event's `output`. Every call in `src/watcher/loop.ts` and `src/watcher/stack-run.ts` passes `config.limits`; `stack-run.ts`'s `halt` helper takes the limits from its caller, and `loop.ts` changes nothing but those calls.
- [ ] `retrySpec` records its `recertification` event's `output` as `tailVerifyOutput(gate.output, config.limits)`, for both outcomes.
- [ ] New `tests/verify-log-sync.test.ts` covers "Sync verify log" of "Verify output logs" through `syncWithDefaultBranch`, with a setup like the one in `tests/vcs-sync.test.ts`.
- [ ] New `tests/event-output-tail.test.ts` covers "Halt detail cut", "Configured tail length" and "Human recertification tail" of "Events that keep a tail", and checks that a one-line halt detail and a short passing recertification output are kept exactly. It calls `haltWorktreeChange` on a located change as `tests/worktree-run.test.ts` does, and `retrySpec` on a scope-regressed task set up like `tests/retry-recertification.test.ts` does.
- [ ] Every existing test passes unchanged. Every file touched other than `src/watcher/loop.ts` stays at or under 250 lines, and every new function at or under 80.
