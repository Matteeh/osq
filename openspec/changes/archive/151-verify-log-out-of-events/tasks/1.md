## Acceptance

- [ ] New `src/core/run/verify-log.ts` exports `writeVerifyLog`, and `src/core/run/verify-excerpt.ts` exports `tailVerifyOutput` (ports below), each doing what "Verify log files", "Verify logs ignored by git" and "Event output tail" say. `writeVerifyLog` creates `.run/logs/` and its `.gitignore` (holding `*` and a newline) when missing, and numbers a log by counting the `<target>-<k>.log` files already there.
- [ ] `runVerificationGateResult` with an event context writes the log of every run, pre-spawn included, then appends `verify_ran` with `log` and with `output` set to the tail only when the tail is not blank, and returns `log` (null without a context). Its limits come from the `config` it is given, else `DEFAULT_CONFIG.limits`.
- [ ] `formatPreSpawnDeadMarker`, `verifyRedFailure`, `formatChangeVerifyMarker`, the archive-time marker in `archive-verify.ts`, and `buildScopeRegressionMarker` end their excerpt with `Full output: <log>` whenever the run's log is known, and keep today's event wording only when it is not. `archive-verify.ts` builds its marker from `runVerificationGateResult`'s output and log and no longer reads its `verify_ran` line back. Timed-out, focused and baseline markers are unchanged.
- [ ] `regression.ts` sets the audit's `log` from the gate, records the scope audit's `regressed` event `output` as `tailVerifyOutput(..., options.limits)`, and passes `autoRecertify` a gate result whose `output` is that tail, so `auto-recertify.ts` itself is unchanged.
- [ ] New `tests/verify-log.test.ts` covers every scenario of "Verify output logs", "Verify log files" and "Verify logs ignored by git" except "Sync verify log", every scenario of "Event output tail", "Scope audit tails" of "Events that keep a tail", and "Verify log run number" of "Dead marker fingerprint", through `writeVerifyLog`, `tailVerifyOutput`, `runVerificationGateResult` with an event context, the scope audit, and `markerFingerprint`. The golden fixtures `tests/fixtures/events/verified.jsonl` and `dead.jsonl` are regenerated with `UPDATE_GOLDEN=1` and differ only by the new `log` keys and any tailed `output`.
- [ ] In `tests/dead-marker-excerpt.test.ts` the task, change and pre-spawn cases expect `Full output: ` plus the `log` of the matching `verify_ran` event, and read all 100 lines from that file instead of from the event's `output`. `tests/scope-regression-excerpt.test.ts` does the same, and expects the `regressed` event's `output` to be the last 40 lines. `tests/verify-excerpt.test.ts` changes only its archive-time block, which expects the log pointer and reads `noise 500` from the log. Every assertion of `excerptVerifyOutput` itself, and the focused and baseline cases, stay as they are.
- [ ] `normalizeFailureBody` in `src/watcher/fingerprint.ts` replaces the run number of a `.run/logs/<target>-<n>.log` path with `<n>` and keeps the target, as "Dead marker fingerprint" says, so two identical deaths still share a fingerprint and the second is marked stuck. Every other existing test passes unchanged, `tests/auto-retry.test.ts` and `tests/steering-triggers.test.ts` included. Every file touched other than `src/harness/types.ts` stays at or under 250 lines, and every new function at or under 80.

## Details

The tail keeps a text exactly when it has at most `markerOutputLines` lines
and none is longer than `markerLineChars`; `tests/retry-prior-output.test.ts`
and `tests/osq-change-env.test.ts` compare short outputs byte for byte,
trailing newline included. Count lines after trimming trailing whitespace.
Cut a long line with the same rule `excerptVerifyOutput` uses; share that
code within `verify-excerpt.ts`.

The log holds the output exactly as `runVerificationCommand` returned it, the
project root already made relative. Write the log before appending the
event, so an event never names a missing file.

`runSyncVerify` in `src/core/vcs/sync-verify.ts` is task 2's; leave it alone.
