## Details

The fixture is data: it is never built, and `cargo fmt` does not reach it.
Never edit it or the scenario table. If a row fails, the rule is wrong.

Rules that are easy to miss:

- `live-references` reports the end of the edge that is named, and the
  finding is about the other end. For `supersedes` and `governs` the named
  end is `from`: `superseded_by: 3` gives the edge `adr:003` to `adr:002`,
  and its finding is about `adr:002`.
- A `governs` edge to a `Capability` node is never checked. A `governs`
  edge to an item, test or file comes from an `Adr:` tag.
- `tagged-functions` skips structs (`Total`), `pub(crate)` methods
  (`Total::set`), private functions and `pub` helpers in `tests/`.
- `complete-capabilities` checks only the capabilities it holds. With the
  group `tools`, `notes` is out of scope.

cargo-mutants runs on every line this task adds. The fixture covers each
rule's main branches. If a mutant survives that the fixture cannot reach,
such as the `src` folder check in `tagged-functions`, add a fast test in
the new `crates/kernel/linter/tests/link_gates_edges.rs` that builds a
`Graph` by hand. Before exiting, run
`cargo mutants -p osq-kernel-linter -f <file> -o "$(mktemp -d)"` on each
new source file.
