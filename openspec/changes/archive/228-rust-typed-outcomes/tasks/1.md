## Acceptance

- [ ] New `event/reasons.rs` holds `DeadReason`, `RegressionReason`, `FailureReason`, `RequeueReason`, `MutationReason`, `ValidatorReason` and `SyncStopReason`. New `event/outcomes.rs` holds `RecertificationOutcome`, `BaselineOutcome`, `FocusedOutcome`, `MutationOutcome`, `ValidatorOutcome`, `AutoSteerOutcome` and `VerificationOutcome`. Each enum's variants and their order are exactly the values of its row in rust-core "Reason and outcome values".
- [ ] Each enum derives `Clone`, `Copy`, `Debug`, `PartialEq`, `Eq`, `Hash`, `Deserialize` and `Serialize` with `#[serde(rename_all = "snake_case")]`, so each variant reads and writes as its row's string. Each has `pub const ALL: [Self; N]` in the row's order, and `pub const fn as_str(self) -> &'static str`.
- [ ] `FailureReason` implements `From<DeadReason>`, `From<RegressionReason>` and `From<RequeueReason>`, each giving the variant with the same `as_str`.
- [ ] `event.rs` declares both modules as `pub mod` and re-exports every enum next to the payload types, so `osq_core::event::DeadReason` names it. Payload fields stay `String` in this task; task 2 switches them.
- [ ] New `tests/event_values.rs` proves rust-core "Reason and outcome values": for each enum, `ALL` mapped through `as_str` equals the row's values as literals copied from the scenario's table, and each variant writes with `serde_json` as that JSON string and reads back from it as the same variant. It also checks that every `DeadReason`, `RegressionReason` and `RequeueReason` converts into the `FailureReason` whose `as_str` is the same. Each test has a one-line doc naming `Covers: rust-core/reason-and-outcome-values`.

## Details

Every item and every variant gets a doc comment (ADR 023): one line per
variant naming when TypeScript writes it is enough. Each public enum and
`as_str` ends its doc with `Implements: rust-core/event-types`. The `From`
impls end with `Implements: rust-core/task-fold`. Nothing here does IO.

The value sets come from TypeScript. `DeadReason` is `RunTaskFailureReason` in
`src/watcher/failure-reason.ts`. `RegressionReason` holds `verify_red` and
`verify_path_missing` from `src/watcher/archive-verify.ts`, `scope_regression`
from `src/watcher/regression.ts`, and `WorktreeHaltReason` from
`src/watcher/worktree-run.ts`. `MutationReason` is `MutationNotMeasuredReason`
in `src/core/run/mutation-run.ts` plus `budget`. Read those files only to
check a value; the scenario's table is the contract.

cargo-mutants runs on every line this task adds. The `as_str` table test and
the `From` test must fail when any arm of `as_str` or any `From` arm changes.
