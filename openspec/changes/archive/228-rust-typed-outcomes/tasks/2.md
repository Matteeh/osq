## Acceptance

- [ ] In `payload.rs`, each field in the field table of rust-core "Event types" holds its enum from task 1 instead of `String`, and stays `Option` where it is optional today. The `reason` of `DoneManualData` and `RejectedData` stays `String`. A line holding a value outside the enum's set gives `InvalidData` naming its type, through the existing data parse in `event.rs`, which this task does not change.
- [ ] `TaskState::reason` becomes `Option<FailureReason>`. `apply_task` converts dead, regressed and requeue reasons with `From`, and matches `RecertificationOutcome::Passed` and `RecertificationOutcome::Requeued` with no catch-all arm.
- [ ] Storage reads the typed values. `DeadAttempt::reason` becomes a `DeadReason`, and `record_dead` stops trimming the reason and drops the `unknown` fallback; it still trims the task. Every row column that holds a reason or outcome gets the value's `as_str` text, so the read model's SQL text is unchanged.
- [ ] Every fixture value outside its set is replaced as the mapping below says, in the fixture event files and in the three row goldens in scope. `reading_snapshot.rs`, `read_model.rs`, `reading_events.rs` and `reading_history.rs` expect the new values. Core's `events.rs`, `fold.rs`, `fold_props.rs`, `gates.rs`, `edges.rs` and `display.rs` use the codes rust-core's "Event types", "Task fold" and "Change fold" tables now give. Every other case and expected value stays as it is.
- [ ] `event_corpus.rs` collects only `<change>/.run/events/*.jsonl` for each change folder directly under `openspec/changes/archive/`, per rust-core "Archived event logs round-trip", and still runs every one of those lines.
- [ ] New `tests/refused_values.rs` proves rust-core "Values outside their set are refused" with the scenario's lines as literals. Each test has a one-line doc naming `Covers: rust-core/values-outside-their-set-are-refused` and has no `#[ignore]`.

## Details

The scope globs are wide only because of the pattern limit. Change only the
core tests named above, the four storage tests named above, `refused_values.rs`,
and these fixture files:

- `fixtures/project/openspec/changes/archive/001-alpha/.run/events/2.jsonl` and `change.jsonl`
- `fixtures/project/openspec/changes/archive/010-late/.run/events/1.jsonl`
- `fixtures/spec-tables/openspec/changes/archive/001-planned/.run/events/2.jsonl` and `4.jsonl`
- `fixtures/history/openspec/changes/archive/001-run/.run/events/1.jsonl`, `2.jsonl` and `change.jsonl`
- `fixtures/spec-tables-rows/task_outcomes.json`
- `fixtures/history-rows/validator_runs.json` and `mutation_picks.json`

Task 1's `tests/event_values.rs` falls inside `crates/core/tests/*.rs`; leave
it as it is.

The mapping for fixture and test values. Each old value is used only where
the table says, so a plain search finds each one:

| Where | Old | New |
|---|---|---|
| `dead` `reason` | `" verify_failed "`, `"verify_failed"` | `"verify_red"` |
| `dead` `reason` | `"  "` (blank) | `"timeout"` |
| `dead` `reason` in `reading_events.rs` | `"r"` | `"crashed"` |
| `retry` `reason` on a task stream | `"verify_failed"`, `"human"` | `"verify_red"` |
| `retry` `reason` on the change stream | `"human"` | `"worktree_dirty"` |
| `regressed` `reason` | `"scope_changed"` | `"scope_regression"` |
| `regressed` `reason` with task `change` | `"land_conflict"` | `"sync_conflict"` |
| `recertification` `reason` | `"verify_failed"` | `"scope_regression"` |
| `sync_stopped` `reason` | `"dirty"` | `"sync_conflict"` |
| `validator_ran` `outcome` | `"passed"` | `"validated"` |
| `validator_ran` `reason` | `"one problem"` | `"no_scenarios"` |
| `mutation_ran` `outcome` | `"survived"` | `"not_measured"` |
| `mutation_ran` `reason` | `"two survived"` | `"command_failed"` |

In the goldens, `task_outcomes.json`'s `dead_reason` values `verify_failed`
and `unknown` become `verify_red` and `timeout`. In `validator_runs.json` and
`mutation_picks.json`, the `outcome` and `reason` cells take the new values
above. Do not touch `crates/kernel/storage/tests/golden/`; it holds the
archive's rows, which do not change.

In `tests/fold.rs`, the `requeued` row starts from a `Regressed` state whose
reason is `worktree_dirty`, so the fold visibly takes the event's
`scope_regression`.

Storage's row builders are in `model/event_rows.rs`, `model/stream_rows.rs`,
`model/validator_rows.rs`, `model/insert_events.rs` and
`model/task_outcome_rows.rs`. `read/snapshot/events.rs` holds `record_dead`.
`read/snapshot.rs` holds `DeadAttempt`, whose doc then reads "The event's
reason."

cargo-mutants runs on every line you change, storage's included. The fixture
tests (`read_model.rs`, `read_model_history.rs`, `reading_snapshot.rs`) must
fail when an `as_str` column mapping changes.
