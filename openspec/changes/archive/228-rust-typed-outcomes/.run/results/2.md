## Changed

- `crates/core/src/event/payload.rs`: every typed `reason`/`outcome` field now
  holds its enum from task 1 (`DeadReason`, `RegressionReason`,
  `FailureReason`, `RequeueReason`, `MutationReason`, `ValidatorReason`,
  `SyncStopReason`, `RecertificationOutcome`, `BaselineOutcome`,
  `FocusedOutcome`, `MutationOutcome`, `ValidatorOutcome`,
  `AutoSteerOutcome`, `VerificationOutcome`). The free-text reasons of
  `done_manual` and `rejected` remain `String`.
- `crates/core/src/fold/task.rs`: `TaskState::reason` is
  `Option<FailureReason>`; dead, regressed and requeue reasons convert with
  `From`, and `RecertificationOutcome` is matched by variant with no catch-all.
- `crates/kernel/storage`: `DeadAttempt::reason` is a `DeadReason`;
  `record_dead` keeps the event's reason untrimmed, still trims the task, and
  no longer substitutes `unknown`. Every reason/outcome row column maps through
  `as_str`, so the SQL text is unchanged.
- `crates/core/tests/refused_values.rs`: one test per scenario line, each with a
  one-line `Covers: rust-core/values-outside-their-set-are-refused` doc.
- `crates/core/tests/event_corpus.rs`: collects only
  `openspec/changes/archive/<change>/.run/events/*.jsonl`.
- Core and storage tests and the listed fixture event files and row goldens use
  the mapping's codes. Added fold tests for absent regressed/requeued reasons
  and for a retry that replaces an earlier reason, so cargo-mutants kills the
  conversions.

## Deviated

- Also changed `crates/kernel/storage/tests/reading_specs_outcomes.rs`: it held
  a `dead` line with reason `"r"`, which is now outside `DeadReason`; without
  the change the full verify fails. It uses `"crashed"` like the same value in
  `reading_events.rs`.
- Changed the fixture task of the `dead` line in `reading_events.rs`'s
  temporary stream to `"9"` so a non-empty event task is asserted over the
  stream id, which kills the `non_empty -> None` mutant.
- Added extra mutation-killing tests to `crates/core/tests/fold.rs`; they prove
  the unchanged-reason branches the scenario table requires.
