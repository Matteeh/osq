## Changed

- Added `crates/core/src/event/reasons.rs` with `DeadReason`, `RegressionReason`,
  `FailureReason`, `RequeueReason`, `MutationReason`, `ValidatorReason` and
  `SyncStopReason`. Each enum derives the required traits with
  `#[serde(rename_all = "snake_case")]`, lists its values in `ALL` in the
  rust-core "Reason and outcome values" order, and gives each variant's string
  through `as_str`. `FailureReason` has `From<DeadReason>`,
  `From<RegressionReason>` and `From<RequeueReason>` impls that keep the string.
- Added `crates/core/src/event/outcomes.rs` with `RecertificationOutcome`,
  `BaselineOutcome`, `FocusedOutcome`, `MutationOutcome`, `ValidatorOutcome`,
  `AutoSteerOutcome` and `VerificationOutcome`, each with `ALL` and `as_str`.
- `crates/core/src/event.rs` now declares `pub mod reasons` and
  `pub mod outcomes` and re-exports every new enum next to the payload types.
  Payload fields are still `String`, as task 1 requires.
- Added `crates/core/tests/event_values.rs`: one test per enum checks `ALL`
  mapped through `as_str` against the scenario table's literals and round-trips
  every variant through `serde_json`; one test checks the three `From` impls.
  Every test's doc names `Covers: rust-core/reason-and-outcome-values`.

## Deviated

- The value table is split into one test per enum rather than one large test,
  because clippy's `too_many_lines` limit (80) rejects a single test holding
  all fourteen rows.
