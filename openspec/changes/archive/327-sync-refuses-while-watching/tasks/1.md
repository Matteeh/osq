## Acceptance

- [ ] `syncChange` takes an optional last parameter `home` and, after the change lookup and before the running-task check, refuses through `readWatchState(projectRoot, home)` as the modified version-control "Sync on request" says, naming the service's pid when a service record is live and the watcher's pid otherwise.
- [ ] `tests/vcs-sync-command.test.ts` gains one test proving "Watcher running", checking every row. It writes the records with `writeWatcherRecord` and `writeServiceRecord` under a new scratch `home` folder, which `afterEach` removes. Every existing case in the file passes unchanged.
- [ ] `syncChange`'s doc carries `@scenario version-control: Watcher running` and `@adr 012`. `pnpm typecheck:cli` passes.

## Details

`src/cli/sync.ts` keeps calling `syncChange` with no `home`, so the CLI
reads the real home folder; it needs no change.

For the rows, reuse the file's `setupProject`, `markDone` and `landOnMain`,
and its `PAIR` change, as "syncs an active change and reports the merge"
does. Pid 999999999 names no process on Linux, so `readWatchState` counts
that record as dead.
