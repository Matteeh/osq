## Changed

- `src/core/vcs/sync-change.ts`: `syncChange` takes an optional last `home`
  parameter and, after the change lookup and before the running-task check,
  reads `readWatchState(projectRoot, home)`. A live service record refuses with
  the service's pid; otherwise a live watcher record refuses with the watcher's
  pid. Both name the change folder and tell the human to stop the watcher or
  retry. The function's doc now carries `@scenario version-control: Watcher
  running` and `@adr 012`.
- `tests/vcs-sync-command.test.ts`: added "Watcher running", which checks every
  row of the scenario table: a live watcher, a live service beside a parent-pid
  watcher, a dead watcher, and no record. Refusal rows assert the exact message,
  an unchanged branch tip, and an empty worktree status; the dead and missing
  rows still sync.

## Deviated

- The test commits the `markDone` marker before moving the default branch. The
  scenario requires an empty worktree `status` on refusal, and an uncommitted
  `.run/done/1` would otherwise appear as an untracked path. The marker is
  committed through the file's existing `commitOnBranch` helper.

## Missing context
