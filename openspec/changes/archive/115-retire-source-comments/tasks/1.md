## Acceptance

- [ ] New `src/core/spec/source-comment-lint.ts` exports `sourceCommentFindings`, which takes the capability, the delta's repository path, and delta requirements, and returns one warning `LintFinding` per requirement other than `Code ownership` whose `raw` has a line that is a source comment, matching `^<!--\s*source:.*-->$` on its own line. A mention inside other text, such as in backticks, doesn't count. The finding's `requirement` is the requirement name, and its message is `<capability>: requirement "<name>" carries a source comment; only Code ownership keeps one`. Build it with `makeFinding`.
- [ ] `verifyDeltaTargets` in `src/core/spec/linter.ts` adds those findings for each delta's ADDED and MODIFIED requirements, next to its `scanInstructionShapedRequirements` call. Nothing else in `linter.ts` changes.

## Details

In the spec-lint-and-approve delta, read only "Source comment warning". The
rest of that delta, and the other seven, are the comment sweep and need
nothing from this task.

Build the temporary project the way `tests/instruction-delta-lint.test.ts`
does: `scaffoldProject`, `installFakeValidator`, a local `verify.cjs`, and a
`writeDelta`-style helper that can put a source comment line under the
requirement header. The MODIFIED case needs a living spec holding `Totals`
first, so write `openspec/specs/<capability>/spec.md` with that requirement.
Filter warnings by the message text; other findings for the temporary change
don't matter here.

Let `biome check --write` sort the imports.
