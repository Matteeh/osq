## Changed

- `src/core/web/web-events.ts`: `InvalidationHubOptions` gained an optional
  `recordPath`. `createInvalidationHub` watches it after the `treeWatchPaths`
  paths (deduplicated) and treats a notification on it as a global
  invalidation, explicitly as well as through the existing
  outside-every-change path. `treeWatchPaths` is untouched, and without
  `recordPath` the watched paths are exactly what they were. Tagged
  `@scenario web-inspection: Tree record change`.
- `src/core/status/dispatch-watch.ts`: `watchDispatch` resolves
  `treeRecordPath(projectRoot, config)` once, in `startWatch` after
  `options.trees` and before the first `openHub`, stores it on the watch state,
  and `openHub` passes it as `recordPath` to every hub it opens, so an osq git
  write that changes the trees fires a batch. `refreshTrees` still compares
  `treeWatchPaths` alone with `state.watchedPaths`. Tagged
  `@scenario status-inspection: Tree record watched` and
  `@scenario status-inspection: Tree record fires`.
- `src/core/foundation/config-inbox.ts`: `DEFAULT_INBOX_CONFIG.pollSeconds`
  changed from `30` to `300`. Tagged `validateInboxConfig` with the
  cli-foundation `Defaults`, `Partial block`, and `Invalid poll interval`
  scenarios.
- `README.md`: the `osq inbox --follow` paragraph now says osq's own git writes
  append to `osq-trees.jsonl` in the repository's common git directory, which
  `--follow` and the dashboard watch; the `inbox.pollSeconds` line reads `300`
  and calls it the backstop for landings made outside osq.
- `tests/config-inbox.test.ts`: only the expected default changed from `30` to
  `300` (the `DEFAULTS` object and the two assertions on the default).
- New `tests/dispatch-watch-tree-record.test.ts`: proves "Tree record watched"
  and "Tree record fires" with `scenario('status-inspection', ...)`, on a
  temporary git repository with `vcs.enabled` and `vcs.author` set. It reuses
  the fake watcher and manual `every` patterns from
  `tests/dispatch-watch.test.ts` and counts calls through the `trees` seam.
  Nothing was added to `tests/dispatch-watch.test.ts`.

## Deviated

- The living `openspec/specs/status-inspection/spec.md` has two scenarios named
  "Archived change that needs steering" (under "Change next step" and under
  "Dispatch items"), so `lookupScenario` refuses *every* lookup for that
  capability with `The status-inspection spec has two scenarios named ...`.
  The task's required `scenario('status-inspection', ...)` calls therefore
  cannot look up against the repository specs as they are. Since the living
  spec and the change's delta are both outside this task's `scope`, the test
  builds a temporary lookup root from a copy of the real living spec with that
  one duplicate scenario header renamed (later copies only), copies the real
  change delta in while it exists, and points `OSQ_CHANGE` there for the
  duration of the file. The scenario text, names, and THEN lines still come
  from the real spec and the real delta; no expected value is invented, and no
  living spec is edited. This is a lookup-root accommodation, not a change to
  what is being proven.

  scenarios through a MODIFIED/REMOVED+ADDED requirement) is needed so future
  status-inspection scenario tests need no accommodation. Left alone.
