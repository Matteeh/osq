## Changed

- New `src/core/web/web-tree-hub.ts` exporting `createTreeHub(options): Promise<InvalidationHub>`: it resolves the change trees through its `trees` seam (default `changeTrees`) and the tree record through `treeRecordPath` at startup, opens a `createInvalidationHub` over both, forwards each inner batch to its own subscribers, then re-resolves the trees. When `treeWatchPaths` differ it opens a fresh hub over the new trees and the same record path, closes the old hub, and emits one `{ ids: [] }` batch to subscribers. Resolutions run one at a time with one queued follow-up; a failed resolution keeps the current hub. An `inbox.pollSeconds` poll runs through its `every` seam (`config.inbox` or `DEFAULT_INBOX_CONFIG`); the default `every` is an `unref()`ed `setInterval`. `cancelPending` cancels the current hub's pending batch; `close` cancels the poll, closes the current hub, and drops subscribers. `TreesFn`/`EveryFn` are reused from `src/core/status/dispatch-watch.ts` with a type-only import. Both `createTreeHub` and `startWebServer` carry `@scenario web-inspection` lines for the five scenarios and `@adr 013`.
- `src/core/web/web-server.ts`: `startWebServer` now builds its hub with `createTreeHub`, passing `serve.eventDebounceMs` and its `watch`, `schedule`, `trees`, and `every` seams; the direct `changeTrees` call and `createInvalidationHub` use are gone. `WebServerOptions` gains optional `trees?: TreesFn` and `every?: EveryFn`. File is 247 lines (budget 250); `startWebServer` still spans 158 lines.
- New `tests/serve-tree-hub.test.ts` proving the five scenarios with `scenario('web-inspection', ...)`: "Tree record in the server's watch", "Tree record change", "New worktree while serving", "Poll finds a new worktree", and "Server closes the poll", driving `startWebServer` with a fake watcher, a manual `schedule` and a manual `every` seam over a temporary git repository with `vcs.enabled` for the record path, and reading SSE frames from a connected `/api/events` client. Two extra `it` tests cover the unref'd default poll and `cancelPending` cancelling the current hub's pending batch.
- `tests/serve-sse-worktrees.test.ts` passes unchanged.

## Deviated

- The acceptance line says `createTreeHub` "forwards each batch to its own subscribers, then resolves the trees again": a resolution that finds changed trees emits the `{ ids: [] }` swap batch only after the tree swap (open/close) completes, matching the spec's ordering ("open a hub ... close the old hub, and send connected clients one changed event with an empty id list"). The batch that triggered the resolution is forwarded first, before any awaiting of the tree read.
