## Changed

- New `src/core/vcs/tree-record.ts`: `treeRecordPath(projectRoot, config)` returns
  `<common git dir>/osq-trees.jsonl` when `vcs.enabled` is true and git prints the
  common directory (resolved against the root), else null, running no git when
  `vcs.enabled` is not true. Also exports `resolveTreeRecordPath(projectRoot,
  config, binary)` (the lazy path resolver the recording class uses) and
  `appendTreeRecord(recordPath, op, root)`, which writes the `{"at","op","root"}`
  line and swallows any failure. `TREE_RECORD_FILE` names the file.
- New `src/core/vcs/git-vcs-recording.ts`: `RecordingGitVcs extends GitVcs`,
  overriding `worktreeAdd`, `worktreeRemove`, `worktreePrune`, `commit`, and
  `fastForward`. Each calls `super` first and records only after it succeeds;
  `fastForward` records only on `done`. It keeps its own root, config, and binary
  copies and resolves the record path once, lazily, at its first recorded write.
  No member is added to the `Vcs` port.
- `src/core/vcs/select.ts`: returns `RecordingGitVcs` wherever it returned
  `GitVcs`, with the same root, config, and binary.
- New `tests/vcs-tree-record.test.ts`: proves every "Tree record" scenario with
  `scenario('version-control', ...)`, including each row of the "Record path"
  table, plus one plain test that `resolveTreeRecordPath` runs no git when
  `vcs.enabled` is not true. Temporary repositories are built and driven the way
  `tests/vcs-path-exists.test.ts` does, and the failing hook follows
  `tests/vcs-write.test.ts`'s "Hook rejects a commit".

## Deviated

- The two-argument `treeRecordPath` always shells out to the real `git`, so the
  "runs no git" guard is exercised through the exported `resolveTreeRecordPath`
  helper with an injected binary instead. The requirement's observable behavior
  (null and no git run) is proven for the guard.
