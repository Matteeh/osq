## Acceptance

- [ ] `InvalidationHubOptions` in `src/core/web/web-events.ts` gains an optional `recordPath: string`. When it is given, `createInvalidationHub` watches it after the paths `treeWatchPaths` returns, and a notification on it is a global invalidation, as web-inspection "Invalidation across worktrees" says. `treeWatchPaths` itself does not change. Without `recordPath`, the watched paths are exactly what they were.
- [ ] `watchDispatch` in `src/core/status/dispatch-watch.ts` resolves `treeRecordPath(projectRoot, config)` from `src/core/vcs/tree-record.ts` once, when it starts and before it opens the first hub. It then passes that path as `recordPath` to every hub `openHub` creates, as status-inspection "Dispatch watch" says. The comparison of watched paths in `refreshTrees` stays on `treeWatchPaths` alone.
- [ ] `DEFAULT_INBOX_CONFIG.pollSeconds` is 300, as cli-foundation "Inbox configuration" says. In `tests/config-inbox.test.ts`, change only the expected default from 30 to 300.
- [ ] In `README.md`'s `osq inbox --follow` section, the `inbox.pollSeconds` line reads `300` and calls it the backstop for landings made outside osq. The paragraph before it says that osq's own git writes append to `osq-trees.jsonl` in the repository's common git directory, which `--follow` and the dashboard watch.
- [ ] New `tests/dispatch-watch-tree-record.test.ts` proves "Tree record watched" and "Tree record fires" with `scenario('status-inspection', ...)` on a temporary git repository with `vcs.enabled` and `vcs.author` set. Take the fake watcher and manual `every` seams from the patterns in `tests/dispatch-watch.test.ts`, and count calls through the `trees` seam. Add nothing to `tests/dispatch-watch.test.ts`. It is in scope only because it names a modified scenario.
- [ ] Exported functions you add or change carry `@scenario` lines for the scenarios they serve.
