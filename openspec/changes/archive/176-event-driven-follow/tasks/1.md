## Acceptance

- [ ] New `src/core/vcs/tree-record.ts` exports `treeRecordPath(projectRoot, config)` as version-control "Tree record" defines it. It finds the common directory with `runGit` and `rev-parse --git-common-dir`, bounded by `timeouts.gitSeconds` (default `DEFAULT_GIT_SECONDS`), and resolves a relative answer against the root. It also exports the helpers the recording `GitVcs` uses: one that resolves the record path for a root and git binary, and one that appends the record line and swallows any error.
- [ ] New `src/core/vcs/git-vcs-recording.ts` exports a class extending `GitVcs` that overrides `worktreeAdd`, `worktreeRemove`, `worktreePrune`, `commit` and `fastForward`. Each override calls `super` first and appends the line only after it succeeds. `fastForward` appends only on `done`. The class keeps its own copies of the root, config and binary, because `GitVcs`'s are private, and resolves the record path once, lazily, at its first recorded write. It adds no member to the `Vcs` port, so `tests/vcs-write.test.ts`'s `PORT_MEMBERS` stays as it is.
- [ ] `selectVcs` in `src/core/vcs/select.ts` returns that class wherever it returned `GitVcs`, passing the same root, config and binary.
- [ ] New `tests/vcs-tree-record.test.ts` proves every scenario of "Tree record", each row of "Record path" included, with `scenario('version-control', ...)` from `@matteeh/osq/testing`. Build temporary repositories and run their git calls the way `tests/vcs-path-exists.test.ts` does. Make the failing hook the way `tests/vcs-write.test.ts`'s "Hook rejects a commit" test does.
- [ ] Exported functions you add carry `@scenario version-control: <name>` lines for the scenarios they serve and `@adr 003`.
