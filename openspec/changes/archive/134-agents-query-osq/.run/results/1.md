## Changed

- `src/core/report/query-tables.ts` (new): exports `HistoryTable`, `HISTORY_TABLES`
  (the five tables with their columns in delta order), and `buildHistoryTables`.
  It dynamically imports `node:sqlite`, opens the archive's stream index with
  `openStreamIndex` for the first change tree's archive folder, builds an
  in-memory `DatabaseSync` inside `withStreamReads` with that index, and closes
  the index in a `finally`. `changes` and `requirements` come from
  `listArchivedChanges`; task rows read each `tasks/<n>.md` title, its stream
  through `readEventStream` (`observeTaskStream` attempts, 0 with no stream),
  and the `.run/done/<n>` marker; `dead_attempts` comes from the record's dead
  attempts; `disclosures` comes from `readChangeDisclosures`, one row per
  non-null section.
- `src/core/report/archive-record-run.ts`: `readStream` now reads through
  `readEventStream`, so `readArchivedRunFields` shares the 132 read scope and
  133 index. `fs` stays for the events-directory listing; `parseEventLines` is
  no longer imported.
- `tests/query-tables.test.ts` (new): builds the tables over a temporary project
  with two archived changes and checks `HISTORY_TABLES`, each table's columns,
  and every table's rows: both changes, all four requirement kinds with a
  renamed row, task rows including one without a stream, the dead attempt, and
  all three disclosure sections.

## Deviated

- The `change` column in the four non-`changes` tables holds the change folder
  name (`010-alpha`), not `changes.id` (`010`). The delta names the column
  `change` and does not say which key it carries; the folder is unique (an id
  can be empty or, in principle, collide), is the report's own change label, and
  joins to `changes.folder`.
- `buildHistoryTables` also calls `listChanges(..., ['archived'])` alongside
  `listArchivedChanges`, only to map each record to its folder path. Records do
  not expose their folder path and `query-tables.ts` cannot change
  `archive-record.ts`, so the second listing gives `readEventStream` and
  `readChangeDisclosures` the folder they need without re-reading any record.

## Missing context

- The delta fixes the column names but not whether `change` references
  `changes.id` or `changes.folder`. I chose the folder; the test pins it.
