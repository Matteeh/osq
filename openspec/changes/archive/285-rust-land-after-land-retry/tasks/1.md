## Acceptance

- [ ] For a landed change, after the landed-change refusals, `land` runs the retry as rust-land "Land after-land retry" says and returns or fails with the lines it names. Every existing land test passes unchanged.
- [ ] The record is read only through `osq_kernel_storage::read_after_land_failure`, with the repository root and `HOME`; the land crate adds no reader of its own and no new dependency.
- [ ] A new `tests/land_after_retry.rs` proves "Retry on a landed change" and "Refused retry runs nothing". Each test's doc names `Covers: rust-land/<scenario>`, each row uses its own land repository, and each test removes its record before it ends.
- [ ] Every public item ends its doc with `Implements: rust-land/<requirement>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Port the landed branch of TypeScript's `cleanupLanded` and `retryAfterLand`.
Add a function to `land/after.rs` beside `finish` that takes the root,
the folder, the configured command and the landed line, and reuses `run`
and `failure_lines`. Call it from `run_land` where it returns
`landed_output` today. Read `HOME` inline with
`std::env::var("HOME").unwrap_or_default()`, as `record_path` does.

In the test, set up the landed state as `already_landed` in
`land_lookup.rs` does, and build the record path and the row's
`osq.toml` as `land_after.rs` does. Copy those helpers into the new file;
`land_after.rs`, `land_lookup.rs` and the support module are frozen test
files, so leave them unchanged.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source. Run the proposal's verify as the watcher does,
with `OSQ_CHANGE=openspec/changes/285-rust-land-after-land-retry`, so the
link gates see this change's new requirement.

## Scenarios

- rust-land: Retry on a landed change
- rust-land: Refused retry runs nothing
