# Task 1 — State, history, and coverage reporting

## Changed

- `src/core/report.ts`
  - `MetricsReport` now exposes `now`, `history`, and `coverage` and drops `tasks`,
    `failureBreakdown`, and `cost`. `specs`, `completionRate`, `durations`, `tokens`,
    and `fileChanges` keep their existing shapes; `completionRate` is `now.done / now.total`.
  - Current state (`now`) derives all eight counts (`total`, `done`, `verified`, `manual`,
    `dead`, `regressed`, `running`, `pending`) only from marker files via
    `deriveSpecState`, for active and archived changes alike. Verified/manual are always
    present, including zero.
  - History is parsed only from `.run/events/<n>.jsonl` task streams: attempts
    (`total`/`byTask` with every discovered task/`multipleAttempts`), `deadByReason`
    (`unknown` only for absent/empty reasons), `unexplainedReruns` (a `started` after a
    prior `started` with no intervening `dead`/`regressed`), `verifyRuns`
    (`total`/`missingExitCode`/ordered per-task codes or `null`), and `cost`
    (`total`/`perSpec`/`formattedTotal`/`provenance: "harness-reported"`/`coverage`
    `reportedAttempts` and `totalAttempts`). Cost events attach to the most recent attempt
    and count at most once per attempt; all finite values are still summed.
  - `coverage` reports `withEvents`/`withoutEvents` totals plus `byChange` with sorted
    task-number arrays; an existing empty event file counts as covered.
  - Shared `discoveredTasks` drives both views so marker and event views cannot disagree.
  - `change.jsonl` is ignored for attempts/coverage/history but still read for the
    unrelated duration/token/file-change aggregates.
  - Text renderer emits `Now:`, `History:`, and `Coverage:` sections and always renders
    `Harness-reported cost: <amount> (n of m attempts reported cost)`.
- `src/cli/report.ts` — `toStableMetrics` projects exactly the new top-level keys,
  dropping `tasks`, `failureBreakdown`, and `cost` from JSON.
- `fixture/report/`
  - New archived three-task change `010-report-history-state`: task 1 has a done marker
    and no event file; task 2 has two `started` events with no intervening `dead`/`regressed`
    (unexplained re-run) plus a `verify_ran` with exit code 0; task 3 has a `dead` event and
    a done marker so current state and history stay separate.
  - Checked-in `fixture/report/expected.json` generated from the built CLI.
- `tests/report.test.ts`, `tests/report-json.test.ts`, `tests/report-cost.test.ts`,
  `tests/report-failure-breakdown.test.ts`, `tests/report-task-states.test.ts` updated for
  the new structure and fixture totals.
- New `tests/report-now.test.ts` (marker-only current state, zero verified/manual,
  historical event does not override a done marker), `tests/report-history.test.ts`
  (attempts/multiple, unexplained re-runs, dead reasons, verify exit codes, cost attempt
  coverage, `change.jsonl` ignored, malformed lines), and `tests/report-coverage.test.ts`
  (totals, per-change task numbers, empty-file coverage).

## Deviated

- Scope listed only `tests/report*.test.ts`, but two frozen tests outside that glob assert
  the removed fields and would fail `pnpm verify`/`tsc`: `tests/done-manual.test.ts` and
  `tests/runner-already-running.test.ts`. Updated mechanically to `report.now` and
  `report.history.deadByReason`; the archived manual test now uses manual done markers
  since events no longer determine current state.
- `tests/fixtures/events/verified.jsonl` and `dead.jsonl` were regenerated
  (`UPDATE_GOLDEN=1`). `tests/golden-events.test.ts` was already failing on clean `HEAD`:
  `DEFAULT_ENV_EXAMPLE` grew by 7 lines in commit `c976800`, changing the scaffolded
  `repoLines` from 423 to 430, but the golden fixtures were not regenerated. The only diff
  is `repoLines`. The golden test file itself is unchanged.
- `tests/report-failure-breakdown.test.ts` marker-fallback tests were rewritten to assert
  the new contract (markers feed `now`; history never falls back to markers), matching the
  proposal's "without falling back to dead markers".

## Drift against features/

- The proposal references `features/metrics-and-reporting`, but the `features/` directory
  is empty in this checkout; the living contract used instead is
  `openspec/specs/metrics-and-reporting/spec.md` plus the proposal's delta.
- The old living-spec scenario "archived spec metrics from `.run/events/<n>.jsonl`" is
  superseded: archived current state now comes from markers only. This is the intended
  delta of change 034.
