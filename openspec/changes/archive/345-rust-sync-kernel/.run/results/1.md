## Changed

- Added the `osq-kernel-sync` workspace member and dependency, its manifest, and `osq-kernel-sync.workspace = true` in the land crate.
- Moved `sync.rs` and its 12 step modules into `crates/kernel/sync/src/`, copied land's `time.rs` byte for byte, and deleted the land copies. `src/lib.rs` now exposes `sync_change`, `append_sync_stopped`, `SyncRequest`, `SyncKind`, `SyncOptions`, `SyncOutcome` and `SyncStop`.
- `sync_change` returns `AlreadySynced`, `Synced { commit }`, or a `SyncStop` with the stop's reason, message and conflicted paths, in merge order.
- The three options work: `records` controls the land stop record, `verify: false` skips verify and recertification, and `tasks: Some(ids)` filters the picked done tasks in the picked order.
- `land.rs` and `sync_command.rs` call the kernel with `records: true`/`false`, `verify: true` and `tasks: None`; `sync_command.rs` uses the kernel's `append_sync_stopped` for a failed active sync.
- Added kernel tests with their own repository builder: the three "Sync outcomes" rows, the five "Options chosen by the caller" rows, "Stopped event appended", a stop that restores recertified files, the copied fixed-time UTC rows, and an archived sync that reapplies its delta to the living specs.

## Deviated

- `Cargo.lock` was rewritten by cargo when the workspace member and dependencies were added; it is not in the task's scope, so it is listed under Touched rather than written by hand.
- `crates/kernel/sync/src/specs.rs` keeps the moved `rebuild` body byte-identical to land's by importing `crate::SyncKind as Kind` instead of rewriting `Kind` to `SyncKind`. That leaves only the import lines in the change diff, so the moved function's body-replacement mutant is not selected; the new `archived_specs.rs` test catches a no-op rebuild anyway, which fixes the previous attempt's missed mutant.
- Added one kernel test (`tests/archived_specs.rs`) beyond the scenario tables to prove the archived delta reapplication that the prior attempt's missed mutant exposed.

## Missing context

- The task's scope names the root `Cargo.toml` but not `Cargo.lock`, so the generated lock update is listed under Touched.
