## Changed

- `tests/inbox.test.ts`: in "reads the inbox through a core helper without advancing the cursor", captured `before = Date.now()` and projected the inbox with `readInbox(project, { now: new Date(before), home })` before the CLI ran; ran `runBin(project, home, ['--json'])`; captured `after = Date.now()` and projected again with `now: new Date(after)`. For each running item it asserts the CLI's `pid` and `startedAt` equal the projection's exactly and that the CLI's `elapsedSeconds` lies in `[projectedBefore, projectedAfter]`. The `Math.abs(...) <= 2` window is gone. `needsYou`/`landed` deep-equality, running-list length, the cursor's absence before the CLI run, and the CLI's cursor write are retained.

## Deviated

- The `before` clock and the pre-CLI projection are taken immediately before the spawn (with the projection between them), rather than the clock being the literal last statement before `runBin`. The pre-CLI projection must read the not-yet-advanced cursor for `landed` to match the CLI's pre-advance view; because `projectRunning` is monotonic in `now`, projecting at a clock at or before the spawn keeps `elapsedSeconds >= projectedBefore` valid and strictly conservative. The post-spawn projection reads the now-advanced cursor but only its running values are used.
