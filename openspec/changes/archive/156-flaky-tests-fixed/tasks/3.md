## Details

`stop()` clears the interval and closes the watcher that exist when it runs. The first `cycleHandler()` is awaited, but after it `startWatcher` awaits `changeTrees(projectRoot, config)` and then creates both without checking `stopped`, so an abort in that window leaves a 5 ms interval running cycles until the process ends. While planning, the whole setup finished within about 3 `setImmediate` turns of the first cycle without version control, so the sweep covers the window but cannot hit it reliably. Do not spend time forcing the old code to fail.

A promise that settles when the watcher has stopped and `isRunningCycle` is false is enough. Resolve it from `stop()` when no cycle runs, or from the `finally` in `cycleHandler` once stopped. `osq watch` and the service worker (`src/cli/watch-service.ts`) pass no signal, so their behaviour must not change. The SIGINT path in `tests/watcher-loop-logging.test.ts` passes a signal and awaits the promise after the task finishes, which still works.
