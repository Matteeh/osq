## Acceptance

- [ ] `buildApprovalDigest(projectRoot, changeFolder, config)` returns the `ApprovalDigest` shape under Details. The goal is the first two sentences of `parseSpecMd(...).goal`, with whitespace collapsed. Each task entry has its number, title, and count of existing files from `resolveScope`. Each delta capability lists requirement names from `parseDelta` by kind. `humanSteps` is the `## Human steps` text, read through `extractSection`, now exported from `parser.ts`.
- [ ] Information, never flags: tasks with `tests.modify: true` carry `existingTests`, the existing resolved scope files under `tests/`.
- [ ] `shared_file`: one flag per task pair sharing any resolved scope path, including declared files that do not exist yet. It is labelled `shared files in tasks <a> and <b>`, and its excerpt names the files and says the watcher will halt for recertification when task `<b>` changes them.
- [ ] `sensitive_path`: one flag per kind present, labelled `<kind> in scope`, with an excerpt naming each path and its tasks. The kinds and patterns are under Details.
- [ ] `verify_without_test`: one flag per task or proposal verify that names neither a test file nor a runner, labelled `verify without a test in task <n>` or `in the proposal`. `removed_requirement`: one per capability, labelled `removes <n> requirements from <capability>`, with an excerpt naming them. `unknown_capability`: one per delta capability with no `<openspecRoot>/specs/<capability>/spec.md`, labelled `unknown capability <capability>`.
- [ ] `formatApprovalDigest` returns the digest text without flags, `formatApprovalFlags` returns one `Flag: <label> — <excerpt>` line per flag, and `summarizeApprovalFlags` returns `<n> flag(s): <label>, <label>`, or an empty string with no flags. Flag order is stable: by id order under Details, then by task number or name.
- [ ] New `tests/approval-digest.test.ts` builds fixture changes in a temporary project: one tripping each flag, one tripping none, and one with a `tests.modify` task. It asserts the structure, labels, env-template exclusions, runner detection, and formatted lines.

## Details

The digest is the port tasks 2 and 3 consume:

```ts
export type ApprovalFlagId =
  | 'shared_file' | 'sensitive_path' | 'verify_without_test'
  | 'removed_requirement' | 'unknown_capability';   // also the flag order
export interface ApprovalFlag { readonly id: ApprovalFlagId; readonly label: string; readonly excerpt: string }
export interface ApprovalDigestTask {
  readonly number: string; readonly title: string; readonly scopeFiles: number;
  readonly testsModify: boolean; readonly existingTests: readonly string[];
}
export interface ApprovalDigestCapability {
  readonly name: string; readonly added: readonly string[];
  readonly modified: readonly string[]; readonly removed: readonly string[];
}
export interface ApprovalDigest {
  readonly change: string;            // folder name
  readonly goal: string;
  readonly tasks: readonly ApprovalDigestTask[];
  readonly capabilities: readonly ApprovalDigestCapability[];
  readonly humanSteps: string;        // '' when absent
  readonly flags: readonly ApprovalFlag[];
}
```

Sensitive kinds, matched on project-relative resolved paths:

- `package manifest`: `package.json` at any depth, `pnpm-workspace.yaml`, `pyproject.toml`, `Cargo.toml`, `go.mod`
- `lockfile`: `pnpm-lock.yaml`, `package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock`, `bun.lock`, `bun.lockb`, `poetry.lock`, `uv.lock`, `Cargo.lock`, `go.sum`, at any depth
- `CI workflow`: `.github/workflows/**`, `.gitlab-ci.yml`
- `osq config`: `osq.config.ts`, `osq.config.js`, `osq.config.mjs`
- `OpenSpec config`: `<openspecRoot>/config.yaml`
- `managed instructions`: `AGENTS.md`, `PLANNER.md`, `CLAUDE.md`, `CLAUDE_PLAN_COMMAND_PATH`, `.opencode/agent/**`
- `env file`: `.env` or `.env.<name>` at any depth, except `.env.example`, `.env.sample`, and `.env.template`

A verify names a test file when a token contains `.test.` or `.spec.`, or a
path segment `test/`, `tests/`, or `__tests__/`. It names a runner when it
contains `--test`, `vitest`, `jest`, `mocha`, `pytest`, `go test`,
`cargo test`, or `(pnpm|npm|yarn|bun) [run ]test|verify`. These lists are
fixed in this change; making them configurable is a non-goal. Split the flag
rules into `digest-flags.ts` so each file stays under 250 lines. The linter's
private overlap helper is not reused; call `resolveScope` directly. Every
existing test is frozen.
