## Acceptance

- [ ] `approveSpec` builds the digest after lint and before planning observation, then calls the optional `review` option described under Details. On `declined` it throws an `ApprovalDeclinedError` naming the flags and writes no plan record, manifest, or `.run/approved`. `ApproveResult` gains `digest`, and without `review` behavior and writes are as today.
- [ ] `buildManifest` records `approvalFlags: { ids, mode }`, with the distinct flag ids sorted and mode `confirmed` only when `review` returned `confirmed`, else `shown`.
- [ ] `approveCommand` prints `formatApprovalDigest`, then the `formatApprovalFlags` lines, then `Approved <id> (<folder>)`, with ` with <summary>` appended when flags fired. Hash, warnings, and the planning notice follow as today.
- [ ] `approveCommand` with `confirm: true` and flags: when the injected terminal check is true, it prints each flag and asks `Approve <id> with <n> flag(s)? [y/N]` through new `src/cli/confirm.ts`, where only `y` or `yes` proceeds. When the check is false, it prints `Refusing to approve <id> without a terminal: <summary>` and exits 1 without prompting. A declined answer exits 1 and writes nothing. With no flags, `--confirm` never asks.
- [ ] `osq approve <ids...> --confirm` and `osq show <id> --json` are registered in `src/cli/index.ts`. `showCommand` appends the digest and flag lines for a change without `.run/approved`. With `json`, it prints one JSON object: the details plus `digest` (null when approved).
- [ ] New `tests/approve-confirm.test.ts` covers default approval with flags (the approval line and a manifest with mode `shown`), confirm answered `y` (mode `confirmed`), confirm answered with an empty line, confirm without a terminal (exit 1, nothing written), and confirm with no flags. New `tests/show-digest.test.ts` covers text and JSON for an unapproved and an approved change.

## Details

The review hook is the port between CLI and core:

```ts
export type ApprovalReview = 'proceed' | 'confirmed' | 'declined';
export interface ApproveOptions {
  // existing fields stay
  review?: (digest: ApprovalDigest) => Promise<ApprovalReview>;
}
```

`approveCommand` takes injectable `confirm`, `isTerminal` (default
`process.stdin.isTTY === true && process.stdout.isTTY === true`), and `ask`
(default a `node:readline/promises` question on stdin/stdout). The injected
functions let tests avoid a real terminal. Use the existing `process.exit(1)`
error path for refusals and declines, as `approveCommand` does today. Keep
`SpecDetails` and `buildSpecDetails` in `src/core/status/show.ts` unchanged,
because the web dashboard reads them; the digest is computed in
`src/cli/show.ts` only. A worktree measurement showed that extra approve and
show output and the new manifest field break no existing test. Every existing
test is frozen.
