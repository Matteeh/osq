## Changed

- `src/core/spec/approve.ts`: builds the digest after lint and before planning
  observation, then calls the optional `review` port. `declined` throws
  `ApprovalDeclinedError` naming the flags before any planning, manifest, or
  `.run/approved` write. `ApproveResult` gains `digest`; the approval passes the
  distinct flag ids and `mode` (`confirmed` only when review confirmed) into
  `buildManifest`. Without `review` the flow and writes are unchanged apart from
  the recorded flag field.
- `src/core/run/manifest.ts`: adds `ApprovalFlagsData` and an optional
  `ManifestData.approvalFlags`. `buildManifest` takes optional approval flags and
  records deduplicated sorted ids plus `mode`; a planning-only caller omits it.
- `src/cli/confirm.ts` (new): `approvalQuestion`, `refusalMessage`,
  `isAffirmative` (only `y`/`yes`), and `requestApproval`, which prints each flag
  with its excerpt and asks, returning `confirmed` or `declined`.
- `src/cli/approve.ts`: injectable `confirm`, `isTerminal` (default both TTYs)
  and `ask` (default `node:readline/promises`). The review prints the digest
  before sealing, prints the flag lines, and under `--confirm` with flags either
  refuses without a terminal (exit 1) or prompts. The approval line appends
  ` with <summary>` when flags fired; hash, warnings, and notice follow.
- `src/cli/show.ts`: appends the digest and flag lines for a change without
  `.run/approved`; `--json` prints one object of the details plus `digest` (null
  when approved). `SpecDetails`/`buildSpecDetails` are untouched.
- `src/cli/index.ts`: registers `osq approve <ids...> --confirm` and
  `osq show <id> --json`.
- `tests/approve-confirm.test.ts`, `tests/show-digest.test.ts` (new): flag
  detection, default approval summary and `shown` manifest, `y` → `confirmed`,
  empty answer decline, terminal refusal, no-flag no-prompt, command
  registration, and show text/JSON for approved and unapproved changes.

## Deviated

- The digest prints from inside the `review` callback so it appears before the
  seal is written, as the "Human approval sealing" delta requires. In the default
  path it also prints the flag lines there; in `--confirm` mode `confirm.ts`
  prints each flag once before the prompt, so flags are never duplicated.
- `buildManifest` omits `approvalFlags` when called without flags (the
  `plan-queue` planning path) so the metrics report can tell an approval apart
  from a queued plan. The approval path always supplies them, including empty
  `ids` with mode `shown` for a clean change.
