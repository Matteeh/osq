## Changed
- Ported TypeScript's recertification branch into Rust retry: `marker::recertification` now picks a task scope regression whose done marker records a non-empty `scope_hash`, and `retry::finish` branches to the new `recertify` orchestrator.
- Added `scope.rs` (`resolveScope` and `computeTaskScopeHash`), `yaml.rs` (the `yaml.stringify` writer), `excerpt.rs` (`tailVerifyOutput`), `recertify.rs`, `recertify/done.rs` and `recertify/fields.rs`.
- A recertification reads the task file through `read_task_file`, loads config, runs the task verify through `run_verify` with the absolute change folder and no diff, hashes the declared scope, rewrites the done marker on a pass, retains the regressed marker and the done marker on a requeue, appends the `recertification` event and prints the `Recertified`/`Requeued` lines.
- Reused `record::retain` and added `record::append_line` so the retry and recertification share the rename and event steps.
- Removed the old recertification refusal text, updated the `11`, `1` refusal row to the missing task-file error, and added `osq-kernel-harnesses`, `sha2` and `yaml-rust2` to the crate manifest.
- Copied the recert fixture and goldens unchanged and added `tests/retry_recert.rs` for the four new scenarios plus extra cases for the output tail, `OSQ_CHANGE`, attribution mapping keys, the YAML writer's empty/deep values and reserved strings, and outside scope roots and entries.

## Deviated
- `Cargo.lock` was rewritten by cargo for the three new crate dependencies. The task scope lists only `crates/features/retry/**`, but the dependencies cannot land without the lock update, and the workspace's lock-file rule lets `Cargo.lock` follow the covered `crates/features/retry/Cargo.toml`.
- The mutation check over every line of the retry crate's source (not only the changed lines) first reported survivors in new branches; the extra test cases above kill them. The final run of the same check reports every mutant caught, 24 unviable, none missed.

## Missing context
- The task scope omitted the root `Cargo.lock` even though the acceptance line requires the three new crate dependencies.
