## Details

Port `retrySpec`'s recertification branch, `refreshRecertifiedDoneMarker`,
`resolveScope`, `computeTaskScopeHash` and `tailVerifyOutput` from
TypeScript, and the `Recertified` and `Requeued` lines from
`src/cli/retry.ts`. The check in `marker.rs` that refuses today becomes the
test that picks a recertification; keep the order of `finish` in
`retry.rs` up to the marker read, then branch.

Build the `VerifyRequest` as the run crate's `verdict.rs` does, but with
`change` set to the change folder's absolute path, `diff` to `None` and
`timeout` to `config.timeouts.verify_timeout`. The limits are
`config.limits.marker_output_lines` and `config.limits.marker_line_chars`,
which 289 adds. Write the event with rust-core `Event::Recertification`,
`RecertificationData`, `RecertificationOutcome` and `RequeueReason`, and
reuse `time.rs` and the retain and append steps in `record.rs` rather than
copying them. Match patterns with rust-specs `scope_covers_path`; do not
depend on `osq-kernel-loop`.

Rewrite the done marker on the `yaml_rust2` mapping `parse_frontmatter`
returns. Set an existing key in place with `get_mut` or hashlink's
`replace`; `insert` moves an existing key to the back. Convert the
`attribution` list to a `serde_json::Value` for the event.

In `tests/retry_recert.rs`, copy the fixture with `support::scratch` and
`support::copy_tree`, dump with `support::dump`, and then write each line
that starts `recertified_at: ` as `recertified_at: <timestamp>`, as the
golden script does. For "Recertified scope files", write the seal with
rust-storage `change_folder_seal`, which the crate already depends on.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source or by running the built `dist` as the golden
script does. Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/297-rust-retry-scope-recert`, so the link
gates see this change's requirements.
