## Details

Port the History part of `buildMetricsReport` and `formatMetricsReport`
in `src/core/report/report.ts`, from `// 5. History and coverage` and from
the `History:` lines, for the nine `history` members only. Never read
anything under `src/` from Rust; it is in `entry` only so you can port it.
`counts.rs` already walks every counted task in order. Gather the history in
the same walk, or in a sibling walk in the same order. The cost sums depend
on that order: `102-beta`'s per-change cost is `0.7000000000000001`.

The text and the JSON grow a lot. Keep `output.rs` small by writing the
History lines and the `history` JSON in new modules. You may move
`serde_json` from `[dev-dependencies]` to `[dependencies]` with
`workspace = true` to build the JSON. Write numbers as JavaScript does,
though: serde_json writes `0.0` where JavaScript writes `0`.

The cost text follows JavaScript's `toFixed`, which rounds a tie away from
zero. Rust's `format!("{:.2}", 0.125)` gives `0.12`, so round yourself.
Treat the sign apart, as `toFixed` does: `-0.5` gives `$-0.5000`.

The old `report_summary.rs` table gains one row, and its goldens now hold the
History lines. Keep the rest of the file as it is.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source. Run the proposal's verify as the watcher does,
with `OSQ_CHANGE=openspec/changes/323-rust-report-history-counts`, so the
link gates see this change's new requirements.
