## Details

`read_retry_context` in `retry.rs` already reads a task stream loosely, line
by line with `serde_json::Value`. Read the stream the same way, then fold the
parsed objects in pure functions, one per counted block: attempts, dead
reasons, verify codes, pre-spawn, costs, retries and scope. A "number" is
a JSON number whose `as_f64()` is finite.

The four TypeScript observers in `entry` are what you port:
`observeTaskStream`, `observePreSpawnEvents`, `observeRetries` and
`observeScopeRegression`. Never read anything under `src/` from Rust; those
files are in `entry` only so you can port them. Every row of both scenario
tables was checked against those observers.

Read the brief's planner with `frontmatter_string`. It does not trim, so
trim its result yourself.

cargo-mutants runs on every line you touch, so give each branch a row that
fails when it flips. The scenario tables cover each branch; add a fast test
when a mutant survives. Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/323-rust-report-history-counts`, so the link
gates see this change's new requirements.
