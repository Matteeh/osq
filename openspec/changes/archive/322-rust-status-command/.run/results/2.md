## Changed

- Added the `status` command to `ShowFeature`, after `show` and `spec`, with the empty usage and the no-arguments usage error before any file read.
- Added `src/status.rs` and its `status/` modules: active changes with worktree, running warning, sync lines, next step and task lines; the archived count and `Not landed` block; rejected changes; and the watcher, log, after-land, validator and autopilot lines.
- Extended `facts` to remember osq worktree roots so an active change in a worktree prints its worktree, running warning and sync lines.
- Copied every file from the change's `golden/` folder into the crate's test fixtures, unchanged.
- Added `tests/status_command.rs` with the usage error and all eight golden rows, plus extra edge checks for empty waiting, a worktree with no running task, a one-commit sync and a landed archive. Updated `tests/feature.rs` for the third command.
- Verified with `cargo test -p osq-feature-show --test feature --test status_command`, `OSQ_CHANGE=openspec/changes/322-rust-status-command sh scripts/verify-rust.sh`, and a manual cargo-mutants run over every touched source file with zero misses.

## Deviated

- The archived `show-project` fixture contains an old task event that the strict storage snapshot reader refuses (`done` with no `data`), while TypeScript's validator reader only reads `change.jsonl`. When `read_change` fails, the status reader now passes `validator_failing` a minimal snapshot built from the readable `validator_ran` events of `change.jsonl`, so the pending golden still gets its validator line. A full snapshot is used whenever the storage reader succeeds.
- The extra edge checks live inside the eight-row golden test so they still run in its isolated-home child, instead of adding more HOME-setting child processes.
