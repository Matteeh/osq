## Details

Build each active change's lines from what `show` already reads: the
change list from `facts::read`'s entries, which cover every git tree; the
status, next step and task lines from `model::read`; and the sync lines and
the land state from the code `show` uses for an archived change's land
lines. A change is not landed when `model::read` gives it the next step
`archived (not landed)`. The rejected reason and timestamp come from
`.run/rejected.md`'s frontmatter, read with rust-specs `parse_frontmatter`.

The test sets `HOME` for one row by running its own test binary again as a
child process with `HOME` set and one test selected, as `show_land.rs` does
with `OSQ_SHOW_LAND_HOME`; never set `HOME` in the test process itself,
since tests run in parallel. Live watch records name the test's own pid,
`std::process::id()`. Build each row's files exactly as the golden script's
case does, writing `osq.toml` with `[vcs]` `enabled = true` and
`author = "osq <osq@example.com>"` where the script writes `osq.config.ts`,
and make git commits with author and committer `osq <osq@example.com>`.

`statusCommand` in `src/cli/status.ts`, `formatStatusOverview` in
`src/core/status/status.ts` and `formatWatcherLine` in
`src/core/status/watcher-line.ts` are the TypeScript to port. Never read
anything under `src/` from Rust; they are in `entry` only so you can port
them. Task 1 added `read_watch_state` and `validator_failing` to the
storage kernel.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/322-rust-status-command`, so the link gates see
this change's new requirements.
