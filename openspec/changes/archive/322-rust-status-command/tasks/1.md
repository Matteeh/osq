## Details

`read_after_land_failure` in `src/read/pending.rs` already reads a JSON
record from `watch_state_dir` with `serde_json`; read `service.json` and
`watcher.json` the same way. Decide liveness as `pid_alive` in the inbox's
`src/groups/running.rs` does: a pid above 0 whose `/proc/<pid>` exists.
The test's live pid is `std::process::id()`.

Move the run rule from the inbox's `item` into `validator_failing`: the
`Run` struct, the stable sort by `timestamp_ms`, the count from the end, the
`failing` outcomes and the first non-blank output line. `item` then only
turns the record into its line, taking the id and title from the snapshot
whose folder the record names. `crates/features/inbox/tests/validator.rs`
shows how to write `validator_ran` events into an archived change's stream
and read the snapshots.

`readWatchState` in `src/core/run/watch-state.ts` and `readValidatorFailing`
in `src/core/status/validator-failing.ts` are the TypeScript to port. Never
read anything under `src/` from Rust; they are in `entry` only so you can
port them.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/322-rust-status-command`, so the link gates see
this change's new requirements.
