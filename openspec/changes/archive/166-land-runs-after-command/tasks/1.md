## Acceptance

- [ ] `VcsConfig` gains optional `afterLand`, validated and trimmed by `validateVcsConfig` through `trimmedField` exactly as `prepare` is, so cli-foundation "After-land command configuration" scenarios "Command kept trimmed" and "Blank command" hold.
- [ ] New `src/core/vcs/land-after.ts` runs the command the way `runPrepare` in `approve-worktree.ts` runs `vcs.prepare`: `runVerificationCommand` in the checkout with no change folder, `{ role: 'prepare', config }`, bounded by `config.timeouts.verifyTimeoutSeconds`. It writes `after-land.json` (`{ change, command, exitCode, failedAt }`) in `watchStateDir(projectRoot, home)` on a failure and removes it on a pass, and exports a reader that returns the record or null, for task 2's status and inbox.
- [ ] `landChange` calls it after the worktree cleanup of a land that moved the default branch, reports `Running after-land command: <command>` through its progress callback, and appends the pass or fail lines version-control "Land runs the after-land command" names; a failure returns code 1. `LandResult` gains a field saying whether the command ran and passed. In the already-landed path it runs the command only when the record names that change. `LandOptions` gains an injectable `home`. Refusals and stops run nothing, and without `vcs.afterLand` every line and code stays as it is.
- [ ] `src/core/vcs/land.ts` stays at or under 250 lines and `landChange` within the function budget; the work lives in `land-after.ts`.
- [ ] `landCommand` takes an injectable `home`, passes it on, and leaves out `REBUILD_MESSAGE` when the command ran and passed, so cli-foundation "Land checks the osq build" holds, its new scenario included, and `tests/vcs-land-stale.test.ts` passes unchanged.
- [ ] New `tests/vcs-land-after.test.ts` builds temporary repositories and archives changes the way `tests/vcs-land.test.ts` does, with a temporary `home` and a local `build.cjs` that writes `built.txt` or prints `boom` and exits 1 as each case needs. Through `landCommand` it checks every scenario of version-control "Land runs the after-land command", "Land into osq itself with a passing after-land command" with a `packageRoot` equal to the repository root, and the two config scenarios through `loadConfig` from a written `osq.config.ts`, with expected values from the scenarios' THEN lines.
- [ ] Exported functions you add or change carry `@scenario <capability>: <scenario name>` lines for the scenarios they serve and `@adr 003` where they run after a land.
