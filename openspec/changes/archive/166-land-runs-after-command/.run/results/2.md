## Changed

- `src/core/status/inbox.ts`: `NeedsYouKind` gains `after-land-failed`. To stay inside the 250-line source budget the builder's line-budget test enforces, the union is written as one declaration line under a `biome-ignore format` comment, like `src/core/status/state.ts` does.
- `src/core/status/inbox-projection.ts`: `readInbox` reads the failure record through task 1's `readAfterLandFailure(projectRoot, options.home)` and, when one exists, adds one needs-you item `{ kind: 'after-land-failed', change: { id, title }, task: null, command: 'osq land <id>' }` with no other key; the title comes from `parseSpecMdFromFolder` on the folder the record names under the checkout's archive directory, else the folder name, and the item is sorted with the other needs-you items by numeric id as today.
- `src/core/status/inbox-text.ts`: `formatInboxText` renders the kind as `  <id>: <title> — after-land command failed — osq land <id>`; every other row is unchanged.
- `src/cli/status.ts`: `statusCommand` reads the record with its `home` option and prints `After-land command failed for <id>: <command> — osq land <id>` after the watcher line and the optional log line, and prints exactly what it printed before when there is no record.
- `packages/ui/src/home/labels.ts`: `NEEDS_YOU_LABELS` gains `'after-land-failed': 'after-land failed'` and `needsYouKindLabel` serves the scenario.
- `tests/inbox-after-land.test.ts` (new): writes `after-land.json` into a temporary home's watch state directory and checks both "Failed after-land command in status and inbox" scenarios through `readInbox`, `formatInboxText` and `statusCommand`, and "After-land failed label" through `needsYouKindLabel`, with the expected values from the scenarios' THEN lines. It also asserts the record round-trips through task 1's `readAfterLandFailure`.

## Deviated

- The task says the test writes `after-land.json` "through task 1's module", but `src/core/vcs/land-after.ts` exports no writer and is outside this task's scope, so the test writes the record's bytes directly through the same `watchStateDir` helper task 1 uses, then verifies `readAfterLandFailure` reads them back.
- Adding the union member naively pushed `inbox.ts` to 251 lines by the line-budget test's counting (it counts the trailing newline). The task forbids any other change in the file, so the union declaration itself is written on one line with a `biome-ignore format` comment, the same pattern `src/core/status/state.ts` uses; the type is identical.
- `statusCommand` places the new line after the `Log:` line when a watch log exists (the acceptance's "after the watcher line and the log line"); the delta spec's "after its watcher line" is ambiguous when both exist.

## Outside scope

- A change whose record names it but whose archive folder lives in an osq worktree (not the checkout) falls back to the folder name as its title, because the record reader and `readInbox` only look at the checkout's archive directory. Title resolution through other trees would need a change beyond this task's scope.
