## Changed

- New `src/docs/markdown.ts`: pure renderers from a `DocsSite` to the file map
  docs "Docs command" defines. `renderIndex` (`# Capabilities`, a
  `## <group>` per group with one `- [<name>](capabilities/<name>.md): <purpose>`
  line per capability, then `# Decisions` with one
  `- [ADR <n>: <title>](adrs/<n>.md) (<status>)` line per ADR);
  `renderCapabilityPage` (`# <name>`, `Group: <group or ungrouped>`, purpose,
  then `## Requirements`, `## Decisions`, `## Code ownership`, `## Code map`
  only when `codeMap` is not null, and `## Recent changes`, writing `None`
  where a section is empty); `renderAdrPage` (`# ADR <n>: <title>`,
  `Status: <status>` with `, superseded by [ADR <n>](<n>.md)`, `Applies to:`
  with `all`, the capability links, or `none`, `Rule: <rule>` when present,
  then the body); and `renderDocsSite`, which maps them to `index.md`,
  `capabilities/<name>.md`, `adrs/<number>.md`. Every file ends in exactly one
  newline and carries no timestamp.
- New `src/docs/docs-command.ts`: `docsCommand(options)` takes `CommandInputs`
  plus `out` (default `docs/osq`), builds the site with `buildDocsSite`,
  resolves `out` against `cwd`, removes the other `.md` files directly in
  `capabilities/` and `adrs/` under `out`, writes the file map (creating
  folders), prints `wrote <n> pages to <out>` through the inputs' `stdout`,
  and returns the written absolute paths. It follows `digestCommand`'s shape:
  `resolveInputs` first, no path outside `out` touched.
- New `src/docs/slice.ts`: `slice` named `docs`, the config block `docs`
  (`DOCS_DEFAULTS` and `resolveDocsConfig`), and the `docs` command in group
  `Inspection`, `--out <dir>` defaulting to `docs/osq`, whose action loads
  `docs-command.js` through `import()`. It imports `docs-config.js` at runtime
  and everything else with `import type`, so it never reaches `config.ts` or
  `slices.ts`.
- `src/cli/slices.ts`: `SLICES` now holds the `docs` slice behind the import
  alias `docs`.
- `README.md`: added `osq docs [--out <dir>]` to the Inspection block, directly
  after `osq spec`.
- New `tests/docs-command.test.ts`: proves "Docs written from the fixture"
  (prints `wrote 7 pages to site`, writes the seven pages, removes
  `site/capabilities/old.md`, keeps `site/notes.txt`, a second run is
  byte-identical, every `.md` ends in one newline) and every row of "Page lines
  from the fixture"; plus that `createProgram()` registers `docs` with `--out`
  defaulting to `docs/osq`, that `commandGroups(SLICES)` places it in
  `Inspection`, and that `loadConfig` on the fixture with
  `docs: { recentChanges: 2 }` carries that block.

## Deviated

- The acceptance asks exported functions to carry `@scenario` and `@adr 016`
  tags. I tagged the Markdown renderers and `docsCommand` (all `export
  function` / `export async function`). I deliberately left the `slice` object's
  doc comment untagged: `export const slice: Slice = { ... }` is not a
  declaration bound to a function, so the traceability scanner cannot attach a
  tag to it and would record each tag line as an *unreadable* form in a scoped
  file (a lint finding if change 175 is linted). `slice` is not a function, so
  the acceptance does not require its tags and the tagged functions already
  carry them.
- I did not add a `declare module '../core/foundation/config.js' { interface
  OsqConfig { docs?: DocsConfig } }` augmentation for the new key. That is the
  slice-config pattern, but a module-augmentation specifier is a quoted
  specifier that is not an import, so it breaks
  `tests/import-graph-build.test.ts`'s "equals a search for whole quoted import
  specifiers" invariant for `src/core/foundation/config.ts` (the naive text
  search counts it, the import graph does not). `DocsConfig` stays typed where
  it is exchanged; `docsConfig()` keeps its existing cast. Adding the
  augmentation needs a test change outside this task's scope.
- `docsCommand` returns absolute written paths. The task only says "returns the
  written paths"; no test fixes the shape, so absolute paths are the useful
  choice.

## Missing context

- The task did not say whether `docsCommand` returns absolute or relative
  paths, nor whether the printed directory is the raw `--out` value or its
  resolved path. The scenario (`wrote 7 pages to site`) fixes the raw value; I
  chose absolute returns.
