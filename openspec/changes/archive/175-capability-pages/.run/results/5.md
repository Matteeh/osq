## Changed

- New `packages/ui/src/docs/` holds the web-inspection "Docs view" views:
  - `DocsView.tsx` routes `#/docs` to the index, `#/docs/capabilities/<name>`
    to the capability page and `#/docs/adrs/<number>` to the ADR page, and
    renders `No such page.` for a name or number the site lacks.
  - `DocsIndex.tsx` lists each group in order (one heading, one link per
    capability with its purpose) then each ADR as a link with its number,
    title and status.
  - `DocsCapability.tsx` shows the group, purpose, requirements with their
    `shall` sentences and scenario names, decisions with rules and ADR links,
    Code ownership globs, the code map when it is not null, and recent changes
    with date and goal, each linking to its change route by folder.
  - `DocsAdr.tsx` shows the status, a link to the successor when superseded,
    links to the applied capabilities, the rule, and the body as a `<pre>`.
  - `DocsLink.tsx` is the one internal link: a real anchor whose href comes
    from `routeToHash` and which routes through `onNavigate`. `index.ts` is
    the barrel.
- New `packages/ui/src/docs/docs.css`: `white-space: pre-wrap` and
  `overflow-wrap: anywhere` on `.docs-body` (the ADR body and the spec text),
  `overflow-wrap: anywhere` on `.docs-path` and `.docs-glob`, imported in
  `packages/ui/src/main.tsx`.
- `packages/ui/src/app.tsx`: `DocsView` import, a `navActive` helper so the
  `Docs` link is active on `docs`, `docs-capability` and `docs-adr`, the
  `Docs` nav link directly after `Graph`, a `DocsRoute` that renders the views
  from `documents.docs` with an empty state while it is null, and the docs
  route rendering.
- New `tests/ui-docs.test.tsx`: builds the site with `buildDocsSite` for
  `docsProject()` and renders `App` with `renderToStaticMarkup`, proving "Docs
  index view" (billing before ungrouped, the pricing link, ADR 003 marked
  superseded), the nav link placement and activity, the null-docs empty state,
  and "Capability and ADR views" (the pricing SHALL sentence,
  `src/pricing/quote.ts:33`, the change 007 link, the ADR 003 successor link,
  `No such page.`), plus the `docs.css` wrap rules.

## Deviated

- `DocsCapability` and `DocsAdr` type their props as
  `DocsSite['capabilities'][number]` and `DocsSite['adrs'][number]` rather
  than importing `CapabilityPage`/`AdrPage`. `packages/ui/src/contracts.ts`,
  which re-exports `DocsSite`, is outside this task's scope, so I did not add
  the two extra type exports there.
- The ADR page renders `Applies to:` as links to `page.capabilities` for every
  ADR, `all` included, because web-inspection "Docs view" says "links to the
  capabilities it applies to" and the page model already expands `all` to
  every living capability.

## Missing context

- The task did not say what the null-`documents.docs` empty state should read.
  I used `No docs are available yet.`, matching the other routes' `No … are
  available yet.` wording.
