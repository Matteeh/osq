## Changed

- New `src/docs/docs-config.ts`: `DOCS_DEFAULTS` (`{ recentChanges: 5 }`),
  `resolveDocsConfig(raw)` (undefined/null -> defaults, otherwise a positive
  integer `recentChanges` or `docs.recentChanges must be a positive integer`),
  and `docsConfig(config)` (the config's `docs` block or the defaults). It
  imports `config.ts` with `import type` only, so task 3's `slice.ts` cannot
  reach `config.ts` at runtime through it.
- New `src/docs/docs-types.ts`: `DocsConfig`, `CapabilityPage` with its
  requirement, decision, code-map and recent-change entries, `AdrPage`,
  `DocsGroup`, and `DocsSite`.
- New `src/docs/code-map.ts`: `buildCodeMaps(projectRoot, config, sources)`
  loads `getSystemGraph` once and `codeMapFromGraph(graph, capability,
  requirements)` builds one entry per scenario in spec order, reading the
  `serves` edges for functions and the `proves` edges for test files.
- New `src/docs/recent-changes.ts`: `loadArchivedRecords` wraps
  `listArchivedChanges`; `recentChangesFor(records, capability, limit)` keeps
  the archived changes whose delta writes the capability, by change number
  newest first, at most `limit`, each with `id`, `folder`, `archivedOn` and the
  first sentence of the Goal.
- New `src/docs/capability-page.ts`: `buildCapabilityPages(projectRoot, config)`
  builds one page per living capability in name order, reusing
  `listCapabilityFolders`, `readCapabilitySpec`, `parseCapabilitySpec`,
  `readLivingSidecar`, `readDecisions`/`governingAdrs`,
  `readCapabilityOwnership` and `collapseWhitespace`, with the code map null
  unless the capability is opted in to traceability.
- New `tests/docs-support.ts`: `docsProject()` copies `fixture/trace/pricing`
  to a temp root and adds the `osq.config.ts` (`harness: 'mock'`, traceability
  on for `pricing`), `pricing`'s `billing` sidecar and Code ownership
  requirement (`src/pricing/**`, `tests/pricing-*.test.ts`), the `invoices`
  spec, ADRs 002 to 004, and archived changes `001-change-1` to `008-change-8`
  with `archived` events at `2026-10-0<n>T09:00:00.000Z`. It also exports
  `cleanupDocsProject(root)` and `cleanupDocsProjects()`.
- New `tests/docs-capability-page.test.ts`: proves every row of "Pages of the
  docs fixture", "Recent change limit" and "Docs config values".

## Deviated

- The task named no functions for the code map or the recent changes, only that
  they come from `getSystemGraph` / `listArchivedChanges`. I split each into a
  pure selector plus a loader so the expensive readers run once per build
  (`buildCodeMaps` loads the graph once for every opted-in capability;
  `loadArchivedRecords` reads the archive once). `capability-page.ts` decides
  opt-in with `isCapabilityOptedIn` and only loads the graph when at least one
  capability is opted in.
- `firstSentence` in `recent-changes.ts` is module-private, so no exported
  helper lacks a `@scenario` line.
- The `resolveDocsConfig` for a non-object block throws the same
  `docs.recentChanges must be a positive integer` message, since the spec
  defines no other one.

## Missing context

- The task did not name the cleanup helper or say what `docsProject()` returns.
  It returns the temp project root path (`Promise<string>`); cleanup is
  `cleanupDocsProject(root)` for one and `cleanupDocsProjects()` for a suite's
  `afterEach`. Tasks 2 to 5 should import these rather than edit the file.
- The docs fixture's ADR 001 is the existing
  `fixture/trace/pricing/decisions/001-money-in-integer-cents.md`; `docsProject`
  only adds ADRs 002 to 004.
