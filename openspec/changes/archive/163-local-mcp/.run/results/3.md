## Changed

- Added `src/cli/mcp-tools.ts` (250 lines when counted as `split('\n').length`)
  exporting `McpTarget` and `createMcpTools(target)`, implementing
  cli-foundation "MCP planning tools".
  - The nine tools are returned in the spec's order: `plan`, `list_files`,
    `read_file`, `write_file`, `edit_file`, `delete_file`, `spec`, `query`,
    `lint`; each has a one-line description and an `inputSchema` whose
    properties are string-typed, whose `required` lists the arguments without
    `?`, and whose `additionalProperties` is `false`.
  - The five file tools call `mcp-files.ts` with a source that is
    `{ kind: 'local', cwd }` or `{ kind: 'remote', workRoot:
    remoteWorkRoot(server, home) }`.
  - Local command tools run through `createForwardedRunner(cwd)`, so they call
    the same command functions as the CLI and keep `plan`'s refusal of a
    change with no brief. Against a server `plan` runs through `planOnServer`,
    `lint` through `lintOnServer`, and `spec`/`query` through `runOnServer`.
  - A forwarded request is `{ command, args, options: {} }`; a missing
    argument becomes `null`.
  - `runForwarded` collects every stdout/stderr chunk in arrival order, then
    on failure appends the error line (when present) and `Next: <next>` (when
    present), exactly as `runCli` prints them. A thrown `CommandError` from
    `planOnServer`/`lintOnServer`/`runOnServer` is read as its exit code,
    message and next; `isError` is true exactly when the exit code is not 0.
  - `createMcpTools` carries the four `@scenario cli-foundation:` lines for
    "MCP planning tools" and `@adr 014`.
- Added `tests/mcp-tools.test.ts`:
  - "lists exactly the nine planning tools in order" (No tap tools) and checks
    each description is one line and each schema is an object with
    `additionalProperties: false`.
  - "gives the CLI text for spec, query and lint": each tool's result is
    compared with the same command function run through shared string writers,
    including the `runCli` failure rendering.
  - "prepares the prompt for a change that has a brief": compares the `plan`
    text with `formatNextStep(await readNextStep(...))` and checks
    `plan-prompt.md` exists.
  - "keeps the runner refusal for a change with no brief".
  - "plans, writes and lints through the working copy": starts a real
    `startWebServer` with a site and `createForwardedRunner` over a fixture
    project, uses a temporary home, and asserts `plan` fills the working copy,
    `write_file` writes under it, and `lint` uploads it and returns the same
    text as the server's `lintCommand`. The server is closed in an `after`
    hook.

## Deviated

- The task and traceability guidance suggest proving scenarios with the
  `scenario` helper. The living `openspec/specs/cli-foundation/spec.md` holds
  two scenarios named "Explicit settings win", and `lookupScenario` rejects a
  capability whose spec repeats a scenario name, so any `scenario(...)` test
  for cli-foundation throws. As in tasks 1 and 2, `tests/mcp-tools.test.ts`
  uses plain `describe`/`it`; the scenarios are tagged on `createMcpTools`
  with `@scenario` instead.
- The local plan refusal text says "on a server" even when run locally,
  because it comes from `createForwardedRunner`'s `planCall`. The test asserts
  that text unchanged.
- `createMcpTools` builds a fresh local runner per command tool via
  `runnerFor`. MCP `tools/call` is already serialized by the task-4 stdio
  loop, so the per-tool serialization queue is not relied on here.
