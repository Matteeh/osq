## Changed

- Added `src/cli/mcp.ts` (126 lines), exporting `registerMcpCommand(program)`
  and implementing cli-foundation "MCP command".
  - Registers `osq mcp` with `--cwd <dir>`, resolves the folder to an absolute
    path (defaulting to the process folder), and targets the server from
    `readServerSetting(process.env)` when set, otherwise the project.
  - Builds the handler once per session with server `name: 'osq'`, the
    program's `version`, and instructions that tell the client to run `plan`,
    read `plan-prompt.md` and follow it, write only inside the change folder,
    run `lint` until it passes, and leave approval to a human.
  - Serves one JSON-RPC message per stdin line; writes each answer as one JSON
    line through `processStdout` and nothing else on stdout. A line that is not
    JSON gets the `-32700` parse error. `tools/call` requests chain onto the one
    before them (the chain assignment is a statement, not an expression);
    every other parsed request is answered at once. On stdin end the loop
    awaits every queued answer and the command exits 0.
- `src/cli/index.ts`: `createProgram` now calls `registerMcpCommand(program)`;
  `parseRejectReason` moved to `reject.ts` (imported from there). 238 lines.
- `src/cli/reject.ts`: exports `parseRejectReason` unchanged, moved there so
  `index.ts` stays under the 250-line budget.
- `src/cli/help-groups.ts` and `tests/help-groups.test.ts`: "Setup and running"
  is now `['init', 'setup', 'watch', 'server', 'mcp']`; the other test cases are
  untouched.
- `README.md`: added the `osq mcp --cwd <dir>` line to the Setup and running
  command block and a new "Planning through MCP" section before "Running osq on
  a server", with the Claude Desktop `mcpServers` entry (`"command": "osq"`,
  `"args": ["mcp", "--cwd", "<project>"]`), the `claude mcp add osq -- osq mcp
  --cwd <project>` line, the `OSQ_SERVER` note, the tool list, and the statement
  that approve, land, reject and retry are not tools.
- Added `tests/mcp-cli.test.ts` (243 lines): spawns `src/cli/bin.ts` through
  tsx like `tests/remote-cli.test.ts`, with `OSQ_SERVER` empty and a temporary
  `HOME`; covers "A planning session over stdio" (pipelined initialize,
  initialized, tools/list and the tool calls, including `read_file` echoing the
  write, `../x.md` refused and `plan-prompt.md` created, exit 0) and "Not JSON".
  Every spawned child is tracked and killed in the `after` hook, and temp dirs
  are removed.

## Deviated

- As in tasks 1 through 3, `tests/mcp-cli.test.ts` uses plain `describe`/`it`
  rather than the `scenario` helper: `cli-foundation` repeats scenario names
  ("Explicit settings win" and others), which makes `lookupScenario` throw. The
  two scenarios are tagged on `registerMcpCommand` with `@scenario` instead.
- The acceptance line "no exported name in `src/cli/` ends in `Command`" is
  read the way `tests/cli-no-direct-output.test.ts` enforces it: exported
  `*Command` functions other than `register...Command` must accept
  `CommandInputs` and appear in its table. `registerMcpCommand` is a register
  function and is exempt, like the other register commands.
