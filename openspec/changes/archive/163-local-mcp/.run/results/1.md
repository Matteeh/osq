## Changed

- Added `src/cli/mcp-protocol.ts` with `createMcpHandler(tools, info)` and the
  `McpTool`, `McpToolResult`, `McpServerInfo` (plus `McpAnswer`) types. It
  imports nothing, owns no I/O, and implements cli-foundation "MCP protocol":
  legacy `initialize` (echoes a supported version, falls back to `2025-11-25`),
  `ping`, `tools/list`, `tools/call`, and modern `server/discover`. A request
  whose `params._meta` holds the version key is validated before dispatch:
  `-32022` for a version other than `2026-07-28`, `-32602` when
  `clientCapabilities` is absent. Modern results gain `resultType: 'complete'`
  and `_meta['io.modelcontextprotocol/serverInfo']`; legacy results do not. A
  throwing tool yields `Error: <message>\n` with `isError: true`; the handler
  never rejects. The file is 223 lines.
- Added `tests/mcp-protocol.test.ts`. It builds the handler from nine stub
  tools named as in "MCP planning tools" and asserts the whole answer with
  `assert.deepEqual` for every row of "Requests and answers", including the
  unknown-tool, unknown-method, unsupported-version and missing-capabilities
  errors, and the no-`id` notification. It also covers "A throwing tool", a
  successful `tools/call`, and a message with `result` and no `method` (null).

## Deviated

- The spec fixes only the code (`-32602`) for a modern request without
  `clientCapabilities`; it names no message. The handler uses `Invalid params`,
  and the test asserts that full answer. No other value was specified.
- The acceptance describes plain `node:test` cases, so the file uses
  `describe`/`it` rather than the `scenario` helper. The two scenarios are still
  tagged on `createMcpHandler` with `@scenario`.

## Outside scope

- `openspec/specs/cli-foundation/spec.md` holds two scenarios named "Explicit
  settings win" (the Pi and Claude configuration requirements). Because
  `lookupScenario` rejects a duplicate scenario name, a `scenario(...)` test for
  any cli-foundation scenario throws. Left alone; it does not affect this task,
  which uses plain tests.
