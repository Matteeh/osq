## Changed

- Added `src/cli/mcp-files.ts` (243 lines): the `McpFolderSource` type and
  `listFiles`, `readFile`, `writeFile`, `editFile`, `deleteFile`, each
  `(source, args) => Promise<McpToolResult>`, implementing cli-foundation
  "MCP file tools".
  - Local sources load the config with `loadConfig(cwd)` and resolve the
    change through `readChangeFiles(cwd, config, change)`, so an approved or
    foreign change fails with that function's exact error. The folder path
    then comes from `findChange`.
  - Remote sources resolve the working copy under `workRoot` whose name
    `matchesFolder` matches, else fail with `no working copy of change
    <change>; run the plan tool first`.
  - A path must pass the lexical guard (`isSafePath`) and its deepest
    existing part must resolve, through symlinks, inside the folder;
    otherwise `path outside the change folder: <path>` and no write.
  - Argument, gate and missing-file failures return `isError: true` with the
    exact text plus newline and never throw; every other error propagates so
    the protocol handler turns it into `Error: <message>`.
  - `listFiles` walks the folder (`listPaths`), skipping `.run/`, and joins
    the sorted `/`-separated paths with newlines. `writeFile` reports
    `wrote <path> (<bytes> bytes)`, `editFile` `edited <path>` /
    `old_text not found in <path>` / `old_text occurs <n> times in <path>`,
    `deleteFile` `deleted <path>`.
  - Each exported function carries its `@scenario cli-foundation:` lines and
    `@adr 014`. The file is 244 code points after Biome formatting
    (`split('\n').length`), within the 250-line budget.
- Added `tests/mcp-files.test.ts`: a temporary project with change `001-demo`
  holding `proposal.md` (`a b b`), `brief.md` and `.run/manifest.json`, plus
  an `escape` symlink out of the folder. It covers every row of "Paths
  outside the change folder refused" (exact error, unchanged snapshot, empty
  outside folder), "Approved change refused", all three "Edits" rows, the
  "Files round trip" with a 1,000,000-character file, argument failures, and
  a remote `workRoot` holding `001-demo/` that refuses change `002` with
  `no working copy of change 002; run the plan tool first`.

## Deviated

- The task and its delta spec say to reuse `resolveRemoteChange` and
  `isSafeUploadPath` from `src/core/web/web-remote-files.ts`. That file on
  the landed base exports neither: it exports only `readChangeFiles` and
  `replaceChangeFiles`, with the resolution and path guard as private
  helpers (`resolveChange`, `isInsideFolder`). Since the scope allows only
  `src/cli/mcp-files.ts`, the file reuses `readChangeFiles` for the local
  gate and defines private equivalents (`isSafePath`, `staysInside`) with
  identical behaviour rather than importing names that do not exist.
- `listFiles` walks the folder itself (`listPaths`) instead of using
  `readChangeFiles`'s return value, because the landed `readChangeFiles`
  only handles the local project and a remote `workRoot` needs the same
  walk. The set of paths is identical to what `readChangeFiles` collects
  (all files except `.run/`).
- The acceptance describes plain `node:test` cases, so the test uses
  `describe`/`it` rather than the `scenario` helper. The living
  cli-foundation spec has duplicate scenario names, so `lookupScenario`
  would reject a `scenario(...)` test (same reason as task 1). The scenarios
  are still tagged on the exported functions with `@scenario`.
