## Changed

- Added `frontmatterYamlError` to `src/core/spec/parser.ts`. It uses the same frontmatter match as `parseFrontmatter`, parses with `YAML.parseDocument`, a `LineCounter`, and `prettyErrors: false`, returns the first error's message plus its file line, and returns `null` for absent or valid frontmatter. `parseFrontmatter` is unchanged.
- Updated `lintChangeFolder` in `src/core/spec/linter.ts` to report change-document YAML errors and skip the checks that read that frontmatter: verify, `features.writes`, capability relations, generated moves, sidecars, `depends_on`, `fixes`, and impact/undeclared reads. Body and task checks still run.
- Updated `lintChangeFolder` to report task YAML errors, keep running control-character and fused-acceptance checks, skip every other check for that task, and leave it out of cross-task checks.
- Added `tests/lint-frontmatter-yaml.test.ts` with one `it` per new scenario, covering broken proposal frontmatter, broken task frontmatter, and `parseFrontmatter` still reading broken frontmatter as empty data with the whole file as body.

The task verify and `pnpm verify` both pass.

Touched: src/core/spec/parser.ts, src/core/spec/linter.ts, tests/lint-frontmatter-yaml.test.ts
