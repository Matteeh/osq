## Acceptance

- [ ] The glob matcher in `crates/kernel/specs/src/owners/glob.rs` moves to new `crates/core/src/scope/glob.rs` as `scope_covers_path`, exported from `osq-core`'s root, with a private JavaScript trim beside it as `js_trim` in `markdown/text.rs` trims. The specs kernel's `scope_covers_path` stays in `owners/glob.rs` as a one-line call to the core function, with its doc and `Implements: rust-specs/scope-globs`, so its callers and tests do not change.
- [ ] New `crates/core/src/scope/audit.rs` holds `ScopeAudit`, `ChangedPath`, `PathChange`, `LockRule`, `Disallowed`, `DisallowReason` and `audit_scope`, exported from `osq-core`'s root, as rust-core "Scope audit" and "Scope audit rules" say. They mirror `scopeViolations` in `src/watcher/git-guard.ts`, `scopeCoversChangedPath` and `lockfileFollowsManifest`, and the authorized check of `findUndeclaredTestChanges` in `src/core/run/test-snapshot.ts`.
- [ ] Core still does no IO: nothing new touches `std::fs`, `std::process` or `std::env`.
- [ ] New `crates/core/tests/scope_audit.rs` proves "Scope coverage cases", "Scope audit cases" and "Lock file at the root follows any covered manifest", one assertion per row, each test doc naming `Covers: rust-core/<scenario>`.

## Details

cargo-mutants checks the moved matcher against `osq-core`'s own tests, so
the "Scope coverage cases" test also runs every row of rust-specs "Scope glob
cases" against `osq_core::scope_covers_path`.

Never read anything under `src/` from Rust; the TypeScript files are in
`entry` only so you can port them. Test modules inside source files, which
TypeScript also freezes, are not part of this audit. Run the proposal's verify
as the watcher does, with `OSQ_CHANGE=openspec/changes/269-rust-scope-audit`,
so the link gates see this change's new requirements.
