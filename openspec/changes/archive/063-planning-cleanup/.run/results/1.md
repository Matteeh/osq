## Changed

- `ObservedPlanningSession` now requires `turns` and no longer declares `usage`,
  `edits`, `startedAt`, or `endedAt`; `harnessVersion` and `sessionCost` stay.
  `PlanningSessionEdit` remains for internal matching.
- `findPlanningSessions` passes `candidate.turns` and
  `candidate.sessionCost ?? null`; the `usage`/`sessionUsage` fallbacks are gone.
- `sliceChangeOwnership` no longer accepts `sessionUsage` and derives a slice's
  `usage` from its owned turns only. `sessionTurns` is deleted and `sessionEdits`
  reads turn edits exclusively.
- The Claude, Codex, and OpenCode readers stop setting `usage` and `edits` and
  drop the loops/helpers that rebuilt edits (`editsFromTurns`). `parseClaudeSession`
  still returns null when no turn carries an edit.
- Added `tests/planning-reader-shape.test.ts`, parsing one session through each
  reader and asserting non-empty `turns` with none of the four removed keys.
- Reworked the planning test helper: `candidate` builds its default turn from the
  old default edit and call sites now pass `turns` built via `editTurn`. Removed
  assertions on the four removed fields and the retired `sessionUsage` test.

## Deviated

- The `candidate` helper keeps no `edits` convenience. The match and approve
  observation tests build sessions through the new `turns: [editTurn(...)]` shape,
  as the acceptance line requires; only the helper's default is derived from the
  single edit it used to list.
