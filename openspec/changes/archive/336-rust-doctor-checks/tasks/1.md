## Acceptance

- [ ] `parse_config` reads `agy`, `opencode`, `codex` and `claude` into `AgyConfig`, `OpencodeConfig`, `CodexConfig` and `ClaudeConfig`, exported from the crate root, as rust-config "Harness settings" says, in the key order "Config file" gives.
- [ ] `Planning` holds `prices: BTreeMap<String, PlanningPrice>`, read from `planning.prices` as "Planning settings" says, and `Config` and `Planning` derive `PartialEq` without `Eq`, `Planning` without `Copy`.
- [ ] New `tests/config_harnesses.rs` proves every row of "Harness settings read".
- [ ] `tests/config_planning.rs` gains a test proving every row of "Planning prices", and its `defaults()` holds an empty `prices`; every other test in it passes unchanged.

## Details

- Read each new table the way `blocks/pi.rs` reads `[pi]`: `value::check_keys`, then `value::non_empty_string` and `value::boolean` in the key order.
- Keep `osq-coder` as a named constant, as the planning defaults are.
- A price accepts a TOML integer or float; every refusal, a missing key or a string included, is `InvalidValue` with the reason `must be a finite non-negative number`, so `ConfigError`'s list of expected types stays unchanged.
- The plan crate reads `config.planning` by reference only; nothing outside this crate copies `Planning`.

## Scenarios

- rust-config: Harness settings read
- rust-config: Planning prices
- rust-config: Planning values
- rust-config: Planning errors
