- [ ] New `tests/doctor_harness.rs` proves every row of "Doctor harness lines", each row in a child process of the test binary.

## Details

- Reuse `probe` in `src/doctor/probe.rs` for every harness program, and keep the pi lines and `PI_TESTED_RANGE` as they are.
- Put the program table, the version assessments and the containment lines in their own modules under `src/doctor/`, as pure functions of the config, the environment map and the version text; `run_doctor` and `collect_lines` stay the orchestrators.
- The `validator-harness` lines of task 4 reuse the harness lines with another harness, so build them from a harness and the config, not from `config.executor` alone.
- Start the child the way `spawn_child` in `tests/doctor_setup.rs` does, which no test of this task changes: remove `AGY_PATH`, `OPENCODE_PATH` and `CODEX_PATH` from its environment, then set the row's variables.
- Run `tests/fixtures/fake-pi/doctor.sh` in place as every harness's program; it prints `fake-pi-version` for any `--version`.
- `doctor_setup.rs` and `doctor_decisions.rs` stay unchanged and keep passing: their scenarios check single lines, and a root with no `osq.toml` now probes `agy`.
- Task 4 extends the files in `src/` after this task.
