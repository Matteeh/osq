## Changed

- Added `src/doctor/harness.rs` and its `program`, `version` and `containment` modules. They build every harness's `harness`, `harness-version` and `harness-containment` lines, with pi's existing version and auth lines reused.
- `run_doctor` now prints the executor harness's lines and, when `osq.toml` loaded, its containment line. A config error falls back to the default agy harness lines and prints no containment line.
- Program resolution follows the harness table: mock needs none; agy uses `AGY_PATH`; opencode uses `OPENCODE_PATH`, then `opencode.bin`; codex uses `codex.bin`, then a trimmed `CODEX_PATH`; claude uses `claude.bin`.
- Added `tests/doctor_harness.rs`, proving every "Doctor harness lines" row in a child process and adding fallback-program rows that cover each harness's default program.
- Updated `tests/doctor_checks.rs` to the scenario's mock and pi rows with containment lines, and `tests/doctor_changes.rs` to run its roots on the mock harness.
