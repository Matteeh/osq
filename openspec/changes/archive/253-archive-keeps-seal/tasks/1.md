- [ ] `ensureArchivedTasksTicked` in `src/watcher/archiver.ts` reads only `<archived folder>/tasks.md`, walks no subfolder, and does nothing when that file does not exist; it writes the file only when its text changes.
- [ ] `tickAllTaskCheckboxes` ticks only `-` bullets: its pattern becomes `^([ \t]*-[ \t]+\[)[ ](\])` with the `g` and `m` flags, and its doc says it ticks only the boxes `hashChangeFolder` clears. Its name and export stay.

- [ ] New `tests/archive-keeps-seal.test.ts` proves watcher-and-harness "Archived seal matches approval", "Root task lines" (one assertion per row, the line found as a whole line of the archived file), "Nested tasks file keeps its bytes" and "Archive without a root tasks file", each through `archiveSpecFolder` on a change built in a temporary project as `tests/archiver.test.ts` builds one. "Archived seal matches approval" writes `hashChangeFolder` of the change folder to its `.run/approved` before the archive.
- [ ] `tests/archiver.test.ts` passes unchanged.

## Details

The seal's own rule is `hashChangeFolder` in `src/core/spec/hasher.ts`; do
not change it. Every line the new pattern ticks is one the seal clears back
to `[ ]`, so ticking leaves the seal as it was.

Take the expected lines from the scenarios' tables, never from running the
code.
