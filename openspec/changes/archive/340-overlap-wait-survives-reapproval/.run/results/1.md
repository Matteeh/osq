## Changed

- `AwaitedDependency` now carries optional `reapproved?: true`. `awaitedDependencies` keeps an overlap line whose change reads `approved` or `archived` under any recorded hash, uses the line's hash, and adds `reapproved: true` only when the change's approved hash differs. `formatStackedOn` still writes no mark.
- `decideStackCut` drops an overlap line only when its change reads `unapproved`; a re-approved overlap stays in the decision and makes the change wait through the existing approved-dependency rule. Declared lines still halt with `dependency_changed` on a new hash.
- Updated the two table-row tests in `tests/approve-overlap.test.ts` and `tests/stack-overlap-cut.test.ts` to the re-approved expectations.
- Added `tests/stack-overlap-reapproved.test.ts`, proving "Overlapped change approved again before it lands" through `runWatcherOnce`: the first cycle waits with no `osq/002-b`, then after `001-a` is archived and landed by hand the second cycle cuts `002-b` from `main` and logs the stacked line.

## Deviated

The new scenario test reaches the active change folder through `OSQ_CHANGE` and, when that is absent, finds the active delta by its scenario header rather than naming this change's folder. It still uses a temporary lookup root with a deduped living watcher-and-harness spec because the living spec repeats scenario names.
