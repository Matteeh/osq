## Details

The rest of each function stays as it is: an overlap line whose change
reads `landed` still leaves `awaitedDependencies`, and in `decideStackCut`
a kept re-approved line that reads `approved` makes the change wait
through the existing `kept.some(... 'approved')` rule. Update the doc
comments of both functions to the new rule.

`src/core/spec/stack-dependencies.ts` has 247 lines and the source budget
is 250, so the change may add three lines at most: replace the hash
`continue` with a push that spreads `reapproved: true` into the entry only
when the hashes differ, and give the new field a one-line doc comment.

Build the new test from the helpers in `tests/stack-overlap-cut.test.ts`
(`makeProject`, `approveIntoWorktree`, `reapproveHash`, `archiveOnBranch`,
`landOnMain`, `stackedRoot`); they are not exported, so copy what the test
needs. Approve `001-a` into its worktree and approve `002-b` so it stacks
with an overlap line on `001-a`, both writing `orders`, then change
`001-a`'s approved hash with `reapproveHash`. For the first cycle, keep
`001-a`'s task from finishing as "waits while the dependency is still
running" in `tests/stack-run.test.ts` does, by dirtying a file outside
its scope in its worktree. Then assert no branch `osq/002-b`, the stacked
approval directory of `002-b` still there, and no
`.run/regressed/change.md` in it. Then clean the dirt, archive `001-a` on
its branch, squash-merge it into `main`, run a second cycle, and assert
`osq/002-b` exists and the log holds
`stacked 002-b on main: worktree <path>` (a capturing logger, as
`tests/stack-run.test.ts` uses).

Import `scenario` from `@matteeh/osq/testing`, as
`tests/languages-lockfiles.test.ts` does, and call `runWatcherOnce`
