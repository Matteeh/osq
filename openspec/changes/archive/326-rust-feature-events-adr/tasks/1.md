## Acceptance

- [ ] `Feature` gains `reacts_to(&self) -> Vec<EventKind>`, returning an empty list by default, and `react(&self, reaction: &Reaction<'_>) -> Result<Output, FeatureError>`, returning `Ok(Output::text(""))` by default, as the modified rust-core "Feature trait" says. The trait stays object safe, and no feature crate changes.
- [ ] New `src/event/kind.rs` holds `EventKind` with one variant per `Event` variant, `Event::kind` and `EventKind::name`, as "Event kinds" says. `EventKind::name` and the existing private `Event::type_name` give the same text; make one call the other so the names live once.
- [ ] `Reaction<'a>` and `Reaction::new` live in `src/feature.rs`, as "Reaction" says. `lib.rs` exports `EventKind` and `Reaction`.
- [ ] New `tests/feature_reactions.rs` proves "Reaction defaults", "Kinds of events", "Every kind names its type" and "Reaction fields". Each test's doc names `Covers: rust-core/<scenario>`. `tests/feature.rs` passes unchanged.
- [ ] Every new public item's doc ends with `Implements: rust-core/<requirement>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Core does no IO (ADR 022): `Reaction` only borrows a `Path` and an
`Envelope`.

For "Every kind names its type", reuse how `tests/events.rs` builds one
valid line of each event type, and copy what you need into the new test
file, since `tests/events.rs` must not change. A `HashSet` of the kinds
proves they are all different.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/326-rust-feature-events-adr`, so the link
gates see this change's new requirements.
