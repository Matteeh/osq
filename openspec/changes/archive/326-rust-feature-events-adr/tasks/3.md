## Details

Raising `rust-version` to 1.89 lets clippy suggest let chains (Rust 1.88)
and `is_multiple_of`. Measured again on main after 331 landed, on
2026-10-24, that gave 43 findings in 35 files in `scope`, among them the
stop-record `if` in `Sync::finish` in `crates/features/land/src/land/sync.rs`,
which 331's active sync kept. `cargo clippy --fix --allow-dirty --workspace
--all-targets` followed by `cargo fmt --all` clears every one with no
other edit. Run that before writing the delivery code. The
`crates/kernel/**` and `crates/features/**` globs are there only because
scope takes at most 8 patterns: outside `crates/kernel/loop/`, change
nothing but clippy's rewrites, and leave task 2's storage files alone. Do
not add an `#[allow]` or change `[workspace.lints]` or `clippy.toml`. A previous
attempt wrote the delivery code and stopped only on these findings; its
result file describes that code. `Cargo.lock` follows the loop's
`Cargo.toml` and is not in `scope`; osq accepts that change.

Split the work into small named functions (ADR 023): listing the delivered
changes, taking the lock, reading and writing the cursor, reading the new
complete lines of one file, and delivering one file to one feature. The
pure parts, such as splitting bytes at the last `\n` and moving an offset,
take no paths.

Listing the delivered changes copies the tree listing from the retry
crate's `find.rs`: `load_config`, `project_git_root`, a `GitVcs` with the
config's timeouts, `worktree_list`, `change_trees` with no stacked folders
and `list_tree_changes`. Do not depend on any feature crate (ADR 022).

`File::try_lock` gives `TryLockError::WouldBlock` when another handle holds
the lock; delivery then skips the change with no failure, since the loop
and a CLI command overlapping is normal. `TryLockError::Error`, and an
error opening the file, give the "could not be taken" failure. In "Held
lock", the test opens its own handle to the same file and calls `lock()` on
it before running delivery, so the two handles conflict even inside one
process. In "Lock error", a folder at the lock's path makes opening it fail.

The check that the byte before a cursor offset is `\n` reads that one byte
from the open file; cursors are committed, so git can rewrite an event file
under one.

Write the cursor with `osq_kernel_storage::write_durable` from task 2.
serde_json's `Map` sorts its keys unless the `preserve_order` feature is on;
check the workspace's serde_json features, and sort by hand if needed.

Test features are hand-written in the tests. Put shared ones in
`tests/delivery_support/mod.rs`. They record their calls in a
`RefCell` or `Mutex` the test reads afterwards, and they write event lines
with a plain `OpenOptions::append` write of the line and `\n`.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/326-rust-feature-events-adr`, so the link
gates see this change's new requirements.
