## Details

`task_history/stream.rs` already parses an event stream loosely, passing
over lines that are not JSON objects. Reuse it for the validator reader,
widening its visibility within the crate if you need to; give its `Event`
a data member's raw `serde_json::Value` if it lacks one. Read timestamps
with `timestamp_ms` from `text.rs`. Trim the outcome with
`osq_kernel_specs::js_trim`, since JavaScript's `trim` also strips U+FEFF.

In "Latest validator runs" every timestamp in a row is on 2026-10-25,
written `YYYY-MM-DDTHH:MM:SS.mmmZ`. Write `tests/fixtures/task-event-files/`
as the two other scenarios describe it, with any short text in each file;
its `305-active` folder needs no proposal.

The TypeScript in `entry` is what you port: `latestForChange` and
`readValidation` in `report-validation.ts`, the `fileExists` check of each
discovered task and `collectCapabilityCoverage` in `report.ts`, and
`readLivingCapabilityNames` in `digest-capability.ts`. Never read anything
under `src/` from Rust; those files are in `entry` only so you can port
them.

cargo-mutants runs on every line you touch, so give each branch a row that
fails when it flips. Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/337-rust-report-traceability-coverage`, so the
link gates see this change's new requirements.
