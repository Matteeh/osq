## Changed

- Added `src/core/spec/digest-decisions.ts` (68 lines): `collectDigestDecisions`
  reads the project's ADRs with `readDecisions` and `governingAdrs`, returns the
  digest's `{ number, rule }` decisions in number order, and parses the
  proposal's `## Decisions` section into one `adr_departure` flag per departure
  line (optional `- ` marker stripped, label `departs from ADR <n>`, excerpt the
  line without the marker). Types `DigestDecision` and `DigestDecisions`.
- `src/core/spec/digest.ts`: `ApprovalFlagId` gains `adr_departure`,
  `ApprovalDigest` gains `decisions`, and `buildApprovalDigest` calls the new
  module with the change's written capability names and the extracted
  `## Decisions` section, then appends the departure flags after
  `buildApprovalFlags`' flags.
- `src/core/spec/digest-format.ts`: prints `Decisions:` and one
  `  ADR <number>: <rule>` line per governing ADR after the capabilities and
  before the human steps, only when the list is non-empty.
- `src/core/report/approval-flags.ts`: `FLAG_IDS` gains `adr_departure` after
  `verify_starts_conflict`, so it appears before `none`.
- Added `tests/approval-digest-decisions.test.ts` (6 tests): governing ADRs in
  number order with formatted placement, only accepted ADRs, no governing ADR
  leaves the digest unchanged, one departure flag per line after every other
  flag, a marker-less departure line, and an `approveSpec` change whose recorded
  `adr_departure` the report counts as shown fired 1 / troubled 1 after a dead
  event.
- `tests/report-approval-flags.test.ts`, `tests/report-json.test.ts`, and
  `fixture/report/expected.json` now expect the `adr_departure` key at zero.

Task verify (`node --import tsx --test tests/approval-digest-decisions.test.ts`,
6/6) and the proposal verify (`pnpm verify`, exit 0) both pass.

## Deviated

- The task says the new module implements the behaviors "with `readDecisions`
  and `governingAdrs`". I import and use those two functions from
  `src/core/foundation/decisions.ts` rather than re-exporting them; the module
  exposes one operation, `collectDigestDecisions`. Behavior matches the delta.
- A departure line is recognized only with the literal `Departs from ADR <n>:`
  prefix after an optional `- ` marker, matching the requirement's wording; the
  excerpt is the trimmed line without the marker.
