## Changed

- `src/core/run/manifest.ts`: `ManifestData` gains optional `decisions`
  (`Record<string, string>`), and the approval branch of `buildManifest` fills
  it from `readDecisions` + `governingAdrs` over the change's written
  capabilities (empty object when none govern, omitted for a planning-only
  manifest). `hashFileContent` is now exported so the drift check hashes
  AGENTS.md with the manifest's exact function.
- `src/harness/types.ts`: `HarnessEventType` gains `instructions_changed`;
  new `InstructionsChangedEventData` (`changed: string[]`) is added to
  `OsqEventData`.
- Added `src/watcher/instructions-drift.ts` (162 lines): `checkInstructionsDrift`
  reads `.run/manifest.json`, does nothing for a later attempt, a manifest
  without `approvedAt`, or a stream that already holds the event; otherwise it
  compares AGENTS.md and, when the manifest has `decisions`, the governing ADR
  set and hashes, appends one `instructions_changed` event via
  `appendHarnessEvent`, and prints
  `task <n>: instructions changed after approval: <changed>` with `logger.warn`.
- `src/watcher/spawn.ts`: after `readRetryContext` and before `adapter.spawn`,
  calls `checkInstructionsDrift` only when `retryContext.attempt === 1`.
- `src/core/status/show.ts`: `formatInstructionsChanged` projects the latest
  `instructions_changed` event, and `formatSpecDetails` prints it right after
  the `Stuck:` line.
- Added `tests/instructions-drift.test.ts` (10 tests): governing ADR recorded
  on approval and omitted at plan time; empty decisions with no ADR; AGENTS.md
  edit appends one event, warns, and still runs; a new governing ADR; a changed
  ADR; a removed ADR; nothing changed; a second attempt after `osq retry` adds
  none; a manifest without `decisions` compares only AGENTS.md; and `osq show`
  prints the drift line under the task.

Both the task verify (`node --import tsx --test tests/instructions-drift.test.ts`,
10/10) and the proposal verify (`pnpm verify`, exit 0) pass.

## Deviated

- The task asked to keep the `spawnTaskAgent` call to three lines inside the
  193-line file. Passing an options object literal was reformatted by Biome to
  eight lines, pushing `spawn.ts` to 204 and breaking the strict under-200
  lifecycle budget. I pass `{ ...opts, attempt: 1 }` instead: `SpawnTaskAgentOptions`
  already carries every field the check needs, so the call stays three lines
  (file is 197 lines). The check still guards `attempt !== 1` itself.
- `spawn.ts` now 197 lines, not 193 plus three, because Biome also reformatted
  nothing else; the only additions are the import, `if`, and `await`.
- The tests declare `verify_starts: green` so the pre-spawn verify does not
  emit its unrelated `started green, but it declared red` warning into the
  logger stub that captures drift warnings.
