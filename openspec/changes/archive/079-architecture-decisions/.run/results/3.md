## Changed

- Added `src/cli/plan-sections.ts` with `formatCapabilitySpecsSection(projectRoot, openspecRoot)`,
  the `## Capability Specs` code moved verbatim out of `buildBaseOpeningPrompt`, and
  `formatArchitectureDecisionsSection(projectRoot, config)`. The latter reads through
  `readDecisions`, keeps only `status: accepted` ADRs in number order, returns null when
  none exist, and renders the required sentence followed by one line per ADR:
  `- ADR <n>: <title>. Applies to: <all | names>. Rule: <rule> Path: <path>`. 54 lines.
- `src/cli/plan-queue.ts`: `buildBaseOpeningPrompt` gained an optional `config` defaulting
  to `DEFAULT_CONFIG`; it calls the two section formatters and inserts the decisions
  section between the capability specs and the brief only when it is non-null. The
  no-decisions output is byte-identical to before. Down to 247 lines, under the 250 budget.
- `src/cli/plan.ts`: `buildOpeningPrompt` resolves the config first and passes it into
  `buildBaseOpeningPrompt`, so `osq plan` reads the configured decisions folder.
- Added `tests/plan-decisions.test.ts` (4 tests) driving `buildOpeningPrompt` with a
  supplied `recordBody`: the requirement's accepted/superseded scenario with exact line
  bytes, section ordering, number order and absence of the superseded ADR; a project with
  only a proposed ADR; a missing decisions folder; and a configured `paths.decisions`.

Task verify (`node --import tsx --test tests/plan-decisions.test.ts`, 4/4) and the
proposal verify (`pnpm verify`, typechecks/build/full suite/lint) both pass.
