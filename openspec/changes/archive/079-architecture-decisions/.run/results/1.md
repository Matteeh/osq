## Changed

- Added `src/core/foundation/decisions.ts`, the single reader of
  `paths.decisions`. It implements the port (`Adr`, `DecisionRecords`,
  `DecisionProblems`, `readDecisions`, `validateDecisions`, `sameAdrNumber`,
  `systemWideAdrs`, `governingAdrs`), parses frontmatter with
  `parseFrontmatter`, hashes UTF-8 content locally, and returns ADRs in number
  order plus sorted ignored paths. 231 lines, under the 250-line budget.
- Added `limits.maxRuleLength` (160) and `limits.maxProjectRules` (10) to
  `OsqLimits` and `DEFAULT_CONFIG.limits`, each with a one-line doc comment;
  they merge through the existing config path.
- Prefixed the frontmatter given in the task to ADRs 001, 002, 004, and 005,
  leaving each body byte-identical.
- Added a `## Format` section to `decisions/README.md` between the opening
  paragraph and `## Index`.
- Added `tests/decisions-read.test.ts` (24 tests) covering both requirement
  scenarios, the three "Decision limits" lines, every validation error and
  warning, a missing decisions folder, `superseded_by` naming a missing ADR,
  `governingAdrs`, `sameAdrNumber('7', '007')`, and osq's own four ADRs read
  with `DEFAULT_CONFIG` against `readLivingCapabilityNames`.

Task verify (`node --import tsx --test tests/decisions-read.test.ts`) and the
proposal verify (`pnpm verify`) both pass.

## Deviated

- The delta spec says validation warns "for each capability name in
  `applies_to` that has no living spec" without restricting the status. I emit
  that warning for any ADR whose `applies_to` is a list (proposed, accepted, or
  superseded), not only accepted ones. For accepted ADRs this matches the
  scenario; for the others it is the literal reading of the sentence.
