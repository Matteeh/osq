## Changed

- Added `src/core/spec/decisions-lint.ts` (177 lines): `collectDecisionsFindings`,
  the one exported function lint calls. It returns no findings when
  `readDecisions` finds no ADR, otherwise folds in `checkProjectRules` (errors
  on file `AGENTS.md`) plus the Decisions checks. It reads `## Decisions` with
  the same section reader as `## Surface`, treats it as missing when absent or
  comment/whitespace-only, reads written capabilities as the directories under
  the change's `specs/` holding a `spec.md`, errors per accepted capability-
  scoped ADR left unnamed, and warns per named ADR that doesn't exist or isn't
  accepted. `sameAdrNumber` backs every number match, so a departure line
  `Departs from ADR <n>:` names it.
- `src/core/spec/linter.ts`: imports the module and calls it once, immediately
  after the `## Surface` check, only when the change document is a `proposal`
  (a legacy `spec.md` is exempt). Each finding is added as the change's own.
- `README.md`: four rows in the lint table (two rejects for the Decisions
  section and governing ADRs, one reject for the stale/oversized rules block,
  one warning for an unknown or unaccepted ADR) and a `### Architecture
  decisions` subsection under the lint documentation describing the ADR
  frontmatter, the AGENTS.md rules block, the `## Decisions` section, the
  `decisions` doctor check, and `limits.maxRuleLength` / `limits.maxProjectRules`.
- Added `tests/decisions-lint.test.ts` (15 tests) on temporary projects built
  like `tests/proposal-surface-lint.test.ts`. It drives `lintChangeFolder` and
  `approveSpec`, covers every scenario of both requirements, asserts finding
  `severity`, `file`, and `section` (not only text), and adds a legacy-spec.md
  exemption test.

Task verify (`node --import tsx --test tests/decisions-lint.test.ts`, 15/15) and
the proposal verify (`pnpm verify`, exit 0) both pass.

## Deviated

- The task pins only the missing-section and unnamed-ADR messages. It leaves the
  unknown-ADR warning text free, so I used one message for both cases:
  `proposal.md ## Decisions names ADR <n>, which does not exist or is not
  accepted`. Tests assert that exact text.
- A capability that an ADR applies to through multiple written capabilities
  yields one error naming the first written capability in sorted order, rather
  than one error per capability. The change is rejected either way.

## Outside scope

- `readDeltaCapabilities` in `src/core/spec/impact-lint.ts` counts any directory
  under `specs/`, while this task defines a written capability as a directory
  holding `spec.md`. The two definitions can disagree for a malformed change
  folder; left alone because impact-lint is outside this task's scope.
