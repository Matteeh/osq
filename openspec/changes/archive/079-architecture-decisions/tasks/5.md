## Acceptance

- [ ] New `src/core/spec/decisions-lint.ts` exports one function that returns `LintFinding`s for a change, implementing the spec-lint-and-approve delta's "Decisions section lint" and "Project rules lint" with `readDecisions` and `checkProjectRules`.
- [ ] `lintChangeFolder` calls it once, next to the `## Surface` check, and adds each finding as the change's own. A legacy `spec.md` is exempt.
- [ ] The written capabilities are the directories under the change's `specs/` that hold a `spec.md`. An ADR counts as named when the Decisions section contains `ADR <n>` whose number `sameAdrNumber` matches.
- [ ] Findings carry the proposal's repository path and the section `Decisions`, except the project rules errors, which carry `AGENTS.md`.
- [ ] `README.md`'s lint table lists the new errors and the warning, and a short `### Architecture decisions` section under the configuration or lint documentation describes the ADR frontmatter, the AGENTS.md rules block, the `## Decisions` section, the `decisions` doctor check, and the two new limits.
- [ ] New `tests/decisions-lint.test.ts` lints temporary projects through `lintChangeFolder` and `approveSpec`, covers every scenario of both requirements, and asserts finding fields, not only text.

## Details

Build the temporary projects as `tests/proposal-surface-lint.test.ts` does. A
project counts as having ADRs when `readDecisions` returns at least one ADR of
any status. Without one, return no findings, so every existing test that
writes a proposal without `## Decisions` passes unchanged; a trial confirmed
it. Read the section the way `readSurfaceSection` does in `linter.ts`, but in
the new module. The missing-section error is:

`proposal.md needs a ## Decisions section: name each accepted ADR that governs a capability this change writes, or write None`

The unnamed-ADR error is:

`proposal.md ## Decisions does not name ADR <number>, which applies to <capability>`

`linter.ts` is on the line-budget allow list and `lintChangeFolder` is
grandfathered in the function budget; keep `linter.ts` to the call. New
functions stay within 80 lines and new files within 250.
