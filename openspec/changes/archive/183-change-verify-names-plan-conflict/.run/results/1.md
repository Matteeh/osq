## Changed

- New `src/watcher/plan-conflict.ts`: exports `findPlanConflict`, which decides whether the last red change-verify run is a plan conflict (run did not time out, `readFailingTestFiles` names at least one test, every named test is outside the current task's resolved scope and owned by another task of the same change with a canonical done marker under `.run/done/`), returning one entry per failing test with the lowest-numbered owning done task, sorted, or null. Ownership comes from each done task's `tasks/<n>.md` scope resolved through `resolveScope` and from the `Touched:` line of its `.run/results/<n>.md` parsed with `parseResultSections`, split on commas and trimmed. Also exports `formatPlanConflictMarker`, which builds the `blocked` dead marker (reason, command, exit code, one `- <test> (task <owner>)` line per failing test, `Revise the plan with osq plan <id>`, and the excerpt via `excerptVerifyOutput` exactly as `formatChangeVerifyMarker` does).
- `src/watcher/change-verify.ts`: `runChangeVerifyGate` calls `findPlanConflict` after the rerun loop when the rerun context is given and the result is red; on a conflict it returns a failure carrying `reason: 'blocked'`, the plan-conflict marker, and the error `Plan conflict: <test> (task <n>), ...`. Every other failure now also names its reason explicitly (`change_verify_red`), so the runner can pass it through.
- `src/watcher/runner.ts`: `runTask` passes `gate.reason` to `fail` instead of the hard-coded `'change_verify_red'`; the gate always sets the reason, defaulting to `change_verify_red` for the non-conflict failures, so otherwise-behavior is unchanged. One-line edit, line count and `runTask` length unchanged.
- New `tests/change-verify-plan-conflict.test.ts`: proves both scenarios through `runTask` with plain `node:test` cases, scripted change-level verify, and a result-writing adapter, mirroring `tests/change-verify-rerun.test.ts`. Every row of the "Failing tests owned by an earlier task" table is one case (scope-owned, Touched-only, no done marker, partially owned, also in the current task's scope, no failing-tests section, timed out), plus a "Plan conflict marker" case asserting the full marker body and the single `dead` event with reason `blocked`, plus a lowest-owner case.

## Deviated

- `runTask` passes `gate.reason` rather than the literal `gate.reason ?? 'change_verify_red'`. The `?? 'change_verify_red'` form measures 103 characters, beyond the repository's biome `lineWidth: 100`, so keeping it on one line (as the acceptance requires, so the line count of `runner.ts` and the length of `runTask` do not grow) is impossible. Instead `runChangeVerifyGate` sets `reason: 'change_verify_red'` on every non-conflict failure, so the runner's single-line change `fail(gate.reason, ...)` produces exactly the same deaths as before.
