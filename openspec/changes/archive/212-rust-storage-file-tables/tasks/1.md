## Details

Types, all public with `Clone`, `Debug` and `PartialEq`:

- `ResultSections`, with `Option<String>` fields `changed`, `deviated`, `missing_context`, `outside_scope`, `blocked`, `next` and `touched`.
- `TaskDisclosure { task: String, deviated: Option<String>, missing_context: Option<String>, outside_scope: Option<String> }`.
- `ManualEdit { file: String, kept_at: String, paths: Vec<String>, capabilities: Vec<String>, comment: String }`.

Put the section parser and the results reading in new files under
`src/read/`. `src/read/snapshot.rs` is near 200 lines and
`src/read/snapshot/events.rs` is over 200, so add only the field and the call
to them. Split lines on `\n` with an optional `\r` before it. "Trimmed"
means Unicode whitespace at both ends, as JavaScript's `trim` does. Write the
heading and `None` rules by hand; add no regex crate.

`read_manual_edits` reads frontmatter with `yaml-rust2`, as
`frontmatter_string` in `src/read/text.rs` does. Reuse `markdown_body` for
the body. A YAML integer or other non-string in `paths` or `capabilities` is
left out. A scalar `capabilities` reads as no entries.

The fixtures and their expected rows are the source of truth. Copy them, and
never edit them. TypeScript's `osq query --json` printed the files under
`files-rows/` for the `files/` project, and task 2 reads them. Tests find the
fixtures from `env!("CARGO_MANIFEST_DIR")`. More test files are allowed when
they match `tests/reading_files*.rs`.

Keep every `.rs` file under 250 lines and every function under 80. Workspace
lints include `clippy::pedantic` and `-D warnings`; meet them rather than
allowing them. Keep tests in `tests/`. When the mutation step reports a
missed mutant, add a case for it. Run `cargo fmt --all` before exiting.
