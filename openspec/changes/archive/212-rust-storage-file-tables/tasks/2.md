## Details

`src/model/mod.rs` is at 171 lines, so put the new row mapping and inserts
in new files under `src/model/`, as `event_rows.rs` and `insert_events.rs`
do for the event tables. The `CREATE TABLE` list in `mod.rs` gains the two
tables. Row mapping is pure: it takes a snapshot, or the manual records, and
returns row structs. Only the insert functions touch SQLite. Insert the
manual edits in their own transaction, as the label fill does.

The expected rows in `tests/fixtures/files-rows/` were printed by TypeScript
and are the truth. When a row disagrees, the Rust mapping is wrong. Never
edit a fixture file. When a row disagrees because of what task 1's reading
returns, write it under `## Blocked`. Read the JSON with `serde_json`. Tests
write their databases under `env!("CARGO_TARGET_TMPDIR")`, one file name per
test. More test files are allowed when they match
`tests/read_model_files*.rs`.

Keep every `.rs` file under 250 lines and every function under 80. Workspace
lints include `clippy::pedantic` and `-D warnings`. When the mutation step
reports a missed mutant, add a case for it. Run `cargo fmt --all` before
exiting.
