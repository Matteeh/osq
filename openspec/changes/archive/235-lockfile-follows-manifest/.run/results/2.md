## Changed

- Added `scopeCoversChangedPath(scope, relativePath, changedPaths)` to `src/core/run/scope.ts`. It is true when `scopeCoversPath` covers the path, or when `lockfileFollowsManifest` says the path follows a changed path the scope covers. It reads no file and carries `@scenario watcher-and-harness: Dependency added to a crate` and `@adr 017`.
- `scopeViolations` in `src/watcher/git-guard.ts` now judges each changed file with `scopeCoversChangedPath`, passing the comparison's changed files.
- `scopedStatusPaths` in `src/core/run/task-commit.ts` now judges each status path and rename source with `scopeCoversChangedPath`, passing every status entry's path.
- Added `tests/lockfile-follows-manifest.test.ts`, which builds committed worktree projects with Cargo and pnpm manifests and proves all four scenarios: a crate dependency is allowed and committed with the lock file, a lock file without its manifest still dies as `scope_violation`, a pnpm package change is allowed and committed with `pnpm-lock.yaml`, and two tasks that each change the lock file both finish and archive without regression. The two-task test also checks that neither done marker records `Cargo.lock`.

## Deviated

- For the single-task scenarios, `runTask` runs the task and the test asserts its result and events; the test then calls `runWatcherOnce` so the watcher makes the verified commit (and archive) the scenarios assert. This keeps the task driven by `runTask` while letting the test prove the real watcher commit path.
