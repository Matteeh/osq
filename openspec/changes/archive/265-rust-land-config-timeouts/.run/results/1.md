## Changed

- `crates/features/land/src/land.rs`: added one private `git_vcs(root, timeouts)` helper that builds `GitVcs::new` and calls `with_timeouts`; `run_land` now reads `config.timeouts` and builds the root's `GitVcs` through it. `check_refusals` and `worktree_head` receive those timeouts and build the change worktree's `GitVcs` through the same helper. No `GitVcs::new` call remains outside the helper.
- Extracted the already-landed output choice into a small `landed_output` helper so `run_land` stays under clippy's 80-line limit.
- Added `crates/features/land/tests/land_timeouts.rs` with one test per row of "A slow git status stops land at the configured limit": the change worktree's status and the checkout's status. Both assert the `Failed` error for `land`, the exact `VcsError::TimedOut` message with the 1s limit, completion within 5 seconds, and an unchanged checkout HEAD.

Verification: `cargo test -p osq-feature-land --test land_timeouts` passes (2 tests). `OSQ_CHANGE=openspec/changes/265-rust-land-config-timeouts sh scripts/verify-rust.sh` passes. `cargo mutants -p osq-feature-land -f crates/features/land/src/land.rs` found no missed mutants (31 caught, 7 unviable).

## Deviated

- The test writes the support's vcs block inline because support's `OSQ_TOML` constant is private and `tests/support/mod.rs` is outside this task's scope. The inline block is byte-for-byte the same content with the `[timeouts]` table appended.
- `run_land`'s already-landed output branch moved into `landed_output` to satisfy clippy's `too_many_lines` after the timeout plumbing.

## Missing context
