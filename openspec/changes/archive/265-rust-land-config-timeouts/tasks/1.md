## Acceptance

- [ ] `run_land` in `crates/features/land/src/land.rs` builds every `GitVcs`, the root's and each change worktree's, through one private helper that takes a path and the loaded config's `timeouts` and calls `GitVcs::new` then `with_timeouts`; no `GitVcs::new` call remains outside it. The worktree's refusal check and `worktree_head` take the timeouts from `run_land`.
- [ ] A git timeout keeps failing with the `VcsError` display, as "Land settings" says; add no new land message.
- [ ] New `crates/features/land/tests/land_timeouts.rs` proves "A slow git status stops land at the configured limit", one test per row, each doc naming `Covers: rust-land/a-slow-git-status-stops-land-at-the-configured-limit`.

## Details

Build each row's repository with the helpers in `tests/support/mod.rs`, as
`land_commit.rs` does: `add_fixture_change`, then `write` the root's
`osq.toml` with the support's vcs block followed by the `[timeouts]` table.
Set the slow worktree config with the support's `git` helper:
`config extensions.worktreeConfig true` at the checkout, then
`config --worktree core.fsmonitor "sleep 30"` in the row's worktree. Git runs
the fsmonitor value through the shell, so no script file is needed, and it
slows only commands that refresh that worktree's index. Assert the elapsed
time as well as the message: with the default 10 second limit the message
would name `10s`.

- rust-land: A slow git status stops land at the configured limit
