## Acceptance

- [ ] `plan-prompt.md` holds sections 1 to 7 as rust-plan "Plan prompt" says, and fails on an archive it cannot read before it writes any file. New `src/next/report.rs` holds the one function that reads the history and the ownership, and a pure function that builds the section text after `## Brief`. `run_next` appends that text to what `prompt::build` returns, and `prompt.rs` does not change.
- [ ] New `src/next/report/record.rs` builds the body of "Repository record section", and new `src/next/report/hints.rs` builds the body of "History hints section". Both are pure functions over `ChangeSnapshot` and `TaskOutcome` values from `osq-kernel-storage`, which run no IO.
- [ ] `tests/fixtures/plan-created/005-beta/plan-prompt.md` becomes the text of `openspec/changes/255-rust-plan-prompt-report/golden/005-beta-plan-prompt.md`, byte for byte. `tests/prompt_sections.rs` changes only to append `<record>` to each expected prompt, as the modified "Prompt sections" says, and `tests/golden_folder.rs` does not change.
- [ ] New `tests/prompt_record.rs` proves "Repository record bodies" and "Archive that cannot be read". New `tests/prompt_history.rs` proves "History hint bodies". Each is one assertion per row that names the row, on roots it writes under `CARGO_TARGET_TMPDIR`.
- [ ] `crates/features/plan/Cargo.toml`, the root `Cargo.toml` and `Cargo.lock` do not change.
- [ ] Each function that implements a requirement ends its doc with one `Implements: rust-plan/<requirement>` line per requirement it serves, such as `Implements: rust-plan/repository-record-section`. Each new test's one-line doc names `Covers: rust-plan/<scenario>` in kebab-case.

## Details

Port `getRepositoryRecord` and `formatRepositoryRecordBody` from
`src/core/report/report.ts`, together with the `medianSeconds`,
`selectLargestFirstAttemptPass`, `scopeFileGeneration` and `formatDuration`
they use. Also port `formatHistoryHints` from
`src/core/report/history-hints.ts`. Read the measured facts from task 1's
`start_scope_resolver` and `measured_ms`, and the history rows from
`task_outcomes`. Do not port TypeScript's event reading: storage already
reads the events.

Count lengths in UTF-16 code units with `str::encode_utf16`, as JavaScript's
`length` counts them. Do the median's rounding in `f64` as JavaScript does:
`Math.round` rounds half up.

`report.rs` is shared with task 3, which adds the disclosure and manual-edit
sections and their submodules. Write it so a later section is one more call
in the builder and one more read in the reading function. Clippy refuses
unused code, so read nothing that this task does not use.

The scenario roots need archived changes with task files and event
streams. Write their `measures` lines as
`crates/kernel/storage/tests/reading_specs_outcomes.rs` does. cargo-mutants
runs on every line this task adds, so each branch must change a value that a
row checks.

Before exiting, run `cargo fmt --all`, then
`OSQ_CHANGE=openspec/changes/255-rust-plan-prompt-report sh scripts/verify-rust.sh`.
