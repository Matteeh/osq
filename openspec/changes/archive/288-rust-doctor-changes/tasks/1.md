## Acceptance

- [ ] `read_change_files`, with `ChangeFiles`, `LockFile` and `DoneMarker`, is exported from the crate root and behaves as rust-storage "Change folder files" says.
- [ ] New `crates/kernel/storage/tests/reading_change_files.rs` proves "Lock pids", "Done marker kinds" and "Change folder file order and presence", one test per scenario, each table row checked in its own scratch folder under `CARGO_TARGET_TMPDIR`, each test's doc naming `Covers: rust-storage/<scenario>`.
- [ ] Every existing storage test passes unchanged, rust-storage "One frontmatter reader" included.

## Details

Put the reader and its three types in `src/read/change_files.rs`, declare
the module and re-export the items in `src/read/mod.rs` with an
`Implements: rust-storage/change-folder-files` line in its module doc, and
add them to the crate root's `pub use read::{...}` list in `src/lib.rs`.

Parse a lock with `serde_json`, which storage already depends on, as
`read_running_lock` in `snapshot/markers.rs` does, but keep the `pid` as
`as_i64` and need no `startedAt`. Split a done marker only with
rust-specs `parse_frontmatter`, and read its keys as `string_field` and
`bool_field` in `markers.rs` read theirs; copy those two small helpers
rather than widening `markers.rs`, which this task does not own. Test
existence with `Path::exists`, so a folder counts as present.

`src/core/foundation/doctor-changes.ts` is in `entry` only to show what
TypeScript reads; never read anything under `src/` from Rust.

Each expected value is in the delta's tables. Write each row's files in a
fresh folder named after the test and row, as `reading_pending_records.rs`
does. Cover each half of the done-marker rule with its own row, as the
table does, so cargo-mutants finds no surviving `&&` or `||`.
