## Acceptance

- [ ] `doctor` prints the `locks`, `archives` and `done-markers` lines after its config and pi lines, as rust-doctor "Doctor change checks" says, and keeps printing them when the config fails to load or the pi binary is unavailable, as the modified "Doctor pi checks" says.
- [ ] `crates/features/doctor/Cargo.toml` depends on `osq-kernel-storage` and `osq-kernel-vcs` through `workspace = true`, as "Doctor command" says, and on no feature crate.
- [ ] `crates/features/doctor/tests/doctor_checks.rs` checks the modified "Doctor checks with a fake pi" table, every row ending with the three healthy lines, and nothing else in it changes.
- [ ] New `crates/features/doctor/tests/doctor_changes.rs` proves "Doctor change lines", every row in its own scratch root, and "Doctor reads every worktree", each test's doc naming `Covers: rust-doctor/<scenario>`.

## Details

Keep `collect_lines` in `src/doctor.rs` building the config and pi lines,
but have it return them along with the config it used, or
`Config::default()` when `load_config` failed, instead of returning early
past the change lines. Put the change checks in a new
`src/doctor/changes.rs`: the folder listing, the liveness check and the
three line builders, each a small function, the line builders pure.

List folders as `changes` in `crates/features/inbox/src/read.rs` does:
`GitVcs::new(..).with_timeouts(&config.timeouts)`, `root()`,
`worktree_list()`, `stacked_root` under `HOME`, then `change_trees` and
`list_tree_changes`; fall back to `list_changes` on the root when vcs is
off, `root()` is `None`, or any git call errs. Copy what you need; a
feature never depends on another feature (ADR 022). Check liveness as
`is_running` in `crates/features/retry/src/retry/running.rs` does, by
`/proc/<pid>`, with pids below 1 not alive. Write the relative-path helper
yourself over `Path::components`; std has none.

Read lock, done-marker and archive files only through storage's
`read_change_files`, never by opening them in doctor.

In the tests, `<live>` uses `std::process::id()`. Build the worktree scenario
as `repository` and `worktree` in `crates/features/inbox/tests/inbox_trees.rs`
do, with git's user name and email set in the scratch repository. Never read
anything under `src/` from Rust; `doctor-changes.ts` is in `entry` only to
show TypeScript's checks.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/288-rust-doctor-changes`, so the link gates see
this change's new requirement.
