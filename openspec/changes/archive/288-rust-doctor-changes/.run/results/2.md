## Changed

- Added `src/doctor/changes.rs`, which takes the root's real path, lists change folders through storage (`list_tree_changes` over `change_trees` when vcs is enabled and git succeeds, otherwise `list_changes`), reads them with `read_change_files`, and builds the `locks`, `archives` and `done-markers` lines. Locks use `/proc/<pid>` liveness, archived folders need a proposal and tasks, active done markers must be verified, rejected folders are skipped, and printed paths are relative to the real root as Node's `path.relative` writes them.
- Changed `collect_lines` to return the loaded config, or `Config::default()` on a load failure, so `run_doctor` always appends the change lines after the config and pi lines, including when config or pi fails.
- Added `osq-kernel-storage` and `osq-kernel-vcs` workspace dependencies to the doctor crate, and updated `Cargo.lock`.
- Extended every fake-pi row in `doctor_checks.rs` to end with the three healthy change lines.
- Added `doctor_changes.rs`, proving every "Doctor change lines" row in its own scratch root and "Doctor reads every worktree" against a scratch repository and worktree.

The task verify and the proposal verify (`OSQ_CHANGE=openspec/changes/288-rust-doctor-changes sh scripts/verify-rust.sh`) both pass; the mutation step reported that `OSQ_DIFF` was not set.

## Deviated

- Added a third test, `doctor_reads_stacked_changes`, to `doctor_changes.rs`. The prior attempt's change-level mutation run found `stacked_folders` survived replacement with an empty list, because none of the specified scenarios exercised a stacked approval folder. The extra test places an orphaned lock in a stacked folder and asserts the same `../worktrees/...` line the worktree scenario expects, which kills both missed mutants. It uses the same `Covers: rust-doctor/doctor-reads-every-worktree` scenario tag.
