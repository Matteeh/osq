## Changed

Prepared the `approveSpec` helper in each of the four land/sync test files for the
overlap stacking a later task adds, without changing today's behavior:

- Added a `dropOverlapLines(stacked, folder)` helper to each file. It reads
  `<stacked>/openspec/changes/<folder>/.run/stacked-on`, drops every line whose
  third whitespace-separated field is `overlap`, and writes the other lines back
  byte for byte (split/join on `\n`, no trimming of kept lines).
- `approveAndArchive` in `tests/vcs-land-refusals.test.ts` and
  `tests/vcs-land-stacked-order.test.ts`: when `result.stackedPath` is set, drop
  the overlap lines before the watcher cycle; then use
  `result.worktreePath ?? worktreePath(config.vcs, repo, folder)` as the returned
  worktree path (the watcher has cut a stacked change by then).
- `setupProject` in `tests/vcs-land.test.ts`: same drop-overlap step, then records
  `result.worktreePath ?? worktreePath(config.vcs, repo, folder)`.
- `approveIntoWorktree` in `tests/vcs-stacked-land.test.ts`: same drop-overlap
  step; the assertion now uses
  `result.worktreePath ?? worktreePath(project.vcs, repo, folder)`.
- Added the `worktreePath` import to each file, next to the existing imports.

Because approve writes no overlap lines today, `result.stackedPath` is never set
in these runs, the drop step is a no-op, and every existing assertion, message,
fixture, and test name is unchanged.

## Deviated

- In `tests/vcs-stacked-land.test.ts`, `approveIntoWorktree` returns `void` and
  never used a worktree path beyond its assertion, so the
  `worktreePath(...)` fallback is exercised only in that assertion. The
  substantive change there is the drop-overlap step.
