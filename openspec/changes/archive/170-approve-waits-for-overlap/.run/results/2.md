## Changed

- `src/core/spec/stack-dependencies.ts`: `AwaitedDependency` gains an optional
  `overlap: readonly string[]`, present only for an overlap line. `awaitedDependencies`
  now returns its `depends_on` entries first, then the `.run/stacked-on` overlap
  lines no entry names whose change still reads `approved` or `archived` with the
  recorded hash. `formatStackedOn` writes `<folder> <hash>` for a declared entry
  and `<folder> <hash> overlap <capability>[,<capability>...]` for an overlap;
  `parseStackedOn` reads both. A parsed declared line still deep-equals
  `{ folder, hash }`.
- New `src/core/spec/stack-overlap.ts` exporting `overlappingChanges`,
  `awaitedForApproval`, and `overlapEntries`. `overlappingChanges` returns the
  changes `listChanges` finds in any location or tree, counted once by folder
  name, whose state through "Stack dependency state" reads `approved` or
  `archived` and whose deltas share a capability, sorted by folder name.
  `awaitedForApproval` returns `awaitedDependencies` first, then each
  overlapping change no earlier entry names, dropping one another returned
  entry already awaits directly or through others (following each entry's own
  folder where `listChanges` found it), so a change that overlaps a chain
  stacks only on its tip.
- `src/core/spec/approve-worktree.ts`: `approveIntoWorktree` calls
  `awaitedForApproval` where it called `awaitedDependencies`; the stacked result
  now also carries `overlaps` (spread from `overlapEntries`) and stays at 245
  lines.
- `src/core/spec/approve.ts`: `ApproveResult` gains optional
  `overlaps: { folder: string; capabilities: string[] }[]`.
- `src/cli/approve.ts`: `printApprovalResult` prints one
  `  Runs after <folder>, which also writes <capabilities>` line per overlap,
  between `  Waiting for:` and `  Stacked:`.
- New `tests/approve-overlap.test.ts` proving all eight rows of "Which changes
  overlap", both "Awaited dependencies" scenarios (`Overlap lines count while
  their change waits to land` with approved, archived, other-hash, rejected and
  landed states, and `Stacked-on lines read back`), and "Approve a change that
  overlaps a running one" and "Approve a change that shares no capability"
  through the approve command's captured writers, plus the stacked copy's
  `.run/stacked-on` and the result's `overlaps`/`waitingFor`.
