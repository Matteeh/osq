## Acceptance

- [ ] New `src/core/status/show-runs-after.ts` exports `readRunsAfter(projectRoot, config, folderPath)` as status-inspection "Runs after in show" says, built on `awaitedForApproval` and `awaitedDependencies`. It selects the vcs itself and returns an empty list without `vcs.enabled` or under `NoVcs`.
- [ ] `SpecDetails` gains optional `runsAfter: { folder: string; capabilities: string[] | null }[]`. `getSpecDetails` sets it for an active change when the list is not empty, next to the next step, and never for archived or rejected changes. `getSpecDetailsFromFolder` does not set it.
- [ ] The text output prints `Runs after: <entries>` right after `Depends on:`, only when `runsAfter` is set. Every other line of `osq show` and `osq show --json` stays byte for byte as it was, so no existing show test changes. `src/core/status/show-text.ts` stays at or under 250 lines.
- [ ] New `tests/show-runs-after.test.ts` proves every row of "Show a change that runs after another" and "Runs after in show JSON" in temporary git repositories, through the show command function with captured writers.
- [ ] Exported functions you add carry `@scenario status-inspection: <scenario name>` lines for the scenarios they serve.
