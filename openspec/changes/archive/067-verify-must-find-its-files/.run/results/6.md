## Changed

- `src/core/status/show.ts`: `formatPreSpawnVerify` now appends the missing-path
  suffix. A new `formatMissingPaths` helper renders `, missing <path>, <path>`
  from the latest pre-spawn event's `missingPaths` only when it is a non-empty
  array whose every entry is a non-empty string (trimmed, recorded order). An
  absent, empty, or malformed value returns null and the pre-spawn line is byte
  for byte what it was before.
- Added `tests/show-pre-spawn-missing.test.ts`. It scaffolds a change the way
  `tests/show-pre-spawn.test.ts` does and writes pre-spawn `verify_ran` events for
  three tasks: two missing paths, none, and a malformed (`[42]`) value. It
  asserts the exact line
  `      Pre-spawn verify: exit 0, expected red, matched, missing tests/a.test.ts, tests/b.test.ts`
  sits directly after the Verify line and that the other two tasks keep the
  unchanged line. A second case covers an explicit empty `missingPaths: []`.

## Missing context

- The task said a "malformed" `missingPaths` leaves the line unchanged but did
  not define malformed. I treated any array that is empty or holds a non-string
  or blank entry as malformed, matching how the pre-spawn report counts only a
  non-empty list.
