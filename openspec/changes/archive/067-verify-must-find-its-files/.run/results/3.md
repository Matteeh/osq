## Changed

- Added `src/watcher/archive-verify.ts`: `verifyArchiveStep` moved out of
  `archiver.ts`. Before running either a task or change-level command it resolves
  the command's named paths through `missingNamedPaths` in
  `src/core/spec/verify-paths.ts`. When any is missing it writes the regressed
  marker (`reason: verify_path_missing`, quoted command, one `- <path>` line per
  missing path), records the regressed event with reason `verify_path_missing`
  and the missing paths in `differingPaths`, and returns false without running
  the command. A command naming no missing path takes the unchanged
  `verify_red` path.
- `src/watcher/archiver.ts`: `checkAndArchiveSpec` imports `verifyArchiveStep`
  from the new module; the local function and the now-unused `outcome`/
  `verify` imports are gone. The file is 195 lines, down from 249.
- Added `tests/archive-verify-path-missing.test.ts`: a done change whose task
  verify names `tests/present.cjs`; deleting that file makes
  `checkAndArchiveSpec` regress the task with `verify_path_missing`, no
  `verify_ran` for the archive run, no `archived` event, and the folder active.
  The second case leaves every named path in place and archives as before.

## Deviated

- A `RegressedEventData` field for missing paths does not exist and
  `src/harness/types.ts` is outside this task's scope, so the event records the
  paths in the established `differingPaths` field rather than a new one.

## Missing context

- The exact archive-time regressed-event field for the missing paths. The task
  only says the event must carry the reason and the path; `differingPaths` was
  the existing typed list field available without touching an out-of-scope file.
