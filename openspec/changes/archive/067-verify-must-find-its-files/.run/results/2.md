## Changed

- Added `src/watcher/failure-reason.ts` holding `RunTaskFailureReason` with the
  new `verify_path_missing` member; `outcome.ts` now imports and re-exports the
  type, shrinking that module to 190 lines.
- `task-verify.ts`: `isPreSpawnMismatch` takes the pre-spawn `missingPaths`, so a
  `red` verify that passes only because a named path is absent is no mismatch.
  `runPreSpawnVerify` computes `missingNamedPaths` through
  `src/core/spec/verify-paths.ts` and adds `missingPaths` to the pre-spawn
  `verify_ran` data only when non-empty, leaving no-path events byte-identical.
  Added `formatMissingPathDeadMarker` and `checkMissingVerifyPaths`.
- `runner.ts`: after `ensureTaskResult` and before the task verify, `runTask`
  makes one call to `checkMissingVerifyPaths`; a missing named path dies with
  `verify_path_missing` and the verify never runs.
- `auto-retry.ts`: `verify_path_missing` joined `ELIGIBLE_AUTO_RETRY_REASONS`.
- `harness/types.ts`: `VerifyRanEventData` gained optional `missingPaths`.
- Added `tests/verify-path-missing.test.ts` covering the `runTask` death and
  done paths, the no-path case, the pre-spawn `missingPaths`/`mismatch: false`
  recording, and the watcher loop's single automatic retry whose next prompt
  names the missing path.

## Deviated

- Kept the `checkMissingVerifyPaths`/`if (missingPath)` lines adjacent with no
  blank line between them so `runner.ts` stays at 199 lines, under the strict
  200-line runner-lifecycle budget in `tests/import-graph.test.ts`.

Touched: src/watcher/failure-reason.ts, src/watcher/outcome.ts, src/watcher/task-verify.ts, src/watcher/runner.ts, src/watcher/auto-retry.ts, src/harness/types.ts, tests/verify-path-missing.test.ts
