## Changed

- `ApprovalFlagId` gained `verify_starts_conflict` after `unknown_capability`.
- `ApprovalFlagTask` now carries the parsed task's `verifyStarts` and declared
  `scope` entries alongside the resolved `paths`; `buildApprovalDigest` fills
  them from `parseTaskMd` through `ResolvedTask`.
- Added `src/core/spec/digest-verify-starts.ts`: it maps each contradiction from
  the shared `analyzeVerifyStarts` rule into one `verify_starts_conflict` flag
  labelled `verify starts conflict in task <n>`, with an excerpt naming the path
  and the declared start. `buildApprovalFlags` appends those flags after
  `unknown_capability`; `digest-flags.ts` is 236 lines.
- Added `tests/approval-digest-verify-starts.test.ts`: `green` and `any` tasks
  that name a test they create raise exactly one conflict flag, the flag is last
  after `unknown_capability`, `red` raises none, an earlier task's scope removes
  the flag whatever the later task declares, and `approveSpec` records the id in
  the manifest's `approvalFlags`.

Touched: src/core/spec/digest.ts, src/core/spec/digest-flags.ts, src/core/spec/digest-verify-starts.ts, tests/approval-digest-verify-starts.test.ts
