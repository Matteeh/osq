## Changed

- Added `src/core/report/report-pre-spawn.ts`: `observePreSpawnEvents` reads one
  task's parsed events and returns `missingPathRuns` (pre-spawn `verify_ran`
  events carrying a non-empty `missingPaths`) plus `byStart.red/green/any`, each
  `{ runs, passed }` where `passed` counts exactly `exitCode: 0`. Post-spawn
  runs, absent or unknown `expected` values, and empty missing-path lists are
  ignored.
- `report.ts` sums those counts over every discovered task stream (next to the
  existing pre-spawn observation, so `report-events.ts` stays untouched),
  extends `PreSpawnVerifyHistory` with `missingPathRuns` and `byStart`, and adds
  the `Pre-spawn verify with missing paths:` and `Pre-spawn verify by declared
  start:` text lines after the unchanged mismatches line.
- `src/cli/report.ts` carries `missingPathRuns` and `byStart` through
  `toStableMetrics`.
- `approval-flags.ts` gains `verify_starts_conflict` in `FLAG_IDS` after
  `unknown_capability`, so the text section and stable JSON report it like every
  other flag.
- Regenerated `fixture/report/expected.json` from the real report command; the
  only diff is the new `preSpawnVerify` keys and the new `byFlag` key.
- Updated `tests/report-json.test.ts` and `tests/report-approval-flags.test.ts`
  for the new keys and flag id, and added
  `tests/report-pre-spawn-starts.test.ts`, which writes pre-spawn events for
  each declared start with passing/failing exit codes and a missing path, asserts
  the JSON counts and both text lines, and asserts a change recording
  `verify_starts_conflict` appears under that flag.
