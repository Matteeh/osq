## Acceptance

- [ ] After `ensureTaskResult` and before the task verify runs, `runTask` makes one short call into `task-verify.ts`. When any path the task verify names is missing (through `src/core/spec/verify-paths.ts`), the task dies with `verify_path_missing` and the verify command does not run.
- [ ] The dead marker's frontmatter has `reason: verify_path_missing` and the quoted `command`. Its body says the verify names paths that do not exist and lists each missing path on its own `- <path>` line.
- [ ] `RunTaskFailureReason` moves to new `src/watcher/failure-reason.ts` with `verify_path_missing` added, and `outcome.ts` re-exports it. `runner.ts` and `outcome.ts` stay under 200 lines.
- [ ] `verify_path_missing` joins `ELIGIBLE_AUTO_RETRY_REASONS`.
- [ ] The pre-spawn `verify_ran` event records `missingPaths`, the named paths absent before spawn, only when at least one is missing, so events for commands naming no missing path are byte-identical to today. When `red` is expected and `missingPaths` is not empty, a passing verify is not a mismatch. `VerifyRanEventData` gains optional `missingPaths`.
- [ ] New `tests/verify-path-missing.test.ts` drives `runTask` on a temp project the way `tests/pre-spawn-verify.test.ts` does. A verify naming one existing test and one missing test, whose command alone exits 0, with an agent that writes only the result file, dies with `verify_path_missing` and a marker listing the missing file. With an agent that also writes the file, the task reaches done. A verify naming no paths behaves as today.
- [ ] The same file drives the watcher loop the way `tests/auto-retry.test.ts` does. It asserts that a `verify_path_missing` death is retried automatically once and that the retry's prompt contains the missing path. It also asserts that a pre-spawn run with a missing named file and a passing command records `missingPaths` and `mismatch: false`.

## Details

Extend `isPreSpawnMismatch` with the missing paths rather than changing its
existing callers' results. `formatPreSpawnDeadMarker` and `verifyRedFailure` stay
as they are. A fake agent that writes extra files can be a test-local subclass of
`MockAdapter` whose `spawn` writes the file and then calls the parent. The retry
prompt already carries the previous dead marker's body since 065, so the marker
text is what the next attempt reads. `tests/pre-spawn-verify.test.ts` and
`tests/auto-retry.test.ts` stay frozen and green. The golden fixtures under
`tests/fixtures/events/` hold pre-spawn events for commands that name no paths,
so they do not change and `tests/golden-events.test.ts` stays green.
