## Acceptance

- [ ] New `src/core/spec/verify-paths.ts` holds `tokenizeVerifyCommand` and the operand rules moved from `linter.ts`. It exports the tokenizer, a function listing a command's named paths, and an async function returning the named paths missing under a project root. Named paths are operands that are not options, absolute, `=` assignments, URLs, or a bare first token, and that contain `/` or `\`. A glob operand is present when `resolveScope` matches at least one file for it.
- [ ] `linter.ts` imports the tokenizer and operand rules from `verify-paths.ts` and keeps no copy. Its existing verify errors and warnings behave as before, except as the acceptance lines below change them, and the file ends shorter than its current 1,108 lines.
- [ ] `scope.ts` exports a function that reports whether a list of declared scope entries covers a project-relative path: equal to an exact entry, or matched by a glob or trailing-directory entry through the existing `globToRegExp`.
- [ ] New `src/core/spec/verify-starts.ts` takes the project root and the tasks in numeric order, each with its number, verify, `verifyStarts`, and declared scope. It returns contradictions (task, path, declared start) and uncreatable paths (task, path). A missing path covered by an earlier task's scope yields neither. Otherwise it is a contradiction when the task's own scope covers it and the task declares `green` or `any`, and uncreatable when no scope up to this task covers it. A glob operand is covered only by an identical scope entry.
- [ ] `osq lint` warns once per contradiction, naming the task file, the path, and the declared start, and once per uncreatable path, saying no task in the change can create it. The existing unresolved-target warning does not fire when every missing named path is covered by the task's own or an earlier task's scope.
- [ ] New `tests/verify-paths.test.ts` covers quoted operands, `--import tsx`, `KEY=value`, URLs, a bare first token, `pnpm verify` (no paths), a path-shaped first token, and a glob operand that matches no file (missing).
- [ ] New `tests/lint-verify-starts.test.ts` lints fixture changes in a temp project and asserts that a 066-shaped task with `any` or `green` gets the contradiction warning, the same task with `red` gets none, a path an earlier task's scope covers gets neither whatever the start, a path outside every scope gets the uncreatable warning, and a task naming only its own new test gets no unresolved-target warning.

## Details

Collect every task's parse result first, then run the shared rule once after the
task loop, next to `collectOverlapWarnings`. Existing tests in
`tests/linter.test.ts` stay frozen and green. The fixture shape for a
contradiction is 066: a verify naming a new test next to an existing one, the new
test inside the task's scope, and `verify_starts: any`. Build test projects the
way `tests/linter.test.ts` does, with its fake validator helper.
