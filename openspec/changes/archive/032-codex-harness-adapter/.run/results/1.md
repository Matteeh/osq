# Task 1 result: Codex harness adapter

## Changed

Codex is now a registered, first-class harness covering configuration, setup,
diagnostics, verified execution, interactive planning, stream translation, and
attribution.

### Configuration (`src/core/config-codex.ts`, `src/core/config.ts`, `src/index.ts`)
- Added `CodexConfig` (`bin`/`model`/`effort`, all optional non-empty strings),
  exported from `src/core/config.ts` and `src/index.ts`.
- `defineConfig` validates Codex settings and merges them; `loadConfig` applies
  `OSQ_MODEL` to `codex.model` only when Codex is the executor.
- Planner validation accepts `codex`, still requires `planner.model`, and
  rejects `planner.agent` with a clear unsupported-setting error. Moved
  `validatePlannerConfig` into `config-codex.ts` (re-imported by `config.ts`) to
  stay inside the 250-line source budget.
- `timeouts.harnessPreflightSeconds` (default 10) and
  `timeouts.harnessKillGracePeriodMs` (default 5000) added as optional fields so
  legacy timeout object literals still type-check.
- Shared helpers: `resolveCodexBinary` (`codex.bin` -> `CODEX_PATH` -> `codex`),
  `resolveCodexModel` (`codex.model` -> `OSQ_MODEL` only for a Codex executor ->
  undefined native default), `resolveCodexEffort`, `resolveHarnessModel`,
  `resolveHarnessEffort`, `resolveAdapterModel`, `resolvePlannerSelection`.

### Diagnostics (`src/core/config-doctor.ts`, `src/core/doctor.ts`)
- Doctor resolves the Codex binary through the same `resolveCodexBinary` helper
  as the adapter and probes it with `--version` under the configured preflight
  deadline. Added `config-doctor.ts` (within the `config*.ts` scope) to hold
  `harnessBinary`/`probeVersion`, which keeps `doctor.ts` at 232 lines without
  changing its behavior.

### Watcher (`src/watcher/loop.ts`, `src/watcher/spawn.ts`)
- Watcher startup invokes the adapter's optional `preflight` port for Codex as
  well as OpenCode, retaining the legacy `preflightOpencode` fallback and the
  "mock never preflights" behavior.
- Started-event model attribution uses `resolveAdapterModel`, so Codex records
  its configured model or the `default` sentinel instead of borrowing agy/OpenCode.

### Manifest (`src/core/manifest.ts`)
- Manifest model for a Codex harness is `codex.model`, `OSQ_MODEL` for a Codex
  executor, or `default`; `effort` records the configured Codex effort or null.

### Adapter (`src/harness/codex.ts`, `src/harness/codex-prompt.ts`, `src/harness/codex-stream.ts`, `src/harness/index.ts`)
- `CodexAdapter` implements the existing ports only (no new methods). Setup is a
  no-op; preflight reuses `spawnWithTimeout` with configured deadlines.
- Exec argv: `--ask-for-approval never exec --json --sandbox workspace-write`,
  `-c web_search="disabled"`, `-c sandbox_workspace_write.network_access=false`,
  optional `--model`/`model_reasoning_effort="..."`, and the prompt as one
  literal argument. No `--auto`, `--file`, `--agent`, or resume flags.
- The prompt resolves task/proposal/prior-result/result-destination/delta/living
  capability paths, scope, entry, verify command, capability rules, and the
  one-attempt procedure.
- `codex-stream.ts` translates only `item.completed` text/tool/file_change
  observations plus `turn.completed` usage, relativizes paths, never treats
  reasoning as text, never re-emits file changes as edit/write tools, tolerates
  malformed/unknown records, flushes the final unterminated record, omits absent
  optional usage counters and cost, and raises a terminal `turn.failed`.
- `spawnInteractive` launches the TUI with inherited stdio, project cwd,
  `--ask-for-approval on-request --sandbox workspace-write`, optional planner
  model, native effort defaults, and rejects an unsupported `agent`.

### Planning (`src/cli/plan.ts`)
- `resolvePlannerSelection` (in `config-codex.ts`) drives both brief metadata and
  the interactive invocation. Explicit `planner.model` wins and never inherits
  executor `OSQ_MODEL`/effort; a Codex fallback writes `default` in the brief but
  omits the CLI model flag; explicit Codex planners never receive an agent.

### Tests (`tests/codex/**`)
- `fake-codex.mjs` (executable) plus three JSONL fixtures.
- `config.test.ts`, `stream.test.ts`, `adapter.test.ts`, `watcher.test.ts`,
  `plan.test.ts` cover every acceptance line, including real `setupCommand`,
  `doctorCommand`/`runDoctorChecks`, `startWatcher`, `runTask`, `buildManifest`,
  `planCommand`, and `reportCommand` entry points.

## Deviated

- Added `src/core/config-doctor.ts` (allowed by the `src/core/config*.ts` scope)
  rather than growing `doctor.ts`, which would otherwise exceed the frozen
  250-line budget. It only hosts the harness-binary resolution and version probe.
- `probeVersion`'s optional timeout unit is seconds (converted internally) so the
  doctor callsite could stay within the line budget while using the configured
  preflight value.
