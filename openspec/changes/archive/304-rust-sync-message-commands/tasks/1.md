## Details

Keep `feature.rs` a dispatcher on `invocation.command`, and put each
command in its own module under `src/land/`, such as `sync_command.rs` and
`message_command.rs`, reusing `land.rs`'s `git_vcs`, `worktree_changes`,
`land_default_branch` and `change_archive`, `find::matches_folder`, and
`message::format` with `read_land_facts`. `land.rs`'s `run_land` and its
refusals do not change.

`sync::run` today fails with the command `land` and always writes the
land stop record through `Sync::finish`. Give it what the caller needs,
such as the command name for its errors and whether a stop is recorded,
so `land` passes `land` and recording and `sync` passes `sync` and no
recording. The existing `land_sync.rs` tests, including "A code conflict
is recorded", must keep passing unchanged.

Build each golden row's repository exactly as the script's comment and
cases say: the fixture change or the alpha change, the commit messages
`initial`, `work on <folder>` and the `main` commits it names, and
`osq.toml` with `[vcs]\nenabled = false\n` for the `vcs-off` rows. Add any
helper the rows need to `tests/support/mod.rs`; keep every existing helper
as it is. Replace `<wt>` in a golden with the worktree's path and `<head>`
with the branch tip before the run. Compare `tip` with
`git log -1 --format=%B osq/<folder>`, which ends with an extra newline.

No new dependency is needed, so `Cargo.lock` does not change. When the
mutation check reports a missed mutant, add a test case for that line
rather than keeping a branch no test reaches; take its expected value from
`sync-change.ts`, `squash-message.ts` or a golden. Run the proposal's
verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/304-rust-sync-message-commands`, so the link
gates see this change's requirements.
