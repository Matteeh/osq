## Acceptance

- [ ] `src/watcher/build.ts` exports `findStaleBuild`, which does what `checkStaleBuild` checks today (same skips, same `allowStale` and `packageRoot` options) but returns the stale line or null without printing or exiting. It takes an optional newest `dist/` mtime to compare against instead of walking `dist/`. It also exports `STALE_BUILD_MESSAGE` (the existing line, byte for byte), `StaleBuildError` (an `Error` whose message is that line), a function that returns the newest `dist/` mtime for a package root, and `osqPackageRoot()`, which returns the existing `PACKAGE_ROOT`. `checkStaleBuild` prints and exits only through `findStaleBuild`, and `tests/watcher-stale-preflight.test.ts` passes unchanged.
- [ ] `runWatcherCycle` and `runWatcherOnce` take an optional fifth argument with an optional stale check, a function that resolves to the stale line or null. When the check returns a line, the cycle throws `StaleBuildError` at the top of the pending-task branch, before `checkSync`, the scope audit, and `runTask`, and at the top of `archiveCompletedSpec`, before `readHumanSteps` and `checkWorktree`. The per-change `catch` rethrows a `StaleBuildError` instead of calling `logWatcherError`. With no check, a cycle behaves as today.
- [ ] `startWatcher`, unless `allowStale` or `dev` is set, runs the start check through `findStaleBuild`, then reads the newest `dist/` mtime once and passes each cycle a check that calls `findStaleBuild` with that mtime. `StartWatcherOptions` gains optional `packageRoot`, passed to both checks, and `exit`, defaulting to `process.exit`. When the start check finds the build stale, or a cycle throws `StaleBuildError`, in `once` mode or from `cycleHandler`, it stops the loop, clears the status line, prints the stale line with `console.error`, calls `exit(1)`, and returns without running another cycle.
- [ ] New `tests/watcher-stale-every-pass.test.ts` covers the watcher-and-harness delta's "Source edited while a task runs" and "Allow stale during a run" through `startWatcher` with `once: true`, a temporary `packageRoot` laid out as in `tests/watcher-stale-preflight.test.ts`, an injected `exit`, and a fake adapter whose `spawn` moves a file's mtime under that `src/` past `dist/` with `fs.utimes`. It covers "Stale before the first spawn" through `runWatcherCycle` with an injected check, and "Rebuilt without restart" through `findStaleBuild` with the start-time mtime.
- [ ] Every new function stays within 80 lines, and `src/watcher/build.ts` and any new module stay within 250 lines. Put new helpers in `src/watcher/stale-pass.ts` rather than growing `runWatcherCycle` or `startWatcher` by more than a few lines each.

## Details

Stale file times are set with `fs.utimes` to fixed dates, as
`tests/watcher-stale-preflight.test.ts` does, never by waiting. A change
fixture and a fake adapter that writes the result file can follow
`tests/watcher-loop-logging.test.ts` or `tests/watcher-preflight.test.ts`.
Capture `console.error` around the call and restore it after. The running
test is TypeScript source, so pass `packageRoot` every time; without it the
check skips.
