## Changed

- `src/watcher/build.ts` now exports `STALE_BUILD_MESSAGE`, `StaleBuildError`,
  `FindStaleBuildOptions`, `findStaleBuild`, `newestDistMtimeMs`, and
  `osqPackageRoot`. `findStaleBuild` carries the old `checkStaleBuild` skips
  (`allowStale`, no `src/`, run from source) and accepts an optional
  `distMtimeMs` so an in-run pass compares against the `dist/` read at start.
  `checkStaleBuild` is now only a print-and-exit wrapper around it.
- New `src/watcher/stale-pass.ts` holds the small helpers: `StaleCheck`,
  `assertNotStale`, `startStaleCheck`, and `handleStaleBuild`.
- `src/watcher/loop.ts`: `runWatcherCycle` and `runWatcherOnce` take an
  optional fifth `StaleCheck` argument and throw `StaleBuildError` at the top
  of the pending-task branch (before `checkSync`, the scope audit, and
  `runTask`) and at the top of `archiveCompletedSpec` (before `readHumanSteps`
  and `checkWorktree`). The per-change catch rethrows it instead of logging a
  `watcher error`. `startWatcher` builds the check through `startStaleCheck`
  unless `allowStale`/`dev` is set, and on a `StaleBuildError` from the start
  check, `once` mode, or `cycleHandler`, it stops the loop, clears status,
  prints the line with `console.error`, calls the injectable `exit` (default
  `process.exit`) with `1`, and returns. `StartWatcherOptions` gained
  `packageRoot` and `exit`.
- New `tests/watcher-stale-every-pass.test.ts` covers the four delta
  scenarios: source edited while task 1 runs, allow-stale during a run, stale
  before the first spawn, and rebuilt without restart.

## Deviated

- The task and delta spec say the source-edited scenario leaves
  `.run/done/1.md`. The watcher actually writes `.run/done/1` (no extension);
  `writeDoneMarker` in `src/watcher/outcome.ts` and every existing test use
  that path. The new test asserts `.run/done/1`, and the spec wording is the
  only thing out of step. No marker-naming code was touched.
- The task did not name the newest-`dist/`-mtime helper; it is
  `newestDistMtimeMs`.
- `newestDistMtimeMs` walks `dist/` even when the start check was skipped for
  a source run with no explicit root; the resulting check always returns null
  in that case, so the only cost is a harmless walk.
