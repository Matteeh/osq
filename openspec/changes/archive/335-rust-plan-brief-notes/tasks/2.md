## Acceptance

- [ ] A name with `--brief` runs a new `run_new` that follows rust-plan "Plan from a brief" step by step and writes `brief.md` as "Brief file text" says, with `--print` behaving as "Plan print" says.
- [ ] New `tests/fixtures/brief-created/` holds byte-for-byte copies of `brief-in.md`, `handoff.txt`, `print.txt` and the folder `005-add-dark-mode/` from `openspec/changes/335-rust-plan-brief-notes/golden/`, with `tasks-md.txt` renamed to `tasks.md`; never edit or regenerate them.
- [ ] New `tests/plan_brief.rs` proves "Golden brief change", "Brief refusals", "Brief name of an active change" and "Brief change names", new `tests/plan_brief_stdin.rs` proves "Brief from standard input", and new `tests/plan_brief_texts.rs` proves "Brief texts", every row checked, each test's doc naming `Covers: rust-plan/<scenario>`, each scratch root a new folder under `CARGO_TARGET_TMPDIR` named after the test and row.

## Details

- Reuse `number::next` for the change number, the `PROPOSAL`, `TASKS_MD` and `TASK_1_MD` texts in `next/files.rs`, `opening_prompt`, `sections` and `handoff::format` from `next.rs`, and `lookup::candidates` and `matches` from `steer/lookup.rs`.
- `parse_frontmatter` gives a `yaml_rust2` hash, so add `yaml-rust2.workspace = true` to the crate's `Cargo.toml` to read its values; never scope or edit the root `Cargo.lock`, which follows the manifest.
- The standard input test cannot feed the test process's own standard input, so it runs its own test binary, `std::env::current_exe()`, again with `--exact <a child test name> --nocapture`, an environment variable the child test checks, and the brief piped into the child's standard input. The child test does nothing when the variable is not set, and the parent compares the folder the child wrote. Mark no test `#[ignore]`.
- The git row of "Brief refusals" runs `git` with `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME` and `GIT_COMMITTER_EMAIL` set, so it does not depend on the machine's git identity.
