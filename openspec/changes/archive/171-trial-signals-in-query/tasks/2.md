## Acceptance

- [ ] `LintResult` gains optional `traceability: LintFinding[]`. `lintChangeFolder` keeps the list `collectTraceabilityFindings` returns, still adds each one to the own findings as today, and returns the list. Every other `LintResult` field and the `osq lint` text and `--json` output stay exactly as they are.
- [ ] `recordPlanReady` takes the lint result's traceability findings as an optional argument, and `lintCommand` passes them. The `plan_ready` record's data gains `traceability` only when the list is not empty, as spec-lint-and-approve "Traceability findings in plan ready records" says.
- [ ] `PlanReadyRecord`'s data gains optional `traceability: { severity, file, message }[]`. `readPlanReady` returns it only when the line has the key, leaving out malformed entries, so every existing reader and test of `readPlanReady` sees the same objects as before.
- [ ] New `tests/plan-ready-traceability.test.ts` proves the three scenarios through `lintCommand` with captured writers in a temporary project, setting up traceability as `tests/trace-lint.test.ts` does, and through `readPlanReady` on hand-written `plan.jsonl` lines.
- [ ] Exported functions you add or change carry `@scenario spec-lint-and-approve: <scenario name>` lines for the scenarios they serve.

- spec-lint-and-approve: No link findings
