## Changed

- `src/core/spec/linter.ts`: `LintResult` gains optional `traceability: LintFinding[]`; `lintChangeFolder` keeps the list `collectTraceabilityFindings` returns, still adds each finding to the change's own findings, and returns the list on the result (the two early returns stay without it).
- `src/core/spec/plan-ready.ts`: `PlanReadyRecord.data` is now the `PlanReadyData` interface with an optional `traceability: PlanReadyTraceabilityEntry[]`; `parsePlanReady` returns `traceability` only when `data.traceability` is an array, dropping entries missing any string `severity`, `file` or `message`; `appendPlanReady` takes the entries and omits the key when the list is empty.
- `src/core/spec/plan-ready-record.ts`: `recordPlanReady` takes the lint result's findings as an optional fourth argument and writes `{severity, file, message}` per finding, so an empty or missing list leaves the record with exactly `hash` and `notices`.
- `src/cli/lint.ts`: passes `result.traceability` to `recordPlanReady`.
- `tests/plan-ready-traceability.test.ts` (new): proves the three spec-lint-and-approve scenarios — the appended `plan_ready` record carries the `widgets` link finding while `--json` keeps its old document and still lists the warning in `findings`, a change with no capability opted in records only `hash` and `notices`, and `readPlanReady` reads a valid entry while leaving out one without `message` and keeps a record without the key unchanged.

## Deviated

- `appendPlanReady`'s new `traceability` argument was inserted before the existing `now` argument rather than after it, so the call reads `(folderPath, hash, notices, traceability, now)`. No existing caller passes `now`, and every existing caller passes three arguments.

Touched: src/core/spec/plan-ready.ts, src/core/spec/plan-ready-record.ts, src/core/spec/linter.ts, src/cli/lint.ts, tests/plan-ready-traceability.test.ts
