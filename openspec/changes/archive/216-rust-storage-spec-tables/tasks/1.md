## Details

Put the code in a new module `src/owners/`, with the glob matcher and the
ownership reader in separate files. Reuse `code_ownership` from
`src/markdown/ownership.rs` for a spec's globs; don't parse the source
comment again. "Trimmed" means whitespace at both ends as JavaScript's
`trim` does; reuse `js_trim`.

Write the glob matcher by hand, as a recursive or backtracking match over
the pattern and the path, and add no regex or glob crate. The rules in
"Scope globs" are TypeScript's `globToRegExp` in `src/core/run/scope.ts`
written out, so the table is the source of truth. In the table, `␠` stands
for one space, so that row's scope is `  src/a.ts  `, and `src\a.ts` holds
one backslash.

`read_capability_ownership` lists `specs_dir` with `std::fs::read_dir`,
keeps directories only, and sorts their names by bytes. A `spec.md` that is
missing, unreadable or not UTF-8 adds nothing; nothing in this function
fails.

The fixture is the source of truth. Copy it, and never edit it. Tests find
it from `env!("CARGO_MANIFEST_DIR")`. More test files are allowed when they
match `tests/owners*.rs`.

Keep every `.rs` file under 250 lines and every function under 80.
Workspace lints include `clippy::pedantic` and `-D warnings`; meet them
rather than allowing them. Keep tests in `tests/`. When the mutation step
reports a missed mutant, add a case for it. Run `cargo fmt --all` before
exiting.
