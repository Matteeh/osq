## Details

Task 2 gave the snapshot `deltas`, `verify`, and each task's `plan` and
`outcome`. Map them to rows in new files under `src/model/`, beside
`file_rows.rs` and `insert_files.rs`, and keep `mod.rs` to the table
statements and the calls. `mod.rs` is near 190 lines.

Use rust-specs `owner_capabilities` for the `capability` column; don't
match globs in storage. Count each capability over the task's
`scope_hash_paths`, then pick the highest count, the first name by bytes on
a tie.

`verify_kind` splits on whitespace as JavaScript's `\s` matches it:
`char::is_whitespace` without U+0085, plus U+FEFF. Write the split and the
`.test.` / `.spec.` check by hand; add no regex crate. Compare the plan's
`verify` with the snapshot's `verify` as both are already trimmed.

`dead_reason` comes from the snapshot's dead attempts, which
`EventFacts.dead_attempts` already holds in task and file order. `attempts`
is the task's `started` count, which `TaskFile.started` already holds.

Bind every value with `rusqlite` parameters: text and null as written,
numbers as integers. The JSON rows were printed by TypeScript and are the
expected values; when a row disagrees, the Rust mapping is wrong, and the
fixture files under `spec-tables/` and `spec-tables-rows/` stay as task 2
copied them. Put the extra cases' change folders in a new fixture project
under `tests/fixtures/spec-tables-cases/`, found from
`env!("CARGO_MANIFEST_DIR")`. Shared helpers cannot be imported across test
files, so write the small JSON comparison again in this file. More test
files are allowed when they match `tests/read_model_specs*.rs`.

Keep every `.rs` file under 250 lines and every function under 80.
Workspace lints include `clippy::pedantic` and `-D warnings`; meet them
rather than allowing them. Keep tests in `tests/`. When the mutation step
reports a missed mutant, add a case for it. Run `cargo fmt --all` before
exiting.
