## Details

Types, all public with public fields, deriving `Clone`, `Debug`,
`PartialEq` and `Eq`:

- `CapabilityDelta { capability: String, delta: osq_kernel_specs::Delta }`.
- `TaskOutcomeFacts { start_scope_files: Option<u64>, scope_hash_paths: Option<Vec<String>>, changed_files: Option<u64>, first_attempt_passed: bool }`, also deriving `Default`, which is the facts of a task without a stream.

Add `StorageError::Specs(osq_kernel_specs::SpecsError)`. Its message is the
specs kernel's message, which already names the file, and its `source` is
that error. Keep the existing variants as they are.

Use the specs kernel's `read_delta`, `read_task_file` and `read_proposal`;
don't parse frontmatter or Markdown in storage for these fields. Storage's
own task title and proposal readings stay as they are, because the other
14 tables use them. `read_task_files` in `src/read/snapshot/folder.rs` may
become fallible to carry the plan; `read_change` already returns a
`Result`.

Gather the outcome facts while the task streams are read, from the typed
`osq_core::Event` values: `Event::Measures` with its `phase`,
`scope_files`, `changed_files` and `scope_hashes`, and `Event::Started`,
`Event::Done`, `Event::Dead` and `Event::Regressed` for the first attempt.
Only `phase` values `start` and `end` count. `scope_hashes` is a
`serde_json::Value`; only a `Value::Object` gives paths. A task's facts
come from its own `<n>.jsonl` only. Write them in a new file under
`src/read/snapshot/`: `snapshot.rs` is near 200 lines and
`snapshot/events.rs` is over 200, so add only fields and calls to them.

For "Refused task file", write a change folder with only that
`tasks/1.md` and a valid `proposal.md` under `env!("CARGO_TARGET_TMPDIR")`,
and build its `ChangeEntry` by hand.

The fixtures and their expected rows are the source of truth. Copy them, and
never edit them. TypeScript's `osq query --json` printed the files under
`spec-tables-rows/` for the `spec-tables/` project, and task 3 reads them.
Tests find the fixtures from `env!("CARGO_MANIFEST_DIR")`. More test files
are allowed when they match `tests/reading_specs*.rs`.

Keep every `.rs` file under 250 lines and every function under 80.
Workspace lints include `clippy::pedantic` and `-D warnings`; meet them
rather than allowing them. Keep tests in `tests/`. When the mutation step
reports a missed mutant, add a case for it. Run `cargo fmt --all` before
exiting.
