## Changed

- `src/core/foundation/package-root.ts`: added `PACKAGE_ENTRY`, the running
  osq's extensionless `index` one level above `core/` (`src/index` under
  `tsx`, `dist/index` once built), derived from `import.meta.url`.
- `src/core/foundation/config-file.ts` (new): `ConfigLoadError` plus
  `loadConfigFile`, which walks `osq.config.ts`/`.js`/`.mjs`, imports the first
  existing file through jiti with
  `alias: { '@matteeh/osq': PACKAGE_ENTRY }`, and rejects with
  `Failed to load <absolute path>: <original message>` on a failed import. The
  `DEBUG_OSQ` fallback is gone. Returns the user config and its file path.
- `src/core/foundation/config.ts`: `loadConfig` now calls `loadConfigFile` and
  re-exports `ConfigLoadError`; removed the try/catch import loop, `fs`, and
  `createJiti`. The loader's own `defineConfig` call is wrapped so a raw config
  object that fails validation also rejects with a `ConfigLoadError` naming the
  file. No config file still yields `DEFAULT_CONFIG` merged with the environment.
- `tests/config-load-errors.test.ts` (new): covers validation failure, import
  failure, the scaffolded config in a project with no `node_modules`, doctor's
  `config` check through `runDoctorChecks`, and the empty-project defaults.

`pnpm verify` passes (typechecks, build, full suite, lint). The three test files
that previously relied on the silent fallback plus `tests/package-root.test.ts`
pass unchanged.

## Deviated

The delta says a config file that "fails to import or validate" must reject with
a `ConfigLoadError`. The task's validation scenario validates inside the config
file's own `defineConfig` call, which the jiti import surfaces. I also wrapped
`loadConfig`'s final `defineConfig` call, so a config that exports a raw object
failing validation (e.g. `export default { vcs: { author: 'osq' } }`) rejects
with the same `Failed to load <path>: <message>` shape instead of a bare error.

Touched: src/core/foundation/config.ts, src/core/foundation/config-file.ts, src/core/foundation/package-root.ts, tests/config-load-errors.test.ts
