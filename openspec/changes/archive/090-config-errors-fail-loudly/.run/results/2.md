## Changed

- `src/cli/run.ts` (new): exports `runCli(argv)`, builds the program with
  `createProgram(resolvePackageVersion())` and awaits `parseAsync(argv)`. A
  rejected `ConfigLoadError` prints `Error: <message>` to stderr, calls
  `process.exit(1)`, and returns without a stack trace; every other error is
  rethrown. The explicit `return` after `process.exit(1)` is needed because the
  test stubs `process.exit`, which then returns instead of terminating.
- `src/cli/bin.ts`: now only `await runCli(process.argv)` after the shebang.
- `src/cli/init.ts`: `initCommand` calls `loadConfig(cwd)` directly and no
  longer falls back to `DEFAULT_CONFIG`, so a broken config aborts before
  `scaffoldProject` runs.
- `tests/cli-config-errors.test.ts` (new): runs `runCli` with `process.chdir`,
  stubbed `process.exit` and `console.error` (all restored in `finally`).
  Covers `status` and `init` with the `defineConfig({ vcs: { author: 'osq' } })`
  broken config (asserting `Error: Failed to load <file>: ...`, exit 1, and no
  `openspec/` for init), plus a `lint 999` action that throws a
  non-`ConfigLoadError` and still rejects `runCli`.

`node --import tsx --test tests/cli-config-errors.test.ts` passes, and
`pnpm verify` (typechecks, build, full suite, lint) passes.

Touched: src/cli/run.ts, src/cli/bin.ts, src/cli/init.ts, tests/cli-config-errors.test.ts
