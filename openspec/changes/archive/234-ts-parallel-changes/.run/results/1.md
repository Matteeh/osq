## Changed

- Added `ChangeLanes` in `src/watcher/lanes.ts`: lanes keyed by change folder path, cap waiting, wait-all, drained outcomes, first kept error, and `close`/spawn tracking so a stop starts no task that had not spawned yet.
- Moved the lane body to `src/watcher/change-lane.ts`: scope audit with `formatScopeRegressionLine`, task, mutation check, verified/dead commit, pause discard, halted line, and archive. A lane logs `watcher error: …` itself and rethrows `StaleBuildError`.
- Moved `archiveCompletedSpec`, `extractHumanSteps` and `readHumanSteps` to `src/watcher/archive-change.ts`; `loop.ts` re-exports `extractHumanSteps` and the cycle's `done` archive uses the same function.
- Split `runWatcherCycle` into `advanceChange`/`reconcileChange`/`startNextTask`/`runActiveChanges` and added its optional `ChangeLanes` parameter. Without it the cycle owns lanes and waits them; with it the cycle skips a running change, keeps counting it as approved waiting, and does not wait.
- Changes in a stacked tree now start no task; they wait for `runStackedChanges` to cut them.
- `startWatcher` makes one `ChangeLanes` for every continuous cycle, closes lanes on abort/SIGINT/build stop, keeps the SIGINT listener until lanes finish, and waits for lanes before handling a `StaleBuildError` or before the signal-driven promise resolves.
- Added `tests/watcher-parallel-changes.test.ts` proving all eight scenarios, and removed `watcher/loop.ts#runWatcherCycle` from the function-budget grandfather list now that it is under 80 lines.

## Deviated

- The fake adapter uses an optional gate for the build-check and abort scenarios so a lane can be held while the watcher stops. The other scenarios use its peer-or-short-wait hold as the task describes.
- To make "no task spawns after the check threw" deterministic, continuous build checks run only once every running lane has already reached its adapter spawn, and a lane checks `lanes.isClosed()` after its audit and before `runTask`. This is intentionally conservative: a build change is still seen while tasks run, but never during a lane's pre-spawn audit.
