## Details

Build projects the way `tests/vcs-land.test.ts` does: a real temporary
repository, changes approved into worktrees with `approveSpec`, and
`runWatcherOnce` with an adapter that edits files in scope. Proposals use a
local `node verify.cjs` verifier that exits by a file the test controls.

For "Default branch moves during the land", first commit an unrelated file on
`main` so the sync merges. Then land with a config whose `vcs.prepare` is
`git -C <checkout> commit --allow-empty -qm moved`. The sync runs `prepare` in
the worktree after its merge, so `main` moves before land compares it with the
branch tip.

For "No verify without a merge", make `verify.cjs` exit 1 after the change
archives, and land without moving `main`.

For "Uncommitted file the change writes", edit in the checkout a tracked file
that the change's task also edits, and leave it unstaged.

The sync's events are written after its `verify` passes and before its commit.
A later stop aborts the merge, and `git merge --abort` drops the staged events
with the rest, so every stop still leaves the worktree's status empty, as
`tests/vcs-sync.test.ts` checks.
