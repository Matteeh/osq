## Acceptance

- [ ] New `src/watcher/archive-specs.ts` exports `applyArchiveSpecs(projectRoot, specFolderPath, config)` and `restoreArchiveSpecs(projectRoot, specFolderPath)`. `applyArchiveSpecs` writes `.run/archive-specs.json` as the watcher-and-harness delta's modified "Archive-time verification re-run" says, then calls `applyOpenSpecDeltas` and `applyArchiveSidecars`. `restoreArchiveSpecs` puts the recorded files back, removes a capability folder left empty, deletes the record, and resolves to whether a record existed; without one it changes nothing.
- [ ] The record is a JSON object that maps each path, relative to the project root with `/` separators, to the file's content or `null` when the file was absent. It lists `spec.md` and `osq.yml` under `<openspecRoot>/specs/<capability>/` for every capability folder under the change's `specs/`.
- [ ] `checkAndArchiveSpec` calls `restoreArchiveSpecs` before anything else, keeps the done check, the scope audit, and every task verify as they are, then calls `applyArchiveSpecs`, then runs the change-level verify through `verifyArchiveStep` unchanged. When that returns false it calls `restoreArchiveSpecs` and returns false. When it passes, the change archives without applying the deltas a second time, and the record is deleted before the folder moves, so the archive never holds it.
- [ ] `archiveSpecFolder` keeps its signature and still applies the deltas and sidecars when called on its own, so `tests/archiver.test.ts`, `tests/archive-sidecars.test.ts`, `tests/living-specs-delta-equivalence.test.ts`, `tests/verification-record.test.ts`, and `tests/osq-change-env.test.ts` pass unchanged.
- [ ] In `src/watcher/loop.ts`, the archive step inside `runWatcherCycle` calls `restoreArchiveSpecs(change.tree.root, change.folderPath)` before `checkWorktree`. Nothing else in `loop.ts` changes.
- [ ] Every function stays within 80 lines and every file other than `loop.ts` within 250. `tests/archive-verification.test.ts`, `tests/archive-verify-path-missing.test.ts`, `tests/plan-prompt-lifecycle.test.ts`, `tests/worktree-run.test.ts`, and every other existing test pass unchanged.
- [ ] New `tests/archive-specs-verify.test.ts` covers the scenarios the delta adds, "Change-level verification regression blocks archive", and "Archive succeeds with a prompt file" for the record.

## Details

Build projects as `tests/archive-verification.test.ts` does, and give the
change a local `node verify.cjs` verifier that exits by a file the test
controls. For "Change verify sees the merged specs", let `verify.cjs` read the
living spec and exit 1 unless it holds the added requirement's heading.

For "Interrupted archive", call `applyArchiveSpecs` on a done change by hand
to leave the record and the applied specs, as a stopped watcher would, then
call `checkAndArchiveSpec`. The delta removes a requirement, so applying it a
second time over the applied specs would fail.

For "Interrupted archive in a worktree", build a project with `vcs.enabled` as
`tests/worktree-run.test.ts` does and run its change to done. Make the first
archive attempt red through `verify.cjs`, so the change stays in its worktree.
Then write the record and the applied specs into the worktree by hand with
`applyArchiveSpecs`, make `verify.cjs` pass, clear the regression with
`retrySpec(projectRoot, '<id>', 'change', config)` from
`src/core/lifecycle/retry.ts`, and run one watcher cycle. The change archives,
and no `worktree_dirty` regression is written.
