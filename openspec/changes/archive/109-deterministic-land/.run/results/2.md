## Changed

- `src/core/vcs/vcs.ts`: added the `VcsFastForwardResult` interface and the
  `commitTree`, `fastForward`, and `countCommits` members to the `Vcs` port.
- Added `src/core/vcs/git-vcs-land.ts` over `GitWriteContext`.
  `commitTree` parses `Name <email>`, writes the message to a temporary file
  and passes it with `-F` (never as an argument), sets `GIT_AUTHOR_NAME` and
  `GIT_AUTHOR_EMAIL` in the child environment, passes `-S` when
  `git config --type=bool --get commit.gpgSign` prints `true`, and returns the
  new commit. `fastForward` compares the passed-in `status` entries against
  `git diff --name-only -z HEAD <commit>`, returns `blocked` with the changed
  paths when any overlap, and otherwise runs `git merge --ff-only`.
  `countCommits` runs `git rev-list --count <from>..<to>` and answers 0 when
  git fails.
- `src/core/vcs/git-vcs-write.ts`: added exported `worktreePrune(ctx)`.
- `src/core/vcs/git-vcs.ts`: delegates `worktreePrune`, `commitTree`,
  `countCommits`, and `fastForward` (passing its own `status()`), keeping the
  file at 249 lines.
- `src/core/vcs/no-vcs.ts`: `countCommits` returns 0; `commitTree` and
  `fastForward` reject naming the reason git is off.
- `tests/vcs-write.test.ts`: added the three members to `PORT_MEMBERS`.
- Added `tests/vcs-land-ops.test.ts`: every "Vcs land operations" scenario on
  temporary repositories (tree commit with an unchanged HEAD/index/status, no
  hook, signing with a fake `gpg.program`, fast-forward past unrelated
  modified/staged/untracked files, blocked modified file and blocked rename,
  non-fast-forward failure, counting, the rename old path) plus the three
  `NoVcs` results.

## Deviated

- `GitVcs.fastForward` omits its explicit `Promise<VcsFastForwardResult>`
  return annotation and infers it from `land.fastForward`, so the `Vcs` type
  import stays on one line and the file fits the 250-line budget; one blank
  line between class members was dropped for the same reason.
