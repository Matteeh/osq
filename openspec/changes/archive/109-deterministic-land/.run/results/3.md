## Changed

- `src/core/vcs/land.ts`: `landChange` now takes an optional fourth
  `progress: (line: string) => void` and passes it to `syncWithDefaultBranch`.
  After the refusals it runs the sync, takes the worktree HEAD as the tip and
  the checkout HEAD as the base, stops with the moved message when the base is
  not an ancestor of the tip, builds the land commit with
  `commitTree(tip, base, message, vcs.author)`, and moves the checkout only
  through `fastForward`. A blocked fast-forward stops with the uncommitted-file
  message; a failed one stops with the moved message when the checkout moved and
  git's output otherwise. The new `landCommit` helper holds the commit and move
  so `landChange` stays within the 80-line budget. `assertCheckoutClean`,
  `assertStillLandable`, `runLandVerify`, the squash through `merge(ref, true)`,
  the `commit` call, and the staged-squash lines are gone.
- `src/core/vcs/land-checks.ts`: removed `assertCheckoutClean`, `runLandVerify`,
  and `outputTail` and their now-unused imports.
- `src/core/vcs/sync-main.ts`: `syncWithDefaultBranch` takes the optional
  progress callback. When no merge is needed it writes nothing and calls no
  callback. Otherwise it announces itself with `countCommits`, merges, rebuilds
  the living specs, runs `vcs.prepare` and the proposal's verify, then appends a
  `verify_ran` and a `synced` event to the archived folder's
  `.run/events/change.jsonl` with `fs` directly, stages that file, and commits.
  `outputTail` remains the single copy and the verify runs only here.
- `src/cli/land.ts`: `landCommand` passes `landChange` a progress callback that
  writes each line and a newline to `stderr`.
- `tests/vcs-land.test.ts`: the hook test becomes "Land commit runs no hook"
  (it lands and the output does not hold `blocked by hook`), and the "osq land
  command" refusal test uses the off-default-branch refusal.
- `tests/vcs-land-refusals.test.ts`: the modified-file test becomes "Modified
  tracked file": the land succeeds and `README.md` keeps its edit.
- `tests/vcs-land-commit.test.ts`: new, through `landCommand`, covering
  "Unrelated uncommitted work stays", "Uncommitted file the change writes",
  "Default branch moves during the land", "No verify without a merge", "Sync
  announces itself", "Sync records its verify", "Progress on stderr", and
  "Message is the land commit's message".

## Missing context

The version-control delta says the sync's `verify_ran` `duration` is "in
milliseconds, ... as the watcher's verify gate writes it". The watcher's gate
writes `runVerificationCommand`'s `duration`, which is seconds. I followed the
explicit "milliseconds", converting the seconds to a rounded millisecond value;
`synced.duration` is the milliseconds from the merge's start. If the intent was
the watcher's seconds, both places are one-line changes in `sync-main.ts`.

## Outside scope

`src/harness/types.ts` still has no `synced` member in `HarnessEventType`; the
new event is written with `fs` directly and no task in this change's scope owns
that file. `osq message` still prints its `Land:` stderr line; removing it is
task 4's work.
