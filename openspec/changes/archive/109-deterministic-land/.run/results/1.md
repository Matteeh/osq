## Changed

- Added `src/watcher/archive-specs.ts` with `applyArchiveSpecs` and
  `restoreArchiveSpecs`. `applyArchiveSpecs` records the living `spec.md` and
  `osq.yml` of every capability under the change's `specs/` into
  `.run/archive-specs.json`, then applies the deltas and sidecars.
  `restoreArchiveSpecs` puts the recorded files back, removes a capability
  folder left empty, deletes the record, and resolves whether a record existed.
  It also exports `archiveSpecsRecordPath` so the archiver can drop the record
  before the move.
- Split the archiver's relocation body into `relocateArchivedSpec`, which
  deletes the record and `plan-prompt.md` before moving. `archiveSpecFolder`
  keeps its signature and still applies deltas and sidecars on its own.
  `checkAndArchiveSpec` now restores any leftover record first, keeps the done
  check, scope audit, and task verifies, then applies the deltas and sidecars,
  runs the change-level verify, restores and returns false on failure, and
  finally relocates without applying the deltas a second time.
- In `src/watcher/loop.ts`, the worktree pre-check inside `runWatcherCycle`
  calls `restoreArchiveSpecs(change.tree.root, change.folderPath)` before
  `commitPendingVerifiedTasks` and `checkWorktree`, so a worktree holding an
  interrupted archive is cleaned instead of halting with `worktree_dirty`.
- Added `tests/archive-specs-verify.test.ts`: the change verify sees the merged
  specs; the record shape; a red change verify puts the specs back and writes a
  `verify_red` regression; an interrupted archive recovers before re-applying;
  a successful archive with a prompt file drops the record; `restoreArchiveSpecs`
  is a no-op without a record; and an interrupted archive in a worktree archives
  instead of halting with `worktree_dirty`.

## Deviated

- The task says the archive step calls `restoreArchiveSpecs` before
  `checkWorktree`. For a `done` worktree change the main-loop worktree pre-check
  runs `checkWorktree` before `archiveCompletedSpec` is ever reached, so a
  restore only inside `archiveCompletedSpec` would still halt with
  `worktree_dirty`. I placed the call at the start of the worktree pre-check
  block, which is before `checkWorktree` and satisfies the required worktree
  scenario.

Touched: src/watcher/archive-specs.ts, src/watcher/archiver.ts, src/watcher/loop.ts, tests/archive-specs-verify.test.ts
