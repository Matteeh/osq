## Acceptance

- [ ] New `src/core/status/leftover-drafts.ts` finds leftover drafts as the status-inspection delta's "Leftover draft in status" says.
- [ ] `getStatusOverview` leaves leftovers out of `specs` and returns them in an optional `leftovers` field, present only when not empty. `formatStatusOverview` prints the `Leftover drafts:` section only then.
- [ ] With `vcs.enabled` off, `osq status` prints exactly what it printed before.
- [ ] README.md lists `osq message <id>` under Commands. Its "Version control" section says how to land a change by hand with `git merge --squash osq/<folder>` and `osq message <id> | git commit -F -`, that `osq status` then flags the leftover copy of the draft, and that the test helper finds the change from an `osq/<folder>` worktree when `OSQ_CHANGE` is unset.
- [ ] New `tests/status-leftover.test.ts` covers every scenario of "Leftover draft in status" through `statusCommand` on temporary git repositories.

## Details

Take the changes and archive directories from the first `changeTrees` tree,
never from `getChangesDir` or `getArchiveDir`
(`tests/change-locations-readers.test.ts`). Read the landed hash with the
`Vcs` port's `show` on `defaultBranch()`, and hash the checkout copy with
`hashChangeFolder`, as `checkoutCopyChanged` in `status.ts` does. Build the
path in the printed command from `changesDirLabel`. Only call `selectVcs`
when `vcs.enabled` is on.

Build the repository as `tests/worktree-run.test.ts` does. Commit
`verify.cjs` before approving, approve with `approveSpec`, run the change to
its archive commit with `runWatcherCycle`, then land it by hand with
`git merge --squash osq/<folder>` and `git commit -m land` in the checkout.
