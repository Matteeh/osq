## Changed

- Added `src/core/status/leftover-drafts.ts`: `findLeftoverDrafts` returns the
  active folders directly under the first `changeTrees` tree's changes
  directory whose `hashChangeFolder` still equals the trimmed contents of
  `<archive>/<folder>/.run/approved` on `vcs.defaultBranch()`. It returns `[]`
  without a show read when `vcs.enabled` is off or `selectVcs` picks `NoVcs`,
  sorts leftovers by numeric folder prefix, and builds each printed path from
  `changesDirLabel(config)`.
- Changed `src/core/status/status.ts`: `StatusOverview` gained an optional
  `leftovers`, `getStatusOverview` drops leftover folder names from `specs` and
  attaches `leftovers` only when non-empty, and `formatStatusOverview` prints
  the `Leftover drafts:` block after `Verification pending:` and before
  `Archived specs:`.
- Added `tests/status-leftover.test.ts`: temporary git repositories driven
  through `statusCommand`, covering an untouched copy after a hand landing, the
  same after `git worktree remove`, an edited copy, an unlanded change, removal
  clearing the flag, `vcs.enabled` off, and git unavailable.
- Changed `README.md`: listed `osq message <id>` under Commands and added the
  hand-landing / leftover / worktree-lookup paragraph to `Version control`.

## Missing context

- The status-inspection delta says "no git read" under `NoVcs`, but detecting
  `NoVcs` itself requires `selectVcs` to probe git. The module returns before
  the `show` read, matching the task detail that `selectVcs` is only reached
  with `vcs.enabled` on.
