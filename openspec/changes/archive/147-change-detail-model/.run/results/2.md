## Changed

Moved the change-detail model out of `src/core/status/show.ts` into model
modules, added the proposal sections and the approval digest to the model, and
made the CLI render through the new output module. `osq show` output stays
byte-identical.

- `src/core/status/show-model-folder.ts` (new): `resolveSpecFolder` and its
  `matchesFolder` helper, moved unchanged.
- `src/core/status/show-model-events.ts` (new): `.run/events/*.jsonl` reading,
  the chronological timeline, recertification projections and
  `buildVerificationHistory`. `readEventStreams` returns the timeline, the
  per-task streams and typed recertification events; `buildRecertifications`
  orders them.
- `src/core/status/show-model-tasks.ts` (new): task files, done/dead/regressed/
  running markers, result files and `attachTaskScenarios` (with
  `distinctScenarioPairs`).
- `src/core/status/show-model.ts` (new): `getSpecDetails`,
  `getSpecDetailsFromFolder`, `withNextStep`, and `buildSpecDetails`, split into
  `readWrittenCapabilities`, `readApprovedHash`, `readPlanningSessionDetails`,
  `readTaskDetails`/`attachTaskScenarios` and `deriveSpecStatus`. It re-exports
  `resolveSpecFolder`.
- `src/core/status/show-types.ts`: `SpecDetails` gains `surface`, `decisions`,
  `beforeApproval` and `digest`, with the `ApprovalDigest` type import added.
- `src/core/status/show-output.ts` (new): `formatShowText` (model text then,
  when present, `formatApprovalDigest` and each `formatApprovalFlags` line) and
  `formatShowJson` (drops `surface`, `decisions` and `beforeApproval`, puts
  `digest` last, two-space indent). Imports no `node:fs`.
- `src/core/status/show.ts`: now only `export ... from` lines for
  `getSpecDetails`, `getSpecDetailsFromFolder`, `resolveSpecFolder`,
  `formatSpecDetails`, `formatShowOutput`, `formatShowText`, `formatShowJson`
  and every `show-types.ts` type. 18 lines, off the line allow list.
- `src/cli/show.ts`: calls `getSpecDetails` and prints
  `formatShowJson`/`formatShowText`; no longer imports `src/core/spec/digest.ts`.
  Return value, printed text and `Show error:` wrapping unchanged.
- `tests/line-budget.test.ts`: removed `core/status/show.ts` from `ALLOW_LIST`.
- `tests/function-budget.test.ts`: removed
  `core/status/show.ts#buildSpecDetails` from `GRANDFATHERED`.
- `tests/show-test-path.test.ts`: discovers the `show-model*.ts` module that
  defines `attachTaskScenarios` and runs the same three assertions there.
- `tests/show-model.test.ts` (new): covers the "Change detail model" scenarios
  (unapproved carries sections and digest; approved keeps text and has a null
  digest from both entry points; renderers read no files and `show.ts` defines
  no function) and the "Show output from the model" scenarios (JSON drops the
  three fields and ends with `digest`; text ends with the digest and flag lines
  `osq approve` prints).

Task verify: `osq show output identical in 324 renderings` (after
`tests/show-model.test.ts` passed). Proposal verify: `pnpm verify` exits 0
(CLI and UI typechecks, build, every test, lint).

## Deviated

`SpecDetails.surface`, `decisions`, `beforeApproval` and `digest` are optional
(`surface?: string`, `digest?: ApprovalDigest | null`) rather than required,
although the acceptance says `(strings)` and `digest: ApprovalDigest | null`.
Task 1 added `tests/show-text.test.ts`, which builds a `SpecDetails` literal and
is not in task 2's `scope`; required fields break its typecheck, and editing it
is outside the scope (rule 6 kills the task). The model still always fills the
four fields, so both entry points carry them as the "Change detail model"
requirement says, and `formatShowJson` still strips the three proposal fields
and emits `digest` last. The proposal's measurement note ("No test builds a
`SpecDetails` literal") predates task 1's test.

Task 1's result says `tests/show-task-lines.ts` imports `TaggedScenario` from
`../trace/tag-scan.js`; task 2 keeps that and does the same in
`show-model-tasks.ts`.

## Missing context

The task's acceptance treats `SpecDetails` as gaining required fields, but task
1's new `tests/show-text.test.ts` builds a literal model. The plan should either
put that test in task 2's `scope` or note that the new fields stay optional.
