## Changed

- `src/core/vcs/sync-bridge.ts` (new): exports `syncBridge(vcs, defaultBranch, head, folderName, author)`. It reads `trailerValues(head, defaultBranch, 'Osq-Head')`, keeps each tip once whose `mergeBase(head, tip)` exists and is not an ancestor of the default branch, and returns the default branch when none is kept. Otherwise it returns `commitTree(defaultBranch, defaultBranch, message, author, keptTips)` with the message `osq: <id> bridge <defaultBranch>`, a blank line, and `Osq-Change: <folder>`. Carries `@scenario` lines for the four "Sync takes landed branch tips" scenarios and `@adr 003`.
- `src/core/vcs/sync-main.ts`: step 2 now merges `syncBridge`'s result instead of always the default branch. The bridge is built inside the existing `try`, so a throw stops through `stopAfter` exactly like a merge throw. Everything else, including the progress line and `countCommits`, is untouched. 247 lines.
- `tests/vcs-stacked-land.test.ts` (new): builds a three-change stack (`001`, `002` on `001`, `003` on `002`) through `approveSpec` and `runWatcherOnce`, with an adapter that writes `<change folder> task <n>` into the task's scope. Covers "Three-change stack lands in order", "Stacked sync merges a bridge" (subject, tree, parents, no other ref reaches it), "Unrelated change merges the default branch" and "Both add to one capability" (`orders` equals `mergeDelta` of the delta over the default branch copy), plus "Stacked dependent after its dependency landed" (`001`'s archive folder on `002`'s branch equals the default branch copy and no conflict marker). "Landed tip missing from the repository" hand-commits on `main` with an `Osq-Head:` trailer naming a sha the repository lacks and checks the sync merges the default branch itself.

`pnpm verify` passes (typechecks, build, every test including the new file, lint).

## Deviated

- The acceptance says the adapter writes `<change folder> task <n>` into the same scoped file. That holds for the three-change stack. For the "Both add to one capability" check the unrelated `002` uses a separate scope, because two unrelated changes that rewrite the same code line conflict by design; the scenario is about the living capability, not code. The adapter writes to `options.scope[0]`, so the stack still shares one file.
- The archive check in the test helper uses `git cat-file -e` on the branch tree rather than `rev-parse --verify`; the latter returned nonzero for a tree path in the harness even though `cat-file` and `ls-tree` resolved it.
