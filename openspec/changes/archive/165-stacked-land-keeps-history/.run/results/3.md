## Changed

- `src/core/vcs/land-checks.ts`: `assertNoEarlierChange` now filters the land candidates to osq-worktree archives, builds the direct/transitive stacked-on graph from each candidate's archived `.run/stacked-on` (read with the existing `parseStackedOn`, missing file names none), and skips every candidate in the closure of changes stacked on the change being landed. The earlier-change refusal lost `, or reject it`. Added `stackedOnNames` and `stackedOn` helpers. The function now carries `@scenario version-control:` lines for "Earlier change shares a capability", "Earlier change stacked on this one" and "Earlier change stacked through another", plus `@adr 003`.
- `tests/vcs-land-refusals.test.ts`: only the shares-a-capability expected refusal changed to `001-order-flow archived before 002-second and also writes orders; land it first`.
- `tests/vcs-land-stacked-order.test.ts` (new): builds a temp repo the way `tests/vcs-land-refusals.test.ts` does and drives `landCommand` for the three "Land refusals" scenarios. Each `.run/stacked-on` is written into the archived folder in the change's worktree and committed on that branch; the archive order sets the `archived` event order.
