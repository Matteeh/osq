## Acceptance

- [ ] The `Vcs` interface's `commitTree` takes an optional fifth argument `extraParents: readonly string[]`. `commitTree` in `git-vcs-land.ts` passes `-p <parent>` and then one `-p <commit>` per entry, in order, and behaves exactly as today without it, so version-control "Vcs land operations" holds, "Commit with extra parents" included. `NoVcs.commitTree` still fails naming the reason git is off.
- [ ] The `Vcs` interface gains `mergeBase(a, b): Promise<string | null>` and `trailerValues(from, to, key): Promise<string[]>`, as version-control "Vcs history reads" says. `GitVcs` runs them through its bounded `run`: `mergeBase` runs `git merge-base <a> <b>`, and `trailerValues` runs one `git log <from>..<to>` with a `%(trailers:key=<key>,valueonly,...)` format that separates commits and values unambiguously. `NoVcs` returns null and an empty list.
- [ ] `src/core/vcs/git-vcs.ts` stays at or under 250 lines. To make room, move the bodies of `GitVcs` reads such as `root`, `head`, `indexDigest`, `stashList`, `status`, `show` and `pathExists` into a new `src/core/vcs/git-vcs-read.ts` that takes the `GitWriteContext`, the way `git-vcs-merge.ts` does, and keep each method a one-line delegation. No behavior changes.
- [ ] No git argument list holds a word "Operations osq never runs" forbids.
- [ ] `PORT_MEMBERS` in `tests/vcs-write.test.ts` gains `mergeBase` and `trailerValues`; nothing else in that file changes.
- [ ] New `tests/vcs-history-ops.test.ts` builds temporary repositories the way `tests/vcs-land-ops.test.ts` does and checks every scenario of "Vcs history reads" and "Commit with extra parents" through `GitVcs` and `NoVcs`, with expected values from the scenarios' THEN lines.
- [ ] `commitTree`, `mergeBase` and `trailerValues` in `git-vcs-land.ts` and `git-vcs-merge.ts` carry `@scenario version-control: <scenario name>` lines for the scenarios they serve and `@adr 003`.
