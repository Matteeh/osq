## Changed

- Added `src/cli/server.ts` with `registerServerCommand`, `startServer` and `stopServer`: the live-record refusal, the role exemption, starting the watch service when no live service or watcher record exists, the detached `OSQ_SERVER_ROLE=supervisor` spawn with its output in `server.log`, `server.json` with pid/startedAt/log/url, and every printed line. `osq server` with no subcommand or an unknown one prints help and exits nonzero through Commander.
- Added `src/cli/server-worker.ts` with `defaultProjectSegment`, `resolveServerSite`, `createServerCommands` (whose `land` calls the land command with `publish: true` and whose other verbs match `osq serve`), and `runServerWorker` (`startWebServer` on `serve.server.port` with the site, a `createServiceBuildCheck` every `serve.server.buildCheckSeconds`, `EXIT_NEW_BUILD` once a settled new build finds no action running, and SIGINT/SIGTERM shutdown after any running action).
- Exported `startBackgroundWatch` and `stopBackgroundWatch` from `src/cli/watch-service.ts` unchanged so `osq server` reuses them.
- Registered `server` in `src/cli/index.ts` and compacted the argv-normalization block to keep the file within budget; added `server` after `watch` in `src/cli/help-groups.ts` and the expected groups in `tests/help-groups.test.ts`.
- Added `osq server start` and `osq server stop` to README's "Setup and running" block and a "Running osq on a server" section.
- Added `tests/server-command.test.ts` covering every "Server commands" scenario: real-process start/stop with a free port and temporary home, the live-record refusal, a live terminal watcher, stop with nothing running, stop after the wait, and the publishing land table.

## Deviated

- The exported command functions are named `startServer` and `stopServer`, not `...Command`, because `tests/cli-no-direct-output.test.ts` requires every exported `*Command` under `src/cli` to appear in its fixed table.
- The worker hands its exit code to `runCli` by settling with a `CommandError` carrying `EXIT_NEW_BUILD` (and a normal resolve for a stop) instead of calling `process.exit`, because `tests/cli-no-process-exit.test.ts` and `tests/cli-no-exit-code.test.ts` forbid `process.exit(` and `process.exitCode =` anywhere under `src/cli`.

## Missing context

- The task specified `EXIT_NEW_BUILD` and exit 0 for the worker but not how to end the process given the repo-wide guards on `process.exit`/`process.exitCode` under `src/cli`. The `CommandError`-with-exitCode path is the only mechanism that both satisfies the supervisor contract and keeps those tests green unchanged.
