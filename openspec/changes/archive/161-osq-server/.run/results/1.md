## Changed

- `src/core/foundation/config-serve.ts`: added `ServeServerConfig`; `ServeConfig` gains `allowedHosts` and `server`; `DEFAULT_SERVE_CONFIG` gains `allowedHosts: []` and `server: { port: 4174, buildCheckSeconds: 30 }`. `validateServeConfig` now validates `allowedHosts` (array of non-empty host names, no whitespace, `/` or `://`) and the `server` block (`port` 1..65535, finite positive `buildCheckSeconds`, non-empty `name`, `project` matching `^[A-Za-z0-9][A-Za-z0-9._-]*$`), each defaulted on its own, with `name`/`project` left absent when unset. The existing `port` and `eventDebounceMs` checks and messages are untouched.
- `src/core/foundation/config-user.ts`: `OsqUserConfig` omits and re-declares `serve` so every key, `server` and its keys included, is optional.
- `src/index.ts`: exports the `ServeServerConfig` type next to `ServeConfig`.
- `src/core/web/web-write.ts`: `isHostAllowed` and `isOriginAllowed` take the allowed hosts as a third parameter defaulting to `[]`; a listed entry matches the whole `Host` exactly; an origin is `http://` or `https://` followed by an allowed host. `actionGet` and `actionPost` pass `options.config.serve?.allowedHosts ?? []`. The server still binds only `127.0.0.1`.
- `tests/config.test.ts`: the three serve cases now expect `allowedHosts: []` and the `server` defaults; no other case changed.
- `tests/hosts-config.test.ts` (new): covers "Server defaults", "Partial server block" and every row of "Invalid server values" through `defineConfig`, asserting the exact table errors plus whitespace and empty host entries.
- `tests/hosts-guard.test.ts` (new): starts real servers with `startWebServer` on port 0 with a config that sets `serve.allowedHosts` and a recording `runAction`, sends raw `http.request`s with `Host`/`Origin`, and covers "Configured host behind a proxy" and every row of "Hosts judged against the list". Port 4180 rows use the bound port.

## Deviated

- Standalone task verify runs without a built `dist`, so the new tests use plain `node:test` like `tests/web-actions.test.ts` instead of the `@matteeh/osq/testing` `scenario` helper, which resolves through `dist/testing`. The scenarios are still named in the test descriptions and the touched source functions carry `@scenario`/`@adr 013` doc tags.
- Added one extra guard, `serve.server must be an object`, for a non-object `server` value; the requirement's table does not name that value.
- `isOriginAllowed` accepts `https://` for loopback hosts too, following the requirement's "an origin is allowed when it is `http://` or `https://` followed by an allowed host".

## Missing context

- The task did not say whether the new scenario test files should use the `@matteeh/osq/testing` helper; the standalone verify command has no `dist`, so plain `node:test` was the only workable choice.
