## Changed

- Added `packages/ui/src/server/`: `resolve-base.ts` (`resolveApiBase`),
  `status-client.ts` (`createServerStatusClient`, `ServerStatusClient`,
  `ServerStatusRequest`, `ServerStatusResponse`), `ServerHeader.tsx`,
  `ServicePanel.tsx`, `index.ts`, and `server.css`. The panel renders the exact
  `Watcher: ...`, `Waiting: ...` and `Service log: ...` lines, shows the
  watcher's version/commit/startedAt, and styles the waiting line with
  `var(--status-regressed)`.
- `contracts.ts` re-exports `WebServerStatus` from `src/core/web/web-site.ts`
  with `export type`.
- `data.ts`: `createDashboardData` takes an optional `base` (default `''`) and
  prefixes the report, graph, inbox, change and events paths with it.
- `change/actions-client.ts`: `createActionClient` takes an optional `base`
  (default `''`) and prefixes its actions URL.
- `app.tsx`: `App` takes an optional `server?: WebServerStatus | null`; with one
  it renders `ServerHeader` next to the title and `ServicePanel` before the
  home route's groups, and without one it renders exactly as before.
- `main.tsx`: resolves the base from `window.location.pathname`, passes it to
  the data module and the action client, and for a non-empty base loads the
  status at start, after each refresh, and after each applied snapshot, keeping
  the last status when a request fails; imports `server/server.css`.
- Added `tests/ui-server.test.tsx`: `resolveApiBase` for `/`, `/index.html`,
  `/p/osq/`, `/p/osq/index.html`, `/p/../`; status client success and every
  failure mode; base-prefixed data, event source and actions URL versus the
  default `/api/` paths that never ask for `api/server`; the header label; all
  four "Service panel states" rows; the watcher detail line; the warning
  palette; the 360-pixel width rule; and the loopback dashboard unchanged.

## Deviated

- The `Waiting:` line is a plain `<p className="service-warning">` without
  `role="status"`, because Biome's `lint/a11y/useSemanticElements` rejects a
  `role="status"` on `<p>`. The requirement only asks for warning styling, which
  the class and `--status-regressed` provide.

## Missing context

- `main.tsx` mounts a DOM root and is not imported by any test, so its
  status-refresh wiring is covered only by `pnpm typecheck:ui`, lint and code
  review; the acceptance's testable parts (base resolution, status client, path
  prefixing, App rendering) are covered in `tests/ui-server.test.tsx`.
