## Changed

- `src/core/vcs/land.ts`: `landChange` takes an optional fifth `LandOptions`
  with `beforeMove?: (commit) => Promise<void>`; `landCommit` calls it after
  `commitTree` and before `fastForward`, so a throw stops the land with that
  error and leaves the default branch where it was. The sync-stop recording
  moved into the `rethrowSyncStop` helper, keeping `landChange` inside its
  80-line budget. `LandOptions` is exported. `landId`, `requireGit` and
  `resolveChange` moved out (see Deviated).
- `src/core/vcs/land-publish.ts` (new): exports `landAndPublish` and
  `LandPublishHooks` (`afterFetch`). It fetches `origin`'s default branch,
  fast-forwards the checkout when origin is ahead (`Updated ...`), stops on
  divergence, runs `landChange` with a `beforeMove` that pushes the land
  commit (`Pushed ...` before `Landed ...`), stops on a rejected push, and,
  when the change had already landed and origin is a strict ancestor, pushes
  the default branch's HEAD. Every stop is an `Error` with the spec's exact
  message.
- `src/core/vcs/land-resolve.ts` (new): holds `landId`, `requireGit` and
  `resolveChange`, shared by `land.ts` and `land-publish.ts`.
- `src/cli/land.ts`: `LandCommandOptions` gained `publish?: boolean`;
  `landCommand` lands through `landAndPublish` when set, with the same
  stale-build refusal, output, rebuild line and `CommandError` handling.
  `registerLandCommand` adds no flag.
- `tests/vcs-land-publish.test.ts` (new): proves every "Land publishes to
  origin" scenario against a real bare `origin` and a second mover clone, plus
  a `landCommand` run with `publish: true` and one without it.

## Deviated

- The new test file uses plain `node:test` `describe`/`it`, as
  `tests/vcs-land.test.ts` and `tests/vcs-remote.test.ts` do; `version-control`
  is not opted into traceability, so the `@matteeh/osq/testing` scenario helper
  is not used.
- `land.ts` gained the `LandOptions` interface and `rethrowSyncStop` and could
  not stay under the 250-line source budget with `landId`, `requireGit` and
  `resolveChange` still in it, so those three helpers moved to the new
  `src/core/vcs/land-resolve.ts` inside the task's `land*.ts` scope. The task
  only suggested moving the sync-stop block within `land.ts`; that part was
  done as well.

## Outside scope

- `src/core/vcs/git-vcs.ts` remains at 249/250 lines (noted by task 2); no
  change was needed here.
