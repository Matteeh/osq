## Acceptance

- [ ] New `src/cli/server.ts` exports `registerServerCommand`, which adds `osq server` with subcommands `start` ("run the dashboard and the watcher service in the background") and `stop` ("stop the server and the watcher service"), and implements cli-foundation "Server commands": the live-record refusal, the role exemption, starting the watch service, the detached supervisor spawn, `server.json`, and every printed line, each the requirement's exact text through `CommandInputs.stdout`, each failure a `CommandError`. `server start` and `server stop` take an optional `home`, used for every record, as `watchCommand` does. `src/cli/index.ts` calls `registerServerCommand(program)` and stays at or under 250 lines; `help-groups.ts` adds `server` after `watch` in "Setup and running", and `tests/help-groups.test.ts`'s expected groups gain it there and nothing else.
- [ ] `src/cli/watch-service.ts` exports the functions that start and stop the background watch service, unchanged, so `osq server` reuses them; its other behaviour does not change.
- [ ] The supervisor role runs `runServiceSupervisor` with `service: 'server'`. New `src/cli/server-worker.ts` runs the worker role: the site's `name` and `project` from `serve.server` or the requirement's defaults, `startWebServer` on `serve.server.port` with that `site` and a `runAction` from `createWebActionRunner({ cwd, config }, createServerCommands())`, where the exported `createServerCommands(land = landCommand)` returns a table whose `land` calls `land(change, { ...inputs, publish: true })` and whose other verbs call the same command functions `osq serve`'s default table calls; a build check from `createServiceBuildCheck` every `serve.server.buildCheckSeconds` that closes the server and exits with `EXIT_NEW_BUILD` on `BuildChangedError` once no action runs, and ignores a `BuildWaitError`; and a SIGINT or SIGTERM handler that closes the server after any running action and exits 0. `src/cli/serve.ts` and `src/cli/serve-actions.ts` do not change.
- [ ] README's "Setup and running" block in `## Commands` gains `osq server start` and `osq server stop`, and a new "Running osq on a server" section says: the server holds its own clone and binds only `127.0.0.1` on `serve.server.port`; reach it with `tailscale serve --bg <port>` after adding the tailnet name to `serve.allowedHosts`, or with `ssh -L <port>:127.0.0.1:<port> <server>`; open `/p/<project>/`; Tailscale Serve or a reverse proxy terminates TLS, never osq; anyone who reaches the port through the private network can tap, because there is no sign-in yet; a land tapped there pushes to `origin` with the server user's git or SSH credentials, which no executor or verify receives, and stops when `origin` moved; `osq land` in a terminal does not push; and `osq serve` is unchanged.
