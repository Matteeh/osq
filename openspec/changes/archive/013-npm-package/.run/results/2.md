# Task 2 — Built bin runtime version resolution

## Changed

- `src/cli/index.ts`
  - Added `resolvePackageVersion(): string` exporting the `version` field read from
    `new URL('../../package.json', import.meta.url)` at runtime (works identically from `src/cli/`
    and `dist/cli/`, i.e. two levels below the package root).
  - Changed `createProgram(version?)` to `createProgram(version?: string)` and removed the
    hardcoded `.version('0.1.0')`; it now uses the passed version or calls `resolvePackageVersion()`.
- `src/cli/bin.ts`
  - Shebang preserved as the first line; now imports `resolvePackageVersion` and calls
    `createProgram(resolvePackageVersion())`.
- `tests/bin-execution.test.ts` (new)
  - `before` hook runs `pnpm build` to compile `dist`.
  - Asserts `dist/cli/bin.js` starts with `#!/usr/bin/env node`.
  - Asserts `dist/index.d.ts` exists, is non-empty, and declares programmatic exports
    (`defineConfig`/`OsqConfig`).
  - Asserts `resolvePackageVersion()` and `createProgram().version()` equal the `package.json`
    version.
  - Runs `node <abs>/dist/cli/bin.js --version` and `--help` from isolated `os.tmpdir()` dirs and
    asserts the version matches `package.json` and all command listings appear without errors.

## Verified

- Task verify: `node --import tsx --test tests/bin-execution.test.ts` → 5 pass / 0 fail.
- Regression: `node --import tsx --test tests/cli.test.ts` → 4 pass / 0 fail.
- `pnpm tsc --noEmit` clean; `pnpm lint` clean (biome reformatted the command loop once).

## Deviations

None. `src/index.ts` was already exporting configuration helpers/types, so no edit was needed there
to satisfy the `dist/index.d.ts` acceptance line.

## Drift against features/

the behavior documented in `features/cli-foundation.md`.
