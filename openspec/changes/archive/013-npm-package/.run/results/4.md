# Task 4 — Release workflow with npm Trusted Publishing

## Changed

- `.github/workflows/release.yml` (new)
  - Trigger: `on.push.tags: ['v*']`.
  - Job `release` on `ubuntu-latest` with `permissions: contents: read`, `id-token: write`.
  - Steps: `actions/checkout@v4`; `pnpm/action-setup@v4` (version 9); `actions/setup-node@v4`
    (Node 22, `cache: pnpm`, `registry-url: https://registry.npmjs.org`); `pnpm install
    --frozen-lockfile`; `pnpm verify`; `pnpm run test` (consumer pack smoke test); a tag/version
    parity guard reading `GITHUB_REF` and `package.json` and exiting 1 on mismatch; and
    `npm publish --provenance --access public`.
  - No `secrets.*`, `NPM_TOKEN`, `NODE_AUTH_TOKEN`, or `.npmrc` auth references.
- `tests/release-workflow.test.ts` (new)
  - Parses `release.yml` with the `yaml` package and asserts: `push.tags` includes `v*`;
    `pnpm install --frozen-lockfile` and `pnpm verify` runs; a test-suite run that is not skipped
    via `OSQ_SKIP_PACK_TEST`; tag/package version check runs before publish and compares the two
    values; publish uses `--provenance` and `--access public`; effective permissions include
    `id-token: write` and `contents: read`; no static secret or `.npmrc` references; and
    checkout/pnpm/Node 22 setup with a pinned pnpm version.
