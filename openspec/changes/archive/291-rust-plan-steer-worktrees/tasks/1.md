## Details

Build the tree list as the next-number code in `next/number.rs` does,
`GitVcs` with the config's timeouts, `worktree_list` turned into
`TreeCandidate`s, but pass no stacked folders. Share that code rather than
copying it. Keep the opening sections built from the root `plan` runs on;
only the steering section, the prompt's path and the handoff's folder path
use the change's own tree. Widen the `handoff` module so it takes the
folder path, and keep the queue handoff's text.

Port the changed requirement names from TypeScript's `changedRequirements`
in `src/core/vcs/sync-specs.ts`, and the requirement blocks from
`requirementLines` in `src/cli/plan-steer.ts`. Read both sides with the
vcs `show` at the base commit and at the default branch, parse them with
rust-specs `parse_living_spec`, and compare each requirement's `raw` text.

A test builds its scratch repository as the golden script's header says,
under a new folder of `CARGO_TARGET_TMPDIR` named after its row, with the
`git` program, as `inbox_trees.rs` does: `trunk`, the `init` commit, one
worktree per folder under the fixture's `changes/` with `.run/base`
holding `init`'s commit id, then the `trunk moves` commit. Canonicalise the
scratch path, and replace it with `<scratch>` in the output and the prompt
before comparing. A test cannot set environment variables.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source. Run the proposal's verify as the watcher does,
with `OSQ_CHANGE=openspec/changes/291-rust-plan-steer-worktrees`, so the
link gates see this change's new requirement.
