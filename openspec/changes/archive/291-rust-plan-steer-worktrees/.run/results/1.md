## Changed

- Copied `fixture/steer-worktrees/` and `golden/` from this change into `crates/features/plan/tests/fixtures/steer-worktrees/` and `crates/features/plan/tests/fixtures/steer-worktrees-golden/`, unchanged.
- Added `src/trees.rs`, the shared tree builder that lists worktrees through `GitVcs` with the config's timeouts and turns them into `TreeCandidate`s; `next/number.rs` now uses it with stacked folders, and steering uses it without.
- `src/steer/lookup.rs` reads the root's config, lists the root or the tree changes, associates each change with its tree root and whether that tree names it, and keeps TypeScript's `matchesFolder`.
- `src/steer.rs` selects the first active match, else with vcs on the first archived match in a naming tree that has a trigger, and gives the "approved and needs no steering" error only for a named change.
- `src/steer/prompt.rs` uses the change's own tree root and default branch in the steering section, and adds the requirement blocks for `requirement_changed`; `src/steer/requirements.rs` ports `changedRequirements` and `requirementLines`, comparing `raw` text at `.run/base`/`.run/requirements-base` and the branch.
- `src/next/handoff.rs` now takes the change's folder path, so a worktree or archived change hands off its own path; the queue handoff text is unchanged.
- Added `tests/plan_steer_trees.rs` proving both new worktree scenarios and the extra lookup/block edge cases, and kept `tests/plan_steer.rs` proving the 278 scenarios.

## Deviated

- Added one supplementary test, `archived_lookup_and_blocks_ignore_edges`, beyond the two named scenario tests. It checks that an archived change in the root is skipped for an id whose named worktree change is steered, that a missing base marker counts as no base text, and that a conflict gets no requirement blocks. These cases cover the changed lookup and prompt branches and remove the mutation survivors reported for those lines.
