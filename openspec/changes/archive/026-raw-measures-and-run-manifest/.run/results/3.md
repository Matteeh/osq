# Task 3 — Measures event at task end

## Changed

- `src/watcher/measures.ts`:
  - Added `snapshotScope(projectRoot, scope): Promise<ScopeState>` — one read pass
    producing per-file `sha256:<hex>` hashes plus line counts. `snapshotScopeHashes`
    and the new `snapshotScopeLines` are thin delegates over it.
  - Rewrote `gatherScopeCounts` to reuse `snapshotScope`; `hashFileForMeasures`
    now reuses the shared `hashContent`.
  - Added `gatherEndMeasures(startMeasures, before, projectRoot, scope)` — diffs
    the start baseline against a fresh snapshot: `scopeHashes` before/after for
    every scoped key, `changedFiles` = keys whose hash differs (covers
    `null → hash` and `hash → null`), `changedLines` = sum of
    `|afterLines - beforeLines|` with a missing version counted as 0 lines. Every
    start field is carried through; only `phase` flips to `end`.
  - Added `createTaskMeasures(projectRoot, specFolderPath, taskNumber, taskData)`
    returning `{ emitStart, emitEnd }`. `emitStart` snapshots the baseline, gathers
    the start payload, and emits it; `emitEnd` is a no-op until a start happened.
- `src/watcher/runner.ts` (199 lines):
  - Holds one `measures` tracker per run. `fail()` calls `measures?.emitEnd()`
    before writing the dead marker, so `verify_red` and `undeclared_test_change`
    emit end measures before their marker.
  - The success path emits end measures before `writeDoneMarker`/`recordDoneEvent`.
  - `finish(result)` emits end measures for the `crashed`/`timeout` and `no_result`
    paths that return directly from `spawnTaskAgent`/`ensureTaskResult`.
- `tests/measures.test.ts`: 6 new tests — `gatherEndMeasures` for modified/added/
  deleted files, untouched scope, and start-field carry-through; runner
  integration for verified done, a scoped edit producing changed files/lines and
  before/after hashes, crashed dead, and `verify_red` with end measures ordered
  before the dead event. Added `ScopeWritingAdapter` and `readMeasuresEvents`
  helpers; the old single-start-event runner test now asserts start + end.

Acceptance: all seven lines satisfied (line 1 via the tracker; see Deviated).

## Deviated

- **`changedLines` semantics.** Task line 5 says "after minus before, absolute
  value, 0 for missing", while Details point 2 says "count lines in the after
  version (or 0 if deleted)". These disagree for a deleted file (before 4 lines:
  acceptance yields 4, Details yields 0) and for an edit that shrinks a file. I
  implemented the acceptance formula (`|after - before|`, missing side = 0) and
  tested it. Flag for the approver if after-only was intended.
- **Dead-marker ordering for agent-powered deaths.** `spawnTaskAgent` (crashed/
  timeout) and `ensureTaskResult` (`no_result`) write their dead markers and dead
  events internally, and both are outside this task's scope. Their end measures
  are therefore emitted immediately after those functions return, i.e. after the
  marker. `done`, `verify_red`, and `undeclared_test_change` all emit end measures
  before their marker, matching acceptance line 2.
- **Snapshot location.** Acceptance line 1 names a runner call to
  `snapshotScopeHashes`. The scope-hash snapshot happens in
  `createTaskMeasures.emitStart` via the shared `snapshotScope` helper, both before
  `spawnTaskAgent`. Inlining the call in `runner.ts` would have broken the
  enforced `< 200`-line runner budget (`tests/import-graph.test.ts`) and risked the
  250-line budget in `measures.ts`. Behavior is covered by the integration test.
- **`measures.ts` refactor.** To add end-phase code while staying under the
  250-line source budget, `IGNORED_DIRS`, `countDeltaRequirementsAndScenarios`,
  `listTsFiles`, and `gatherRepoCounts` were condensed and the combined
  `snapshotScope` centralises scope reads. Public names and behavior are preserved.

## Drift against features/
