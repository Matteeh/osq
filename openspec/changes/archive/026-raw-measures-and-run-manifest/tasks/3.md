- [ ] runner.ts re-snapshots scope hashes after spawn outcome and before done or dead marker
- [ ] runner.ts calls emitMeasures with phase end including changedFiles, changedLines, and scopeHashes before/after
- [ ] changedFiles counts scoped files whose hash differs before vs after (including null to non-null and vice versa)

- [ ] measures end event is emitted for both done and dead outcomes
- [ ] src/watcher/runner.ts remains under 250 lines

## Details

1. In `src/watcher/runner.ts`, after measures start emission (added by task 2):
   - Store `const scopeHashesBefore = await snapshotScopeHashes(projectRoot, taskData.scope);`

2. Add a helper or inline logic to compute end-phase diffs:
   - `const scopeHashesAfter = await snapshotScopeHashes(projectRoot, taskData.scope);`
   - Build `scopeHashes` record: for each key in the union of before/after, `{ before: beforeHash, after: afterHash }`.
   - `changedFiles`: count of keys where `before !== after`.
   - `changedLines`: for each changed file, count lines in the after version (or 0 if deleted).

   - The simplest approach: use a `finally`-like pattern or a dedicated emit point right before the outcome markers.
