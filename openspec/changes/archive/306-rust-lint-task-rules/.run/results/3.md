## Changed

- Added `crates/features/lint/src/lint/entry.rs`, implementing rust-lint
  "Lint entry paths": task files are reread in the cross-task warnings' order,
  their `entry` lists are checked against the change folder, the task and
  earlier scopes, the project tree or default branch, and other approved or
  archived changes, and each miss gives the requirement's error.
- Provider 4 reads a change's state in this crate: landed from the default
  branch's archive folder, then its `osq/<folder>` branch marker, then its
  stacked copy under `vcs.worktreeRoot`, then its active or archived checkout
  marker. Other changes come from rust-storage `list_changes`.
- Wired the entry findings into `lint.rs` between task 2's per-task errors and
  its cross-task warnings, for both the parsed and invalid-frontmatter proposal
  paths.
- Added `tests/lint_entry_paths.rs`, proving every row of "Entry path findings"
  plus the path forms, providers, brace and frontmatter skips, task ordering
  and the task-error/entry order, and `tests/lint_entry_git.rs`, proving "Entry
  paths with git on" in scratch repositories made with `git init -b main` and a
  fixed author, plus branch, archived, stacked, landed, unapproved, checkout,
  configured-default-branch and nested-project cases.
- Task verify `cargo test -p osq-feature-lint --test lint_entry_paths --test
  lint_entry_git --test lint_task_rules` passes.
- `sh scripts/verify-rust.sh` passes with `OSQ_CHANGE` set.
- Manual `cargo mutants` over `entry.rs` catches 66 mutants with 4 unviable and
  no missed mutant; over `lint.rs` it catches 24 with 8 unviable and no missed
  mutant.

## Deviated

- A task whose `scope` or `entry` already holds a brace group stays out of the
  entry rule. The existing `lint_task_rules` brace row expects only the two
  brace errors, while its non-brace entry would also be missing; task 3 may not
  edit that test, so such a task is skipped for entry findings.
- In the git scenario's uncommitted-file row, `crates/delta/src/local.rs` holds
  a valid `Implements:` tag rather than the table's `x`, because `lint` runs the
  link gates after the entry rule and an untagged Rust file would add a
  link-gate finding the scenario does not expect.

## Missing context

- The delta spec's "Task rule findings" brace row and "Lint entry paths"
  conflict: the first expects no entry findings for `crates/**/entry` and
  `crates/{x,y}/lib.rs`, while the second would report them. The task scope
  excludes `tests/lint_task_rules.rs`, so the implementation resolves the
  conflict by skipping a task that already has a brace group finding.
