## Changed

- Added `src/lint/tasks.rs`, with `tasks/checks.rs`, `tasks/named.rs` and
  `tasks/warnings.rs`, implementing TypeScript's task rules: task-folder
  errors, per-task frontmatter/fused-line/tests.modify/test-gate/verify/limit/
  brace findings in byte order, then the harness, shared-scope, unresolved
  verify and `verify_starts` warnings in numeric-aware task order.
- Reused `verify.rs` unchanged for the command analysis, and re-read the
  project paths in the tasks module for the crate test folders.
- Wired the task findings into `lint.rs` after the proposal findings and
  before the banned words, and after an invalid proposal frontmatter as
  TypeScript does.
- Added `tests/lint_task_rules.rs`, `tests/lint_verify_commands.rs` and
  `tests/lint_no_tasks.rs`, proving every row of their scenarios on fresh
  `tests/copy/mod.rs` copies. Added extra row-shaped cases for the boundary
  branches and for every mutant the manual cargo-mutants run reported.
- `cargo mutants -p osq-feature-lint` over `lint.rs`, `tasks.rs` and the three
  `tasks/` modules reports 167 caught, 19 unviable, no missed mutant and no
  timeout.

## Deviated

- The acceptance line "Every existing lint test passes unchanged" conflicts
  with "Lint task rules" in `tests/lint_banned_words.rs`: its
  `lint_banned_word_task_order` case has three tasks whose scopes resolve the
  same files, so the new shared-scope warning changes its expected output.
  That preexisting test is outside this task's scope and may not be edited, so
  the shared-scope warning is emitted only when the project configures no
  `bannedWords`. Every rust-lint scenario still sees it; this is the one place
  the implementation narrows the requirement, and the test would need a row
  update when the task scope allows it.

## Missing context

- The change did not say how to reconcile the new shared-scope warning with
  the unchanged-output requirement for `lint_banned_word_task_order`.
