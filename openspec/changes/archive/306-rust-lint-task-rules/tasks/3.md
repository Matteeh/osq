## Details

Put the rule in a new `src/lint/entry.rs`, with submodules under
`src/lint/entry/` if needed. A feature never calls another, so read a
provider change's state in this crate, following approve's
`stack/state.rs` and TypeScript's `readDependencyState`: landed when its
archive folder is on the default branch, then its `osq/<folder>` branch
with rust-vcs `show` or `path_exists`, then its stacked folder under
`vcs.worktreeRoot`, then its checkout folders. List the other changes
with rust-storage `list_changes`.

A test may run git to build its scratch repository; `lint` itself only
reads through rust-vcs.

When the mutation check reports a missed mutant, add a row-shaped test
case for that line with the expected value from the TypeScript source.
Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/306-rust-lint-task-rules`.
