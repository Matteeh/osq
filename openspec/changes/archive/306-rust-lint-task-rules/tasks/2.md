## Acceptance

- [ ] `lint` gives the task folder errors and each task file's findings, in byte order of its name, after the proposal findings, as rust-lint "Lint task rules" lists them.
- [ ] After the per-task findings, `lint` gives the harness, shared-scope, unresolved verify and `verify_starts` warnings in that order, with the tasks ordered as `banned.rs` orders task files, leaving the place between them for task 3's entry findings.
- [ ] New `tests/lint_task_rules.rs` proves "Task rule findings", new `tests/lint_verify_commands.rs` proves "Verify command analysis", and new `tests/lint_no_tasks.rs` proves "Change with no task files", each row on its own scratch copy from `tests/copy/mod.rs`.
- [ ] Every existing lint test passes unchanged.
- [ ] Every public item ends its doc with `Implements: rust-lint/<requirement>`, and each new test's doc names `Covers: rust-lint/<scenario>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Put the rules in a new `src/lint/tasks.rs`, with submodules under
`src/lint/tasks/` for the per-task checks and the cross-task warnings,
each a pure function, so the function budget holds. Reuse `verify.rs` from
task 1 and do not change it; a rule that needs more
goes in the tasks module.

Resolve a task's scope with rust-loop `scope_files` and keep the paths
that are regular files (`symlink_metadata` is a file), as TypeScript's
`resolveScope` does. Read `tests.modify` from the frontmatter rust-specs
`parse_frontmatter` gives, since `parse_task_file` folds a bad value to
false, and write a non-boolean value as JSON, mapping a YAML string,
integer, real, boolean, null, list or mapping to the same JSON value.

The task order for the warnings reuses the comparison `banned.rs` already
uses for task files; move it into a shared place only inside `tasks.rs`,
since `banned.rs` is not in this task's scope.

When the mutation check reports a missed mutant, add a row-shaped test
case for that line with the expected value from the TypeScript source.
Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/306-rust-lint-task-rules`.

## Scenarios

- rust-lint: Verify command analysis
- rust-lint: Change with no task files
- rust-lint: Lint fixture changes
