## Acceptance

- [ ] `run` hands `executor_prompt` the `PriorAttempt` and writes the `started` attempt that rust-run "Run attempts" says, in place of `PriorAttempt::default()` and the fixed attempt 1.
- [ ] New `crates/kernel/storage/tests/reading_retry_context.rs` proves "Retry contexts" and new `crates/features/run/tests/run_attempts.rs` proves "Prior context handed to pi", one test per scenario, each table row checked, each test's doc naming `Covers: <capability>/<scenario>`.
- [ ] Every existing storage and run test, the prompt goldens and "Executor exits" included, still passes unchanged.

## Details

Put the reader in `src/read/retry.rs`. Parse each line with `serde_json`
into a `Value`, not with core's `parse_event_line`: TypeScript reads these
lines loosely, and a field of the wrong type is passed over, not refused.
Take the marker body with `markdown_body` from `text.rs`, and strip the
ANSI codes with a small hand-written scanner, since the workspace has no
regex crate. Every expected value is in the delta's table; TypeScript's
`dist` printed it. Write each row's files under its own folder in
`CARGO_TARGET_TMPDIR`.

In the run, read the context in `after_lock` before the prompt is built,
and pass the attempt to `start::run`, so its `started_data` writes it.
Never read anything under `src/` from Rust; the TypeScript files are in
`entry` only so you can port them.

For "Prior context handed to pi", commit a new executable fake pi at
`tests/fixtures/record-pi/run.sh`, modelled on `fake-pi/run.sh`. pi runs in
the project root and gets the prompt as its last argument. The fake saves
that argument to a file beside the project folder, such as
`../<project folder name>.prompt`, so the scope audit never sees it, then
writes `src/a.txt` and the result file as the `done` mode does. Build each
row's root with `support::repo`, point `pi.bin` at the fake as
`run_outcomes.rs` does, and write the row's events and markers before the
run. Leave `fake-pi/run.sh` and `tests/support/mod.rs` as they are.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/281-rust-run-attempts`, so the link gates see
this change's new requirements.
