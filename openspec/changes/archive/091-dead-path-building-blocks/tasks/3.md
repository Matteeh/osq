## Acceptance

- [ ] New `src/core/run/dead-commit.ts` exports `commitDeadTask`, taking the `Vcs`, the config, the change folder, the task number, the reason, the title, and the outcome line, and doing what the watcher-and-harness delta's "Dead task record" says, in that order.
- [ ] The id in the subject is the folder's numeric prefix, and committed paths are relative to the worktree root.
- [ ] New `tests/dead-commit.test.ts` covers the three scenarios of "Dead task record" in a temporary repository with a linked worktree on an `osq/` branch, plus a missing `vcs.author` failing with no file written.

## Details

Get the `Vcs` in tests with `selectVcs` on the worktree path and a config with
`vcs: { enabled: true, author: 'osq <osq@example.org>' }`; never import
`GitVcs`. For "Patch before discard", pass a `Vcs` wrapper whose `discard`
throws. The worktree root is `vcs.root()`. The test writes `.run/dead/<n>.md`
and `.run/events/<n>.jsonl` itself, as the watcher would, before calling
`commitDeadTask`. Apply the patch in the test with `git apply` from the
worktree root after the dead commit.
