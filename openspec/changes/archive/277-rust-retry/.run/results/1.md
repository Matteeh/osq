## Changed

- Implemented `RetryFeature`'s `retry <id> <task|change>` command, with its argument errors, every refusal in TypeScript's `retrySpec` order, marker retention, the `retry` event and TypeScript's output lines.
- Split the implementation into private modules under `crates/features/retry/src/retry/`: folder matching, argument and id shaping, approval seal, running pid checks, marker/reason/scope-hash reads, record writes, text and UTC time.
- Added `osq-kernel-storage`, `osq-kernel-specs` and `serde_json` to the crate manifest; `Cargo.lock` follows.
- Copied the change's `fixture/retry-project` and `golden` folders unchanged into `crates/features/retry/tests/fixtures/`.
- Replaced the empty-feature test with command and argument-error tests, and added the golden and refusal tests plus their shared support module.

## Deviated

- The golden test also includes a fixed-time UTC test by including `src/retry/time.rs` through `#[path]`, as the run crate does, so the copied formatter's lines are covered.
- The refusal tests add cases beyond the two scenario rows for branches the golden rows do not reach: blank approval, zero and negative pids, empty scope hash, a non-string marker reason, a missing event folder, and the four conditions of recertification. They take their expected values from the TypeScript source.
