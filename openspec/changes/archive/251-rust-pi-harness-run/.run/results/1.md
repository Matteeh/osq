## Changed

- Added `resolve_pi_binary`, `assess_pi_version`, `preflight_pi` and the public
  `PiVersionRange`, `PiVersionAssessment`, `PiPreflight`, `PiReady` and
  `PiPreflightError` types, re-exported from the crate root.
- Split the pure parts into private `src/pi/preflight/` modules for binary
  choice, version parsing and range checks, auth-object reading, and error
  texts, with the process orchestration in `src/pi/preflight.rs`.
- Added `tests/pi_version.rs` and `tests/pi_preflight.rs`, plus the fake pi
  fixture `tests/fixtures/fake-pi/preflight.sh`.
- Ran the task verify, the change's full Rust verify with `OSQ_CHANGE` set, and
  cargo-mutants over the new preflight source files; it reported no missed
  mutants or timeouts.

## Deviated

- When the auth text is a JSON object with a status but a blank reason, and the
  auth run failed, the detail falls back to the object's status (the
  "Preflight with a fake pi" row expects `expired`) rather than the run-failure
  reason the requirement prose lists.
