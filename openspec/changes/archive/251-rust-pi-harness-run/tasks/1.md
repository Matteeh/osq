## Details

Port `resolvePiBinary`, `assessPiVersion` and `runPiAuthCheck` from
`src/core/foundation/config-pi.ts`, and `probePiVersion` and `preflightPi`
from `src/harness/pi/pi.ts`. Put the pure parts (binary choice, version
parse and range check, the auth object's status and reason, the error
texts) in private functions under `src/pi/preflight/`, and the orchestrator
that starts programs in `src/pi/preflight.rs`, declared from `src/pi.rs`.
Start both programs with the existing `run_process`, collecting stdout
lines through `on_line`; do not change the process runner. Parse the auth
text with `serde_json`, already a dependency.

Keep each condition observable for cargo-mutants: add a row-named test for
any branch the scenario tables leave unchecked rather than a branch no test
reaches.

Before exiting, run `cargo fmt --all`, then
`OSQ_CHANGE=openspec/changes/251-rust-pi-harness-run sh scripts/verify-rust.sh`
so the link-gate corpus test sees this change's requirements.
