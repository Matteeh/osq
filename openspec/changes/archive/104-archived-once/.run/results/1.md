## Changed

- Added `src/core/status/landed-copies.ts` with `filterLandedCopies`. It drops
  a worktree or stacked tree's archived or rejected folder when the project
  root tree (the checkout) holds the same folder in the same location. Active
  folders are never dropped.
- `listChanges` in `src/core/status/change-locations.ts` now runs each named
  tree's entries through `filterLandedCopies(trees[0], own)`. `changeTrees` is
  unchanged, so a kept worktree still contributes its tree.
- `buildSquashMessage` in `src/core/run/squash-message.ts` no longer reads
  `listChanges`. It resolves the matching worktree trees through `changeTrees`
  and checks each worktree's active and archive directories directly, so a
  checkout that already holds the archive after `git merge --squash` changes
  nothing. Every refusal message is unchanged.
- Added `tests/change-locations-landed.test.ts`: the two new "Change locations"
  scenarios (`listChanges`/`changeTrees` for an archive and a rejection held in
  both checkout and worktree), the "Landed change counted once" scenario read
  through `queueCommand`, `statusCommand`, `inboxCommand --json`,
  `inboxDispatchCommand --json`, and `reportCommand --json`, and "Checkout
  already holds the archive" through `messageCommand`.

## Deviated

- The two "Change locations" scenarios use a lightweight real git repo that
  writes the checkout and worktree archive/rejected folders directly, instead
  of running a full approval and watcher archive. The value under test is the
  resolver rule, not the landing flow; the full landing project is used for the
  command-level and `messageCommand` scenarios.
