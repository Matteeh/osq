## Changed

- `src/core/vcs/vcs.ts`: added `VcsWorktree` (`path`, `branch`, `head`) and the
  ten new `Vcs` members: reads `configValue`, `hookNames`, `listBranches`, and
  writes `createBranch`, `worktreeAdd`, `worktreeRemove`, `worktreeList`,
  `commit`, `patch`, `discard`.
- `src/core/vcs/git-vcs.ts`: `GitResult` now carries `stderr`; `runGit` takes
  optional `extraEnv`, applied after `GIT_DIR`/`GIT_INDEX_FILE`/`GIT_WORK_TREE`
  are removed, so only the patch's temporary index can reintroduce one. Added a
  private `runCommit` bounded by `timeouts.gitCommitSeconds`
  (`DEFAULT_GIT_COMMIT_SECONDS` from `config-vcs.ts`), a `GitWriteContext`, and
  delegating methods for every new port member; the existing reads are
  unchanged and still bounded by `timeouts.gitSeconds`.
- `src/core/vcs/git-vcs-write.ts` (new): all write and new-read logic.
  `createBranch`/`worktreeAdd`/`worktreeRemove` run plain git and throw git's
  combined stdout+stderr on failure. `commit` stages exactly the given paths,
  passes the message through a temporary file (never an argument) with
  `--author`, runs hooks, and returns `rev-parse HEAD`. `patch` copies
  `rev-parse --git-path index` to a temporary file, runs `add -A` and
  `diff --cached --binary HEAD` with `GIT_INDEX_FILE` pointing at the copy,
  then deletes it. `discard` asserts a linked worktree (`--git-dir` differs
  from `--git-common-dir`) and a HEAD branch starting `osq/` before touching
  anything, restores tracked paths with `checkout HEAD --`, and removes
  untracked files with `clean -fd --`, leaving ignored files alone.
  `hookNames` reads `rev-parse --git-path hooks` and returns executable,
  non-`.sample` files. `listBranches` uses `branch --list --format` with the
  prefix glob. `worktreeList` parses `worktree list --porcelain`.
- `src/core/vcs/no-vcs.ts`: the new reads return `null`/empty lists; every
  write throws `Error('git is off: <reason>')`.
- `tests/vcs-write.test.ts` (new): 16 tests. They cover every "Vcs write
  operations" scenario, the modified port's "Active hooks", `runGit`'s stderr
  and extra environment, a detach-HEAD worktree, `listBranches`/`configValue`,
  the `NoVcs` contract, and the two structural checks (no forbidden git
  argument literal under `src/core/vcs/`; the `Vcs` interface exposes exactly
  the intended members). Each test builds its own temporary repository and
  worktrees through a local `user.name`/`user.email`.

## Missing context

- The version-control delta says "the names of the active commit hooks", while
  the task Details defines a hook as active when it is an executable file whose
  name does not end in `.sample`. I followed the Details and did not add a
  commit-hook-name allow list, so an executable `pre-push` would be returned.
  If the planner wanted only the seven commit-lifecycle hooks, that filter
  belongs here.
- The delta fixes no message for a `NoVcs` write beyond "naming the reason git
  is off". I used `git is off: <unavailableReason>`, which contains the reason.
