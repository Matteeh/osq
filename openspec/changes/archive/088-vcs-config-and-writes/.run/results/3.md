## Changed

- `src/core/vcs/doctor-git.ts`: `gitCheck` now returns both its
  `DoctorCheckResult` and the selected `Vcs`, so `checkGit` can read the port
  without selecting twice. When `config.vcs.enabled` is true and the selected
  port is `GitVcs`, `checkGit` appends the three warnings immediately after the
  `git` line and before the existing `git-env` line:
  - `vcs-prepare` when one of `pnpm-lock.yaml`, `package-lock.json`,
    `yarn.lock`, `bun.lock`, or `bun.lockb` exists and `vcs.prepare` is unset;
    the message names every lockfile found and tells the reader to set
    `vcs.prepare` to the install command.
  - `git-hooks` when the port's `hookNames()` returns any commit-lifecycle
    hook; the message names each and says to check it runs unattended and
    leaves the tree as verified.
  - `git-signing` when the port's `configValue('commit.gpgsign')` is a git-truthy
    value; the message says to check signing runs without a prompt.
  Every warning is `ok: true, warning: true`, so doctor stays green and its
  exit code does not change. With `vcs.enabled` off, none are added.
- `tests/vcs-doctor-warnings.test.ts` (new): five tests through
  `runDoctorChecks` in real temporary repositories. They cover the lockfile
  warning (naming `pnpm-lock.yaml` and appearing after `git`), the executable
  `pre-commit` hook warning, `commit.gpgsign` set true in the repository's own
  config, `vcs.enabled` off adding none of the three, and a fully healthy repo
  where all three warn while `report.ok` stays true and `doctorCommand` calls
  its exit sink with nothing.

## Deviated

- The delta says `git-hooks` names "each active commit hook". `hookNames()`
  returns every executable non-`.sample` file, including non-commit hooks such
  as `pre-push`. I filter in `doctor-git.ts` to the four hooks git runs on a
  commit (`pre-commit`, `prepare-commit-msg`, `commit-msg`, `post-commit`)
  rather than every hook, because only those run during osq's `commit`. Task 2
  flagged this ambiguity and I resolved it here rather than widening the port.
