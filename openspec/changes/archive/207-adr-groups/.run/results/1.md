## Changed

- Added `src/core/foundation/decisions-groups.ts` exporting `appliesToGroup(entry)`,
  `readCapabilityGroups(projectRoot, config)` (living sidecars first, then each active
  change folder's `specs/<capability>/osq.yml` for a capability a living sidecar did not
  cover, change folders in name order, `archive`/`rejected` left out, malformed sidecars
  giving no group) and `resolveGoverns(appliesTo, groups)` (`all`, or the capability
  names and group members it lists, sorted and deduped). Each export carries `@scenario`
  tags for the cli-foundation scenarios it serves.
- `src/core/foundation/decisions.ts`: `Adr` gained `governs`; `DecisionRecords` gained the
  optional `groups` map; `readDecisions` reads the groups once through
  `readCapabilityGroups` and fills `governs` through `resolveGoverns` while keeping
  `appliesTo` as written. `systemWideAdrs` and `governingAdrs` now read `governs`, with
  their signatures unchanged.
- `src/core/foundation/decisions-validate.ts`: `validateDecisions` warns for each
  `group:<name>` entry no living capability's sidecar names, as
  `<path>: applies_to group "<name>" has no living capability`, and keeps the existing
  capability-name warning.
- Added `tests/decisions-groups.test.ts`, one case per table row for "ADR applying to a
  group" and "Group validation" plus "Group ADR governs a change", in temporary projects
  built the way `tests/decisions-read.test.ts` builds them.

Task verify and the proposal verify (`pnpm verify`) both pass.

## Deviated

- `readCapabilityGroups` builds the active-changes directory with
  `path.join(projectRoot, config.paths.openspecRoot, 'changes')` instead of calling
  `getChangesDir`. `tests/change-locations-readers.test.ts` (preexisting, outside this
  task's scope and not marked `tests.modify`) fails any file outside its allow list that
  calls `getChangesDir`/`getArchiveDir`, and the allow list is not in scope. The
  surrounding comment records why the path is built there.

## Missing context

- The task said which sidecar parser to use but not which seam to list active change
  folders through. `change-locations` would include worktree and stacked trees and sorts
  by numeric prefix, while the delta says "change folders in name order", so the direct
  readdir was used.

## Outside scope

- `src/core/spec/decisions-lint.ts` still tests `adr.appliesTo` for capability names, so a
  `group:<name>` entry is still treated as an unknown capability there (it would neither
  match a written capability nor warn). Task 2's "Group ADR governs a created capability"
  closes that; left untouched.
