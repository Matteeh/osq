## Changed

- `src/core/spec/decisions-lint.ts`: `unnamedAdrFindings` reads `adr.governs`
  instead of `adr.appliesTo`, so a `group:<name>` entry reaches the capability
  the change creates through its own sidecar. A system-wide ADR (`governs:
  'all'`) and an invalid one (`governs: []`) still produce no finding.
- `src/core/spec/traceability-links.ts`: `adrApplies` reads `adr.governs`, so
  an `@adr` tag counts when a `group:<name>` entry names a served capability.
- `src/core/web/system-graph-specs.ts`: the `applies_to` edges come from
  `adr.governs`; the ADR node still carries `appliesTo` as written.
- `src/docs/adr-page.ts`: `capabilitiesFor` takes `adr.governs` (living names
  for `all`, the resolved members for a list, empty otherwise), and the page's
  `appliesTo` stays `adr.appliesTo` as written.

  capability" through `lintChangeFolder` (fails unnamed, passes named),
  "Group ADR edges" through `getSystemGraph`, and "ADR page of a group ADR"
  through `buildAdrPages`, each in a temporary project built the way
  `tests/decisions-lint.test.ts` and `tests/web-system-graph.test.ts` build
  theirs.
