## Changed

- Added `blocks/limits.rs` with the `Limits` struct, one named constant per TypeScript default, `Limits::default()` and `read_limits`, which checks the table's keys under `limits` and reads every key with the shared positive-integer reader in the requirement's order.
- Added `blocks/banned_words.rs` with `BannedWord`, the named list-error reason and `read_banned_words`, which checks each entry's keys under `bannedWords` before reading and trimming `word` and `paths`, and reports every shape fault as the one `InvalidValue` on `bannedWords`.
- Extended `parse_config` and `Config` with `limits` and `banned_words`, adding both keys to `TOP_LEVEL_KEYS` after `pi`, reading them in that order, and giving `Limits::default()` and an empty list by default.
- Exported `Limits` and `BannedWord` from the crate root through `blocks/mod.rs` and `lib.rs`.
- Added `tests/config_limits.rs` covering all five limit scenarios and `tests/config_banned_words.rs` covering both banned-word scenarios, including the list error's display text.

## Deviated

- The shared integer reader is wrapped in a small private `limit` helper in `limits.rs`, mirroring `read_timeouts`' `seconds`/`millis` helpers, so each key falls back to its named default.
- Ran `sh scripts/verify-rust.sh` with `OSQ_CHANGE` set to this change, because the corpus link-gate test only sees the delta's new requirements and scenarios when that variable names the change.

## Outside scope

- Running the proposal verify without `OSQ_CHANGE` makes `link_gates_corpus` report the new `Implements:`/`Covers:` tags as unknown, since the living spec does not hold them until archive. With `OSQ_CHANGE` set, as osq's own verify does, it passes.
