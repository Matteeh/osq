## Acceptance

- [ ] New `blocks/limits.rs` holds `Limits`, one named constant per TypeScript default, and a `read_limits` that checks the table's keys with `value::check_keys` under the prefix `limits`, then reads each key in the requirement's order with `value::positive_integer`, as `read_timeouts` reads its keys.
- [ ] New `blocks/banned_words.rs` holds `BannedWord` and a `read_banned_words` that takes the raw `bannedWords` value and does what rust-config "Banned words" says, checking each entry's keys with `value::check_keys` under the prefix `bannedWords` before reading `word` and `paths`. Every other fault returns the one `InvalidValue` with reason `must be a list of { word, paths } entries`, kept as a named constant.
- [ ] `parse_config` in `config.rs` adds `limits` and then `bannedWords` to `TOP_LEVEL_KEYS` after `pi`, reads them in that order into the new fields `Config.limits` and `Config.banned_words`, and `Config::default()` gives `Limits::default()` and an empty list. `Limits` and `BannedWord` are exported from the crate root.
- [ ] New `crates/kernel/config/tests/config_limits.rs` proves "Limit defaults", "Every limit set", "One limit set", "Each limit refuses zero" and "Limit errors", one assertion per row, each test doc naming its `Covers: rust-config/<scenario>` line.
- [ ] New `crates/kernel/config/tests/config_banned_words.rs` proves "Banned words read" and "Banned word errors", one assertion per row, and asserts the list error's display text, each test doc naming its `Covers: rust-config/<scenario>` line.
- [ ] The existing config tests, `config_file.rs` among them, pass unchanged.

## Scenarios

- rust-config: Limit defaults
- rust-config: Every limit set
- rust-config: One limit set
- rust-config: Each limit refuses zero
- rust-config: Limit errors
- rust-config: Banned words read
- rust-config: Banned word errors
