## Changed

- Added `templates/decisions/README.md`: describes the ADR frontmatter osq
  reads (`status`, `applies_to`, `rule`, `superseded_by`, `checks`, `denies`),
  that only accepted ADRs take effect, and that the number comes from the file
  name. It mirrors the repository README's `## Format` section without the
  index or osq's own ADR names.
- Added `templates/decisions/000-how-this-project-is-built.md`: a proposed
  starter with `status: proposed`, `applies_to: all`, and no `rule`, headed
  `# 000. How this project is built`, with `## Layering`, `## State`,
  `## Errors`, `## Tests`, and `## Naming` questions in order and a closing
  section on turning answers into accepted ADRs. It prescribes no answer.
- `src/core/foundation/init.ts`: added `writeDecisionsScaffold`, which writes
  `<paths.decisions>/README.md` whenever missing and the starter when the
  starter file already exists or the folder holds no markdown other than the
  README, both through `writeOrRefreshFile` with `refresh` false and
  `TEMPLATES_ROOT`. `scaffoldProject` now calls it once; the helper and call
  keep `scaffoldProject` and `init.ts` under their line budgets.
- `src/core/foundation/doctor-decisions.ts`: `checkDecisions` now appends
  `no accepted ADR applies to all; write the architecture and style ADRs
  first` to the validation warnings (joined with `; `) whenever
  `systemWideAdrs` is empty, and warns when either source is non-empty.
- `src/core/spec/decisions-lint.ts`: `collectDecisionsFindings` now returns no
  findings unless at least one ADR is `accepted`; doc comments updated to match.
- `tests/decisions-scaffold.test.ts` (new): covers the "Decisions scaffold"
  scenarios (fresh project, re-run keeps edits, project with ADRs), the
  "No system-wide ADR" and "System-wide ADR accepted" doctor scenarios, and
  the "Only a proposed ADR" lint scenario through `lintChangeFolder`.
- `tests/pi/doctor.test.ts`: both check-name lists gain `decisions` after
  `managed-blocks`.
- `tests/codex/adapter.test.ts`: "doctor probes the same configured Codex
  binary and reports failures" now expects 10 lines.
- `tests/decisions-lint.test.ts`: "warns when the section names an ADR that is
  not accepted" also writes an accepted capability-scoped ADR so the lint gate
  opens and the warning is still checked.
