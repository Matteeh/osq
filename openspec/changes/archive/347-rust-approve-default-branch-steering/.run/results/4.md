## Changed

- Added `approve/default_branch/conflict.rs`: it sorts a `sync_conflict` stop's paths into planning paths and paths a task's scope owns, picks the done tasks to reopen and keep, formats the `  Reopened ` line, and orchestrates the resolving sync, the `.run/done/<n>.<k>` renames and the `retry` event lines.
- `default_branch::sync` now routes a `sync_conflict` stop through the conflict module, records a planning stop when no task owns a conflicting path, records the resolving sync's commit and any later stop, and returns the reopen result.
- `default_branch::approve` re-reads the change after every write so `  Continues from task <n>` reflects the reopened done markers, and passes the `  Reopened ` line to the output.
- `text::default_branch` prints the `  Reopened ` line between `  Merged ` and `  Continues from task `.
- Added `tests/approve_conflict_reopen.rs`, covering every row of "Conflicts reopen the owning tasks" and "Conflicts no task owns stop for planning", plus retained-ordinal cases and a non-conflict stop case needed to kill the remaining mutants.

## Deviated

- Added two tests beyond the scenario tables, `retained_ordinals_are_used` and `a_non_conflict_stop_is_recorded`, because cargo-mutants reported missed mutants on the ordinal scan and on the `sync_conflict` match guard. Both are tagged with the scenario they serve.
