## Changed

- Widened the approval reaction's stream check in
  `crates/features/retry/src/retry/reaction.rs`: a target is skipped when its
  stream holds, at or after the `approved` event, a `retry` event for that
  target or a `regressed` or `dead` event whose task is that target. Renamed
  the check to `failure_at_or_after` and updated its docs.
- Added `crates/features/retry/tests/retry_reaction_later.rs`, proving every
  row of rust-retry "Failures recorded after the approval are kept" through
  `Reaction::new`, plus a companion case for older, untargeted and change-less
  failures so every branch of the widened check is exercised.

## Deviated

- The new test file has one extra test beyond the scenario table,
  `older_other_and_untargeted_failures_do_not_skip`. It covers the false
  branches of the widened event matching and timestamp comparison, so the
  mutation check has no missed mutant on the new logic.
