## Details

Add `osq-kernel-sync.workspace = true` to the crate's `[dependencies]`.
Cargo updates `Cargo.lock` itself; list it under Touched.

Put the approval in its own module beside `steered.rs`, with the
replanned commit, the spec copies, the stop record and the done-marker
refresh as small named functions, and give task 4 one seam: a function
that takes the `sync_conflict` `SyncStop` and, for now, records it as an
approval stop. Reuse `steered.rs`'s event append and `write_marker`, and
`worktree.rs`'s `Recorder` for the `commit` records, in the order the
golden's `record:` lines show. Take the default branch as `refuse.rs` takes
it.

`lookup.rs`'s `active_approved` picks the worktrees `change_trees` is
built from. Widen it to the archived marker, and pick the archived match
after every active one, as the requirement says. `steering.rs`'s
`Trigger::is_default_branch` already classifies.

The spec copies follow TypeScript's `rebuildLivingSpecs` with `archived`
false and no conflicts: the capability folders under the worktree's
`openspec/specs/` and the change's delta capabilities, once each in byte
order, each written from the default branch with rust-vcs `show`, or
removed, then staged. The done-marker refresh uses rust-storage
`read_done_scope`, `task_scope_hash` and `refresh_done_marker`.

To build the repositories, reuse `worktree_support`'s public helpers as
they are, from the new test files. Port the rest of the case setup from
the golden script: the archived or active folder in the worktree on
`osq/001-alpha-twice`, the old seal, `.run/done/1` with rust-storage
`task_scope_hash`, the case's marker, the commit as `Osq Tester` with
`GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE` set to the script's `DATE`, then
`main moved` and the uncommitted edit to `tasks/1.md`. Read the commits,
branches and tree with `git` exactly as the script does, and write
`<root>` and `<main>` as it writes them. The test calls the feature's
`run`, so no event is delivered: the golden's `regressed/change.1.md` and
`retry` line are retry's work, which only the CLI test in task 5 compares.

Never read anything under `src/` from Rust; it is in `entry` only so you
can port it. Never depend on the land or retry crate. When the mutation
check reports a missed mutant, add a test case for that line. Run the
proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/347-rust-approve-default-branch-steering`, so
the link gates see this change's new requirements.
