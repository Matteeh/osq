## Details

`sync.rs`'s `Sync::run` matches the merge outcome and hands the conflicted
paths to `text::conflict_stop` and then `steps`. Thread the listed paths
through `run` into the `Sync` value, and between the merge and
`conflict_stop` resolve each listed conflicted path with the worktree's
`GitVcs`: `show(default_branch, path)` gives the text to write, `None`
means remove the file, then `stage(&[path])`. Pass only the paths left
conflicted to `conflict_stop` and `steps`. The existing `finish` aborts the
merge on a stop, which undoes the resolution too.

Build the repositories with `tests/support/mod.rs`'s public helpers as they
are: `mod support;` from the new file, then `SyncRepo::new`, `main_file`,
`add_archived_change`, `write` and `commit_all` as `sync_outcomes.rs` uses
them. `SyncRepo::sync` calls `sync_change`, so build the `SyncRequest`
the way it does and call `sync_change_taking_default` directly for each
row. Port any helper you need into the new file rather than changing
`support/mod.rs`.

Run the proposal's verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/347-rust-approve-default-branch-steering`, so
the link gates see this change's new requirement.
