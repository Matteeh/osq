## Acceptance

- [ ] `show` loads `osq.toml`, decides git on and finds the change as "Show git state" and the MODIFIED "Show lookup" say, and prints the `Next:` line of the MODIFIED "Show status and next step".
- [ ] For an archived change, the land section prints the headline, the `Diff:` line and the `Sync stopped:` line as "Show land lines" says, in TypeScript's `landLines` order.
- [ ] The seven files in this change folder's `goldens/` are copied unchanged into `tests/fixtures/golden/`, and `print-land-goldens.mjs.txt` beside them.
- [ ] A new `tests/show_land.rs` proves "Show land lines equal TypeScript's" for every row and "Show refuses a bad config". Each test's doc names `Covers: rust-show/<scenario>`, and each row builds its own git repository.
- [ ] `Cargo.toml` adds `osq-kernel-config` and `osq-kernel-vcs` with `workspace = true`, and `Cargo.lock` follows. Every earlier show test passes unchanged.
- [ ] Every public item ends its doc with `Implements: rust-show/<requirement>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Port `readGitFields` and `headline` from TypeScript's
`show-land-model.ts` and `show-land-lines.ts`, the stop rule of
`readLastSync` from `last-sync.ts`, and the vcs branch of
`readArchivedNextStep` from `next-step.ts`. Read the config and git once
per run, in one reader module, and pass the facts to the model and the
land section; keep the line builders pure. Build the change trees as the
inbox crate's `read.rs` does, and reuse `NextStep::new` for the new
`archived` step.

The existing goldens stay as they are because their scratch copies sit
under `CARGO_TARGET_TMPDIR`, inside a repository whose top level is not
the copy, so git is off there.

In the test, build each row as `print-land-goldens.mjs.txt` does. Run git
with `std::process::Command`, isolated and with fixed author and committer
as the land crate's `tests/support/mod.rs` `git` does (copy that helper;
do not import it), and set `commit.gpgSign` to `false`. Canonicalize each
scratch root, put the worktree beside the checkout inside the row's own
scratch folder, and write `osq.toml` before the first commit for a row
with `vcs.enabled`. Compare each whole output with its golden, and also
assert the row's `Next:` and `Land:` lines from the table.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source. Run the proposal's verify as the watcher does,
with `OSQ_CHANGE=openspec/changes/287-rust-show-land-lines`, so the link
gates see this change's new requirements.
