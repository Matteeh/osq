## Changed

- Added `src/core/spec/lint-findings.ts`: the `LintFinding` type (`severity`,
  `file`, `requirement`, `section`, `message`), `makeFinding`, the shared
  `openSpecSeverity` classifier, and `LintFindingSet`, which keeps the change's
  own findings apart from repository findings and derives the legacy `errors`
  and `warnings` message arrays from the change's own findings only.
- Added `src/core/spec/openspec-issues.ts`: `parseOpenSpecItems` reads OpenSpec
  JSON `items`; `scanOpenSpecIssues` maps each issue to a finding, resolves
  `requirements[<index>]` against the living spec with `parseCapabilitySpec`,
  reads a change issue's requirement from its `ADDED "<name>"`-style message,
  attributes own versus repository by item `type`/`id`, and appends the
  unsupported-`skip_specs` note. `execFileCapture` moved here and is shared with
  `merged-spec-check.ts`.
- Added `src/core/spec/merged-spec-check.ts`: `validateMergedSpecs` writes every
  mergable delta's `mergeDelta` text into one temporary tree, runs
  `openspec validate --specs --strict --json --no-interactive` once with
  `OPENSPEC_TELEMETRY=0` and the configured timeout, removes the folder, and
  returns findings whose file is the delta file with message
  `openspec: <capability> after archive: <message>`, omitting any issue the
  living spec already carries on the same requirement or section.
- Reworked `src/core/spec/linter.ts` to build `LintFindingSet` for every check,
  set repository-relative `file` (and `requirement`/`section` where defined),
  keep every existing message except the chained verify refusal, add `findings`
  and `repository` to `LintResult`, make `valid` depend only on the change's own
  errors, pass the linted change's folder name to `validateWithOpenSpec`,
  attribute OpenSpec `items` via the new scanner (falling back to the existing
  `parseOpenSpecFindings` for items-less output), and run merged spec validation
  from `verifyDeltaTargets` using the change's repository findings.
- Added `tests/lint-findings.test.ts`: lints temporary scaffolded projects with
  the repository's real OpenSpec binary and asserts finding fields for every
  ADDED delta scenario except the three output ones.
- Updated the pinned assertion in `tests/linter.test.ts`'s "retains the chaining
  diagnostic without reinterpreting it" to reject the more specific
  `that is not defined in the root package.json` phrase.

## Deviated

- The legacy items-less fallback lives in `linter.ts` (`addLegacyFindings`, using
  the existing `parseOpenSpecFindings`) rather than in `openspec-issues.ts`.
  `scanOpenSpecIssues` returns `null` for items-less output. This keeps
  `parseOpenSpecFindings` where it already was and avoids a circular import
  between `linter.ts` and `openspec-issues.ts`.
- Kept `parseOpenSpecFindings` in `linter.ts` for the same reason, so acceptance
  item 3's "parsed by the existing `parseOpenSpecFindings`" is satisfied by the
  existing function rather than a move.
- Shared the OpenSpec level-to-severity classifier as `openSpecSeverity` in
  `lint-findings.ts` instead of duplicating it in `openspec-issues.ts` and
  `merged-spec-check.ts`.
