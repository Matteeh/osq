## Changed

- Added `src/core/spec/lint-output.ts`: `formatFinding` /
  `formatChangeFinding` / `formatRepositoryFinding` render
  `<prefix>: <severity> <file> (<requirement or section>): <message>` with the
  parenthesis omitted when both are null; `dedupeFindings` drops findings equal
  in every field; `printChangeFindings` prints a change's findings at `error`
  or `warn` and its `<change>: valid` line at `info`; `printRepositoryFindings`
  prints the fixed repository header plus each unique finding, or nothing when
  empty; `buildLintJson` builds the `{ valid, changes, repository }` document.
- `src/cli/lint.ts`: `LintCommandOptions` gained `json` and `stdout`; text mode
  prints through the new helpers, the repository group is deduplicated across
  every linted change and never affects the exit code; JSON mode writes one
  document plus newline through the sink (default `process.stdout.write`),
  emits no logger lines, and passes no logger into `lintChangeFolder`, so the
  OpenSpec version info line is absent. The exit path is unchanged and shared
  by both modes.
- `src/cli/index.ts`: `osq lint` registers `--json` (description
  `print findings as JSON`) and passes it to `lintCommand` with a sink writing
  to `process.stdout`.
- Added `tests/lint-output.test.ts`: four cases running `lintCommand` on
  temporary scaffolded projects with the repository's real OpenSpec binary,
  covering the error/warning text lines with severity, file, and requirement;
  the same fields in the JSON document with an empty recording logger; one
  repository warning printed once under a single header after two changes with
  `exit` never called; and no header when there are no repository findings.

## Deviated

- The JSON document is compact (`JSON.stringify`) rather than pretty-printed;
  the spec only fixes its structure, so this keeps the sink output single-line.
- `repository` in JSON mode is deduplicated with the same `dedupeFindings` used
  for text. The spec requires dedup only for the printed group, but sharing the
  helper keeps the two modes consistent.
- Added a fourth test (no repository header when there are none) beyond the
  three named scenarios, to pin acceptance line 3's "prints no header when
  there are none".
