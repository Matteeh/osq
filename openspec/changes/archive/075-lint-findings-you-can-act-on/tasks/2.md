## Acceptance

- [ ] New `src/core/spec/lint-output.ts` formats a change's finding and a repository finding as the delta's "Lint output" and "Repository lint output" say, and builds the document "Lint JSON output" describes from the lint entries.
- [ ] `lintCommand` prints each change's `findings` in that format through `logger.error` for errors and `logger.warn` for warnings, and `<change>: valid` through `logger.info` when the change is valid.
- [ ] After every change, `lintCommand` prints the "Repository lint output" header line and then the `repository` findings of all linted changes once each, dropping findings equal in every field, through the level that matches their severity. It prints no header when there are none, and repository findings never set the exit code.
- [ ] `lintCommand` accepts `json` and a `stdout` sink in `LintCommandOptions`; with `json` it writes the JSON document through the sink, followed by a newline, prints no logger lines, and passes no logger to `lintChangeFolder`, so the OpenSpec version line is not printed either. The exit code is the same as without `json`.
- [ ] `src/cli/index.ts` registers `--json` on `osq lint` with the description `print findings as JSON` and passes it to `lintCommand`, writing to `process.stdout`.
- [ ] New `tests/lint-output.test.ts` runs `lintCommand` on temporary projects with the repository's real OpenSpec binary and covers the scenarios of "Lint output", "Repository lint output", and "Lint JSON output": an error and a warning line with their severities, file, and requirement, the same fields in `json`, and one repository warning printed once after two changes while `exit` is never called.

## Details

Build the temporary projects the way `tests/lint-findings.test.ts` does. A task
verify that chains commands gives an error on a task file; a delta ADDED
requirement without `SHALL` or `MUST` gives a warning with a requirement name. A
living spec with a requirement longer than 500 characters gives a repository
warning. Keep `lintCommand` at 80 lines or fewer by putting formatting and
deduplication in `lint-output.ts`. `tests/scope-lint.test.ts` and
`tests/lint-skip-rejected.test.ts` read the recorded logger lines and must keep
passing unchanged.
