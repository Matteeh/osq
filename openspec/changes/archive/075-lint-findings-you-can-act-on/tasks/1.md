## Details

Set up each temporary project as `tests/lint-skip-rejected.test.ts` does, with
`installFakeValidator` from `tests/helpers.ts` for the version manifest and
`scaffoldProject` and `createNewSpec` for the change, and point lint at the real
binary through config: `{ ...DEFAULT_CONFIG, openspec: { bin } } as OsqConfig`,
where `bin` is the absolute path of this repository's
`node_modules/.bin/openspec`. `resolveOpenSpecBin` accepts an absolute path.
A clean change needs a delta, because OpenSpec refuses a change without one;
that refusal is also the `skip_specs` case. A requirement longer than 500
characters gets OpenSpec's `INFO` issue "Requirement text is very long". A new
capability whose delta `## Purpose` is one word gets the `WARNING` "Purpose
section is too brief (less than 50 characters)" only after the merge.

Keep `linter.ts` from growing where you can: put the new logic in the three new
modules and call them from `linter.ts`. New functions stay at 80 lines or fewer.
Do not change `src/cli/lint.ts` or `approve.ts`; they read `valid`, `errors`,
and `warnings`, which keep their meaning.
