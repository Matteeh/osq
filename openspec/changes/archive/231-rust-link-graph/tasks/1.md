## Acceptance

- [ ] New `crates/core/src/graph.rs`, with files beside it under `crates/core/src/graph/` as you see fit, holds `NodeId`, `Location`, `Node`, `EdgeKind`, `Edge`, `Graph`, `Rule`, `Finding`, `run_rules` and `tag_id`, following rust-core "Link graph", "Tag ids" and "Link rules".
- [ ] `NodeId` is an enum with one `String` per variant, in the requirement's variant order, deriving `Ord` so ids sort by variant and then by key. `NodeId`, `Location` and `Finding` implement `Display` as the requirement says. `Node`, `Edge`, `Location` and `Finding` have public fields. All types derive `Debug`, `Clone`, `PartialEq` and `Eq`, and `Graph` also `Default`.
- [ ] `Graph` keeps nodes in a `BTreeMap<NodeId, Node>` and edges in a `Vec<Edge>`. `add_node`, `add_edge`, `node`, `nodes`, `edges`, `edges_of`, `edges_from`, `edges_to` and `dangling` behave as "Link graph" says.
- [ ] `Rule` has `fn name(&self) -> &str` and `fn check(&self, graph: &Graph) -> Vec<Finding>`, and `run_rules(graph: &Graph, rules: &[&dyn Rule]) -> Vec<Finding>`.
- [ ] `src/lib.rs` declares `pub mod graph;` and re-exports those ten items from it.
- [ ] New `crates/core/tests/graph.rs` proves every scenario below with literal values copied from the scenario tables. "Rules run in order" uses two rules written in the test, `dangling` and `quiet`.
- [ ] Every public function and method ends its doc with `Implements: rust-core/link-graph`, `Implements: rust-core/tag-ids` or `Implements: rust-core/link-rules`. Each test has a one-line doc naming `Covers: rust-core/<scenario>` with the scenario in kebab-case, such as `Covers: rust-core/node-id-display`, never the scenario's title.

## Details

Core does no IO (rust-core "Core does no IO"): no file under
`crates/core/src/` may contain the text `std::fs`, `std::process`,
`std::env`, `std::net`, `std::thread`, `SystemTime` or `Instant`, comments
included, and core gains no dependency.

`tag_id` works on ASCII only: `é` is a separator like a space.

`run_rules` is the only caller of `Rule` in `src/`; the trait exists for
`rust-link-gates`, and the test's two rules are its implementations for
now (ADR 023 allows a trait a test double needs).

cargo-mutants runs on every line this task adds. Each query and each
`Display` arm has to change a value a scenario checks. Before exiting, run
`cargo mutants -p osq-core -f <file> -o "$(mktemp -d)"` on each new
source file.
