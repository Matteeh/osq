## Details

The fixture is data, not code: it is never compiled, and `cargo fmt`
does not reach it. Never edit it. If a row of the table fails, the reader
is wrong.

Rules that are easy to miss:

- A doc attribute's value is split into lines; `#[doc = "a\nb"]` gives two
  tags, both at the attribute's line.
- `fn nested` inside `add`'s body and the `fn $name` inside
  `macro_rules! cases` are not items.
- In `proptest!`, `///` comments arrive as `#[doc = ...]` attribute tokens.
  `#![proptest_config(...)]` is an inner attribute and belongs to no
  function.
- `pub(crate)` is not public. A trait method is public when the trait is.
  A trait `impl`'s methods are never public.

cargo-mutants runs on every line this task adds. Each rule has a row in
the fixture table, so a mutant in naming, lines, visibility, test
detection or tag parsing changes a checked value. If a mutant survives
that the fixture cannot reach, add a fast test in a new
`tests/code_tags_edges.rs` with its own source text. Before exiting, run
`cargo mutants -p osq-kernel-linter -f <file> -o "$(mktemp -d)"` on each
new source file.
