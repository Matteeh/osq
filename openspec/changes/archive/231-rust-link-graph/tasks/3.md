## Details

The fixture is data: it is never built, and `cargo fmt` does not reach it.
Never edit it or the scenario tables. If a row fails, the builder is
wrong; say in `## Deviated` which rule you found and how you matched it.

Rules that are easy to miss:

- ADR edges come before spec nodes, and ADR `governs: all` edges go to
  every `Capability` node, so read the living specs before adding ADR
  edges, while keeping the edge order the table gives.
- `supersedes` points from the newer ADR to the one that holds
  `superseded_by`, and the number resolves by value: `3` names `003`, and
  `7` stays `adr:7`.
- An `Adr:` tag's edge runs from the ADR to the item, the reverse of
  `implements` and `covers`.
- Only folders directly under `<openspec>/specs` holding `spec.md` are
  capabilities; `notes/` is not. `crates/gamma` is not a member,
  `crates/beta/build.rs` is outside `src/` and `tests/`, and
  `crates/alpha/tests/fixtures/` is never read.
- A missing `decisions` or `openspec` folder adds no nodes; it is not an
  error.

The corpus test reads the files of the graph's `File` nodes and counts tag
lines with plain text matching, so it checks the `syn` reader by a second
method. Do not fix any tag the graph reports as dangling; those are
outside this task.

cargo-mutants runs on every line this task adds; the fixture tables cover
each step and edge kind. Before exiting, run
`cargo mutants -p osq-kernel-linter -f <file> -o "$(mktemp -d)"` on each
new source file.
