## Acceptance

- [ ] `seal.rs` adds `ComputedSeal`, a tuple struct around a private `Seal`, which derives `Clone`, `Debug`, `PartialEq` and `Eq`, and has `as_str` and `seal` readers. `compute_seal` returns it, `lib.rs` re-exports it, and storage's `change_folder_seal` returns `Result<ComputedSeal, StorageError>`. `Change::approve` takes `computed: ComputedSeal`, and `ApproveError::SealMismatch` keeps `computed: Seal`.
- [ ] `ChangeState`'s `record` and `tasks` fields become private. `record()` returns `&ChangeRecord` and `tasks()` returns `&BTreeMap<TaskId, TaskState>`, and `change_status` and `next_task` read through them. `ChangeState` keeps `new`, `Clone`, `Debug`, `PartialEq` and `Eq`, and loses `Default`.
- [ ] `compile_fail` doc tests, written like the four on `Change` in `change.rs` and each with the error code rustc reports, prove rust-core "Gates cannot be skipped" for the new forgeries. These are: `approve` given a `Seal` as its computed seal, a `ComputedSeal` built by hand, a `ChangeState` built by hand, and a write to a `ChangeState`'s `tasks` or `record`.
- [ ] The `change_state` helpers in `tests/gates.rs` and `tests/fold.rs`, and the done state in `tests/edges.rs`, build their states with `ChangeState::new` and `apply` over event lines read with `parse_event_line`, such as `started`, `done`, `dead`, `regressed` with a task `n`, and on the change stream `regressed` with task `change`, `archived` and `rejected`. Every case and expected value in those tests stays as it is. Approvals take the seal from `compute_seal`, and `approve_checks_the_seal` and `a_change_keeps_its_id_and_tasks` follow the new tables of "Approve checks the seal" and "A change keeps its id and tasks". `archive_corpus.rs` and `reading_snapshot.rs` read `state.record()` and `state.tasks()`.
- [ ] New `tests/sealed_gates.rs` proves rust-core "Computed seal reads back" and "Folded state reads back". Each test has a one-line doc naming `Covers: rust-core/<scenario>` and has no `#[ignore]`. `ComputedSeal::as_str`, `ComputedSeal::seal`, `ChangeState::record` and `ChangeState::tasks` end their docs with an `Implements: rust-core/<requirement>` line.

## Details

Only `fold/change.rs` can see the private fields. `fold/status.rs` and
`change.rs` are sibling modules, so they need the readers. The
`event(line)` helper in `tests/fold.rs` already parses event lines. Write
the other files' lines in the same envelope form. The fold's own rules
give each status: `started` gives `Running`, `done` gives `Done`, `dead`
gives `Dead`, and `regressed` on a task stream gives `Regressed`. The
change-stream events are `regressed` with task `change`, `archived` and
`rejected`. The record helpers in `tests/fold.rs` that build a
`ChangeRecord` for `apply_change` keep working, because `ChangeRecord`'s
fields stay public. `seal_compute.rs`, `reading_seal.rs` and
`seal_corpus.rs` only call `.as_str()` and need no change. Run the doc
tests with `cargo test -p osq-core --doc` before you exit; the change-level
verify runs them too.
