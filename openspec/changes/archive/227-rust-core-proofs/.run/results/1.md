## Changed

- `crates/core/src/seal.rs`: added `ComputedSeal`, a tuple struct around a private `Seal` with `as_str` and `seal` readers; `compute_seal` now returns it.
- `crates/core/src/lib.rs`: re-exported `ComputedSeal`.
- `crates/core/src/change.rs`: `approve` takes `computed: ComputedSeal` and puts `computed.seal()` into `SealMismatch`; `next_task` reads through `ChangeState::tasks()`. Added the `E0308` compile-fail doc test for a bare `Seal` as the computed seal.
- `crates/core/src/fold/change.rs`: made `ChangeState`'s fields private, dropped `Default`, added `record()` and `tasks()`, and added `E0451`/`E0616` compile-fail doc tests for building or writing a state by hand.
- `crates/core/src/fold/status.rs`: `change_status` reads through `record()` and `tasks()`.
- `crates/core/tests/gates.rs`, `tests/fold.rs`, `tests/edges.rs`: states are now built with `ChangeState::new` and `apply` over parsed event lines; approvals take `compute_seal`'s seal; field reads use the readers.
- `crates/core/tests/sealed_gates.rs`: new tests for "Computed seal reads back" and "Folded state reads back".
- `crates/kernel/storage/src/read/seal.rs`: `change_folder_seal` returns `Result<ComputedSeal, StorageError>`.
- `crates/kernel/storage/tests/archive_corpus.rs`, `tests/reading_snapshot.rs`: read `state.record()` and `state.tasks()`.

## Deviated

- `ComputedSeal::seal` takes `self` by value and returns `Seal` rather than borrowing. Passing a by-value `ComputedSeal` to `approve` without consuming it tripped clippy's `needless_pass_by_value` under `-D warnings`, and an `#[allow]` is forbidden. Consuming the computed seal in `approve` keeps the required signature and satisfies clippy.
- The new `ComputedSeal` hand-build doc test names `E0423` (cannot initialize a tuple struct with private fields), which is the code rustc reported; `E0603` was not what this case emits.

## Outside scope

- The four pre-existing `compile_fail` doc tests on `Change` name `E0603` for the `Change<Archived>` forgery, but rustc reports `E0423` for a tuple struct constructor with a private field. They still fail to compile and the doc tests pass; I left them alone because the task only asked for the new forgeries.
