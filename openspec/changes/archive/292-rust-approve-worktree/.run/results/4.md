## Changed

- Added `approve/stack.rs` and `approve/stack/{capabilities,changes,order,state,text}.rs`: with git on, `approve` now refuses a change TypeScript's `awaitedForApproval` would stack, after the other refusals and before the rejected-branch claim or any write.
- The refusal lists each approved or archived `depends_on` folder in proposal order, then each other approved or archived change folder that shares a delta capability, sorted by name, each folder once, and prints `Change <folder> would stack on <folders>. Rust approve does not stack approvals yet.`.
- Change folders are read from the root, the `osq/` worktrees and the folders under `stacked_root` with `worktree_list`, `change_trees` and `list_tree_changes`; `depends_on` is read with the specs kernel's `read_proposal` and matched with `find::matches`, now `pub(crate)`.
- A folder's state is read in TypeScript's `readDependencyState` order: the default branch's archive, then its `osq/` branch's archive or approval marker, then the stacked copy or checkout markers on disk.
- Added `tests/approve_stacking.rs`, proving every row of "Stacking refusals" through the unchanged `tests/worktree_support/mod.rs` helpers, plus a checkout-marker case.

## Deviated

- Declared the new `stack` module from `approve/refuse.rs` with `#[path = "stack.rs"]` instead of from `approve.rs`, because `approve.rs` is outside this task's scope and the check had to stay in `approve/stack.rs`.
- Added the extra test `checkout_marker_awaits`: `cargo mutants` reported a missed mutant on the checkout marker's `||` in `stack/state.rs`, so the test proves a checkout `openspec/changes/<f>/.run/approved` alone makes a `depends_on` folder await approval.
- `stack/changes.rs` uses the repository root it is given rather than reading `vcs.root()` again, since git on has already established that the checkout is the repository root.
