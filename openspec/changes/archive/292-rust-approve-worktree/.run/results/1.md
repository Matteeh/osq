## Changed

- `crates/kernel/vcs/src/git/write.rs`: added `delete_branch`, running `branch -d <name>` and never `-D` or `--force`.
- `crates/kernel/vcs/src/port.rs` and `crates/kernel/vcs/src/git.rs`: added `delete_branch` to the `Vcs` trait and implemented it for `GitVcs`.
- `crates/kernel/vcs/src/record.rs` (new): exported `append_tree_record(path, at, op, root)`, writing `{"at":<at>,"op":<op>,"root":<root>}` with `serde_json`-encoded string values and a newline, ignoring every open or write failure.
- `crates/kernel/vcs/src/git/state.rs` and `crates/kernel/vcs/src/git.rs`: added `GitVcs::tree_record_path`, reading `rev-parse --git-common-dir`, resolving a relative answer against the root, joining `osq-trees.jsonl`, and giving none when git refuses or prints nothing.
- `crates/kernel/vcs/src/lib.rs`: module and re-export for `append_tree_record`.
- `crates/kernel/vcs/Cargo.toml` and `Cargo.lock`: added `serde_json` to the vcs crate.
- `crates/kernel/vcs/tests/branch_deletion.rs` (new): proves all four rows of "Branch deletions", including the exact `branch -d` command on each refusal and that the ahead and busy branches survive.
- `crates/kernel/vcs/tests/tree_record.rs` (new): proves both rows of "Tree record path and lines", including the exact two record lines and their escapes, and "Tree record without git", including a program that prints nothing and one that cannot start, plus the ignored write into a missing folder.

## Deviated

- `tests/tree_record.rs` asserts two things the scenarios do not spell out: a silent git program makes the path none, and a program that cannot start gives `VcsError::Spawn` naming the command. Both are requirement lines of "Tree record", and both are needed so the mutation check has a test for the empty-output branch and the propagated spawn error.
- The record line encodes each value through `serde_json::Value::String(..).to_string()`, an infallible display path, instead of a fallible `to_string` with an unreachable fallback that no test could reach.
