## Changed

- Read `osq.toml` with `load_config` at the start of `run_approve`, before any change is read.
- Added the git-on test and the worktree approval path: branch at the base commit, worktree add, `worktree-add` record, `vcs.prepare` with the verify role's environment and the configured timeouts, rollback on a failed prepare (remove folder, prune, record `worktree-prune`, `delete_branch`), recursive copy of the checkout's change folder, `.run/approved`, `.run/base` and `.run/approver`, the approval commit with the configured author and `commit` record, stacked-copy removal, and checkout-draft removal unless HEAD holds the change.
- Added `approve/worktree.rs` plus `worktree/{copy,markers,path,prepare,record,text}.rs`; the worktree path is the parent of `stacked_root` joined with the folder, and the tree record path is resolved once before the first write.
- Made `reject::time` crate-visible so the records use its UTC timestamp, and added `osq-kernel-config`, `osq-kernel-vcs` and `osq-kernel-harnesses` to the crate.
- Copied every golden except `print-goldens.mjs.txt` into `tests/fixtures/approve-worktree/`, unchanged.
- Added `tests/approve_worktree.rs` and `tests/worktree_support/mod.rs`, proving the three "Worktree approvals equal TypeScript's" rows, prepare-failure rollback and a second succeeding approve, git off in the checkout, stacked-copy removal and an unreadable config. The support module also offers a build-with-setup hook for tasks 3 and 4.

## Deviated

- `Cargo.lock` changed when Cargo registered the three new workspace dependencies; no task scopes it, and the proposal allows the lock to follow a manifest in scope.
