- [ ] With git on, `approve` refuses as "Approval refusals with git on" says and claims a rejected branch as "Rejected branch claim" says, every refusal before the first write and the rename as the first write.
- [ ] `tests/approve_feature.rs` proves the modified "Approve feature commands" and every row of the modified "Approve argument errors"; only its usage string and its new rows change.
- [ ] New `tests/approve_worktree_refusals.rs` proves every row of "Worktree refusals equal TypeScript's" and "More refusals with git on", and "Kept branch name skips a taken one", with the helpers of `tests/worktree_support/mod.rs` unchanged.
- [ ] Every public item and every function that implements a requirement ends its doc with `Implements: rust-approve/<requirement>`, and each new test's doc names `Covers: rust-approve/<scenario>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Parse the flags in `feature.rs` and pass them to `run_approve` as a small
plain struct. Put the three refusals and the claim decision in
`approve/refuse.rs`, with pure pieces such as the refusal texts and the
next kept name under `approve/refuse/`. Call it from `approve.rs` once git
is known to be on and validation has passed. It gives back whether a
rejected branch must be renamed and to what; `approve/worktree.rs` does
that rename first among its writes and passes the kept name to the output
in `approve/worktree/text.rs`, which prints it right after the hash line.
Task 4 adds its stacking check at the end of `refuse.rs`, after the claim
decision and before any write, so keep that function's last step easy to
extend.

Read task scopes from the `read_change` snapshot the steering check
already reads: each task's `plan.scope`. Match with rust-core
`scope_covers_path`, which ports TypeScript's `scopeCoversPath`. Read the
default branch with `default_branch`, passing `vcs.default_branch` or
`main`.

Build the refusal rows' repositories with the task 2 helpers and do each
row's setup with their `git` helper; for "More refusals with git on",
compare the branch list, the worktree list and the checkout copy before
and after the run.

When the mutation check reports a missed mutant, add a test case for
that line rather than keeping a branch no test reaches, and take its
expected value from the TypeScript source or a golden. Run the proposal's
verify with `OSQ_CHANGE=openspec/changes/292-rust-approve-worktree`.
