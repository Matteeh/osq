## Details

In `approve.rs`, load the config right after the arguments are known and
keep the lookup, steering refusal and validation as they are. After
validation, decide whether git is on; when it is not, write the checkout
marker exactly as today. Put the worktree path in `approve/worktree.rs`,
with its pure pieces (the worktree path, the provenance lines and the
output text) in files under `approve/worktree/`, and keep the output text
in `approve/worktree/text.rs`, since task 2 adds the kept-branch line
there. Build every `GitVcs` with `with_timeouts(&config.timeouts)`, as
`land.rs`'s `git_vcs` does. Take the worktree path as the parent of
`stacked_root(&config.vcs, &repo, home)` joined with the folder, so no
vcs kernel change is needed; read `HOME` as `plan/src/next/number.rs`
does. Run the prepare command the way `land/after.rs` builds its
`VerifyRequest`. Copy the change folder with a small recursive copy, as
`tests/support/mod.rs`'s `copy_tree` does, after removing any old copy.

Follow TypeScript's `approveIntoNewWorktree` step by step: branch and
worktree first, prepare next, then the copy, the seal, `.run/base`,
`.run/approver`, the commit, the stacked folder and the checkout draft.
Prepare must stay before the copy and the commit: the rollback deletes
the branch only because it still holds no commit of its own, and
`delete_branch` uses `branch -d`, which git refuses otherwise (ADR 003).
Read the tree record path once with `tree_record_path` on the root's
`GitVcs` before the first write, and take the time from
`reject/time.rs`'s `now`, made `pub(crate)` by changing `mod time;` in
`reject.rs` to `pub(crate) mod time;`; change nothing else there.

`tests/worktree_support/mod.rs` builds each repository as
`buildRepo` in `print-goldens.mjs.txt` does: copy
`tests/fixtures/approve-repo` to `<root>/repo` under a fresh scratch
`<root>` in `CARGO_TARGET_TMPDIR` named after the test row, canonicalized;
`git init -q -b main`, `user.name Osq Tester`, `user.email
tester@example.com`, `commit.gpgsign false`; append `osq.config.mjs`,
`osq.toml` and `node_modules` to `.git/info/exclude`; write `osq.toml`
with the `[vcs]` table the scenario names, `worktreeRoot` set to
`<root>/worktrees`, plus the row's extra lines; then `git add -A -- .
':!openspec/changes/001-alpha-twice'` and commit with
`GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE` `2026-10-22T10:00:00Z`. The
script's `osq.config.mjs` and `node_modules` link are for TypeScript
only; leave them out. Give the module a `git` helper that returns stdout,
a helper that runs `approve` with given arguments through
`ApproveFeature`, and a helper that writes a run's golden text exactly as
the script's `outcome`, `worktrees`, `commitLines`, `treeRecord` and
`runTree` do,
with `<root>` and `<base>` put back. For a `Failed` error, the message is
the display without its `approve failed: ` prefix, trailing whitespace
dropped. Tasks 3 and 4 reuse this module unchanged, so give it a setup
hook that runs before `approve`, and keep the helpers general.

When the mutation check reports a missed mutant, add a test case for
that line rather than keeping a branch no test reaches, and take its
expected value from the TypeScript source or a golden. Run the proposal's
verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/292-rust-approve-worktree`, so the link
gates see this change's requirements.
