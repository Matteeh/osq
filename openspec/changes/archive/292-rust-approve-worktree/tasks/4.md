## Details

Call the check as the last step of `approve/refuse.rs`, and put it in
`approve/stack.rs`, with pure pieces such as the folder order and the
refusal text under `approve/stack/`. List the changes as
`plan/src/next/number.rs`'s `trees_highest` does, with `worktree_list`,
`change_trees`, `list_tree_changes` and the folders under
`stacked_root`; copy those few lines, since a feature never calls
another. Read `depends_on` with the specs kernel's `read_proposal` on
the change's `proposal.md`, and match each entry with
`approve/find.rs`'s `matches`, made `pub(crate)`, against folders in any
location, as TypeScript's `resolveDependencyFolder` does. Read a folder's state on branches with
`list_branches`, `path_exists` and `default_branch`, and on disk with
`Path::exists`, in the order TypeScript's `readDependencyState` does.

Build each row's repository with the task 2 helpers. For a row that runs
`approve` first, run it through the same helper and check that it gave an
`Output`.

When the mutation check reports a missed mutant, add a test case for
that line rather than keeping a branch no test reaches, and take its
expected value from the TypeScript source. Run the proposal's verify with
`OSQ_CHANGE=openspec/changes/292-rust-approve-worktree`.
