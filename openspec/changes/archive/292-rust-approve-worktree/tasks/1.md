## Acceptance

- [ ] `Vcs` gains `delete_branch` and `GitVcs` implements it as rust-vcs "Branch deletion" says, with `branch -d` and never `-D` or `--force`.
- [ ] `GitVcs::tree_record_path` and the exported `append_tree_record` behave as "Tree record" says. `Cargo.toml` adds `serde_json` with `workspace = true` for the record line, and `Cargo.lock` follows.
- [ ] New `tests/branch_deletion.rs` proves every row of "Branch deletions", and new `tests/tree_record.rs` proves "Tree record path and lines" and "Tree record without git". Every earlier vcs test passes unchanged.
- [ ] Every public item ends its doc with `Implements: rust-vcs/<requirement>`, and each new test's doc names `Covers: rust-vcs/<scenario>`. `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Add `delete_branch` next to `rename_branch` in `git/write.rs` and the
trait, following its pattern. Put `append_tree_record` in new
`record.rs` and export it from `lib.rs`. Write the line as
`{"at":<at>,"op":<op>,"root":<root>}` with each value encoded by
`serde_json::to_string`, so the key order and the escapes equal
`JSON.stringify({ at, op, root })`. Read the common directory
with the same read helper `state.rs` uses for other reads, and resolve a
relative answer against the `GitVcs` root.

Build the test repositories as `tests/support/mod.rs` and
`branch_and_commit_writes.rs` do. Take expected values from the spec's
THEN lines.

When the mutation check reports a missed mutant, add a test case for
that line rather than keeping a branch no test reaches. Run the
proposal's verify with
`OSQ_CHANGE=openspec/changes/292-rust-approve-worktree`, so the link
gates see this change's requirements.

## Scenarios

- rust-vcs: Branch deletions
- rust-vcs: Tree record path and lines
- rust-vcs: Tree record without git
