## Acceptance

- [ ] `MetricsReport.history.sizes` and stable JSON contain ordered scope-file and acceptance-line bucket rows for `1-2`, `3-4`, `5-8`, and `over-8`, each with tasks, firstAttemptPassRate, meanAttempts, and nullable medianDurationSeconds.
- [ ] Only a task with a valid first start measures event contributes; its first measure supplies scopeFiles, `parseTaskMd` supplies acceptanceLines and title, started events supply attempts, typed first-attempt terminal events supply pass outcome, and paired measures timestamps supply duration without filesystem inference.
- [ ] Sizes expose one nullable largestFirstAttemptPass selected by scopeFiles, then acceptanceLines, then stable change/task order, carrying change, task, title, scopeFiles, and acceptanceLines.
- [ ] `formatMetricsReport` prints both size-against-outcome tables and exactly one hint line listing every largest-task observation within one of `config.limits.maxScopeFiles` or `config.limits.maxAcceptanceLines`, without mutating or recommending a new limit.
- [ ] Shared report helpers derive and format a repository record from only the 20 highest numeric archived changes, with measured task count, first-attempt pass rate, median duration, largest pass, and no more than ten deterministic dead rows of change, task title, and event reason with `unknown` fallback.
- [ ] Record and size derivation read numbered task events and task metadata only, ignore malformed or missing values defensively, never read `.run/results` or diffs, and preserve every pre-existing report field plus the dependency-039 queue view.
- [ ] A checked-in local fixture has at least five measured tasks across three buckets, a retry, dead reasons, tied largest candidates, missing coverage, and near-limit values; focused text/JSON assertions and `fixture/report/expected.json` remain deterministic.

## Details

Extend the existing `HistoryMetrics` rather than adding a new top-level report
section. Use these exact keys under `history.sizes`: `byScopeFiles`,
`byAcceptanceLines`, and `largestFirstAttemptPass`. Each bucket row has
`bucket`, `tasks`, `firstAttemptPassRate`, `meanAttempts`, and
`medianDurationSeconds`. The largest row is null when no measured task passed on
its first attempt; otherwise it has `change`, `task`, `title`, `scopeFiles`, and
`acceptanceLines`.

Build one internal measured-task projection and reuse it for bucket aggregation,
largest selection, and the recent archive record. A task contributes once, using
its first valid `measures` start for size. Count attempts from valid `started`
events. Treat the first attempt as passed only when its event segment reaches a
typed `done` before another `started`, `dead`, or `regressed` outcome. Pair
`measures` start/end events in stream order, discard reversed or incomplete
pairs, sum covered attempt intervals per task, and take the ordinary sorted
median across covered tasks. Expose rates and means as deterministic numbers
rounded consistently to two decimal places; empty buckets use zero rates and
means and null duration.

Export a repository-record derivation and body formatter from
`src/core/report.ts` for task 2. Discover only canonical archived folders, sort
by numeric prefix descending with a stable name tie-break, and inspect at most
20. Dead rows come from every typed `dead` event in that window, ordered by
newest selected change, numeric task, then event order, and truncated to ten.
Do not substitute current markers or result-file prose. The formatted body must
render either `This repository's measured record is too small (fewer than 5
tasks).` for fewer than five measured tasks, or these labeled groups:
`First-attempt pass rate`, `Dead outcomes`, `Largest first-attempt pass`, and
`Median task duration`. Render each dead outcome as
`- <change>, <task title>, <reason>`. The formatter does not own the section
heading.

Pass `OsqConfig` through text formatting so the hint compares the selected
largest task with the loaded limits. A limit matches when the absolute
difference between configured and observed values is at most one. Emit no hint
without a largest pass, and combine both matching limits on one line. Keep the
line observational and never propose or write a replacement value.

Reuse `parseEventLines`, `asData`, `parseTaskMd`, `compareNumericPrefix`,
`formatDuration`, `getArchiveDir`, `getMetricsReport`, `formatMetricsReport`,
`toStableMetrics`, and the post-039 queue-preservation behavior. Add a focused
fixture under `tests/fixtures/report-sizes/`; update the established report
fixture only for the new stable empty-or-populated `history.sizes` shape. Do not
weaken unrelated report assertions. Run the task verify and `pnpm verify` before
exit.
