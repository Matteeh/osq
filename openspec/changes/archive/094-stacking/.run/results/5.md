## Changed

- New `src/core/lifecycle/reject-vcs.ts`: `commitRejectedWorktree` selects the
  `Vcs` on the rejected change's tree root, commits every status path under the
  old folder and the rejected folder with subject `osq: <id> rejected`, the
  reason and `rejected to <path>` as body lines, an `Osq-Change` trailer, and
  `vcs.author`, then removes the worktree with `worktreeRemove` (never forced).
  A failed commit, leftover changes outside the two folders, or a failed
  removal returns a kept-worktree outcome with a `why` instead of throwing; the
  branch is always kept. Returns null when git cannot be selected.
- `src/core/lifecycle/reject.ts`: `RejectResult` gains optional `worktree`,
  `branch`, and `stackedPath`. `rejectSpec` now reads a change's tree and:
  - for a stacked tree, applies the same eligibility rules, deletes the stacked
    approval directory, moves nothing, and writes no rejection record;
  - for a worktree tree, does the move and rejection record as before, then
    commits and removes through `reject-vcs.ts`.
  Eligibility moved into `assertRejectable`, and the worktree commit/removal
  into `finalizeRejectedWorktree`, to stay within the 80-line function budget.
- `src/cli/reject.ts`: prints `Worktree removed: <path>` or
  `Worktree kept: <path> (<why>)` then `Branch kept: osq/<folder>` for a
  worktree change, `Withdrew stacked approval: <path>` in place of the
  `Destination` line for a stacked change, and the unchanged `Destination`
  line when `vcs.enabled` is off.
- `tests/worktree-lifecycle.test.ts`: only the reject case changed; it now
  asserts the rejected folder and `.run/rejected.md` at `osq/<folder>` with
  `git show`, the worktree and its `worktreeList` entry are gone, and the
  checkout copy is unchanged.
- New `tests/reject-worktree.test.ts`: clean-worktree rejection (commit
  contents, body, trailer, branch kept, worktree gone), dirty-worktree kept
  (commit excludes the outside file, worktree and file remain), not recreated
  by `recreateWorktrees`, a halted stacked change's withdrawal (no branch,
  checkout unchanged), a healthy stacked change refused, and every CLI line
  for the removed, kept, stacked, and vcs-off cases.
- `README.md`: the "Version control" section drops "stacking is not
  implemented" and the "unfinished" warning, describes stacked approvals and
  the cut, lists `dependency_changed`, `dependency_diverged`, and
  `stack_cut_failed`, and describes reject's commit, worktree removal, kept
  branch, and stacked-approval withdrawal.

## Deviated

The task Details say to build the reject message with `formatCommitMessage`
and `readCommitTrailers`. `readCommitTrailers` always adds an `Osq-Task`
trailer and needs a task number, while the delta's "Rejection under version
control" names only the `Osq-Change: <folder>` trailer for a change-level
commit. I used `formatCommitMessage` alone with that single trailer, matching
the delta and the proposal's Surface entry.
