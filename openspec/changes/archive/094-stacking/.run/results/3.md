## Changed

- New `src/core/spec/stack-dependencies.ts`:
  - `readDependencyState(projectRoot, config, vcs, folder)` reads `landed`,
    `approved`, `archived`, or `unapproved` exactly as "Stack dependency
    state" says: the default branch's archive, then `osq/<folder>`'s archive
    or changes copy, then the stacked approval, then the checkout. Hashes are
    trimmed and an archived state carries `osq/<folder>` as `base`.
  - `resolveDependencyFolder` matches a `depends_on` entry to a folder name
    across `listChanges`, using `findChange`'s matching rules.
  - `awaitedDependencies` reads a change's `depends_on` and returns the
    `{ folder, hash }` entries that read `approved` or `archived`, in order.
  - `formatStackedOn` / `parseStackedOn` implement `.run/stacked-on`.
  - `recordStackedApproval` deletes any existing stacked approval, copies the
    checkout's folder into it, appends observed sessions, seals it (passing
    the stacked root as the manifest project root), writes `.run/approver`,
    and writes `.run/stacked-on`.
  - `writeProvenance` moved here from `approve-worktree.ts` (base plus
    approver) so `approve-worktree.ts` stays under the 250-line budget.
- `src/core/spec/approve-worktree.ts`: dropped `refuseUnlandedDependencies`;
  after the refusals and the review it reads `awaitedDependencies` and records
  a stacked approval when any entry awaits, else approves into a worktree and
  deletes any stale stacked approval. The worktree write moved to
  `approveIntoNewWorktree` to keep both functions under the function budget.
- `src/core/spec/approve.ts`: `ApproveResult` gains `stackedPath` and
  `waitingFor`. When `findChange` returns the change from a stacked tree,
  `approveSpec` lints, reviews, hashes, and copies the checkout's folder of the
  same name, failing with `findChange`'s message when the checkout has none.
- `src/cli/approve.ts`: prints `  Waiting for: <folders>` and
  `  Stacked: <path>` for a stacked approval in place of `Worktree:`/`Branch:`.
- `tests/approve-worktree.test.ts`: the "refuses an approved dependency that has
  not landed" case became "stacks on an approved dependency that has not
  landed".
- New `tests/approve-stacked.test.ts`: covers the five "Stack dependency state"
  scenarios, the four "Stacked approval" scenarios, and the stacked-on
  format/parse.

## Deviated

Moved the preexisting `writeProvenance` helper into
`stack-dependencies.ts` rather than duplicating it, because `approve-worktree.ts`
grew past the 250-line budget once the stacked branch was added. The move also
keeps the "approver line" logic in one place.

## Missing context

None blocking. The `depends_on` folder resolver had to replicate
`findChange`'s unexported `matchesFolder` because `change-locations.ts` is not
in this task's scope and does not export it.

## Outside scope

The background note says `tests/worktree-lifecycle.test.ts`'s reject case will
break once task 5 commits the rejected move before removing the worktree. That
file is task 5's scope, so it was left alone.
