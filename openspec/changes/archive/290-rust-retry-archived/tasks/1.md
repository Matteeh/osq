## Details

Keep the active lookup in `find.rs` first and load config only when it
finds nothing, so the 277 goldens, which have no `osq.toml`, never read
git. Build the trees as the inbox's `read.rs` does, with `GitVcs::new`,
`with_timeouts`, `worktree_list` and `change_trees`, but pass no stacked
folders. Keep an archived entry only when its tree's `folder` is set.
Reuse `find.rs`'s folder match for the id.

Run the existing approval, running, marker and record steps on the found
folder unchanged, then commit with `GitVcs` in the tree's root. Read each
path's `HEAD` text with `show` before committing. On a commit error,
write those texts back, delete files `HEAD` lacks, call `stage` on the
paths and ignore its error, then fail with `osq could not record the
retry: ` and the `VcsError`'s display.

In the test, build each repository with `git` through
`std::process::Command`, as `inbox_trees.rs` does: `init -b main`,
`user.name`, `user.email`, `commit.gpgsign false`, `README.md` holding
`fixture`, and `osq.toml` holding the `[vcs]` table the script writes.
The script's `osq.config.mjs` is for TypeScript only; leave it out. Dump
the archive folder with `support::dump`, and read the tip subject with
`git log -1 --format=%s osq/<folder>` and the status with `git status
--porcelain` in the worktree. The golden writes the copy's root as
`<root>` only in the not-found message.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source or a golden. Run the proposal's verify as the
watcher does, with `OSQ_CHANGE=openspec/changes/290-rust-retry-archived`,
so the link gates see this change's requirements.
