## Acceptance

- [ ] `missingEntryFindings` in `src/core/spec/entry-lint.ts` treats an entry inside the linted change folder as spec-lint-and-approve "Entry paths exist" says. An entry is inside when it starts with `<config.paths.openspecRoot>/changes/<folder>/` or resolves from the project root into `folderPath`. It counts only when the rest exists under `folderPath`: `entryExists` for a plain path, or a `resolveScope` match there for a pattern. The other ways an entry is provided, their order and the error text do not change.
- [ ] New `tests/entry-lint-worktree.test.ts` proves "Entries inside the change folder" through `lintChangeFolder`, one assertion per row that names the row. It proves "Steered change linted from main" through `lintCommand` from `src/cli/lint.ts`, run in the main checkout. Each runs on a git repository under `os.tmpdir()` with `vcs.enabled` on and a worktree outside the checkout.
- [ ] `tests/entry-lint.test.ts` and every other test do not change and keep passing.
- [ ] `missingEntryFindings` keeps its `@scenario` and `@adr` lines and gains `@scenario spec-lint-and-approve: Entries inside the change folder` and `@scenario spec-lint-and-approve: Steered change linted from main`.

## Details

Build the repository as `tests/entry-lint.test.ts` does: `scaffoldProject`, git
with the test's own clean environment, and a local `node verify.cjs`
verifier. Add the worktree with `git worktree add -b osq/001-steer <path>`
and write the change folder only there. Find how `osq lint 001` resolves a
worktree change in `tests/change-locations-worktrees.test.ts`. Name each
`describe` after its scenario and each `it` after its row. The `scenario`
helper is not used, because the living spec-lint-and-approve spec holds
duplicate scenario names it refuses. Use `getChangesDir` from
`src/core/status/layout.ts` for the folder prefix, and compare with `/`
separators.
