## Changed

- `src/core/spec/entry-lint.ts`: replaced `liesInsideChangeFolder` with `entryInsideChangeFolder` and `providedInsideChangeFolder`. An entry now counts as inside the linted change folder when it starts with `<changes dir>/<folder>/` or resolves from the project root into the folder; the remaining path is checked inside that folder with `entryExists`, or with `resolveScope` for a pattern. This finds the folder in a worktree, a checkout, or a stacked copy. The other ways an entry is provided, their order, and the error text are unchanged.
- Added the two scenario tags to `missingEntryFindings`'s doc comment.
- `tests/entry-lint-worktree.test.ts`: new test proving all five rows of "Entries inside the change folder" through `lintChangeFolder`, and "Steered change linted from main" through `lintCommand`. Each row uses a temp git repository with `vcs.enabled`, a `node verify.cjs` verifier, and a worktree on `osq/001-steer` outside the checkout where required.
