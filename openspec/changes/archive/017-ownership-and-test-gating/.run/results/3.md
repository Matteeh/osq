# Task 3 Result

## Changed

- `src/harness/types.ts`
  - Added optional `capabilityRules?: string[]` to `SpawnTaskOptions`.
  - Added `extractCapabilityRules(specFolderPath)`: synchronously walks the change
    folder's `specs/` directory (sorted by capability name), reads each
    `specs/<capability>/spec.md`, and returns one rule string per
    `### Requirement:` block as
    `<capability>: <requirement title> — <requirement statement>`. Comments are
    stripped, whitespace collapsed, and scenario subheadings excluded from the
    statement. Returns `[]` when `specs/` is absent.
  - Added `resolveCapabilityRules(options)` (explicit `capabilityRules` wins,
    including `[]`; otherwise extract from the change folder) and
    `capabilityRuleLines(rules)` (returns no lines when empty, so no empty header
    is ever emitted).
- `src/harness/agy.ts`
  - `buildAgyPrompt` resolves capability rules and appends the shared
    `Capability Rules:` sub-section after the standard numbered rules.
- `src/harness/opencode.ts`
  - `buildOpencodePrompt` appends the identical `Capability Rules:` sub-section.
- `tests/harness-prompt-injection.test.ts`
  - New suite covering extraction (multiple capabilities, document order,
    missing `specs/`), injection into both prompts under a dedicated section after
    `Rules:`, fallback with no empty header, explicit empty array, and
    auto-derivation from the change folder when `capabilityRules` is absent.

## Verify

`node --import tsx --test tests/harness-prompt-injection.test.ts` → 7 pass / 0 fail.
`pnpm tsc --noEmit` clean. `pnpm biome check` on the four touched files clean.

## Deviated

- The task only specified that `buildAgyPrompt`/`buildOpencodePrompt` inject
  extracted rules and that `extractCapabilityRules` exists. Because `runner.ts`
  is outside this task's scope and does not pass `capabilityRules`, the build
  functions call `extractCapabilityRules` themselves when the option is absent.
  This makes prompt injection functional end-to-end without a runner change. An
  explicit `[]` is respected and yields no section.
- The dedicated section is rendered as a blank line, `Capability Rules:`, then a
  `- <rule>` bullet per requirement, appended after rule 7 of the standard
  `Rules:` block. The exact format was not prescribed by the spec; the tests in
  `tests/harness-prompt-injection.test.ts` are its definition.
