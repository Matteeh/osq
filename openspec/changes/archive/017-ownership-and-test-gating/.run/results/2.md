# Task 2 Result

## Changed

- `src/core/linter.ts`
  - `lintChangeFolder` now resolves the change document with `resolveChangeDoc`
    (imported from `./parser.js`), preferring `proposal.md` and falling back to
    legacy `spec.md`. Missing both yields an explicit lint error.
  - Added `readTestsModifyDeclaration(content)` which inspects raw frontmatter
    (`parseFrontmatter`) for nested `tests: { modify: ... }` and the flat
    `tests.modify` key. When present and non-boolean it records an error:
    `Task in <n>.md tests.modify must be a boolean (got <json>)`.
  - Added `globToRegExp`, `listExistingTestFiles`, and `touchedTestFiles`.
    Existing files under `tests/` are walked once (cached per lint run) and
    matched against each task scope glob (`*`, `**`, `?`, trailing `/`). When a
    scope matches a preexisting test file and `task.testsModify` is false, lint
    rejects with `... without tests.modify: true`. New test files do not exist
    yet, so creating them never triggers the check.
- `tests/linter.test.ts`
  - Moved the scaffolded change folder into `openspec/changes` in `beforeEach`
    so `lintCommand` can resolve `001` under the configured `paths.specs`.
  - Added `writeTaskFile` + `PASSING_VERIFY` helpers.
  - New cases: proposal.md resolution, missing both docs, non-boolean nested
    and flat `tests.modify`, boolean nested acceptance, `tests/existing.test.ts`
    scope rejection, `tests/**` scope rejection, `tests/**` scope with
    `tests.modify: true` passing, and a nonexistent new test file passing.
