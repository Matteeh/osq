# Task 4 Result

## Changed

- `src/watcher/runner.ts`
  - `RunTaskFailureReason` union now includes `undeclared_test_change`.
  - Added `hashFileContent` (sha256), `snapshotTestFiles(projectRoot)`, and
    `findUndeclaredTestChanges(projectRoot, snapshot)`. The snapshot walks
    `tests/**` recursively and maps repo-relative POSIX path -> content hash.
    The comparison reports `(modified)` when a hash differs and `(deleted)`
    when a preexisting file no longer reads, and ignores paths absent from the
    snapshot so newly created tests are never flagged.
  - `runTask` fingerprints preexisting tests immediately before
    `adapter.spawn` when `taskData.testsModify` is false (no snapshot is taken
    when the declaration is true, so edits are permitted).
  - After a clean agent exit and before the result/verify pipeline, a non-empty
    undeclared-change list writes `.run/dead/<n>.md` with
    `reason: undeclared_test_change` plus the offending paths, appends the
    matching `dead` event, logs the outcome, and returns without invoking
    `taskData.verify`.
- `tests/runner-test-gating.test.ts` (new)
  - Compile-time union acceptance; deletion detection (proves the snapshot is
    taken before spawn); modification case asserting the dead marker contents,
    exactly one `dead` event with reason `undeclared_test_change`, absence of a
    `verify_ran` event, and no `done` marker; brand-new test file allowed; and
    `tests.modify: true` permitting edits. Uses an inline `FileMutatingAdapter`
    so the mutation happens inside `spawn` without touching `src/harness/mock.ts`.

## Deviated

- The snapshot stores content hashes rather than mtimes/sizes; this is
  deterministic and distinguishes a rewrite from a same-size edit.
- The gate is evaluated before result-file handling, so an undeclared change is
  caught even when the agent wrote `.run/results/<n>.md`. The ordering relative
  to result handling was not prescribed.
- The test root is hardcoded to `tests`, matching the linter's hardcoded root.
  The `tests.patterns` config hook from the cli-foundation delta still has no
  owning task (`src/core/config.ts` is out of scope here).
- `tests/runner-test-gating.test.ts` constructs its change folder directly under
  `openspec/changes` instead of calling `createNewSpec`, because the latter
  still defaults to `specs/` while `DEFAULT_CONFIG.paths.specs` is now
  `openspec/changes` (016 migration fallout). This keeps the task's verify green
  without editing out-of-scope files.
