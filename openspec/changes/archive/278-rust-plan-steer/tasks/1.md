## Details

Build the opening sections with the existing `prompt::build` and
`report::sections`, so both forms of `plan` share one prompt builder. Pass
no dependencies, and the steered change's brief and title. Build the
handoff with the existing `handoff` module, given the next step as text.

Port the trigger rules from TypeScript's `deriveSteering`, and read the
inbox crate's `needs/steering.rs` as a guide; do not depend on
`osq-feature-inbox`. Copy the folder match from the run crate's `find.rs`.
Read each marker's body with rust-specs `parse_frontmatter`, and use the
whole text when the frontmatter does not parse.

Copy the fixture with the dot folders included, because the markers live
under `.run/`. In a test, replace the copy's root with `<root>` in the
output and the prompt before comparing.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Take its expected value
from the TypeScript source. Run the proposal's verify as the watcher does,
with `OSQ_CHANGE=openspec/changes/278-rust-plan-steer`, so the link gates
see this change's new requirements.
