## Changed

- `src/cli/reject.ts`: `RejectCommandOptions extends CommandInputs` and keeps
  `reason`. The command resolves its inputs through `resolveInputs`, awaits
  `inputs.config()` before the `try` exactly where it loaded config before, and
  writes each former `console.log` line as `` `${line}\n` `` to `inputs.stdout`
  in the same order. The `CommandError` text is unchanged.
- `src/cli/retry.ts`: `RetryCommandOptions` is now `CommandInputs`. The command
  resolves its inputs, awaits `inputs.config()` before the `try`, and writes the
  recertified/requeued/retried, reason, and retained-marker lines to
  `inputs.stdout` as `` `${line}\n` ``. The `CommandError` text is unchanged.
- `tests/reject-worktree.test.ts`: replaced the `console.log`/`console.error`
  monkey-patch helper with `captureLines`, which collects the command's
  `stdout` writes and splits them back into lines; the four output tests pass
  `stdout` and assert the same lines.
- `tests/retry-recertification.test.ts`: replaced the `console.log` helper with
  `captureOutput`, which returns the exact `stdout` text; the two CLI-output
  tests pass `stdout` and assert the same text.
- New `tests/command-inputs-lifecycle.test.ts`: for `osq reject 001 --reason
  stop` and `osq retry 001 1`, it runs each command once through
  `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and `stderr`
  writers that append to strings, then asserts the stdout and stderr text is
  identical both ways and that the direct call leaks nothing to the process
  streams.

`pnpm verify` exits 0: CLI and UI typechecks, build, the full test suite, and
lint.

## Deviated

The acceptance says each run is "on its own copy of the same project state".
Because `osq reject` prints the destination's absolute path, two copies at
different absolute paths would never produce the same stdout. The test resets
one project directory to the same fresh state before each of the two runs, so
the CLI and the direct call each start from their own rebuilt copy of the same
state at the same path and their text is byte-identical.
