## Changed

- `src/cli/run.ts`: `runCli` now prints a `CommandError`'s message and a `ConfigLoadError` line through `processStderr`, and the `Next:` line through `processStdout`, each plus `\n`, replacing `console.error`/`console.log`. Streams, text and exit codes are unchanged.
- `src/cli/index.ts`: the `lint` action passes its parsed `options` straight to `lintCommand` instead of injecting its own `stdout: (text) => process.stdout.write(text)` writer; the command's own resolved `stdout` is used.
- `tests/cli-config-errors.test.ts`: captures CLI output through `runCliCaptured` (`tests/cli-capture.ts`, which hooks the process stream writes) instead of replacing `console.error`, and asserts the same stderr line, `stderr` text, and exit code.
- `tests/cli-no-direct-output.test.ts` (new): reads every `.ts` file under `src/cli/` and fails, naming each offending file with its rule and line, when any file other than `command-inputs.ts` contains `console.`, `process.stdout.write` or `process.stderr.write` (comments stripped first). It also holds the typed command table: one entry per exported `*Command` function that is not a `register...Command`, each entry receiving the `CommandInputs` in the command's options position, so the CLI typecheck fails if a command stops accepting them. A source scan finds every exported `*Command` function and the test fails naming any that the table lacks, plus unit tests for the sample patterns, comment handling, a missing `ghostCommand`, and a `registerGhostCommand`.

## Deviated

- `browserCommand` in `src/cli/serve.ts` is a synchronous helper whose name ends in `Command`, so the missing-name scan finds it even though it is not a command. Since `src/cli/serve.ts` is outside this task's scope, the table carries a `browserCommand` entry whose wrapper ignores the inputs; every real command's wrapper passes `inputs` into its options position so the typecheck still guards them.
