## Changed

- Added `src/cli/command-inputs.ts`: `Writer`, `CommandInputs`, `processStdout`, `processStderr`, `resolveInputs` (fills `cwd`, writers, and a `config()` that gives the passed config or `loadConfig(cwd)`), and `commandLogger(inputs, level = 'normal')` (the `osq` process logger, or a non-interactive logger over a `node:stream` `Writable` forwarding to the passed `stderr`).
- Rewrote `tests/cli-capture.ts` to hook `process.stdout.write` and `process.stderr.write` instead of `console.log`/`error`/`warn`. Each write becomes one `CliLine` with one trailing newline removed, and `CliCapture` gained the exact `stdout` and `stderr` text. Writes and `process.exit` are restored in `finally`.
- Rewrote `captureLogs` in `tests/planning-observed-helpers.ts` to record process-stream writes the same way instead of console calls.
- Updated `tests/lint-command-error.test.ts` and `tests/sync-graph-migrate-command-error.test.ts` to read CLI output from the capture (`capture.stdout` / `capture.stderr`) instead of wrapping `runCliCaptured` in their own write hooks, and removed the now-unused `runCliWithStderr` helper.
- Added `tests/command-inputs.test.ts` covering the six exports, `resolveInputs` defaults and passed values (a throwing config file proves `config()` does not load when a config is passed), `commandLogger` with and without `stderr`, and the exact `stdout`/`stderr` capture fields.

## Deviated

- In `tests/sync-graph-migrate-command-error.test.ts` the migrate CLI test dropped `assert.deepEqual(capture.lines, [])`. The capture now records the logger's stderr writes, so `lines` is no longer empty; the equivalent intent is asserted as `capture.stdout === ''` plus `assert.match(capture.stderr, ...)`, which is what "assert the same text" asks for.
- `resolveInputs().config` is `async` so it always returns `Promise<OsqConfig>` whether the config was passed or loaded; the delta only specifies it returns a `config()`.

## Missing context

- The delta says `commandLogger` is "the `osq` logger at a level" without naming the level parameter position or its default. I chose `commandLogger(inputs, level = 'normal')` to sit next to the other command input helpers. Later tasks that convert `lint`, `migrate`, and `watch` must use that shape.
- The first acceptance line says `src/cli/command-inputs.ts` is the only file under `src/cli/` calling `process.stdout.write`/`process.stderr.write`; that only becomes true after the later tasks convert the existing commands. The `src/cli` guard test is task 12.

## Outside scope

- Every other file under `src/cli/` still calls `console.*`, `process.stdout.write`, or `process.stderr.write`. Per the proposal these are converted by tasks 2–12, so I left them alone.
