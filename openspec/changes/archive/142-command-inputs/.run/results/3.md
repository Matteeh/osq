## Changed

- `src/cli/report.ts`, `src/cli/query.ts` and `src/cli/digest.ts` now take
  `CommandInputs` through `resolveInputs`. `ReportCommandOptions`,
  `QueryCommandOptions` and `DigestCommandOptions` extend `CommandInputs`
  instead of declaring `cwd`, `config` and `stdout` themselves. Each awaits
  `inputs.config()` at the same point it loaded config before (outside the
  error handling) and writes its output as one `` `${text}\n` `` to
  `inputs.stdout`, replacing `options.stdout(text)` / `console.log(text)`.
  `digest --out` still writes the file and prints nothing. Return values and
  positional arguments are unchanged; `digest` resolves `--out` against
  `inputs.cwd`.
- `tests/report.test.ts` captures the writer output with `+=` and asserts it
  equals the returned text plus `\n`.
- `tests/report-json.test.ts` asserts the captured JSON document is the
  returned text plus `\n`, then parses the returned text.
- New `tests/command-inputs-history.test.ts` runs `osq report`,
  `osq report --json`, `osq query <select>`, `osq query`, `osq digest <id>`
  and `osq digest <id> --json` once through `runCliCaptured` and once directly
  with string-appending `stdout` and `stderr`, in the same project, asserting
  identical stdout and stderr and that the direct calls write nothing to the
  process streams. It also asserts bare `osq digest` and `osq digest --json`
  exit one with the same stderr through `runCli` and reject with that same
  `CommandError` message directly. `HOME` is pointed at a temporary folder for
  the CLI calls and the same folder is passed as `home` to `reportCommand`, so
  the developer's inbox wait log is never read.

## Deviated

- The acceptance names bare `osq digest` and `osq digest --json` among the
  commands whose stdout and stderr must match both ways. Those invocations
  cannot succeed: with no ids and no `--since`, `buildChangeDigest` refuses
  with `Give change ids or --since <date>`, and a direct call rejects while
  `runCli` catches the `CommandError` and prints it. The new test therefore
  covers those two argv forms as refusals (exit code 1, same stderr message,
  same direct rejection) and covers the successful newline path with
  `osq digest <id>` and `osq digest <id> --json`.
- `tests/report.test.ts` and `tests/report-json.test.ts` use the command's
  return value for the newline-free report text and assert the writer received
  `${return}\n`, so the report body assertions stay byte-for-byte identical.
