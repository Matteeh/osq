## Changed

- `src/cli/new.ts`: `newCommand(name, options: CommandInputs = {})` now
  resolves its inputs with `resolveInputs` and writes the two lines as
  `` `${line}\n` `` to `inputs.stdout`, replacing `console.log`. Config is
  still awaited inside the `try`, so a load failure is wrapped in
  `CommandError('Error: ...')` as before.
- `src/cli/init.ts`: added `InitCommandOptions extends CommandInputs` with the
  existing `refreshSchema` flag; `initCommand(options)` resolves its inputs,
  loads config outside any error handling as before, and writes all nine
  output forms (created dirs/files, exists, refreshed, current, updated
  AGENTS.md, project rules, and the trailing success line) through
  `inputs.stdout`.
- `src/cli/setup.ts`: `setupCommand(options: CommandInputs = {})` resolves its
  inputs, loads config outside any error handling as before, runs
  `updateAgentsMd` and the harness setup against `inputs.cwd`, and writes the
  completion line to `inputs.stdout`. Called with no argument it still uses
  the process cwd, stdout and config.
- `tests/init-refresh-schema.test.ts`: the two init-output tests capture through
  the new `stdout` option (stripping each write's trailing newline) instead of
  monkey-patching `console.log`.
- `tests/rules-block.test.ts`: the `osq init command` test captures through the
  new `stdout` option instead of `console.log`.
- New `tests/command-inputs-scaffold.test.ts`: for `osq new Demo Change`,
  `osq init` and `osq init --refresh-schema`, runs the command once through
  `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and
  `stderr`, each in a freshly reset project at the same path, and asserts the
  stdout and stderr text is identical and that the direct call leaks nothing to
  the process streams. It also calls `setupCommand` with a fresh `cwd`, a
  `defineConfig({ harness: 'mock' })` config and a `stdout` writer, and asserts
  it receives exactly `Harness 'mock' setup completed successfully.\n`.

## Deviated

- The acceptance says each run is "in a fresh temporary project". Because
  `osq new` prints the absolute `Path`, two projects at different paths would
  never match byte for byte. The test resets one project directory in place
  before each run, so the CLI and direct call each start from a fresh empty
  project at the same path and their absolute paths are identical.
