## Changed

- `src/cli/approve.ts`: `ApproveCommandOptions` now extends `CommandInputs`
  (dropping its own `cwd` and `config`). `approveCommand` resolves its inputs
  with `resolveInputs` and awaits `inputs.config()` at the same point as the
  old `loadConfig(cwd)` call (before the empty-id check); every use of the old
  local `cwd` now goes through `inputs.cwd`. `printApprovalResult` takes the
  `stdout` and `stderr` writers: the approval result lines go to `stdout` as
  each line plus `\n`, and each former `console.warn` `  Warning: ...` line
  goes to `stderr` with its `\n`. The digest and the flag lines in `review`
  now write through `inputs.stdout`, and the `--confirm` path passes
  `requestApproval` a `print` that writes the line plus `\n` to `stdout`.
- `src/cli/confirm.ts`: `ApprovalConfirmOptions.print` is now required, and
  `requestApproval` calls it for each flag line without its newline instead of
  defaulting to `console.log`.
- `tests/approve-confirm.test.ts`: `captureExitAndLogs` now collects output
  through `captureLogs` (process stream writes) instead of replacing
  `console.log`/`warn`/`error`, then appends the thrown `CommandError`'s
  message and `Next:` line as before.
- `tests/approve-rejected-branch.test.ts`: the "prints the kept branch after
  the hash line" test uses `captureLogs` instead of monkey-patching
  `console.log`.
- New `tests/command-inputs-approve.test.ts`: approves a flagged change once
  through `runCliCaptured` and once directly with `cwd`, `config`, `stdout`
  and `stderr` writers on two separate copies of the same project, asserting
  identical stdout and stderr text and no process-stream leak; plus a
  `--confirm` run with `isTerminal: () => true` and an `ask` stub whose flag
  lines reach `stdout`.

Task verify (`node --import tsx --import ./tests/git-test-env.ts --test
tests/command-inputs-approve.test.ts`) passes, and the proposal's `pnpm
verify` exits 0 (CLI and UI typechecks, build, all tests, lint).
