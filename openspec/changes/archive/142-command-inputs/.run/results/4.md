## Changed

- `src/cli/doctor.ts`: `DoctorCommandOptions` extends `CommandInputs` with
  only `report` left, so `cwd`, `config`, `stdout` and `stderr` come from the
  shared type. `doctorCommand` resolves them with `resolveInputs` and writes
  each check as `` `${prefix} ${name}: ${message}\n` `` to `inputs.stdout`.
  When no `report` is injected it calls `runDoctorChecks(inputs.cwd, {
  loadConfig: async () => inputs.config() })`, so a passed `config` reaches the
  config check through the existing dependency and no config is loaded when the
  report is injected or the config is passed.
- `src/cli/serve.ts`: `ServeCommandOptions` extends `CommandInputs`; `cwd`,
  `config` and `stdout` are gone from the interface and the other options are
  unchanged. `serveCommand` resolves inputs with `resolveInputs`, awaits
  `inputs.config()` at the same point it loaded config before, and writes the
  export lines and the URL line as `` `${text}\n` `` to `inputs.stdout`.
- `tests/doctor-command-error.test.ts`: the direct-call assertions expect the
  trailing newline each check line now carries.
- `tests/serve.test.ts`: the awaited URL lines end in `\n`, and the browser
  test trims that newline before comparing the launch argument and platform
  commands.
- `tests/serve-export.test.ts`: the captured export lines and the awaited
  serve URL end in `\n`.
- `tests/command-inputs-doctor-serve.test.ts`: runs `osq doctor` and
  `osq serve --export snapshot` through `runCliCaptured` and directly with
  `cwd`, `config`, `stdout` and `stderr` string-appending writers, asserting
  identical stdout and stderr and that the direct calls write nothing to the
  process streams. A separate case writes a repo configured for `agy`, passes a
  `mock` config to `doctorCommand`, and asserts the config check reports
  `harness: mock`, proving the passed config reaches the check.

## Deviated

- `src/cli/index.ts` is outside this task's scope, but commander derives the
  `--export <dir>` value under `options.export`, while the serve action passes
  the options object with `exportDir` unset. The CLI therefore started a server
  for `osq serve --export` (a pre-existing bug), which would hang the new
  `runCliCaptured` case. `serveCommand` now reads the commander key as a
  fallback (`raw.exportDir ?? raw.export`) without adding it to
  `ServeCommandOptions`, so the CLI reaches the export branch while the
  interface still matches the acceptance ("other options unchanged"). The
  correct long-term fix is to rename the key in `src/cli/index.ts` or move
  serve registration into `serve.ts`.

## Outside scope

- `osq serve --export <dir>` never exported through the CLI before this task:
  `src/cli/index.ts` reads `options.exportDir` but commander yields
  `options.export`. No CLI-level test exercised it. Left the index.ts definition
  alone; worked around it in `serve.ts` as described above.
