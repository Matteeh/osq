## Changed

Converted the five VCS/spec commands to take their inputs through
`src/cli/command-inputs.ts`:

- `src/cli/land.ts`: `LandCommandOptions extends CommandInputs`; the command
  now calls `resolveInputs(options)` and awaits `inputs.config()` inside its
  error handling, keeping the stale-build check, `landChange` call, rebuild
  line, and non-zero `CommandError` behaviour unchanged. `cwd`, `config`,
  `stdout` and `stderr` are gone from the interface.
- `src/cli/message.ts`: `MessageCommandOptions` is now `CommandInputs`. Config
  is still awaited outside the `try`, so a `ConfigLoadError` reaches `runCli`
  as before.
- `src/cli/sync.ts`: `SyncCommandOptions` is now `CommandInputs`; config is
  awaited inside the `try`, as before.
- `src/cli/graph.ts`: `GraphCommandOptions extends CommandInputs`;
  `json` unchanged; config awaited inside the `try`.
- `src/cli/spec.ts`: `SpecCommandOptions` is now `CommandInputs`; config
  awaited inside the `try`.
- `tests/command-inputs-vcs.test.ts`: new test. It runs `osq graph`,
  `osq graph --json`, `osq spec` and `osq spec alpha` through
  `runCliCaptured` and directly through `graphCommand`/`specCommand` with
  `cwd`, `config`, `stdout` and `stderr` writers that append to strings, and
  asserts both streams are byte-identical. It then runs `syncCommand` with
  `vcs.enabled` off (rejects `osq sync needs vcs.enabled and git`), and
  `messageCommand`/`landCommand` with a vcs-enabled config in a git repo with
  no `osq.config.ts`, proving the passed config is used: both reject with
  `No archived change "999" in an osq worktree`, matching what
  `osq message 999` and `osq land 999` print to stderr through `runCli`.

`pnpm verify` exits 0; the existing land, message, sync, graph and spec tests
pass unchanged.

## Deviated

The acceptance says to call the three commands directly with "a `cwd` that has
no `osq.config.ts` and a passed `config`". Reaching the unknown-id refusal for
`message` and `land` needs `vcs.enabled` on, which the default (loaded) config
does not set, so the test passes a vcs-enabled `config` directly, then writes
`osq.config.ts` into the same repository before the `runCli` comparison. This
keeps a single no-config `cwd` for the direct calls while giving `runCli` the
config it needs to reach the same refusal.

## Missing context

The task did not say which `config` to pass for the `message`/`land` unknown-id
case. Because `buildSquashMessage` and `landChange` check `vcs.enabled` before
the archive lookup, a default config rejects with `osq message needs
vcs.enabled and git`, not the refusal, so I used a vcs-enabled config.
