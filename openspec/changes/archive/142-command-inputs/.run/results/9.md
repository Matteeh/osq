## Changed

- `src/cli/inbox-dispatch.ts`: `InboxDispatchOptions` now extends
  `CommandInputs` and drops its own `cwd`, `config`, `stdout` and `stderr`.
  `inboxDispatchCommand` resolves them through `resolveInputs` and awaits
  `inputs.config()` at the same point the old `loadConfig(cwd)` call sat (before
  the `--follow`/`--json` check). The text view and the JSON document now write
  `text + '\n'` through the resolved `stdout` in one call; the local `print`
  helper and its `console.log`/`console.error` fallbacks are gone. Added
  `lineWriter`, which appends `\n` to the resolved `stderr` for both wait
  recorders, and `defaultSound`, which builds the default `createInboxSound`
  with a `bell` seam writing the bell to `stdout` and a `warn` seam writing the
  message plus `\n` to `stderr`. `sessionOptions` and `followOptions` now always
  receive and forward the resolved `stdout` and `stderr` (no conditional
  spreads), and `createTerminalInput` is called with the resolved `stdout`.
- `src/cli/inbox-terminal.ts`: `createTerminalInput` takes an optional
  `stdout: Writer` defaulting to `processStdout`; `line` writes the question
  through it instead of `process.stdout.write`.
- `tests/inbox-dispatch.test.ts`: the text view expects
  `` `${formatDispatchText(...)}\n` `` and the empty view `'Nothing needs you.\n'`.
- `tests/inbox-cards.test.ts`: the no-terminal text view expects the trailing
  newline; the line-read test now passes a writer and asserts the question
  reaches it.
- New `tests/command-inputs-inbox.test.ts`: `osq inbox` and `osq inbox --json`
  run once through `runCliCaptured` (with `HOME` pointed at a temp dir) and once
  directly with `cwd`, `config`, `stdout`, `stderr`, `home` and
  `isTerminal: () => false`, asserting identical stdout and stderr and no
  process-stream leak; plus a card-session run with `home` as a file asserting
  the wait-log failure line reaches the passed `stderr`, and a `--follow` run
  with the `bell` sound config and manual watch/schedule/every seams asserting
  the bell reaches the passed `stdout`.
