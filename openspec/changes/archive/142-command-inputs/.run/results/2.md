## Changed

- `src/cli/status.ts`, `src/cli/queue.ts`, `src/cli/show.ts` and
  `src/cli/inbox.ts` now take `CommandInputs` through `resolveInputs`, load
  config at the same point as before, and write output as one
  `` `${text}\n` `` to `stdout` instead of `options.stdout(text)` or
  `console.log(text)`. `QueueCommandOptions` and `InboxCommandOptions` extend
  `CommandInputs`; `ShowCommandOptions` is new and extends it with `json`.
  Return values and positional arguments are unchanged.
- `tests/queue.test.ts` captures the queue CLI through `runCliCaptured`
  (`tests/cli-capture.ts`) instead of monkey-patching `console.log`.
- New `tests/command-inputs-views.test.ts` runs `osq status`, `osq queue`,
  `osq show 001`, `osq show 001 --json`, bare `osq` and `osq --json` once
  through `runCliCaptured` and once directly with string-appending `stdout`
  and `stderr` writers in the same project, asserting identical stdout and
  stderr and that the direct calls write nothing to the process streams. The
  bare `osq` calls share a temporary `home` (via `HOME` for the CLI call and
  the `home` option directly) and pass a fixed `now`; the project has no
  running tasks, so the fixed clock and the cursor both leave the text
  unchanged. Each CLI call also asserts a zero exit code.
