## Acceptance

- [ ] `PlanCommandOptions` extends `CommandInputs` instead of declaring `cwd`, and `planCommand` resolves its inputs through `resolveInputs`; a passed `config` replaces `loadConfig`, loaded at the same point as before.
- [ ] `--print` writes the prompt plus `\n` to `stdout`. The handoff line goes to `stdout` with its `\n`; `writePromptHandoff` moves from `plan-queue.ts` into `plan.ts`, its only caller, and takes the writer.
- [ ] `createChange` and `createQueueChange` take a `Writer | null` in place of `quiet`, and print the two created lines to it with `\n` when it is not null; `planCommand` passes its `stdout` only for `--session`, as `quiet` did.
- [ ] `prepareQueueSelection` takes an optional `stderr` writer, default `processStderr`, and writes the incomplete-cost notice plus `\n` to it; `planCommand` passes its `stderr`.
- [ ] Through `runCli`, `osq plan <name> --brief <file>`, `osq plan <name> --print` and `osq plan --next` print the same stdout and stderr as before and exit with the same code.
- [ ] New `tests/command-inputs-plan.test.ts` runs `osq plan --next --print` with an incomplete planning cost once through `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and `stderr` writers that append to strings, each on its own copy of the same project, and asserts the same stdout and stderr text both ways; it also asserts a handoff run writes its line to the passed `stdout`.
- [ ] `tests/plan-command-error.test.ts` reads the notice from the `stderr` writer or `tests/cli-capture.ts` instead of `console.error`, and asserts the same text.
