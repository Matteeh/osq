## Acceptance

- [ ] `LintCommandOptions` and `MigrateCommandOptions` extend `CommandInputs` instead of declaring `cwd`, `config` and `stdout`, and keep their `logger` option, which wins over `stderr` when both are passed. Without a `logger`, each logs through `commandLogger(options)`.
- [ ] `lintCommand --json` writes its document plus `\n` to the resolved `stdout`.
- [ ] `watchCommand` accepts `WatchCommandOptions & CommandInputs`, uses the resolved `cwd` and `config`, and gives the watcher and `recreateWorktrees`' lines a logger from `commandLogger(options, resolveLogLevel(options))`. The `--dev` supervisor path is unchanged.
- [ ] Through `runCli`, `osq lint <id>`, `osq lint --json`, `osq migrate <target>` and `osq watch --once` print the same stdout and stderr as before and exit with the same code.
- [ ] New `tests/command-inputs-logger.test.ts` runs `osq lint <id>` on an invalid change and `osq migrate legacy` once through `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and `stderr` writers that append to strings, and asserts the same stdout and stderr text both ways.
- [ ] The same test calls `watchCommand({ once: true, allowStale: true, cwd, config, stderr })` on a temporary project with nothing to run and asserts nothing reaches the process streams.
- [ ] Every existing lint, migrate and watch test passes unchanged.

## Details

The lint fixture needs a local `node verify.cjs` verifier, as
`tests/lint-command-error.test.ts` builds one. The logger behind `lint` and
`migrate` never animates, so its text is the same through either writer.
