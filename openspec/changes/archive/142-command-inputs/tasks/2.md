## Acceptance

- [ ] `statusCommand`, `queueCommand`, `showCommand` and `inboxCommand` accept `CommandInputs`, through `resolveInputs`, and keep their other options and return values. `QueueCommandOptions` and `InboxCommandOptions` extend `CommandInputs` instead of declaring `cwd`, `config` and `stdout` themselves.
- [ ] Each writes its output to `stdout` as one write of the text plus `\n`, where it called `options.stdout(text)` or `console.log(text)` before, and loads its config at the same point as before.
- [ ] Through `runCli`, `osq status`, `osq queue`, `osq show <id>`, `osq show <id> --json`, `osq` and `osq --json` print the same stdout and stderr as before and exit with the same code.
- [ ] New `tests/command-inputs-views.test.ts` runs each of those commands once through `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and `stderr` writers that append to strings, in the same project, and asserts the same stdout and stderr text both ways, with nothing written to the process streams by the direct call.
- [ ] `tests/queue.test.ts` captures the CLI output through the new writers or `tests/cli-capture.ts` instead of `console.log`, and asserts the same text.

## Details

The bare `osq` command advances the inbox cursor; pass `home` to a temporary
folder in the new test, as `tests/inbox.test.ts` does, and use a fixed `now`
on both calls so their text matches.
