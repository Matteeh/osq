## Acceptance

- [ ] `ApproveCommandOptions` extends `CommandInputs` instead of declaring `cwd` and `config`, and `approveCommand` resolves them through `resolveInputs`, loading config at the same point as before.
- [ ] The digest, the flag lines and the approval result lines go to `stdout` as each line plus `\n`; each `Warning:` line goes to `stderr` with its `\n`, where it used `console.warn` before.
- [ ] `requestApproval`'s `print` option is required and receives each flag line without its newline; `approveCommand` passes one that writes the line plus `\n` to its `stdout`. The prompt still asks through `ask`.
- [ ] Through `runCli`, `osq approve <id>` prints the same stdout and stderr as before and exits with the same code, flagged and unflagged.
- [ ] New `tests/command-inputs-approve.test.ts` approves a flagged change once through `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and `stderr` writers that append to strings, each on its own copy of the same project, and asserts the same stdout and stderr text both ways; it also covers a `--confirm` run with `isTerminal` true and an `ask` stub, whose flag lines reach `stdout`.
- [ ] `tests/approve-confirm.test.ts` and `tests/approve-rejected-branch.test.ts` capture the output through the new writers, `tests/cli-capture.ts` or `captureLogs` instead of console methods, and assert the same lines.
