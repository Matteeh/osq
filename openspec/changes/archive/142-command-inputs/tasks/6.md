## Acceptance

- [ ] `newCommand(name, options)`, `initCommand(options)` and `setupCommand(options)` accept `CommandInputs` through `resolveInputs`; `initCommand`'s options also keep `refreshSchema`. `setupCommand()` with no argument still works.
- [ ] Each writes every line it printed with `console.log` to `stdout` as the line plus `\n`, in the same order, and loads config at the same point as before: inside the error handling for `new`, outside it for `init` and `setup`.
- [ ] Through `runCli`, `osq new <name>`, `osq init` and `osq init --refresh-schema` print the same stdout and stderr as before and exit with the same code.
- [ ] New `tests/command-inputs-scaffold.test.ts` runs `osq new <name>` and `osq init` once through `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and `stderr` writers that append to strings, each in a fresh temporary project, and asserts the same stdout and stderr text both ways.
- [ ] The same test calls `setupCommand` with a temporary `cwd`, a `config` whose `harness` is `mock`, and a `stdout` writer, and asserts it receives exactly `Harness 'mock' setup completed successfully.\n`.
- [ ] `tests/init-refresh-schema.test.ts` and `tests/rules-block.test.ts` capture the output through the new `stdout` option or `tests/cli-capture.ts` instead of `console.log`, and assert the same lines.

## Details

`osq init` output names created files, which are the same in two fresh
projects built the same way; compare after building both.
