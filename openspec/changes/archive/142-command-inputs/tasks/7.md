## Acceptance

- [ ] `RejectCommandOptions` extends `CommandInputs` and keeps `reason`; `RetryCommandOptions` is `CommandInputs`. Both commands resolve their inputs through `resolveInputs` and load config at the same point as before.
- [ ] Each writes every line it printed with `console.log` to `stdout` as the line plus `\n`, in the same order. Error messages are unchanged.
- [ ] Through `runCli`, `osq reject <id> --reason <text>` and `osq retry <id> <target>` print the same stdout and stderr as before and exit with the same code.
- [ ] New `tests/command-inputs-lifecycle.test.ts` runs a reject and a retry once through `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and `stderr` writers that append to strings, each on its own copy of the same project state, and asserts the same stdout and stderr text both ways.
- [ ] `tests/reject-worktree.test.ts` and `tests/retry-recertification.test.ts` capture the output through the new `stdout` option or `tests/cli-capture.ts` instead of `console.log`, and assert the same lines.
