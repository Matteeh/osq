## Acceptance

- [ ] `DoctorCommandOptions` and `ServeCommandOptions` extend `CommandInputs` instead of declaring `cwd`, `config` and `stdout` themselves, and both commands resolve them through `resolveInputs`. Their other options are unchanged.
- [ ] `doctorCommand` writes each check line to `stdout` with its `\n`. A passed `config` reaches `runDoctorChecks` through its `loadConfig` dependency; without one, doctor loads config as before.
- [ ] `serveCommand` writes the URL line and each export line to `stdout` with its `\n`, and loads config at the same point as before.
- [ ] Through `runCli`, `osq doctor` and `osq serve --export <dir>` print the same stdout and stderr as before and exit with the same code.
- [ ] New `tests/command-inputs-doctor-serve.test.ts` runs `osq doctor` and `osq serve --export <dir>` once through `runCliCaptured` and once directly with `cwd`, `config`, `stdout` and `stderr` writers that append to strings, and asserts the same stdout and stderr text both ways. It also asserts a passed `config` reaches doctor's config check.
- [ ] `tests/doctor-command-error.test.ts`, `tests/serve.test.ts` and `tests/serve-export.test.ts` expect the trailing newline their `stdout` writer now receives.

## Details

Tests in `serve.test.ts` and `serve-export.test.ts` await the first URL line
before aborting the server; when the line no longer equals the expected URL
they hang instead of failing, so update every such comparison.
