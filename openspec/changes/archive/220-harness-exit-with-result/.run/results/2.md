## Changed

- `src/harness/types.ts`: added `exit_continued` to `HarnessEventType` and `OsqEventData`, with the new `ExitContinuedEventData` payload (`exitCode: number`).
- `src/watcher/task-result.ts`: new module holding `ensureTaskResult`, `EnsureTaskResultOptions` and `EnsureTaskResultOutcome` unchanged, plus `resultWrittenSince`, which reports whether `.run/results/<n>.md` exists with an mtime at or after a given epoch-millisecond time.
- `src/watcher/spawn.ts`: re-exports the moved result helpers, and after the usage-limit pause check and before the dead-marker branch, a non-zero non-timeout exit whose result file was written during this attempt appends one `exit_continued` event with a verbose log line and returns `{ ok: true, elapsedMs }`. Every other non-zero exit and every timeout still goes through `describeAgentFailure`.
- `tests/exit-with-result.test.ts`: new table-driven test running `runTask` with `MockAdapter` for every row of "Agent exit and result file", asserting the done/dead marker, the dead reason, and the `exit_continued` events. The earlier-attempt row writes `.run/results/1.md` an hour back with `fs.utimes` and runs with `writeResult: false`.
- The four crash tests that expected `crashed` with the mock's default result now set `writeResult: false`: the `crashed` row of `DEAD_SCENARIOS`, the crashed outcome-logging case, the halt-logging case, and the real-run dead-fingerprint case.

## Deviated

- `resultWrittenSince` allows a 1-second clock-granularity tolerance: on this filesystem, kernel-assigned mtimes trail `Date.now()` by several milliseconds (a file written during the attempt can read as up to ~10 ms before the recorded spawn start), so a strict `mtimeMs >= sinceMs` would reject the agent's own fresh result. One second also covers a coarse one-second mtime granularity, while a result left by an earlier attempt is minutes or more old. The constant is documented in `src/watcher/task-result.ts`.
