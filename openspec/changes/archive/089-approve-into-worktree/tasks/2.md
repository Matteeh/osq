- [ ] `ChangeTree` gains optional `worktreeFolder`, and `changeTrees` and `listChanges` follow the status-inspection delta's modified "Change locations": the project root first, then one tree per osq worktree when `config.vcs?.enabled` and `selectVcs` returns git.

- [ ] `runWatcherCycle` skips every active change whose tree has `worktreeFolder`, as the watcher-and-harness delta's "Worktree changes wait" says.
- [ ] New `tests/change-locations-worktrees.test.ts` covers the "Running change in a worktree", "Worktree of another branch", and "One tree today" scenarios, and "Approved change in a worktree" through `runWatcherCycle` with the mock adapter.

## Details

Select through `selectVcs` on the project root and read `worktreeList`; never
import `GitVcs`. Compare worktree paths with `fs.realpath` on both sides,
because git reports resolved paths. Build a worktree tree's directories with
`getChangesDir`, `getArchiveDir`, and `getRejectedDir` on the worktree path.
Tests create a temporary repository with `git init -b main`, commit the
folders, run `git branch osq/001-a` and `git worktree add <tmp>/wt/001-a osq/001-a`
with the worktree folder inside the test's temporary folder but outside the
repository, and write `.run/approved` there. Pass a config with
`vcs: { enabled: true, author: 'osq <osq@example.org>', worktreeRoot: <tmp>/wt }`.
`src/watcher/loop.ts` is on the line budget's allow list, and
`runWatcherCycle` is grandfathered in the function budget; add only the skip.
