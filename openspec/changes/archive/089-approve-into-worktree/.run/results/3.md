## Changed

- `startWebServer` now resolves `changeTrees(projectRoot, config)` once and passes
  them as `trees` to `createInvalidationHub`.
- Added `src/core/web/web-trees.ts` holding `singleChangeTree`,
  `classifyChangePath`, and the new `classifyTreePath` / `treeWatchPaths` helpers.
  The hub watches the first tree's configured OpenSpec root plus the change
  folder (`changesDir`/`worktreeFolder`) of each worktree tree, and a path inside
  a worktree's change folder invalidates that folder's numeric id.
- `web-events.ts` keeps exporting `classifyChangePath` (re-export) for existing
  focused tests, and falls back to `singleChangeTree` when no `trees` are given,
  so hub behaviour without `trees` is unchanged.
- Added `tests/serve-sse-worktrees.test.ts`: one unit scenario covering worktree
  classification with the injectable `watch`/`schedule` seams and the no-trees
  baseline, and one "Server wiring" scenario against a temporary git repository
  with one `osq/001-a` worktree.

## Deviated

- Moved `classifyChangePath` and `folderKeyWithin` into `web-trees.ts` as well,
  not only `singleChangeTree`, to avoid a circular import between `web-events.ts`
  and `web-trees.ts`. The value is re-exported from `web-events.ts`, so its
  public surface and all existing imports are unchanged.
