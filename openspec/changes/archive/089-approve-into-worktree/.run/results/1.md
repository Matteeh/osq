## Changed

- `src/core/foundation/config-vcs.ts`: added `VcsConfig.defaultBranch`, validated and trimmed through the existing `trimmedField`; exported `DEFAULT_BRANCH` (`main`) and `DEFAULT_WORKTREE_ROOT` (`~/.osq/worktrees`). `DEFAULT_VCS_CONFIG` remains `{ enabled: false }`.
- `src/core/vcs/vcs.ts`: added `defaultBranch(): Promise<string>` to the `Vcs` port.
- `src/core/vcs/git-vcs-write.ts`: added `defaultBranch(ctx, fallback)`, reading `refs/remotes/origin/HEAD` with `symbolic-ref --quiet --short` and stripping the `origin/` prefix, else the fallback.
- `src/core/vcs/git-vcs.ts`: implemented `defaultBranch()` by delegating to the write helper with `config.vcs?.defaultBranch ?? DEFAULT_BRANCH`.
- `src/core/vcs/no-vcs.ts`: implemented `defaultBranch()` returning `DEFAULT_BRANCH`.
- `src/core/vcs/worktree.ts` (new): `worktreeBranch(folderName)` and `worktreePath(config, repoRoot, folderName, home)`; expands a leading `~` and defaults `home` to `os.homedir()`.
- `tests/vcs-write.test.ts`: added `defaultBranch` to `PORT_MEMBERS`; nothing else changed.
- `tests/vcs-worktree-setup.test.ts` (new): covers the trimmed/blank `defaultBranch` through `loadConfig`, both default-branch port scenarios in temporary repositories, and both worktree-location scenarios.

## Deviated

- `worktreePath` takes a `VcsConfig`, not the whole `OsqConfig`, since the location derives from `vcs.worktreeRoot`. Callers holding an `OsqConfig` can pass `config.vcs ?? DEFAULT_VCS_CONFIG`.

## Missing context
