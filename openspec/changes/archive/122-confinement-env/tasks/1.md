- [ ] `src/core/foundation/config.ts` stays within 250 lines. It is at 249, and the new lines take it to about 254, so write the `log` and `limits` merges in `defineConfig` on one line each, for example `log: { ...DEFAULT_CONFIG.log, ...(config.log || {}) },`. Behavior does not change.
- [ ] `HarnessCatalogEntry` in `src/core/foundation/harness-catalog.ts` gains a required `readonly agentEnv: readonly string[]`, and every entry in `DEFINITIONS` carries the names the cli-foundation delta's "Harness agent environment names" lists, in that order.
- [ ] New `src/core/run/role-env.ts` exports `BASE_ENV_NAMES` and `buildRoleEnv` exactly as the watcher-and-harness delta's "Role environments" describes. It finds a harness's names with `findHarness`, and an unknown harness name adds no `agentEnv` names. It reads the role's names from `config?.confinement?.roles[role].env`, so a config without the block still works. It exports the `RoleEnvOptions` type it takes.
- [ ] New `tests/confinement-env.test.ts` covers the cli-foundation delta's "Default", "One role", "Unknown role", "Flat key", "Bad name", and "Every entry declares names", and the watcher-and-harness delta's "Base and OSQ variables pass", "Configured verify name", "Agent gets its harness keys", "Verify never gets the model key", and "Extra variables win". It calls `buildRoleEnv` with a `source` object, so it never changes `process.env`, and it checks that the source is unchanged afterwards.
