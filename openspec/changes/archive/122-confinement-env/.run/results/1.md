## Changed

- Added `src/core/foundation/config-confinement.ts`: `ConfinementRole`,
  `CONFINEMENT_ROLES`, `ConfinementConfig`, `ConfinementRoleConfig`,
  `DEFAULT_CONFINEMENT_CONFIG`, `validateConfinementConfig`, plus the
  per-harness `agentEnv` allowlist (`HARNESS_AGENT_ENV`). Validation throws the
  delta's messages byte for byte and always resolves all three roles.
- `src/core/foundation/config.ts`: validates `config.confinement` in
  `defineConfig`, adds `OsqConfig.confinement`, sets `DEFAULT_CONFIG.confinement`,
  re-exports `ConfinementConfig`.
- `src/core/foundation/config-user.ts`: omits the resolved `confinement` and
  accepts the partial `{ roles?: Partial<Record<ConfinementRole, { env?: ... }>> }`
  shape.
- `src/core/foundation/harness-catalog.ts`: `HarnessCatalogEntry` gains a
  required `agentEnv`; every `DEFINITIONS` entry carries its names in the
  delta's order.
- Added `src/core/run/role-env.ts`: `BASE_ENV_NAMES`, `RoleEnvOptions`, and
  `buildRoleEnv`. Copies the base names, every `OSQ_` name, the role's
  configured names, and (agent only) the harness's `agentEnv`; prepare and
  verify never get a harness `agentEnv` name; extras win; Windows matches
  case-insensitively; result is a new object and the source is untouched.
- Added `tests/confinement-env.test.ts` covering the config scenarios, the
  catalog agent-env lists, and the role-environment scenarios. It passes a
  `source` object everywhere and asserts the source is unchanged.

## Deviated

- The harness `agentEnv` literals live in `HARNESS_AGENT_ENV` in
  `config-confinement.ts` and the catalog entries reference them
  (`agentEnv: HARNESS_AGENT_ENV.pi`), instead of inlining each array in
  `DEFINITIONS`. `harness-catalog.ts` was already at the 250-line budget, so
  inline arrays (especially `pi`'s 25 names and `opencode`'s 12) would have
  blown it; one reference line per entry keeps the catalog within budget while
  every entry still declares its names.
- To fit the new import, interface field, and six `agentEnv` assignments in
  `harness-catalog.ts`, I compressed the module doc comment and the
  `resolveExecutorIdentity` doc comment to one line each and dropped one blank
  line. No behavior changed.
- `config.ts` landed at the 250-line cap (not below it). The `log` and `limits`
  merges are one line each as the task asked; the two `config-confinement.js`
  imports are split because the combined import exceeds Biome's 100-column
  width and would be expanded to five lines.

## Missing context

- The task only warned about `config.ts`'s line budget, but
  `harness-catalog.ts` was also at 249 `wc -l` (250 by the budget test's
  `split('\n')` count). Adding a required `agentEnv` to six entries needed
  compression there too, which is why the lists live in
  `config-confinement.ts` rather than inline.
