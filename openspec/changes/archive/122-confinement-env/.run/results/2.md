## Changed

- `src/core/run/verification.ts`: added exported `VerificationCommandOptions`
  (`role?`, `config?`, `extraEnv?`) and replaced the trailing `extraEnv`
  parameter with it. The child environment is now `buildRoleEnv(role ??
  'verify', { config })`, then `OSQ_CHANGE` is set or removed, then
  `extraEnv`. `process.env` is no longer spread; the doc comment says so.
- `src/core/run/mutation-run.ts`: `runMutationPick` takes an optional `config`
  as its last argument and passes `{ config, extraEnv: { OSQ_MUTATE,
  OSQ_MUTATION_TESTS, OSQ_MUTATION_REPORT } }` to `runVerificationCommand`.
- `src/core/run/focused-tests.ts`: `runFocusedTests` passes `{ config }`.
- `src/core/lifecycle/retry.ts`: the recertification verify passes `{ config }`.
- `src/core/lifecycle/verification-record.ts`: `runCheck` passes `{ config }`
  with its null change folder.
- `src/core/spec/approve-worktree.ts`: `runPrepare` passes
  `{ role: 'prepare', config }`.
- `src/core/vcs/sync-verify.ts`: `runOne` passes `{ config: options.config }`.
- Added `tests/verify-role-env.test.ts`: three scenarios. Each sets probe
  variables on `process.env` inside the test and restores them in a `finally`.
  Commands are `node -e` one-liners that exit 0 only when the expected
  variables are set and the forbidden ones are absent. It covers the verify
  role (VERIFY_PROBE seen, SECRET_PROBE not), the prepare role through
  `runPrepare` with a `defineConfig` `vcs.prepare` (NPM_TOKEN seen,
  VERIFY_PROBE and SECRET_PROBE not), and the archived check case with a null
  change folder while osq's environment has `OSQ_CHANGE`.

## Deviated

- `runVerificationCommand` builds from `buildRoleEnv` without passing
  `extraEnv` into it, then applies `OSQ_CHANGE`, then `extraEnv`. The delta
  says build then `OSQ_CHANGE` then `extraEnv`, while `buildRoleEnv` says
  extras are set last. Applying them in the command after `OSQ_CHANGE`
  satisfies both, and lets a caller's extra win over `OSQ_CHANGE` exactly as
  the acceptance describes.
