## Changed

- Added `crates/core/src/feature.rs`: the object-safe `Feature` trait and the
  `Command`, `Invocation`, `Output` and `FeatureError` types, all
  `#[non_exhaustive]` with the `new`/`text`/error constructors, plus `Display`
  and `std::error::Error` for `FeatureError`.
- Declared `pub mod feature;` and re-exported `Command`, `Feature`,
  `FeatureError`, `Invocation` and `Output` from `crates/core/src/lib.rs`.
- Added `crates/core/tests/feature.rs`, implementing `echo` and `count` by
  hand and proving all four rust-core scenarios with the literal table values:
  command runs, `Box<dyn Feature>` registration and dispatch, constructor
  fields and error text.

## Deviated

`FeatureError::UnknownCommand` is a `#[non_exhaustive]` tuple variant, so a
test outside `osq-core` cannot bind its field. The constructor test therefore
checks the variant with `matches!(..., FeatureError::UnknownCommand { .. })`
and checks the name through the displayed text; `Usage` and `Failed` bind
their public fields directly with a wildcard arm.

Verification: `cargo test -p osq-core --test feature` passes; `cargo mutants
-p osq-core -f crates/core/src/feature.rs` reports 1 caught and 4 unviable,
with no missed mutant; `OSQ_CHANGE=openspec/changes/240-rust-feature-trait sh
scripts/verify-rust.sh` passes.

Touched: crates/core/src/feature.rs, crates/core/src/lib.rs, crates/core/tests/feature.rs
