## Acceptance

- [ ] New `crates/core/src/feature.rs` holds the `Feature` trait and the types `Command`, `Invocation`, `Output` and `FeatureError`, following rust-core "Feature trait" and "Feature errors" and section 1 of `adr/028-rust-feature-trait.md` in this change folder.
- [ ] `Feature` has exactly the methods `fn name(&self) -> &str`, `fn commands(&self) -> Vec<Command>` and `fn run(&self, invocation: &Invocation) -> Result<Output, FeatureError>`, with no default bodies and no supertraits.
- [ ] `Command` has public `String` fields `name`, `summary` and `usage`; `Invocation` has public fields `root: PathBuf` (from `std::path`), `command: String` and `args: Vec<String>`; `Output` has the public field `text: String`. `FeatureError` is an enum with `UnknownCommand(String)`, `Usage { command: String, message: String }` and `Failed { command: String, message: String }`. All five types derive `Debug`, `Clone`, `PartialEq` and `Eq`. These four types and each `FeatureError` variant are `#[non_exhaustive]`, and each type has the constructors of rust-core "Feature constructors": `Command::new`, `Invocation::new`, `Output::text`, `FeatureError::unknown_command`, `FeatureError::usage` and `FeatureError::failed`. Each takes `impl Into<String>` for its strings, `impl Into<PathBuf>` for `root`, and `Vec<String>` for `args`. Fields stay public.
- [ ] `FeatureError` implements `Display` with the texts of "Feature error text" and implements `std::error::Error` with an empty body.
- [ ] `src/lib.rs` declares `pub mod feature;` and re-exports `Command`, `Feature`, `FeatureError`, `Invocation` and `Output`. Nothing else in it changes.
- [ ] New `crates/core/tests/feature.rs` implements the `echo` and `count` features by hand and proves "A hand-written feature runs its commands", "Features register as a list", "Constructors fill every field" and "Feature error text" with the literal values of their tables and THEN lines. `count` counts its args and prints the number. The test file builds every `Command`, `Invocation`, `Output` and `FeatureError` through the constructors, never with a struct or variant literal (the compiler refuses those outside core), and "Constructors fill every field" asserts every public field each constructor sets, so a mutant that drops or swaps a constructor argument fails a test. Its `FeatureError` rows check the variant and fields with `matches!` or a `match` with a wildcard arm.
- [ ] Every public item's doc, trait methods included, ends with `Implements: rust-core/feature-trait`, for each constructor `Implements: rust-core/feature-constructors`, or, for `FeatureError` and its `Display`, `Implements: rust-core/feature-errors`. Each test's doc names `Covers: rust-core/<scenario>` in kebab-case, such as `Covers: rust-core/feature-error-text`.

## Details

Model the trait's docs on the `Rule` trait in `crates/core/src/graph.rs`, and
the test's helper style on `crates/core/tests/schedule.rs`.

Core does no IO (rust-core "Core does no IO"): no file under
`crates/core/src/` may contain the text `std::fs`, `std::process`,
`std::env`, `std::net`, `std::thread`, `SystemTime` or `Instant`, comments
included, and core gains no dependency. `std::path::PathBuf` is allowed.

Do not write an `Adr:` tag in any doc comment; ADR 028 reaches `decisions/`
only in task 2.

cargo-mutants runs on every line this task adds. Each `Display` arm must
change a text a test checks, and each constructor argument must reach a field a test checks. Before exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-core -f crates/core/src/feature.rs -o "$(mktemp -d)"`,
then `OSQ_CHANGE=openspec/changes/240-rust-feature-trait sh scripts/verify-rust.sh`.
The link gates corpus needs `OSQ_CHANGE` to see this change's new
requirements while they live only in its delta.
