- [ ] `show`, `report` and `inbox` each call rust-vcs `project_git_root` right after `load_config`, as rust-vcs "Project root check" says, and use its folder where show's `git_root`, report's `git` and inbox's `changes` decided before whether git is on; their own root comparisons are gone.
- [ ] New `tests/show_nested_root.rs`, `tests/report_nested_root.rs` and `tests/inbox_nested_root.rs` each prove their crate's rows of rust-vcs "Every git command refuses a nested root", building `<outer>` themselves.
- [ ] `show_git_on_requires_the_repository_root` in `tests/show_land.rs` and `report_git_off_below_the_repository_top` in `tests/report_trees.rs` now expect that refusal instead of "git off"; every other show, report and inbox test passes unchanged.
- [ ] Each new test's doc names `Covers: rust-vcs/every-git-command-refuses-a-nested-root`; every function this task adds or changes keeps or gains an `Implements:` tag.
- [ ] `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Map the `NestedRoot` to `FeatureError::failed` with the command's own
name and its display. `spec` and `query` read no git and stay as they
are. Run each command through its crate's `Feature::run` with an
`Invocation` on `<outer>/sub`. Snapshot `<outer>`'s git state with the
git CLI in the test, with `GIT_CONFIG_GLOBAL=/dev/null` and
`GIT_CONFIG_NOSYSTEM=1`. A rough version of this change, measured on
2026-10-23, broke only the two named tests in these crates.

Run the proposal's verify with
`OSQ_CHANGE=openspec/changes/315-vcs-root-fails-fast`, so the link gates
see this change's requirements.
