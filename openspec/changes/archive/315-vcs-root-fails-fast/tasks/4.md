## Acceptance

- [ ] `archive`, `retry` and `run` each call rust-vcs `project_git_root` right after `load_config`, as rust-vcs "Project root check" says, and use its result wherever they decided before whether git is on: archive's `lookup::find`, retry's `find_archived`, and run's `git_on` and `refusals::check`.
- [ ] Their own root comparisons are gone; archive's lookup no longer lists worktrees for a root `project_git_root` gives no folder for.
- [ ] New `tests/archive_nested_root.rs`, `tests/retry_nested_root.rs` and `tests/run_nested_root.rs` each prove their crate's rows of rust-vcs "Every git command refuses a nested root", building `<outer>` themselves.
- [ ] Each new test's doc names `Covers: rust-vcs/every-git-command-refuses-a-nested-root`; every function this task adds or changes keeps or gains an `Implements:` tag; every other test of the three crates passes unchanged.
- [ ] `cargo fmt --all`, then the proposal's verify, pass with no missed mutant.

## Details

Map the `NestedRoot` to `FeatureError::failed` with the command's own
name and its display. The run row refuses before the harness check, so
the default harness in `osq.toml` does not matter. Run each command
through its crate's `Feature::run` with an `Invocation` on `<outer>/sub`.
Snapshot `<outer>`'s git state with the git CLI in the test, with
`GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`.

Run the proposal's verify with
`OSQ_CHANGE=openspec/changes/315-vcs-root-fails-fast`, so the link gates
see this change's requirements.
