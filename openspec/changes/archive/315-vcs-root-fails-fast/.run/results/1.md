## Changed

- `src/core/vcs/select.ts`: added the exported `NestedRootError`, and made
  `selectVcs` throw it when `vcs.enabled` is true and the real project root
  differs from git's real top level; with `vcs.enabled` off it still returns
  `NoVcs('not the repository root')`.
- `src/cli/run.ts`: reports `NestedRootError` like `ConfigLoadError`, printing
  `Error: <message>` to stderr and setting exit code 1 without ending the
  process.
- `tests/vcs-root-refusal.test.ts`: proves the new version-control and
  cli-foundation scenarios, including every command row and the unchanged
  repository state before and after each command.
- Ran the task verify, `pnpm verify`, and `sh scripts/verify-rust.sh`; all pass.

## Deviated

- The living `openspec/specs/cli-foundation/spec.md` contains several repeated
  scenario names (for example `Explicit settings win`, `Default`, and
  `Defaults`), so `lookupScenario` refuses that capability before the new
  cli-foundation scenario can run. The test copies only the real
  `Config error exit` requirement and the change's real cli-foundation delta
  into a temporary openspec root for that one lookup, leaving every spec file
  untouched. The version-control scenarios use the real spec and delta.

## Outside scope

- `openspec/specs/cli-foundation/spec.md` has duplicate scenario names across
  requirements. That is a pre-existing spec problem, not changed here.
