## Changed

- `crates/features/plan/src/next.rs`, `next/number.rs`, `steer.rs` and
  `steer/lookup.rs`: `plan --next` and `plan <id>` now load `osq.toml`, call
  rust-vcs `project_git_root`, and map a `NestedRoot` to `plan failed:
  <display>`. The next number and steering lookup pass the kernel's repository
  top level to `trees::list`; `plan --next` refuses before it reads the queue,
  and the steering lookup no longer decides git from `vcs.enabled`.
- `crates/features/lint/src/lint.rs` and `lint/entry.rs`: `lint` loads the
  config and checks `project_git_root` before listing changes, mapping a
  `NestedRoot` to `lint failed: <display>`. `Tree::read` takes the kernel's
  folder and the entry root comparison is gone; `project_paths` is unchanged.
- `crates/features/doctor/src/doctor.rs`: `doctor` loads the config and checks
  `project_git_root` before building any line, mapping a `NestedRoot` to
  `doctor failed: <display>`; with `vcs.enabled` off its git lines are unchanged.
- Added `tests/plan_nested_root.rs`, `tests/lint_nested_root.rs` and
  `tests/doctor_nested_root.rs`. Each builds its own `<outer>` under
  `CARGO_TARGET_TMPDIR`, runs the crate's rows through `Feature::run` on
  `<outer>/sub`, checks the full refusal, and checks that `<outer>`'s status,
  branches, worktrees and files outside `.git` are unchanged.
- Changed `lint_entry_git_nested_project` in `tests/lint_entry_git.rs` to expect
  the nested-root refusal instead of the old git-off finding.
- Ran `cargo fmt --all`, the task verify, every plan, lint and doctor test, and
  the proposal verify with `OSQ_CHANGE=openspec/changes/315-vcs-root-fails-fast`;
  all pass.

  found 30 mutants: 22 caught, 8 unviable, none missed.
