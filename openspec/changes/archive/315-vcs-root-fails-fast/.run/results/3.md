## Changed

- `src/approve.rs`: `run_approve` now calls rust-vcs `project_git_root` right
  after `load_config` and maps a `NestedRoot` to `approve failed: <display>`;
  the feature-local `git_repo` helper and its root comparison are gone.
- `src/reject.rs`: `run_reject` calls `project_git_root` right after
  `load_config`, maps `NestedRoot` to `reject failed: <display>`, and passes the
  resulting folder down to `locate`, which no longer calls `git_repo`.
- Added `tests/approve_nested_root.rs`, which builds a fresh `<outer>` under
  `CARGO_TARGET_TMPDIR` with the nested fixture, runs the approve and reject
  rows through `ApproveFeature::run` on `<outer>/sub`, and checks both the
  refusal text and that `<outer>`'s status, branches, worktrees and files
  outside `.git` are unchanged.
- Changed `git_off_approves_in_the_checkout` in `tests/approve_worktree.rs` to
  write an `osq.toml` with `enabled = false`; the output and marker checks are
  unchanged.
- Ran `cargo fmt --all`, the task verify, `cargo test -p osq-feature-approve`,
  and the proposal verify with
  `OSQ_CHANGE=openspec/changes/315-vcs-root-fails-fast`; all pass. A cargo-mutants
  run over the changed source lines found 5 mutants: 4 caught, 1 unviable.

## Deviated

- No `OSQ_DIFF` was available outside the watcher, so I reconstructed the
  pre-change source of `approve.rs` and `reject.rs`, wrote a unified diff of
  only this task's changed lines, and ran `scripts/mutants-rust.sh` on it.
- The `enabled = false` config in `git_off_approves_in_the_checkout` is written
  inline because the shared `write_config` helper lives in
  `tests/worktree_support/mod.rs`, outside this task's scope.
