## Changed

- `src/watcher/git-guard.ts`: `GitGuard.check()` now returns a `GuardViolation` (`reason`, `marker`, `error`) or null. `beginGitGuard` computes a `kill` flag from `vcs.enabled` and the pre-spawn HEAD branch starting with `osq/`, and only that guard returns a violation; elsewhere it records the same events as before. The violation dead marker is built from `formatVcsViolationWarning` for `vcs_violation` and the file list for `scope_violation`, with `vcs_violation` winning when both happen.
- `src/watcher/git-guard.ts`: a file under `tests/` that status lists as untracked after spawn and did not list before spawn is filtered out of scope violations.
- `src/watcher/runner.ts`: `runTask` stores the guard's violation and, after the spawn-failure return, kills with it in one statement. Runner stays at 197 lines.
- `src/watcher/failure-reason.ts`: adds `vcs_violation` and `scope_violation`.
- `tests/worktree-guard.test.ts`: covers the three "Violations kill in a worktree" scenarios, the new-test-file exemption in both the worktree and the checkout, and both violations at once dying with `vcs_violation`.

## Deviated

- Kept the `gitGuard.check()` call where it was (before the spawn-failure return) and placed only the kill statement after that return, so events keep being recorded when a spawn already failed while the task still keeps its spawn failure.
- The worktree commit scenario asserts the dead marker contains `formatVcsViolationWarning(moved)` for the moved fields the event recorded, rather than a fixed `['head']`, because a commit also moves the index digest.
