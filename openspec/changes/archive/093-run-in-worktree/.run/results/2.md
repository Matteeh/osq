## Changed

- `src/watcher/loop.ts`: removed the `continue` that skipped worktree changes. A worktree change now reaps locks, records each reaped `crashed`/`timeout` through the dead commit, auto-retries, commits pending verified tasks, checks the worktree before spawning, commits the passing task, commits the dead task, and commits the archive. The clean check runs before both spawn and archive; every halt writes a change-level regression and skips the change. Flag-off behaviour is unchanged because every new call is gated on `change.tree.worktreeFolder`.
- `src/watcher/worktree-run.ts` (new): `checkWorktree` (HEAD on `osq/<folder>`, status clean outside the change folder's `.run/` and `tasks.md`), `haltWorktreeChange` (`writeRegressedMarker` + `recordRegressedEvent` for target `change` + one log line), and the `WorktreeHalt` types.
- `src/watcher/worktree-commit.ts` (new): `commitWorktreeVerifiedTask`, `commitPendingVerifiedTasks`, `commitWorktreeDeadTask`, `commitWorktreeArchive`, plus the pending-done scan and the new archive-folder detection. Outcome lines use `formatTaskOutcomeLine` with symbols off and whole seconds since the last `started` event.
- `src/core/run/task-commit.ts` (new): `commitVerifiedTask` (scope-covered status paths, a rename's source, untracked `tests/` files, and the `.run/done`, `.run/results`, `.run/events`, and `tasks.md` records) and `commitArchive` (the old change folder, the archive directory, and the living specs directory, with the `Osq-Change` trailer).
- `src/watcher/auto-retry.ts`: `vcs_violation` and `scope_violation` join the eligible reasons.
- `tests/worktree-run.test.ts` (new): drives `runWatcherCycle` over a real temporary repository with a change approved into a linked worktree. Covers the worktree run and `OSQ_CHANGE`, dirty and off-branch halts and clearing a halt, records-not-dirt, two verified commits and their contents, a new outside-scope test file, a commit left undone, the archive commit and a clean worktree, a rejected hook and its retry, the runner and reaper dead paths with their patches, and the scope-violation automatic retry.
- `tests/change-locations-worktrees.test.ts`: dropped the `Watcher worktree wait` case and the two imports only it used.
- `README.md`: the Version control section now describes the watcher running inside the worktree, its task and archive commits, the dead patch, the halts, the violation kills, and that stacking is not implemented so `vcs.enabled` stays off; the automatic-retry bullet and dead-reasons paragraph name `vcs_violation` and `scope_violation`.

## Deviated

- The "Off its branch" scenario is exercised by calling `checkWorktree` and `haltWorktreeChange` directly with a located change after switching the worktree branch, instead of through `runWatcherCycle`. `changeTrees` only reports worktrees whose branch starts with `osq/`, so once the branch is switched the resolver drops the tree and the cycle never reaches the check. The check remains in the loop and fires for a branch moved between resolution and the check or archive.
- `commitPendingVerifiedTasks` treats a done marker as pending when status lists it untracked (`??`) or newly staged (`A `). `vcs.commit` stages its paths before `git commit` runs the hook, so a rejected commit leaves `.run/done/<n>` staged; detecting only `??` would leave the verified task uncommitted forever after `osq retry <id> change`.
- Pending verified commits run before the worktree clean check (both precede the spawn). The delta does not fix the order between the two, and this order is what lets a retry after `commit_failed` commit the staged task before the check rejects it as dirty.
- `commitArchive` passes the status paths under the old change folder, the archive directory, and the living specs directory rather than the three directories themselves. `git add` stages the deleted old-folder files and the added archive files, so the commit holds exactly those locations' changes and the worktree ends clean.

## Missing context

- The "Off its branch" requirement is not reachable through `runWatcherCycle` with the current `change-locations` resolver, because an off-branch worktree is not a tree at all. If the intent is that a switched branch halts the change, `changeTrees` would need to keep reporting the worktree or the loop would need to look it up by the recorded change folder; neither is in this task's scope.
