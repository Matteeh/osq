- [ ] `rejectSpec` reads markers in the located change's tree and moves the change into that tree's rejected directory, as the watcher-and-harness delta's "Lifecycle commands in a worktree" says.
- [ ] `retrySpec`'s recertification runs the task's verify and hashes its scope in the located change's tree root.
- [ ] `formatStatusOverview` prints the running-task warning as the status-inspection delta's modified "Running change in status" says.

## Details

`findChange` returns the change with its `tree`; use `tree.root` and
`tree.rejectedDir` in place of the project root. Approve into a worktree with
`approveSpec` as `tests/approve-worktree.test.ts` does, then write the dead,
done, and regressed markers the scenarios need directly in the worktree's
change folder. A running task is `.run/running/<n>.pid` holding
`process.pid`. Build status output with `getStatusOverview` and
`formatStatusOverview` from the checkout, as `tests/status-worktree.test.ts`
does.
