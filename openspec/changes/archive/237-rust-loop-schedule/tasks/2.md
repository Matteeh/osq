## Details

The step from snapshots to core's input is pure: which changes run, which
dependencies are done, and each change's files are small named functions,
and only `active_schedule` reads the disk (ADR 023).

A change's dependencies come from `read_proposal` on its `proposal.md`
only when that file exists. The storage kernel's `read_change` already
refuses a task file that does not parse, so the broken fixture gives
`LoopError::Storage`.

cargo-mutants runs on every line this task adds. The approved check, the
done and started tests for running, archived-only dependency matching by
id and by folder name, files being empty for an unapproved change, and
listing order must each change a value the fixture table checks. Before
exiting, run `cargo fmt --all`, then
`cargo mutants -p osq-kernel-loop -f <file> -o "$(mktemp -d)"` on each new
source file, then `sh scripts/verify-rust.sh` with `OSQ_CHANGE` set to
`openspec/changes/237-rust-loop-schedule`.
