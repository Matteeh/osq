## Changed

- `crates/kernel/loop/Cargo.toml` adds only `osq-kernel-storage.workspace = true`, and `Cargo.lock` records it.
- New `crates/kernel/loop/src/active.rs` holds `active_schedule`, `ActiveSchedule`, `ActiveChange`, `ActiveState` and `LoopError`. It reads the proposal's dependencies first with the specs kernel's `read_proposal`, then each active change with the storage kernel's `read_change`, computes task scope files with `scope_files`, answers running from `.run/approved` plus a done or started task, and calls core's `schedule` with `QueuedChange`, `Dependency` and `RunningChange`.
- `crates/kernel/loop/src/lib.rs` keeps its crate doc, declares `mod active;` and re-exports the five new items.
- Added the fixture archive change `001-landed` and the eight active folders `002-unapproved` through `009-nothing` under `crates/kernel/loop/tests/fixtures/repo/openspec/changes/`, plus the broken fixture `crates/kernel/loop/tests/fixtures/broken/openspec/changes/001-broken/`. The `008-started` event file copies the `started` line of the storage fixture's `010-late` event file.
- New `crates/kernel/loop/tests/active_schedule.rs` proves every row of "States of the fixture repository", its display text and `start`, "Project without changes" and "Unreadable task file".
- New `crates/kernel/loop/tests/schedule_corpus.rs` proves "Active schedule of this repository" from the repository root, with the corpus ignore.

## Deviated

The fixture table cannot show a dependency that matches an archived change by folder name only, because the specs kernel pads any leading-digit id to three digits, nor can it show an unapproved change with a done marker or a proposal that does not read. `active_schedule.rs` therefore also builds two small projects under `CARGO_TARGET_TMPDIR`: one with an archived folder `landed`, an unapproved change holding `.run/done/1` and an approved change with no proposal, and one whose proposal frontmatter does not parse. Those assertions make the folder-name match, the approved guard on running and the `LoopError::Specs` path observable to the mutation check, alongside the literal fixture table.
