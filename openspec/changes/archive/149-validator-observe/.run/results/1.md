## Changed

- Added `src/core/foundation/config-validator.ts` with the `ValidatorConfig` port,
  `DEFAULT_VALIDATOR_TIMEOUT_SECONDS` (900), `validateValidatorConfig`, and
  `validatorRunConfig`. Harness names come from `findHarness`/`HARNESS_NAMES`;
  `validatorRunConfig` sets `harness` and the catalog entry's `configKey`
  section's `model`, leaving every other field unchanged.
- Added `src/core/foundation/config-limits.ts` and moved the `OsqLimits`
  interface into it unchanged; `config.ts` imports the type for `OsqConfig`
  and re-exports it, so existing `OsqLimits` imports from `config.js` still
  work. `config.ts` is 235 lines (was 249).
- `config.ts`: `OsqConfig` gains `validator?: ValidatorConfig`; `defineConfig`
  destructures `validator` out of the user config, validates it, and spreads it
  in only when one was given.
- `config-user.ts`: `OsqUserConfig` omits `validator` and adds
  `validator?: Partial<ValidatorConfig>`.
- `src/index.ts` exports the `ValidatorConfig` type.
- Added accepted `decisions/010-validator-role.md` (ADR 010) dated 2026-10-04
  with `applies_to: [watcher-and-harness, cli-foundation]`, the required rule,
  and `checks: [tests/validator-config.test.ts]`, plus its `decisions/README.md`
  index line.
- Added `tests/validator-config.test.ts` covering every scenario of "Validator
  configuration", every error message, and a `loadConfig` of a temporary
  project whose `osq.config.ts` sets a validator.
