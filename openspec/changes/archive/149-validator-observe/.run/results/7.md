## Changed

- Added `src/core/report/report-validation.ts`: `collectValidation(folders)` reads
  each archived change's `.run/events/change.jsonl` through `readEventStream`,
  keeps the latest `validator_ran` event per change (by timestamp), and returns
  `{ changes, validated, findings, perChange }` in folder name order, or
  `undefined` when no change has one. `formatValidation(summary)` renders the
  `Validation:` section. Finding counts are zero unless the outcome is
  `validated`.
- `src/core/report/report.ts`: `MetricsReport` gained optional `validation`;
  `buildMetricsReport` collects it from the archived folders and sets it only
  when present; `formatMetricsReport` prints the section right after `Mutation:`;
  exported `buildMetricsReport` so the new test exercises it directly.
- `src/cli/report.ts`: `toStableMetrics` copies `validation` into the stable
  JSON with `changes`, `validated`, `findings`, and `perChange`
  (`{ change, outcome, findings }`).
- Added `tests/report-validation.test.ts` covering the three "Validation in
  report" scenarios plus malformed events, finding counts for non-validated
  outcomes, and the section's placement after `Mutation:`.

## Deviated

- The acceptance names `buildMetricsReport`; it was private, so I exported it
  to test through it. `getMetricsReport` behaves exactly as before.

Touched: src/core/report/report-validation.ts, src/core/report/report.ts, src/cli/report.ts, tests/report-validation.test.ts
