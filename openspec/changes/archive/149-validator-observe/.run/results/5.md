## Changed

- Added `src/watcher/validator.ts` exporting `runValidator`. It returns at once
  when the config's validator is missing or disabled; otherwise it selects the
  `Vcs`, reads the inputs from `readValidatorInputs`, records `not_run` when they
  say so, removes any old findings file, writes `diff.patch` and `scenarios.md`,
  snapshots the tree, spawns the validator's adapter once (the passed one, else
  `getHarnessAdapter`), puts the tree back, resolves the outcome
  (`timed_out`/`failed`/`unreadable`/`validated`), appends one `validator_ran`
  event to the change's `change.jsonl` via `appendHarnessEvent`, and always
  removes `.run/validator/`. Every error is caught: the logger gets
  `validator failed: <message>`, a `failed` event is appended when possible, and
  the archive goes on. The spawn uses `projectRoot`, `taskNumber` `validator`,
  tier `smart`, the validator's `timeoutSeconds`, `validatorRunConfig`, and
  `buildValidatorPrompt` as `prompt`.
- Added `src/watcher/validator-guard.ts` with `snapshotValidatorTree` and
  `restoreValidatorTree`. It records `vcs.status()` and every listed file's
  bytes before the spawn, then after the spawn restores every changed path: a
  recorded path gets its bytes back (or is removed when it was missing then),
  and any other path goes through `vcs.discard`. Paths under the change's
  `.run/validator/` and its `.run/events/validator.jsonl` are left alone. It
  returns the project-relative restored paths, sorted.
- `src/watcher/archiver.ts`: `checkAndArchiveSpec` takes an optional fourth
  argument `CheckAndArchiveOptions` (`validatorAdapter`, `logger`), calls
  `runValidator` after the change-level check passes and before
  `relocateArchivedSpec`, and archives whatever the validator does. The loop's
  call is unchanged.
- Added `tests/validator-run.test.ts` covering every scenario of "Validator run
  at archive" and "Validator tree guard" through `checkAndArchiveSpec` with a
  fake `HarnessAdapter`: findings recorded, adapter throws, times out,
  unreadable findings, tree edits put back, no base, and validator off. Each
  spawning test checks the adapter got `taskNumber` `validator`, the validator's
  `timeoutSeconds`, a config whose harness/model are the validator's, and a
  prompt naming `.run/validator/findings.json`.

## Deviated

- `runValidator` is split across small helpers (`writeInputs`, `optionsFor`,
  `resolveOutcome`, `runEvent`, `failureEvent`, `runAndRecord`) to stay inside
  the 250-line file and 80-line function budgets.
