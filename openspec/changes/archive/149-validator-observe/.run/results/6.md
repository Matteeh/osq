## Changed

- Added `src/core/status/show-model-validation.ts` exporting
  `buildValidation(timeline)`. It scans the timeline for `validator_ran`
  events whose `taskNumber` is the change stream, keeps the latest by
  timestamp, and returns its data, or `undefined`. It imports no `node:fs`.
- Added `src/core/status/show-validation-lines.ts` exporting
  `validationLines(details)`. It returns the `Validation:` block from the
  detail's `validation`, or no lines without one: the blank line and headline,
  `not_run (<reason>)` or `<outcome> by <harness>/<model> in <rounded>s` with
  `, <scenarios> scenarios judged, <n> findings` for a validated run, one
  finding line per finding with the problem words, and `Restored:` when the
  paths are non-empty. It reads no files.
- `src/core/status/show-types.ts`: `SpecDetails` gains optional `validation`.
  The module defines core-local `ValidatorProblem`, `ValidatorFinding`, and
  `ValidatorRanEventData` (see Deviated).
- `src/core/status/show-model.ts`: `withNextStep` builds the validation for an
  archived change and sets `validation` only when an event exists, keeping the
  key out otherwise; the verification block is layered on top unchanged.
- `src/core/status/show-text.ts`: `formatSpecDetails` prints
  `validationLines(details)` right after the task section and before the
  planning sessions. `show-output.ts` is unchanged, so JSON keeps `digest`
  last and `validation` before it.
- Added `tests/show-validation.test.ts`, covering every "Validation in show"
  scenario through `getSpecDetails`, `formatShowText`, and `formatShowJson` on
  temporary archived changes whose `.run/events/change.jsonl` the test writes,
  plus latest-by-timestamp, all three problem words, the `Restored:` line,
  `failed` rounding, and the two new modules reading no files.

## Deviated

- The task says `SpecDetails.validation` is "typed with `ValidatorRanEventData`
  from `src/harness/types.ts`". `src/core` may not import `src/harness`:
  `tests/import-graph.test.ts` fails with "core stays inside core", and task
  7's acceptance confirms the pattern ("without importing `src/harness/`").
  To keep every existing test passing unchanged, I defined a structurally
  identical `ValidatorRanEventData` (with `ValidatorFinding` and
  `ValidatorProblem`) in `show-types.ts` and typed `validation` with it. The
  emitted harness payload remains assignable by structural typing.
