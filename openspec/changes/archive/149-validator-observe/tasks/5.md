## Ports

```ts
export interface RunValidatorOptions {
  /** A test's adapter; otherwise `getHarnessAdapter(validator.harness)`. */
  readonly adapter?: HarnessAdapter;
  readonly logger?: Logger;
}

/** Run the configured validator once for a change about to archive. Never throws. */
export function runValidator(
  projectRoot: string,
  specFolderPath: string,
  config: OsqConfig,
  options?: RunValidatorOptions,
): Promise<void>;
```

## Details

Order inside `runValidator`: return at once when the validator is missing
or disabled. Then select the `Vcs` and read the inputs, recording `not_run`
when it returns `notRun`. Remove any old findings file and write `diff.patch` and
`scenarios.md`. Record the tree, spawn, and put the tree back. Read and
parse the findings, append the event, and remove `.run/validator/`. Wrap all
of it in one `try`. A `catch` logs `validator failed: <message>` through the
logger when there is one, tries to append a `failed` event with that
message as `output`, swallows any error from that too, and still removes
`.run/validator/`.

Paths in the guard are project-relative POSIX paths, as `vcs.status()`
reports them. The files the guard skips are those under
`<change folder>/.run/validator/` and `<change folder>/.run/events/validator.jsonl`,
taken relative to the project root. Compare a path's contents before and
after as bytes. A path missing before and after is unchanged.

In the worktree tests, the fake adapter writes the findings file from inside
`spawn`, like a real harness, at `<specFolderPath>/.run/validator/findings.json`,
and for the guard scenario also edits the three paths. A committed living
spec plus the delta the archive applies gives a dirty living spec before the
spawn.
