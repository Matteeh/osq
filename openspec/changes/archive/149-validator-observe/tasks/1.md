## Ports

```ts
export interface ValidatorConfig {
  readonly enabled: boolean;
  readonly harness: string;
  readonly model: string;
  readonly timeoutSeconds: number;
}

export function validateValidatorConfig(raw: unknown): ValidatorConfig | undefined;

export function validatorRunConfig(config: OsqConfig, validator: ValidatorConfig): OsqConfig;
```

## ADR rule

```
The validator judges a change once at archive on its own harness and model, writes only its findings file, and never stops or changes the change.
```

## Details

`validateValidatorConfig(undefined)` returns undefined. Check the keys first
(`enabled`, `harness`, `model` and `timeoutSeconds` only), then `enabled`,
then `harness`, then `model`, then `timeoutSeconds`, so the first error a
test sees is predictable. Trim `harness` and `model`, and store the
catalog's canonical name for the harness. Don't read `OSQ_MODEL` or any
harness section to fill a missing model.

The ADR is the record a later planner reads, so write the measurement
exactly as Background states it: the due point (15 validated changes or
2026-11-15, whichever comes first), how findings are labeled, and the block,
drop and in-between rules.
