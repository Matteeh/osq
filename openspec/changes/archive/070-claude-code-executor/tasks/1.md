## Acceptance

- [ ] `tests/fixtures/claude/run.jsonl` is a byte-for-byte copy of this change's `fixtures/claude-run.jsonl`.
- [ ] New `src/harness/claude/claude-stream.ts` exports `createClaudeStreamState()` and `processClaudeStdoutLine(line, ctx, state)`, with `ctx` holding `specFolderPath`, `taskNumber`, `projectRoot`, and an optional `logger`, like `processPiStdoutLine`. Blank, malformed, and unknown records are skipped without throwing; a trailing `\r` is tolerated.
- [ ] Each `tool_use` block in an `assistant` record writes a `tool` event: the summary is `input.command` for `Bash`, `input.file_path` for `Read`, `Edit`, and `Write`, `input.pattern` for `Glob` and `Grep`, and the JSON input otherwise, relativized to the project root and cut to 60 characters (in new `claude-tools.ts`). Each non-empty `text` block writes a `text` event. `thinking` blocks and per-message `usage` write nothing.
- [ ] The state remembers each `tool_use` block's `id`, `name`, and `input.file_path`. A `tool_result` block in a `user` record whose `is_error` is not `true`, for a remembered `Edit` or `Write`, writes a `file_changed` event with the project-relative path. Any other tool result writes nothing.
- [ ] The `result` record writes one `tokens` event per `modelUsage` entry: `promptTokens` is `inputTokens + cacheReadInputTokens + cacheCreationInputTokens`, `candidateTokens` is `outputTokens`, `totalTokens` is their sum, `cachedTokens` is `cacheReadInputTokens`, `reasoningTokens` is `thinkingTokens` when present, `cost` is `costUSD`, and `model` is the entry's key. The state also records the record's `subtype`, `is_error`, and `result` text, so an adapter can name a failing subtype.
- [ ] New `tests/claude/stream.test.ts` replays `tests/fixtures/claude/run.jsonl` line by line through `processClaudeStdoutLine` into a temp change folder and asserts:
  - one `tool` event per `tool_use` block, in order (`Read`, `Write`, `Edit`, `Bash`, `Bash`, `Grep`, `Glob`), with summaries such as `notes.txt` and `git status`;
  - one `text` event per non-empty `text` block;
  - `file_changed` events for `hello.txt` from the `Write` and the `Edit` only;
  - one `tokens` event whose `cost` equals the fixture's `total_cost_usd`.
- [ ] The same test covers hand-written records in `tests/claude/fixtures/stream-*.jsonl`: a `result` with two `modelUsage` entries writes two `tokens` events whose costs sum to `total_cost_usd`; a malformed line and an unknown record type are skipped; a `tool_result` with `is_error: true` after a `Write` writes no `file_changed`.

## Details

Model the module on `src/harness/pi/pi-stream.ts` and reuse `asRecord`,
`firstNonEmptyString`, `resolveEventTimestamp`, `appendHarnessEvent`, and
`relativizeToolSummary`. `assistant` and `user` records carry a `timestamp`;
other records fall back to the current time through `resolveEventTimestamp`.
Each content block arrives in its own `assistant` record repeating the whole
message's `usage`, which is why tokens come from `result` only.

The fixture is a real captured run with contents replaced by placeholders such
as `<text>` and `<content>`, and the project path replaced by `/project`. Use
`/project` as `projectRoot` when replaying it. Read the fixture and never edit
it. Task 2's adapter imports this module; this task does not wire it into any
adapter, catalog, or config.
