## Acceptance

- [ ] The README lists `claude` under the available adapters as the Claude Code harness adapter running fresh headless `claude -p` tasks.
- [ ] A new Claude Code section gives a config example with `harness: 'claude'` and a placeholder model, describes `claude.bin`, `claude.model` with the `OSQ_MODEL` fallback, and `claude.sandbox`, and states the minimum version `2.1.278`, which doctor and preflight enforce.
- [ ] The section explains authentication: the user's Claude Code login by default, and `--bare` when `ANTHROPIC_API_KEY` is set, which never reads the login. The `started` event records which one through `harnessAuth`.
- [ ] The section lists the stripping flags (`--tools Bash,Read,Edit,Write,Glob,Grep`, `--strict-mcp-config`, `--disable-slash-commands`, `--setting-sources ""`, `--no-session-persistence`, auto-memory off) and says they exist so the agent pays no tokens for MCP servers, skills, plugins, hooks, and tools a coding task never uses, measured at about 29,500 versus 13,300 input tokens per request on a one-line prompt. It says that no config key re-enables them.
- [ ] The section describes containment honestly: `dontAsk` with file tools confined to the project and `git` denied, even inside compound commands. Without `claude.sandbox`, Bash is not confined and has network. `claude.sandbox: true` sandboxes Bash with no network, fails at startup when the sandbox is unavailable, and on Linux and WSL2 needs `apt install bubblewrap socat`.
- [ ] The section says that planning with Claude Code uses the tool-native `/osq-plan` command, not this adapter, and that setup writes no Claude Code files for execution.
- [ ] New `tests/claude/readme.test.ts` reads `README.md` and asserts that the Claude Code section contains `harness: 'claude'`, `claude.sandbox`, `2.1.278`, `ANTHROPIC_API_KEY`, `--strict-mcp-config`, `dontAsk`, `Bash(git:*)`, and `bubblewrap`.
