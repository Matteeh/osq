## Acceptance

- [ ] `defineConfig` and `loadConfig` accept harness `claude` and a `claude` section with optional non-empty `bin` and `model` strings and an optional boolean `sandbox`. Any other value fails with a message naming `claude.<key>`. The binary resolves from `claude.bin`, then `claude`. The model resolves from `claude.model`, then `OSQ_MODEL` only when Claude is the executor, then `default`. Effort is null. `ClaudeConfig` is exported from `src/index.ts`.
- [ ] Through `getHarnessAdapter('claude')` and a fake `claude` under `tests/claude/`, a spawned task receives exactly `-p --output-format stream-json --verbose --no-session-persistence --permission-mode dontAsk --tools Bash,Read,Edit,Write,Glob,Grep --allowedTools Bash Read Edit(./**) Write(./**) Glob Grep --disallowedTools Bash(git:*) --strict-mcp-config --disable-slash-commands --setting-sources "" --settings <json> [--model m] [--bare] -- <prompt>`. The prompt equals `buildExecutorPrompt` for the same options. The task runs in the project root with `OSQ_TASK_NUMBER` and `OSQ_SPEC_FOLDER` set and stdin closed (the fake records reading EOF at once).
- [ ] The settings JSON is exactly `{"autoMemoryEnabled":false}` unless `claude.sandbox` is true. Then it also carries `"sandbox":{"enabled":true,"failIfUnavailable":true,"autoAllowBashIfSandboxed":true,"allowUnsandboxedCommands":false,"network":{"allowedDomains":[],"strictAllowlist":true}}`. `--bare` is passed only when `ANTHROPIC_API_KEY` is non-empty. `SpawnDetails` and `StartedEventData` gain optional `harnessAuth: 'api_key' | 'login'`, and the `started` event carries it with `harnessVersion` from `claude --version`. `tests/golden-events.test.ts` passes unchanged.
- [ ] The adapter feeds stdout through `EventStreamParser` into task 1's `processClaudeStdoutLine`. Through the watcher on a disposable fixture copy:
  - replaying `tests/fixtures/claude/run.jsonl` reaches `done` only after the watcher's own verify, with a result file synthesized from the last `text` event;
  - the fake printing `sandbox required but unavailable` to stderr and exiting 1 writes a `crashed` dead letter with that stderr;
  - a stream ending in a `result` with `is_error: true` and exit 1 names that `subtype` in the dead letter.
- [ ] The catalog registers `claude` with `configKey: 'claude'`, `envModelWhenUnselected: false`, and `planner.agent` unsupported. `HarnessCatalogEntry` gains optional `containment: (config) => string`. For `claude` it returns `file tools confined to the project; git denied; Bash unconfined with open network` by default, and `file tools confined to the project; git denied; Bash sandboxed with no network` when `claude.sandbox` is true.
- [ ] The `claude` entry's `diagnose` hook returns a `harness-version` check that fails when the probed version is below `2.1.278`, naming both, and a passing `harness-containment` check carrying the containment text. `ClaudeAdapter.preflight` probes `--version` under `timeouts.harnessPreflightSeconds` and fails on the same condition before any task spawns. New tests cover both through `runDoctorChecks` with the fake binary printing `2.1.200 (Claude Code)` and `2.1.278 (Claude Code)`.
- [ ] Every source file stays under 250 lines and every function under 80; `spawn.ts` stays under 200. `config.ts` and `harness-catalog.ts` get their room by moving code out, not by growing the allow lists. Existing tests and existing adapters' behavior do not change.

## Details

Model the adapter on `PiAdapter` and its argument builder on `buildPiArgs`:
reuse `spawnWithTimeout` (stdin `ignore`), `EventStreamParser`, and
`buildExecutorPrompt`. Put `ClaudeConfig`, its validation, binary and model
resolution, the minimum version constant, the version check, the containment
text, and the `diagnose` hook in new `src/core/foundation/config-claude.ts`, the
way `config-pi.ts` holds Pi's, so doctor never imports `src/harness`.
`applyHarnessModelEnv` already handles the `OSQ_MODEL` fallback once the entry
has `configKey: 'claude'` and `envModelWhenUnselected: false`. `doctor.ts`
already runs a catalog entry's `diagnose` hook and does not change.

Making room: a rough version of this task measured `config.ts` at 251 lines
and `harness-catalog.ts` at 258. For `config.ts`, move `OsqUserConfig` into new
`src/core/foundation/config-user.ts` and re-export it from `config.ts`. For the
catalog, move `resolvePiModel` into `config-pi.ts`, and move Codex's inline
executable and model logic into plain functions in a new module that imports
nothing from the catalog. Keep every existing export reachable from its current
module through re-exports. That measurement broke no other existing test.

The fake `claude`, `tests/claude/exec-fake-claude.mjs`, follows `tests/pi/fake-pi.mjs`: a Node script, selected
through `claude.bin`, that answers `--version` from an environment variable,
records its argv, cwd, environment, and whether stdin was at EOF, then replays a
named JSONL fixture, writes optional stderr, and exits with a chosen code. Put
hand-written fixtures in `tests/claude/exec-fixture-*.jsonl`, and read
`tests/fixtures/claude/run.jsonl` without editing it. Pass `--setting-sources`
and its empty string as two argv entries.
