## Changed
- Added `src/core/foundation/config-claude.ts`: `ClaudeConfig`, `validateClaudeConfig`, `CLAUDE_MINIMUM_VERSION` (2.1.278), `assessClaudeVersion`, `resolveClaudeBinary`, `resolveClaudeModel(config, selected)`, `claudeContainment`, and the `diagnoseClaude` hook (`harness-version` + `harness-containment`).
- Added `src/core/foundation/config-user.ts` and moved `OsqUserConfig` there, re-exported from `config.ts`, to free config-budget room. Added the `claude` section to `OsqConfig`.
- Added `src/core/foundation/config-codex-resolve.ts` holding the Codex executable/model logic as catalog-free functions; the public `resolveCodexBinary`/`resolveCodexModel`/`resolveCodexEffort` in `harness-catalog.ts` now delegate. Added `resolvePiModel` (logic) to `config-pi.ts`; the catalog keeps a thin compatibility wrapper for its entry and for `pi-args.ts`.
- Extended `harness-catalog.ts`: registered `claude` (`configKey: 'claude'`, `envModelWhenUnselected: false`, `planner.agent` unsupported), added the optional `containment` field, and used a namespace import to stay under the line cap.
- Added `src/harness/claude/claude-exec-args.ts` (`buildClaudeArgs`, `claudeSettingsJson`, `usesClaudeBare`) and `src/harness/claude/claude-exec.ts` (`ClaudeAdapter`, `preflightClaude`). Registered the adapter in `src/harness/index.ts`.
- Added `harnessAuth` to `SpawnDetails`/`StartedEventData` and wired it into the `started` event in `src/watcher/spawn.ts`. Exported the Claude config surface from `src/index.ts`.
- Added `tests/claude/exec-fake-claude.mjs`, `exec-support.ts`, the four `exec-*.test.ts` suites, and two `exec-fixture-*.jsonl` fixtures.

## Deviated
- `resolvePiModel`'s body moved to `config-pi.ts`, but the exported `resolvePiModel` name stayed in `harness-catalog.ts` as a compatibility wrapper because the out-of-scope `pi-args.ts` imports it from there.
- The public Codex resolvers stayed in `harness-catalog.ts` as delegating wrappers, since out-of-scope `codex.ts`/`codex-prompt.ts` import them via `config-codex.ts`.
- `harness-catalog.ts` imports `config-pi` as a namespace (`import * as piConfig`) to keep its file budget after moving code out without touching the line-budget allow list.
