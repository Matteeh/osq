## Acceptance
- [ ] lintChangeFolder scans all files in the change folder recursively (excluding .run/, .git/, and .DS_Store) and rejects any file containing prohibited control characters
- [ ] Prohibited control characters are ASCII control characters 0x00-0x1F and 0x7F excluding newline (\n, 0x0A) and tab (\t, 0x09)
- [ ] lintChangeFolder rejects a task file if any line contains two or more acceptance checkbox items ([-*]\s*\[[ xX]\])
- [ ] osq approve runs lint and fails with exit code 1 on mangled files, preventing approval
- [ ] PLANNER.md and MANAGED_PLANNER_BLOCK in src/core/init.ts gain the sentence: Write files with the file tool, never through a shell echo.
- [ ] tests/mangled-lint.test.ts verifies rejection of bell character (\x07), backspace (\x08), carriage return (\r), and fused acceptance lines
- [ ] tests/init-planner.test.ts passes with updated managed block content

## Details

1. In `src/core/linter.ts`:
   - Implement a recursive scan over all files in `folderPath`, ignoring directories `.run`, `.git`, and `.DS_Store`.
   - For each file, test content against prohibited control characters:
     `const PROHIBITED_CONTROL_REGEX = /[\x00-\x08\x0B-\x1F\x7F]/;`
     If detected, push an error:
     `File ${relPath} contains prohibited control character (0x${code})`.
   - In task file inspection:
     - Check each line of the task file content for fused acceptance lines:
       Split by `\n`. For each line, count occurrences of `/(?:^|\s)[-*]\s*\[[ xX]\]/g` (or match all `[-*]\s*\[[ xX]\]`).
       If count > 1, push an error:
       `Task in ${taskFile} contains fused acceptance lines on line ${lineIndex + 1}`.

2. In `src/core/init.ts` and `PLANNER.md`:
   - In `MANAGED_PLANNER_BLOCK` under `### Before you write a task`, append:
     `- Write files with the file tool, never through a shell echo.`
   - In repository root `PLANNER.md`, update the managed block identically between `<!-- OSQ:START -->` and `<!-- OSQ:END -->`.

3. In `tests/mangled-lint.test.ts`:
   - Write tests creating change folders with:
     - A bell character (`\x07`) in a task file or proposal.md -> assert lint fails and approve fails.
     - A backspace character (`\x08`) or carriage return (`\r`) -> assert lint fails.
     - Two acceptance items on a single line (`- [ ] item 1 - [ ] item 2`) -> assert lint fails.
     - Clean files with valid `\n` and `\t` -> assert lint passes.

4. In `tests/init-planner.test.ts`:
