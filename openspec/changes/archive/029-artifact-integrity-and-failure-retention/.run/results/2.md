# Task 2 — Dead marker retention and attempt renaming on re-approval

## Changed

- `src/core/approve.ts`
  - Added private `retainDeadMarkers(runDir)`: reads `.run/dead/`, and for each active `^(\d+)\.md$` marker computes `nextAttempt` (1 when no `dead/<n>.<attempt>.md` exists, else `max(existing attempts) + 1`) and renames it to `dead/<n>.<attempt>.md`.
  - `approveSpec` invokes `retainDeadMarkers(runDir)` after creating `.run`, before writing `.run/approved`. `.run/` is excluded from `hashChangeFolder`, so renaming does not perturb the approval hash.
- `src/watcher/runner.ts`
  - Deleted the `fs.unlink(path.join(runDir, 'dead', `${taskNumber}.md`))` block on the success path. The runner no longer deletes any marker under `.run/`. File now 196 lines (< 200 module budget).
- `tests/dead-marker-retention.test.ts` (new)
  - Re-approval renames `dead/1.md` → `dead/1.1.md`, then a second failure + re-approval → `dead/1.2.md` (with `1.1.md` retained).
  - `dead/1.1.md` and `done/1` coexist after a successful rerun (reproduced by first running failing verify, re-approving with passing verify, then running).
  - An active `dead/1.md` survives a successful run without re-approval, proving the runner deletion is gone.
