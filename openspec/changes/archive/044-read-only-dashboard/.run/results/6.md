# Task 6 result

## Changed

New graph view under `packages/ui/src/graph/` (all files within the 250-line
budget; largest is `GraphCanvas.tsx` at 215 lines):

- `controls.ts`: `GraphFill`, `GraphControls`, `DEFAULT_GRAPH_CONTROLS`, and the
  exported pure `graphControlsReducer` over `toggle-rejected`, `toggle-reads`,
  `toggle-depends`, `set-fill`, and `select-capability`. Rejected visibility,
  reads visibility, dependency visibility, and fill are independent fields;
  selecting the open capability closes it again.
- `types.ts`: fixed geometry plus the `GraphLane`, `GraphLaneTarget`,
  `GraphFillValue`, `GraphMark`, `GraphRelationship`, `GraphBand`, and
  `GraphLayout` contracts and a deterministic `round`.
- `fill.ts`: single `fillValue` projection. Cost is the sum of the non-null
  execution and planning observations with their summed reported/total
  denominators; both-null means `missing` with no estimate; attempts come
  straight from the node.
- `relationships.ts`: `projectRelationships` projects `depends_on` between
  present change marks and `reads` from marks to capability lane headers,
  honoring each layer's independent control.
- `layout.ts`: `orderedArchived` (valid archived dates only, sorted timestamp
  then folder key) and `graphLayout`. Capability nodes establish lane order; a
  writes edge to an absent capability is ignored. One time scale places archived
  changes left to right with stable per-location ordinal offsets for exact ties.
  Active changes get a labelled right gutter; rejected changes get a separate
  labelled band only when their toggle is on. Multi-write changes are one mark
  with lane anchors and a vertical connector. Content width has a node-count
  floor; lane-less changes fall into an unmapped row.
- `format.ts`: cost/count/coverage formatting plus `markAriaLabel`, which always
  states title, date, planner, task count, attempts, exact value and coverage,
  written capabilities, and the activation target.
- `interaction.ts`: `changeRoute`, `navigateToChange`, and `activationKey`
  (Enter/Space/Spacebar).
- `ChangeMark.tsx`, `GraphCanvas.tsx`, `GraphControlsBar.tsx`,
  `CapabilityPanel.tsx`, `GraphView.tsx`, `index.ts`: presentational SVG and
  native controls. The SVG lives in a keyboard-focusable, `overflow-x: auto`
  region labelled `Capability archive graph`; lane headers and marks are
  focusable and activate through the supplied callback; the panel exposes the
  complete capability spec text after selection. `GraphView` takes an optional
  `initialControls` so a transition can be server-rendered.

`packages/ui/src/app.tsx`: replaced only the graph placeholder with `GraphRoute`
rendering `<GraphView graph={documents.graph} onNavigate={onNavigate} />`.

`tests/ui-graph.test.tsx`: 20 tests covering every acceptance line — pure
layout/control/reducer/fill/interaction tests plus server-rendered fixture
states, with a network-spy test and a graph module line-budget test.

Verification: `pnpm verify` exits 0 — CLI typecheck, UI typecheck, production UI

## Deviated

- The SVG mark and lane-header groups are focusable and activate on
  click/Enter/Space but no longer carry `role="button"`. Biome's recommended
  `a11y/useSemanticElements` rejects that role on an SVG `<g>` and the only
  suppression form it accepts for JSX attributes cannot attach to a
  multi-line attribute; the accessible name, keyboard handler, and title remain.
- The scroll region is a `<section aria-label=…>` rather than
  `<div role="region">`, because `a11y/useSemanticElements` maps `region` to
  `<section>`. Its `tabIndex` carries one `biome-ignore` for
  `a11y/noNoninteractiveTabindex` so the region stays keyboard-scrollable.
- Archived changes without a valid landed timestamp are omitted from the
  timeline rather than placed; only active and rejected changes are placed
  without a landed date, which matches the stated active/rejected treatment.
- Lane-less changes (including a writes edge to an absent capability) are drawn
  in an unmapped row below the lanes rather than dropped or given a synthetic
  lane.

## Missing context

- The task does not specify where a change whose writes target no current
  capability lane should sit. The chosen unmapped row keeps "one mark per
  change" true without inventing a lane; if a different placement was intended,
  only `graphLayout`'s `unmappedY`/`hasUnmapped` path changes.
- The task does not define the visual scale for overlapping landed timestamps;
  the chosen per-location ordinal offset (`GRAPH_GEOMETRY.overlapOffset`) only
  prevents exact overlap and is not a duration encoding.
