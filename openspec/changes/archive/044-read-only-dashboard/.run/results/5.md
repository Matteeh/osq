# Task 5 result

## Changed

New pure projection and presentation modules under `packages/ui/src/report/`:

- `scales.ts`: finite `linearScale`/`bandScale` plus `polylinePoints`/`stepPath`
  helpers. Singleton and all-zero domains, empty counts, and non-finite values
  fall back to finite geometry rather than `NaN`, `Infinity`, or fabricated
  order.
- `format.ts`: cost/count/percent/duration/date formatting and explicit
  `unavailable` labels. `costWithCoverage` always places `n of m <unit>
  reported` beside a value; `modelLabel` renders a null model as `model
  unavailable`.
- `landed.ts`: `landedChanges` (archived + valid recorded landed time, sorted
  timestamp then folder key), `planningBoundaryIndex`, `aggregateTokens`,
  `passWindows` (`PASS_WINDOW_SIZE = 5`), `durationHistogram`, and
  `capabilityWriteSeries`.
- `Figure.tsx`: semantic `<figure>`/`<figcaption>` with a text alternative and
  a reusable accessible `DataTable`.
- `CostChart.tsx`, `TokenChart.tsx`, `PassChart.tsx`, `DurationChart.tsx`,
  `WritesChart.tsx`: the five purpose-labelled inline SVG figures.
- `RepositoryTotals.tsx`, `ScopePanel.tsx`: unchanged `MetricsReport`
  repository totals, overall coverage, separate legacy/resolver-2 scope-file
  tables with their boundary, combined acceptance-line table, and the five
  scope-regression counters.
- `ReportView.tsx`, `index.ts`: composition and public entrypoint.

`packages/ui/src/app.tsx`: replaced only the report placeholder with
`<ReportView>` behind the existing null guard; graph/change placeholders are
untouched for tasks 6 and 7.

`tests/ui-report.test.tsx`: 17 server-render and pure-projection tests covering
all seven acceptance lines, including late planning, partial coverage, a
recorded zero, both resolver generations, empty/malformed history, input
immutability, no network access, and the report module line budget.

Verification: `pnpm verify` exits 0 (CLI typecheck, UI typecheck, production UI
build, 1220 Node tests, 31 UI `.tsx` tests, Biome clean over 267 files).

## Deviated

- The five figures use landed (`archived` + valid `landed`) graph nodes for
  cost, first-attempt windows, and cumulative writes, but token provenance and
  the duration distribution aggregate across every non-rejected graph node.
  The acceptance lines and details restrict only the landed timelines; the
  task-1 fixture's landed nodes carry no token or duration evidence while its
  active change does, so an all-node projection is the only one that populates
  those two charts from the comprehensive fixture and matches "durations exposed
  by graph nodes".
- `planningBoundaryIndex` treats a change as carrying a valid planning record
  when `planningCost !== null` **or** `planningCoverage.total > 0`, so a valid
  start without a finite cost still creates the boundary.
- Scope-series evidence is rendered as labelled tables inside the report
  section rather than a sixth `<figure>`/`<svg>`, preserving acceptance line 1's
  exactly-five figures.
- `packages/ui/src/styles.css` was not touched (outside this task's scope).
  Charts use semantic classes plus inline SVG attributes (`viewBox`,
  `width="100%"`, patterns, dashes) and `currentColor` text so they remain
  legible and distinct without new CSS.

## Drift against features/

None. `MetricsReport` and `WebGraph` are consumed through erased `import type`
only; no core field was added, no core module imports the UI, and no view
constructs `fetch` or `EventSource`. Report components treat both inputs as
immutable (asserted by test).

## Missing context

- The task text says "use task 1's per-change graph observations only where the
  five historical charts require ordered change-level values", which does not
  settle whether token/duration charts are landed-only. The chosen all
  non-rejected scope is documented above; if the intended scope was
  landed-only, only `aggregateTokens`/`durationHistogram` need to switch to
  `landedChanges(graph)`.
