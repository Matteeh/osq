# Task 3 result

## Changed

- `src/core/web-events.ts` (new): the server-owned invalidation core.
  - `InvalidationHub`/`createInvalidationHub` creates exactly one watcher over
    the resolved `openspecRoot` with `ignoreInitial: true`, classifies every
    `add`/`change`/`unlink`/`addDir`/`unlinkDir` path from normalized absolute
    paths into active, archive, rejected, or `.run` children, and debounces a
    batch on the first notification. Numeric ids are deduplicated and sorted
    numerically; any unclassifiable path (capability specs, root layout,
    numericless folders) makes the whole batch carry an empty id list.
  - Injectable `WatcherFactory` and `ScheduleFn`/`TimerHandle` seams; a
    monotonically increasing token makes a cancelled or post-close timer
    callback a no-op, and a closed hub ignores later events.
  - `formatChangedEvent` emits exactly `event: changed\ndata: {"ids":[...]}\n\n`.
  - `createEventStream`/`EventStream` own the `/api/events` responses: HEAD
    writes matching headers and ends without registering a client; GET writes
    `text/event-stream; charset=utf-8` + `Cache-Control: no-store` +
    `Connection: keep-alive`, flushes headers, and tracks each response with
    idempotent `close`/`error` cleanup. `close()` unsubscribes and ends every
    open response.
- `src/core/web-server.ts`: constructs the hub and event stream once during
  `startWebServer` (never in the route handler), routes `GET`/`HEAD
  /api/events`, and extends the existing `close()` to clear the debounce timer,
  end SSE responses, close the watcher, then close the listener. Startup now
  rejects before creating a listener when the watcher factory fails, and closes
  the watcher before rethrowing a listen failure. Rewritten compactly to keep
  the file under the 250-line budget while adding `watch`/`schedule` options.
- `tests/serve-sse.test.ts` (new): focused tests with a fake chokidar-compatible
  watcher and a manual debounce clock covering one-watcher ownership, path
  classification, debounced sorted/unique batching, global empty batches,
  timer cancellation and post-close silence, exact SSE framing/headers, HEAD
  parity without a stream, fan-out to multiple clients, idempotent disconnect
  cleanup, close ordering (timer, responses, watcher, listener), watcher-init
  rollback, `EADDRINUSE` watcher rollback, and one real chokidar integration
  case that awaits `ready` and an explicit SSE connection before writing
  several files in a temporary change and then one capability spec.

## Deviations

- The hub watch root is the resolved `openspecRoot` watched recursively (one
  chokidar instance), rather than assembling separate active/archive/rejected/
  `.run` watch paths. `.run` and all three change locations live under that
  root, so this still satisfies the acceptance contract and keeps exactly one
  watcher.
- `WebServerOptions` gained optional `watch` and `schedule` seams for the
  focused tests; both are inert in production.
- To respect the 250-line source budget, `web-server.ts` was compacted
  (comments and multi-line signatures reduced); behavior and exports are
  unchanged. `serve.test.ts` and its integration fixture were not modified.
