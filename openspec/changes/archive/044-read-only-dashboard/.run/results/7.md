# Task 7 result

## Changed

New presentational and formatting modules below `packages/ui/src/change/`
(every file within the 250-line budget; largest is `TaskEvidence.tsx` at 83):

- `format.ts`: pure `UNAVAILABLE` label plus cost/count/seconds/timestamp/
  exit/timeout/planner formatting, `coverageText`, `costWithCoverage`
  (coverage always adjacent to cost), and `runningDescription` (server start and
  elapsed only). Every non-finite, negative, or missing value returns the
  explicit `unavailable` label; no value is inferred.
- `ChangeHeader.tsx`: semantic `<dl>` with folder key, location, state,
  nullable planner, derivation time, and rejection reason/time when present.
- `BriefPanel.tsx`: the brief body as escaped `<pre>` text, or a visible
  `brief absent` label with the complete proposal goal as escaped text.
- `TaskTable.tsx`: semantic `<table>`/`<th scope="col">` with task
  number/title, server state, attempts, recorded reason, observed duration (or
  the running description), and cost with exact `n of m attempts reported`
  coverage. An evidence-free change renders an explicit empty state.
- `TaskEvidence.tsx`: a nested native disclosure exposing declared scope,
  resolved scope files (path plus present/not-present, never merged with the
  declared form), acceptance lines, and the verify command as inert `<pre>`.
- `Recertifications.tsx`: typed human rows in recorded order showing actor,
  outcome, time, verify, exit, timeout, differing paths, and every attribution
  pair, or an explicit `No recertifications recorded.` state.
- `ResultDisclosure.tsx`: verbatim result in a closed native `<details>`
  (`data-result`, no `open`) as escaped `<pre>` text; absent or empty results
  render explicit unavailable text instead of an empty disclosure.
- `ChangeView.tsx`, `index.ts`: composition of the above with an optional error
  alert and retry callback.

`packages/ui/src/app.tsx`: replaced only the change placeholder with
`ChangeRoute`, which passes the current `WebChange`, the shell error, and the
refresh callback into `ChangeView`. The shell-level error alert is suppressed on
the change route so the view/route owns that state without a duplicate message;
the report and graph routes are unchanged. The now-unused local `Section`
helper was removed.

`tests/ui-change.test.tsx`: 18 server-render and pure-helper tests covering all
seven acceptance lines — formatting/labels, identity and brief (present and
absent), semantic table provenance, scope/acceptance/verify separation, typed
recertification evidence and its empty state, closed verbatim result
disclosures with escaping, rejected and running documents, malformed optional
evidence, an empty-evidence change, app-shell wiring, input immutability, no
fetch/EventSource construction, and the change route's task-4 SSE seam
(matching id, global empty id, unrelated id) rendering the freshly fetched
`WebChange` elapsed value with no client timer.

Verification: `pnpm verify` exits 0 — CLI typecheck, UI typecheck, production UI
build, 1220 Node tests, 69 UI `.tsx` tests, Biome clean over 291 files.

## Deviated

- `WebTask` is imported as an erased `import type` directly from
  `src/core/web-data-types.js` in the three task components because
  `packages/ui/src/contracts.ts` (an entry file, not in scope) re-exports only
  `WebChange`/`WebGraph`/`Inbox`/`MetricsReport`. The one-way boundary still
  holds; no runtime value is imported from `src/`.
- `app.tsx` no longer renders the shared error alert on the change route; the
  change route/view renders it (with the retry control) instead of showing the
  same error twice.
- An empty result string is treated as unavailable, per the detail that a task
  with an empty result uses explicit unavailable text.
- The "archived recertified" server-render document is constructed in the test
  because no archived fixture change carries a recertification and
  `tests/fixtures/web/**` is outside this task's scope: the real fixture is used
  for active-recertified, rejected, running, brief-absent, and malformed docs.

## Drift against features/

None. `WebChange` and `WebTask` are consumed through erased `import type` only
and never mutated (asserted by test). No `src/` module imports `packages/ui`, no
change component calls `fetch` or constructs an `EventSource` (asserted by a
source scan), and the CLI runtime dependency set is unchanged. The result,
verify, and scope text use escaped React text with no `dangerouslySetInnerHTML`
or markdown dependency.

## Missing context

- The `WebTask` contract exposes no duration coverage, so only cost coverage is
  rendered; the details made duration coverage conditional on its presence.
- The change route has no dedicated navigation control, so "navigation labels
  may show numeric ids" has no site in this view; documents remain keyed by the
  decoded folder key and the view never uses a numeric id as a client key.
