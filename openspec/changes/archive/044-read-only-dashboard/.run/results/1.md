# Task 1 result

## Changed

New core modules (all inside scope, every new file within the 250-line budget):

- `src/core/report-events.ts` — pure event observation helpers (`parseEventLines`,
  `asData`, `eventTimestampMs`, `parseTokenEvent`, `observeAttempts`,
  `observeTaskStream`).
- `src/core/web-data-types.ts` — public contracts plus `WebDataError` with typed
  `not-found`/`ambiguous` kinds.
- `src/core/web-data-folders.ts` — capability/change folder discovery, stable
  ordering, and exact-key-or-numeric selector resolution.
- `src/core/web-data-lifecycle.ts` — recorded brief/manifest/archive/rejection
  metadata readers (no mtimes).
- `src/core/web-data-tokens.ts` — token grouping keyed by harness plus nullable
  model with cached input retained.
- `src/core/web-data-observations.ts` — execution/planning summaries with
  attempt/session cost coverage, covered durations, and first-attempt counts.
- `src/core/web-data-graph.ts` — `getWebGraph` node and typed-edge projection.
- `src/core/web-data-change.ts` — `getWebChange` detail projection.
- `src/core/web-data.ts` — narrow public entrypoints and re-exports.
- `src/core/inbox-cursor.ts` — moved `resolveLastLookPath` and `readLastLook`.
- `src/core/inbox-projection.ts` — `readInbox`, the read-only inbox projection.

Refactors:

- `src/core/report.ts` now consumes `report-events.ts` for attempts, cost, token,
  duration, first-attempt, scope-regression, and verification semantics. The
  `MetricsReport` shape and values are unchanged (frozen report tests pass).
- `src/core/show.ts` extracts `getSpecDetailsFromFolder`, resolves the rejected
  location, and derives regressed task metadata.
- `src/cli/inbox.ts` keeps `writeLastLook` and the cursor-advancing decision but
  delegates reading and projection to core helpers.

Tests and fixtures:

- `tests/web-data.test.ts` covers every acceptance line for graph and change
  documents, including duplicate numeric ids and malformed optional evidence.
- `tests/fixtures/web/build.ts` builds the fixture (active, archived, rejected;
  duplicate `002`; two capability writes; partial execution/planning; malformed
  plan and event lines; result; typed recertification) and injects the live lock.
- `tests/inbox.test.ts` imports cursor reading from core and adds a read-only
  projection parity test; report/show assertions are untouched.

## Deviations

- The web fixture is a checked-in builder (`tests/fixtures/web/build.ts`) rather
  than a tree of static files. The running lock must reference a live PID and the
  fixture needs controlled timestamps, so the test builds it into a temp root.
- Graph/change observation objects expose `cost: number | null` with a
  `costCoverage { reported, total }`; execution coverage counts attempts and
  planning coverage counts valid planning starts. This is the chosen contract for
  downstream tasks 2/3.
- `WebChange` also carries `rejection` so the rejected-change scenario can return
  rejection evidence at the detail endpoint.

## Drift against features/

None. Existing report, inbox, show, parser, scope, state, and planning contracts
are preserved and remain authoritative; no module under `src/` depends on web
inspection.
