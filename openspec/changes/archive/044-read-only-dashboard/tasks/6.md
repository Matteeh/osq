## Acceptance

- [ ] The graph route renders one labeled horizontal lane per current capability with valid landed changes ordered left to right, one focusable mark per change, and a connector spanning every lane named by that change's unique `writes` edges.
- [ ] Active changes occupy a distinct labeled right-edge region, rejected changes are hidden initially and controlled by an explicit toggle, and changes without a valid landed date remain visible only in their appropriate active/rejected treatment.
- [ ] `depends_on` and `reads` relationships use different labeled styles and independent visibility controls, and toggling either layer changes only presentation state without altering the graph document.
- [ ] A fill control switches change marks between observed total cost and attempts; absent or partial cost coverage stays visibly distinct and the accessible label always states the exact value and coverage.
- [ ] Pointer title and keyboard-focus labels expose title, date, planner, task count, attempts, cost, coverage, and written capabilities, while activating a change invokes navigation to its folder-key route.
- [ ] Activating a lane header exposes that capability node's complete current spec text, and the SVG sits in a labeled horizontally scrollable region with usable minimum geometry at narrow widths.
- [ ] Pure layout/control tests cover multi-capability writes, stable date/key ordering, active/rejected placement, missing metrics, edge toggles, fill switching, navigation callbacks, and capability text without a DOM-test dependency or network access.

## Details

Add deterministic layout and control-state helpers plus presentational React
components below `packages/ui/src/graph/`, then replace only the graph
placeholder in `app.tsx`. Treat `WebGraph` as immutable. Current capability
nodes establish lane order; a writes edge to a missing capability remains in
the document but cannot create a synthetic lane.

Use one time scale for archived changes with valid landed timestamps, sorted by
timestamp then folder key. Reserve a labeled right gutter for active nodes and
a separate rejected band when its toggle is on. Stable per-location ordinal
offsets prevent exact overlaps. A multi-write change is one node with a
vertical connector and lane anchors, not duplicated nodes. The scroll region
gets a content minimum width derived from node count while the outer page may
shrink.

Project dependency relationships between present change nodes and reads
relationships from change nodes to capability lane headers. Render them in
separate SVG groups with dash/marker differences and adjacent text in the
legend. Controls are native buttons, checkboxes, or radios with visible labels
and an exported pure reducer so interaction transitions can be tested without
a browser DOM. Rejected visibility, reads visibility, dependency visibility,
and fill mode are independent fields.

Total cost is the sum of non-null execution and planning observations and its
coverage is the corresponding summed reported/total denominators; do not turn
missing planning history into zero coverage. Attempts come directly from the
node. Encode missing and partial coverage with an explicit neutral/pattern
treatment and retain numeric values in accessible labels. Each node is
keyboard focusable and responds to Enter/Space through the supplied navigation
callback.

Server-render representative graph states and unit-test pure layout/control
helpers. Assert semantic controls, focus labels, one node for a two-lane write,
separate relationship groups, hidden rejected content by default, and full
capability text after the exported selection transition. Do not snapshot
coordinate strings wholesale or read from the data module inside the view.
