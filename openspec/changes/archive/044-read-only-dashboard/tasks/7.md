## Acceptance

- [ ] The change route shows folder key, location/state, title, nullable planner, and brief body; when the brief is absent it displays the complete proposal goal under a visible `brief absent` label.
- [ ] A semantic task table shows task number/title, current state, attempts, recorded dead or regressed reason, observed duration, observed cost, and exact reported-of-total cost coverage, with unavailable evidence labeled instead of inferred.
- [ ] Each task exposes declared scope, currently resolved scope files, acceptance lines, and verify command without collapsing one scope form into the other or executing/interpreting the command in the browser.
- [ ] Typed recertifications identify `actor: human` and retain outcome, time, differing paths, attribution, verify, exit, and timeout evidence; missing recertifications have an explicit empty presentation.
- [ ] Verbatim result text is placed in a native `<details>` disclosure that is closed initially, and absent results remain visibly unavailable without markdown rendering or HTML injection.
- [ ] Running tasks display the server-derived start and elapsed seconds, and a relevant or global SSE invalidation flows through task 4's data module to replace the route with a freshly fetched `WebChange` rather than incrementing a client timer or reading markers.
- [ ] Server-render tests cover archived recertified, rejected, running, brief-absent, malformed optional, and empty-evidence documents, preserve result bytes as text, and perform no direct fetch or EventSource construction.

## Details

Add pure formatting and presentational components below
`packages/ui/src/change/`, then replace only the change placeholder in the
shared app shell. Select documents by the exact decoded folder key held in the
route; navigation labels may show numeric ids, but must not use them as a
unique client key. The app passes the current `WebChange`, retry/error state,
and refresh callback into the view.

Keep summary evidence visible and put verbose declared scope, resolved files,
acceptance, verify, recertifications, and results in accessible cells or nested
native disclosures. Use `<pre>` or equivalent escaped React text for proposal,
brief, verify, and result content. Never use `dangerouslySetInnerHTML` or a
markdown/runtime syntax dependency. A task with an empty result uses explicit
unavailable text rather than an empty disclosure.

Render finite non-negative observed values only. Cost coverage is always
adjacent to cost and uses the server's reported/total attempt counts; duration
coverage, if present in the contract, receives the same treatment. Show
nullable planner, date, reason, start, duration, and cost consistently with the
foundation's unavailable label. Do not derive status from which optional
fields happen to exist.

Recertification rows come only from task 1's typed projection and must display
the supplied human actor rather than guessing from marker text. Preserve stable
event order and every recorded attribution pair. The result disclosure omits
the `open` attribute and preserves newline content exactly as React text.

Prove refresh behavior by exercising task 4's fake EventSource/data-source
seam with an open change and then server-rendering the replacement props; the
view itself must have no event subscription. Include a global empty-id event,
a matching numeric id, and an unrelated id. Assert meaningful cell text and
disclosure attributes rather than full HTML snapshots.
