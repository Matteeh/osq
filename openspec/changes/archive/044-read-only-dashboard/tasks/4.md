## Acceptance

- [ ] A private `packages/ui` workspace uses strict TypeScript, React 19.3.0, React DOM 19.3.0, matching type declarations, and Vite 8.3.0 on Node 24, with no React plugin, router, state, chart, DOM-test, or other frontend dependency.
- [ ] UI contracts import `MetricsReport`, `Inbox`, `WebGraph`, and `WebChange` only through erased `import type`; architecture checks reject any runtime import from `src/` into UI and any import from `packages/ui` into `src/`.
- [ ] One data module owns every report, graph, inbox, change, and SSE access, prefers complete route data from typed `window.__OSQ_DATA__`, and otherwise uses only same-origin `/api/*` fetches and one `/api/events` EventSource.
- [ ] A `changed` event refetches report, graph, and inbox plus the open change when its numeric id is listed or the list is empty, while malformed events are ignored and stale requests cannot replace a newer refresh.
- [ ] Components receive documents, navigation, and refresh callbacks and contain no `fetch` or `EventSource`; inlined fixture data server-renders report, graph, and change routes without constructing either browser API.
- [ ] A small hash router recognizes report, graph, and safely encoded change keys, preserves a usable fallback, and the application shell supplies semantic navigation, loading/error/empty states, system fonts, narrow-width layout, and light/dark color variables.
- [ ] Root verification typechecks and production-builds the UI in addition to the existing CLI checks, while React/Vite remain confined to the private workspace and the CLI runtime dependency list is unchanged.

## Details

Add `packages/ui` to `pnpm-workspace.yaml` and keep every frontend package in
that workspace's `devDependencies`; it is a private application whose output is
bundled, not an install-time library. Use the verified planning-time releases
React/React DOM 19.3.0, `@types/react`/`@types/react-dom` 19.3.0, and Vite 8.3.0.
Configure `jsx: react-jsx`, strict unused/indexed-access checks, DOM libraries,
and an explicit Node `>=24` engine. Vite builds to `packages/ui/dist` for now;
task 8 owns deterministic staging to package-root `ui/dist`. Ignore both build
directories without ignoring authored UI source.

Keep direct `packages/ui/src/*` files for `contracts.ts`, `data.ts`,
`router.ts`, `app.tsx`, `main.tsx`, and shared CSS. The intentionally shared
`app.tsx` starts with honest route placeholders and will be extended in order
by tasks 5, 6, and 7. View-specific source belongs in nested directories so it
does not fall within this task's broad foundation scope.

Define `OsqInlineData` with optional report, graph, inbox, and a folder-keyed
change map, plus a safe global Window declaration. Give the data source
injectable fetch/EventSource constructors for Node tests. Inlined data is
authoritative only for documents present in the object; a fully supplied route
must not touch the network or open SSE. Live mode validates HTTP success and
parsed object shapes at the boundary, owns the one EventSource, coalesces
invalidations through a monotonic refresh generation, and exposes a close
method. It never interprets filesystem paths or markers.

Use native `hashchange` and history updates rather than a routing package.
Canonical routes are `#/report`, `#/graph`, and
`#/changes/<encodeURIComponent(folderKey)>`; `/` redirects in memory to report.
Reject decoded separators and dot traversal in the route parser. Keep view
components pure: task tests and later server-render tests must pass documents
directly without a DOM emulator.

Extend root scripts so the existing `pnpm verify` performs CLI typechecking,
UI typechecking, the production UI build, all Node tests, and Biome checks for
authored CLI/UI/test source. Do not stage or pack assets yet. Extend the import
graph test to scan `.ts` and `.tsx` under both trees and distinguish type-only
imports. `tests/ui-data.test.tsx` should use React DOM's server renderer and
injected throwing network constructors to prove the inlined path, plus fake
fetch/EventSource objects to prove URL ownership, invalidation, race ordering,
route parsing, and cleanup.
