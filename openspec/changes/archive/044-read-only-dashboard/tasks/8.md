## Acceptance

- [ ] Root build production-builds the strict UI, replaces package-root `ui/dist` with exactly that output, then builds the CLI; `prepublishOnly` uses this path and `files` includes staged UI while excluding workspace source and build dependencies.
- [ ] Package metadata, maintained CI and release jobs, TypeScript Node declarations, UI engine, and README agree on a Node 24 LTS minimum, with CI selecting the maintained `24` line and no Node 22-only baseline left in those surfaces.
- [ ] The root CLI retains exactly its permitted runtime dependency categories and React, React DOM, their declarations, and Vite remain private-workspace build dependencies absent from installed runtime dependencies.
- [ ] `pnpm verify` typechecks, production-builds, tests, and lints both packages, then fails with a measured total when regular staged `ui/dist` files exceed 1,000,000 bytes or when a non-grandfathered UI source file exceeds 250 lines.
- [ ] `npm pack --dry-run` contains `ui/dist/index.html` and fingerprinted production assets, permits no UI source/workspace manifest leak, and keeps every established CLI/template/legal package-hygiene assertion.
- [ ] The isolated tarball smoke install proves the compiled executable can start `osq serve --port 0`, report its loopback URL, return the packaged index and one asset, and shut down cleanly without React or Vite installed as runtime dependencies.
- [ ] The complete change passes `pnpm verify` from a clean staged-output state, with no committed generated bundle required and no production source change in this final reconciliation task.

## Details

This is the final-tree distribution owner. Earlier tasks intentionally share
`package.json`, `pnpm-lock.yaml`, and `pnpm-workspace.yaml`; preserve their UI
workspace and test scripts while making build/stage/package ordering final.
Do not change server or UI production source. Add one small
`scripts/stage-ui.mjs` using Node filesystem APIs to remove only the explicit
package-root `ui/dist` directory, recreate it, and copy regular output from
`packages/ui/dist` without following an output path outside either root.

Use clear root scripts such as separate CLI build, UI build, staging, and
verification phases, but keep `build` and `prepublishOnly` as the authoritative
production route. Verification must build before asset inspection so stale or
missing output cannot pass. Do not make `npm pack` recursively invoke an
unbounded verify loop. Preserve pnpm's pinned package-manager field and update
the lockfile only through the chosen React/Vite workspace graph.

Raise root `engines.node` to `>=24.0.0`, use compatible maintained 24.x Node
types, and set both GitHub workflows to `node-version: 24`. README should name
the Node 24 LTS prerequisite and document the local-only `osq serve` command,
default URL, port/open options, read-only nature, and hash routes without
promising remote hosting. Do not pin CI to a short-lived Current line.

Add the staged-byte assertion in `tests/package-ui-budget.test.ts`, matched by
this task's package-test scope. Recursively sum only regular files, report the
measured byte count and limit on failure, and fail clearly when the staged
index is missing. Extend `tests/line-budget.test.ts` to scan authored `.ts`,
`.tsx`, and CSS-supporting source below `packages/ui/src` with the same
250-line ceiling and no new allow-list entry.

Update package hygiene to allow only `ui/dist/**` in addition to established
assets, require the index and at least one generated asset, reject
`packages/ui/**`, and inspect root dependencies separately from workspace
devDependencies. Extend the existing sequential install smoke test: spawn the
installed executable with literal `serve --port 0`, parse its one printed URL
under a timeout, request index and an asset with Node fetch, assert loopback and
content headers, send SIGTERM, and require prompt clean exit. Ensure failure
cleanup always terminates the child and removes the temporary project.

Run `pnpm verify` after deleting only generated UI outputs through the staging
script's supported clean path, then inspect `npm pack --dry-run --json`. The
ordinary verify remains offline apart from the already-established isolated
package install behavior and needs no browser, TTY, model, or external web
service.
