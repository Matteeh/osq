## Acceptance

- [ ] The report route renders exactly five purpose-labeled inline SVG figures for landed cost, token provenance, first-attempt pass windows, covered task durations, and cumulative capability writes, each with deterministic marks and an accessible text alternative.
- [ ] Landed cost is ordered by recorded landed time and visually distinguishes execution from planning; every shown cost is adjacent to its exact reported-of-total coverage and partial or unavailable values are labeled without estimation.
- [ ] Planning cost has no zero-valued marks before the first change carrying a valid planning record, and that first observed change is identified by a visible and text-readable boundary annotation.
- [ ] Token totals group by the recorded harness and model, retain cached-input values and cache share, and never merge unlike or unavailable provenance into a guessed bucket.
- [ ] First-attempt pass rate is computed in consecutive landed windows containing at most five changes, task-duration distribution includes only covered values, and cumulative writes counts deterministic `writes` edges over landed time.
- [ ] Legacy and resolver-2 scope-file series are rendered separately with their recorded boundary while acceptance-line evidence remains combined; all five scope-regression counters appear in a compact labeled table.
- [ ] Empty, malformed optional, and partially covered fixtures server-render without throwing, without network access, and with explicit unavailable text; report components never mutate their `MetricsReport` or `WebGraph` inputs.

## Details

Add pure projection helpers and presentational React components below
`packages/ui/src/report/`, then replace only the report placeholder in the
shared app shell. Use the unchanged `MetricsReport` for repository totals,
scope series, regressions, and overall coverage, and use task 1's per-change
graph observations only where the five historical charts require ordered
change-level values. Do not add a web-only field to `MetricsReport`.

Render each question as a semantic `<figure>` with a heading/figcaption, an
application-owned `<svg>`, and a concise textual summary or table that carries
the same values. Put reusable linear/band scale and path helpers in small local
modules; handle a singleton domain, all-zero observed values, and missing dates
without `NaN`, infinity, or fabricated order. Colors supplement rather than
replace labels, patterns, or shape differences.

For cost, use each node's separate execution/planning observed totals and
coverage denominator. A null planning cost means no valid planning record and
is absent; a recorded zero with coverage is a real mark. Identify the earliest
landed node with planning coverage and render one boundary rule/label there.
Token grouping keys are the explicit harness/model pair; display nullable model
as unavailable rather than attributing it to another model. Cache share uses
reported cached input divided by the recorded input basis and remains
unavailable when that basis is absent.

Sort valid landed changes by timestamp then folder key. Chunk them into
consecutive slices of five for first-attempt numerator/denominator sums.
Duration bins are derived deterministically from only finite non-negative task
durations exposed by graph nodes. Cumulative capability writes increments once
per unique writes edge per landed change and keeps a stable capability order.
Do not include active or rejected nodes in landed timelines.

Use React DOM `renderToStaticMarkup` in the focused test with the comprehensive
task-1 fixture documents. Assert five figures, labels and values rather than
pixel snapshots; cover late planning, partial coverage, recorded zero, both
scope resolver generations, empty history, and input immutability. The test
must render through passed props, not construct the data source.
