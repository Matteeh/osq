## Acceptance

- [ ] One server owns exactly one chokidar watcher for the configured OpenSpec root and its active, archive, rejected, and discovered `.run` content; connecting or disconnecting SSE clients never creates a second watcher.
- [ ] File notifications accumulated for the configured debounce interval produce one `changed` SSE frame per client with JSON `{ "ids": [...] }`, sorted unique numeric change ids, and no document, file content, path, marker, or other project state.
- [ ] Notifications within one recognized change map to its leading numeric id, while a capability or other root-level notification makes the batch carry an empty id list so clients conservatively refresh shared documents.
- [ ] `GET /api/events` returns a correctly framed keep-open event stream with no-store headers, multiple clients receive the same batch, disconnect cleanup is idempotent, and HEAD returns the matching status and headers without opening a stream.
- [ ] Server close clears a pending debounce timer, ends all connected responses, closes the filesystem watcher, then closes the HTTP listener; no delayed event is written after shutdown.
- [ ] Watcher initialization or HTTP startup failure closes every resource already created and rejects the start operation once, so `osq serve` retains task 2's single actionable failure path.
- [ ] Focused tests use an injectable watcher seam for exact ownership/cleanup assertions and one real chokidar integration case for debounced change and capability invalidations without timing races or writes outside temporary fixtures.

## Details

Implement the subscription and batching logic in `web-events.ts` behind a
small `InvalidationHub`-style interface. Construct it once during server
startup, not in the route handler. Watch the canonical configured OpenSpec root
recursively; path classification must recognize active, archive, and rejected
folder layouts and `.run` children from normalized absolute paths. Chokidar is
already a permitted runtime dependency. Do not add polling state or persist an
event cursor.

Treat a batch as global when any path cannot be attributed to exactly one
change folder, including current capability specs and changes to the root
layout. Otherwise collect leading numeric ids in a set and sort numerically
with a stable string tie-break. Emit exactly:
`event: changed\ndata: {"ids":[...]}\n\n`. Do not send an initial snapshot; the UI
loads through ordinary documents and uses SSE only for subsequent invalidation.
Ignore callbacks after closing.

Extend task 2's `WebServerHandle.close()` rather than adding a second shutdown
API. Track response close/error events, remove clients without closing the
shared watcher, and tolerate repeated close calls. Order startup so a watcher
failure cannot leave a listener and a listen failure cannot leave the watcher;
the integration may create either first as long as rollback is complete.

The focused test may inject a fake chokidar-compatible watcher and manual
clock/timer hooks to prove one instance, one debounce, fan-out, and close
ordering deterministically. The real watcher case should await an explicit SSE
connection, perform several writes in a temporary change, then one capability
write, and bound every wait with a short test timeout. Do not modify task 2's
transport test; it is a frozen shared-composition check.
