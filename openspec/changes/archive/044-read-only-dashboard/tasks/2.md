## Acceptance

- [ ] Public configuration adds validated `serve.port` and `serve.eventDebounceMs` values defaulting to 4173 and 100; `--port` overrides configuration and accepts only integer values from 0 through 65535, including ephemeral port zero.
- [ ] `startWebServer` binds only `127.0.0.1`, returns an idempotently closable handle with the actual URL, and recomputes report, graph, inbox, and selected-change documents from current files for each ordinary request without starting the execution watcher or writing project/cursor state.
- [ ] API JSON is deterministically serialized with UTF-8 and `Cache-Control: no-store`; report deeply equals `getMetricsReport`, inbox deeply equals the read-only core projection, typed change failures map to 404 or 409, and request failures return JSON without terminating the listener.
- [ ] GET and HEAD have matching status and headers with no HEAD body, every other method is rejected before route lookup with 405 and `Allow: GET, HEAD`, unknown API GET is 404, unsafe or malformed change selectors are 400, and no response emits a permissive CORS header.
- [ ] Static delivery resolves only regular files inside `resolveUiDir()`, serves `/` and `/index.html` plus correct asset content types, rejects traversal and directory listing, gives the HTML a self-only CSP and revalidation, and permits immutable caching only for fingerprinted assets.
- [ ] `osq serve` prints the actual loopback URL after listening, opens it once only after successful startup when requested, waits for SIGINT or SIGTERM, and closes its server resources; browser launch uses platform commands without a dependency.
- [ ] Invalid configuration, `EADDRINUSE`, static/API errors, and browser-launch failure produce one actionable CLI error and nonzero status without opening early, calling `process.exit` in core code, or leaking a listener.

## Details

Add a `ServeConfig` validator in `config*.ts` so `defineConfig` owns defaults
and rejects non-finite, fractional, negative, or out-of-range ports and
non-finite or negative debounce values. Export the public config types through
`src/index.ts`. Parse the CLI port with Commander's argument validation; do not
silently coerce decimals, whitespace-only strings, overflow, or trailing text.

Keep `web-server.ts` as the dependency-injected composition root. Its options
should accept project root, resolved config, UI directory, request clock/home
for inbox tests, and document functions where useful. Use `node:http`; route on
the parsed URL pathname, decode a change selector exactly once, and reject `/`,
`\\`, encoded separators, dot segments, and malformed escapes before calling
task 1. Stable JSON serialization belongs in core code rather than importing
the CLI report serializer. HEAD may run the corresponding read-only derivation
to determine its response but must never write bytes.

Keep static containment in `web-static.ts`. `resolveUiDir()` must resolve the
same package-root `ui/dist` from both `src/core` under tsx and `dist/core` in an
installed package. Normalize and segment-check the decoded path, use `lstat`
or `stat` to require a regular file, and never provide an SPA fallback for an
unknown path: hash routing needs only the index request. Cover HTML, JS, CSS,
JSON, SVG, and common image MIME types. Use a CSP whose allowed sources are
only `'self'` as needed by the generated application and same-origin SSE.

Expose a programmatic start function for tests and a CLI orchestration function
that stays alive until a signal. Inject browser launching and signal wiring in
tests. Use `open` on macOS, `cmd /c start` on Windows, and `xdg-open` on Linux
through literal child-process arguments; startup success must not depend on
the child remaining attached. If opening fails, close the server before
surfacing the error. Task 3 will extend the explicitly shared
`src/core/web-server.ts` handle with the one SSE watcher.

Build `tests/serve.test.ts` around a temporary repository and temporary UI
directory. Start the real server on port zero and exercise it with Node's
`fetch`; snapshot the relevant project and cursor trees before unsupported
methods and inbox reads. Include CLI registration/precedence, occupied-port,
HEAD, deterministic JSON, traversal, CSP/cache, error mapping, and close
idempotence cases. Extend `tests/config.test.ts` only for the public serve
merge and validation contract; existing CLI tests remain frozen.
