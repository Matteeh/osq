## Acceptance

- [ ] `getWebGraph` reads current capability specs plus active, archived, and rejected change folders on every call and returns stable capability/change node and edge arrays ordered independently of directory enumeration.
- [ ] Change nodes carry folder key, numeric id, slug, title, location state, recorded created/approved/landed/rejection/planner metadata, task and attempt counts, and separate execution and planning observations without using file mtimes or estimates as missing evidence.
- [ ] Per-change observations report cost coverage, tokens grouped by the recorded harness and model with cached input retained, covered task durations, and first-attempt pass counts; no valid planning start yields `planningCost: null`, not zero.
- [ ] Graph edges contain one stable key for every present `depends_on`, declared `features.reads`, and delta-folder `writes` relationship, with duplicate declarations collapsed and references ordered deterministically.
- [ ] `getWebChange` resolves an exact folder key or an unambiguous numeric id across all three locations and returns proposal/brief/planner metadata plus tasks with declared and resolved scope, acceptance, verify, marker state, attempts, reasons, running timing, observed duration/cost coverage, human recertifications, and verbatim result text.
- [ ] Missing or malformed optional manifests, planning records, events, markers, briefs, and results become null or empty fields without dropping valid sibling evidence; ambiguous and absent selectors remain distinguishable errors for the HTTP layer.
- [ ] Inbox cursor location and reading move behind a core helper used by both CLI and web callers; the read-only projection exactly matches the first contemporaneous JSON CLI projection, while only `inboxCommand` advances the cursor.

## Details

Create small `web-data*.ts` modules for public contracts, folder discovery,
event observations, graph projection, and change projection; keep every new
source module within the repository's 250-line budget. Export one narrow
`getWebGraph(projectRoot, config)` entrypoint and one
`getWebChange(projectRoot, selector, config, now)` entrypoint from
`web-data.ts`. Give selector failures a typed not-found or ambiguous kind so
the server does not parse error strings. Do not store an index or cache a
document between calls.

Discover locations only through the canonical layout helpers. A folder key is
its preserved directory basename and a numeric id is its leading digit run.
An exact folder key wins only when unique; numeric lookup must collect every
matching folder before deciding. Ignore `_` and dot entries and require a real
directory with a resolvable change document. Capability nodes come only from
`<specs>/<id>/spec.md` and include its complete UTF-8 text. Derive writes from
actual delta directories, never the removed frontmatter form.

Use recorded lifecycle evidence for dates: brief/manifest creation fields,
manifest approval, typed `archived` and `rejected` events, and their preserved
rejection marker fallback. Planner attribution follows the established
planning/manifest rules and stays null when unreported. Extract the minimum
pure event-observation helpers from `report.ts` into a `report*.ts` module and
make the terminal report consume them too, so attempt, cost, token, duration,
and first-attempt semantics have one implementation. Preserve the exact
`MetricsReport` shape and values; existing report tests are frozen checks.

Compose `getSpecDetails`, `deriveSpecState`, `resolveScope`, task parsing, and
`readPlanningSessions` rather than interpreting their files incompatibly.
Extend the composition only where `show` lacks rejected-location or regressed
task metadata. A running start comes from the parsed lock and elapsed seconds
use the injected `now`; do not test host PIDs for archived/rejected evidence.
Cost coverage denominators are recorded attempts or planning starts, not task
count, and a token group key contains both harness and nullable model so unlike
provenance is never merged.

Move `resolveLastLookPath` and `readLastLook` into `inbox*.ts` core code and add
a read-only inbox projection helper around `getStatusOverview`,
`collectLandedItems`, and `projectInbox`. Keep `writeLastLook` and the decision
to call it in the CLI path. Extend `tests/inbox.test.ts` only for this extraction;
keep report/show compatibility assertions unchanged. The web fixture must
cover all three change locations, duplicate numeric ids, partial execution and
planning evidence, malformed optional lines, two capability writes, a running
task, a result, and a typed human recertification.
