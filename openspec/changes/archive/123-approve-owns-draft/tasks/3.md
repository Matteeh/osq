## Details

For a stacked change, `approveSpec` must set `folderPath` and `specsDir` to
the checkout's changes directory before lint runs, as it does today, so
`claimBranch`, `refuseDirtyScope`, and the relative paths in
`approveIntoNewWorktree` and `recordStackedApproval` all see a checkout
folder. `recordStackedApproval` already deletes the old stacked approval
before copying, and that copy now comes from the restored draft.

The fixtures in these tests create their drafts after the seed commit, so
the drafts are untracked and approval removes them. To test a committed
draft, commit the folder before approving.
