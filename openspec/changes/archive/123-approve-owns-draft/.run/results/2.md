## Changed

- `src/core/status/leftover-drafts.ts`: reduced to an inert module. It now
  carries a comment and `export {}`; nothing imports it.
- `src/core/status/status.ts`: dropped the `leftovers` field from
  `StatusOverview`, the `checkoutChanged` field from `ChangeWorktree`, the
  `checkoutCopyChanged` helper, the leftover listing and filtering in
  `getStatusOverview`, and both the `Leftover drafts:` section and the
  checkout-copy warning from `formatStatusOverview`. Removed the now-unused
  `path` and `hashChangeFolder` imports.
- `src/core/vcs/land.ts`: `cleanupChange` now removes only the worktree; no
  `Removed leftover draft` line, and no `fs`/`findLeftoverDrafts` imports.
- `tests/status-leftover.test.ts`: reduced to an inert module, same constraint
  as below.
- `tests/status-worktree.test.ts`: dropped the `checkoutChanged` assertions and
  the warning assertion; the edited-checkout test writes its own folder with
  `fs.mkdir`/`fs.writeFile` and asserts no warning prints.
- `tests/status-sync.test.ts`: the sync-order test writes its own folder and
  now only asserts the sync line follows the worktree line.
- `tests/vcs-land.test.ts`: dropped the `Removed leftover draft` and
  checkout-copy-exists assertions; the keeps-a-leftover test writes its own
  `proposal.md` and task file.
- `tests/vcs-land-commit.test.ts`: "Progress on stderr" expects three stdout
  lines instead of four.
- Added `tests/checkout-copy-ignored.test.ts`, building its repositories like
  `tests/vcs-land.test.ts` and covering status-inspection's "Edited checkout
  copy" and "Untouched checkout copy" and version-control's "Edited leftover
  copy is kept", "Landed by hand, worktree kept", and "Land after archive". For
  each checkout folder it needs, it removes whatever approval left and writes
  the folder itself.

## Deviated

- Acceptance 1 and 3 ask me to delete `src/core/status/leftover-drafts.ts` and
  `tests/status-leftover.test.ts`. I could not delete them. The watcher's git
  guard (`src/watcher/git-guard.ts` `scopeViolations`) resolves the task
  `scope` with `resolveScope`, which returns a null `absolutePath` for an
  exact-declared path that no longer exists, so it reports every deleted
  scoped file as a `scope_violation`. Attempt 1 was killed exactly this way.
  Both paths now stay as 0-behavior inert modules (`export {}`) so the guard
  can still resolve them and nothing imports them; the code and test behavior
  is the deletion the task describes.
- `tests/vcs-land.test.ts`: the two `exists(checkoutFolder(...)) === false`
  assertions also had to go; their outcome flips between task 2 (approval
  leaves the copy) and task 3 (approval removes it). The new "Land after
  archive" test covers the archive-only checkout instead.
- `tests/status-worktree.test.ts` keeps its "checkout copy is missing" case,
  which removes approval's copy; that is the only way to present an absent
  checkout folder while approval still leaves one.

## Missing context

- Task 2 must keep every listed test green while approval still leaves the
  checkout copy and task 3 removes it. Assertions about whether the checkout
  folder survives a land cannot hold in both states, so I removed them rather
  than assert a state that flips between tasks.
