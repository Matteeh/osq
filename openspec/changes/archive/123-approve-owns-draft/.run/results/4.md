## Deviated

- Acceptance 1 and 3 ask me to delete `src/cli/done.ts`,
  `src/core/lifecycle/done.ts`, and `tests/done-manual.test.ts`. I could not
  delete them. The watcher's git guard (`src/watcher/git-guard.ts`,
  `scopeViolations`) resolves the task `scope` with `resolveScope`, which
  returns a null `absolutePath` for an exact-declared path that no longer
  exists, so it reports every deleted scoped file as a `scope_violation`.
  Attempt 2 was killed exactly this way. Task 2 hit the same block and resolved
  it the same way: both source files and the test file now stay as 0-behavior
  inert modules (`export {}`), and nothing imports them.
- Because the source modules stay on disk, acceptance 4's "do not exist" check
  is impossible under the guard. `tests/done-removed.test.ts` instead asserts
  the observable behaviour the removal is about: no `done` command is
  registered, an unknown `done` invocation fails non-zero and writes no marker,
  and the two command modules export no done entry points. The task's
  `tests/command-error-changes.test.ts` and `tests/worktree-lifecycle.test.ts`
  changes are exactly the two removals acceptance 3 names.

## Missing context

- The planner's acceptance assumes a task can delete a file that its own
  `scope` names, but the watcher's scope guard cannot resolve a deleted exact
  path. Task 2's delta already recorded this same limitation; task 4 did not
  carry it forward, so the task as written cannot be met literally.

## Outside scope

- `src/watcher/git-guard.ts` `scopeViolations` treats every deleted scoped
  path as out of scope because `resolveScope` returns a null `absolutePath`
  for a missing exact declaration and the guard drops null entries. This kills
  any task that removes a file its scope authorizes. I left it alone; fixing it
  would change watcher-and-harness behavior outside this task's scope and is
  the reason this task keeps inert stubs instead of deleting them.
