## Changed

- Added `src/core/spec/checkout-draft.ts` with `removeCheckoutDraft(vcs,
  projectRoot, folderPath)` and `restoreStackedDraft(projectRoot, config,
  change)`. Removal is skipped when `vcs.pathExists('HEAD', <repo-relative
  path>)` is true; restore copies the stacked folder to the checkout's changes
  directory, replacing what is there, then keeps only `.run/manifest.json` and
  `.run/plan.jsonl` and returns the copy's absolute path.
- `src/core/spec/approve-worktree.ts`: `approveIntoNewWorktree` calls
  `removeCheckoutDraft` after its approval commit, and the stacked branch of
  `approveIntoWorktree` calls it after `recordStackedApproval` returns. No
  other change; the file is 247 lines.
- `src/core/spec/approve.ts`: a change found in a stacked tree is restored with
  `restoreStackedDraft` and approved as a checkout draft; the old
  `not found in <changesDir>` refusal is gone. The whole approval runs in a
  try/catch that removes the restored draft with `fs.rm` and rethrows on any
  failure, declined confirmation included. The doc comment now says the draft
  is removed. `approveInPlace` is unchanged.
- `src/core/lifecycle/reject.ts`: a stacked change is restored to the checkout
  before its stacked directory is deleted; `RejectResult` gains `restoredPath`
  relative to the project root with `/` separators.
- `src/cli/reject.ts`: prints `  Restored draft: <restoredPath>` after the
  `Withdrew stacked approval:` line.
- `tests/approve-worktree.test.ts`: the approval test reads and hashes the
  worktree's copy, expects the checkout's untracked entry gone, and its title
  now says the draft is removed.
- `tests/approve-stacked.test.ts`: the dependency-worktree and stacked-on hashes
  read the worktree copy; the stacked test compares `git status` with
  `--untracked-files=all` and expects only the approved folder's entries gone;
  "replaces the stacked copy when approved again" edits the task file in the
  stacked copy.
- `tests/reject-worktree.test.ts`: the stacked reject test expects the restored
  draft (authored files preserved, approval markers pruned) and the output test
  expects the `Restored draft:` line.
- Added `tests/approve-owns-draft.test.ts`, built like `tests/approve-stacked.
  test.ts`, covering "Uncommitted draft removed", "Committed draft stays",
  "Failed approval keeps the draft", "Version control off", "Restore a halted
  stacked change", and a lint-failing re-approval of a stacked change that
  leaves no checkout folder and an unchanged stacked directory.

## Deviated

- `approve-worktree.ts`'s doc comment still says the worktree path writes
  nothing to the checkout. Acceptance item 2 said nothing else in that file
  changes, so I left the comment rather than the behavior. The comment is now
  stale; `approve.ts`'s comment was updated.
