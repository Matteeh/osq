## Changed

- Added `src/core/foundation/change-number.ts`: moved `getNextSpecNumber` there
  unchanged, and added `knownChangeFolders(projectRoot, config)` (folders from
  `listChanges`, plus, with `vcs.enabled` and `GitVcs`, every `osq/` branch
  without its prefix and trailing `-rejected-<n>`) and a private
  `nextChangeNumber` used by `createNewSpec`.
- `src/core/foundation/new.ts` re-exports `getNextSpecNumber`, takes an
  optional `config`, and numbers a new change one above the highest prefix
  across the scanned folders and `knownChangeFolders`.
- `src/core/spec/linter.ts`: `checkDependencyExists` now answers from
  `knownChangeFolders`, so `depends_on` and `fixes` find worktree, stacked, and
  `osq/`-branch changes. Removed the now-unused layout imports.
- `src/cli/new.ts` loads the project config with `loadConfig(cwd)` and passes
  it to `createNewSpec`.
- `src/cli/plan-queue.ts`: `createChange` takes `config?: OsqConfig` and
  forwards it; `createQueueChange` passes its config.
- `src/cli/plan.ts` passes `{ config }` for a named change.
- Added `tests/change-number.test.ts` covering "Running change keeps its
  number", "Stacked change keeps its number", "Rejected branch keeps its
  number", "Version control off", "Depends on a running change", "Fixes a
  change rejected on its branch", and "Still missing".

## Deviated

- `knownChangeFolders` collapses duplicate folder names to one entry (a kept
  `osq/006-f` branch and its `osq/006-f-rejected-1` both add `006-f` once). The
  delta says "the name of every branch"; the folder set is the same.
