## Acceptance

- [ ] `Seal`, `Seal::parse` and `SealError` behave as rust-core "Approval seal" says.
- [ ] `Change<S>` with the state types `Draft`, `Approved` and `Archived`, `Change::draft`, `approve`, `next_task`, `archive`, `ApproveError` and `ArchiveError` behave as "Change typestate" says. `next_task` and `archive` read `change_status` from task 2's `fold` module instead of repeating its order.
- [ ] `Change`'s fields are private and the state types cannot be built outside the crate, so no public path other than `approve` and `archive` reaches `Change<Approved>` or `Change<Archived>`.
- [ ] `crates/core/tests/gates.rs` proves "Seal texts", "Approve checks the seal", "Next task of an approved change" and "Archive needs a done change", one case per table row.
- [ ] `compile_fail` doctests on `Change` prove "Gates cannot be skipped": one builds a `Change<Approved>` by hand, one builds a `Change<Archived>` by hand, one calls `next_task` on a `Change<Draft>`, and one calls `archive` on a `Change<Draft>`. `cargo test --workspace` in the verify script runs them.
- [ ] Every public function's doc ends with `Implements: rust-core/<requirement>` and each test function's doc names `Covers: rust-core/<scenario>`, both in kebab-case; each doctest names its scenario in the text above it.
- [ ] `sh scripts/verify-rust.sh` passes.

## Details

Reuse `ChangeState`, `TaskId`, `TaskStatus` and `change_status` from the
`fold` module; do not change them. In `lib.rs`, only add the `seal` and
`change` modules and their re-exports.

A sealed marker trait or a private field in each state type keeps the states
closed. Each `compile_fail` doctest must fail for the reason it names, so
write each one so it would compile if that one gate were missing.

Keep tests in `crates/core/tests/` and doctests, never a `#[cfg(test)]`
module. Pedantic clippy lints are denied through `-D warnings`. Run
`cargo fmt --all` before exiting.

- rust-core: Approve checks the seal
