## Acceptance

- [ ] New `src/core/run/verify-diff.ts` exports one function that, given the project root, the change folder (or null) and the config, returns the path of a diff file and a cleanup, or null. It reads `<change folder>/.run/base` trimmed, gets the `Vcs` with `selectVcs(projectRoot, config)`, and, when the kind is `git` and the base is not empty, writes `vcs.patch(base)` to a file in a folder made with `fs.mkdtemp` under `os.tmpdir()`. A missing marker, an empty base, a `NoVcs`, or a `patch` that throws gives null, never an error.
- [ ] `runVerificationCommand` calls it with `options.config`, falling back to `DEFAULT_CONFIG`, sets `OSQ_DIFF` to the file's absolute path when it gets one, and otherwise removes `OSQ_DIFF` from the child's environment, as it does for `OSQ_CHANGE` with null. `extraEnv` is still set last. The cleanup runs after the command ends, whether it passed, failed, timed out or could not start.
- [ ] `runVerificationCommand` stays within the 80-line function budget and `verification.ts` within 250 lines; move the environment assembly into `verify-diff.ts` if it is needed for room. Its signature and every caller stay as they are.

## Details

`vcs.patch(base)` already builds the diff osq needs: it copies the index to a
temporary one, runs `git add -A` there and `git diff --cached --binary <base>`,
so untracked files are included and the real index is never touched. Reuse it;
add no method to the `Vcs` port. `NoVcs.patch` throws, which is one of the
null cases.

The diff carries every changed file, the change's `.run/` files included. Only
the verify command decides what to do with it; this task does not filter it.
