## Acceptance

- [ ] `scripts/verify-rust.sh` keeps its three cargo steps in order. After `cargo test --workspace` it runs `sh scripts/mutants-rust.sh "$OSQ_DIFF"` when `OSQ_DIFF` is set and not empty, and the script's exit status is that command's. Otherwise it prints `mutation check not run: OSQ_DIFF is not set` and exits 0. Its header comment says so. It stays POSIX `sh` under `set -eu`, so an unset `OSQ_DIFF` is read as `${OSQ_DIFF:-}`.
- [ ] New `tests/rust-verify-script.test.ts` proves rust-core "Verify script steps", one case per table row, and "Verify script names the missing diff". It runs the real `sh scripts/verify-rust.sh` from the repository root with a `PATH` that puts a temporary folder holding a recording `cargo` stub first. The stub is a `sh` script that appends its arguments as one line to a log file and exits with a given status when its first argument is `mutants`, and 0 otherwise. The test builds the child environment itself and passes no `OSQ_DIFF` unless the row sets one. No real `cargo` runs.
- [ ] AGENTS.md's `## Rust crates` section gains, after its last bullet, the bullet under "Guide text" below, exactly. Nothing else in AGENTS.md changes, and every managed block is untouched.

## Details

Use plain `node:test` cases, as `tests/rust-ci.test.ts` does. Spawn the script
with `execFile` or `spawn` and `sh`, not through a shell string. With the stub,
the `mutants` line holds `--in-diff` and the diff path `mutants-rust.sh`
resolved, which is the same absolute path the row passed.

## Guide text

```markdown
- The watcher's verify also runs cargo-mutants on every Rust line your change touched since its base, from the diff osq passes in `OSQ_DIFF`, and fails on a missed mutant. A miss means no test checks that line: add one that does. To check a file by hand, run `cargo mutants -p <package> -f <file> -o "$(mktemp -d)"`.
```
