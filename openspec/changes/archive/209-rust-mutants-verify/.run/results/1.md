## Changed

- Added `src/core/run/verify-diff.ts`: `prepareVerifyDiff(projectRoot, changeFolder, config)` returns `{ path, cleanup }` or null. It reads `<changeFolder>/.run/base` trimmed, selects the `Vcs` with `selectVcs`, and, when the kind is `git` and the base is not blank, writes `vcs.patch(base)` into a `fs.mkdtemp` folder under `os.tmpdir()`. A missing marker, a blank base, `NoVcs`, and a `patch` that throws all give null. The file also exports `prepareVerifyEnv`, which assembles the role environment, applies the `OSQ_CHANGE` and `OSQ_DIFF` rules, sets `extraEnv` last, and returns the diff cleanup.
- Changed `src/core/run/verification.ts`: `runVerificationCommand` now builds `env` and `cleanup` through `prepareVerifyEnv(projectRoot, changeFolder, options)` and runs `await cleanup()` after the child promise, so the temporary diff folder is removed on pass, fail, timeout, and spawn error. Its signature and callers are unchanged.
- Added `tests/verify-diff.test.ts`: one test for watcher-and-harness "Verify gets the change's diff" (temporary git repo, `vcs.patch(B)` equality, both `src/a.rs` and `src/b.rs` named, file gone after the call) and one per table row of "No diff without a base" (null folder, missing `.run/base`, blank `.run/base`, non-git root), each with a probe that sets and restores `OSQ_DIFF=/stale.diff`.

## Deviated

- `verify-diff.ts` exports two functions rather than one: the diff function the acceptance describes and `prepareVerifyEnv`, the environment assembly the acceptance explicitly allows moving into this file for room. `runVerificationCommand` stays at 70 lines, well inside the 80-line budget.
- Note on the expected red start: `node --test <missing file>` reports success in this Node version, so the task's `verify` was green before the test file existed; the red start was not observable. The new test is still the proof of the two scenarios.
