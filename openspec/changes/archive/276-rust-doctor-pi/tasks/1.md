## Details

Port the line texts from TypeScript's `diagnosePi`, `checkConfig` and
`checkHarness`. Reuse rust-harnesses `resolve_pi_binary`, `run_process`,
`assess_pi_version` and `preflight_pi`, and rust-config `load_config` and
`Harness::as_str`. Hold the tested range as one `PiVersionRange`
constant.

`load_config` already rejects a blank `pi.provider`, so a set provider
needs no second blank check.

Read the process environment once, inline in the orchestrator, with
`std::env::vars()`. Don't give it a function of its own, because no test
can tell an empty map from the real one.

Write each row's `<fake>` as
`Path::new(env!("CARGO_MANIFEST_DIR")).join("tests/fixtures/fake-pi/doctor.sh")`.
Write a file the row lists as empty with no content.

`osq-cli` already registers `DoctorFeature`, so dispatch needs no change
there.

When the mutation check reports a missed mutant, add a test case for that
line rather than keeping a branch no test reaches. Run the proposal's
verify as the watcher does, with
`OSQ_CHANGE=openspec/changes/276-rust-doctor-pi`, so the link gates see
this change's new requirements.
