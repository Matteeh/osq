## Changed

- Gave `DoctorFeature` its `doctor` command, with the summary and empty usage the delta names, and its `UnknownCommand` and `Usage` refusals before any IO.
- Added the doctor checks: `load_config` and its one-line failure or harness line, pi only when the executor harness is `pi`, `resolve_pi_binary`, `pi --version` through `run_process`, `assess_pi_version` against `PI_TESTED_RANGE`, and `preflight_pi` for a configured provider. Failed checks return `FeatureError::failed("doctor", ...)` with the lines.
- Added `osq-kernel-config` and `osq-kernel-harnesses` to the crate manifest; `Cargo.lock` follows.
- Copied the fake pi to `crates/features/doctor/tests/fixtures/fake-pi/doctor.sh` byte-for-byte with mode 755.
- Replaced the empty-feature test with "Doctor feature commands" and "Doctor argument errors", and added `tests/doctor_checks.rs` for every fake-pi row and the fixture's execute bits.

## Deviated

- The `version-timeout` row's `osq.toml` also sets `harnessKillGracePeriodMs = 100`. The table names only `harnessPreflightSeconds = 1`, but the process runner waits the default 5000 ms kill grace after the timeout, so the row took about 6 seconds and could not meet the scenario's under-5-seconds rule. The extra setting keeps the row's behavior and result exact while satisfying the time bound.

## Missing context

- The timeout row's table omits a kill grace, so the under-5-seconds rule cannot hold with the default grace and the fake pi's orphaned `sleep 10`.

## Outside scope

- `sh scripts/verify-rust.sh` without `OSQ_CHANGE` fails the link-gate corpus because the new requirements and scenarios live only in this change's delta until archive. With `OSQ_CHANGE=openspec/changes/276-rust-doctor-pi` it passes.
