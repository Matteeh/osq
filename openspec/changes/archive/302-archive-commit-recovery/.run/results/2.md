## Changed

Added `hasFailedArchiveCommit` and `listArchivedCommitFailed` in `steering-change.ts` for archived worktree changes whose `.run/regressed/change.md` has reason `commit_failed` and no steering. `readNextStep` now returns `dead (archive commit failed) — osq retry <id> change` for such an archived change, so it is dropped from `notLanded`. `readInbox` adds one `change-regressed` needs-you item per failed archive commit, and `readDispatchItems` adds one `halt` item with `osq retry <id> change` and `osq show <id>` while suppressing that change's `land` item.

Added `tests/status-archive-commit.test.ts` with the two status-inspection scenarios, building the archived worktree change like `tests/steering-archived.test.ts` and writing the halt marker by hand. Because the living status spec has a duplicate scenario name, the test uses a clean lookup root for the effective delta, as `tests/archive-commit-recovery.test.ts` does.
