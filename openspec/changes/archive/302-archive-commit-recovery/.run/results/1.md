## Changed

- A failed "Archive commit" now returns a `commit_failed` halt from `commitWorktreeArchive`; `archive-change.ts` records it on the change where it now sits in the worktree's archive directory through `haltWorktreeChange`, keeping the warning and leaving the marker, event, and move uncommitted.
- New `src/watcher/archive-catch-up.ts` catches up archived worktree changes whose marker reason is `commit_failed`, in numeric order, within `gates.commitRetries`, using the same budget rule as task commit catch-up. It clears the halt with an automatic retry, commits the whole archive with the archived proposal title, logs `↻ archive of <id> committed after commit_failed`, and halts again on another failure. `loop.ts` calls it once per cycle before changes are advanced.
- `osq retry <id> change` on a `commit_failed` archived change now commits the whole archive as "Archive commit" does instead of `osq: <id> land retry`. A failed human retry restores the archived `.run/regressed/` files and `.run/events/change.jsonl` and throws `osq could not commit the archive: <git output>`.
- Both retry paths restore and re-remove the moved-away original folder so its deletion can be staged after an earlier failed attempt already staged it.
- New `tests/archive-commit-recovery.test.ts` proves all five watcher-and-harness scenarios with `scenario()` on scratch worktree repositories.

## Deviated

- The scenario helper refuses `watcher-and-harness` because the living spec repeats the scenario name "Native model". The test builds a temporary lookup root with a clean living spec and this change's real delta so `scenario()` can look the five names up.
- The test's `pre-commit` hook rejects only commits that stage `openspec/changes/archive/`, because a one-task change commits the task and archives in the same watcher cycle.
