## Acceptance

- [ ] A new `src/core/vcs/land-cleanup.ts` holds the cleanup, moved out of `land.ts` (`cleanupChange` and `cleanupLanded`). It runs when a folder exists at `worktreePath` or `worktreeList` lists it. It copies `<archive>/<folder>/.run/logs` from the worktree into the checkout's same path with `fs.cp` (`recursive`, `force: false`), deletes the folder with `fs.rm` (`recursive`, `force`), then calls `vcs.worktreePrune()`. It stops at the first failure with the line `Could not remove worktree <path>: <message>` and reports that it failed.
- [ ] `landChange` and the already-landed path return code 1 when the cleanup failed, else the after-land code as today. The lines and their order are unchanged apart from the new failure line replacing `Kept worktree`.
- [ ] New `tests/vcs-land-cleanup.test.ts` proves "Ignored build output removed", "Logs kept in the checkout", "Removal fails after the land commit" and "Leftover folder removed on the next land".
- [ ] The exported cleanup function carries an `@scenario version-control:` line for each of the four scenarios and `@adr 003`; every other test passes unchanged, and `pnpm typecheck:cli` passes.

## Details

Build each project with `createRecoveryProject` from
`tests/recovery-support.ts` and one task scoped `src/one.txt`. Approve it,
then run `watchOnce` with a `ScriptedAdapter` writing `task\n` until
`archivedFolder` exists, as `tests/recovery-land-red-verify.test.ts` does.
The project's `.gitignore` ignores `node_modules/`, so put the ignored
files there. The watcher already writes `.run/logs` in the worktree's
archived change folder; that folder holds its own `.gitignore`, so copying
it keeps the checkout clean.

For "Removal fails after the land commit", create
`node_modules/locked/f` in the worktree and `chmod` `node_modules/locked`
to `0o500`; restore `0o755` in `afterEach` before deleting the temporary
folders. For "Leftover folder removed on the next land", land once, then
create `target/big` at the worktree path and land again.

Find the checkout's archived change folder with `listChanges(projectRoot,
config, ['archived'])` from `src/core/status/change-locations.ts`, taking the
entry for the folder whose tree is the project root, and take the worktree's
logs from the same path relative to the worktree folder. Never call
`getArchiveDir` or `getChangesDir`: `tests/change-locations-readers.test.ts`
fails any file outside its allow list that does. The scenario
helper's `covers` is `landChange`; call it through `run` with the project's
`repo`, `config` and `'001'`, and assert on its `lines` and `code`.

A rough version of this change, measured on 2026-10-24, passed all four
scenarios and broke no existing test. Moving the cleanup out brings
`land.ts` from 249 lines to about 205.
