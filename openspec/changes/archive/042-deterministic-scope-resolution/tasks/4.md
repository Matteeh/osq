## Acceptance

- [ ] Start and end `measures` events carry `scopeResolver: 2`, and all scope-derived hashes, line counts, changed paths, and import fan-in consume `resolveScope` without another path expansion or glob matcher.
- [ ] `scopeFiles` counts existing resolved files, so one glob matching several files records several, an unmatched glob records zero, and an exact missing path remains in hashes with null but does not increase the file count.
- [ ] Start and end snapshots re-resolve the tree and compare their key union, so files added to, modified under, or deleted from a glob contribute correct `changedFiles`, `changedLines`, and `scopeHashes` rows.
- [ ] `history.sizes.scopeFileSeries` contains ordered `legacy` and `resolver-2` series, each with its own scope buckets and largest first-attempt pass; the resolver-2 series also exposes the earliest measured change or null.
- [ ] No scope bucket, largest-task comparison, near-limit hint, or repository-record largest pass compares legacy counts with resolver-2 counts; acceptance-line buckets remain one combined series because their unit did not change.
- [ ] Text output labels both scope-file series, marks the first resolver-2 change, and stable JSON carries the same boundary while preserving all non-size report, regression-history, planning, cycle, queue, and coverage fields.
- [ ] Mixed fixtures include legacy and resolver-2 measures with conflicting largest tasks, glob counts, malformed versions, and no-v2 history; report output is deterministic, and report plus golden-event fixtures are synchronized to the completed final tree.

## Details

Replace the literal loop in `snapshotScope` with task 1's resolver projection.
Retain null hashes and zero lines for exact missing entries, but derive
`scopeFiles` from non-null resolved files. Pass the same resolved paths to
`countImportFanIn`; it must no longer resolve glob text as a literal import
target. Re-run resolution for the end snapshot and preserve the existing union
diff so newly matching and deleted files remain visible. Add `scopeResolver`
to `MeasuresEventData` as the required literal 2 on newly emitted events while
keeping older lines readable.

Replace the ambiguous single scope-size aggregation with
`history.sizes.scopeFileSeries`, ordered as `legacy` then `resolver-2`. Each
series contains `resolver`, `startsAtChange`, `byScopeFiles`, and
`largestFirstAttemptPass`; legacy uses a null boundary and events whose first
valid start measure has no resolver field, while resolver-2 uses only exact
numeric version 2 and records the lowest stable numeric change containing one.
Malformed or unknown versions contribute to neither scope-file series. Keep
`history.sizes.byAcceptanceLines` over every otherwise valid measured task.

Use only the resolver-2 largest pass for the configured-scope near-limit hint
when resolver-2 data exists; do not fall back across generations in that case.
For the recent repository record, select measured tasks from resolver 2 when
any exist in its archive window and otherwise retain the labeled legacy
fallback, so its largest scope value also has one unit. Render explicit text
headings for both series and `resolver 2 starts at: <change|unavailable>`.

Extend `tests/measures.test.ts` for glob start/end snapshots and exact missing
paths. Extend `tests/report-sizes.test.ts` and the existing report JSON fixture
for separate series, boundary ordering, malformed version exclusion, v2
largest selection, legacy fallback, and unchanged acceptance buckets. Update
only report fixtures required by the stable shape. Tasks 1 and 2 changed the
repository-size values recorded in `tests/fixtures/events/*.jsonl`; include
`tests/golden-events.test.ts` in final-tree verification and update only those
stale measured counts after task 4's code is complete. Reuse `snapshotScope`,
`gatherScopeCounts`, `countImportFanIn`, `projectMeasuredTasks`,
`aggregateSizeBuckets`, `selectLargestFirstAttemptPass`,
`getRepositoryRecord`, `formatMetricsReport`, and `toStableMetrics`.
