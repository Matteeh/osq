## Acceptance

- [ ] `resolveScope` is the sole scope glob implementation under `src/`, supports exact paths plus the established `*`, `**`, `?`, and trailing-directory forms, and uses no new dependency.
- [ ] Resolution returns deduplicated, lexically sorted project-relative POSIX entries; existing regular files carry their usable file path, an exact missing path is retained with null, and an unmatched glob contributes no entry.
- [ ] Resolution is independent of declaration order, handles an exact entry also matched by a glob once, stays inside the project tree, and produces the same bytes for the same tree.
- [ ] `computeTaskScopeHash` reads only the resolver projection, hashes existing UTF-8 file contents, retains null exact files, folds sorted path/hash pairs into the established aggregate SHA-256 shape, and supplies resolver-aware `scope_files` evidence to `attributeScopePaths` without changing its sole-editor, ambiguous, or contradicted-hash outcomes.
- [ ] Adding, modifying, and deleting files matched by `src/core/queue-report*.ts` between hashes changes the aggregate and yields sorted `(added)`, `(modified)`, and `(deleted)` paths through `findDifferingPaths`.
- [ ] The linter's test compliance check consumes `resolveScope`, preserves every existing compliance fixture result, and removes `globToRegExp` plus its private tree walker without changing the declared-pattern limit.
- [ ] Existing literal hash callers, watcher audit exports, import boundaries, and source line budgets remain green while `SCOPE_RESOLVER_VERSION` exposes the value 2 for later tasks.

## Details

Create `src/core/scope.ts` and move the established matcher semantics out of
`globToRegExp` in `src/core/linter.ts`. Keep the core module filesystem-only
and free of watcher, harness, CLI, and parser imports. Represent each result with a
normalized relative path and either an existing absolute file path or null so
callers never reimplement existence or glob decisions. Walk only directories
inside `projectRoot`, include regular files, normalize `./` and platform
separators, and sort directory entries and final results explicitly rather than
depending on filesystem order. Treat glob metacharacters as the distinction
between a missing exact entry and a no-match pattern; negative patterns remain
ordinary unsupported syntax.

Refactor `computeTaskScopeHash` in `src/core/scope-hash.ts` to consume
`resolveScope`. Preserve `ScopeHashResult`, the compatibility export from
`src/watcher/regression.ts`, the `sha256:` prefixes, and the canonical joined
digest format. Export `SCOPE_RESOLVER_VERSION` as 2 and let `readDoneMarker`
surface a finite recorded `scope_resolver` or null for task 2 without changing
audit behavior yet. Keep `findDifferingPaths` as the one union comparison so a
glob match entering or leaving the result is classified from recorded and
current maps rather than from the pattern text.

Cut the existing `tests.modify` compliance check over in the same task so
`globToRegExp`, `listExistingTestFiles`, and `touchedTestFiles` can be deleted
immediately. Resolve a task once, filter its non-null existing paths to the
same existing `tests/` file set used today, and preserve the exact existing/missing
behavior. Keep collecting the resolved set locally so task 3 can extend the
linter with pairwise warnings, but do not add overlap behavior in this task.

Add `tests/scope-resolver.test.ts` for normalization, ordering, overlap,
missing exact paths, empty globs, nested `**`, segment `*`/`?`, and attempts to
resolve outside the project. Extend only the hash cases in
`tests/runner-scope-hashes.test.ts` with a temporary `queue-report` fixture that
adds, modifies, and deletes matches and asserts exact differing displays.
`tests/linter.test.ts`, `tests/scope-recertification.test.ts`, import-graph
tests, and line-budget tests are frozen final-tree regression checks. Reuse `relativePosix`,
`computeTaskScopeHash`, `findDifferingPaths`, `attributeScopePaths`, and
`readDoneMarker` rather than introducing parallel normalization or comparison.
