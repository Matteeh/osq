## Acceptance

- [ ] `lintChangeFolder` reuses task 1's resolved task projection for overlap analysis and introduces no matcher, tree walker, or scope normalization of its own.
- [ ] Existing test compliance is unchanged: an existing exact or glob-matched file under configured test patterns requires `tests.modify: true`, while a missing exact new test and an unmatched glob do not.
- [ ] After all tasks are parsed, each existing resolved file shared by two tasks emits a deterministic warning naming both task numbers and the project-relative POSIX path.
- [ ] Duplicate declarations inside one task do not self-warn; a file shared by three tasks yields one warning for each stable task pair; missing exact paths and unmatched globs never produce overlap warnings.
- [ ] Overlap warnings do not set `valid` false, suppress independent errors, or change the configured `maxScopeFiles` check, which continues to count declared patterns.
- [ ] The existing compliance fixtures pass unchanged and focused tests cover exact/glob overlap, pair ordering, three-task overlap, no-match scopes, and warning-only exit behavior through the real lint entrypoint.

## Details

Extend the resolved-task collection established by task 1 after all task files
have been parsed. Use each task's cached non-null existing paths to build
cross-task intersections. Do not re-resolve scopes or reopen the compliance
implementation. The task's own scope declaration remains the input to the
existing pattern-count limit; this change does not reinterpret `maxScopeFiles`
as a resolved-file limit.

Collect enough task identity during the existing task loop to sort by numeric
task filename with the established stable fallback. Format one warning per
task-pair/file in task order and then path order. The diagnostic must include
both task numbers and the relative path, but must not use task titles as the
only identifiers. Preserve all proposal, verify-command, delta, validator,
acceptance, and tests.modify schema diagnostics.

Build `tests/scope-lint.test.ts` through `lintChangeFolder` with the existing
fake-validator helper. Include source and test files in a temporary project so
the suite proves the compliance result rather than testing the resolver in
isolation. `tests/linter.test.ts` is frozen and supplies the required unchanged
compliance cases. Reuse `resolveScope`, `compareNumericPrefix`,
`readTestsModifyDeclaration`, and the existing `LintResult.warnings` channel.
