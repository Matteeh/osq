## Changed

- `src/core/linter.ts`:
  - `ResolvedTaskScope` now also carries `taskNumber` (numeric task filename
    without `.md`), collected during the existing task loop alongside the cached
    resolved `existingPaths` from task 1.
  - Added `collectOverlapWarnings`: after all tasks are parsed it orders the
    collected scopes with the established `compareNumericPrefix` (imported from
    `./state.js`) using the task filename with its stable lexical fallback, then
    emits one warning per task-pair/file (`Tasks <a> and <b> share resolved scope
    file <relative-posix-path>`) in task order then sorted path order. It only
    intersects the already-resolved, deduplicated, non-null path lists: no
    matcher, tree walker, or scope normalization of its own.
  - The warnings are appended to the existing `LintResult.warnings` channel, so
    they never set `valid` false, never suppress independent errors, and the
    `maxScopeFiles` check still counts declared `task.scope.length`.
- `tests/scope-lint.test.ts` (new): drives `lintChangeFolder` end to end with the
  same local fake-validator helper used by `tests/linter.test.ts`, in temporary
  projects holding real source and test files. Covers exact and glob overlap,
  three-task pair expansion, path/pair ordering, duplicate in-task declarations,
  missing exact paths and unmatched globs, overlap coexisting with an independent
  error, unchanged `maxScopeFiles` counting, exact and glob test-compliance
  outcomes, new-exact/unmatched-glob test scopes, and warning-only zero-exit
  through the real `lintCommand` entrypoint.
