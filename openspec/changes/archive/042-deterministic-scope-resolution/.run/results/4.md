(`pnpm tsc --noEmit && pnpm test && pnpm lint`) is clean: `1095` tests pass,

## Changed

- `src/watcher/measures.ts` (249 lines, still under the 250-line budget):
  - `snapshotScope` now projects task 1's `resolveScope` instead of resolving
    each declaration literally. Missing exact entries keep their key with a
    `null` hash and zero lines; glob and trailing-directory entries contribute
    only their resolved existing files. `gatherScopeCounts` therefore derives
    `scopeFiles` from non-null resolved files, so one glob matching several files
    records several and an unmatched glob records zero.
  - `countImportFanIn` consumes `resolveScope` and filters its resolved absolute
    paths to `src/`, so a glob is expanded into real import targets rather than
    matched as literal text.
  - `gatherStartMeasures` emits `scopeResolver: SCOPE_RESOLVER_VERSION` (2);
    `gatherEndMeasures` spreads it and re-resolves the end tree, preserving the
    existing key-union diff for files added to, modified under, or deleted from
    a glob.
- `src/harness/types.ts`: `MeasuresEventData.scopeResolver` is a required
  literal (`typeof SCOPE_RESOLVER_VERSION`) on newly emitted events. Legacy
  lines without the field remain readable because report parsing is raw JSON.
- `src/core/report.ts`: `SizeMetrics` now exposes ordered `scopeFileSeries`
  (`legacy` then `resolver-2`) plus the unchanged combined `byAcceptanceLines`.
  Each series carries `resolver`, nullable `startsAtChange`, its own scope-file
  buckets, and its own largest first-attempt pass. `MeasuredTask` records the
  raw first-start `scopeResolver`: absent is legacy, exact numeric 2 is
  resolver 2, and malformed/unknown versions enter neither scope-file series but
  still count in acceptance buckets. The resolver-2 boundary is the lowest
  numeric change with a version-2 measure. The near-limit hint uses the
  resolver-2 largest pass whenever resolver-2 data exists (no fallback) and the
  legacy pass only when it does not. `RepositoryRecord.scopeFileResolver`
  records the single generation behind its scope-sized largest pass
  (resolver-2 when the window has any, otherwise legacy) and
  `formatRepositoryRecordBody` labels it `[legacy scope]` / `[resolver 2 scope]`.
  Text output prints `Size by scope files (legacy):`,
  `Size by scope files (resolver-2):`, and `Resolver 2 starts at: <change|unavailable>`.
- `src/cli/report.ts`: `toStableMetrics` projects the same ordered
  `scopeFileSeries` and boundary into the stable JSON while preserving every
  non-size field.
- `tests/measures.test.ts`: start measures carry `scopeResolver: 2`; runner
  start/end both carry 2; glob counts (several files, unmatched glob, exact
  duplicate, exact missing path); `snapshotScopeHashes` keeps a missing exact
  path as `null` and omits unmatched globs; `gatherEndMeasures` union diff for
  added/modified/deleted glob matches; `countImportFanIn` resolves a glob.
- `tests/report-sizes.test.ts`: series expectations for the legacy-only
  checked-in fixture (empty resolver-2 with null boundary); ordering; separate
  largest passes; new mixed-generation fixture (legacy vs resolver-2 conflicting
  largest, malformed version excluded from scope series but counted in
  acceptance buckets, resolver-2 boundary, resolver-2-only hint); repository
  record resolver-2 selection and labeled legacy fallback; malformed-only
  record; `RepositoryRecord` literals updated.
- `tests/report-json.test.ts`: stable `history.sizes` keys are
  `byAcceptanceLines` + `scopeFileSeries`; manual `MetricsReport` fixtures and
  text assertions updated.
- `tests/fixtures/events/{verified,dead}.jsonl`: regenerated via
  `UPDATE_GOLDEN=1`; measures now carry `scopeResolver: 2` and the pre-existing
  stale `repoLines` (`436`) is synchronized to the current templates (`439`).
- `fixture/report/expected.json`: regenerated through the real report command
  so the checked-in JSON matches the completed final tree.
