# Task 2 — Resolver-versioned completion and legacy recertification

Status: complete. All seven acceptance lines are implemented and the task verify
command passes (`49` tests, `0` failures). `pnpm tsc --noEmit`, `pnpm lint`, and
`tests/line-budget.test.ts` are clean.

## Changed

- `src/watcher/outcome.ts`: `DoneMarkerMetadata` gained optional `scopeResolver`;
  `writeDoneMarker` emits `scope_resolver: <version>` (defaulting to
  `SCOPE_RESOLVER_VERSION`) beside `scope_hash`/`scope_files` for every
  metadata-bearing marker. Timestamp-only markers remain frontmatter-free and
  `readDoneMarker` still returns `null` for them.
- `src/watcher/regression.ts`: `buildDoneMetadata` records
  `scopeResolver: SCOPE_RESOLVER_VERSION`. `auditScopeRegressions` now treats a
  task as stale when the resolver version is absent, malformed, or not 2 even
  though the aggregate hash matches, and skips differing-path computation for a
  version-only upgrade so no path is invented. The regression marker frontmatter
  and `regressed` event both carry `recorded_resolver`/`recordedResolver`
  (`null` when legacy) and `current_resolver`/`currentResolver`. The existing
  stale-task paths (verify, blocking, active-marker idempotency, attribution)
  are unchanged and shared by the pre-dispatch and pre-archive callers.
- `src/harness/types.ts`: `RegressedEventData` gained optional
  `recordedResolver`/`currentResolver`.
- `src/core/retry.ts`: a passing scope recertification rebuilds the canonical
  done marker with `scope_resolver: SCOPE_RESOLVER_VERSION` alongside the fresh
  `scope_hash`/`scope_files`, preserving body bytes and unknown keys; the failed
  path is untouched and still requeues without a canonical done marker.
- `tests/scope-resolver-upgrade.test.ts` (new): ordinary completion emits
  resolver 2 and timestamp-only markers stay unrecognized; a version-only legacy
  marker is detected with empty differing paths and resolver context; a legacy
  glob marker also reports differing resolved paths; repeated cycles are
  idempotent; wrong and malformed versions are stale while a manual marker is
  excluded; the pre-archive gate blocks; passing retry refreshes the marker and
  failed retry requeues; an archived marker stays byte-identical; README has one
  `Upgrading` note with the detection/verify/`osq retry <id> <task>` contract.
- `README.md`: one `## Upgrading` note describing the one-time active-change
  recertification wave, detection verification, idempotent regression marker,
  explicit per-task retry, and untouched archive markers.

## Deviations

None. No new numeric literal was introduced: the version always flows from
`SCOPE_RESOLVER_VERSION`. Marker resolver context is written by string
augmentation of the existing shared marker builder because `src/core/scope-hash.ts`
is outside this task's scope; `retry.ts` imports the constant from
`./scope.js` directly to stay under the source line budget.
