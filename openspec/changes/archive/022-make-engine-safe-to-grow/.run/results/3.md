- `tests/golden-events.test.ts` (new, 186 lines)
  - `normalizeEvents(rawJsonl, projectRoot)` helper: parses each JSONL line, recursively
    masks absolute project paths to relative posix paths, then replaces `timestamp` with
    `[TIMESTAMP]`, `data.pid` with `12345`, `data.commit` with `[COMMIT]`,
    `data.version`/`data.osqVersion` with `[VERSION]`, and `data.elapsedSeconds` with `0`,

  - Test "verified": scaffolds a project, creates the `Golden Events` change

## Deviated

- **Event order differs from the task Details.** The Details list the expected sequence as
  `started`, `tokens`, `result_written`, `exited`, `verify_ran`, `done`/`dead`. The actual
  end-to-end order with the stock `MockAdapter` is `tokens`, `result_written`, `started`,
  `exited`, `verify_ran`, `done`/`dead`. Cause: `src/watcher/spawn.ts` emits `started` from
  `onSpawn`/after `adapter.spawn` resolves, and `MockAdapter` (unlike opencode/agy) never
  invokes `options.onSpawn`; it writes its `tokens`/`result_written` events before returning.
  The fixtures were generated from the real emitted stream (a characterization/regression
  golden), not hand-written to the assumed order. The acceptance checkboxes require a
  checked-in golden sequence, not a specific order, so all lines still hold.
- **`started` carries no `pid` in these fixtures.** Because `MockAdapter` does not call
  `onSpawn` and returns no `pid`, `data.pid` is `undefined` and therefore omitted by
  `JSON.stringify`; the normalization still masks `pid` when present (proven by the unit
  test). The Details note "(with masked pid)" is only achievable once the mock signals
  spawn.
- `normalizeEvents` is not exported. Biome's `lint/suspicious/noExportsInTest` forbids
  exports from test files, and nothing else imports it.
