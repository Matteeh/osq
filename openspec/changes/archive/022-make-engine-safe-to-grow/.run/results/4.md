# Task 4 — `osq doctor` repository health diagnostics

## Changed

- `src/core/doctor.ts` (new, 198 lines):
  - Exports `DoctorCheckResult`, `DoctorReport`, `DoctorDependencies`, and
    `runDoctorChecks(projectRoot, deps?)` returning results for exactly five checks in order:
    `config`, `harness`, `managed-blocks`, `locks`, `archives`.
  - `config`: calls `loadConfig(projectRoot)` (injectable seam) in a try/catch and validates
    required properties (`harness`, `limits`, `paths.specs`, `paths.archive`, `timeouts`).
    Fails on a throw or an incomplete/invalid config.
  - `harness`: resolves the configured binary (`OPENCODE_PATH` → `config.opencode.bin` → `opencode`;
    `AGY_PATH` → `agy`; unknown harness → its own name) and probes `<bin> --version` with a 10s
    timeout via `node:child_process.execFile`. `mock` needs no binary. Fails naming the binary when
    the probe throws.
  - `managed-blocks`: reads `AGENTS.md` and `PLANNER.md`. `PLANNER.md` must exist and carry both
    `OSQ_START_MARKER`/`OSQ_END_MARKER` in order. A missing file, a partial/reversed marker pair, or
    a markerless `PLANNER.md` fails; a markerless `AGENTS.md` is reported as unmanaged (see
    Deviated).
  - `locks`: scans active change dirs under `config.paths.specs` and legacy `specs/`, skipping
    `archive`/`_`/`.` dirs, for `.run/running/*.pid` and `.run/locks/*.pid`. A lock whose `pid` is
    not alive (`isPidRunning`) is named as orphaned; live locks pass.
  - `archives`: scans `config.paths.archive` and legacy `specs/archive`. Each direct child must have
    `proposal.md` (or `spec.md`) and `tasks/` (or `tasks.md`); offenders are named.
- `src/cli/doctor.ts` (new, 33 lines): `doctorCommand(options?)` runs `runDoctorChecks(cwd)` and
  prints one line per check as `[ok] <name>: <message>` / `[fail] <name>: <message>`, then sets a
  non-zero exit code (default `process.exitCode = 1`) when any check fails. `cwd`, `stdout`, and
  `exit` are injectable for tests.
- `src/cli/index.ts`: imports `doctorCommand` and registers `program.command('doctor')` with
  description `validate repository health, configuration, and archives`.
- `tests/doctor.test.ts` (new, 259 lines): 12 tests covering the healthy five-check pass, config
  failure (invalid property and throwing loader), harness failure for a missing binary,
  managed-blocks failure (markerless `PLANNER.md`, partial marker pair), orphaned vs. live locks,
  corrupt vs. complete archives, CLI printing/exit behavior, and a binary-gated run against the
  active osq checkout.

## Deviated

- **Strict per-file reading of the managed-blocks check was relaxed for `AGENTS.md`.** The task
  Details say fail unless *both* `AGENTS.md` and `PLANNER.md` contain both markers. The active
  checkout's root `AGENTS.md` is hand-authored and has **no** osq markers, and `AGENTS.md` is out of
  this task's `scope`, so the literal rule makes acceptance line 15 (`osq doctor` on the active
  checkout exits 0) unsatisfiable without editing an out-of-scope file. Doctor therefore treats a
  file with *no* markers at all as unmanaged, while any partial/reversed pair (and a markerless
  `PLANNER.md`, which is always osq-owned) is still a failure. The healthy-repo test writes markers
  into both files, so the both-files path is still exercised.
- **The harness check does not call the adapter `preflight`.** `src/core/doctor.ts` may not import
  `src/harness/**` (enforced by `tests/import-graph.test.ts`), and `preflightOpencode` calls
  `process.exit(1)` on failure, which would terminate the diagnostic command. The core check mirrors
  the preflight intent (spawn `<bin> --version`) using `node:child_process` directly.
- `src/core/doctor.ts` uses a `node:child_process` import; that is a builtin, not a new runtime
  dependency, so it does not require an ADR.
- `DoctorDependencies.loadConfig` was added as an optional second argument to `runDoctorChecks` so
  the throwing-loader path is testable without a config file that can actually make `loadConfig`
  throw (it swallows config import errors).
