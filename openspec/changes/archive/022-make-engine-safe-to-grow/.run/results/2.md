# Task 2 — Typed event union and write-time tool summary relativization

## Changed

- `src/core/summary.ts` (new, 27 lines): extracted `relativizeToolSummary(summary, root = process.cwd())`
  verbatim from the watcher so core/harness/watcher share one implementation.
- `src/watcher/heartbeat.ts` (177 lines): imports `relativizeToolSummary` from `../core/summary.js`
  and re-exports it; the duplicated body was deleted.
- `src/harness/types.ts`: added typed payloads `StartedEventData`, `TokensEventData`, `ToolEventData`,
  `TextEventData`, `FileChangedEventData`, `VerifyRanEventData`, `ResultWrittenEventData`,
  `ExitedEventData`, `DoneEventData`, `DeadEventData`; added the `OsqEventData` type→payload map and
  `OsqEvent` as a discriminated union over `type` with typed `data`. `HarnessEvent` is now an alias of
  `OsqEvent`.
- `src/watcher/spawn.ts` (199 lines): the runner's `started` event now carries `harness: adapter.name`,
  `model` (resolved from the active harness config, falling back to `config.agy.model` then `default`),
  and `osqVersion: buildInfo.version`, alongside `version`, `commit`, `pid`, and `timeoutSeconds`.
  Compacted formatting/spread to stay under the 200-line lifecycle-module budget.
- `src/harness/opencode.ts` / `src/harness/agy.ts`: renamed the shared tool handler to
  `emitObservedToolEvent`; it now relativizes `toolEvent.summary` against `projectRoot` before
  appending (and uses the relativized value for the verbose log). `projectRoot` is threaded from each
  adapter's `spawn` through `process*StdoutLine` and the `*EventStreamParser` constructor.
- `src/harness/mock.ts`: removed the adapter-emitted `started` and `exited` events; the runner is the
  single emitter for lifecycle events.
- `tests/runner-lifecycle-logging.test.ts`: added six tests covering the core export + heartbeat
  re-export, the `OsqEvent` union, write-time relativization for opencode and agy, `harness`/`model`/
  `osqVersion` on `started`, and single `started`/`exited` emission with `MockAdapter`.

## Deviated

- `VerifyRanEventData` fields are optional and it retains a legacy `command?` field. `src/watcher/runner.ts`
  (out of scope) still emits `verify_ran` with `{ command: taskData.verify }` before running the gate,
  so required `exitCode`/`verifyCommand` would have broken `pnpm tsc --noEmit`.
- `OsqEventData['started']` is `StartedEventPayload = StartedEventData | Record<string, unknown>`.
  The out-of-scope `tests/harness.test.ts` constructs a `HarnessEvent` with `{ tier, pid }`; the legacy
  record member keeps `pnpm tsc` green while `StartedEventData` remains the canonical shape.
- `emitObservedToolEvent` is module-private in both adapters. Exporting both made
  `src/harness/index.ts`'s `export *` ambiguous (`TS2308`), and `index.ts` is out of scope.
- Task detail mentioned `path.dirname(path.dirname(specFolderPath))` as a project-root fallback; it does
  not hold for the current `openspec/changes/<id>` layout, so the adapters thread the real `projectRoot`
  instead. Direct-call fallback remains `relativizeToolSummary`'s `process.cwd()`.

## Drift against features/

- `specs/watcher-and-harness/spec.md` "Typed event hygiene and single emission path" is satisfied for
  the `started` metadata, write-time relativization, and single emission path.
- Acceptance line "All modified files remain strictly under 200 lines" is not literally achievable
  within scope: `src/harness/opencode.ts` (536), `src/harness/agy.ts` (375), `src/harness/types.ts`
  (257), and `tests/runner-lifecycle-logging.test.ts` (306) were already over or grew past 200. Only
  the watcher lifecycle modules (`spawn.ts` 199, `heartbeat.ts` 177) are governed by the enforced
  budget in `tests/import-graph.test.ts`; they comply.

## Missing context / out-of-scope fallout

- `tests/harness.test.ts` (out of scope, `MockAdapter` suite) asserts that `MockAdapter.spawn` writes
  `"type":"started"` and `"type":"exited"` events. Acceptance line 5 intentionally removes those, so
  after this task `pnpm test` is 498 pass / 1 fail. That test needs to assert `tokens`/`result_written`
  and rely on the runner for lifecycle events (task 3 touches the golden suite but not this file).
- `src/watcher/runner.ts` (out of scope) still emits the pre-verification `verify_ran` payload
  `{ command }`, which does not match the new `{ exitCode, verifyCommand }` intent.
