## Acceptance
- [ ] src/core/doctor.ts exports runDoctorChecks returning results for config, harness, managed blocks, locks, and archives
- [ ] Doctor validates harness binary availability and version using harness preflight
- [ ] Doctor validates AGENTS.md and PLANNER.md contain valid managed blocks
- [ ] Doctor validates no orphaned locks exist in active changes and all archived changes validate
- [ ] src/cli/doctor.ts prints one line per check and exits non-zero if any check fails
- [ ] src/cli/index.ts registers the doctor command on the osq CLI program
- [ ] Running osq doctor on the active checkout passes all checks with exit code 0

## Details

1. In `src/core/doctor.ts`:
   - Implement diagnostic check runner:
     ```ts
     export interface DoctorCheckResult {
       name: string;
       ok: boolean;
       message: string;
     }
     export interface DoctorReport {
       ok: boolean;
       checks: DoctorCheckResult[];
     }
     export async function runDoctorChecks(projectRoot: string): Promise<DoctorReport>
     ```
   - Check 1 (`config`): Call `loadConfig(projectRoot)`. Pass if config loads with valid properties; fail if exception thrown.
   - Check 2 (`harness`): Instantiate configured harness adapter or check binary availability (e.g. executing `<bin> --version` via preflight). Pass if binary is accessible; fail if binary not found or non-zero. For test/mock environments or when configured harness binary is missing, report clear failure line.
   - Check 3 (`managed-blocks`): Read `AGENTS.md` and `PLANNER.md`. Pass if both exist and contain `OSQ_START_MARKER` and `OSQ_END_MARKER`.
   - Check 4 (`locks`): Scan `openspec/changes` (and legacy `specs/`) for `.run/locks/` or active lock files. Pass if no orphaned locks found; fail naming orphaned lock files.
   - Check 5 (`archives`): Scan `openspec/changes/archive/`. For each archived change, verify proposal and tasks exist. Pass if all archives validate; fail if any archive is corrupt.
   - Keep `src/core/doctor.ts` strictly under 200 lines.
2. In `src/cli/doctor.ts`:
   - Call `runDoctorChecks(process.cwd())`.
   - For each check, format: `[ok] <message>` (green/plain) or `[fail] <message>` (red/plain).
   - If `!report.ok`, set `process.exitCode = 1`.
   - Keep file under 50 lines.
3. In `src/cli/index.ts`:
   - Import `doctorCommand` from `./doctor.js`.
   - Register `program.command('doctor').description('validate repository health, configuration, and archives').action(async () => { await doctorCommand(); });`.
4. In `tests/doctor.test.ts`:
   - Test healthy repository passes all 5 checks.
   - Test failing config marks config check failed.
   - Test missing managed block marks managed-blocks check failed.
   - Test orphaned lock marks locks check failed.
5. Verification:
   - Run `node --import tsx --test tests/doctor.test.ts`.
