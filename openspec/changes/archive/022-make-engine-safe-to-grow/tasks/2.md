## Details

1. In `src/core/summary.ts`:
   - Extract `relativizeToolSummary(summary: string, root: string = process.cwd()): string` from `src/watcher/heartbeat.ts` to make it available to core, harness, and watcher without violating layer boundaries.
2. In `src/watcher/heartbeat.ts`:
   - Import and re-export `relativizeToolSummary` from `../core/summary.js` for backward compatibility.
3. In `src/harness/types.ts`:
   - Define typed payload interfaces for each event type:
     - `StartedEventData`: `{ harness: string; model: string; osqVersion: string; commit?: string; pid?: number; timeoutSeconds: number; version?: string }`
     - `TokensEventData`: `{ promptTokens: number; candidateTokens: number; totalTokens?: number; cachedTokens?: number; reasoningTokens?: number; cost?: number }`
     - `ToolEventData`: `{ tool: string; summary: string }`
     - `TextEventData`: `{ readonly text: string }`
     - `FileChangedEventData`: `{ path: string }`
     - `VerifyRanEventData`: `{ exitCode: number; verifyCommand: string; output?: string }`
     - `ResultWrittenEventData`: `{ path: string; synthesized?: boolean }`
     - `ExitedEventData`: `{ exitCode: number; pid?: number; signal?: string; timedOut?: boolean; elapsedSeconds?: number }`
     - `DoneEventData`: `{ readonly task: string }`
     - `DeadEventData`: `{ readonly task: string; readonly reason: string }`
   - Define `OsqEventData` and define `HarnessEvent` as a discriminated union over `type` with typed `data`.
4. In `src/watcher/spawn.ts`:
   - In `spawnTaskAgent`:
     - When emitting `started`, extract model name from `config[config.harness]?.model ?? config.agy?.model ?? 'default'`.
     - Include `harness: adapter.name`, `model`, and `osqVersion: buildInfo.version` alongside `version`, `commit`, `pid`, `timeoutSeconds`.
5. In `src/harness/opencode.ts` and `src/harness/agy.ts`:
   - In `emitObservedToolEvent`:
     - Relativize `toolEvent.summary` against `projectRoot` (or `path.dirname(path.dirname(specFolderPath))`) using `relativizeToolSummary` prior to calling `appendHarnessEvent`.
6. In `src/harness/mock.ts`:
   - Remove duplicate `started` and `exited` event emissions from `MockAdapter.spawn()`. The runner's `spawnTaskAgent` is the single code path responsible for lifecycle `started` and `exited` events.
7. Verification:
   - Run `node --import tsx --test tests/runner-lifecycle-logging.test.ts tests/watcher-build-identity.test.ts`.
