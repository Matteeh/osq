## Changed

- `src/core/foundation/decisions.ts`: `Adr` gains `checks`, `denies`, and
  `malformed`; `toAdr` reads both fields (present-but-not-a-non-empty-string-list
  is recorded in `malformed`, missing reads as empty), check paths are trimmed,
  backslashes become forward slashes, and a leading `./` is dropped. Re-exports
  `validateDecisions`, `sameAdrNumber`, and `DecisionProblems`.
- `src/core/foundation/decisions-validate.ts` (new): holds `DecisionProblems`,
  `sameAdrNumber`, and `validateDecisions`; reports one error per malformed field
  as `<adr path>: <field> must be a list of non-empty strings`, before the
  existing status/applies_to/rule/superseded checks.
- `src/core/foundation/doctor-decisions.ts`: `checkDecisions` also fails for each
  check file named by an accepted ADR that doesn't exist, as
  `<adr path>: check file <file> does not exist`, resolved against the project
  root. Proposed and superseded ADRs are skipped.
- `decisions/README.md`: `## Format` documents `checks` and `denies` and states
  that only accepted ADRs' checks and denials take effect.
- `tests/adr-checks-denies.test.ts` (new): covers reading and normalization,
  missing fields, malformed `checks` and `denies` (one error each), and doctor
  failing on a missing accepted check file (through `checkDecisions` and the
  printed `[fail] decisions:` line via `doctorCommand`), passing when the file
  exists, and not failing for superseded and proposed ADRs.

## Deviated

- Moved `sameAdrNumber` and `VALID_STATUSES` to `decisions-validate.ts` too,
  since `sameAdrNumber` is a validation helper and `decisions-validate.ts` needs
  it; `decisions.ts` re-exports `sameAdrNumber` so existing callers are
  unchanged.
- Malformed-field errors are reported for every ADR, including ones with an
  invalid status, because `malformed` is a reading concern independent of the
  status vocabulary.
