## Changed

- Added `src/core/report/report-dependencies.ts`: `addedPairs`/`distinctPairs`
  validate, dedupe, and sort `{ file, name }` pairs; `collectDependencies`
  reads every numbered task stream of each active/archived folder for
  `dependencies_added` events and returns one `{ change, added }` entry per
  change in numeric order; `formatDependencies` renders the section body.
- `src/core/report/report.ts`: `HistoryMetrics` gains optional `dependencies`;
  `getMetricsReport` calls `collectDependencies(allSpecFolders)` and includes
  the field only when non-empty; `formatMetricsReport` prints the
  `Dependencies added:` section only when the list isn't empty.
- `src/cli/report.ts`: `toStableMetrics` copies `history.dependencies` only
  when non-empty, so the `fixture/report` stable JSON keeps its exact bytes.
- `src/core/status/show.ts`: new `formatDependenciesAdded` beside
  `formatStuck`, called after `formatInstructionsChanged`, prints
  `      Dependencies added: <name> (<file>), ...` from all of a task's
  `dependencies_added` events.
- `README.md`: the Architecture decisions section documents `checks`/`denies`,
  the `adr_check_modified` flag, the dependency baseline and
  `dependencies_added` event, the `denied_dependency` dead reason with its
  automatic retry, and the new show/report lines; the dead-reasons paragraph
  lists `denied_dependency`.
- Added `tests/dependencies-report.test.ts`: report listing/order, JSON
  omission when empty, dedupe+sort across streams/attempts, rejected exclusion,
  and the show line with its placement after instructions changed.

## Deviated

- The report's dependency entries name the change by folder name (`012-adds`),
  matching the delta scenario's text `012-<slug>` and the cycle/planning
  sections, rather than the padded numeric id that rework and disclosures use.
  The pair container is `added`, matching the `dependencies_added` event's
  data field; the task left the JSON shape and identifier unstated.

## Missing context

- The metrics-and-reporting delta says `history.dependencies` lists changes
  "in change order" and text prints `  <change>: ...` but never pins whether
  `<change>` is the padded id or the folder name; the scenario's `012-<slug>`
  text was the only signal, so I used the folder name consistently in JSON and
  text.
