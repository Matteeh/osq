## Details

The port, in `src/core/vcs/vcs.ts`:

```ts
export interface VcsHead {
  readonly sha: string | null; // null in a repository with no commit
  readonly branch: string | null; // null when HEAD is detached
}
export interface VcsStash {
  readonly sha: string;
  readonly branch: string | null;
}
export interface VcsStatusEntry {
  readonly path: string; // relative to the project root
  readonly code: string; // the two-letter porcelain v1 code, such as ' M', 'A ' or '??'
  readonly from?: string; // the old path of a rename or copy
}
export interface Vcs {
  readonly kind: 'git' | 'none';
  readonly unavailableReason: string | null; // null for GitVcs
  root(): Promise<string | null>;
  head(): Promise<VcsHead>;
  indexDigest(): Promise<string>;
  stashList(): Promise<VcsStash[]>;
  status(): Promise<VcsStatusEntry[]>;
}
```

`select.ts` exports `selectVcs(projectRoot: string, config: OsqConfig, options?: { gitBinary?: string }): Promise<Vcs>`.
`gitBinary` defaults to `git` and lets a test name a binary that does not exist.
`select.ts` is the only module that imports `git-vcs.ts` or `no-vcs.ts`.

Use `execFile` with an argument list, never a shell. Read the digest as a
SHA-256 of `ls-files --stage -z`. Read stashes with
`stash list --format=%H%x00%gs`; the subject starts `WIP on <branch>:` or
`On <branch>:`, and `(no branch)` means null. Read status with
`status --porcelain=v1 -z --untracked-files=all`; in `-z` form a rename's old
path follows as the next field. Read HEAD with `rev-parse --verify --quiet HEAD`
and `symbolic-ref --quiet --short HEAD`; a non-zero exit from either means null.
`build-project.ts` shows the existing `rev-parse` call; leave it alone.

`config.ts` is at its line budget with one line to spare, so the new field is
one line with no doc comment, and its default of 10 lives in `git-vcs.ts`
beside a comment. `timeouts.harnessPreflightSeconds` is the precedent. In tests,
set `user.name` and `user.email` with `-c` or in the temporary repository's
config, so a machine without a global identity can commit. New files stay
within 250 lines and new functions within 80.
