## Acceptance

- [ ] `buildManifest` records `decisions` on the approval path, as the watcher-and-harness delta's "Governing decisions in the manifest" says, with `governingAdrs` over the change's written capabilities. `ManifestData` gains the optional field.
- [ ] `HarnessEventType` and `OsqEventData` gain `instructions_changed` with a typed `InstructionsChangedEventData` holding `changed: string[]`.
- [ ] New `src/watcher/instructions-drift.ts` implements "Instructions changed after approval": it reads the manifest, compares, appends the event with `appendHarnessEvent`, and prints the warning with `logger.warn`.
- [ ] `spawnTaskAgent` calls it after `readRetryContext` and before `adapter.spawn`, only when the attempt is 1. The task's run does not depend on the result.
- [ ] `formatSpecDetails` prints the status-inspection delta's "Instructions changed in show" line after the `Stuck:` line.
- [ ] New `tests/instructions-drift.test.ts` covers every scenario of the three requirements with `runTask` and `MockAdapter` on approved temporary projects, including a second attempt after `osq retry` adding no event and a manifest without `decisions` comparing only AGENTS.md.

## Details

Set up the approved projects as `tests/measures.test.ts` does, and approve with
`approveSpec` so the manifest is real. Capture the warning with a logger stub.
The written capabilities are the directories under the change's `specs/`, as
`buildManifest` already lists them. Compare against the same hash function the
manifest uses. `src/watcher/spawn.ts` is 193 lines and
`tests/import-graph.test.ts` keeps it strictly under 200, so keep the call to
three lines. `src/watcher/runner.ts` has no room and is not in scope. `show.ts`
is on the line-budget allow list and `formatSpecDetails` is grandfathered; add
the formatter as a small function beside `formatStuck`. A trial that appended
this event in the runner broke no other test. New functions stay within 80
lines and new files within 250.
