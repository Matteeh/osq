## Details

### Port

```ts
export const RULES_START_MARKER = '<!-- OSQ:RULES:START -->';
export const RULES_END_MARKER = '<!-- OSQ:RULES:END -->';
/** The canonical block for these records, or null with no system-wide ADR. */
export function renderRulesBlock(records: DecisionRecords): string | null;
/** Write, replace, or remove the block in AGENTS.md; true when the file changed. */
export function writeRulesBlock(projectRoot: string, config: OsqConfig): Promise<boolean>;
/** Error messages for a stale, missing, or unexpected block, and for too many rules. */
export function checkProjectRules(projectRoot: string, config: OsqConfig): Promise<string[]>;
```

The block, for ADRs 003 and 007, is exactly:

```markdown
<!-- OSQ:RULES:START -->
## Project rules

- Every service logs JSON to stdout. ADR 003
- UI components use React. ADR 007
<!-- OSQ:RULES:END -->
```

It sits directly before `<!-- OSQ:START -->` with one blank line between the
end marker and the start marker. When AGENTS.md has no `<!-- OSQ:START -->`,
append the block at the end. Removing a block also removes the one blank line
that followed it, so writing and then removing a block restores the file byte
for byte. `writeRulesBlock` writes the block even past the limit; only
`checkProjectRules` reports the limit. The stale message says to run
`osq init`.

The doctor check's name is `decisions`. With no ADR file under the decisions
folder other than `README.md` and no rules marker in AGENTS.md, return nothing,
so `tests/doctor.test.ts`, which pins the check list, passes unchanged. Its
passing message is `<n> ADRs valid`. Keep `doctor.ts` within 250 lines;
`checkPlanningPrices` in `doctor-prices.ts` is the model for an optional check.
`scaffoldProject` is 71 lines and must stay within 80. New functions stay
within 80 lines and new files within 250.
