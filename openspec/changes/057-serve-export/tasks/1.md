## Acceptance

- [ ] New `src/core/web/web-export.ts` exports `exportDashboard(options)`, taking `projectRoot`, `config`, `targetDir`, and optional `uiDir` (default `resolveUiDir()`), `home` (default `os.homedir()`), and `now`. It returns the written file paths.
- [ ] It refuses a target that exists and contains any entry, throwing an error that names the directory, before writing anything. A missing target is created.
- [ ] It builds `OsqInlineData` from `getMetricsReport`, `getWebGraph`, `readInbox`, and `getWebChange` for every change node in the graph. Each change is keyed by its folder key and by its id prefix, such as `053`.
- [ ] Every string anywhere in that document has `projectRoot` replaced by `.` and then `home` replaced by `~`. The export writes `data.js` as `window.__OSQ_DATA__ = <JSON>;`. It copies the built UI, and inserts `<script src="./data.js"></script>` into the copied `index.html` immediately before its first `<script`.
- [ ] `packages/ui/vite.config.ts` sets `base: './'`, so the built `index.html` references `./assets/...`. The served dashboard still loads its assets from `/`.
- [ ] New `tests/web-export.test.ts` covers an export of a fixture project with an archived, an active, and a rejected change into a temp directory, using a stub `uiDir`. A task result contains the absolute project path and a fake `home`. It asserts every document and both keys per change, no absolute path in any written file, `data.js` inserted before the first script, and the refusal of a non-empty target. It also asserts that the real staged `ui/dist/index.html` uses relative asset paths.
- [ ] The task's verify command passes.

## Details

This task's `scope` is authoritative over any injected code-ownership rules.
`OsqInlineData` in `packages/ui/src/contracts.ts` is the document shape the UI
reads; build the same shape in `web-export.ts` from the core types, without
importing from `packages/ui`. `startWebServer` in `web-server.ts` shows how each
document is produced for a request; reuse the same functions and the same
`serializeWebJson` for stable output. Don't touch `.run/` or anything outside
`targetDir`.
