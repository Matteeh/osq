## Acceptance

- [ ] `SpecData` gains `fixes: string[]`; `parseSpecMd` reads frontmatter `fixes` with the same normalization as `depends_on`, and an absent or non-array value gives `[]`.
- [ ] `lintChangeFolder` reports `fixes names missing change: <id>` for each `fixes` id that `checkDependencyExists` does not find, next to the `depends_on` check.
- [ ] `QueueItem` gains `fixes: readonly string[]`. `parseSection` accepts an optional `Fixes:` line as the next non-empty line after `Depends on:`, with comma-separated slugs that must each be valid, unrepeated, not the item's own slug, and an earlier item; an empty value, an invalid slug, or a second `Fixes:` line fails with the queue path and item. The line is not part of the body and the raw-section hash is unchanged in meaning.
- [ ] Queue projection in `src/core/status/queue-state.ts` lists an item's unlanded `fixes` slugs in `unmetDependencies` after its unlanded dependencies, so `prepareQueuePlan` waits for them.
- [ ] `QueuePlanSelection` gains `landedFixes` resolved like `landedDependencies`; `createQueueChange` passes their change ids as `fixes` through `createChange` to `createNewSpec`, and `seedProposal` writes `fixes: ["<id>"]` on the line after `depends_on` only when the list is non-empty.
- [ ] New `tests/fixes-declaration.test.ts` covers parsing, the lint error, every invalid `Fixes:` case, the waiting rule, and `osq plan --next --print` on a temp project where `first-item` landed as a change and `second-item` has `Fixes: first-item`, asserting the new proposal carries that change's id in `fixes`.

## Details

`fixes` never enters `resolveUnmetDependencies` in `src/core/status/state.ts`;
the watcher does not wait on it. `tests/queue-plan.test.ts` shows how to build a
queue with a landed item on a temp project.
