## Acceptance

- [ ] `crates/core/Cargo.toml` gains `serde` and `serde_json` under `[dependencies]` with `.workspace = true`, and nothing else. The root `Cargo.toml` already declares their versions.
- [ ] `Event` has one variant per row of rust-core "Event types", with the data fields of that row, required fields as plain fields and optional ones as `Option`. A field marked `or null` keeps whether it was absent or `null`. Nested objects and arrays of objects are `serde_json::Value`. Numbers that can hold decimals on disk, such as `duration` and `cost`, are `serde_json::Number`, so `56` and `55.94` come back as written.
- [ ] `parse_event_line(&str) -> Result<Envelope, EventError>` and `event_line(&Envelope) -> String` behave as "Event lines round-trip" and "Event read errors" say. `EventError` has the variants `NotJson`, `InvalidEnvelope`, `UnknownType` and `InvalidData`; the last two hold the type name.
- [ ] `crates/core/tests/events.rs` proves "Every event type parses", "Absent, null and numbers stay as written" and "Lines that are refused", one case per table row, with the lines taken from the tables.
- [ ] `crates/core/tests/event_corpus.rs` proves "Archived event logs round-trip": it walks `openspec/changes/archive/` from `env!("CARGO_MANIFEST_DIR")` up two folders, reads every `.run/events/*.jsonl`, and on failure names the file, the line number and the error. It fails when it finds no event file at all.
- [ ] `crates/core/tests/no_io.rs` proves "Core does no IO" by reading `crates/core/Cargo.toml` and every `.rs` file under `crates/core/src/`.
- [ ] `sh scripts/verify-rust.sh` passes, so every item has the doc comment the workspace lints require. Each public function's doc ends with `Implements: rust-core/<requirement>` and each test function's doc names `Covers: rust-core/<scenario>`, both in kebab-case.

## Details

Read the data in two steps to keep the error kinds apart: first a raw
envelope of `type`, `timestamp` and `data` that refuses other keys, then the
data by its type with `#[serde(deny_unknown_fields)]`. Optional fields use
`skip_serializing_if` so an absent field stays absent. A `null` that may also
be absent needs a small wrapper, since `Option` alone cannot tell them apart.

`src/harness/types.ts` holds the TypeScript payload types the table came from;
the table wins where they differ, because it follows what is on disk.

Keep tests in `crates/core/tests/`, never in a `#[cfg(test)]` module, so later
tasks that add lines to `lib.rs` do not edit a test. Workspace lints include
`clippy::pedantic` at warn and `-D warnings` in the verify script, so lints
such as `must_use_candidate` and `missing_errors_doc` must be met, not
allowed. Run `cargo fmt --all` before exiting. The first build fetches the
crates and writes `Cargo.lock`.
