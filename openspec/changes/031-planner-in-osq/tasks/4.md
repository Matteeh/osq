## Acceptance
- [ ] osq plan creates change folder and brief.md before opening interactive harness session
- [ ] brief.md frontmatter records planner model and date
- [ ] Opening prompt contains PLANNER.md content, change ID and title, capability spec paths, and brief.md in order
- [ ] -print flag outputs opening prompt strictly to stdout without launching interactive session
- [ ] osq plan on existing change folder with brief.md resumes session without creating new change folder
- [ ] tests/plan.test.ts validates new planning, brief creation, ordered prompt generation, -print output, and session resumption with mock harness

## Details

Implement `planCommand(nameOrId: string, options: { brief?: string; print?: boolean; cwd?: string })` in `src/cli/plan.ts`.
In `src/cli/index.ts`, register `program.command('plan <name>').description('initialize and launch interactive planning session').option('--brief <file>', 'brief file path or - for stdin').option('-print, --print', 'output prompt to stdout without launching session').action(...)`.
In `planCommand`:
Check whether `nameOrId` matches an existing change folder under `openspec/changes` via `findSpecFolder`. If found and `brief.md` exists within it, skip folder creation and resume planning. Otherwise, create a new change via `createNewSpec(cwd, nameOrId)`.
If creating or `brief.md` is missing, populate `brief.md` from `--brief <file>` (or stdin if `-`, or `$EDITOR` if omitted/interactive). Format `brief.md` with frontmatter `planner: <planner.model>` and `date: <YYYY-MM-DD>`.
Build the opening prompt with four sections in strict order:
1. Full content of `PLANNER.md` in repository root.
2. Change ID and title (e.g. `Change: <id> - <title>`).
3. Paths of capability specs under `openspec/specs/` (e.g. `openspec/specs/<cap>/spec.md`).
4. Full content of `brief.md`.
If `-print` is true, write the prompt to `process.stdout` and return without launching any session.
Otherwise, resolve the planner harness adapter (`config.planner?.harness || config.harness`), resolve model and agent, call `adapter.spawnInteractive({ prompt, cwd: projectRoot, model, agent })`, and set `process.exitCode` to the returned exit code.
Create fixture `tests/fixtures/brief.md`.
Create `tests/plan.test.ts` using `MockAdapter` to verify folder creation, `brief.md` writing, section order in opening prompt, stdout-only `-print` behavior, and resumption of existing change folders.
