- [ ] runner logs single-line summary to stderr upon successful verification
- [ ] runner logs single-line summary to stderr upon verification failure or timeout

- [ ] logged line includes task number, outcome status, and failure reason
- [ ] tests capture stderr and verify single-line outcome logs for pass and dead paths

## Details

1. In src/watcher/runner.ts:
   - When verification succeeds and .run/done/taskNumber is written:
     logger?.info(formatTaskOutcomeSummary(taskNumber, true));
     Output line: 	ask  verified (passed)

     logger?.info(formatTaskOutcomeSummary(taskNumber, false, 'verify_red', verifyTimedOut ? 'timed_out: true' : undefined));
     Output line: 	ask  dead (reason: verify_red) or 	ask  dead (reason: verify_red, timed_out: true)
   - When a dead marker is written for any other reason:
     - spec_conflict: 	ask  dead (reason: spec_conflict)
     - already_running: 	ask  dead (reason: already_running)
     - crashed: 	ask  dead (reason: crashed, code: )
     - timeout: 	ask  dead (reason: timeout)
     - no_result: 	ask  dead (reason: no_result)
2. Invariant: Every outcome log line is written directly alongside the corresponding marker write (.run/done/<n> or .run/dead/<n>.md) in the exact same code path.
3. tests/runner-outcome-logging.test.ts runs mock tasks verifying stderr output lines for passing tasks and every failure reason.
