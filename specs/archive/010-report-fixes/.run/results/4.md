# Task 4 result

## Changed

- `src/core/report.ts`:
  - `TokenMetrics` now defines the neutral categories `input`, `cached_input`, `output`, `reasoning`, `total`, and `cacheSharePercent`, with `readonly` fields, while retaining the previous `promptTokens`/`candidateTokens`/`totalTokens`/`prompt`/`candidate` aliases for backward compatibility.
  - The `tokens` event branch maps neutral categories across harnesses:
    - `input`: `data.input ?? data.input_tokens ?? data.promptTokens ?? data.prompt`
    - `output`: `data.output ?? data.output_tokens ?? data.candidateTokens ?? data.candidate ?? data.completionTokens`
    - `reasoning`: `data.reasoning ?? data.thinking_tokens ?? data.reasoningTokens`
    - `cached_input`: `data.cached_input ?? data.cachedTokens ?? data.cache_read_tokens ?? data.cache.read ?? data.cache`
  - Aggregates `totalInput`, `totalCachedInput`, `totalOutput`, `totalReasoning`, `totalTokens` and returns the new fields plus aliases.
  - `cacheSharePercent` = `(cached_input / (input + cached_input)) * 100` rounded to one decimal, `0` when the denominator is zero.
  - `formatMetricsReport` prints `Input`, `Cached input (<n>% cache share)`, `Output`, `Reasoning`, and `Total tokens`; the old `Prompt tokens`/`Candidate tokens` lines are gone.
- `tests/report-tokens.test.ts` (new): 8 tests covering the fixture sums and percentage, the presence of all neutral fields plus aliases, the formatted labels, opencode `cache.read`/`reasoning` mapping, Antigravity `input_tokens`/`output_tokens`/`thinking_tokens`/`cache_read_tokens` mapping, total derivation when no total is reported, and zero share with no input.

## Deviated

- Task Details 2 states `cached_input` is read directly from the event cache fields. Taken literally on `fixture/report/` the cache fields sum to `8958336`, which contradicts the task's own explicit expected value (`cached_input: 9036195`) and acceptance line 4 (`total` equals the sum of the categories), because the fixture's `totalTokens` sum (`9386624`) does not equal `input + cachedTokens + output`. The fixture's per-event `totalTokens` is consistently larger than `input + cachedTokens + output` by an unreported remainder (`77859` total).
  - To satisfy the explicit expected numbers and the "total equals sum" invariant, a harness-reported total (`data.total ?? data.totalTokens`) is treated as authoritative: `cached_input` is derived per event as `max(0, total - input - output - reasoning)`, and `total` is the reported total. When a harness reports no total, `cached_input` falls back to the cache fields and `total` is the sum of categories.
  - Consequence: when harness data is internally consistent (`total == input + cached + output + reasoning`), the residual equals the reported cache read, so `cache.read` still maps to `cached_input` (covered by the mapping test). Only inconsistent totals fold the unexplained remainder into `cached_input`.
