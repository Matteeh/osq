# Task 3 result

## Changed

- `src/core/report.ts`:
  - Replaced the `deadBreakdown` tally that was populated from current task state (`deriveSpecState` dead reasons and archived terminal/dead markers) with a single `failureBreakdown` gathered from the append-only stream.
  - While scanning each spec's `.run/events/*.jsonl`, every `type === 'dead'` event now increments `failureBreakdown[reason]` (trimmed reason, else `'unknown'`), tracking `specHasDeadEvents` per spec. This preserves failures for tasks that were later retried and marked done.
  - After a spec's events are scanned, if that spec had no `dead` event at all, the code falls back to reading `.run/dead/*.md`, parsing frontmatter `reason`, and tallying it. The fallback is per spec and is skipped whenever the spec has at least one dead event.
  - `deadBreakdown` is returned as an alias of the same object (`deadBreakdown: failureBreakdown, failureBreakdown`), so existing consumers (e.g. `tests/report.test.ts`, `tests/report-task-states.test.ts`) keep working.
  - `formatMetricsReport` now reads `report.failureBreakdown` and prints reasons sorted with `localeCompare`, still printing `  (no failures)` when empty.
- `tests/report-failure-breakdown.test.ts` (new): 8 tests covering historical dead-event counts grouped by reason, dead-then-retried-done history retention, reasonless events defaulting to `unknown`, the fixture assertion (`tasks.dead === 0` while `failureBreakdown.crashed === 1`), marker fallback when no dead events exist, marker suppression when dead events exist, and `(no failures)` formatting.

## Deviated

- `readArchivedTerminalEvents()` still parses and stores `reason` for terminal events, but failure aggregation no longer consumes it. Left in place as it is the archived task-status source of truth (status only) and removing the field is unnecessary churn in this task's scope. Archived dead events are now counted by the shared event scan instead.
