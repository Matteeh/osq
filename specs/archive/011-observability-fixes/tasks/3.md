## Acceptance
- [ ] Runner acquireLock failure on already_running does not append a dead event to events.jsonl
- [ ] Runner acquireLock failure does not write a dead marker file under .run/dead/
- [ ] Runner logs already_running task outcome summary to stderr
- [ ] Only an explicit dead marker write under .run/dead/ can append a dead event to events.jsonl
- [ ] osq report does not report already_running lock collisions as task failures
- [ ] Test executes runner against active lock using real adapter and asserts events.jsonl remains free of dead events

In `src/watcher/runner.ts`:

  projectRoot: string,

## Details

1. In `src/watcher/runner.ts`:
   - Locate the `acquireLock` check in `runTask`.
   - When `!lockResult.acquired`, remove `await recordDeadEvent(specFolderPath, taskNumber, 'already_running')`.
   - Keep the outcome summary log `logger?.info(formatTaskOutcomeSummary(taskNumber, false, 'already_running'))`.
   - Return `{ success: false, reason: 'already_running', error: 'Task is already running' }`.
2. Invariant: Only writing a `.run/dead/<n>.md` marker file may emit a `dead` event to `.run/events/<n>.jsonl`. A lock collision represents an active in-flight task rather than a failure outcome.
3. In `tests/runner-already-running.test.ts`:
   - Create a test project with an approved spec and simulate an active lock by holding `.run/running/1.pid`.
   - Run `runTask` with a real adapter.
   - Assert `result.success === false` and `result.reason === 'already_running'`.
   - Assert that no `.run/dead/1.md` file is created and `.run/events/1.jsonl` contains zero `dead` events.
