# Task 2 — Watcher loop lifecycle logging

## Changed

- `src/core/logger.ts`
  - Added `resolveSymbol(symbol, word, enabled?)` and `symbolsEnabled()`. `resolveSymbol` picks the unicode symbol when enabled, otherwise the plain word; the default `enabled` consults `process.stderr.isTTY`, `CI`, and `NO_COLOR`.
  - Extended `Logger` with two optional read-only capability flags: `interactive` (TTY + not quiet + not CI; status animation active) and `symbols` (interactive and `NO_COLOR` unset). `createLogger` now sets both.
  - No change to existing status sink behavior; `status()`/`clearStatus()` still no-op when not animated.
- `src/watcher/loop.ts`
  - Added `StartWatcherOptions` (`once`, `pollIntervalMs`, `signal`, `logger`) and threaded `logger` through `startWatcher` -> `runWatcherCycle` -> `runTask`.
  - `runWatcherCycle` now emits exactly one permanent info line per event: pick-up (`▶ spec <id> picked up (<folder>)` / `[spec] <id> picked up (<folder>)`), archive (`✓ spec <id> archived (<folder>)` / `[archived] <id> archived (<folder>)`), halt (`■ spec <id> halted (task <n> dead)` / `[halted] <id> halted (task <n> dead)`).
  - Per-spec failures (e.g. missing `spec.md`) are caught and logged at error level as `✗ watcher error: <msg>` / `[error] watcher error: <msg>`; the cycle continues with remaining specs.
  - Added `formatIdleStatus`, `formatAgo`, and `findLatestArchivedSpec`. When a cycle runs no tasks, it sets `logger.status('watching <specsDir> · <n> approved waiting · last: <id> archived <ago>')` (or `last: none`). "Approved waiting" counts approved specs with status `pending`, `running`, or `blocked`. Last-archived is derived from archive folder mtimes so it survives a restart.
  - `startWatcher` registers a `SIGINT` listener (removed on stop/abort/idle-first-SIGINT). First SIGINT: `clearStatus()`, writes `\x1b[?25h` to stderr when the logger is interactive, logs `waiting for running task to exit (press Ctrl+C again to kill)`, and lets the active cycle finish (no new cycles start). Second SIGINT: `process.exit(130)`. Abort listener is registered before the first cycle so an early abort always stops the watcher.
- `tests/watcher-loop-logging.test.ts` (new, 12 tests)
  - End-to-end `runWatcherCycle` + `MockAdapter` + capture logger for pick-up/archive/halt/error lines.
  - Real `createLogger` with fake TTY/non-TTY streams plus `CI`/`NO_COLOR` toggles asserting symbol vs word output.
  - `formatIdleStatus` unit test and an integration idle-status test (archived `001`, locked `002` => `1 approved waiting`, `last: 001 archived <ago>`).
  - `startWatcher` SIGINT test with a blocking adapter: asserts status cleared, cursor restored, waiting line logged, and `process.exit(130)` on second SIGINT.

## Deviations

- `resolveSymbol` is implemented as `(symbol, word, enabled = symbolsEnabled())` rather than a strict two-argument helper. The loop calls it with `logger.symbols` as the third argument so the choice matches the logger's actual sink; the two-argument form still works via environment detection. The task's two-arg signature is preserved for direct use.
- Plain-word archive output is the mechanical substitution `[archived] <id> archived (<folder>)`; the task did not pin the word-mode archive phrase, and a single template keeps symbol and word lines consistent.
