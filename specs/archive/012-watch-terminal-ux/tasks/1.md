## Acceptance
- [ ] Logger interface exposes status(text: string): void and clearStatus(): void
- [ ] When status is active on a TTY stderr sink, log lines clear the status row, write the message, and redraw status below
- [ ] When status is active, an unreferenced 80ms setInterval timer animates spinner frames
- [ ] When stderr is not a TTY or process.env.CI is set, status() is a no-op and renders no escape sequences
- [ ] clearStatus() clears the active status row and stops the animation timer
- [ ] Tests inject a fake writable with isTTY toggled and assert exact byte sequences for TTY, non-TTY, and CI modes

## Signatures

In `src/core/logger.ts`:

```ts
export interface Logger {
  info(msg: string): void;
  verbose(msg: string): void;
  warn(msg: string): void;
  error(msg: string): void;
  status(text: string): void;
  clearStatus(): void;
}

export interface LoggerOptions {
  stream?: NodeJS.WritableStream & { isTTY?: boolean };
  isTTY?: boolean;
}

export function createLogger(level: LogLevel, prefix?: string, options?: LoggerOptions): Logger;
```

## Details

1. In `src/core/logger.ts`:
   - Extend `Logger` with `status(text: string): void` and `clearStatus(): void`.
   - Update `createLogger(level: LogLevel, prefix?: string, options?: LoggerOptions): Logger`. Allow injecting an alternative `stream` (defaulting to `process.stderr`) and `isTTY` override for testing.
   - Detect animation and interactive status capability: `(options?.isTTY ?? stream.isTTY) === true && level !== 'quiet' && !process.env.CI`. When false, `status()` and `clearStatus()` are no-ops.
   - Spinner animation: define a frames array (e.g. `['⠋', '⠙', '⠹', '⠸', '⠼', '⠴', '⠦', '⠧', '⠇', '⠏']`) and advance index every 80ms via `setInterval`. Call `timer.unref()`.
   - When `status(text)` is called, store the current status message and render `\r\x1b[2K<frame> <rendered-text>`.
   - When any log method (`info`, `verbose`, `warn`, `error`) is called while status is set:
     - Clear the row (`\r\x1b[2K`).
     - Write the formatted log line ending in `\n`.
     - Redraw the current status row below it.
   - When `clearStatus()` is called: clear the row (`\r\x1b[2K`), stop and clear the 80ms interval, and reset status state.
2. In `tests/logger-status.test.ts`:
   - Inject fake `Writable` streams with `isTTY: true` and `isTTY: false`.
   - Assert exact written byte sequences when writing log lines while status is active.
   - Assert `status()` is a no-op when `isTTY: false` or `process.env.CI` is defined.
   - Invariant: tests must run without requiring a real terminal TTY.
