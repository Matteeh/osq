## Acceptance
- [ ] Running status row displays spinner, task number, elapsed time, tool count, tokens, cost, and truncated tool summary
- [ ] Runner logs task started on a single info line with title truncated to terminal width
- [ ] Runner logs task outcome (verified or dead with reason and elapsed) on a single info line
- [ ] Heartbeat drives both 1s TTY status update and 60s non-TTY heartbeat log from shared computeTaskHeartbeatStats
- [ ] TTY mode demotes periodic heartbeat log lines from info to verbose
- [ ] In-memory event counter is preferred over disk re-reading, with polling interval capped at 1s
- [ ] End-to-end test uses fake-binary pattern or mock harness asserting status text without relying on mock adapter alone

## Signatures

In `src/watcher/runner.ts`:

```ts
export interface TaskHeartbeatStats {
  elapsedSeconds: number;
  eventCount: number;
  totalTokens: number;
  toolCount: number;
  cost?: number;
  lastToolSummary?: string;
}

export function formatTaskStatusRow(
  taskNumber: string,
  stats: TaskHeartbeatStats,
  terminalWidth?: number,
): string;
```

## Details

1. In `src/watcher/runner.ts`:
   - Extend `computeTaskHeartbeatStats` to track `toolCount`, `cost` (when reported on `tokens` event), and `lastToolSummary` (from the most recent `tool` event). Prefer updating in-memory counters as events are appended, or cap jsonl scan to 1s.
   - In `runTask`:
     - When starting a task, log single info line: `▶ task <n> started: <truncated-title>` (respecting symbols vs word prefix).
     - Single heartbeat timer: in TTY mode, interval runs every 1s and invokes `logger.status(formatTaskStatusRow(taskNumber, stats))`. In non-TTY mode, timer runs every `config.log.heartbeatSeconds` (default 60s) and logs `logger.info(...)`. In TTY mode, heartbeat log is sent to `logger.verbose(...)`.
     - When task completes, call `logger.clearStatus()`, then log single info line with outcome: `✓ task <n> verified (elapsed: <elapsed>s)` or `✗ task <n> dead (reason: <reason>, elapsed: <elapsed>s)`.
   - Terminal width truncation: truncate `lastToolSummary` so the complete status line fits within `process.stderr.columns ?? 80`.
2. In `tests/runner-terminal-status.test.ts`:
   - Implement tests using the fake-binary pattern (spawning a real node script adapter) or mock harness verifying status string formatting and counter increments.
   - Assert that the status row and heartbeat log derive from the identical `computeTaskHeartbeatStats` calculation.
   - Invariant: Task 3 must not satisfy acceptance with a mock adapter alone.
