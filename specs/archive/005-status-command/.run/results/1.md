# Task 1 Result: When osq status is invoked, change folders with task states are displayed

## Changed
- `src/core/status.ts`: Added `getStatusOverview` to inspect active change folders, derive their approval and task states using `deriveSpecState`, and count archived change folders. Added `formatStatusOverview` to format active specs and tasks with indicators (`[x]` / `[done]`, `[>]` / `[running]`, `[ ]` / `[pending]`, `[!]` / `[dead] (reason: ...)`).
- `src/cli/status.ts`: Implemented `statusCommand` handler connecting the CLI to core status derivation and output formatting.
- `src/cli/index.ts`: Registered `status` command on the root commander program.
- `tests/status.test.ts`: Added unit and integration tests covering each acceptance criterion:
  - `getStatusOverview` returns active specs with derived spec and task states.
  - `getStatusOverview` counts archived change folders.
  - `statusCommand` prints formatted overview with state indicators.
  - Commander CLI program registers `status`.
  - Output clearly distinguishes pending, running, done, and dead tasks.

## Drift against features/
- None. Implementation adheres to `features/cli-foundation.md` and `features/watcher-and-harness.md`. Documentation for `features/status-inspection.md` will be applied upon spec archiving.
