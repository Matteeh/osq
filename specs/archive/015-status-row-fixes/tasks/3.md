## Acceptance
- [ ] Token count formatter abbreviates counts: below 1000 as-is, X.Xk below 1M, X.XM at or above 1M
- [ ] Formatter rolls over values rounding to 1000.0k (such as 999_950) to 1.0M
- [ ] Shared token count formatter is applied identically in both formatTaskStatusRow and formatTaskHeartbeatLine
- [ ] Cost rendering remains unchanged as $X.XXXX
- [ ] Table-driven tests verify 999, 1000, 999_949, 999_950, and 1_000_000 boundary behaviors
- [ ] Status text assertion verifies abbreviated token rendering in formatTaskStatusRow

## Signatures

In `src/watcher/runner.ts`:

```ts
export function formatTokens(tokens: number): string;
```

## Details

1. In `src/watcher/runner.ts`:
   - Implement `formatTokens(tokens: number): string`:
     - If `tokens < 1000`: return `tokens.toString()`.
     - If `tokens < 1_000_000`:
       - Calculate `k = (tokens / 1000).toFixed(1)`.
       - If `k === '1000.0'`, roll over and return `'1.0M'`.
       - Otherwise return `${k}k`.
     - At or above 1M (`tokens >= 1_000_000`): return `${(tokens / 1_000_000).toFixed(1)}M`.
   - Use `formatTokens` in `formatTaskStatusRow`: `${formatTokens(stats.totalTokens)} tokens`.
   - Use `formatTokens` in `formatTaskHeartbeatLine`: `tokens: ${formatTokens(stats.totalTokens)}`.
2. In `tests/runner-terminal-status.test.ts`:
   - Add table-driven unit tests for `formatTokens` testing `999` ('999'), `1000` ('1.0k'), `999_949` ('999.9k'), `999_950` ('1.0M'), and `1_000_000` ('1.0M').
   - Assert status row renders abbreviated token count.
