## Acceptance
- [ ] Tool summaries in status row and heartbeat line have project root and trailing separator stripped from absolute paths
- [ ] Relative path stripping falls back to process.cwd() when projectRoot is omitted
- [ ] Raw tool summaries in events.jsonl remain intact without path stripping
- [ ] Status text for a tool event with an absolute path under the project root displays clean relative path
- [ ] Tests verify paths appear without leading slash (such as specs/014-... rather than /specs/014-...)

## Signatures

In `src/watcher/runner.ts`:

```ts
export function relativizeToolSummary(summary: string, root?: string): string;

export async function computeTaskHeartbeatStats(
  specFolderPath: string,
  taskNumber: string,
  startTime: number,
  projectRoot?: string,
): Promise<TaskHeartbeatStats>;
```

## Details

1. In `src/watcher/runner.ts`:
   - Implement `relativizeToolSummary(summary: string, root: string = process.cwd()): string`:
     - Normalize root to ensure trailing separator is stripped when matching.
     - Strip `${normalizedRoot}/` and `${normalizedRoot}\\` from occurrences in `summary`.
     - If exact path matches root, relativize to `.` or relative name.
   - In `computeTaskHeartbeatStats`:
     - Accept optional `projectRoot?: string` parameter.
     - When processing `event.type === 'tool'`, set `accumulator.lastToolSummary = relativizeToolSummary(summary, projectRoot)`.
   - In `runTask`: pass `projectRoot` into `computeTaskHeartbeatStats(specFolderPath, taskNumber, startTime, projectRoot)`.
2. In `tests/runner-terminal-status.test.ts`:
   - Add tests asserting that a tool event with summary containing an absolute path under `projectRoot` displays as `specs/...` and not `/specs/...`.
   - Assert `events.jsonl` contains the unstripped raw summary.
