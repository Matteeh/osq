# Task 7 result — synthesize a missing result from final stream text

## Changed

- `src/watcher/runner.ts`
  - Added private `asRecord` and `extractTextFromStreamEvent(event)` helpers. The latter pulls the last agent text out of a single event, accepting the harness shape `{ type: 'text', data: { text } }` plus OpenCode (`part.text`) and Antigravity (`step_update.text_delta`) raw shapes, and the `data.text_delta` / `data.response` / `data.message` variants.
  - Added exported `extractFinalTextFromStream(specFolderPath, taskNumber): Promise<string | null>`. Reads the append-only `.run/events/<n>.jsonl`, keeps the text of the last event that carries text, and returns `null` when the file is absent, malformed, or text-free. Since it reads the event stream, it survives a watcher restart and does not need in-memory state.
  - Added exported `synthesizeResultFile(resultsDir, taskNumber, finalText): Promise<string>`. Writes `<resultsDir>/<n>.md` with `synthesized: true` frontmatter and an HTML comment attributing the file to the watcher, then returns the result path.
  - Changed the exit-0/no-result branch of `runTask`: it now calls `extractFinalTextFromStream`. If text exists it synthesizes the result, appends a `result_written` event with `{ path, synthesized: true }`, logs `task N result synthesized from agent message`, and falls through to the normal independent verify step. If there is no text it writes `dead/<n>.md` with `reason: no_result` (message now notes "and produced no final text") and returns the same failure. Verify, done marker, and checkbox ticking are untouched and still run after synthesis.
- `README.md`
  - "What the watcher guarantees" now states that an agent which exits without a result file is not lost: when a final text message was captured the watcher synthesizes a `synthesized: true` result and proceeds to verify, and only an exit with neither result nor text is `no_result`.
  - The "Reasons emitted" line annotates `no_result` with "(no result file and no final text)".
- `tests/runner-synthesized-result.test.ts` (new, the task verify command) — 7 tests:
  - `extractFinalTextFromStream` returns `null` with a text-free stream and with a missing stream, and returns the last of multiple text messages.
  - `synthesizeResultFile` writes the `synthesized: true` frontmatter and attribution header and returns the path.
  - Case A: a stub adapter exits 0 with no result file but emits a `text` event; the runner synthesizes the result, appends `result_written { synthesized: true }`, logs the synthesis line (asserted via `createLogger('normal')` + intercepted stderr), records `verify_ran`, and writes `done/1`.
  - Case B: exit 0 with no result and no text is `dead` with `reason: no_result` and no result file is created.
  - `README.md` documents the synthesized behavior alongside `no_result`.

## Deviated

- `extractFinalTextFromStream` is declared `async` (the task's signature block wrote `export function ... : Promise<string | null>` with no `async` keyword). The signature/return contract is identical; only the implementation keyword differs.
- Text extraction is broader than a single `text` event: it also accepts `data.text_delta` / `data.response` / `data.message`, OpenCode `part.text`, and Antigravity `step_update.text_delta` / `step_update.text`. The task Details name the OpenCode `text` and agy `agent_response` shapes, but the exact persisted harness-event shape is not yet defined, so the reader is tolerant.
- The `result_written` event's `data` includes `path` in addition to `synthesized: true`. The task named only `{ synthesized: true }`; `path` matches the mock adapter's `result_written` shape and is additive.
- Blank/whitespace-only text is treated as absent (falls to `no_result`), so a stream that only ever emitted empty deltas cannot create an empty result file.

The new `text`-event consumption, `synthesized: true` result, and updated `no_result` semantics are additive and undocumented until task 8/archive applies the delta.

## Missing context

- **Adapter capture is not implemented and is outside this task's scope.** `src/harness/opencode.ts` still logs `type: 'text'` events at `console.debug` and does not persist them, and `src/harness/agy.ts` ignores `step_update.text_delta`. `extractFinalTextFromStream` can therefore only find text that an adapter already persisted; in a real `osq watch` run with the current adapters it returns `null` and behavior is unchanged (`no_result`). To make the acceptance line "runner captures final text message emitted by agent execution stream" true end to end, a follow-up must: (a) add `'text'` to `HarnessEventType` in `src/harness/types.ts`, and (b) append a `{ type: 'text', data: { text } }` event in `processOpencodeStdoutLine` (text part) and `processAgyStdoutLine` (`step_update` with `step_type: 'agent_response'`, concatenating `text_delta`). Both files are outside this task's `scope`.
- The live run that produced this result uses those same adapters, so the watcher could not exercise synthesis on this task itself; the test file is the only place the path is exercised.
