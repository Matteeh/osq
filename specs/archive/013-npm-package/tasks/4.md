## Acceptance
- [ ] .github/workflows/release.yml triggers on v* tag push events
- [ ] Workflow installs dependencies with pnpm install --frozen-lockfile and executes pnpm verify
- [ ] Workflow verifies git tag version matches package.json version before publishing
- [ ] Workflow publishes via npm publish --provenance --access public using id-token: write permissions
- [ ] Workflow contains no NPM_TOKEN secrets or .npmrc authentication files
- [ ] Test parses release.yml to validate triggers, OIDC permissions, and absence of static token secrets

## Signatures

In `.github/workflows/release.yml`:

```yaml
name: Release

on:
  push:
    tags:
      - 'v*'

jobs:
  release:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: 'pnpm'
          registry-url: 'https://registry.npmjs.org'
      - run: pnpm install --frozen-lockfile
      - run: pnpm verify
      - run: pnpm run test
      - name: Verify tag matches package.json version
        run: |
          TAG_VERSION=${GITHUB_REF#refs/tags/v}
          PKG_VERSION=$(node -p "require('./package.json').version")
          if [ "$TAG_VERSION" != "$PKG_VERSION" ]; then
            echo "Tag version ($TAG_VERSION) does not match package.json ($PKG_VERSION)"
            exit 1
          fi
      - name: Publish to npm with provenance
        run: npm publish --provenance --access public
```

## Details

1. In `.github/workflows/release.yml`:
   - Trigger strictly on `push.tags: ['v*']`.
   - Grant top-level permissions: `contents: read`, `id-token: write`.
   - Install dependencies using `pnpm install --frozen-lockfile`. Never commit or generate `package-lock.json`.
   - Run verification gate (`pnpm verify`).
   - Run consumer pack integration smoke test.
   - Compare tag name against `package.json` version and fail immediately if they do not match.
   - Run `npm publish --provenance --access public`. Notice: no `NODE_AUTH_TOKEN` or `NPM_TOKEN` secret is used. OIDC Trusted Publishing handles authentication automatically.
   - Note on org assertion: In trusted publishing, token minting happens via the OIDC exchange with npm based on the configured trusted publisher. There is no CLI `npm whoami` available before the exchange occurs; document this in the task result and verify that the package manifest and configuration never declare an organisation scope.
2. In `tests/release-workflow.test.ts`:
   - Read and parse `.github/workflows/release.yml` using `yaml`.
   - Assert `on.push.tags` includes `v*`.
   - Assert `permissions.id-token` is `'write'`.
   - Assert `npm publish` includes `--provenance` and `--access public`.
   - Assert no secrets (e.g. `secrets.NPM_TOKEN`) are referenced anywhere in `release.yml`.
