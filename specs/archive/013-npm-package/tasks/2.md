## Acceptance
- [ ] dist/cli/bin.js preserves executable shebang (#!/usr/bin/env node) after compilation
- [ ] osq --version resolves and prints package.json version at runtime rather than a hardcoded string
- [ ] osq --help displays usage information without errors
- [ ] Programmatic exports generate valid type declarations at dist/index.d.ts
- [ ] Automated test compiles dist and verifies direct bin execution from an isolated temp directory

## Signatures

In `src/cli/index.ts`:

```ts
export function resolvePackageVersion(): string;
export function createProgram(version?: string): Command;
```

In `src/cli/bin.ts`:

```ts
#!/usr/bin/env node
import { createProgram, resolvePackageVersion } from './index.js';

const program = createProgram(resolvePackageVersion());
await program.parseAsync(process.argv);
```

## Details

1. In `src/cli/index.ts` and `src/cli/bin.ts`:
   - Implement runtime resolution of version from `package.json`. Read `package.json` relative to `import.meta.url` using `fs.readFileSync` or `node:module` `createRequire`.
   - Update `createProgram(version?: string)` so it uses the resolved version or falls back to resolving `package.json` version dynamically instead of hardcoding `0.1.0`.
   - Ensure `src/cli/bin.ts` preserves `#!/usr/bin/env node` shebang line at top of file, and verify it survives `tsc -p tsconfig.build.json` compilation into `dist/cli/bin.js`.
   - Ensure `dist/index.d.ts` exposes programmatic exports (configuration types and helpers).
2. In `tests/bin-execution.test.ts`:
   - Execute `pnpm build` (or `tsc -p tsconfig.build.json`).
   - Confirm `dist/cli/bin.js` starts with `#!/usr/bin/env node`.
   - Confirm `dist/index.d.ts` exists.
   - Run `node ./dist/cli/bin.js --version` from a temporary directory outside the project root and assert the output matches `package.json` version.
   - Run `node ./dist/cli/bin.js --help` and assert that standard command listings appear without runtime errors.
